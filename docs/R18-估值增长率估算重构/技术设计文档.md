## 0. 结论摘要与 P6-0 探源结论

### 0.1 设计结论（先看这里）

1. **宏观 GDP 数据源已找到，本轮实测稳定可用**：东财 `RPT_ECONOMY_GDP` 季度表（无鉴权/无 Cookie/无签名，UTF-8 JSON）。**不需要**回退常量拍板；长期稳定性仍需上线后观察。
2. **关键口径陷阱**：`SUM_SAME` 是**实际同比**，不是名义同比；名义 GDP 必须用 `DOMESTICL_PRODUCT_BASE`（累计值，亿元）拆单季后计算「近 4 个单季合计（TTM）」的同比。
3. 实测最新 TTM 名义同比：**2026H1 = 4.613%**，按 0.5pp 网格为 **4.5%**；`gdp_as_of=2026-06-30`，`growth_macro_basis="dynamic_gdp"`。
4. 一致预期主接口 `ProfitForecast/PageAjax` 可用：`yctj_list` 提供实际/预测年度，`ycmx` 提供机构覆盖与离散度；备用源 `RPT_WEB_RESPREDICT` 提供 EPS 口径。
5. 分红接口 `RPT_SHAREBONUS_DET` 可用：按 `REPORT_DATE` 报告年度汇总、只取 `ASSIGN_PROGRESS="实施分配"`，可修复 R10 的年份错位。
6. 服务端新增 **纯函数增长链**：宏观锚、前瞻锚、历史锚 → 复合锚 A → 周期位置修正 → 负增长归因 → 终值 g∞ → 均值回归路径 → 模型分档 → SGR 软上限/离散度折减 → C4a/b/c。
7. 取数全部在 `client`，增长计算全部在 `service`（无 IO、无时钟），API 层只负责并发取快照与注入；分层不破坏。
8. 新增 24h 进程内单飞缓存（一致预期/GDP/分红），失败不缓存、不阻塞 AI 主链路。
9. `/api/stock/:code/ai-analysis` 的 `data.valuation` 只增只读字段；手动 `/api/stock/:code/valuation` 完全不动。
10. 无新增第三方依赖；Go 标准库 + 现有依赖即可落地。

**TTM 算法（服务端纯函数）**

1. 把累计值按 `(year, quarter)` 建表，`quarter = month/3`（3→1、6→2、9→3、12→4）。
2. 单季值：
   - Q1：`single = cumulative(Q1)`；
   - Q2/Q3/Q4：`single = cumulative(Qk) − cumulative(Qk−1)`（同一年内）。
3. 只接受**连续季度**序列；缺任一前置累计值的单季点丢弃，若最后 8 个单季不连续则 `G_GDP` 不可用。
4. `TTM_latest = sum(最后 4 个单季)`；`TTM_prev = sum(再往前 4 个单季)`；`YoY = (TTM_latest / TTM_prev − 1) × 100`。
5. 异常检测：再算「上一季度截止的 TTM 同比」（需要至少 9 个连续单季）；本期与上期都落在 `[0,10]` 之外 → `ConsecutiveAnomalies=2`，回退常量；只有本期异常 → 收口到 `[0,10]` 并告警。
6. `G_GDP = roundHalf(clamp(YoY, 0, 10))`；`gdp_as_of = 最新季度的季末日期`（如 2026H1 → `2026-06-30`）。

**为什么不用 `SUM_SAME`**

`SUM_SAME` 是「按不变价计算的累计实际同比」。2026H1 `SUM_SAME=4.7%`，而由 `DOMESTICL_PRODUCT_BASE` 算出的近 4 季名义同比是 4.613%。若直接取 `SUM_SAME`，会把实际增速误当名义增速，系统性低估通胀/价格因素。因此：
- **宏观锚只用 `DOMESTICL_PRODUCT_BASE` 计算的 TTM 名义同比**；
- `SUM_SAME` 仅可作为日志/核对字段，不进入任何计算。

**回退与长期方案**

- 运行时接口失败、返回空、连续两期异常 → `G_GDP = 4.5%`、`growth_macro_basis="fallback_constant"`、省略 `gdp_as_of`。
- 本次已找到稳定源，**不触发**「需用户拍板回退 4.5%」；但若未来长期退化为常量，仍须按 D1 回报用户确认后才能作为长期默认。
- 当前动态值 4.613% 恰好按网格落在 4.5%，与回退常量同值；运行时必须靠 `growth_macro_basis="dynamic_gdp"` 与 `gdp_as_of` 区分，不能因为数值相同就认为源未生效。

## 1. 设计目标与影响面

### 1.1 目标

按需求 FR-1~FR-10 落地：

- 复合增长锚 A：历史锚 X（R15 三项稳健增速）+ 前瞻锚 A_fwd（一致预期）+ 宏观锚 A_macro（动态名义 GDP），按可靠度加权。
- 周期位置意识：周期股识别、`CyclePosition=(GMpos+NMpos)/2`、`Δ_cycle` 只修正历史锚。
- 负增长归因：结构性 → 零增长；周期性 → 低永续；不得落入旧 `g1<=0 → zero`。
- 均值回归路径：`n_total=clamp(round(gap/1.5),3,10)`，两阶段/三阶段平滑衰减，0.5pp 网格。
- 终值动态 GDP：`g∞=min(G_GDP, r−1.0pp, SGR)`，0.5pp 向下取整；取消 `{4,3,2}` 映射。
- SGR 语义重构：payout 留存率（分母为归母净利润）、软上限、只约束终值；C4 拆 C4a/b/c。
- 输出字段、24h 缓存、前端展示、确定性与降级。

### 1.2 非目标（严格不做）

- 不改 DCF 公式与 `internal/service/valuation.go:321 dcfValue`。
- 不改手动估值端点 `GET /api/stock/:code/valuation` 及其 handler。
- 不改 WACC/β 数值口径（Rf=2.5%、ERP=5.5%、β 1.2/1.0/0.8）。
- 不改基期 FCF 选取（`RecommendBaseFCF`、`trim_mean`、`fcf_years=3/5/7`、成长性否决）。
- 不改研发调整双条件与 `rd_expansion`。
- 不新增模型类型（H 模型用三阶段近似）。
- 不新增行业增速数据源、不新增第三方依赖、不新增密钥。
- 不把外部原始 JSON 透传给前端。

### 1.4 兼容性与破坏性变更

**API 兼容**

- 不新增路由、不改变请求参数。
- `AIValuation` 新字段全部 `omitempty`；旧前端忽略未知字段。
- 手动 `/valuation` 不受影响。
- `ApplyValuationRecommendation` 对旧字段的覆盖顺序不变，仅追加新字段覆盖。

**行为变更（需要更新既有单测，不是 API 破坏）**

- 旧导出函数 `RecommendValuation` / `RecommendValuationWithIndustry` 保留，但内部传**零值快照**：
  - 无一致预期 → `A=0.85×X+0.15×4.5`；
  - 无动态 GDP → `g∞` 由 4.5 回退常量计算，不再用 `{4,3,2}`；
  - 无分红 → 留存率回落权益增长；
  - 模型分档改为 `A + gap`。
- 因此 R15 中依赖 `gk∈{2,3,4}`、`g1=floor(SGR)`、`X<3→zero` 的测试必须更新。生产 API 的结果也会变化，这是本需求的目的。
- **确定性契约升级**：同一份财报 + 同一外部快照（`consensus_as_of` / 分红报告期 / `gdp_as_of`）下逐位一致；快照变化必须可归因。旧契约「同一财报多次分析完全相同」不再成立（外部快照可能更新）。

### 1.5 设计原则

- **分层**：`client` 只取数/解析；`service` 只做纯计算；`api` 只做并发、缓存、注入、日志；`model` 只放数据。
- **不猜数**：字段缺失/基数非正/口径不一致 → 该锚不可用，写 Warning，不补 0、不猜 CAGR。
- **单一 g∞**：M1 包络、gap、模型分档、参数构造、前端展示必须使用同一个 `g∞`。
- **单一周期信号**：周期位置只修正历史锚一次；离散度折减与周期修正可叠加时按 M2 减半；不得再叠加 SGR 硬压。
- **可解释**：每个最终参数都能追溯到「哪个锚 + 哪个修正 + 哪个上限」。

### 2.2 新增模块落点与理由

- **`model/growth.go`**：快照与原始季度/机构/分红记录。放 model，因为 client 产出、service 消费，属于跨层数据契约。
- **`client/growth.go`**：所有外部 IO。GDP 只返回**原始累计季度点**，TTM 计算放 service，保证「取数」与「口径计算」分离、TTM 可单测。
- **`service/growth.go`**：所有口径计算。纯函数，入参是快照与既有 `incomeByYear`/`cycle`/`gp`，不读时钟、不发请求。
- **`api/growth_cache.go`**：24h 缓存与会话内单飞。缓存是横切关注点，放 api；client 只负责一次取数。
- **`api/ai.go`**：快照注入点。预推导与终态重算必须用**同一个快照对象**，否则两次结果不可归因。

### 2.3 请求时序（`computeAIAnalysis`）

```text
computeAIAnalysis 入口（code 已在 GetAIAnalysis 校验）
  ├─ ★ 启动 fetchGrowthSnapshot goroutine（3 路并发，缓冲 1）
  ├─ FetchQuote（既有，~0.2s）
  ├─ fetchAnalysisReports（F10，冷启动 ~12s）
  ├─ FetchSegmentIncome（既有）
  ├─ ★ <-snapCh（通常已就绪，近零等待）
  ├─ RecommendValuationWithSnapshot 预推导 → BuildAIPrompt
  ├─ LLM（主耗时）
  ├─ ParseAIResult
  ├─ RecommendValuationWithSnapshot 终态（同一 snap）
  └─ Apply + 日志 + 汇合 leader/industry
```

- 快照 goroutine 在函数入口、`FetchQuote` 之前启动，用行情 + F10 + LLM 的耗时覆盖外部请求（code 已校验，失败只会浪费一次后台请求）。
- 若 F10 命中 15min 缓存，快照冷启动最多增加 `max(一致预期主+备, GDP, 分红)` ≈ 2~4s；P90 主接口成功时为 2s 内。见 §10 风险。
- 快照 goroutine 写缓冲 channel，提前 return 不会泄漏。

### 2.4 确定性契约

- `service` 不调用 `time.Now()`；所有「快照日期」来自 `model.GrowthSnapshot` 或 client 解析结果。
- 24h 缓存命中时，缓存值（含 `AsOf`）原样复用；`RequestDate` 只用于日志与缺失 `AsOf` 时的兜底。
- 同一 `(财报, snapshot)` 连续调用 3 次，`reflect.DeepEqual` 必须相等；Warning 顺序稳定。
- 快照更新（`consensus_as_of`/`gdp_as_of` 变化）导致的参数变化，必须在响应字段中可归因。

### 2.5 降级矩阵

| 场景 | 行为 | 输出 |
| --- | --- | --- |
| 一致预期主接口失败 | 立即尝试备用源；备用也失败 → `A_fwd` 不可用 | `growth_forward` 省略；Warning；`A=0.85X+0.15macro` |
| 一致预期主接口成功但无数据 | 同主接口失败（尝试备用） | 同上 |
| 覆盖机构 <2 / 离散度 >25pp / 实际年≠baseYear / 基数非正 | `A_fwd` 不可用，但不重试 | `consensus_reliability="unavailable"`；保留 `consensus_as_of/institutions/years`；Warning |
| 分红接口失败 | 留存率回落权益增长 | `retention_basis="equity_growth"` |
| 分红无当年记录 | 回落权益增长（不把「无记录」当 0 分红） | 同上 |
| GDP 接口失败/数据不足 | 回退 4.5% | `growth_macro_basis="fallback_constant"`；省略 `gdp_as_of`；Warning |
| GDP 单期异常 | 收口 `[0,10]` | `dynamic_gdp` + 原 `gdp_as_of`；Warning |
| GDP 连续两期异常 | 回退 4.5% | `fallback_constant`；Warning |
| 周期窗口 <3 年 / 区间过窄 | `CyclePosition=0`，不修正 | `cycle_position` 省略；Warning |
| SGR 不可用 | 终值不施加 SGR；软上限只用 `A_fwd/A+5pp` | `retention_basis="unavailable"`；Warning |
| 任一外部源失败 | AI 分析仍 `code=0` | 不返回 5xx |

## 3. 数据模型

### 3.1 `internal/model/growth.go`（新增）

```go
package model

// GrowthSnapshot 一次 AI 分析使用的全部外部增长快照。
// 零值 = 调用方未接入外部源：宏观锚回退 4.5%、无前瞻锚、留存率回落权益增长。
type GrowthSnapshot struct {
    RequestDate string             // 本次请求日期 yyyy-mm-dd（api 注入；service 不读时钟）
    Consensus   ConsensusForecast  // 一致预期
    GDP         GDPAnchor          // 宏观 GDP（原始累计季度点）
    Dividends   DividendSnapshot   // 现金分红（原始记录）
}

type ConsensusForecast struct {
    Source       string                // "profit_forecast" / "web_respredict" / ""（未取到）
    AsOf         string                // 快照日期 yyyy-mm-dd（主接口取最新 PUBLISH_DATE；备用源取请求日）
    Years        []ConsensusYear       // 主接口 yctj_list 的实际/预测年度；备用源由 YEAR1..4 构造
    Institutions []ConsensusInstitution // 主接口 ycmx（每机构一行，含各自年度）；备用源为空
    RatingOrgNum int                   // 备用源 RATING_ORG_NUM（主接口为 0）
}

type ConsensusYear struct {
    Year      int     // 年度
    Mark      string  // "A" 实际 / "E" 预测
    NetProfit float64 // 归母净利润（元；备用源为 0）
    Revenue   float64 // 营业总收入（元；备用源为 0）
    EPS       float64 // 每股收益（元/股）
}

type ConsensusInstitution struct {
    OrgCode     string          // 机构代码（去重键）
    PublishDate string          // "2026-09-21 00:00:00"
    Years       []ConsensusYear // 该机构 YEAR1..4
}

type GDPAnchor struct {
    Quarters  []GDPQuarter // 按 (year, quarter) 升序或降序均可，service 会排序
    Available bool         // 是否取到可用原始数据
}

type GDPQuarter struct {
    Year       int     // 2026
    Quarter    int     // 1..4
    Cumulative float64 // 累计名义 GDP（亿元）
    ReportDate string  // "2026-06-01 00:00:00"（仅日志/兜底）
}

type DividendSnapshot struct {
    AsOf      string           // 最新记录 NOTICE_DATE（yyyy-mm-dd）或取数日
    Records   []DividendRecord // 只含 ASSIGN_PROGRESS="实施分配"
    Available bool             // 接口成功即 true（可为 0 条）
}

type DividendRecord struct {
    ReportYear int     // REPORT_DATE 的年度（报告年度，不是除权日）
    CashYuan   float64 // PRETAX_BONUS_RMB/10 × TOTAL_SHARES（元）
    NoticeDate string  // NOTICE_DATE（yyyy-mm-dd）
}
```

**设计说明**

- 快照只保存「原始解析结果」，不保存 TTM、A_fwd、可靠度等派生值；派生值全部由 service 纯函数计算，便于单测与口径复核。
- `DividendSnapshot.Available=true` 且 `Records` 为空，表示「接口成功、确实没有实施分配记录」；service 仍回落权益增长（不把无记录当 0 分红），避免数据缺失被误判为高留存。
- `ConsensusForecast.Source==""` 表示未取到；`Source!=""` 表示取到数据（可能因口径不一致导致 A_fwd 不可用）。两者对应不同的输出字段策略（§5.3）。

### 4.1 宏观 GDP：`RPT_ECONOMY_GDP`

**取数函数**

```go
// internal/client/growth.go
func gdpURL() string
func (c *Client) FetchGDPAnchor() (model.GDPAnchor, error)
func (c *Client) fetchGDPURL(rawURL string) (model.GDPAnchor, error)
```

- 使用 `c.hcFast`（2s）。
- URL 参数：`reportName=RPT_ECONOMY_GDP&columns=ALL&pageNumber=1&pageSize=24&sortColumns=REPORT_DATE&sortTypes=-1&source=WEB&client=WEB`。
- 24 条 ≈ 6 年季度累计值，足够 TTM + 上期 TTM + 异常检测。
- 解析：
  - `REPORT_DATE` 取前 7 位 `yyyy-MM`；`month∈{3,6,9,12}`，`quarter=month/3`。
  - `DOMESTICL_PRODUCT_BASE` → `toFloat`；`<=0` 的行丢弃。
  - `TIME`/`SUM_SAME` 不入模型（`SUM_SAME` 仅日志核对）。
  - 按 `(Year, Quarter)` 去重；若重复，保留 `REPORT_DATE` 最新的一条。
- 返回 `GDPAnchor{Quarters, Available: len(Quarters)>0}`。
- 错误：HTTP 非 200、非 JSON、`success=false`、无有效行 → `error`；API 层降级，不缓存。
- **不在这里算 TTM**：TTM 是口径计算，放 service，便于用 fixture 单测。

**注意**

- 字段名 `DOMESTICL_PRODUCT_BASE` 的拼写必须逐字一致。
- `REPORT_DATE` 是月初（03-01/06-01/09-01/12-01），`gdp_as_of` 要映射到季末（03-31/06-30/09-30/12-31）。
- 统计局可能修订历史季度值；24h 缓存 + `gdp_as_of` 保证快照可追溯。

### 4.2 一致预期主接口：`ProfitForecast/PageAjax`

**URL**

```text
GET https://emweb.securities.eastmoney.com/PC_HSF10/ProfitForecast/PageAjax?code=SH600519
```

- `code` = 大写交易所前缀 + 6 位代码：`SH` / `SZ` / `BJ`（复用 `quotePrefix`，再 `strings.ToUpper`）。
- 使用 `c.hcFast`（2s）；UTF-8 JSON；无需鉴权。

**返回结构（实测）**

顶层键：`pjtj`、`jgyc`、`yctj_chart`、`yctj_list`、`ycmx`。

`yctj_list[]`（6 行：2023A/2024A/2025A/2026E/2027E/2028E）：

| 字段 | 含义 | 单位 |
| --- | --- | --- |
| `YEAR` | 年度 | 年 |
| `YEAR_MARK` | `A` 实际 / `E` 预测 | — |
| `PARENT_NETPROFIT` | 归母净利润 | 元 |
| `TOTAL_OPERATE_INCOME` | 营业总收入 | 元 |
| `ROE` | 净资产收益率 | % |
| `EPS` | 每股收益 | 元/股 |

`ycmx[]`（每机构一行，实测茅台 30 行）：

| 字段 | 含义 |
| --- | --- |
| `ORG_CODE` | 机构代码（去重键） |
| `PUBLISH_DATE` | 预测发布日期 |
| `YEAR1..4` / `YEAR_MARK1..4` | 该机构的年度与 A/E 标记 |
| `PARENT_NETPROFIT1..4` | 该机构的归母净利润预测（元） |
| `EPS1..4` | 该机构的 EPS 预测 |
| `RATING` | 评级 |

实测样本：600519 30 家/3 个预测年；600900 15；601919 7；688002 8；002714 18；300750 23。

**解析规则**

1. `yctj_list` → `[]ConsensusYear`：
   - `YEAR`/`YEAR_MARK`/`PARENT_NETPROFIT`/`TOTAL_OPERATE_INCOME`/`EPS` 逐行映射。
   - 同一年出现多行时，保留最后一行（接口按 `RANK` 排序，正常不重复）。
   - 至少要有 1 个 `A` 年，否则 `Source` 仍保留但 service 判 A_fwd 不可用。
2. `ycmx` → `[]ConsensusInstitution`：
   - 每行取 `ORG_CODE`、`PUBLISH_DATE`、`YEAR1..4`/`MARK`/`PARENT_NETPROFIT`/`EPS`。
   - 空 `ORG_CODE` 丢弃；`ORG_CODE="00000000"` 视为聚合行丢弃。
   - **不在 client 去重**：同一机构可能有多条不同日期的预测，全部带回，由 service 按「每机构最新 `PUBLISH_DATE`」去重（便于单测与口径透明）。
3. `AsOf = max(PUBLISH_DATE)` 的日期部分（`2026-09-21`）；若 `ycmx` 为空，取请求日 `time.Now().Format("2006-01-02")`。
4. `RatingOrgNum=0`（主接口不用）。
5. `Source="profit_forecast"`。

**机构覆盖数与离散度（service 计算）**

- 覆盖机构数：按 `ORG_CODE` 去重；每机构取 `PUBLISH_DATE` 最大的一行；排除空/`00000000`。
- 每机构 3 年 CAGR：
  - 在该机构行内找到 `Year == 共识最新实际年 Y_A` 且 `NetProfit>0` 的年度；
  - 找到 `Mark=="E"` 且 `NetProfit>0` 的最大年度；
  - `span = 最大年度 − Y_A`；要求 `span ≥ 2`（3 年 CAGR 至少跨 2 年；茅台 2025→2028 为 3）；
  - `CAGR = (NP_last/NP_base)^(1/span) − 1`。
- 离散度 = 这些 CAGR 的**四分位距** `Q3 − Q1`（pp）：
  - 排序后用线性插值：`index = p*(n−1)`，取相邻两点加权；
  - `n < 4` → `DispersionOK=false`（不判高可靠，降为中可靠）。
- 实测茅台：30 家，IQR = **1.785pp**（Q1=3.672，Q3=5.458），`AsOf=2026-09-21`。

| `PRETAX_BONUS_RMB` | 每 10 股税前现金分红 | 元/10 股；预披露行可能为 null |
| `TOTAL_SHARES` | 总股本 | 股 |

4. `ReportYear = REPORT_DATE` 的前 4 位；解析失败跳过。
5. 同一 `REPORT_DATE` 的中期 + 年度分红**相加**；同一计划不重复（接口一行一计划）。
6. `AsOf = max(NOTICE_DATE)` 的日期部分；无记录时取请求日。
7. `Available=true`（接口成功即 true，0 条也算成功）。

**实测茅台 2025 报告年度**

- 2025 年度：`280.2423/10 × 1,250,081,601 = 350.33 亿元`；

- **注意**：2026H1 的 `预披露` 行（`PRETAX_BONUS_RMB=null`）必须排除，不能算进 2026 报告年度。

### 4.6 24h 缓存（`internal/api/growth_cache.go`）

需求要求的 24h 缓存放在 API 层，而不是 client 的 15min 报表缓存；原因是：
- 需要单飞并发去重（同一股票并发 AI 请求只打一次外部接口）；
- 需要缓存「解析后的快照」，失败不缓存；
- GDP 是全局键，可跨股票复用。

```go
const (
    growthCacheTTL = 24 * time.Hour
    growthCacheMax = 256
)

type growthSnapshotCache struct {
    consensus *ttlCache[model.ConsensusForecast]
    gdp       *ttlCache[model.GDPAnchor]
    dividend  *ttlCache[model.DividendSnapshot]
}

func newGrowthSnapshotCache() *growthSnapshotCache
```

  - GDP：`"gdp|CN"`

- 命中且未过期 → 直接返回，零网络请求。
- 未命中 → 创建 flight；同键并发调用等待同一个 `done` channel，只执行一次 `fn`。
- `fn` 返回 error → 不写缓存；等待者拿到同一 error；下次请求重试。

- 容量：插入时若 `len(entries) >= max`，先删过期项；仍满则删 `expires` 最早的一项（O(256) 可接受）。

**缓存与确定性**

- 缓存值包含 `AsOf`；命中时原样复用，保证同一 24h 窗口内参数逐位一致。
- 缓存过期后重新取数，`AsOf` 变化 → 参数变化可归因（AC-19）。
- 一致预期主接口失败、备用源成功时，缓存的是备用结果 24h；主接口恢复要等缓存过期。这是 24h 新鲜度的取舍，文档标注。

### 6.2 历史锚 A_hist

- **沿用 R15 的 X**：`weightedGrowth`（营收/净利润/FCF 三项等权，缺项按可用项归一化；FCF 不稳定时按 `assessFCFGrowth` 排除）。
- `A_hist = X`；`GrowthHistory = X`（周期修正前）。
- 周期修正后的生效历史锚：`A_hist_adj = X + Δ_cycle`；`Δ_cycle` 只作用于历史锚，不作用于前瞻/宏观。
- 若 `k==0`（X 不可用）：`A_hist_adj=0`，不参与合成；`Δ_cycle=0`（无历史锚可修正）。
- **不对 A_hist_adj 单独 clamp**；最终 A 统一收口 `[-5,30]`。这样极端历史值不会在中间步骤被悄悄改写，最终包络仍可控。

### 6.3 宏观锚 `resolveMacroAnchor`

```go
type macroAnchor struct {
    Value   float64 // 0.5pp 网格
    Basis   string  // "dynamic_gdp" / "fallback_constant"
    AsOf    string  // 季末 yyyy-mm-dd；回退为空
    Warning string
}

func resolveMacroAnchor(gdp model.GDPAnchor) macroAnchor
```

步骤：

1. 若 `r18DynamicGDPEnabled == false` 或 `!gdp.Available` 或季度点不足 → 返回 `{4.5, "fallback_constant", "", "动态 GDP 数据不可用，宏观锚回退 4.5% 常量。"}`。
2. 调用 `computeGDPTTM(gdp.Quarters)`：
   - 输入按 `(Year, Quarter)` 去重、升序。
   - 计算单季值；要求连续。
   - 返回 `latestTTM, prevYearTTM, latestYoY, prevQuarterYoY, latestQuarter, ok`。
3. 若 `!ok` 或 `prevYearTTM<=0` → fallback。
4. `raw = (latestTTM/prevYearTTM-1)*100`。
5. 异常：
   - `latestAnomaly = raw<0 || raw>10`；
   - `prevAnomaly = prevQuarterYoY 可算 && (prevQuarterYoY<0 || prevQuarterYoY>10)`；
   - 两者都异常 → fallback + Warning「动态 GDP 连续两期异常，回退 4.5% 常量」；
   - 仅本期异常 → `raw = clamp(raw,0,10)` + Warning。
6. `Value = roundHalf(raw)`（0.5pp 网格，四舍五入）。
7. `Basis="dynamic_gdp"`；`AsOf = quarterEnd(latestQuarter)`。

**`computeGDPTTM` 细节**

```go
func computeGDPTTM(quarters []model.GDPQuarter) (ttm, prevTTM, yoy, prevYoY float64,
    latest model.GDPQuarter, ok bool)
```

- 排序、去重；对每个点：
  - Q1：`single = cumulative`；
  - Q2~Q4：若前一季度累计存在且连续 → `single = cum − prevCum`；否则该点不可用。
- 只保留连续单季序列；若最后 8 个不连续 → `ok=false`。
- `ttm = sum(last4)`；`prevTTM = sum(4 before last4)`。
- `prevYoY`：若最后 9 个单季连续，取「去掉最新单季后的 4 个」与「再往前 4 个」计算；否则 `prevYoY=NaN`。
- 所有 `ttm/prevTTM` 必须 >0。

### 6.4 前瞻锚 `resolveConsensus`

```go
type forwardAnchor struct {
    Value        float64
    Available    bool
    Fetched      bool
    Reliability  string // high/medium/unavailable
    Institutions int
    Years        int
    AsOf         string
    Dispersion   float64
    DispersionOK bool
    Basis        string
    Warning      string
}

func resolveConsensus(cons model.ConsensusForecast, baseYear int, baseNP float64, requestDate string) forwardAnchor
```

步骤：

1. `Fetched = cons.Source != ""`。若 `!Fetched`：返回不可用；Warning「一致预期不可用，增长率仅按历史与宏观锚定。」（仅当调用方显式提供快照/请求日时写，避免零值快照的旧单测噪声）。
2. `AsOf = cons.AsOf`；若空 → `requestDate`。
3. 取实际年 `Y_A`：
   - 主接口：`Years` 中 `Mark=="A"` 的最大 `Year`；
   - 备用源：同；若无 A 标记，取最小 `Year` 作为基数；
   - 无 `Y_A` → 不可用。
4. `Y_A != baseYear` → 不可用；Warning「一致预期基准年 Y_A 与基期年 baseYear 不一致」。（C7 口径一致性校验：一致预期基准年必须等于 `baseYear`。）
5. `baseNP <= 0` → 不可用；Warning「基期净利润非正，前瞻锚不可用」。
6. 取预测年：`Years` 中 `Mark=="E" && Year>Y_A`，升序；`Years=len`（最多 3）。
   - 无预测年 → 不可用。
7. 主接口：
   - `NP_YA` = `Y_A` 行的 `NetProfit`；`NP_Ek` = 最新预测年的 `NetProfit`；两者 >0 才算 `G_np`。
   - `REV_YA` / `REV_Ek` >0 才算 `G_rev`。
   - `G_np = (NP_Ek/NP_YA)^(1/span)−1`；`G_rev` 同理；`span=Y_Ek−Y_A`。
   - `A_fwd = 0.7*G_np+0.3*G_rev`；仅一项可用取该项；都不可用 → 不可用。
8. 备用源：
   - `EPS_YA` / `EPS_Ek` >0 → `G_eps`；`A_fwd=G_eps`；`Basis="EPS 口径（主接口不可用）"`。
9. `A_fwd = clamp(A_fwd*100, -20, 50)`（内部用小数还是百分数？统一用百分数，公式先乘 100）。
10. 可靠度：
    - `Institutions` = 主接口去重机构数；备用源 = `RatingOrgNum`。
    - `DispersionOK` / `Dispersion` 见 §4.2；备用源 `DispersionOK=false`。
    - `high`：主接口 && 机构≥5 && 预测年≥2 && `DispersionOK` && `Dispersion≤15`。
    - `medium`：机构≥2 && 预测年≥1 && (`!DispersionOK` || `Dispersion≤25`) && 非 high。
    - `unavailable`：其他（机构<2、无预测年、离散度>25、基数非正、年不一致）。
11. 若 `Reliability=="unavailable"`：`Available=false`，但保留 `Fetched/AsOf/Institutions/Years/Dispersion`；Warning 写具体原因（机构数/离散度/基准年/基数）。
12. `Available=true` 时：`Value=A_fwd`；`Basis` 写「归母净利润 CAGR x%、营收 CAGR y%（权重 0.7/0.3）」或「EPS CAGR x%」。

**不猜算**

- 任何一端非正、跨度非正、机构不足、年不一致 → 不补 0、不取平均、不猜。
- 主接口取到数据但离散度 >25pp → 不回落备用源，直接 `unavailable`。

### 6.5 复合锚 `composeGrowthAnchor`

```go
type compositeAnchor struct {
    A            float64
    Insufficient bool
    Envelope     float64 // M1 包络：5 或 3（pp）
    AnchorCount  int     // 有效独立锚数量（动态宏观才计数）
    Warning      string
}

func composeGrowthAnchor(hist float64, histOK bool, delta float64,
    fwd forwardAnchor, macro macroAnchor) compositeAnchor
```

权重表（需求 FR-3）：

| 场景 | 历史 | 前瞻 | 宏观 |
| --- | ---: | ---: | ---: |
| 历史可用 + 前瞻高可靠 | 0.45 | 0.45 | 0.10 |
| 历史可用 + 前瞻中可靠 | 0.55 | 0.35 | 0.10 |
| 历史可用 + 前瞻不可用 | 0.85 | 0 | 0.15 |
| 历史不可用 + 前瞻可用 | 0 | 0.85 | 0.15 |
| 两者都不可用 | 0 | 0 | 0 |

- `histAdj = hist + delta`（仅 `histOK` 时）。
- `A_raw = wHist*histAdj + wFwd*fwd.Value + wMacro*macro.Value`。
- `A = clampFloat(roundHalf(A_raw), -5, 30)`。
- `insufficient = !histOK && !fwd.Available`；此时 A=0。
- **M1 锚数量与包络**：
  - `AnchorCount = count(histOK, fwd.Available, macro.Basis=="dynamic_gdp")`。
  - `AnchorCount >= 2` → `Envelope=5pp`；`AnchorCount == 1` → `Envelope=3pp`；`AnchorCount == 0` → `insufficient=true`。
  - 含义：宏观锚回退常量 4.5 只作为合成项，**不计为独立动态锚**；因此「仅历史 + 回退常量」或「仅前瞻 + 回退常量」时，M1 收窄为 `A±3pp`。这与 FR-1 M1「只有一个锚时 ±3pp」一致。
  - 历史+宏观（动态）、前瞻+宏观（动态）、三者齐全 → 均为 `±5pp`。
- Warning：
  - `histOK && fwd.Available && sign(histAdj)!=sign(fwd.Value)` → 「历史锚与前瞻锚方向相反，按权重合成；结果接近 0 时按负增长归因处理。」
  - `!histOK && fwd.Available` → 「历史增速样本不足，复合锚按前瞻+宏观合成。」
  - `histOK && !fwd.Available` → 「一致预期不可用，增长率仅按历史与宏观锚定。」（仅显式快照时）
  - `insufficient` → 既有「可用同比增速样本不足…模型退化为零增长」。

**输出**

- `GrowthHistory = hist`（修正前）。
- `GrowthComposite = A`；`GrowthNormalized = A`。
- `GrowthMacro = macro.Value`；`GrowthMacroBasis = macro.Basis`；`GDPAsOf = macro.AsOf`。
- `GrowthForward = fwd.Value`（仅 `fwd.Available`）；`ConsensusFetched/AsOf/Institutions/Years/Reliability` 按 §5.3。

### 6.6 周期识别与周期位置

#### 6.6.1 周期股识别 `detectCyclical`

```go
func detectCyclical(industryType string, cycle fcfCycle, gp growthPattern, profitCycle bool) (bool, string)
```

优先级：

1. **AI 定性优先**：`normalizeIndustryType(industryType) == "cyclical"` → `true`，basis「AI 行业分类为周期性行业」。
2. **成长性否决**：`gp.Veto == true` → `false`（确定性兜底不判周期；AI 已判周期的仍按第 1 条 true，但位置强制 0）。
3. **FCF 强周期**：`cycle.Cyclical`（= `RawCyclical && !GrowthVeto`，CV>0.50 或正负交替≥2）→ `true`，basis「FCF 强周期（CV=x，翻转=n）」。
4. **盈利周期**：`profitCycle` → `true`，basis 由 `detectProfitCycle` 给出。
5. 否则 `false`。

**盈利周期 `detectProfitCycle`**

窗口：`yearWindow(incomeYears, latest, valCycleMaxWindowYears)`（5~7 年，至少 3 年）。

```go
func detectProfitCycle(incomeByYear map[int]model.ReportRow, years []int, gp growthPattern) (bool, string)
```

判据：

- `gp.Veto` → false（成长股豁免）。
- 毛利率极差 `GM_range ≥ 8pp`（只统计 `rev>0 && cost>0` 的年度）。
- 营收/净利润同比在窗口内**同时出现过** `≤−5%` 与 `≥+10%`：
  - 营收：`rowYoY`（上年>0 才计算）。
  - 净利润：自定义 `npYoY`：
    - 上年>0、本年>0 → 正常同比；
    - 上年>0、本年≤0 → 记为 `−100%`（衰退）；
    - 上年≤0、本年>0 → 记为 `+100%`（恢复）；
    - 两者≤0 → 跳过。
  - 在营收与净利润两组同比值中，至少各出现一次下行与一次上行（`hasDown && hasUp`）。
- 成立 → true；basis「盈利周期（毛利率极差 x pp，营收/净利润同比出现 ≤−5% 与 ≥+10%）」。

**说明**：盈利周期只用于**增长锚的周期识别**，不加入 β 的 `fallbackCyclical`，以保持 AC-20 的 WACC/β 与 R15 一致。

#### 6.6.2 周期位置 `computeCyclePosition`

```go
func computeCyclePosition(incomeByYear map[int]model.ReportRow, years []int,
    isCyclical bool, gp growthPattern) (position float64, label, basis, warning string)
```

- 非周期 / `gp.Veto` → `0, "", "非周期股或成长性否决，不修正", ""`。
- 窗口至少 3 年；不足 → `0, "中位", "周期窗口不足 3 年，位置按 0 处理", "周期窗口不足 3 年，周期位置按 0 处理。"`。
- 毛利率序列：`GM=(rev−cost)/rev*100`，要求 `rev>0 && cost>0`；至少 3 个点。
- 净利率序列：`NM=netProfitReconstructed/rev*100`，要求 `rev>0`；至少 3 个点。**按 FR-4.2 保持重构净利润口径，与 §6.7.1 负增长归因的归母净利润口径不同，勿统一。**
- `GM_range = max−min`；`NM_range = max−min`。
- 两者都低于最小分母（`GM_range<4 && NM_range<2`）→ `0, "中位", "毛利率/净利率区间过窄，位置按 0 处理", "周期位置指标区间过窄，按非周期处理。"`。
- `GMpos = clamp((GM_latest − median(GM))/max(GM_range,4), -0.5, 0.5)`。
- `NMpos = clamp((NM_latest − median(NM))/max(NM_range,2), -0.5, 0.5)`。
- 若一个序列可用、另一个不可用 → 用可用序列的位置；两者都不可用 → 0 + warning。
- `CyclePosition = (GMpos + NMpos)/2`（两者都可用）；单个可用时取单个。
- `label`：`>=0.2` 高位；`<=−0.2` 低位；否则中位。
- `basis`：包含识别依据 + `GMpos`/`NMpos` + 窗口年份 + 极差。
- 输出 `growth_cycle_adjust` 时把 `position` 保留 2 位小数；`Δ` = `-clamp(position*10, -6, 6)`，输出保留 1 位小数。

**成长性否决**

- `gp.Veto=true` → `position=0`，`delta=0`，无论 AI 是否判周期。
- AI 判 `cyclical` + `gp.Veto=true`：`isCyclical=true`（保留分类），但位置 0，不修正；负增长归因仍按 `isCyclical` 走，但 `CyclePosition=0` 不满足「低位」条件。

### 6.7 负增长归因 `attributeNegativeGrowth`

```go
type structuralMetrics struct {
    RevenueCAGR      float64
    RevenueCAGROK    bool
    NProfitCAGR      float64
    NProfitCAGROK    bool
    NProfitNote      string // 归母净利润缺失/非正时的回落说明（空表示使用归母口径）
    GMTrendDown      bool
    GMTrendBasis     string
    Window           []int
}

func attributeNegativeGrowth(A float64, isCyclical bool, position, delta float64,
    fwd forwardAnchor, sm structuralMetrics) (typ, basis, warning string)
```

#### 6.7.1 结构性指标

窗口 `cycleWindow`（5~7 年）：

- `RevenueCAGR_full`：首末营收都 >0 且 span>0 → `pow(last/first,1/span)−1`；否则用窗口内营收同比中位数（`rowYoY`）；仍不可算 → 不可用。
- `NProfitCAGR_full`：按 FR-4.5.2 取**归母净利润** `PARENT_NETPROFIT`；首末值都 `>0` 且 span>0 → `pow(last/first,1/span)−1`。
  - 某一端点归母净利润缺失/非正 → 该端点回落 `netProfitReconstructed`，并置 `NProfitNote="归母净利润缺失或非正，净利润 CAGR 按重构净利润近似"`（逐端点取数，不影响另一端点仍用归母口径）。
  - 首末非正时用窗口内同比中位数（同样走「归母优先、缺失回落重构」的取数函数）；仍不可算 → 不可用。
  - `NProfitNote` 非空且本次命中任一结构判据时，`basis`/`warning` 追加「口径说明：…」。
- `GMTrendDown`：
  - 最近 GM ≤ `median(GM) − 2pp`，或
  - 窗口内 GM 对年份索引的线性回归斜率 <0（至少 3 点）。
  - 任一成立 → true；basis 写具体值。
- `ForwardNegative = fwd.Available && fwd.Value < 0`。

#### 6.7.2 判据

| 组 | 判据 |
| --- | --- |
| S1 | `RevenueCAGR_full<0 && NProfitCAGR_full<0` |
| S2 | `GMTrendDown && (RevenueCAGR_full<0 || NProfitCAGR_full<0)` |
| S3 | `ForwardNegative && (RevenueCAGR_full<0 || NProfitCAGR_full<0)` |
| S4 | `A<0 && position>−0.2 && !fwd.Available` |

- 任一组成立 → `structural`。
- **结构性优先于周期性**。
- S1/S2/S3 的利润维度统一使用**归母净利润 CAGR**（`NProfitCAGR_full`）；归母净利润缺失/非正时按重构净利润近似，并在 `basis`/`warning` 的「口径说明」中标注。
- S4 只用 `A` / `CyclePosition` / `fwd.Available`，不涉及净利润口径。
- 若 CAGR 因端点非正不可算，用同比中位数替代；仍不可算 → 该组不成立，转入 S4/无法归因。

#### 6.7.3 周期性判据

同时满足：

```text
isCyclical == true
A < 0
structural == false
且以下任一：
  position <= -0.2
  fwd.Available && fwd.Value > 0
  delta >= 2.0
```

→ `cyclical`。

#### 6.7.4 默认与互斥

- `A>=0` → `none`（无论是否周期股）。
- `A<0 && structural` → `structural`。
- `A<0 && !structural && isCyclical && cyclical条件` → `cyclical`。
- `A<0 && !structural && !isCyclical` → `structural`，basis「非周期股负增长，按结构性衰退处理」。
- `A<0 && !structural && isCyclical && 不满足周期性条件` → `structural`，basis「周期/结构无法区分，保守按结构性处理」+ Warning「周期/结构无法区分，保守按零增长处理」。
- `negative_growth_type` 三选一；`negative_growth_basis` 只写实际命中的判据（含具体数值）。
- `growth_normalized = A`。

**Warning 文案**

- 结构性：「负增长归因：结构性衰退（命中 S1/S2/S3/S4：…），按零增长处理。」
- 周期性：「当前增速为负但处于周期低位/前瞻预期恢复，按正常化 A=x% 走低永续，不归零。」

### 6.8 终值 `terminalGrowth`

```go
func terminalGrowth(macro, discount, sgr float64, sgrOK bool) (g float64, warning string)
```

```text
gRaw = min(macro, discount − 1.0)
if sgrOK { gRaw = min(gRaw, sgr) }
g = max(0, floorHalf(gRaw))
```

- `macro` 已是 0.5pp 网格；`discount` 是 0.5pp 网格；`sgr` 任意。
- `floorHalf(v)=math.Floor(v*2)/2`，保证不越上限。
- `g < discount` 恒成立（`discount−1 < discount`）。
- Warning：
  - `sgrOK && sgr < macro && sgr < discount−1` → 「终值受长期内生增速 SGR x% 约束，向下取整至 y%。」
  - `discount−1 < macro && discount−1 < sgr` → 「终值受折现率−1pp 约束，向下取整至 y%。」
  - `!sgrOK` → 「SGR 不可用，终值未施加 SGR 约束。」
  - `gRaw<0` → 「终值上限为负，按 0 处理。」
  - `sgr` 可用但 `sgr<=0` → 终值 0（由 min 自然得到）。
- **取消** `perpetualGrowthRaw`（`r≤9→4`、`r≤11→3`、else→2）与 `gk=min(4%,...)`；函数可删除或标记 unused，测试同步删除。

### 6.9 SGR 与 payout 留存率

```go
func sustainableGrowthR18(balanceByYear, incomeByYear map[int]model.ReportRow,
    year int, div model.DividendSnapshot) (sgr, retention float64,
    basis string, ok bool, warning string)
```

**口径（与 FR-6.2 及当前实现对齐）**

- 留存率分母与 SGR 的 ROE 分子统一取**归母净利润** `PARENT_NETPROFIT`；字段缺失或非正时回落 `netProfitReconstructed`，并写 Warning「归母净利润缺失或非正，留存率与 ROE 按重构净利润近似。」
- ROE 分母仍取 `TOTAL_EQUITY`（免费接口无归母权益字段），因此 SGR 是近似值；与 R15 的差异只在分子，分母口径不变。
- `retention_basis` 枚举不变（`payout` / `equity_growth` / `unavailable`）；归母→重构的回落只体现在 Warning，不新增输出字段。

步骤：

1. `year <= 0` → 直接 `ok=false`、`basis="unavailable"`。否则 `np := v0(incomeByYear[year], "PARENT_NETPROFIT")`；若 `np <= 0` → `np = netProfitReconstructed(incomeByYear[year])`，`npNote = "归母净利润缺失或非正，留存率与 ROE 按重构净利润近似。"`。
2. `equity := equityValue(balanceByYear[year])`；`equity <= 0 || np <= 0` → `ok=false`，`basis="unavailable"`，Warning「留存率/ROE 数据不足，SGR 不可用，终值不施加 SGR 约束」。
3. `roeSGR := np / equity * 100`（归母口径分子；分母 `TOTAL_EQUITY`）。
4. 留存率：
   - **payout 主口径**（`r18PayoutRetentionEnabled` 且 `div.Available`）：
     - 汇总 `div.Records` 中 `ReportYear==year` 的 `CashYuan`；
     - 若该年至少 1 条记录：
       - `payout = cash / np`（**分母为归母净利润**）；
       - `retention = clamp(1−payout, 0, 1)`；
       - `sgr = roeSGR * retention`；
       - `basis="payout"`；
       - `payout>1` → `retention=0`，Warning 合并 `npNote` + 「现金分红超过归母净利润，留存率按 0 计。」；
       - 否则 Warning=`npNote`（未回落时为空）。
     - 若该年无记录 → **不当作 0 分红**，回落权益增长（避免数据缺失被误判）。
   - **权益增长备用口径**：
     - 复用既有 `retentionRate(balanceByYear, incomeByYear, year)`（R15 口径：`(期末权益−期初权益)/netProfitReconstructed`，clamp [0,1]）；
     - 需要上年权益与重构净利润>0；否则不可用；
     - `sgr = roeSGR * retention`，`basis="equity_growth"`，Warning=`npNote`。
     - 说明：payout 分母是归母口径；权益增长备用口径沿用 R15 的重构净利润分母，仅作为分红数据缺失时的近似，不改变 `retention_basis` 枚举。
5. 两种口径都不可用 → `ok=false`，`basis="unavailable"`，Warning「留存率/ROE 数据不足，SGR 不可用，终值不施加 SGR 约束」。
6. 输出 `RetentionRate=retention`、`SGR=sgr`、`RetentionBasis=basis`、`SGRRole="long_run_reference"`。

**分红按报告年度汇总**

- 只认 `DividendRecord.ReportYear`（client 从 `REPORT_DATE` 解析）。
- 同一年度中期+年度相加；特别分红计入对应报告年度。
- 不用除权除息日年份（R10 错位的根因）。

### 6.10 均值回归路径与模型分档

#### 6.10.1 `fadeYears`

```go
func fadeYears(gap float64) int {
    n := int(math.Round(gap / 1.5))
    if n < 3 { n = 3 }
    if n > 10 { n = 10 }
    return n
}
```

- `gap=1.5→1→3`；`gap=4→3`；`gap=12→8`。
- 只在 `A>=0` 且构造两/三阶段时使用；`gap<1.5` 不构造。

#### 6.10.2 模型选择 `classifyGrowthModel`

```go
func classifyGrowthModel(A, gap, score float64, insufficient bool, negType string) (model string, degraded bool, warning string)
```

按序：

1. `insufficient` → `zero`。
2. `A<0 && negType=="structural"` → `zero`。
3. `A<0 && negType=="cyclical"` → `perpetual`（低永续）。
4. `A>=6 && gap>=4 && score>=70` → `three_stage`。
5. `A>=2 && gap>=1.5 && score>=45` → `two_stage`。
6. `A>=0` → `perpetual`。
7. 兜底 → `zero`。

**说明**

- `scoreSignals` 直接复用 `classifyModelScore` 的评分部分（`valuation_recommend.go:754-776`），只把增速分输入从 `x` 改为 `A`；删除其落档 `switch`（`:778-789`），改由 `classifyGrowthModel` 处理。旧硬闸门 `x<3 → zero`、`x≥12 → three`、`x≥6 → two` 不再使用。
- 评分权重仍为 0.6/0.2/0.2，门槛 70/45 不变；`25` 不再作为 `perpetual` 的门槛（FR-5.3 表没有该门槛，D7 的「25 暂不变」指的是评分常量保留，不是分档必须 ≥25）。见 §10 关键决策点。
- `0<=A<3` 不再归零，走永续；`g=clamp(roundHalf(A),0,g∞)`。
- `A<0` 先归因，再选模型；不得先经过 `g1<=0→zero`。
- `gap<1.5` 时即使 A 很高也只走永续（FR-5.3/M4）。
- `gap>=3` 但得分<45 → 仍按表走永续；这是评分门槛导致的降级，不是 SGR 导致的降级（AC-8 的解释见 §10）。
- `degraded=true` 只用于「构造阶段失败后的降级链」，不用于按表选择低档模型。

#### 6.10.3 路径构造 `constructGrowthPath`

```go
type growthPath struct {
    Model     string
    G1        float64
    N1        int
    G2        float64
    N2        int
    GInf      float64
    NTotal    int
    Degraded  bool
    Warning   string
}

func constructGrowthPath(model string, A, gInf, gap, g1, discount float64) growthPath
```

- `nTotal = fadeYears(gap)`（仅两/三阶段）。
- `zero`：Params 空，`NTotal=0`。
- `perpetual`：
  - `g = clampFloat(roundHalf(A), 0, gInf)`；`NTotal=0`。
  - 周期性负增长 A<0 → `g=0`，模型仍为 `perpetual`。
  - Params：`[{g, "永续增长率", g}]`。
- `two_stage`：
  - `n1=nTotal`，`G1=g1`，`G2=gInf`。
  - 要求 `G1 > G2` 且 `G2 < discount`；否则降级为 `perpetual`（`Degraded=true` + Warning）。
- `three_stage`：
  - `n1=ceil(nTotal/2)`，`n2=floor(nTotal/2)`；
  - 首选平滑解：`G2 = roundHalf(gInf + gap/2)`；再 `G2 = min(G2, discount−0.5)`（0.5 网格，保证 `< discount`）；
  - 要求 `G1 > G2 > GInf` 且 `G2 < discount`；
  - 不满足 → 尝试兜底解 `G2 = gInf + 1.0`（R15 `gk+1` 语义的保留），需同时满足 `G1 > G2 > gInf` 且 `G2 < discount`；
  - 兜底解仍不满足 → 降为 `two_stage`，再按两阶段规则降级；`Degraded=true` + Warning。
- **所有 g 参数 0.5pp 网格**。
- `two_stage` 的 `NTotal=n1`；`three_stage` 的 `NTotal=n1+n2`；组装时 `GrowthFadeYears=path.NTotal`（`zero`/`perpetual` 为 0，`omitempty` 省略）。
- `g∞` 可能高于原 4%；`gap` 与 M1 包络必须使用同一个 `gInf`。

**降级链**：`three_stage → two_stage → perpetual → zero`；每次降级写 Warning 与 `model_degraded=true`。

**对既有 `buildParams` 的改造要求**

- `buildParams`/`twoStageParams`/`recommendParams` 的降级骨架可复用，但必须：
  1. 删除或屏蔽 `g1 <= 0 → zero` 分支（`valuation_recommend.go:1527-1535`）；负增长归因已在 `classifyGrowthModel` 之前完成，周期性负增长由 `perpetual` 直接构造，不得再经过该分支。
  2. `perpetual` 的 `g` 由 `constructGrowthPath` 计算后传入（`clamp(roundHalf(A),0,gInf)`），不再固定为 `gk/gInf`。
  3. `three_stage` 的 `g2` 改为 `roundHalf(gInf+gap/2)`（含 `gk+1` 兜底），`n1/n2` 改为 `fadeYears` 拆分，不再用 `stageYears(x)`。
  4. `twoStageParams` 的降级目标 `g=clamp(roundHalf(g1),0,gk)` 改为 `clamp(roundHalf(A),0,gInf)`，并保持 0.5pp 网格。

### 6.11 向下调整与 M1/M2 包络

```go
func applyDownwardAdjustments(A, gap, dispersion, delta float64,
    fwd forwardAnchor, sgr float64, sgrOK bool, envelope float64) (g1, cap float64, adjustment string)
```

#### 6.11.1 离散度折减

```text
if A > 0 {
    factor = clamp(dispersion * 0.004, 0, 0.40)
    d = min(5.0, A * factor)
    if abs(delta) >= 2.0 { d = d / 2 }   // 周期高点不重复惩罚
    candidate = A - d
} else {
    candidate = A
}
```

- `dispersion` 是既有「营收/净利润同比全幅极差的最大值」。
- 折减绝对幅度 ≤5pp，且 ≤A（A>0 时）。
- 周期修正绝对值 ≥2pp → 折减减半。
- **不得**再叠加 SGR 硬压；SGR 只通过软上限与终值生效。

#### 6.11.2 SGR/前瞻软上限

```text
base = fwd.Available ? fwd.Value : A
capRaw = max(sgrOK ? sgr : -Inf, base) + 5.0
cap = min(30.0, capRaw)
```

- SGR 不可用 → 只用 `base+5`。
- `cap` 可能低于 A（例如 A=20、A_fwd=5、SGR=3 → cap=10）；这是软上限的预期效果。
- 若 `cap < candidate` → 收口到 `cap`，Warning「高增长期增速超过软上限 x%，已收口至 y%」。
- **软上限本身不改模型档位**：档位由 §6.10.2 的 `A/gap/score` 决定；仅当收口后参数无法满足严格递减（`g1>g2` / `g1>g2>g3`）时，才按构造约束降级，Warning 写明「收口后无严格递减解」而非「SGR 导致降级」。

#### 6.11.3 M1 包络

```text
g1 = min(candidate, cap)
g1 = roundHalf(g1)              // 0.5 网格，四舍五入（与 A 的取整一致）
if g1 > cap { g1 = floorHalf(cap) }  // 只在取整越上限时才向下收口
g1 = max(A - envelope, g1)      // M1 下限；envelope=5 或 3
```

- 采用 `roundHalf` 而不是一律 `floorHalf`：M2 的向下调整量本身是实数，网格化应按「最近 0.5pp」输出；只有 `g∞` 因为要保证「不越上限」才规定向下取整。这样避免「极小的离散度折减把 g1 多降 0.5pp」而误伤 AC-16 的成熟样本。
- 若 `roundHalf` 后超过 `cap`，用 `floorHalf(cap)` 保证不越软上限（例如 `cap=10.4` → g1=10.0）。
- `g1` 允许因四舍五入比 `A` 高最多 0.25pp（仍在 M1 的 `A+5` 内），不视为「向上调整」。

- `envelope` 来自 `composeGrowthAnchor`：至少两个独立锚（历史/前瞻/动态宏观）→5pp；仅一个 →3pp；`insufficient` 不适用。
- 若 `cap < A-envelope`：`g1=A-envelope`，Warning「软上限 x% 低于复合锚 A−{envelope}pp 包络下限 y%，按包络下限收口（唯一主导原因：SGR/前瞻软上限）」。
- 若 `candidate < A-envelope`（离散度折减按构造 ≤5pp；envelope=3 时可能触发）：同样按包络下限收口，并写明「离散度折减」原因。
- `g1` 永不超过 A（没有向上调整；周期低位已内含于 A）。
- 记录 `GrowthCap=cap`。
- `growth_adjustment` 按顺序拼接：
  1. 周期修正：「周期位置 +0.32（高位）→ 历史锚修正 -3.2pp，已内含于复合锚」；
  2. 离散度：「增速离散度 12.0pp → 折减 1.6pp」或「周期修正≥2pp，折减减半至 0.8pp」；
  3. 软上限：「SGR/前瞻软上限 10.0% 生效，g1 由 20.0% 收口至 10.0%」或「未触发」；
  4. 包络：「A−5pp 包络未触发」或「A−3pp 包络未触发」或「按包络下限 x% 收口」；
  5. 终值：「终值受 SGR/折现率约束…」；
  6. 模型：「three_stage→two_stage 降级…」。
- 无调整时写「无向下调整」。

#### 6.11.4 M2 检查

- 周期修正只作用一次（合成 A 前）。
- A 之后只有离散度折减与 SGR/前瞻软上限；两者取实际生效的更小者，且最终不低于 A−envelope（5 或 3pp）。
- 一致预期可靠度只通过权重体现，不再额外扣减。
- 不叠加「一致预期上调」；向上调整只有周期低位修正（已内含于 A）。

### 6.12 C4a / C4b / C4c

```go
func verifyC4a(gInf, discount, sgr float64, sgrOK bool) (ok bool, warning string)
func verifyC4b(g1, sgr float64, sgrOK bool) string
func verifyC4c(g1, cap, lowerBound float64) bool
```

**调用顺序**：`terminalGrowth` → `constructGrowthPath` → `verifyC4a`（硬约束；异常时用收口后的 `gInf` 重建路径）→ `verifyC4b`（只告警）→ `verifyC4c`（防御复核，冲突豁免）。C4a 的重建只允许改写 `gInf` 及依赖它的 `gap/n_total/g2/g3`，不得改写 `A`、周期位置或负增长归因。

- **C4a（硬约束）**：`gInf <= sgr`（SGR 可用时）且 `gInf < discount`。
  - 构造上由 `terminalGrowth` 保证；若出口违反（未来回归），用 `gInf` 重新 `floorHalf` 收口并重建路径，写 Warning。
- **C4b（软约束）**：`g1 > sgr` 时只告警，不降级、不重算参数。
  - Warning：「高增长期增长率 x% 高于长期内生增速 SGR y%，仅告警，不降级（高增长期可通过留存/杠杆/增发实现）。」
- **C4c（防御复核）**：出口若 `g1 > cap + 1e-9` **且** `cap >= A − envelope`，用 `cap` 重建参数并复核严格递减。
  - 正常构造不会触发；保留作为回归防线。
  - **冲突豁免**：若 `cap < A − envelope`（软上限低于 M1 包络下限），§6.11.3 已按包络下限收口，此时 `g1 > cap` 是**有意的**（M1/M2 的「合计向下 ≤5pp」优先），C4c 不得二次收口；只保留 §6.11.3 的「唯一主导原因」Warning。
  - 这样既不违反 C4c 的防御意图，也不让 C4c 把 AC-5/AC-15 的包络保证推翻。
- **删除**旧「`g1 > SGR` 就 `floor(SGR)` 重建」逻辑（`rebuildWithG1Cap` 的旧语义）。
- `verifyC4` 旧函数与测试同步删除/替换。

### 10.2 关键决策点 / 待确认

> 以下为设计中对需求内部张力的取舍。均已按推荐执行；如评审不认可，可在实现前调整。

1. **GDP 数据源（已解决，无需拍板）**
   - 结论：东财 `RPT_ECONOMY_GDP` 稳定可用；`DOMESTICL_PRODUCT_BASE` 累计值拆单季算 TTM；`SUM_SAME` 不是名义增速。
   - 当前值 4.613% → 4.5%，`growth_macro_basis="dynamic_gdp"`、`gdp_as_of="2026-06-30"`。
   - 运行时失败才回退 4.5%；若长期退化，按 D1 回报用户确认。

2. **`perpetual` 是否保留 `score≥25` 门槛**
   - 需求 FR-5.3 表：`A_norm≥0` 即 `perpetual`，无 25 门槛；D7 又说「门槛 70/45/25 暂不变」。
   - **推荐**：按 FR-5.3 表执行——70/45 用于三/两阶段，25 仅保留为评分常量，不再作为 perpetual 门槛。理由：表是更具体的分档规则；25 门槛会让 `0≤A<3` 的成熟公司无谓降为零增长，违背 D5。
   - 备选：保留 25 门槛，`score<25` 时 zero。风险：高分红/成熟样本可能不满足 AC-16。

3. **SGR/前瞻软上限与 M1 `A±5pp` 包络冲突**
   - 例：A=20、A_fwd=5、SGR=3 → `g1_cap=10`，低于 `A−5=15`。
   - **推荐**：M1 包络优先，`g1=max(A−5, min(candidate, cap))`；写「唯一主导原因：SGR/前瞻软上限」的 Warning。理由：M1 是 P0 验收硬约束（AC-5），不能静默越界；软上限仍是实际生效的向下调整。
   - 备选：让软上限胜出，允许 `g1<A−5` 并标注。风险：AC-5/AC-15 不达标。

4. **`growth_history` 输出修正前还是修正后**
   - **推荐**：输出**修正前** X；`growth_cycle_adjust` 单独输出 Δ；前端展示「生效 = X+Δ」。理由：严格匹配 FR-9.1「历史锚 A_hist」，且让周期修正可归因；`base_growth` 仍保留 X。
   - 备选：输出修正后的 A_hist_adj，前端三层锚可直接加权。风险：用户看不到原始 X，周期修正不透明。

5. **非周期股负增长的默认归因**
   - **推荐**：按 FR-4.5.4 视为 `structural` → zero，Warning「非周期股负增长，按结构性衰退处理」。理由：无周期证据时不编造正常化增速。
   - 备选：`none` + zero。风险：与 AC-12c「三选一」不符。

6. **AI 判 `cyclical` 但成长性否决命中**
   - **推荐**：`isCyclical=true`（保留 AI 定性），但 `CyclePosition=0`、`Δ=0`（FR-4.1.3/FR-4.3「成长性否决强制位置 0」）。负增长归因仍可用 `A_fwd>0` 作为周期性证据。
   - 备选：AI 分类被否决覆盖为 `general`。风险：违背「AI 定性优先」。

7. **盈利周期是否加入 β 的确定性兜底**
   - **推荐**：不加入。β 兜底仍用 `(volatile && !gp.Veto) || cycle.Cyclical`，保持 AC-20 的 WACC/β 与 R15 一致；盈利周期只用于增长锚。
   - 备选：加入 `profitCycle`。风险：部分公司 β 变化，AC-20 回归失败。

8. **一致预期取到但 A_fwd 不可用时，元数据是否输出**
   - **推荐**：输出 `consensus_as_of/institutions/years` + `reliability="unavailable"`；只有接口失败/未接入才省略。理由：解决 FR-2.4「必须携带」与 AC-2「不可用省略」的冲突，且便于排查。
   - 备选：一律省略。风险：无法区分「接口失败」与「口径不可用」。

9. **live 回测是否加 build tag**
   - **推荐**：`//go:build live`，默认 `go test ./...` 不依赖网络；手动运行。理由：AC-24 要求离线测试通过，沙箱网络不稳定。
   - 备选：默认跑，网络失败 skip。风险：CI 不稳定、耗时。

10. **`g2` 是否强制 `< r`**
    - **推荐**：强制，`g2=min(roundHalf(g∞+gap/2), r−0.5)`；不满足严格递减则降两阶段。理由：FR-7 明确要求 `g2<r`；R4 `dcfValue` 只校验 g3<r，需在构造层补。
    - 备选：不强制，依赖 DCF 公式。风险：不满足需求/AC-9。

11. **`growth_forward` 为 0 时 JSON 省略**
    - **推荐**：接受；与项目既有 `omitempty` 模式一致。前端把「缺失」当不可用；0% 可信前瞻极少见。
    - 备选：改为 `*float64` 区分 0 与缺失。风险：破坏字段类型一致性、增加 Apply 复杂度。

12. **SGR 不可用与 SGR≤0 的区分**
    - **推荐**：`sgrOK=false` 表示数据不足（不约束终值）；`sgrOK=true && sgr<=0` 表示可计算但非正（终值 0）。两者 Warning 不同。
    - 备选：SGR≤0 视为不可用。风险：持续亏损公司终值可能高于 0，不符合经济含义。
