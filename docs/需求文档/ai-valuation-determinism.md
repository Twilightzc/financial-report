# AI 估值模型参数确定性约束

> 来源：用户反馈（2026-09）「对于 AI 智能分析，估值模型参数的推荐多次分析还是会有较大的误差，对 AI 估值模型参数的预测加一些约束，尽量减小多次预测的差值」。
> 对应现状代码：`internal/service/ai.go`（系统提示词 `aiSystemFramework` 的「估值模型推荐规则」约 43–53 行、后处理 `normalizeValuation()` 约 259–267 行）、`internal/client/deepseek.go`（`Temperature: 0.0`，第 92 行）、`internal/api/ai.go`（handler，已拿到三张报表全量数据）。

## 1. 背景与目标

### 1.1 背景与根因

R5 AI 智能分析会在结论中给出**估值模型推荐**（模型 + 折现率 + 各阶段增长率/年数 + 选择理由），用户可一键「套用到估值」到 R4 表单。用户实测：**同一只股票、同一条件下多次「一键分析」，推荐的模型与参数出现明显跳变**（例如高增长期增长率在 10%–18% 间波动、模型在 `two_stage` / `three_stage` 间来回切换）。

根因分析（已核实）：

1. **模型侧随机性**：`deepseek-v4-pro` 是推理模型，即使 `Temperature = 0.0`，思考链每次仍存在随机性，导致「模型选择」与「增长率取值」两个自由度双双跳变。
2. **现有约束只做量化、未做锁定**：`normalizeValuation()` 仅把折现率四舍五入到 0.5%、增长率取整，属于「把连续值吸附到最近刻度」，没有消除刻度选择本身的随机性（四舍五入前是 10.2 还是 11.4，结果就不同）。
3. **模型选择规则本身存在歧义**：现有提示词对「负增长或剧烈波动」允许 `zero` **或** `two_stage`，二选一未收敛，模型选择天然不稳定。
4. **参数可确定性推导但未利用**：`internal/api/ai.go` 的 handler 已拉到利润表、现金流量表、资产负债表三张年报全量数据，`service.ComputeAnalysis` 也已算出六维指标（含营业收入/净利润/经营活动现金流量净额及其同比趋势、财务杠杆倍数、有息债务、利息保障倍数等）。也就是说，估值参数所需的输入**在 Go 侧完全具备**，具备「后端确定性算参数、大模型只写理由」的条件。

### 1.2 目标

- **可衡量目标**：同一股票、同一分析条件（年份范围 + 分析模式）下，**任意次**「一键分析」返回的估值模型与全部参数**完全一致**（差值 = 0）；参数取值全部落在固定、可枚举的网格上。
- 参数的来源**可追溯**：每个参数都能对应到后台由实际财报数据算出的基准值（如基准增速 X%），而不是大模型自由发挥。
- 推荐结果**可直接套用**到 R4 估值表单并计算成功，不触发参数校验错误。
- 不改变 R4 的估值公式与口径，不改变五维评分/结论/行业分析/业务板块（这些仍由大模型生成，允许措辞波动）。

## 2. 用户故事 / 使用场景

- 作为使用 AI 分析的投资者，我想要同一只股票每次点「一键分析」拿到的估值建议完全一样，以便我信任这个建议而不是怀疑它在「掷骰子」。
- 作为要把 AI 建议套用到估值表单的用户，我想要参数能一眼看懂来源（基于哪几年的什么增速、为什么是这个折现率），以便判断是否接受这个估值假设。
- 作为产品维护者，我想要估值参数由后端按财报数据确定性推导，以便它可被单元测试断言、不随大模型版本或采样波动。

## 3. 功能需求

### FR-1 参数取值必须来自有限、固定的确定性网格（P0）

- **触发**：AI 分析返回估值推荐（`valuation`）。
- **要求**：参数取值必须落在下表网格内，**不允许出现网格外的值**（含任意小数）：

| 参数 | key | 取值网格 | 说明 |
| --- | --- | --- | --- |
| 折现率 | `discount_rate` | 8.0 / 8.5 / 9.0 / 9.5 / 10.0 / 10.5 / 11.0 / 11.5 / 12.0 | 0.5% 一档，限定 8%–12% 区间 |
| 高增长期增长率 | `g1` | 整数百分比，区间 `[-5, 30]` | 一票一值，无小数 |
| 永续/终值增长率 | `g` / `g2` / `g3` | 2 / 3 / 4 | 贴近长期 GDP 增速 |
| 高增长期年数 | `n1` | 5 / 6 / 7 / 8 / 9 / 10（整数） | |
| 第二阶段年数 | `n2` | 3 / 4 / 5（整数） | 仅 three_stage 使用 |

- **边界**：任何参数取到网格外或非有限值（NaN/Inf）时，必须被吸附到最近的合法网格值，不得原样透传给前端。
- **一致性**：`g2`/`g3` 必须小于 `discount_rate`（沿用 R4 校验），否则按网格就近下调。

### FR-2 模型选择由确定性分档规则唯一决定（P0）

- **触发**：同 FR-1。
- **要求**：模型（`zero` / `perpetual` / `two_stage` / `three_stage`）必须由**基准增速 X%（见 FR-3）唯一确定**，规则中不得存在「或」的歧义分支：

| 基准增速 X% | 模型 | 参数集 |
| --- | --- | --- |
| X ≥ 20 | `three_stage` | `g1`（= 取整后的 X，clamp 到 [-5,30]）、`n1`、`g2`、`n2`、`g3` |
| 8 ≤ X < 20 | `two_stage` | `g1`、`n1`、`g2` |
| 0 ≤ X < 8 | `perpetual` | `g`（取 2–4） |
| X < 0 | `zero` | 无 params |

- **要求补充**：对「剧烈波动」的定义必须收敛为确定性判据（推荐：近三年同比增速的极差 > 40 个百分点视为剧烈波动；波动剧烈时 `g1` 取基准增速的 50% 向下取整、模型仍按上表档位判定），不得由大模型自主取舍。
- **输出**：`model`、`model_name`（中文名）与 `params` 的 key 集合三者互相自洽（`zero` 无 params；`perpetual` 只有 `g`；`two_stage` 有 `g1/n1/g2`；`three_stage` 有 `g1/n1/g2/n2/g3`）。

### FR-3 基准增速 X% 由后端按实际财报数据确定性计算（P0）

- **触发**：同 FR-1。
- **要求**：
  - 基准增速 X% 必须由后端**从实际财报数据计算**，输入至少覆盖：营业收入、净利润、经营活动现金流量净额的**同比增速**（这三项在现有六维指标中已可取得）。
  - 计算口径必须固定且可复现：**近 3 个完整年度的同比增速**、按固定聚合方式得出单一 X%（推荐：取三项增速的中位数，抗单年异常）。
  - 可用年度不足 3 年时，按固定降级规则处理（推荐：用可用年度的增速取中位数；不足 2 年时 X% 取 0 并置 `zero` 模型或返回明确提示，二选一由实现定但必须唯一）。
- **边界**：增速为负、数据缺失（`nil`）、上期为 0 或负导致增速不可计算时，必须有确定的处理规则（跳过该样本，不得记为 0 参与中位数）。

### FR-4 折现率由财务风险指标确定性分档（P0）

- **触发**：同 FR-1。
- **要求**：`discount_rate` 必须由**实际财务风险指标**按固定阈值表确定性地映射到 FR-1 的折现率网格，输入指标至少包含：财务杠杆倍数、利息保障倍数、有息债务占比（或债务对股东权益比率）；指标缺失时按固定规则降级（推荐：取默认档 10.0%）。
- **边界**：利息保障倍数因「真实财务费用 ≤ 0」等原因缺失时，不得由大模型补猜，必须走确定性降级分支。

### FR-5 大模型不得自主决定参数值（P0）

- **触发**：同 FR-1。
- **要求**：估值模型与参数值必须**以 FR-1~FR-4 的确定性结果为准**；大模型在估值部分只负责输出 `rationale`（选择理由文案），不得覆盖 `model` / `discount_rate` / `params[].value`。
- **异常**：当大模型返回的模型/参数与后端确定性结果不一致时，**以后端结果为准**（大模型返回的对应字段直接丢弃），不得原样透传。

### FR-6 多次分析参数一致性（幂等）（P0）

- **触发**：同一股票 + 同一分析条件（年份范围 + 分析模式）重复点击「一键分析」。
- **要求**：任意次分析（≥3 次）返回的 `valuation.model`、`model_name`、`discount_rate`、`params`（含每个 key 与 value）**完全一致**；已命中前端缓存的复用结果同样必须一致。
- **边界**：不同分析模式（简洁/标准/详细）之间，估值参数**允许不同但不强制相同**；同一模式内必须一致（因参数由后端确定性推导，推荐不同模式之间也保持一致，仅 `rationale` 详略不同）。

### FR-7 参数来源可追溯、可展示（P1）

- **触发**：AI 结果展示。
- **要求**：接口应在估值推荐中返回计算所得的**基准增速 X%** 及其口径说明（如「近 3 年营收/净利/经营现金流同比增速中位数」）；前端在「估值模型推荐」区展示该基准增速与参数依据，使用户能理解参数为何是这些值。新增字段为只读信息，需向后兼容（不改变现有字段语义）。
- **边界**：`rationale` 文案仍由大模型生成（允许措辞波动），但其内容不得与后端参数矛盾（提示词需明确要求「只能解释，不能改数」）。

### FR-8 与 R4 参数校验保持一致，套用可直接计算（P0）

- **触发**：点击「套用到估值」。
- **要求**：AI 推荐参数套用到 R4 表单后，R4 估值计算必须成功（`r > 0`、永续/终值增长率 < r、年数为正整数）；不得出现因 AI 参数越界导致的校验报错。
- **异常**：若确定性推导出的参数使 R4 估值不适用（如基期经营资产自由现金流 ≤ 0），AI 推荐必须给出明确提示（而非编造参数使计算「看起来能跑」）。

### FR-9 大模型失败时的降级（P2，可选）

- **触发**：DeepSeek 调用失败（网络/超时/鉴权/格式异常）。
- **要求（可选增强）**：由于估值参数已由后端确定性算出，可考虑在 LLM 失败时仍返回半成品（确定性估值参数 + 兜底 `rationale`），或维持现状「整体报错、可重试」。默认维持现状，作为后续增强项。

## 4. 非功能需求

- **确定性可测**：参数生成必须是纯函数（无 IO、无随机、无时间依赖），可写单元测试对固定输入断言固定输出。
- **性能与成本**：不得新增数据拉取请求（复用 handler 已获取的三张报表 + 六维指标结果）；确定性计算开销可忽略。
- **接口兼容**：不破坏现有 `/api/stock/:code/ai-analysis` 响应结构；新增字段（如基准增速）为只读附加字段，前端旧逻辑不因缺字段报错。
- **可观测**：估值参数的产生过程（基准增速、命中档位）应可通过日志或接口字段排查，便于日后核对。
- **不降低现有质量**：五维评分、结论、行业分析、业务板块分析、token 用量展示均保持不变。

## 5. 边界与约束

- **非目标**：不改变 R4 的估值公式、公司价值/股权价值口径、FCF 选取与研发调整逻辑；不改变 AI 的五维评分维度与结论结构；不追求「大模型输出文本」的完全一致（结论/点评/理由文案仍可能波动，本需求只约束**估值模型与参数**）。
- **依赖**：复用 `service.ComputeAnalysis` 已算出的指标与 handler 已拉取的三张年报，不新增数据源。
- **已知限制**：金融股（银行/保险/券商）全量报表口径不同，暂不支持（与 R3/R4 一致）；负增长、亏损、经营现金流为负的公司，参数按 FR-2/FR-3 的确定性降级规则处理。
- **前端现状**：`applyAIValuation()` 已能套用 `model/discount_rate/params`，本需求不要求改交互（FR-7 的展示为新增信息）。

## 6. 验收标准

- [ ] 同一股票（如 600519）同一条件，连续点击 3 次「一键分析」，`valuation.model`、`model_name`、`discount_rate`、`params`（全部 key 与 value）**逐字段完全一致**。
- [ ] 所有参数值落在 FR-1 网格内：`discount_rate` ∈ [8.0, 12.0] 且为 0.5 的整数倍；增长率均为整数且 `g/g2/g3` ∈ {2,3,4}；年数为整数且在枚举范围。
- [ ] `model` 与 `params` 的 key 集合自洽（`zero` 无 params；`perpetual` 仅 `g`；`two_stage` 为 `g1/n1/g2`；`three_stage` 为 `g1/n1/g2/n2/g3`）。
- [ ] 大模型返回的模型/参数若与后端确定性结果不一致，最终响应仍为后端结果（可通过构造不一致的模型输出来验证）。
- [ ] 点击「套用到估值」后，R4 估值计算成功且无参数校验报错。
- [ ] 单元测试：给定固定输入（含 X% 分档边界值 20%、8%、0%、负值，及数据不足 3 年场景），参数生成函数返回断言值。
- [ ] 前端「估值模型推荐」区展示基准增速 X% 及其口径说明。
- [ ] 五维评分、结论、行业分析、业务板块分析、token 用量展示与改动前一致（无回归）。

## 7. 待确认问题

- **Q1 实现路线：参数由后端确定性计算（方案 A）vs 后处理强约束（方案 B）**：影响最大，决定多次分析差值能否归零。
  - 方案 A（**推荐**）：模型选择 + 折现率 + 全部参数由 Go 根据财报数据确定性推导并锁定到网格，大模型只写 `rationale`。**多次分析差值 = 0**，参数可追溯、可单测；代价是丢失「大模型基于行业知识做 ±1–2% 微调」的灵活性（行业中观判断不再影响参数）。
  - 方案 B：保留大模型输出，仅在 `normalizeValuation()` 里把模型/增长率/折现率 clamp 吸附到「由财报数据算出的确定性基准」附近（±1 档）。差值可大幅缩小，但**不为 0**（模型选择仍可能跳变）。
  - **推荐 A**：用户诉求是「尽量减小多次预测的差值」，A 是唯一能把差值降到 0 的方案；且大模型的价值本就体现在逻辑与文案（结论/行业/板块/理由）上，参数交给确定性推导更符合「据实预估」的既有口径。**请用户拍板 A 或 B。**
- **Q2 基准增速 X% 的口径**：影响所有参数档位与估值结果，是最关键的口径决策。
  - 推荐：取**近 3 个完整年度**的「营业收入 / 净利润 / 经营活动现金流量净额」同比增速，三项取**中位数**作为 X%。
  - 备选 1：只用营业收入同比增速中位数（更稳定、更可解释，但忽略盈利质量）。
  - 备选 2：用三年复合增长率（CAGR）替代同比增速中位数（对首末年敏感度更高）。
  - 备选 3：三项增速加权平均（需确认权重）。
- **Q3 分档阈值与网格边界**：影响模型切换频率与参数自由度。推荐沿用现有阈值（≥20% 三阶段 / 8–20% 两阶段 / 0–8% 永续 / 负增长零增长），折现率网格 8.0–12.0 步长 0.5。需确认：是否接受此阈值表，及折现率区间上/下限（8%–12% 是否覆盖极端公司）。
- **Q4「剧烈波动」的确定性判据**：影响是否存在未收敛分支（FR-2 要求唯一）。推荐：近三年同比增速极差 > 40 个百分点即为剧烈波动，此时 `g1` 取基准增速的 50% 向下取整。需确认阈值与降级方式。
- **Q5 不同分析模式（简洁/标准/详细）之间参数是否必须一致**：影响是否符合直觉。推荐**一致**（参数由后端推导，与模式无关，仅 `rationale` 详略不同）；备选为仅要求同一模式内一致。
- **Q6 大模型失败时是否降级返回确定性参数（FR-9）**：影响可用性与实现量。推荐**暂不做**（维持现状报错可重试），作为后续增强项登记。
