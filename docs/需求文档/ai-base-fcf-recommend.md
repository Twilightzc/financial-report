# AI 估值推荐新增基期自由现金流选择

> 来源：用户反馈（2026-10-11）「（AI 智能分析的结果）对于估值模型的推荐，除了之前要求的给出对应的增长率、折现率等参数外，也希望 AI 分析能够给出**基期自由现金流的选择**——结合公司的发展情况，判断是选用当前已给的选项（最近一年、平均值、中位数等）还是自行给出一个合理的自定义基期自由现金流；AI 给出的基期自由现金流必须是**基于公司发展**来给的，例如分析当前的业绩增速是否可持续、对应的自由现金流增速是否可持续。另外，估值模块中的『基期现金流』文案应改为『基期自由现金流』。」
>
> 对应现状代码：`internal/service/valuation_recommend.go`（`RecommendValuation`，R7 确定性推导）、`internal/service/ai.go`（`valuationPromptBlock`、`ApplyValuationRecommendation`、`aiSystemFramework` 估值段）、`internal/model/ai.go`（`AIValuation` / `ValuationRecommendation`）、`internal/api/ai.go`（`GetAIAnalysis` 串接）、`internal/web/app.js`（`applyAIValuation`、估值卡片模板、AI 结果「估值模型推荐」区、自定义基期现金流校验）、`internal/service/valuation.go`（`selectBaseFCF`、`ParseCustomFCF`、`valFCFModeNames`）。相关既有文档：`docs/需求文档/ai-valuation-determinism.md`（R7）、`docs/需求文档/valuation-custom-fcf.md`（R12）、`docs/技术设计文档.md` 第 11/16 节。
>
> 说明：本需求只登记「要什么」，不涉及技术实现方案（接口字段、函数结构等由 `techexpert` 在技术设计中确定）。

## 1. 背景与目标

### 1.1 背景

AI 智能分析的「估值模型推荐」目前（R7 起）已由后端按财报数据**确定性推导**并回填模型、折现率、各阶段增长率/年数、基准增速 X%，大模型只写 `rationale`（多次分析结果完全一致）。但推荐里**唯独缺少基期自由现金流的选取建议**：

- R4 估值的基期自由现金流有 5 种选取方式（`latest` 最近一年 / `average` 近几年平均值 / `median` 近几年中位数 / `trim_mean` 去极值平均值 / `custom` 自定义，见 R12），默认 `latest`；
- 「套用到估值」（`applyAIValuation`）目前**只套用**模型与增长率/折现率参数 + 研发调整开关，**不触碰** `fcf_mode` 与自定义值（R12 既有边界，需求 `valuation-custom-fcf.md` 第 5 节明确「不改动 fcf_mode」）；
- 用户希望 AI 估值推荐把「基期自由现金流选哪种方式」也一并给出，且该选择要**结合公司发展**——即用「业绩增速是否可持续、自由现金流增速是否可持续」来判断该用最近一年、还是用多年中枢（平均/中位数/去极值）、还是给一个自定义的可持续值。

同时存在一处**文案不一致**：估值卡片的选取控件 label 与相关提示仍写作「基期现金流」，而其余位置（结果表、产品文档）用「基期自由现金流」。用户要求统一为「基期自由现金流」。

### 1.2 目标

- **可衡量目标**：同一股票、同一分析条件下，**任意次**「一键分析」返回的**基期自由现金流推荐**（选取方式 / 年数 / 自定义值 / 口径说明）**完全一致**（差值 = 0），且推荐值全部落在可枚举、可解释的确定性规则上。
- 推荐**可追溯**：每个推荐都能对应到由实际财报数据算出的判据（如「近 N 年自由现金流增速是否可持续」的结论），而不是大模型自由发挥。
- 推荐**可一键套用**到 R4 估值表单并计算成功（含把选取方式切到推荐项、custom 时填入推荐值与单位），不触发参数校验错误。
- 估值模块面向用户的「基期现金流」措辞统一为「基期自由现金流」，且与 AI 推荐用词一致。
- 不改变 R4 的 DCF 公式与公司价值/股权价值口径，不改变 R7 五维评分/结论/行业/板块（仍由大模型生成）。

## 2. 用户故事 / 使用场景

- 作为使用 AI 分析的投资者，我想要 AI 在给出估值参数的同时，也告诉我**基期自由现金流该取哪一种**（并用财报数据说明理由，如「近三年自由现金流稳步增长、增速可持续，故取最近一年」），以便我理解并直接采用。
- 作为面对周期股 / 现金流波动大公司的投资者，我想要 AI 判断**当前业绩与自由现金流增速是否可持续**，并在「最近一年偏高、不可持续」时给出一个更稳健的基期自由现金流（自定义值或多年中枢），以便不被单年高点误导。
- 作为产品维护者，我想要基期自由现金流的推荐与 R7 一样由后端按财报数据确定性推导，以便同一公司多次分析结果不变、可单元测试。
- 作为普通用户，我想要估值表单里「基期现金流」这个叫法与结果区「基期自由现金流」一致，以便不产生「这两个是不是一回事」的困惑。

## 3. 功能需求

### FR-1 基期自由现金流选取的推荐由后端确定性推导（P0）

- **触发**：AI 分析返回估值推荐（`valuation`）。
- **要求**：推荐的基期自由现金流选取方式（`fcf_mode`）、选取年数与自定义推荐值，必须**由后端按实际财报数据确定性推导**，遵循 R7 同一原则（`ai-valuation-determinism.md` FR-1/FR-5）：纯函数、无 IO、无随机、无时间依赖；大模型**不得**决定这些取值。
- **输入**：复用 `RecommendValuation` 已持有的三张报表（`balance` / `cashflow` / `income`）与已算出信号，不新增数据拉取。
- **输出**：确定性推荐的基期自由现金流选择及其口径说明。
- **边界**：可用数据不足以判定时，走 FR-10 的确定性降级分支，不得空白、不得由大模型补猜。

### FR-2 推荐结构：推荐「选取方式」为主，custom 时附推荐值与单位（P0）

- **触发**：同 FR-1。
- **要求**：推荐包含以下信息（命名由 techexpert 定，语义如下）：
  - 推荐选取方式 `fcf_mode`（取值必须是 R4 的 5 个 key 之一：`latest` / `average` / `median` / `trim_mean` / `custom`）；
  - 当推荐方式为 `average` / `median` / `trim_mean` 时，给出推荐的**选取年数**（`fcf_years`，正整数）；
  - 当推荐方式为 `custom` 时，给出**推荐的自定义基期自由现金流数值**（以元为内部口径）与**展示/套用用单位**（千/万/亿/元之一，用于回显与套用，非核心语义）；
  - 一段**确定性口径说明**（如「近 3 年经营活动自由现金流稳步增长、增速可持续，取最近一年」），用于展示与喂给大模型写理由。
- **互斥**：非 `custom` 时不得输出自定义值与单位（或输出后按现状被忽略）；`custom` 时自定义值必须 > 0（FR-4）。
- **兼容**：上述为新增只读字段，旧客户端缺字段不得报错（沿用 R7/R8 的 `omitempty` 约定）。

### FR-3 选取判定规则：基于「业绩增速与自由现金流增速的可持续性」（P0）

- **触发**：同 FR-1。
- **要求**：推荐方式必须由以下**可复用信号**按固定规则唯一确定（不得出现「或」的歧义分支）：
  - 逐年经营资产自由现金流 `fcfByYear[y] = operatingFreeCashFlow(incomeByYear[y], cfByYear[y])`（R4 同口径，纯函数已存在）；
  - 现有 `Volatile`（近三年营收/净利/经营现金流同比增速极差 > 40pp）与 `BaseGrowth X%`（现有 `growthPoints` / `medianOf`）；
  - 自由现金流增速序列（逐年 FCF 同比，可用于判断是否单调、波动幅度、是否含负值）。
- **判定规则（已决策，阈值固定）**：

  | 判据（按序命中，唯一出口） | 推荐 `fcf_mode` | 理由（口径说明要点） |
  | --- | --- | --- |
  | 无可用 FCF 数据或近 N 年 FCF 全为非正 | 不推荐（退回 `latest` + 提示，见 FR-10） | 无法评估自由现金流可持续性 |
  | FCF 近 3 年均为正、单调不减、FCF 增速 ≥ 0 且波动小，且 `!Volatile` 且 `X% ≥ 0` | `latest` | 自由现金流随业绩稳定增长，最近一年代表当前可持续水平 |
  | FCF 波动大（增速极差 > 40pp / 存在某年显著偏离中枢）或 `Volatile` 为真，但近年整体为正 | `median`（N 取可用近 3–5 年） | 单年不代表常态，中位数更能反映中枢 |
  | FCF 总体平稳（增速接近 0、无单调趋势）且波动不大 | `average` 或 `trim_mean` | 多年均值代表稳定经营水平 |
  | 业绩增速不可持续（`X% < 0` 或 `Volatile`）且最近一年 FCF 明显高于多年中枢（`latest > 1.3 × median`） | `custom` | 最近一年偏高、不可持续，下调至可持续中枢（FR-4） |
  | 最近一年 FCF 明显低于多年中枢（`latest < 0.7 × median`），且非「逐年下滑」 | `median` 或 `custom` | 中枢更能代表常态，避免用偏低的单年低估 |

- **固定阈值（已决策）**：FCF 增速极差 > 40pp 视为「波动大」（复用 `valVolatileSpread` 口径）；`latest > 1.3 × median` 视为「最近一年偏高」、`latest < 0.7 × median` 视为「偏低」；中枢样本年数 N 取可用近 3–5 年。
- **边界**：上述阈值统一为固定常量，保证同一份财报多次推导一致；规则必须**唯一确定**、**可解释**，不得出现「或」的歧义出口（表中同格内的备选按更靠前者命中）。

### FR-4 自定义基期自由现金流推荐值的确定性口径（P0）

- **触发**：FR-3 命中 `custom`。
- **要求**：推荐值必须由后端按**可持续基期自由现金流**的固定口径确定性计算（已决策）：
  - **口径（已决策）**：可持续中枢 ×（1 + 可持续增速）。其中「中枢」= 近 N 年（为正的）FCF 中位数或去极值均值，「可持续增速」= 被 clamp 后的增速（如取 `min(max(FCF 增速中位数, 0), X%)`）。该口径使 custom 与 `median`（纯历史中枢）有区分、体现「前瞻可持续」。
- **展示与套用**：推荐值以元为内部口径；另给一个展示/套用单位（如「亿」）与按该单位表示的数值，便于用户阅读与前端回填；**展示值取整到整亿**（已决策，见第 7 节 Q6），内部计算与套用仍用元值。
- **边界**：计算结果 ≤ 0 时**不得**作为推荐值输出，退回 FR-10 降级（推荐非 custom 方式或提示）。

### FR-5 推荐理由由大模型撰写，但不得改数（P0）

- **触发**：同 FR-1。
- **要求**：
  - 确定性推荐（选取方式 / 年数 / 自定义值 / 口径说明）必须作为事实喂给大模型（扩展 `valuationPromptBlock`），并要求大模型在 `rationale` 中**结合公司发展解释**为何选该基期自由现金流（如业绩与自由现金流增速是否可持续）。
  - 大模型**只解释、不改数**：若大模型返回与后端不一致的基期选择/数值，一律以后端结果为准（沿用 `ApplyValuationRecommendation` 覆盖逻辑）。
- **边界**：提示词中出现的任何数字必须与后端给定值一致（沿用 R7 硬性要求）。

### FR-6「套用到估值」一并套用基期自由现金流选择（P0）

- **触发**：点击 AI 结果区「套用到估值」。
- **要求**：套用时除现有模型/折现率/增长率参数与研发调整开关外，**一并**将估值表单的基期自由现金流选择设为推荐项（已决策）：
  - 推荐为 `latest` / `average` / `median` / `trim_mean` 时，设置对应 `fcf_mode` 与（多年度方式的）`fcf_years`；
  - 推荐为 `custom` 时，设置 `fcf_mode=custom`，并回填推荐数值与单位；
  - 套用后立即重新计算且不触发校验错误。
- **说明（已决策，明确改动 R12 边界）**：本条**改变** R12 既有边界（`valuation-custom-fcf.md` 第 5 节曾明确「AI 套用不改动 fcf_mode」）。经用户拍板，套用时**一并写入** `fcf_mode` / 自定义值+单位，使推荐可一键采纳。

### FR-7 多次分析推荐一致性（幂等）（P0）

- **触发**：同一股票 + 同一分析条件重复「一键分析」。
- **要求**：任意次（≥3 次）返回的基期自由现金流推荐（`fcf_mode` / `fcf_years` / 自定义推荐值 / 口径说明）**完全一致**；命中前端缓存复用的结果同样一致（与 R7 FR-6 同等强度）。
- **边界**：不同分析模式（简洁/标准/详细）之间推荐**推荐一致**（与 R7 一致，仅 `rationale` 详略不同）。

### FR-8 前端展示基期自由现金流推荐（P1）

- **触发**：AI 结果展示。
- **要求**：在「估值模型推荐」区新增展示推荐选取方式及其口径说明（custom 时同时展示推荐数值与单位），展示形式与现有 `ai-v` 标签/`ai-text` 说明风格一致；信息为只读。
- **边界**：不新增破坏现有布局的控件；移动端不溢出（延续既有界面约定）。

### FR-9 文案统一：「基期现金流」→「基期自由现金流」（P0）

- **触发**：估值模块面向用户的所有文案。
- **要求**：把用户可见的「基期现金流」统一改为「基期自由现金流」，至少覆盖：
  - 估值卡片「自由现金流假设」区的选取控件 label（`app.js:1225`）；
  - 自定义模式的**输入校验提示**（前端 `validateCustomFCF`：`请输入基期现金流` / `基期现金流格式不正确…` / `基期现金流需大于 0` / `未知的基期现金流单位` / `基期现金流换算后金额过大…`，以及后端 `ParseCustomFCF` 同源的错误串——这些串会经接口回显到前端）；
  - AI 结果区新增的基期自由现金流推荐文案，与估值卡片、结果区用词一致。
- **口径（已决策）**：覆盖**用户可见的全部**「基期现金流」文案；结果元信息「基期FCF取……」统一为「基期自由现金流取……」。代码注释/常量名等非用户可见处不做强制要求；历史需求文档（`valuation-custom-fcf.md` 等）不改（属历史记录）。
- **边界**：不改变任何取值 key（`fcf_mode` 等）与展示逻辑，纯文案替换。

### FR-10 边界与确定性降级（P0）

- **触发**：数据不足或自由现金流异常的公司。
- **要求**：以下情形必须有确定的处理分支（不得空白、不得由大模型补猜）：
  - **无足够 FCF 历史**（可用年报不足计算 FCF 增速或中枢）：不推荐 custom，退回 `latest` 并给出说明；
  - **最近一年 FCF ≤ 0**：沿用 R7 `Warning`（「…套用后 R4 估值可能提示『现金流贴现法不适用』」），基期选择退回 `latest`；
  - **近年 FCF 全为非正 / 亏损**：不推荐 custom（无法构成正的可持续值），退回 `latest` + 提示；
  - **资产负债/利润表缺失导致判据不可得**：按固定默认方式（推荐 `latest`）推荐，并说明判据不足。
- **输出**：所有降级均给出可读中文说明，推荐不得触发 R4 参数校验错误。

## 4. 非功能需求

- **确定性可测**：基期自由现金流推荐必须是纯函数（无 IO、无随机、无时间依赖），可对固定输入断言固定输出，并断言连续多次调用结果完全相同。
- **性能与成本**：不新增数据拉取请求（复用 `RecommendValuation` 已取的报表）；确定性推导开销可忽略；不显著增加喂给大模型的文本长度。
- **接口兼容**：不破坏 `/api/stock/:code/ai-analysis` 响应结构；新增字段为只读附加字段（沿用 `omitempty`），旧前端不因缺字段报错。
- **移动端**：新增展示在桌面端与 ≥320px 视口移动端均不横向溢出（延续既有界面约定）。
- **不降低现有质量**：五维评分、结论、行业分析、业务板块、token 用量展示均保持不变；R4 的 DCF 公式与口径不变。

## 5. 边界与约束

- **只扩展 AI 估值推荐**：在现有确定性推导中**新增**基期自由现金流选择，不改变 R7 已定的模型/折现率/增长率/年数/研发调整建议逻辑。
- **复用 R4/R12 口径**：推荐的 `fcf_mode` 取值、自定义值单位与换算口径、`fcf_years` 语义，全部复用 R4/R12 既有定义（`selectBaseFCF` / `ParseCustomFCF` / `valFCFCustomUnits`）。
- **确定性优先于多样性**：为满足「多次分析一致」，基期自由现金流推荐由后端推导；大模型只写解释文案（与 R7 FR-5 一致）。
- **不改动范围**：不改 DCF 四种模型公式、公司价值/股权价值/债务价值口径、金融资产与长期股权投资价值口径；不改五维评分维度与结论结构；不改 R4 估值接口对既有请求的行为（向后兼容）。
- **已知限制**：金融股（银行/保险/券商）全量报表口径不同，暂不支持（与 R3/R4 一致）；本需求不追求大模型文本（结论/理由）本身的一致，只约束**确定性推荐**。
- **依赖**：复用 `RecommendValuation` 的输入与 `service` 包内既有口径函数（`operatingFreeCashFlow`、`growthPoints`、`medianOf` 等）。

## 6. 验收标准

- [ ] 同一股票（如 600519）同一条件，连续点击 3 次「一键分析」，基期自由现金流推荐（`fcf_mode` / `fcf_years` / 自定义推荐值 / 口径说明）**逐字段完全一致**。（FR-1、FR-7）
- [ ] 推荐的 `fcf_mode` 恒为 `latest` / `average` / `median` / `trim_mean` / `custom` 之一；`average`/`median`/`trim_mean` 时给出正整数的 `fcf_years`。（FR-2）
- [ ] `custom` 时给出推荐值与单位，推荐值 > 0 且展示值取整到整亿；非 custom 时不输出自定义值与单位。（FR-2、FR-4、Q6）
- [ ] 给定固定输入（含：稳定增长、剧烈波动、最近一年偏高、近年 FCF 非正、数据不足 2 年等场景），推荐函数返回断言值。（FR-3、FR-4、FR-10）
- [ ] 大模型返回与后端不一致的基期选择/数值时，最终响应仍为后端结果。（FR-5）
- [ ] 点击「套用到估值」后，R4 表单的基期自由现金流选择被设为推荐项（custom 时含数值与单位），估值计算成功、无参数校验报错。（FR-6）
- [ ] 「估值模型推荐」区展示推荐的选取方式与口径说明（custom 时含推荐数值）。（FR-8）
- [ ] 估值卡片选取控件 label、自定义校验提示（前后端）、AI 推荐文案一律使用「基期自由现金流」，无残留「基期现金流」；且未把 key / 展示逻辑改坏。（FR-9）
- [ ] 数据不足 / 最近一年 FCF ≤ 0 / 近年 FCF 全为非正时，给出确定推荐的降级分支与可读中文提示，不报参数校验错误。（FR-10）
- [ ] 不携带新字段的旧响应在前端仍可正常渲染（无回归）；五维评分、结论、行业、板块、token 用量展示与改动前一致。（第 4 节 兼容性）

## 7. 已决策记录

以下 7 项已于 2026-10-11 经用户拍板确认，作为定稿口径；正文相关 FR 已同步。

- **Q1 推荐口径来源 → 后端确定性推导（已决策）**：基期自由现金流推荐由后端按财报数据确定性推导（与 R7 同一原则），大模型只写解释理由；多次分析结果完全一致。对应 FR-1、FR-5、FR-7。
- **Q2 推荐结构 → 方式为主 + 自定义附值（已决策）**：推荐 `fcf_mode` 五选一；`average`/`median`/`trim_mean` 附推荐年数，`custom` 附推荐值与单位；二者互斥。对应 FR-2。
- **Q3 判定规则与阈值 → 按建议采用（已决策）**：FCF 增速极差 > 40pp 视为波动大；`latest > 1.3 × median` 视为偏高、`latest < 0.7 × median` 视为偏低；中枢年数 N 取可用近 3–5 年。对应 FR-3。
- **Q4 自定义推荐值口径 → 中枢 ×（1 + 可持续增速）（已决策）**：可持续中枢取近 N 年（为正的）FCF 中位数或去极值均值，可持续增速取被 clamp 的增速。对应 FR-4。
- **Q5 套用边界 → 随「套用到估值」一并写入（已决策）**：套用时一并把 `fcf_mode` /（多年度方式的）年数 /（custom 的）推荐值与单位写入估值表单并重算；**明确改动** R12 既有边界（原为「AI 套用不改动 fcf_mode」）。对应 FR-6。
- **Q6 custom 推荐值展示 → 取整到整亿（已决策）**：展示层取整到整亿，内部计算与套用仍用元值。对应 FR-4、FR-8。
- **Q7 文案统一范围 → 覆盖用户可见全部（已决策）**：估值卡片 label、前后端自定义校验提示、AI 推荐新文案、结果元信息「基期FCF取」统一为「基期自由现金流」；历史需求文档不改。对应 FR-9。
