# 指标趋势信号灯

> 来源：用户需求（2026-09）「对于每个指标，根据其指标含义及选择年份范围的变化趋势，来给当前指标做一个趋势变化是好还是坏的一个信号灯展示。比如资产周转率变快，这是经营效率提高的表现，应该以某种颜色体现向好趋势；再比如息税前利润逐年下滑是盈利能力恶化的表现，则以另一种颜色表示。如果该指标的趋势变化没有特别明显好坏的意义，则默认显示一般的颜色，如保持当前一致的无色。这样用户查看一个指标时心里提前有底。至于颜色信号灯的展示是另外弄一个图标还是直接在图标按钮上直接加颜色，哪种更好，你来评审一下。」
> 对应现状代码：`internal/service/analysis.go`（122 个分析指标，见附录 A）、`internal/service/trend_signal.go`（方向映射 + 趋势/信号计算）、`internal/model/analysis.go`（`AnalysisIndicator`）、`internal/web/app.js` 财务指标分析区（指标行模板约 950–975 行、`trendTip` 约 630–650 行）、`internal/web/style.css`（`.trend-dot` 约 414–422 行）。
>
> **决策更新（2026-09，用户拍板）**：颜色语义定为**绿 = 向好/健康、红 = 恶化/坏**（推翻评审阶段「红=向好」的推荐）；**股价行情卡片与三大报表同比保留 A 股「红涨绿跌」**（市场/数值口径，非好坏信号）。据此本需求范围从「加一个信号灯」升级为**「趋势信号灯 + 整页颜色语义重构」**：改写 FR-4/FR-6，新增 FR-7~FR-11（六维同比方向感知、行情与报表例外、AI 评分配色反转、图表主色、色令牌统一）。详见 Q2 决策记录。
>
> **决策更新 2（2026-09，用户预览实现后二次调整，取代原「中性不渲染圆点」约定）**：
> 1. **三态圆点全部渲染**：所有指标行都渲染 8px 圆点——绿=向好、红=恶化、**灰=中性/无信号**（含 `direction=neutral`、趋势平稳未超 5% 阈值、数据不足、维度非 `done`）。灰点 hover/聚焦给温和说明。改写 FR-4 样式与语义、FR-5 文案、FR-12 降级、FR-13 移动端，更新 AC-5~AC-9 与 AC-10/AC-12，新增 AC-24。
> 2. **tooltip 措辞按变化幅度分级**：`|R| < 20%` 用温和措辞（「略有改善 / 略有走弱」），`|R| ≥ 20%` 才用评价词（「向好 / 恶化」），阈值与模板见**新增 FR-16**（对应新增 AC-25~AC-27；用户反馈原措辞「恶化」对被小幅变化说重了）。
>
> 两条调整**只改展示与措辞，不改方向判断**：FR-1 方向属性、FR-2 趋势判定（5% 阈值）、FR-3 判定矩阵、附录 A 方向映射表**全部不变**。

## 1. 背景与目标

### 1.1 背景

R3「六维财务指标分析」当前把每个指标的**各年数值 + 同比涨跌（红涨绿跌）**竖排展示在一张表里。用户面对一屏 20–30 个指标时，存在两个痛点：

1. **「看懂」门槛高**：六维分析表的同比颜色只表达「数值变大还是变小」（`app.js` 的 `yoyClass`），**不表达「变大是好还是坏」**。例如「存货周转天数 +18%」显示红色（数值上涨），但天数上涨实为**经营效率恶化**；「财务杠杆倍数 +12%」同样显示红色，而杠杆升高是**财务风险加大**。用户需要自己知道每个指标的方向含义，才能把颜色翻译成好坏。
2. **看不出整体趋势**：同比只对比相邻两年，逐格读完才能拼出「这几年是变好还是变差」。用户希望**一眼扫过**就知道每个指标在所选年份范围内的走向是利还是弊。
3. **全页颜色语义不自洽**：同一页面存在两套相反的色彩观感——股价行情卡片与三大报表同比用 A 股「红涨绿跌」，而 AI 评分进度条 `scoreColor` 却是「红=优秀、绿=较弱」（见 `app.js` 约 544–549 行），雷达图与指标趋势图的主色又是品牌红（`#d64040`）。用户对同一个颜色在不同卡片里得到相反结论，需要统一。

因此本轮把需求从「加一个信号灯」升级为**「趋势信号灯 + 整页颜色语义重构」**：以「**绿=健康/好、红=恶化/坏**」作为全页统一的语义色，剔除「红涨绿跌」在**非行情、非原始科目**场景的误用；同时保留红涨绿跌在**市场/数值口径**场景的惯例。

### 1.2 目标

- 六维分析中**每一个指标**在指标名前呈现一个可见的趋势信号圆点，三态齐全：向好（绿）/ 恶化（红）/ 中性（灰）。
- 方向中性或趋势不显著的指标显示**灰色圆点**，表示「无明确向好或恶化的判断」，不引起警觉、不构成好坏误导。
- 六维分析表的**同比颜色改为方向感知**（绿=向好、红=恶化），与信号灯同一套语义，用户在一个表格内不再看到自相矛盾的红绿。
- 全页非行情组件的颜色语义统一为「绿=好、红=坏」：六维分析同比、信号灯、AI 评分进度条、指标趋势图主色、雷达图主色。
- **行情与原始科目例外**：股价行情卡片、三大报表原始科目同比**保持 A 股「红涨绿跌」不变**（它们表达的是市场「价格方向 / 数值涨跌」，不是好坏）。
- 趋势与方向判定规则**集中、可单点维护、可测试**；新增指标时只需补一条方向映射（该映射**同时驱动信号灯与六维同比色**），漏标时默认中性（不误报、不误染）。
- 移动端（≤768px）下信号可辨识，且不破坏现有指标行的布局与交互。

## 2. 用户故事 / 使用场景

- 作为看财报的个人投资者，我想要在扫一眼指标表时就看出**哪些指标在变好、哪些在变差**，以便不用先把每个指标的方向含义在脑子里过一遍。
- 作为关注经营效率的用户，我想要「资产周转率逐年升高」被标为**向好**、「存货周转天数逐年升高」被标为**恶化**，以便不被「都是数值上涨、都是红色」误导。
- 作为关注盈利质量的用户，我想要「息税前利润总额逐年下滑」被标为**恶化**，以便第一时间警觉，再点开趋势图看细节。
- 作为快速筛选公司的用户，我想要「金融资产占比」「营运资产占比」这类**没有绝对好坏**的结构占比显示**灰色圆点**（而非整行缺一个圆点），以便一眼扫过时行与行对齐、不需要分辨「这里为什么少了个点」。
- 作为同时看多张卡片的用户，我想要**绿色一律代表健康、红色一律代表恶化**（AI 评分、六维同比、信号灯、图表都一致），以便不用为每张卡片重新学习一遍颜色含义。
- 作为看行情的用户，我想要股价卡片和三大报表里的「红涨绿跌」保持 A 股惯例不变，以便用既有市场直觉读价格与科目数值。

## 3. 功能需求

### FR-1 每个分析指标携带「方向属性」（P0）

- **要求**：六维分析中每个 `AnalysisIndicator` 必须携带一个**方向属性**，取值仅三档：
  - `higher_better`：越高越好（如 ROE、毛利率、周转率、现金含量、利润总额）；
  - `lower_better`：越低越好（如营业周期、现金周期、周转天数、财务杠杆倍数、财务成本负担率）；
  - `neutral`：无明确好坏（如各类金额水平值、结构占比、净额类）。
- **覆盖范围**：以代码实际产出的指标 key 为准（当前 122 个，见附录 A）。附录 A 给出全部 key 的映射草案，作为本需求的组成部分。
- **兜底规则**：**任何未在映射表中的指标 key，一律按 `neutral` 处理**（渲染灰点，FR-4）。新增指标漏标方向时不得报错、不得误报向好/恶化。
- **口径提示**：方向属性表达的是「该指标数值升高，对公司质地是利还是弊」的**单指标含义**，与年份范围无关（不随选择范围变化）。

### FR-2 趋势判定规则（P0）

- **触发**：请求财务指标分析（`GET /api/stock/:code/analysis`）并返回 `done` 状态的维度时，对每个指标按**所选年份范围**（默认最近 5 个年报，最多 10 个）计算趋势。
- **输入**：该指标在所选年份范围内的数值序列，按**年份升序**，剔除 `null`（无数据）后得到有效序列 `S = [s1, …, sm]`（对应年份 `y1 < … < ym`）。
- **判定规则（推荐主口径：首末对比 + 相对阈值）**：
  1. `m < 2`（有效数据不足 2 个点）→ 趋势 = **无信号**。
  2. `s1 == 0` → 趋势 = **无信号**（首值为 0 时相对变化无经济含义，避免极小基数造成的假信号）。
  3. 计算相对变化率 `R = (sm − s1) / |s1|`（分母取绝对值，使「负值区间继续恶化 / 由负转正」也能得到有意义的符号）。
  4. 显著性阈值 `T = 5%`（可配置常量）：
     - `|R| < T` → 趋势 = **平稳**；
     - `R ≥ T` → 趋势 = **上升**；
     - `R ≤ −T` → 趋势 = **下降**。
- **输出**：每个指标得到 `无信号 / 平稳 / 上升 / 下降` 之一。
- **边界**：
  - 序列含 `null` 空洞时，只取**首个非空值**与**末个非空值**，中间空洞不参与（例：`[2020: 1.0, 2021: null, 2022: 1.2]` 用 1.0→1.2 判定）。
  - 全部为 `null` → 无信号。
  - 全部数值相等 → `R = 0` → 平稳。
  - 数值跨越零点（如净利润 −2 亿 → +3 亿）→ `R = (3 − (−2)) / 2 = +250%` → 上升，符合语义（扭亏为盈）。
  - 范围为 1 个年份（起止年相同）→ `m < 2` → 无信号。

### FR-3 好坏信号判定矩阵（P0）

- **要求**：由「方向属性 × 趋势」确定信号，判定矩阵如下（**必须严格按此表实现**）：

| 趋势 \\ 方向 | higher_better（越高越好） | lower_better（越低越好） | neutral（中性） |
| --- | --- | --- | --- |
| 上升 | 向好 | 恶化 | 中性 |
| 下降 | 恶化 | 向好 | 中性 |
| 平稳 | 中性 | 中性 | 中性 |
| 无信号 | 中性 | 中性 | 中性 |

- **输出**：每个指标得到 `向好 / 恶化 / 中性` 之一（或等价的枚举值），随指标数据一起返回给前端。三态与圆点颜色的对应：向好→绿、恶化→红、中性→**灰**（FR-4）。
- **说明**：`neutral` 方向的指标**无论趋势如何都为中性**；趋势不显著（平稳）或数据不足的指标**无论方向如何都为中性**。判定逻辑本身不变，变化的是「中性」的**展示方式**——由「不渲染」改为「渲染灰色圆点」（见 FR-4）。

### FR-4 信号灯展示：指标名前的独立圆点，三态全渲染（P0）

- **展示方式（推荐方案，取舍说明见 3.1）**：在指标行的指标名前放置一个**独立的小圆点**，作为信号灯。
- **位置与顺序**：在 `.ind-name` 弹性行内，顺序为 `[趋势按钮] [信号灯圆点] [指标名] [帮助?] [警告!]`。趋势按钮保持在行首（与所有指标行一致，不改变既有点击习惯），信号灯紧贴它所修饰的指标名。
- **样式要求**：
  - 圆点直径 `8px`、`border-radius: 50%`、行内 `inline-block`、垂直居中对齐（`align-items: center` 已由 `.ind-name` 提供）。
  - 颜色（**已定：绿=向好、红=恶化、灰=中性**）：
    - 向好 → 语义绿 `var(--good)` 即 `#149a5e`；
    - 恶化 → 语义红 `var(--bad)` 即 `#d64040`；
    - 中性 → 中性灰 `var(--neutral-bar)` 即 `#998c8c`（与 FR-10 中「中性/无信号」柱色同值同语义；不复用 `--up`/`--down`，也不复用品牌红）。
  - 圆点**不触发趋势图弹窗**（趋势图仍只由趋势按钮触发）；点击/聚焦圆点仅用于唤起说明文案（FR-5），因此需可聚焦（`tabindex="0"`）。
  - 不改变行高、不改变数值列宽度与列对齐。
- **三态全覆盖（取代原「中性不渲染」约定）**：**每一个指标行都必须渲染一个圆点**，不得出现「部分行有圆点、部分行没有」。
  - `向好` → 绿点；`恶化` → 红点；`向好/恶化` 以外的全部情况（方向中性、趋势平稳、数据不足、指标恒为空、维度非 `done`）→ **灰点**。
  - 灰点与绿点/红点**尺寸、位置、间距完全一致**，仅颜色不同；灰点同样可 hover / 聚焦 / 点击唤起温和说明（FR-5），且 aria-label 不得为空。
  - 灰点的 hover 样式不得使用品牌红或语义红（避免「中性」被误读为警示）。

#### 3.1 展示方式评审：独立圆点 vs 趋势按钮染色

| 维度 | 方案 A：独立圆点（推荐） | 方案 B：给趋势按钮染色 |
| --- | --- | --- |
| 语义 | 干净分离：按钮=「点击看趋势」（操作），圆点=「趋势方向」（状态） | 混淆：同一个 13px 图标同时承担操作与状态两种语义 |
| 可见性 | 8px 实心圆点对色块面积友好，移动端辨识度好 | 按钮是 1.5px 描边**空心线框**图标（见 `app.js` `chart-btn` 的 SVG，`fill="none"`），染色后是细线着色，小屏上辨识度低 |
| 交互冲突 | 无 | 现有 `.chart-btn:hover` 会变品牌色，hover 时**信号色被覆盖**，出现「一摸就变」的矛盾 |
| 实现 | 新增一个 `span` + 3 个类名，现有 DOM 结构不动 | 需修改按钮的类绑定，并处理 hover 覆盖的优先级 |
| 中性态 | 渲染灰点，与绿/红同尺寸同位置，全表行节奏一致、可整体扫读对齐（✅ 已定，见 Q9） | 染色后需再定义「中性」如何回退（透明线框=按钮消失感） |

**结论：推荐方案 A（独立圆点）**，方案 B 作为备选（见待确认 Q1）。

### FR-5 信号说明文案（P1）

- **触发**：鼠标悬停（桌面端）或点击/聚焦信号灯圆点时（移动端点击、键盘 Tab 聚焦）。**三态（绿 / 红 / 灰）都必须可触发，且都不得出现空文案**。
- **要求（绿点 / 红点）**：弹出 tooltip，用一句话说明「范围 + 数值变化 + 方向解读 + 结论」，句式为固定模板（末词的轻重由**FR-16 幅度分级**决定）：
  - 向好：`近 {N} 年{指标名}由 {s1}{unit} {升至/降至} {sm}{unit}（{R}%），{方向解读}{结论词}`
  - 恶化：同上，仅替换 `{结论词}`
  - 其中 `N = ym − y1 + 1`（范围内年份跨度），`{方向解读}` 取该维度/指标的方向短语（如「经营效率」「盈利能力」「债权人保障」），`{R}` 为 FR-2 同一口径的首末相对变化率（分母取 `|s1|`），数值单位格式沿用现有数值格式化（元→亿/万）。
- **要求（灰点）**：灰点 tooltip 必须**温和陈述事实、不含「向好 / 恶化 / 改善 / 走弱」这类评价词**，按中性原因给出对应文案：
  - 方向 `neutral`（可算出 `R`）：`近 {N} 年{指标名}由 {s1}{unit} {升至/降至} {sm}{unit}（{R}%），该指标无明确好坏方向`
  - 方向有向但趋势平稳（`|R| < 5%`）：`近 {N} 年{指标名}变化不大（{R}%），趋势平稳`
  - 数据不足（有效点 < 2 / 全为空 / 首值为 0 / 指标恒为空）：`{指标名}在所选范围内数据不足，暂无法判断趋势`
  - 维度非 `done`：`该维度暂无数据，暂无法判断趋势`
- **示例**：
  - 绿点：「近 5 年资产周转率由 0.52 次升至 0.58 次（+11.5%），经营效率略有改善」（`|R| < 20%`，温和措辞）；`+25%` 时末词为「向好」。
  - 红点：「近 4 年息税前利润总额由 8.10 亿降至 6.20 亿（−23.5%），盈利能力恶化」（`|R| ≥ 20%`）；`−8%` 时末词为「略有走弱」。
  - 灰点：「近 5 年金融资产占比由 12.00% 升至 15.00%（+25.0%），该指标无明确好坏方向」。
- **无障碍**：tooltip 必须可通过键盘聚焦触发（沿用现有 `tabindex="0"` + `el-tooltip :trigger="['hover','focus']"` 模式），因为颜色单独不足以传达信息。
- **降级**：如因异常无法生成灰点文案，回退为通用短句「暂无趋势判断」，**不得渲染空 tooltip 或隐藏圆形占位**（保持三态行对齐不变）。

### FR-6 颜色语义分界与解耦（P0）

- **要求**：全页明确划分两套颜色语义，二者**不得混用**，且必须在实现上**相互隔离**：

| 语义域 | 含义 | 适用组件 | 颜色规则 |
| --- | --- | --- | --- |
| **好坏口径** | 绿=健康/好、红=恶化/坏 | 六维分析表同比、趋势信号灯、AI 评分进度条、指标趋势图主色、雷达图主色 | 与方向映射表（附录 A）一致 |
| **数值/行情口径** | 红=涨、绿=跌 | 股价行情卡片（价格、涨跌幅）、三大报表原始科目同比 | **保持现状不变** |

- **解耦要求**：六维分析表的同比着色与三大报表的同比着色**必须使用不同的样式类**，不得共用同一套颜色类（现状是二者共用 `yoyClass()` 返回的 `.up` / `.down`，见 `app.js` 的 `yoyClass` 与 `style.css` 约 289–291、370–371 行）。改造后：
  - 三大报表（`stmt-table`）继续用原「数值涨跌」类；
  - 六维分析表（`analysis-table`）使用新的「方向感知」类，颜色由方向映射表 + 数值变化方向共同决定。
- **变量命名要求**：`--up` / `--down` 的语义**保留为「数值涨跌」专用**，不得再被语义色复用；新增语义色令牌 `--good`（`#149a5e`）与 `--bad`（`#d64040`）供好坏口径组件使用。
- **一致性要求**：同一指标在同一屏内，趋势信号灯颜色与六维分析表同比颜色必须**语义一致**（都向好则都绿、都恶化则都红），不得出现「圆点绿、同比红」。

### FR-7 六维分析表同比色改为方向感知（P0）

- **触发**：财务指标分析（六维）表格渲染时。
- **要求**：六维分析表每个数值下方的同比，颜色由**「该指标方向 × 本年数值相对上年变化方向」**决定，复用附录 A 的方向映射表，规则与信号灯判定矩阵（FR-3）同构：

| 今年相对上年 | higher_better | lower_better | neutral |
| --- | --- | --- | --- |
| 上升 | 向好（绿） | 恶化（红） | 无色 |
| 下降 | 恶化（红） | 向好（绿） | 无色 |
| 持平 | 无色 | 无色 | 无色 |

- **输出**：如「存货周转天数 +18%」（`lower_better`）显示**红**（恶化）；「资产周转率 +11%」显示**绿**（向好）；「金融资产占比 +3%」（`neutral`）**不着色**（保持默认文字色）。
- **边界**：沿用既有 `yoyText` 的显示规则（范围内最早年无上年数据、上年为 0 或负时只显示数值不显示百分比）——**无论是否显示百分比文本，着色规则不变**；上年为 0 或负时（相对变化率无定义）**不着色**。
- **中性方向**：`neutral` 方向指标的同比**一律不着色**（当前是机械的涨红跌绿，改造后统一为默认文字色），以避免「好坏」语义被强行赋予无好坏意义的指标。
- **与信号灯的区别（勿混淆）**：本节的「无色」指**同比文字不着色**（同比是逐年单元格信息，不存在灰色文字态）；信号灯的灰点（FR-4）是**每行唯一一个**、位于指标名前的状态点，二者互不影响。同一指标可以「同比文字无色 + 圆点为灰」或「同比文字有色 + 圆点为绿/红」（口径不同：同比比相邻两年、圆点比范围内首末）。

### FR-8 行情与三大报表颜色保持不变（P0）

- **要求**：以下组件**不得改动**着色规则，且需回归验证：
  - 股价行情卡片：`stock-price`、`stock-chg` 的「涨红跌绿」（`app.js` 模板中 `data.quote.change_pct >= 0 ? 'up' : 'down'`）。
  - 三大报表（利润表 / 资产负债表 / 现金流量表）数值列同比：继续按**数值涨跌**着色（红涨绿跌）。
- **理由**：二者表达的是市场「价格方向」与原始科目的「数值涨跌」，属行业惯例与客观口径，不承载好坏判断。
- **口径提示**：三大报表同比与六维同比在 `lower_better` 指标上可能出现**同向数值、异色**（例如同一现象在报表里是红、在六维里是红或绿取决于指标方向）。这是**设计意图**，需在 `docs/产品设计文档.md` 中写明分界（见第 5 节）。

### FR-9 AI 评分进度条配色反转（P0）

- **要求**：`scoreColor(score)`（`app.js` 约 544–549 行）的分档配色**反转为「绿=优秀、红=较弱」**，并给出四档连续色阶，保证相邻档位过渡和谐（同色相带上依次偏移，避免跳色）：

| 分档 | 含义 | 现值 | 改为 | 色相 |
| --- | --- | --- | --- | --- |
| 90–100 | 优秀 | `#d64040`（红） | `#149a5e`（绿） | 绿 |
| 75–89 | 良好 | `#e8833a`（橙） | `#6aa84f`（黄绿） | 黄绿 |
| 60–74 | 一般 | `#d9a240`（琥珀） | `#d9a240`（琥珀，不变） | 琥珀 |
| <60 | 较弱 | `#149a5e`（绿） | `#d64040`（红） | 红 |

- **说明**：色阶从绿 `#149a5e` → 黄绿 `#6aa84f` → 琥珀 `#d9a240` → 红 `#d64040` 构成连续色相带，分档可辨且无突兀跳变；琥珀色作为中间档**保持不变**，避免用户对「中等」的既有认知被打破。
- **边界**：分数为 `null` / 非数字 / 越界（<0 或 >100）时按现有 `el-progress` 行为处理，不新增异常分支。

### FR-10 图表主色改为「健康绿 / 恶化红」（P1）

- **要求**：把图表主色从品牌红 `#d64040` 改为语义色，**图中颜色必须与指标方向/趋势一致**：
  - **指标趋势图**（`buildIndicatorChartOption`，`app.js` 约 53–136 行）：
    - 柱状系列主色按**该指标的信号**（FR-3）取值：向好 → 绿 `#149a5e`；恶化 → 红 `#d64040`；无信号 / 中性 → 中性灰 `#998c8c`（避免中性指标被染成红而与「恶化」混淆）。
    - **负值柱无论信号如何一律用红**（负值本身即警示）。
    - 同比增速折线维持中性琥珀 `#d97706`（增速是「数值涨跌」而非好坏，无需语义化）。
  - **雷达图**（`buildRadarOption`，`app.js` 约 163–189 行）：折线 / 数据点 / 区域填充从品牌红与蓝改为**绿色系**（如折线 `#149a5e`、填充 `rgba(20,154,94,0.18)`），背景分层色由蓝改为绿色淡染，保持与「财务评分越高越好」语义一致。
- **边界**：图表 tooltip、图例、轴名的文字色**不变**（属中性信息，不需语义色）。
- **说明**：若用户希望图表**只表达数值正负**而不表达「该指标的好坏」（即不使用方向映射），则简化为「正值绿 / 负值红」——二者取一，见待确认 Q8。

### FR-11 展示色令牌可维护性（P1）

- **要求**：好坏口径的颜色必须来自统一的 CSS 令牌（`--good` / `--bad`，必要时补 `--good-soft` / `--bad-soft`），JS 中的配色（`scoreColor`、ECharts `itemStyle.color`）也必须引用同一组色值常量，**不得在各处硬编码红色/绿色的十六进制值**（现状 `app.js` 内多处硬编码 `#d64040` / `#149a5e`，改色时易漏改）。
- **中性格令牌**：中性灰统一使用既有 `--neutral-bar`（`#998c8c`，CSS 侧）与 `PALETTE.neutral`（JS 侧），供**信号灯灰点**（FR-4）与**图表中性柱**（FR-10）共用；不得为灰点另引一个新色值。
- **依据**：本轮一次性反转多处配色语义，硬编码会导致「改了信号灯忘了进度条」类不一致。

### FR-12 边界与降级：无信号时的灰点（P0）

- **要求**：以下情况**不判为向好/恶化**，一律渲染**灰色圆点**（FR-4）+ 温和文案（FR-5），且不产生错误、不产生空 tooltip：
  1. 维度 `status != "done"`（`pending` / `no_data`）——整维度不参与信号判定，该维度下每个指标渲染灰点。
  2. 指标在所选范围内有效数据点 `< 2`。
  3. 指标全部为 `null`。
  4. 指标方向未标注或标为 `neutral`。
  5. 趋势判定为「平稳」（`|R| < 5%`）。
  6. 首值 `s1 == 0`。
  7. 恒为空的指标（当前为 `fixed_asset_new_rate` 固定资产成新率，因原始值不可得恒为空）——自然落入第 3 条。
- **一致性要求**：以上任一条命中时，**圆点仍然渲染**（灰），只是不承载好坏判断——行的视觉结构不因数据缺失而变化（这是本次调整的核心动机）。
- **异常**：单指标计算信号时发生任何异常，必须**只影响该指标**（降级为灰点）并记录日志，不得导致整个分析接口返回失败，也不得导致该行缺失圆点。

### FR-13 移动端适配（P1）

- **要求**：`≤768px` 视口下：
  - 圆点尺寸不小于 `8px`，三态（绿/红/灰）颜色与桌面端一致；
  - 不因新增圆点导致指标名列换行、行高跳变或数值列错位；
  - 圆点可通过**点击**（tap）唤起 tooltip 文案（移动端无 hover），**三态均可点击且文案非空**。
  - 与现有横向滑动切换维度标签的手势（`tabTouchStart` / `tabTouchEnd`）不冲突——点击圆点不得被判定为滑动。
- **说明**：现有 `.analysis-table .help-icon { display: none; }` 的移动端隐藏规则**不适用于信号灯**（信号灯在小屏上价值更高，必须保留）。

### FR-14 方向映射的可维护性（P1）

- **要求**：
  - 方向映射必须**集中维护在一处**（单一数据源），不得散落在各维度构造函数中逐条硬编码，也**不得只存在于前端**（避免前后端两份真相）。
  - 映射以**指标 key** 为键；key 与方向的对应关系需有测试覆盖（至少覆盖「全部已产出 key 都在映射表内或显式允许缺省」）。
  - 信号（趋势 + 方向 → 向好/恶化/中性）的计算规则与方向映射同为**可测试的纯逻辑**。

### FR-15 非功能要求

- **性能**：信号计算为纯数值运算，不新增对外数据请求、不新增接口往返；分析接口响应时间不因本需求产生可感知变化（<10ms 级）。
- **兼容性**：桌面端（>768px）与移动端（320–768px）均正常；不改变现有 DOM 结构与列对齐；不新增第三方依赖。
- **可访问性**：颜色不得是**唯一**的信息载体——三态圆点（含灰点）都必须有 tooltip 文案（FR-5）与键盘可聚焦（FR-5 无障碍条）；灰点不得退化为「无法聚焦、无文案的装饰点」。
- **易用性**：信号灯不引入新的点击跳转/弹窗层级；点击圆点不展开趋势图（趋势图仍由趋势按钮触发）。
- **文案稳健性**：tooltip 措辞必须与变化幅度匹配（FR-16），不得对小幅变化使用「恶化 / 向好」这类强评价词。

### FR-16 tooltip 措辞按变化幅度分级（P1）

- **背景**：用户反馈——「有些指标的趋势走坏得不明显、幅度较小，说明里却用了『恶化』，过于吓人」。小幅波动（如 −8%）用「恶化」属**过度评价**，需按幅度收放用词。
- **分级依据**：首末相对变化率的绝对值 `|R|`（`R` 与 FR-2 完全同口径、同一次计算，`R = (sm − s1) / |s1|`，属纯展示分级，不参与信号判定）。
- **阈值常量**：`MILD_THRESHOLD = 20%`（可配置常量，命名建议 `mildChangeThreshold`；与 FR-2 的显著性阈值 `T = 5%` **相互独立**，二者职责不同、不得互相替代）。
- **文案分级（`{结论词}` 取值）**：

| `|R|` | 结论词（向好） | 结论词（恶化） | 用词性质 |
| --- | --- | --- | --- |
| `|R| < 20%` | 略有改善 | 略有走弱 | 温和陈述，不含评价词 |
| `|R| ≥ 20%` | 向好 | 恶化 | 明确评价 |

- **完整模板**（`N = ym − y1 + 1`，`{方向解读}` 同 FR-5）：
  - 绿点（向好）：`近 {N} 年{指标名}由 {s1}{unit} {升至/降至} {sm}{unit}（{R}%），{方向解读}{结论词}`
  - 红点（恶化）：同上，`{结论词}` ∈ {略有走弱, 恶化}
- **示例（同为恶化方向，措辞随幅度变化）**：
  - `−6%` → 「近 3 年存货周转天数由 120.00 天升至 127.20 天（−6.0%）……」——注意此处**数值上升**，`{升至/降至}` 必须按数值方向取「升至」，末词为「略有走弱」。
  - `−28.9%`（毛利下滑）→ 「近 5 年毛利率由 45.00% 降至 32.00%（−28.9%），盈利能力恶化」。
- **约束**：
  - 分级**只影响 tooltip 文字**，**不影响颜色**（`|R| < 20%` 的向好仍是绿点、恶化仍是红点，不做深浅色分层），也不影响 FR-2/FR-3 的信号判定。
  - 数值方向词（`{升至/降至}`）由 `sm` 与 `s1` 的大小关系决定；结论词（`{结论词}`）由**向好/恶化极性**决定，二者独立——保证 `lower_better` 指标（如存货周转天数数值上升=恶化）不会出现「上升 + 略有改善」这类自相矛盾的组合（见 Q10.1）。
  - 阈值常量集中定义、可单点调整；调整后仅改变措辞轻重，回归测试应验证「同一指标 `|R|` 跨过 20% 时颜色不变、仅末词切换」。

## 5. 边界与约束

- **不做**：
  - **不修改三大报表与股价行情**的「红涨绿跌」着色（见 FR-8）。
  - **不修改品牌主色 `--brand`（`#d64040`）的装饰性用法**——品牌标识、主按钮、Tab 选中下划线、搜索框聚焦、`chart-btn`/`help-icon` 的 hover 色、页面渐变等**保持红色不变**（见待确认 Q8）。
  - 不修改趋势图弹窗、AI 智能分析（R5）与估值（R4）的既有**业务逻辑与文案**；不把信号灯喂给 AI 分析（后续可另立需求）。本需求只改它们的**配色**。
  - 不为 `neutral` 指标提供「按行业/公司类型改变方向」的上下文判定（如银行股的营业成本率）。
  - 不引入绝对值阈值以外的更复杂统计模型（显著性检验、回归置信度等）作为 P0 范围。
- **依赖**：依赖六维分析正常产出 `done` 维度与指标数值；依赖既有年份范围选择交互（`analysisStartYear` / `analysisEndYear`）。
- **已知限制**：
  - 首末对比口径在「V 型反转」场景可能与直觉不符（中间年份大跌、首末净变化不大时判为平稳，属预期内的保守处理）。
  - 部分指标的方向存在合理争议（见附录 A 标注与待确认 Q4），需用户拍板；该映射现**同时驱动信号灯与六维同比色**，影响面比原先更大。
  - 阈值 5% 对金额类小基数指标较敏感、对大基数指标较钝，统一口径下为可接受的折中。
  - **措辞阈值 20% 为经验值**（FR-16）：`|R|` 处于 5%–20% 区间时颜色为绿/红但用词温和，用户可能感到「明明变差了却没说重」。这是本次调整的**有意取舍**（宁少吓人、不多惊扰）；若实际使用中觉得过于含蓄，可直接下调该常量（如 15% / 10%），无需改动判定逻辑。
  - **灰色圆点数量可能偏多**：附录 A 中 45.1% 的指标为 `neutral` 方向，加上趋势平稳与缺失数据的指标，灰点占比预计过半，需要用户实际观感确认是否「灰点太多、信号被稀释」（见 Q9.2）。
  - **同页仍并存两套颜色语义**（好坏口径 vs 数值/行情口径，见 FR-6）：三大报表同比与六维同比在 `lower_better` 指标上可能「同向数值、异色」。这是已确认的设计，但需在产品文档写明分界，否则用户仍可能困惑（见待确认 Q7）。
  - **品牌红与语义红同值**（均为 `#d64040`）：页面上的红既可能是装饰（品牌），也可能是「恶化」（语义），二者视觉不可区分（见待确认 Q8）。
- **口径延续**：金额单位沿用既有「元」；百分比指标单位为 `%`；比率类（周转率）单位为「次」。tooltip 中的变化率一律为**相对变化率**，并标注符号。措辞分级口径（FR-16）：`|R|` 相对**首末有效值**计算，不取各年同比均值；`|R|` 恰好等于 20% 时按 `≥ 20%` 处理（用评价词）。
- **文档同步**：落地后需在 `docs/产品设计文档.md` 中补充「颜色语义规范」小节（好坏口径 vs 数值/行情口径的分界、各组件配色表），供后续迭代遵循。

- **Q10 tooltip 措辞幅度分级（✅ 已定，2026-09 用户预览后拍板，阈值与文案可调）**
  - **决策**：按 `|R|` 分级——`|R| < 20%` 用温和措辞（向好→「略有改善」、恶化→「略有走弱」）；`|R| ≥ 20%` 用评价词（「向好 / 恶化」）。见 FR-16。**理由（用户原话）**：「趋势走坏得不是很明显、幅度较小，说明里却用了『恶化』，过于吓人」。
  - **Q10.1 结论词按「好坏极性」还是「数值方向」？**（本需求已按前者落文档，请用户确认）：用户原话为「上升→小幅上升，略有改善；下降→小幅回落，略有走弱」，按字面读会与指标方向冲突——例如「存货周转天数」数值上升属**恶化**，字面模板却给出「略有改善」。**推荐：末词（改善/走弱）按向好/恶化极性取，数值动向由句中的 `升至/降至` 表达**（即 FR-16 的写法），否则会出现红点 + 「略有改善」的自相矛盾。备选：严格照字面按数值方向定末词（**不推荐**，会误导）。
  - **Q10.2 阈值 20% 是否合适？** **推荐 20%**（约等于「五年内平均年化 4% 以上的变化」，能覆盖多数有意义的经营趋势，同时避免把 5%–15% 的常规波动说成恶化）。备选：`15%`（更谨慎、更少用评价词）或按指标类型分档（金额类 20%、比率类 10%）——分档更精细但增加维护成本与解释成本，**本期不推荐**。
