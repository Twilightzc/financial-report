# 估值基期现金流自定义与单位选择

> 来源：用户反馈（2026-09-27）：「我想在公司估值功能中增加基期现金流自定义选项，然后可选单位，如千、万、亿，也可以不选单位纯输入完整的数字，注入输入框依旧要保持对齐整洁」。
>
> 对应现状代码：`internal/service/valuation.go`（`selectBaseFCF` 约 171–232 行、`ComputeValuation` 约 59–166 行、`rdExpansion` 约 234–247 行）、`internal/api/handler.go`（`GetValuation` 约 239–272 行、`parseValuationParams` 约 310–330 行）、`internal/model/valuation.go`（`ValuationParams` / `ValuationResult`）、`internal/web/app.js`（估值状态约 247–277 行、`fetchValuation` 约 488–515 行、估值表单模板约 1181–1205 行、结果表约 1208–1252 行）、`internal/web/style.css`（`.val-form` / `.val-fields` / `.val-field` / `.val-unit` 约 453–507 行，移动端媒体查询约 595 行）。相关既有文档：`docs/公司股票估值.md`。
>
> 说明：本需求只登记「要什么」，不涉及技术实现方案（接口字段、组件结构等由 `techexpert` 在技术设计中确定）。

## 1. 背景与目标

### 1.1 背景

「公司估值」功能（现金流贴现法 DCF）当前的**基期自由现金流**只能由程序从报表推导，用户可在下拉框选择 4 种选取方式：

- `latest` 最近一年；
- `average` 近几年平均值（配合「选取年数」）；
- `median` 近几年中位数（配合「选取年数」）；
- `trim_mean` 去极值平均值（配合「选取年数」）。

这些方式都基于财报数据自动计算，用户**无法直接指定一个具体的基期现金流数值**。实际使用中，估值者常有自己的判断（例如按行业可比公司调整、按自己的自由现金流口径估算、按研报给定的数值），当前无处录入。

同时，自由现金流金额量级大（茅台 2024 年约 600 亿元级），若只能按「元」输入完整数字，用户需要输入 11 位数字（如 `60000000000`），既繁琐又极易数错位数；因此需要提供「千 / 万 / 亿 / 不选单位」的换算输入方式。用户还明确要求输入区**保持对齐整洁**——这是既有的界面约定（`.val-form` 通过 `--val-label-w` / `--val-input-w` 保证 label 列与输入框列的跨行列对齐，见需求文档 `ui-polish-and-ai-rd-adjust.md` 主题 A），新增控件不得破坏。

### 1.2 目标

- 用户在「基期现金流」选取方式中可选**自定义**，并手动录入一个基期自由现金流数值；该值是**唯一**参与后续 DCF 贴现的基期自由现金流来源（不再由程序从报表自动推导）。
- 用户可选择输入数值的**单位（千 / 万 / 亿）**，也可**不选单位**（即按「元」输入完整数值）；系统按所选单位换算为「元」参与计算。
- 自定义输入区在桌面端与移动端（≥320px 宽）**保持 label 列 / 输入框列对齐、无横向溢出**，与现有估值表单风格一致。
- 未使用自定义时，现有 4 种选取方式的**行为、参数与展示完全不变**（向后兼容）。

## 2. 用户故事 / 使用场景

- 作为对某公司自由现金流有自己判断的估值者，我想要在估值表单里直接填入一个基期自由现金流数值，以便用我自己估计的现金流（而非程序从报表推导的值）跑 DCF 得到估值。
- 作为不熟悉财务的普通用户，我想要在输入金额时选择「亿」或「万」作为单位，以便不用敲一长串零、也不会数错位数。
- 作为需要精确取数的用户，我想要在某些情况下不选单位、直接输入完整的元数值，以便与报表口径逐位对齐。

## 3. 功能需求

### FR-1 新增「自定义」基期现金流选取方式（P0）

- **触发**：用户在「基期现金流」下拉框中选中「自定义」。
- **要求**：
  - 「基期现金流」下拉框在现有 4 项（最近一年 / 近几年平均值 / 近几年中位数 / 去极值平均值）基础上**新增一项「自定义」**，作为同一控件的第 5 个选项（本需求约定），而非另起一个独立控件。默认选项保持为「最近一年」，**不改变**现有默认行为。
  - 选中「自定义」后，表单**展开出现**数值输入框与单位选择（见 FR-2）；未选中时二者不展示，界面与现状一致。
  - 选中「自定义」后，基期自由现金流**完全由用户输入决定**，不再由程序从「经营活动现金流量净额 − 保全性资本支出」逐年推导、也不再按往年取平均/中位数。
- **输入**：一个金额数值 + 一个单位。
- **输出**：换算为「元」的基期自由现金流，参与后续 DCF 计算；结果区「经营资产自由现金流（基期）」展示该值。
- **边界**：若自定义输入为空或非法（见 FR-4），不发起计算并给出提示。

### FR-2 单位选择与换算口径（P0）

- **触发**：选中「自定义」（FR-1）。
- **要求**：紧贴数值输入框之后提供单位选择，可选值为：

  | 单位 | 换算系数（→ 元） |
  | --- | --- |
  | 千 | ×1,000（1e3） |
  | 万 | ×10,000（1e4） |
  | 亿 | ×100,000,000（1e8） |
  | （不选单位） | ×1（即直接按「元」输入完整数值） |

  - 换算后统一以「元」参与 DCF 计算，与现有基期自由现金流口径一致（项目内部一律以元计，亿/万仅作展示与输入口径，延续既有「口径写进文档」习惯）。
  - 单位选择必须有明确的当前态展示；「不选单位」以**单位下拉显式提供「元」选项**表示（已决策，见第 7 节 Q6），不得出现「看起来没选、实际按亿算」的歧义。
  - 单位默认值：**「亿」**（已决策，见第 7 节 Q2）。
- **输出**：用户输入的「数值 × 单位系数」= 元为单位的基期自由现金流。
- **异常/边界**：切换单位不改变用户已输入的数值（数值与单位相互独立），但会改变换算后的金额，须在用户点击「计算估值」时以**最新**的「数值 + 单位」组合计算。

### FR-3 数值输入格式与精度（P0）

- **触发**：在自定义数值输入框中录入。
- **要求**：
  - 只接受**正数**数值输入，允许小数。
  - 小数位数**最多 2 位**（已决策，见第 7 节 Q3）；不使用千分位分隔符输入。
  - 换算为「元」时按精确换算（如 `6.5 亿` = `650,000,000` 元），换算过程不四舍五入；展示层沿用结果区既有格式化（`fmtYi` 以亿展示）。
- **边界**：超大数值须有上限守卫，**换算后金额 ≤ 1e14 元**（已决策，见第 7 节 Q4），避免极端值导致后续计算数值溢出或明显的误输入被接受。

### FR-4 输入校验与提示（P0）

- **触发**：用户点击「计算估值」（或自定义输入失焦/非法）。
- **要求**：
  - 输入为空：提示「请输入基期现金流」，不发起计算。
  - 非数字字符：输入控件须阻止非数字录入（含负号、字母）；若被绕过（如粘贴），不得提交非法请求。
  - 数值 ≤ 0：提示「基期现金流需大于 0」，不发起计算（自定义数值由用户直接给定，≤0 属于**输入错误**，与系统推导值的「不适用」语义不同，须给出可读的针对性提示）。
  - 换算后金额超过上限（1e14 元）：提示上限说明，不发起计算。
  - 后端**仍须保留**「基期自由现金流 ≤ 0 → 现金流贴现法不适用」的兜底校验（防止绕过前端的非法请求），但正常前端交互下该分支不应被自定义模式触发。
- **输出**：非法输入有明确中文提示，界面不展示过期/错误的估值结果。

### FR-5 与「研发调整」开关的关系（P0）

- **触发**：选中「自定义」且用户开启了「研发调整」开关（`adjust_rd`）。
- **要求**（关键口径，已决策，见第 7 节 Q1）：研发调整对自定义模式**仍然生效**——最终基期自由现金流 = 自定义换算值 **+** 研发投入扩张部分（本年度研发费用 − 上年度研发费用，>0 时）。
  - 理由：现有实现中研发调整是在基期选取**之后**统一叠加的（`ComputeValuation` 中 `fcf += rdAdj`），研发扩张额是「相对上年度」的增量，与基期用什么方式选取无关；若自定义模式下不叠加，会造成同一开关在不同选取方式下行为不一致，用户难以理解。
  - 结果区沿用既有提示：当 `adjust_rd` 为真且扩张额 > 0 时，展示「（含研发扩张加回 X）」（现有模板已具备）。
  - 若上年度研发数据缺失（`rdExpansion` 返回 0），自定义模式下即按自定义值计算，不额外调整。
- **输出**：最终参与 DCF 的基期自由现金流已含研发扩张加回；结果区可见加回金额。
- **说明**：此为已确认口径，自定义值即基底 FCF，研发调整在其上叠加。

### FR-6 与「选取年数」的互斥（P0）

- **触发**：切换到 / 切离「自定义」。
- **要求**：
  - 选中「自定义」时，「选取年数」输入框**隐藏**（自定义不涉及年份范围）。
  - 选中「自定义」时，计算请求**不得**携带生效的年数参数（或携带时被忽略），避免歧义。
  - 切回其他选取方式时，「选取年数」恢复显示并保留原值（不清零）。

### FR-7 结果展示与说明（P1）

- **触发**：自定义模式下计算成功。
- **要求**：
  - 结果区「经营资产自由现金流（基期）」展示换算后的元值（沿用 `fmtYi` 亿展示）。
  - 结果元信息（`val-meta`）中「基期FCF取……」应显示为「自定义」或等价可读文案，不得沿用其它选取方式的名称或错误展示年数。
  - 提供一个说明性文案（`val-desc` 或 `notes`），说明自定义值为用户手动给定、单位换算口径为「千/万/亿 = ×1e3/1e4/1e8」，以及研发调整是否叠加（呼应 FR-5）。

### FR-8 布局对齐与移动端适配（P0）

- **触发**：自定义输入区渲染（含桌面端与 ≤768px 移动端）。
- **要求**：
  - 自定义数值输入框**复用**现有 `--val-input-w`（130px）统一宽度约定，保证与表单内其他数值框左右边缘对齐、跨列对齐关系不变（衔接 `ui-polish-and-ai-rd-adjust.md` 主题 A 的既有约定）。
  - `[label] [数值输入框] [单位选择]` 在同一 `.val-field` 行内排布，间距与现有 `.val-field` 一致（gap 8px）、单位紧随输入框；label 列保持 `--val-label-w` 定宽，单位列起止位置与其它字段的单位（`%` / `年`）竖列基本对齐。
  - 移动端（≤768px，`.val-fields` 退化为单列）自定义行**不得横向溢出**；当 `[label 92px] + [输入框 130px] + [单位]` 在窄屏（低至 320px 视口）放不下时，优先保证数值完整可读，允许单位选择控件收窄（或按移动端规则换行），不得出现数值被裁切或越过卡片边界。
  - 自定义输入区展开/收起不应造成表单明显跳动（布局抖动），推荐预留稳定宽度、控件高度与原表单一致。
- **边界**：字段因 grid `auto-fill` 换行使某行字段数不同时，允许右侧留空，但对齐关系不得错乱。

### FR-9 模式切换时自定义值的保留（P1）

- **触发**：用户先填了自定义值，再切回其他选取方式，之后又切回「自定义」。
- **要求**：自定义数值与所选单位**保留**，不清空、不重置为默认（除非用户手动修改）。切换到其他选取方式时，自定义值仅**不参与**当前计算，但仍随前端状态保留。

### FR-10 计算触发时机（P0）

- **触发**：自定义数值或单位发生变化。
- **要求**：沿用现有约定——**不**因输入即自动重算，统一由用户点击「计算估值」按钮触发计算（`fetchValuation`）；`doSearch` 的既有触发行为不变。切换「基期现金流」为「自定义」本身也**不**自动重算。

## 4. 非功能需求

- **性能**：自定义模式不增加额外数据拉取，估值接口耗时不高于现状（自定义模式下理论上无需按多年份推导，但不强制优化）。
- **兼容性**：
  - 前端为 CDN 方式加载的 Vue 3 + Element Plus，无构建步骤；新增控件的实现须沿用现有控件（如 `el-input-number` / `el-select`），不得引入需构建或新增依赖的方案。
  - **接口向后兼容**：不带自定义参数的请求，行为与改动前完全一致（`fcf_mode` 的 4 个既有取值语义不变）。
- **移动端**：桌面端与 ≥320px 视口移动端均不横向溢出（见 FR-8）。
- **易用性**：单位「不选单位」与「选中某单位」在界面上必须可区分、无歧义；提示文案统一中文。
- **安全**：前端对输入做格式/范围校验；后端对换算后金额做独立兜底校验，不信任前端传入值。

## 5. 边界与约束

- **只改「基期自由现金流」的取值来源**，不改变 DCF 四种模型（零增长 / 永续 / 两阶段 / 三阶段）的公式、折现率与增长率口径、金融资产与长期股权投资价值口径、债务价值口径。
- 自定义值一律以**元**为内部口径参与计算（此前的「千/万/亿」仅为输入换算口径）。
- 自定义模式**不**改动报表推导逻辑，但**不解耦报表依赖**（已决策，见第 7 节 Q5）：仍要求能取到年报数据（金融资产 / 长期股权投资 / 有息债务等科目本就来自报表），仅将「基期 FCF」一项替换为用户输入。
- AI 智能分析的「套用到估值」（`applyAIValuation`）不改动 `fcf_mode` 与自定义值，保持用户当前选择。
- 不涉及估值以外的模块（三大报表、六维分析、AI 评分等）。
- 已知限制：不提供「千分位分隔符输入」与「科学计数法」。

## 7. 已决策记录

以下 6 项已于 2026-09-27 经用户拍板确认，作为定稿口径；正文相关 FR 已同步。

- **Q1 自定义值与研发调整的关系 → 仍生效叠加（已决策）**：研发调整开关对自定义模式仍然生效，最终基期自由现金流 = 自定义换算值 + 研发扩张额，与既有四种模式叠加逻辑一致；结果区复用「（含研发扩张加回 X）」提示。对应 FR-5。
- **Q2 单位默认值 → 「亿」（已决策）**：默认选中「亿」。本项目结果区本就以「亿」展示（`fmtYi`），自由现金流常在数亿至数百亿量级，用「亿」输入数字最短、最不易数错。对应 FR-2。
- **Q3 小数与精度 → 允许最多 2 位小数（已决策）**：允许小数、最多 2 位；换算过程不四舍五入，以换算后的元值参与计算。对应 FR-3。
- **Q4 数值上限 → 换算后 ≤ 1e14 元（已决策）**：以换算后金额 ≤ 1e14 元（100 万亿元量级）作为防溢出/防误输入守卫，超限提示且不发起计算。对应 FR-3、FR-4。
- **Q5 报表依赖 → 不解耦（已决策）**：自定义估值仍要求取到年报数据（金融资产 / 长期股权投资 / 有息债务等科目本就来自报表）；仅将「基期 FCF」一项替换为用户输入，其余口径与前置条件不变。对应第 5 节「边界与约束」。
- **Q6 「不选单位」呈现 → 下拉显式提供「元」选项（已决策）**：单位下拉显式提供「元」选项代表「不选单位（按元输入完整数值）」，避免出现「空选但按某单位算」的歧义。对应 FR-2。
