# R13 技术方案：AI 基期自由现金流推荐（确定性推导 + 一键套用）

> **「基期自由现金流推荐功能仍存在，但已与全局 x/volatile 解耦（R15 P2~P4）；`RecommendBaseFCF` 现签名 `(fcfByYear, years, cycle)`，可持续增速 gS 改用 FCF 自身增速中位数（clamp 到 15%），不再用全局基准增速 X。最新口径见 R15 §19。」**

> 需求文档：`docs/R13-AI基期自由现金流推荐/需求文档.md`（2026-10-11 定稿，Q1–Q7 已拍板）。
> 关联既有章节：§11（R7 估值参数确定性推荐）、§12（R8 研发调整建议）、§16（R12 `fcf_mode=custom`）。

### 17.1 设计目标与影响面

**目标**：在 R7 确定性估值推荐中**新增**「基期自由现金流选取」的推荐（`fcf_mode` / `fcf_years` / custom 值与单位 / 口径说明），由后端按财报数据**纯函数推导**，大模型只写 `rationale`；「套用到估值」一并写入该选择；估值模块面向用户的「基期现金流」统一为「基期自由现金流」。**不改** R4 的 DCF 公式与公司/股权价值口径，**不改** R7 已定的模型/折现率/增长率/年数/研发调整逻辑，**不改** `/valuation` 请求契约。

**涉及文件清单**

| 文件 | 改动 |
| --- | --- |
| `internal/model/ai.go` | `ValuationRecommendation` 新增 6 字段；`AIValuation` 新增 6 个 JSON 只读字段 |
| `internal/service/valuation_recommend.go` | 新增 `RecommendBaseFCF` + 判据/辅助纯函数；`RecommendValuation` 计算 FCF 序列并回填 |
| `internal/service/ai.go` | `valuationPromptBlock` 增加基期 FCF 段；`aiSystemFramework` 估值段补「解释基期选择」；`ApplyValuationRecommendation` 覆盖基期字段 |
| `internal/web/app.js` | AI 结果展示基期推荐；`applyAIValuation` 写入 `fcf_mode`/年数/custom 值+单位；文案替换 |

**是否破坏既有接口**：否。`/api/stock/:code/ai-analysis` 响应**只增只读字段**（`omitempty`），`/api/stock/:code/valuation` 契约不变。

### 17.2 总体架构与数据流

```
GetAIAnalysis (api/ai.go)
  └─ RecommendValuation(balance, cashflow, income)   // R7 主入口，新增 FCF 序列计算
       ├─ (既有) 基准增速 X% / Volatile / 模型 / 折现率 / 研发调整

  └─ BuildAIPrompt(..., rec) → valuationPromptBlock 喂「基期选择 + 口径」给大模型（只写 rationale）

  └─ 前端：展示 + applyAIValuation 写入估值表单
```

- 新增逻辑放在 **service（纯函数、无 IO）**，符合分层单向依赖；数据获取（`client`）与 HTTP（`api`）均不新增拉取。
- 复用 R7 已算出的 `X%`、`Volatile` 与三张报表，**不新增数据拉取**（需求 FR-1、非功能「性能与成本」）。

### 17.3 数据模型（`internal/model/ai.go`）

**`ValuationRecommendation` 新增字段**（内部结构，无 JSON tag，纯计算结果）

```go
// R13：基期自由现金流选取推荐（与 R7 同源，确定性推导）
FCFMode       string  // latest / average / median / trim_mean / custom（复用 service.valFCF* 常量）
FCFModeName   string  // 中文名（复用 service.valFCFModeNames）
FCFYears      int     // average/median/trim_mean 的推荐年数；latest/custom 为 0
FCFCustomYuan float64 // custom 推荐值（元，整亿倍数）；非 custom 为 0
FCFCustomUnit string  // custom 单位 key（本期固定 "yi"）；非 custom 为 ""
FCFRationale  string  // 确定性口径说明（供展示与喂给大模型写理由）
```

**`AIValuation` 新增 JSON 字段**（响应体；沿用 `omitempty` 约定，旧客户端忽略未知字段不报错）

```go
FCFMode        string  `json:"fcf_mode"`                   // 恒为五选一；不设 omitempty（稳定契约，镜像 model/model_name）
FCFModeName    string  `json:"fcf_mode_name"`              // 中文名；不设 omitempty
FCFYears       int     `json:"fcf_years,omitempty"`        // 多年度方式年数（>0）；latest/custom 为 0 不输出
FCFCustomValue float64 `json:"fcf_custom_value,omitempty"` // custom 展示值（单位见 fcf_custom_unit，取整到整亿）
FCFCustomUnit  string  `json:"fcf_custom_unit,omitempty"`  // custom 单位 key（"yi"）
FCFRationale   string  `json:"fcf_rationale,omitempty"`    // 口径说明
```

字段语义与兼容性说明：

- **数值口径**：内部真值 `FCFCustomYuan` 以**元**为口径，且恒为整亿倍数（Q6）；JSON 的 `fcf_custom_value` 是**按 `fcf_custom_unit` 表示的展示值**（本期单位固定「亿」→ 即整亿数值），供前端回填表单（与 `/valuation` 入参 `fcf_custom_value` 的「单位值」语义一致）。二者关系 `fcf_custom_value = FCFCustomYuan ÷ factor(unit)`，在 `ApplyValuationRecommendation` 里换算。
- **互斥**：非 `custom` 时 `FCFYears`为 0 或 `FCFCustom*` 为空（`omitempty` 不输出），满足 FR-2「互斥」。
- **`fcf_mode` 不设 `omitempty` 的理由**：算法**恒**产出一个 mode，恒输出便于前端稳定判断；与 `base_growth`（不设 `omitempty`）、`adjust_rd`（不设）风格一致。旧客户端读到未知字段自动忽略，不报错。
- **不新建 model 常量**：`fcf_mode` key 复用 `service` 包既有 `valFCFLatest/valFCFAverage/valFCFMedian/valFCFTrimMean/valFCFCustom` 与 `valFCFModeNames`，避免「五选一」出现第二处字面量真值源。

### 17.4 数据源与字段映射（无新增）

- **不新增任何东财/腾讯接口调用**。基期 FCF 序列复用 R4 `operatingFreeCashFlow(income, cf)`（`internal/service/valuation.go:396`），对每个现金流量表年报年度 y 计算 `fcfByYear[y] = operatingFreeCashFlow(incomeByYear[y], cfByYear[y])`（与 `ComputeValuation:147-149` **完全同口径**）。
- 逐年增速、波动、单调性均基于 `fcfByYear` 序列与 R7 已算出的 `X%`、`Volatile`，不引入新字段名。
- 年报口径沿用 `annualRows`（只取 `12-31` 结尾年报），与全项目一致。

### 17.5 确定性推导规则（核心算法，`internal/service/valuation_recommend.go`）

> **本节 §17.5.1~17.5.4 为 R13 原始口径，已被 R15 P2~P4 修订**：签名改为 `RecommendBaseFCF(fcfByYear, years, cycle)`（去掉 `x`/`volatile`、新增周期 `cycle`）；规则表以 R15 §19.7.4 为准（新增「强周期 → trim_mean」、R4/R8 改用 FCF 自身信号）；custom 可持续增速 `gS = clamp(FCF 增速中位数, 0, 15%)`（不再用全局 `X`）。以下旧正文仅作历史参考。

#### 17.5.1 新增常量与信号定义

```go
const (
    valFCFRecMaxYears = 5   // 中枢/波动判定窗口最多取近 5 年（FR-3 的 3–5 年）
    valFCFRecMinYears = 3   // 中枢判定至少需 3 个可用年度，否则退回 latest（FR-10）
    valFCFHighRatio   = 1.3 // latest > 1.3 × median → 最近一年明显偏高（Q3）
    valFCFLowRatio    = 0.7 // latest < 0.7 × median → 最近一年明显偏低（Q3）
    // 波动阈值直接复用既有 valVolatileSpread = 40.0（FCF 增速极差 > 40pp 视为波动大，FR-3）
)
```

设窗口 `win` = `fcfByYear` 对应的最近 `min(len(cfYears), valFCFRecMaxYears)` 个年度（升序），窗口值 `vals`（长度 `m`）。信号：

| 信号 | 定义 |
| --- | --- |
| `latest` | `vals[m-1]`（最近一年 FCF，元） |
| `median` | `medianOf(vals)`（含负值，用于高低判据） |
| `center` | `medianOf(仅正的 vals)`（custom 的「中枢」，FR-4；无正值时不可用） |
| `growth` | `fcfGrowthPoints(fcfByYear, win)`：窗口内相邻年度的 FCF 同比增速（`%`），仅计**上一年 FCF > 0** 的年度（上一年 ≤ 0 增速无意义，跳过，与 `growthPoints` 同口径） |
| `gSpread` | `spread(growth)`（增速极差，pp） |
| `gMedian` | `medianOf(growth)`（增速中位数） |
| `allPositive` / `allNonPositive` | 窗口值是否全正 / 全非正 |
| `monotoneUp` / `monotoneDown` | 窗口值是否**单调不减** / **单调不增** |
| `high` / `low` | `latest > valFCFHighRatio × median` / `latest < valFCFLowRatio × median` |
| `volatileFCF` | `gSpread > valVolatileSpread`（FCF 增速波动大） |
| `X` / `volatile` | R7 已算出的基准增速（`%`）与剧烈波动标志（营收/净利/现金流极差 > 40pp），**直接入参** |

新增纯函数：

```go
// fcfGrowthPoints 窗口内逐年 FCF 同比增速（%，升序；仅计上一年 FCF > 0 的年度）。
func fcfGrowthPoints(fcfByYear map[int]float64, years []int) []float64
// allPositive / allNonPositive / monotoneUp / monotoneDown：窗口值性质判定（辅助纯函数）
```

#### 17.5.2 规则优先级表（按序命中，唯一出口）

**排序说明**：需求 FR-3 原表「按序命中」，但其中「波动大 → median」与「偏高且不可持续 → custom」都以「波动/不可持续」为条件，若严格按原表自上而下，"latest 偏高"会被"波动大→median"先行截胡、custom 永不触发。故本设计将**判据的排他性**收敛为如下优先级：先判「稳定增长（唯一用 latest 的常规出口）」→ 再判「偏高不可持续（custom）」→ 再判「逐年下滑（latest 保守）」→ 再判「偏低 / 波动（median）」→ 兜底「平稳（average）」。**排序后仍为「按序命中、唯一出口、无或分支」**，阈值全部为固定常量。

| 序 | 判据（全部满足才命中） | 推荐 | 口径说明（`FCFRationale`） |
| --- | --- | --- | --- |
| R0 | `m == 0`（现金流量表无年报） | `latest` | 「无可用经营自由现金流数据（现金流量表为空），退回最近一年。」 |
| R1 | `m < 3`（可用年度不足） | `latest` | 「可用经营自由现金流年度不足 3 年，无法评估可持续性，退回最近一年。」 |
| R2 | `allNonPositive(vals)` | `latest` | 「近年（{win 年份}）经营自由现金流均为非正，无法构成可持续中枢，退回最近一年。」 |
| R3 | `latest <= 0` | `latest` | 「最近一年（{年}）经营自由现金流为非正，退回最近一年。」 |
| R4 | `allPositive && monotoneUp && gSpread <= 40 && !volatile && X >= 0` | `latest` | 「近 {N} 年经营自由现金流逐年增长（{年份}），且增速可持续，取最近一年代表当前可持续水平。」 |
| R5 | `high && (X < 0 \|\| volatile)`，且 custom 值取整后 > 0 | `custom` | 「业绩增速不可持续（基准增速 {X}%）且最近一年自由现金流明显高于多年中枢，按可持续中枢 {center 亿} ×（1 + 可持续增速 {gS}%）下调为 {值} 亿元。」 |
| R6 | `monotoneDown` | `latest` | 「经营自由现金流逐年下滑，取最近一年以反映当前水平。」 |
| R7 | `low && !monotoneDown` | `median` | 「最近一年自由现金流明显低于多年中枢（{latest 亿} vs 中枢 {median 亿}），取近 {N} 年中位数以避免低估。」 |
| R8 | `volatileFCF \|\| volatile` | `median` | 「近 {N} 年经营自由现金流增速波动较大（极差 {gSpread} 个百分点），单年不代表常态，取近 {N} 年中位数。」 |
| R9 | 兜底（平稳、无趋势、波动不大） | `average` | 「近年经营自由现金流总体平稳（{年份}），取近 {N} 年平均值。」 |

- **R5 取整后 ≤ 0 的回落**：`disp <= 0` 时**不产出 custom**，落到 R7/R8 的 `median`（口径说明追加「…取整到整亿后不足 1 亿元，退回中位数」），保证推荐值 > 0（FR-4 边界）。
- **N（推荐年数）**：R5 用不到；R7/R8/R9 的 `FCFYears = m`（窗口大小，`3 ≤ m ≤ 5`）；R4/R6/R0–R3 的 `FCFYears = 0`。
- **`trim_mean` 与规则 6 的 `custom` 备选**：需求原表两处的次选（`trim_mean`、「median 或 custom」）按「更靠前者命中」规则**不被选中**——本期算法可达的模式为 `latest` / `median` / `average` / `custom` 四种，`trim_mean` 仍保留在契约枚举中（见 17.12 #1）。

#### 17.5.3 custom 推荐值口径（FR-4 / Q4 / Q6）

```
可持续中枢  center = medianOf(正的窗口 FCF)            // 元，> 0（否则已在 R2 降级）
可持续增速  gS     = clamp(gMedian, 0, 15)             // %, 被 clamp 到 [0, 15]（R15 P2 起不再用全局 X）
原始推荐值  y      = center × (1 + gS / 100)            // 元
展示/套用值 disp   = round(y / 1e8)                     // 取整到整亿（Q6）；disp <= 0 → 回落 median
规范元值    FCFCustomYuan = disp × 1e8                  // 内部真值，恒为整亿倍数
单位        FCFCustomUnit = "yi"                        // 展示/套用单位「亿」
```

- 原 `min(max(gMedian,0), X)`（用全局 `X` 封顶）已由 R15 P2 改为 `clamp(gMedian, 0, 15)`（固定上限 15%，与全局基准增速 `X` 解耦）：增速为负 → 取 0；增速 >15% → 封顶 15%。见顶部提示与 R15 §19.6.7。
- **展示取整而套用/内部同源**：`disp × 1e8` 既是展示值的元等价，也是套用后 `ParseCustomFCF(disp, "yi")` 得到的元值，**三者恒等**，避免「展示一个数、计算另一个数」。

### 17.8 套用链路（`applyAIValuation` + 后端带出）

**前端 `applyAIValuation`（`app.js:695`）**，在既有模型/参数/`valAdjustRD` 之后、`fetchValuation()` 之前插入：

```js
  }
  if (v.fcf_mode === 'custom') {
    if (v.fcf_custom_value != null) valFCFCustomValue.value = v.fcf_custom_value;
    if (v.fcf_custom_unit) valFCFCustomUnit.value = v.fcf_custom_unit;
  }
}
```

- `if (v.fcf_mode)` 守卫保证**旧响应/前端缓存**（无该字段）不误改当前选择，向后兼容。
- 推荐 `custom` 时 `fcf_custom_value > 0` 且单位合法（后端保证），`fetchValuation` 里的 `validateCustomFCF` 必通过，不报校验错（FR-6 末条）。
- 已有 `fetchValuation()` 调用不变 → 改变 ref 后立即重算。

### 17.12 R13 关键决策点 / 待确认项

1. **规则排序（本设计已定序，需求原表「按序命中」需据此细化）**。原表把「波动大→median」排在「偏高→custom」之前，严格自上而下会使 custom 永不触发；本设计改为「稳定增长→latest / 偏高不可持续→custom / 逐年下滑→latest / 偏低或波动→median / 平稳→average」的排他序。**推荐采用本序**（唯一出口、无「或」分支，仍满足 FR-1/FR-3「确定性」）。若产品坚持原表字面序，需接受 custom 仅由「`X<0` 且 FCF 不波动」极窄场景触发——**不推荐**。
2. **`trim_mean` 与规则 6 的 `custom` 备选是否可达**。按「同格取更靠前者」，本期算法**不产出** `trim_mean`，规则 6 恒取 `median`。**推荐维持**（不新增阈值，遵守「阈值固定（已决策）」）；若希望真正用到 `trim_mean`，可把 R8 细分为「存在单一极端值（偏离中位数 > X%）→ `trim_mean`，否则 `median`」，但**会引入新阈值**，需用户拍板。
3. **custom 单位固定「亿」vs 动态单位**。本期恒取整到整亿（Q6），故 `fcf_custom_unit="yi"`；副作用是**可持续中枢 < 0.5 亿的公司**取整后为 0 → 回落 `median`（已在 R5 处理）。**推荐本期固定「亿」**；若要覆盖小市值公司可用「万」单位（避免回落），需改 Q6 的「取整到整亿」口径，属产品决策。
4. **`fcf_custom_value` 的语义（单位值 vs 元值）**。本设计取**单位值**（=元值÷1e8，与 `/valuation` 入参 `fcf_custom_value` 同语义、便于 `applyAIValuation` 直填表单）；`AIValuation` 不另出元值字段（元值 `FCFCustomYuan` 仅在 Go 内部结构与日志/测试中）。**推荐此方案**（前后端一致、前端零换算）；若偏好「响应即含元值」，可再加 `fcf_custom_yuan`（冗余，不推荐）。
5. **`fcf_mode`/`fcf_mode_name` 不设 `omitempty`**。理由：算法恒产出、前端需稳定显示，与 `base_growth`/`adjust_rd` 风格一致；其余三个（`fcf_years`/`fcf_custom_*`/`fcf_rationale`）设 `omitempty`。**推荐此组合**。
6. **R4 与 R8 对「growing 但 volatile」的取向**。本设计让「单调增长且非 volatile、X≥0」才走 `latest`；若增长同时剧烈波动，则可能落 R5（custom，下调）或 R8（median）。**推荐**（体现「不被单年高点误导」）；如需「只要单调增长就用 latest」，放宽 R4 去掉 `!volatile` 即可，需用户确认。
7. **降级提示是否复用 R7 `Warning`**。R0–R3 的降级说明放在新增 `fcf_rationale`（信息级展示），**不**复用 R7 `Warning`（后者是「套用后 R4 可能不适用」的告警级 `el-alert`，语义不同）。**推荐分离**，避免误报为告警。
8. **前端未套用基期字段时的行为**：`applyAIValuation` 用 `if (v.fcf_mode)` 守卫，旧响应/缓存不触碰当前选择（保持 R12 边界）；仅新响应会写入。**推荐**，向后兼容。
