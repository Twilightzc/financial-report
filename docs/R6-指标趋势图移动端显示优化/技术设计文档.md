# R6 技术方案：指标趋势图移动端显示优化

> 对应需求文档 `docs/R6-指标趋势图移动端显示优化/需求文档.md`。本轮**只调整展示层**（ECharts option + CSS），不改数据口径、接口与双轴设计。

### 10.1 设计目标与影响面

| 项 | 内容 |
| --- | --- |
| 目标 | 320–768px 视口下图例、轴名、刻度互不重叠且不被裁切；单位语义由刻度标签自身承载；移动端图表高 320px、字号 ≥ 11px |
| 改动文件 | `internal/web/app.js`（`renderIndicatorChart` 重构 + 新增格式化/布局小工具函数 + 弹窗 resize 与销毁）、`internal/web/style.css`（新增 `.chart-box` 高度规则、移动端媒体查询内 dialog 内边距） |
| 不改动 | `/api/stock/:code/analysis` 接口与返回结构、柱=指标值/折线=同比增速的双轴设计、`yoyText`/`yoyClass`、tooltip 数值口径、弹窗宽度 `min(680px, 92vw)`、断点仍只用 `@media (max-width: 768px)` |
| 破坏性 | 无（纯前端展示层，无接口变更、无新增依赖，继续用现有 `echarts@5.5.0` CDN） |

### 10.2 关键判断：「窄屏」的口径取图表可用宽度，「移动端」的口径取视口

需求里两个阈值口径不同，必须分别实现，不能混用一个：

- **FR-2/FR-3 的「窄屏」= 图表可用宽度 < 480px**：决定图例位置、图例缩略、字号与 `grid` 左右边距。在渲染时用 `chartRef.clientWidth` 实测（`narrow = el.clientWidth < CHART_NARROW_WIDTH`，常量 `CHART_NARROW_WIDTH = 480`）。
- **FR-4 的「移动端」= 视口 ≤ 768px**：决定图表容器高度（380px → 320px）与弹窗内边距，沿用既有 CSS 媒体查询断点，不去 JS 里算。

两者会在中间区间（视口约 548–768px）出现组合：容器高度已是移动端 320px、而图表宽度 > 480px 仍用顶部图例。这是两个需求条款直接推导的结果，属预期行为，不算回归。用 JS 实测宽度而非按视口推断，好处是弹窗宽度本身是 `min(680px, 92vw)`（非固定），实测值才是真实可用宽度。

### 10.3 option 改造（`internal/web/app.js`）

把现在内联在 `renderIndicatorChart` 里的 option 构造拆成**纯函数 + 常量**，便于按宽度重算：

```js
const CHART_NARROW_WIDTH = 480; // 图表可用宽度窄于此值时：图例移底、字号 11px、边距收紧

// 左 y 轴刻度：单位语义由刻度标签承载（FR-1）。
function fmtAxisValue(v, unit) {
  if (unit === '元') {
    if (v === 0) return '0';
    const yi = v / 1e8;
    if (Math.abs(yi) >= 1) return yi.toFixed(1) + '亿';
    return (v / 1e4).toFixed(0) + '万';
  }
  if (unit === '%') return fmtAxisPct(v);
  if (unit === '倍') return v.toFixed(2) + '倍';
  return Number(v).toFixed(2);
}

// 百分比刻度：至多 1 位小数（12.5% / 10% / 0% / -5%）；左轴与右轴（同比增速）共用。
function fmtAxisPct(v) {
  if (v === 0) return '0%';
  const r = Math.round(v * 10) / 10;
  return (Number.isInteger(r) ? r.toFixed(0) : r.toFixed(1)) + '%';
}

// 窄屏图例缩略：超过 6 个汉字截断为 6 字 + 「…」（全名仍在弹窗标题与 tooltip）
function legendLabel(name, narrow) {
  return narrow && name.length > 6 ? name.slice(0, 6) + '…' : name;
}

// 同比增速折线（首年/上期缺失/上期为 0 或负 → null），口径不变
function growthSeries(values) {
  return values.map((v, i) => {
    if (i === 0) return null;
    const prev = values[i - 1];
    if (v == null || prev == null || prev === 0 || prev < 0) return null;
    return ((v - prev) / prev) * 100;
  });
}
```

`buildIndicatorChartOption(it, years, values, growth, narrow)` 返回完整 option，关键改动：

| 项 | 现状 | 改后（宽屏 / 窄屏） |
| --- | --- | --- |
| 左 y 轴轴名 | `name: unit`（`%` / `元` / `倍` 单符号） | **移除轴名**（Q1 推荐方案，单位已由刻度承载） |
| 左 y 轴刻度 | `fmtAxis`：`%`/`倍` 返回裸数字 | `axisLabel.formatter: (v) => fmtAxisValue(v, unit)`（`%`→`12.5%`、`倍`→`1.20倍`、`元`→`1.2亿`/`500万`/`0`） |
| 右 y 轴（增速） | `name:'增速 %'` + `'{value}%'` | 保留轴名，加 `nameGap: 8`；formatter 改 `fmtAxisPct`（避免 `{value}%` 输出长小数） |
| 图例 | `top:0`，`data:[it.name,'同比增速']` | 宽屏：`top:0`，fontSize 12；窄屏：`bottom:0, left:'center', itemGap:12`，fontSize 11；窄屏长名缩略（同时用于 `legend.data` 与 series `name`） |
| grid | `{left:64,right:64,top:40,bottom:32}` | 宽屏 `{left:12,right:16,top:48,bottom:24,containLabel:true}`；窄屏 `{left:8,right:12,top:28,bottom:46,containLabel:true}`（左右合计 20px ≤ 24px，满足 FR-3） |
| 字号 | 未显式设置（默认 12） | 窄屏 legend/axisLabel/nameTextStyle 统一 11，宽屏 12 |
| x 轴刻度 | 默认 | 加 `axisLabel.hideOverlap: true`（ECharts 5.5 支持），年份多时不互相压字 |

要点与理由：

1. **图例文本必须同时改在 `legend.data` 与 series `name` 上**：ECharts 图例按 `name` 与 series 关联，只改 `legend.data` 会导致图例项点不动/不显示。缩略后 series `name` 也变了，但 tooltip 用的是自定义 `formatter`（内部写死 `it.name` 与 `'同比增速'`），弹窗标题也用 `chartIndicator.name`，所以**全名信息不丢**（满足 FR-2）。
2. **`containLabel: true` 与边距的关系**：开启后 `grid.left/right/bottom` 是「轴刻度标签之外」的留白，因此左右可压到 8/12px 而不会裁切 `1.2亿` 这类长刻度（FR-3 边界）。窄屏 `bottom: 46px` 是给底部图例留位（x 轴标签由 containLabel 负责）。
3. **`top` 的取值**：顶部无图例（窄屏）时 `top:28px` 刚好容纳右轴轴名（文本 + `nameGap:8`）；顶部有图例（宽屏）时 `top:48px` 让图例与轴名分层，消除需求里「图例换行压住轴名」的根因。
4. **仅 1 年数据时不渲染增速系列**（FR-2 边界）：`growth` 全为 null 时不 push 折线 series、不加右 y 轴、`legend.data` 只含指标名一项。这同时避免了一个隐患——若折线系列被移除而 `yAxisIndex:1` 仍存在，或反之，图例会与系列错配。
5. **`grid.top`/`bottom` 的具体像素值需实机微调**：右 y 轴轴名（`nameLocation:'end'` 默认置顶）在 `containLabel` 下的占位由 ECharts 内部布局决定，文档给不出可以离线验证的精确值；实现时按 10.7 的手工核对（320px 下 `%` 与长名指标各一张）确认无压字/裁切，若轴名与绘图区顶部过挤，优先微调 `grid.top`（窄屏 28 → 32）而非移除轴名。

`renderIndicatorChart()` 改为：计算 `growth` → `dispose` 旧实例 → `echarts.init(el)` → 实测 `chartNarrow.value = el.clientWidth < CHART_NARROW_WIDTH` → `chart.setOption(buildIndicatorChartOption(...))`。

> ⚠️ **R9 追加（第 13 节，不覆盖本节其余结论）**：柱状系列 `itemStyle.color` 由固定 `'#d64040'` 改为按该指标的 `trend_signal` 取色（向好绿 / 走弱红 / 无信号或中性灰 / 负值恒红），折线维持琥珀但改用 `PALETTE.growth` 常量。`buildIndicatorChartOption` 的**签名与本节其余 option 结构不变**，`series` 数组的构造顺序（柱在前、折线可选在后）与「仅 1 年数据不渲染增速系列」的判据也不变。详见 13.9④。

### 10.4 断点行为矩阵

| 视口宽度 | 图表可用宽度 | 容器高度 | 图例 | 左轴轴名 | 字号 | grid（左右合计） |
| --- | --- | --- | --- | --- | --- | --- |
| > 768px（桌面） | ≥ 480px | 380px | 顶部居中，不缩略 | 无 | 12px | 12 / 16（28px） |
| 约 548–768px | ≥ 480px | 320px（CSS 768 断点） | 顶部居中，不缩略 | 无 | 12px | 12 / 16（28px） |
| ≤ 约 548px | < 480px | 320px | **底部居中**，>6 字缩略 | 无 | 11px | 8 / 12（20px） |

（「约 548px」是 `min(680px, 92vw)` 弹窗在扣除内边距（移动端 12px×2）后、图表可用宽度恰好等于 480px 的视口临界点；示例：视口 600px → 弹窗 `min(680, 552)=552` → 图表可用宽度 552 − 24 = 528px > 480px，图例仍在顶部。实现以 JS 实测宽度为准，不写死视口值。）

### 10.5 style.css 改动（`internal/web/style.css`）

新增全局（媒体查询外）规则，用于图表容器高度：

```css
/* 指标趋势图容器：桌面 380px，移动端见下方媒体查询（FR-4） */
.chart-box { width: 100%; height: 380px; }
```

并在既有 `@media (max-width: 768px)` 块内追加（沿用同一断点，不新增断点）：

```css
  .chart-box { height: 320px; }            /* FR-4：移动端 380 → 320 */
  .el-dialog { --el-dialog-padding-primary: 12px; }  /* FR-4 边界：320px 视口收紧弹窗内边距，给图表留宽度 */
```

`el-dialog` 由 Element Plus teleport 到 `body`，选择器为全局匹配，写在 `style.css` 即可生效；该变量由 Element Plus 用于 dialog header/body/footer 内边距。

同时把 `app.js` 模板里的 `<div ref="chartRef" style="width:100%;height:380px">` 改为 `<div ref="chartRef" class="chart-box">`（高度交给 CSS，横向 resize 与横竖屏切换时浏览器自动改高，ECharts 靠 `resize()` 重新测量）。

### 10.6 弹窗生命周期：resize 重排与销毁（FR-5）

```js
const chartNarrow = ref(false); // 当前图表是否处于窄屏布局

let chartResizeTimer = null;
function handleChartResize() {
  if (!chartVisible.value || !chartRef.value) return;
  clearTimeout(chartResizeTimer);
  chartResizeTimer = setTimeout(() => {
    if (!chartVisible.value || !chartRef.value) return;
    const el = chartRef.value;
    const chart = echarts.getInstanceByDom(el);
    if (!chart) return;
    const next = el.clientWidth < CHART_NARROW_WIDTH;
    if (next !== chartNarrow.value) {
      // 跨越 480px 阈值：图例位置/grid/字号需整体重算
      chartNarrow.value = next;
      chart.setOption(buildIndicatorChartOption(chartIndicator.value, analysis.value.years || [], chartIndicator.value.values || [], growthSeries(chartIndicator.value.values || []), next));
    }
    chart.resize(); // 容器尺寸变化后重新测量
  }, 120); // 防抖，横竖屏切换时 resize 会连续触发
}

// 弹窗关闭时销毁实例，避免 echarts 实例挂在已移除的 DOM 上
function disposeIndicatorChart() {
  if (!chartRef.value) return;
  const c = echarts.getInstanceByDom(chartRef.value);
  if (c) c.dispose();
}
```

- 在 `setup()` 末尾注册一次 `window.addEventListener('resize', handleChartResize)`（单页应用，无需解绑）；窗口 resize 与手机横竖屏切换都会触发。
- `el-dialog` 增加 `@close="disposeIndicatorChart"`（当前只有 `destroy-on-close` + `@opened`）。
- 备选方案：对图表容器用 `ResizeObserver`（能捕获非窗口 resize 引起的容器变化，如 Element Plus 弹窗过渡）。本轮推荐 `window.resize`（改动小、覆盖 FR-5 全部列举的触发源），`ResizeObserver` 作为后续可选增强。

### 10.8 R6 关键决策点

1. **左轴轴名**：按需求 Q1 推荐**直接移除**（单位由刻度承载）。备选：保留并改为中文「金额（元）/百分比」——信息更全但多占一行、窄屏更易挤，不推荐。
2. **窄屏图例位置**：按需求 Q2 推荐**移到图表底部**（与绘图区不争顶部空间，最不易重叠）。备选：仍置顶部并动态抬高 `grid.top`。
3. **缩略触发条件**：需求写「图例项宽度超过图表宽度一半」，实现用**字符数 > 6 即缩略**的近似判据（汉字宽度近似均匀，6 字 ≈ 70px 远小于 480px 的一半，天然满足条件且无需测量文本宽度）。备选：用 `echarts.format.getTextRect` 实测宽度，更精确但多一次布局依赖，收益有限。
