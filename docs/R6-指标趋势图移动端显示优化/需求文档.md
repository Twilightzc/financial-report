# 指标趋势图移动端显示优化

> 来源：用户反馈（2026-09）「对于指标的图，在手机上显示感觉比较混乱，图例和 y 轴变量名都重叠了；还有左边 y 轴显示百分比的时候，百分比竟然是作为单位的，y 轴上只显示数据；优化一下手机端上的显示」。
> 对应现状代码：`internal/web/app.js` 的 `renderIndicatorChart()`（约 190–279 行）、弹窗 `el-dialog`（约 775–777 行）、`internal/web/style.css` 移动端 media query（约 503 行起）。

## 1. 背景与目标

### 1.1 背景

指标趋势图弹窗（柱状 = 指标值、折线 = 同比增速，双 y 轴）在桌面端展示正常，但未做移动端适配，手机（视口 320–480px）上出现三类问题：

1. **图例与轴名/绘图区重叠**：图例使用完整中文指标名（如「息税前经营资产回报率」「周转性经营投入周转率」）加「同比增速」，手机弹窗宽度仅 `min(680px, 92vw)`（375px 视口下约 345px，扣除弹窗内边距后图表区约 305px），图例换行成两行，而 `grid.top` 仅 40px，导致图例压住绘图区与坐标轴名。
2. **百分比单位语义错位（用户核心痛点）**：百分比指标的左 y 轴把「%」作为**轴名**单独放置，而刻度标签 `fmtAxis` 对非「元」单位直接返回裸数字（10、20、30），用户看到「孤零零一个 %」+「一排没有单位的数据」，读不出刻度的量纲。
3. **绘图区被挤压**：`grid` 左右各留 64px，在约 305px 宽的图表里绘图区只剩约 177px，柱体/折线拥挤，刻度标签也容易被裁切。

### 1.2 目标

- 在 320–768px 视口宽度下，图例、左右轴名、刻度标签、绘图区**互不重叠、互不遮挡、不被裁切**。
- 百分比/倍/金额三类单位的语义**由刻度标签自身表达**，不再依赖一个孤立的单位符号轴名。
- 移动端无需横向滚动即可完整查看趋势图；桌面端（>768px）显示不劣化。

## 2. 用户故事 / 使用场景

- 作为用手机看财报的个人投资者，我想要在手机上点开任意指标的趋势图就能看清「哪根柱子是哪年、折线是什么、刻度是什么单位」，以便在通勤等碎片时间快速判断指标趋势。
- 作为用手机看百分比类指标（如 ROE、毛利率、周转率）的用户，我想要刻度上直接写出「10%」而不是只看到一个孤立的「%」符号，以便不用心算就知道数值量纲。
- 作为桌面端用户，我想要移动端适配不破坏我现有的图表布局，以便继续用大屏获得更宽的趋势视图。

## 3. 功能需求

### FR-1 单位语义由刻度标签承载（用户核心痛点）（P0）

- **触发**：任意指标点击趋势图图标，弹窗渲染。
- **要求**：
  - 左 y 轴（指标值轴）的**刻度标签必须自带单位后缀**，按指标 `unit` 分档：
    - `%`：数值保留至多 1 位小数 + `%`（例：`12.5%`、`10%`、`0%`）。
    - `倍`：数值保留 2 位小数 + `倍`（例：`1.20倍`）。
    - `元`：沿用现有亿/万规则（|值| ≥ 1 亿 → 1 位小数 + `亿`；否则 → 万元整数 + `万`；0 → `0`）。
    - 其他/空单位：数值保留 2 位小数，不带后缀。
  - **左 y 轴不得再出现「仅含单位符号」的轴名**（如把 `%`、`元` 单独当轴名）。单位信息完全由刻度标签表达后，左轴轴名应移除；若实现选择保留轴名，则轴名必须为完整可读中文（如「金额（元）」「百分比」），且不得与图例、刻度重叠。
- **输出**：`%` 指标图左侧刻度为 `10%`、`12.5%` 形式，不再出现「轴名 = % + 裸数字刻度」。
- **边界**：指标值包含 0、负值、正负混合时，刻度格式化规则不变（负号在数字前，如 `-5.0%`）；刻度值为 0 时显示 `0%`。

### FR-2 图例布局随宽度自适应，不再与轴名/绘图区重叠（P0）

- **触发**：同 FR-1。
- **要求**：
  - 图例必须**完整展示两个系列**（指标名、同比增速），任一情况下不得被裁切、不得压住绘图区与坐标轴名。
  - 窄屏（图表可用宽度 < 480px）时：图例置于图表**底部**、水平居中等宽分布，字号不小于 11px；`grid.bottom` 相应预留图例高度。
  - 宽屏（图表可用宽度 ≥ 480px）时：图例保持现状（顶部居中）。
  - 图例项文字过长（移动端图例项宽度超过图表宽度的一半）时，**缩短为固定长度（建议最多 6 个汉字）并以「…」结尾**；完整指标名在弹窗标题与 tooltip 中始终可见，不得丢失信息。
- **边界**：指标只有 1 年数据（无同比增速折线）时，图例只展示 1 项，布局仍需居中且不遮挡。

### FR-3 绘图区外边距自适应，刻度不被裁切（P0）

- **触发**：同 FR-1。
- **要求**：
  - 坐标轴开启标签自适应（`containLabel`），保证「1.2亿」这类长刻度标签不被裁切。
  - 移动端（≤768px）左右外边距必须收窄（建议左右合计 ≤ 24px），使绘图区宽度不低于图表可用宽度的 60%。
  - 左右轴名与刻度、图例之间必须留出足够间隙（轴名 gap），任何视口宽度下不得出现文字相互覆盖。
- **边界**：金额单位且数值为万元级（刻度文本较长）时，仍需完整显示。

### FR-4 移动端图表尺寸与字号（P0）

- **触发**：同 FR-1。
- **要求**：
  - 图表容器高度：桌面（>768px）保持 380px；移动端（≤768px）降至 **320px**（保证手机竖屏下图表完整可见、无需滚动）。
  - 弹窗宽度保持 `min(680px, 92vw)`，不在移动端溢出视口。
  - 移动端图例文字、坐标轴名、刻度标签字号不小于 11px，保证可读性。
- **边界**：320px 最小支持宽度下，弹窗内边距应按移动端收紧，避免图表可用宽度被过度压缩。

### FR-5 尺寸变化时重新布局（P1）

- **触发**：弹窗打开、浏览器窗口 resize、手机横竖屏切换。
- **要求**：图表在尺寸变化后必须重新计算布局（resize/重绘），保持 FR-1~FR-4 的不重叠要求；横竖屏来回切换后不出现图例错位、绘图区被压扁的残留状态。
- **边界**：弹窗关闭后销毁图表实例，再次打开按新宽度重新渲染。

### FR-6 桌面端显示不回归（P1）

- **触发**：桌面视口（>768px）打开趋势图。
- **要求**：桌面端显示效果与当前一致或更清晰（刻度带单位后语义更完整属预期改进）；不得引入新的重叠、裁切或布局错位。

## 4. 非功能需求

- **移动端兼容**：需覆盖 320px / 360px / 375px / 414px 视口宽度，主流移动端浏览器（iOS Safari、Chrome for Android、微信内置浏览器）正常。
- **可读性**：所有文字（图例、轴名、刻度）在移动端字号 ≥ 11px，颜色对比沿用现有主题色，不引入浅色不可读文本。
- **性能**：图表渲染/重绘耗时与现状同量级（无新增网络请求，纯前端布局调整）。
- **一致性**：与现有三大报表、指标表的移动端适配风格保持一致（沿用 `style.css` 的 `@media (max-width: 768px)` 断点，不新增断点）。
- **无回归**：不改变趋势图的既有数据口径（柱状 = 指标值、折线 = 同比增速、tooltip 内容）。

## 5. 边界与约束

- 本轮**只调整展示层**（图例位置/尺寸、坐标轴单位与刻度、绘图区边距、容器高度），**不改变**指标计算口径、同比增速规则、双轴设计（柱状=值、折线=增速）。
- 不引入新的第三方图表库或依赖；继续使用现有 ECharts CDN 与内嵌静态资源方式（非独立构建）。
- 不做平板/桌面端的整体重设计，只在移动断点内做适配。
- 已知现状：指标无数据时已有的「该指标暂无数据」提示行为保持不变。

## 6. 验收标准

- [ ] 375px 视口下打开「息税前经营资产回报率」（单位为 `%`）趋势图：左轴刻度显示为 `10%`、`12.5%` 形式，**不出现**「轴名 = 孤立 % + 裸数字刻度」。
- [ ] 375px 视口下打开任意长指标名（如「周转性经营投入周转率」）趋势图：图例完整可见、不与坐标轴名或绘图区重叠；长名被缩略时可在弹窗标题/tooltip 看到全名。
- [ ] 320px 视口下重复上述两条，仍不出现文字重叠、裁切、横向滚动。
- [ ] 移动端（≤768px）图表高度为 320px、桌面端为 380px；两者均为渲染后实测值。
- [ ] 金额单位指标（如营业收入）左轴刻度仍为「1.2亿」/「500万」形式且不被裁切。
- [ ] 手机横竖屏切换一次后，图表重新布局且无文字重叠。
- [ ] 桌面端（如 1440px）打开趋势图，无新增重叠/裁切，图表主体布局与当前一致。

## 7. 待确认问题

- **Q1 左轴轴名的最终处理**：影响移动端排版与信息表达；推荐**直接移除左轴轴名**（单位已由刻度承载，可同时缓解重叠），备选为保留并改为中文可读文案「金额（元）/百分比」。此项影响不大，若用户不表态即按推荐执行。
- **Q2 移动端图例位置**：影响实现方式与视觉重心；推荐**窄屏时图例置于图表底部**（换行风险最小、与绘图区不争顶部空间），备选为仍置顶部但动态抬高 `grid.top`。推荐方案实施更稳妥。
