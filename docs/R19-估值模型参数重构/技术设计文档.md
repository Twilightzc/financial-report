## 1. 设计目标与影响面

### 1.1 设计目标

按需求文档完成一次彻底重构，不做增量修补：

- 删除保守/基准/乐观三档、带宽、收窄、逐档 FCF 锚定、逐档套用，只保留一套「适中基准估值参数」。
- 修正 6 类错误：WACC 口径、复合锚 A 加总、三档不一致、Capex 覆盖率、FCF/净利润、风险溢价层级。
- 每个对外数字都能由「财报科目 + 公式 + 年份/窗口」手工复算；取整与区间约束单独成行。
- 后端确定性计算，AI 只输出 `industry_type`、定性 `company_risks`、`rationale` 三段，不参与任何数值。
- 输出洁净：不出现工具说明、推导过程、规则元语言、内部变量名。
- 基期自由现金流公式原样保留：`operatingFreeCashFlow = NETCASH_OPERATE − preservationCapex`，本次不改写、不重算、不换口径；只改「Capex 覆盖率」与「FCF/净利润」两个比值指标的分子/分母口径。

### 1.2 非目标

- 不改 DCF 四种模型公式、估值表单字段、R16 历史记录存储机制。
- 不改 `operatingFreeCashFlow`、`preservationCapex` 及逐年 FCF 序列的公式与字段处理。
- 不改 R3 六维分析（含 `maintenanceCapex` 及其指标标签）；六维分析与估值参数是两条独立链路。
- 不做相对估值、三张表预测、行业 β 回归、目标价/评级。
- 不新增外部数据源或第三方依赖；市值继续用腾讯行情，财报继续用东财。

## 2. 总体架构与计算顺序

### 2.1 数据流

```
api.GetAIAnalysis
  ├─ FetchQuote(code) ────────────────► quote.MarketCap（元）
  ├─ fetchAnalysisReports(code) ─────► balance / cashflow / income
  ├─ fetchGrowthSnapshot(code) ──────► GDP + 一致预期 + 分红快照
  │
  ├─① 预推导（industry=""，risks=nil）
  │     service.RecommendValuation(ValuationRecommendInput)
  │       ├─ 基期年对齐 / FCF 序列 / 基期 FCF
  │       ├─ 历史锚 / 周期修正 / 前瞻锚 / 宏观锚 / 锚构成表 A
  │       ├─ CAPM + WACC + 取整/区间 + 对账
  │       ├─ SGR / 终值 / g1 / n1 / 模型 / 参数
  │       └─ Capex 覆盖率 / FCF 净利润 / 适用性
  │
  ├─② BuildAIPrompt(analysis, quote, ..., rec) ──► DeepSeek
  │       AI 只返回 industry_type / company_risks / rationale
  │
  ├─③ 终态重算（industry=AI 原始串，risks=AI 风险项，MarketCap 不变）
  │     service.RecommendValuation(ValuationRecommendInput)
  │
  ├─④ ApplyValuationRecommendation(&result, rec)
  │       确定性字段全部覆盖；rationale 清洗后保留
  └─⑤ 返回 {code, data, message}
```

计算顺序固定为：

1. 基期年对齐（利润表 ∩ 现金流量表）。
2. FCF 逐年序列、基期 FCF（含研发扩张）。
3. 历史锚、周期位置修正、前瞻锚、宏观锚、复合锚 A。
4. 折现率（需要市值、行业分类、公司风险项）。
5. SGR、终值 g∞（需要折现率）。
6. g1、n1、模型选择、g2/n2、参数表。
7. Capex 覆盖率、FCF/净利润（需要基期 FCF 与窗口）。
8. 适用性与材料性警告。
9. 组装输出。

预推导与终态重算只允许因 `industry_type`、`company_risks` 改变 β、RP、Re、WACC、r、g∞、g1、n1、g2/n2、模型及其派生字段；其余字段两次必须逐位相同。

### 2.2 分层职责

- `api`：取数、并发编排、调用 LLM、缓存、JSON 返回。不计算估值参数。
- `service`：全部数值与文本口径的确定性计算，纯函数，无 IO/随机/时间依赖（基期年由报表年份决定）。
- `client`：腾讯行情、东财财报、DeepSeek。不参与口径判断。
- `model`：请求/响应结构体与共享枚举。不引入业务计算。
- `web`：只读 `/api/*`，不猜权重、不重算数字、不拼推导公式。

## 3. 数据模型

### 3.1 新增共享结构体（`internal/model/ai.go`）

```go
// GrowthContribution 复合锚构成表的一行。金额单位均为 %，权重为 0–1。
type GrowthContribution struct {
    Key          string  `json:"key"`          // history / forward / macro
    Name         string  `json:"name"`         // 历史锚（含周期修正）/ 前瞻锚 / 宏观锚
    Value        float64 `json:"value"`        // 锚值 %，2 位小数；不可用为 0
    Weight       float64 `json:"weight"`       // 权重 0–1，2 位小数；不可用为 0
    Contribution float64 `json:"contribution"` // 锚值×权重，2 位小数
    Available    bool    `json:"available"`    // 该锚是否可用
}

// GrowthAnchorTable 复合锚 A 的可复算构成。
// 恒满足：Σ(Value×Weight) = Raw；Raw + RoundingAdjustment + RangeAdjustment = Final。
type GrowthAnchorTable struct {
    Rows              []GrowthContribution `json:"rows"`
    WeightSum         float64              `json:"weight_sum"`          // 2 位小数；正常为 1.00
    WeightOK          bool                 `json:"weight_ok"`           // 权重合计校验
    Raw               float64              `json:"raw"`                 // 加权合计，2 位小数
    Rounded           float64              `json:"rounded"`             // 0.5pp 取整后，2 位小数
    Final             float64              `json:"final"`               // 区间约束后 = A，2 位小数
    RoundingAdjustment float64             `json:"rounding_adjustment"` // Rounded − Raw
    RangeAdjustment    float64             `json:"range_adjustment"`    // Final − Rounded
    Note              string               `json:"note,omitempty"`      // 仅材料性说明
}

// CompanyRiskItem 公司特定风险项。AI 只提供 Type/Severity/Note，Premium/Label 由后端回填。
type CompanyRiskItem struct {
    Type     string  `json:"type"`               // governance/litigation/customer_concentration/liquidity/accounting_quality
    Label    string  `json:"label"`              // 中文名，后端回填
    Severity string  `json:"severity"`           // medium/high
    Premium  float64 `json:"premium"`            // 0.5 / 1.0，后端回填；合计 ≤3.0
    Note     string  `json:"note,omitempty"`     // ≤30 字，不含数字/百分比
}

// CapexCoverageDetail 净资本支出 ÷ 保全性资本支出。
type CapexCoverageDetail struct {
    Available   bool    `json:"available"`
    Ratio       float64 `json:"ratio"`        // 2 位小数
    Numerator   float64 `json:"numerator"`    // 元，同窗口合计
    Denominator float64 `json:"denominator"`  // 元，同窗口合计
    WindowStart int     `json:"window_start"`
    WindowEnd   int     `json:"window_end"`
    Mode        string  `json:"mode"`         // 与基期 FCF 相同的选取方式
    Note        string  `json:"note"`         // 口径与窗口
    Reason      string  `json:"reason,omitempty"` // Available=false 时非空
}

// FCFProfitDetail 基期 FCF ÷ 同期净利润。
type FCFProfitDetail struct {
    Available   bool    `json:"available"`
    Ratio       float64 `json:"ratio"`        // 2 位小数
    FCF         float64 `json:"fcf"`          // 元，等于展示的 fcf_base_value
    Profit      float64 `json:"profit"`       // 元，同窗口同聚合
    ProfitBasis string  `json:"profit_basis"` // parent / reconstructed
    Mode        string  `json:"mode"`
    WindowStart int     `json:"window_start"`
    WindowEnd   int     `json:"window_end"`
    Years       int     `json:"years"`        // 有效窗口年数
    AdjustRD    bool    `json:"adjust_rd"`
    RDExpansion float64 `json:"rd_expansion"` // 元
    Note        string  `json:"note"`
    Reason      string  `json:"reason,omitempty"`
}
```

`GrowthWeights`、`ValuationScenario` 删除；权重只从 `GrowthAnchorTable.Rows` 读取，避免两套值。

## 5. 核心实现细节与算法

### 5.1 基期年与 FCF 序列

```go
incomeByYear, incomeYears := annualRows(income)
cfByYear, cfYears := annualRows(cashflow)
balanceByYear, balanceYears := annualRows(balance)

common := commonBaseYear(incomeYears, cfYears) // 两表交集最大年
latest := common
if latest == 0 {
    latest = latestYear(incomeYears, cfYears, balanceYears)
}
```

逐年 FCF：

```text
FCF_y = NETCASH_OPERATE_y − preservationCapex(income_y, cf_y)
```

`operatingFreeCashFlow`（`valuation.go:410-412`）与 `preservationCapex`（`valuation_consistency.go:44-49`）本次原样保留，不重写、不换字段、不改符号处理；`valuation_recommend.go:273` 继续直接复用该函数，保证 DCF 与参数推荐同源。

`FCF_t` 不含研发调整；研发调整只加到最终选中的基期 FCF，历史序列保持原口径。

基期 FCF 选取沿用 `selectBaseFCF`（`valuation.go:239-305`）：

- `latest`：最近一年。
- `average` / `median` / `trim_mean`：最近 N 年，缺省 3，超过可用年数截断；`trim_mean` 在 N≥3 时去掉最高、最低后平均。
- `custom`：用户输入值，按单位换算为元。

研发扩张：

```text
rdExpansion = max(0, RESEARCH_EXPENSE_latest − RESEARCH_EXPENSE_{latest-1})
              （上年度缺失 → 0）

baseFCFBeforeRD = selectBaseFCF(...)
baseFCF = baseFCFBeforeRD + (AdjustRD ? rdExpansion : 0)
```

`baseFCF <= 0` 时 `applicable=false`，原因“基期经营资产自由现金流为负或零，现金流贴现法不适用”，不得取绝对值或强行调正。

输出：

- `fcf_base_value` = `baseFCF`（元，含研发调整）。
- `fcf_base_before_rd` = `baseFCFBeforeRD`。
- `fcf_mode` / `fcf_mode_name` / `fcf_years` / `fcf_window_start` / `fcf_window_end`。
- `adjust_rd` / `rd_expansion` / `rd_ratio`。
- `fcf_note`：例如“最近 3 年平均（2022–2024）；已加回研发扩张 0.56 亿元。”

删除 `finalizeFCFRationale`、`fcfRationaleContext`、`appendFCFRationale`、`withCycleNote` 等过程性文案构造；`recommendBaseFCF` 只保留模式判定与 `ReasonCode`，最终 `fcf_note` 统一生成。

### 5.2 保全性资本支出（唯一口径）

```text
preservationCapex(income, cf) =
    assetImpairmentLoss(income)
  + creditImpairmentLoss(income)
  + FA_IR_DEPR
  + USERIGHT_ASSET_AMORTIZE
  + IA_AMORTIZE
  + LPE_AMORTIZE
  + max(0, DISPOSAL_LONGASSET_LOSS)
  + FA_SCRAP_LOSS
```

约束：

- FCF 扣减、Capex 覆盖率分母、口径文案三处必须调用同一个 `preservationCapex`，不得再写第二套。
- 该口径含非现金减值/处置/报废损失，是“维持现有经营能力的保守近似”，不是纯现金资本支出；文案必须写“保全性支出含非现金减值/处置项”。
- 六维分析（R3）的 `maintenanceCapex` 及其指标标签不在本次范围，保持现状不动；估值链路继续只使用 `preservationCapex`，两者不得混用。
- `operatingFreeCashFlow` 继续原样调用 `preservationCapex`，公式、字段、符号规则一律不改。

### 5.3 折现率：CAPM + WACC + 取整/区间对账

#### 5.3.1 输入与守卫

```text
E_raw = MarketCap > 0 ? MarketCap : TOTAL_EQUITY
E_source = market_cap / book_equity
D_raw = interestBearingDebt(balance_latest)
D = max(0, D_raw)
V = E_raw + D
t = effectiveTaxRate(income_latest)          // 0–1
```

守卫顺序：

1. 无资产负债表：`discount = 10.0`，`discount_base_label="default"`，`discount_reconcile_available=false`，警告“缺少资产负债表，折现率按默认值 10.0%”。
2. `E_raw <= 0` 或 `V <= 0` 或 `V < 1e6 元`（0.01 亿元）：不计算权重，`discount_base_value = Re`，`discount_base_label="Re"`，`discount_reconcile_available=false`，警告“净资产为负或资本结构异常，折现率按 Re 回落”。
3. `D_raw < 0`：`D=0`，警告“有息债务为负，按 0 计”。
4. `D=0`：`wD=0`，`Rd=0`，`WACC=Re`，`discount_reconcile_available=true`，口径行写“无有息债务”。

#### 5.3.2 组件计算

```text
Re_raw = Rf + β × ERP + RP_company
Re     = round2(Re_raw)

wE = round4(E_raw / V)
wD = round4(1 − wE)
```

`wD` 用 `1−wE` 强制权重合计 1.0000；`wE` 先四舍五入到 4 位小数，因此展示成百分数时正好 2 位小数（如 0.8249 → 82.49%）。

债务成本：

```text
if debtCapitalCost != nil:
    Rd_pre_raw = *debtCapitalCost
    estimated = false
else if D > 0:
    Rd_pre_raw = clamp(Rf + 2.0, 3.0, 8.0)     // 4.5
    estimated = true
else:
    Rd_pre_raw = 0
    estimated = false

Rd_pre   = round2(Rd_pre_raw)
t_pct    = round2(t × 100)
Rd_after = round2(Rd_pre × (1 − t_pct / 100))
```

- 实际 `Rd` 不截断；`Rd_pre > 15` 或 `< 1` 时追加警告“债务成本异常（X%），请核对利息支出与有息债务”。
- 估计 `Rd` 时 `debt_cost_estimated=true`，口径行写“债务成本不可用，按 Rf+2.0pp 估计”。

WACC 用展示值计算，保证卡片上的乘加能闭合：

```text
WACC_disp = round2(wE × Re + wD × Rd_after)
r_round   = roundHalf(WACC_disp)          // 0.5pp 网格
r         = clamp(r_round, 8.0, 15.0)
round_adj = round2(r_round − WACC_disp)
range_adj = round2(r − r_round)
```

恒等式：

```text
WACC_disp + round_adj + range_adj = r
```

输出：

- `discount_base_value = WACC_disp`（正常）或 `Re`（回落）。
- `discount_base_label = "WACC"` / `"Re"` / `"default"`。
- `discount_rounded = r_round`。
- `discount_rounding_adjustment = round_adj`。
- `discount_range_adjustment = range_adj`。
- `discount_rate = r`。
- `discount_reconcile_available = true` 仅当权重可用。
- `discount_note`：区间下限/上限约束、无债务、Rd 估计、市值回落等，一句一条，去重。

#### 5.3.3 对账展示行

前端按以下顺序渲染（数值均来自 API）：

```text
Re = 2.50% + 1.00×5.50% + 0.50% = 9.60%
Rd（税后）= 3.20% × (1−25.00%) = 2.40%
E/V = 82.49%，D/V = 17.51%（E 按总市值）
WACC = 82.49%×9.60% + 17.51%×2.40% = 8.34%
取整 0.5pp：−0.34pp → 8.00%
区间约束 [8.0,15.0]：0.00pp → r = 8.00%
```

容差 0.05pp；若手工复算超出，视为缺陷。

#### 5.3.4 公司特定风险溢价

`valuationRiskPoints` 删除，不得再用有息债务占比、利息覆盖倍数、财务杠杆。

AI 输出：

```json
"company_risks": [
  {"type": "governance", "severity": "high", "note": "控股股东质押比例高"},
  {"type": "customer_concentration", "severity": "medium", "note": "前五大客户集中"}
]
```

后端枚举与映射：

```go
var companyRiskDefs = []struct{ Type, Label string }{
    {"governance", "治理结构"},
    {"litigation", "诉讼与合规"},
    {"customer_concentration", "客户集中"},
    {"liquidity", "流动性"},
    {"accounting_quality", "会计质量"},
}
var companyRiskPremiumBySeverity = map[string]float64{
    "medium": 0.5,
    "high":   1.0,
}
```

校验与计列：

1. `type` 必须在五类枚举内，否则丢弃。
2. `severity` 必须是 `medium` / `high`，否则丢弃。
3. 同 `type` 去重，保留更高 severity。
4. 按 severity 降序、同 severity 按枚举顺序排序。
5. 依次累加 `premium`，合计不超过 3.0；超出上限的项不进入 `company_risk_items`。
6. `RP_company = round2(Σ premium)`，只进入 `Re`，绝不加到 WACC 之后。
7. 无有效项：`RP_company=0`，`company_risk_note="未叠加公司特定风险溢价"`。
8. 有项：`company_risk_note` 为空；`company_risk_items` 逐项展示。
9. `note` 清洗：≤30 字，去掉数字、百分号、工具/过程话术；不合法则留空。

`Re` 公式固定为 `Rf + β×ERP + RP_company`。验收时用“有 RP / 无 RP”两次结果比较，WACC 差值必须为 `wE × RP`，不能是 `RP`。

#### 5.3.5 β 与行业分类

沿用 `betaFor`：

- AI 行业分类有效：`cyclical=1.2`、`general=1.0`、`utility=0.8`。
- 分类缺失/非法：`volatile || FCF 强周期` → 1.2，否则 1.0。
- β 最终 `clamp[0.5,2.0]`。

对外 `beta_basis` 只输出机器 key：`industry_classification` / `volatility_fallback` / `default`；前端映射为“行业分类”/“波动兜底”/“默认”，不展示内部判断过程。

### 5.4 复合锚 A：可加总表格

#### 5.4.1 历史锚与周期修正

历史锚 `x` 沿用 `weightedGrowth`：营业收入、重构净利润、FCF 三项稳健同比增速的等权平均；每项至少 2 个有效年报、上年为正；缺项按剩余项归一化；全部不可用则历史锚不可用。

周期修正：

```text
delta = cycleAdjustment(pos)    // −clamp(pos×10, ±6)，1 位小数
histBase   = round2(x)
histAdjust = round2(histBase + delta)
```

只作用于历史锚；`delta=0` 时不输出 `growth_cycle_note`，否则输出“周期位置修正 +X.Xpp，已含于历史锚”。

#### 5.4.2 锚值与权重

```text
fwd = round2(fwd.Value)      // 不可用 → 0，available=false
macro = round2(macro.Value)  // 动态 GDP 或 4.5% 常量
```

权重表（与需求文档一致）：

| 可用锚 | 历史 | 前瞻 | 宏观 |
|---|---:|---:|---:|
| 历史 + 前瞻（高可靠） | 0.45 | 0.45 | 0.10 |
| 历史 + 前瞻（中可靠） | 0.55 | 0.35 | 0.10 |
| 仅历史 | 0.85 | 0 | 0.15 |
| 仅前瞻 | 0 | 0.85 | 0.15 |
| 历史、前瞻都不可用 | 0 | 0 | 0 |

`weight_sum = round2(sum)`；正常必须为 1.00。`insufficient = !histOK && !fwd.Available` 时 `weight_sum=0`、`weight_ok=true`、`A=0`、模型退化为零增长。

#### 5.4.3 加总与取整

```text
for each row:
    contribution_i = round2(value_i × weight_i)

raw     = round2(Σ contribution_i)
rounded = roundHalf(raw)
final   = clamp(rounded, −5.0, 30.0)
round_adj = round2(rounded − raw)
range_adj = round2(final − rounded)
```

恒等式：

```text
Σ contribution_i = raw
raw + round_adj + range_adj = final
```

输出 `growth_anchor.rows` 三行，每行 `value/weight/contribution` 均 2 位小数；`weight_sum` 单独一行显示 1.00；`raw` 行标签“加权合计”；`rounding_adjustment` 行标签“0.5pp 取整”；`range_adjustment` 行标签“区间约束 [−5.0, 30.0]”；`final` 行标签“最终 A”。

正文与结论中禁止出现 `A_raw`；需要注记时只写“加权合计”。

#### 5.4.4 负增长处理

- `A < 0` 且结构性负增长 → `zero` 模型。
- `A < 0` 且周期性负增长 → `perpetual` 模型，永续增长取 0。
- 不得把负 A 简单截断为 0 后当正常增长。

### 5.5 SGR、终值、g1、n1、g2/n2 与模型

#### 5.5.1 SGR

沿用 `sustainableGrowthR18`：

```text
SGR = ROE × 留存率 × 100%
ROE = 归母净利润 ÷ 期末股东权益 × 100%
留存率 = 1 − 现金分红/归母净利润
```

归母净利润缺失/非正时回落重构净利润并标注；留存率优先现金分红口径，否则权益增长口径；不可用时 SGR 不施加约束。

#### 5.5.2 终值 g∞

```text
g_raw = min(macro, r − 1.0, SGR if available)
g∞    = max(0, floorHalf(g_raw))
```

`terminal_constraint` 只输出真正生效的约束：

- `g_raw <= 0` → `zero`，note “终值按 0”。
- 否则取最小值来源：SGR → `sgr`；`r−1` → `discount`；宏观 → `macro`。
- 并列时按 `sgr > discount > macro` 取一个作为主约束，note 补充“与 X 相同”。
- 未生效的约束不得写成“受 X 约束”。

`g∞` 必须 `< r`；`r−1 < 0` 时取 0。

#### 5.5.3 g1

```text
capBase = 30.0
if fwdOK && sgrOK:
    capBase = min(30.0, max(fwd, SGR) + 2.0)
else if fwdOK:
    capBase = min(30.0, fwd + 2.0)
else if sgrOK:
    capBase = min(30.0, SGR + 2.0)

if capBase < g∞:
    g1 = g∞
    constraint = cap_below_terminal
else:
    g1 = floorHalf(clamp(A, g∞, capBase))
    constraint = (g1 < A ? upper : (A < g∞ ? terminal : none))
```

- `g1` 必须 ≥ `g∞`，不得为负。
- 只保留一个上限；删除离散度折减、软上限、包络。
- `g1_note` 只在约束生效时输出一句：
  - `upper`：“g1 受前瞻/SGR +2pp 上限约束。”
  - `terminal`：“g1 按终值收口。”
  - `cap_below_terminal`：“上限低于终值，g1 按终值收口。”

#### 5.5.4 n1 / n2

```text
nTotal = clamp(round((g1 − g∞) / 1.5), 3, 10)
```

- 两阶段：`n1 = nTotal`。
- 三阶段：`n1 = ceil(nTotal/2)`，`n2 = nTotal − n1`；`n1 + n2 = nTotal ≤ 10`，且 nTotal≥3 时 n1、n2 均≥1。
- 永续/零增长不输出 n1。
- 三阶段 `g2` 取 `roundHalf((g1 + g∞)/2)`，并要求 `g1 > g2 > g∞` 且 `g2 < r`；无解时降级两阶段。
- 两阶段要求 `g1 > g∞` 且 `g∞ < r`；否则降级永续。
- 降级链：`three_stage → two_stage → perpetual → zero`；模型名后加“（已降级）”，`model_reason` 说明一句。

#### 5.5.5 模型选择

内部保留 `classifyGrowthModel(A, gap, score, insufficient, negType)`，`gap = A − g∞`：

- `A≥6 && gap≥4 && score≥70` → 三阶段。
- `A≥2 && gap≥1.5 && score≥45` → 两阶段。
- `A≥0` → 永续。
- 否则零增长。
- 负增长结构性 → 零增长；周期性 → 永续。

对外只输出 `model_name` + `model_reason`，不输出评分、权重、阈值。`model_reason` 映射：

| 模型 | 理由 |
|---|---|
| 三阶段 | “增长锚较高且与终值差距大，适用三阶段。” |
| 两阶段 | “增长锚高于长期终值，适用两阶段。” |
| 永续 | “增长锚接近长期终值，适用永续增长。” |
| 零增长 | “增长锚为负或样本不足，按零增长处理。” |
| 降级 | “阶段参数无严格递减解，已降级为 X。” |

#### 5.5.6 参数表

`paramsFromPath` 继续输出与 `/valuation` 对齐的 key：

- zero：`[]`。
- perpetual：`g`。
- two_stage：`g1`、`n1`、`g2`。
- three_stage：`g1`、`n1`、`g2`、`n2`、`g3`（`g3=g∞`）。

### 5.6 Capex 覆盖率

#### 5.6.1 分子与分母

```text
netCapex_y = CONSTRUCT_LONG_ASSET_y − DISPOSAL_LONG_ASSET_y
```

- `CONSTRUCT_LONG_ASSET_y` 在窗口内任一年缺失 → `available=false`，原因“购建长期资产现金缺失（YYYY）”。
- `DISPOSAL_LONG_ASSET_y` 缺失按 0；处置收回大于购建时允许负净资本支出，不截断。
- 分母 `preservationCapex(income_y, cf_y)`；窗口合计 ≤0 → `available=false`，原因“保全性资本支出≤0”。

#### 5.6.2 窗口与聚合

与基期 FCF 完全一致：

| FCF 模式 | 覆盖率窗口 | 聚合 |
|---|---|---|
| latest | 最新年报 | 单年 |
| average / median / trim_mean | `selectBaseFCF` 返回的 `usedYears` | 窗口内净资本支出合计 ÷ 保全性支出合计 |
| custom | 最新年报 | 单年，注明“自定义 FCF，覆盖率按最新年报” |

不得逐年求比值再平均；不得用单年覆盖率解释多年基期 FCF。

```text
ratio = round2(Σ netCapex_y / Σ preservationCapex_y)
```

`note` 固定包含：“净资本支出（购建−处置收回）/ 保全性资本支出（含非现金减值/处置项）；窗口 YYYY–YYYY。”

#### 5.6.3 告警

- `ratio > 1.3` 且模型为两阶段/三阶段：追加材料性警告“资本支出为保全性支出的 X 倍，基期 FCF 未扣扩张性资本支出”。
- 不再计算 ΔNWC/FCF，不输出 `delta_nwc_ratio`。

### 5.7 FCF/净利润

#### 5.7.1 分子

分子严格等于展示的 `fcf_base_value`，包含：

- 相同的 `fcf_mode`。
- 相同的窗口。
- 研发调整（若 `adjust_rd=true`）。

#### 5.7.2 分母

先确定窗口 `usedYears`：

- latest/custom：`[latest]`。
- average/median/trim_mean：`selectBaseFCF` 返回的 `usedYears`。

净利润序列：

- 若窗口内每一年 `PARENT_NETPROFIT` 字段均存在（包括负值），`profit_basis="parent"`。
- 否则整个窗口统一用重构净利润 `TOTAL_PROFIT − INCOME_TAX`，`profit_basis="reconstructed"`，note 标注“含少数股东损益”。
- 不对亏损年做剔除，不做年度比值中位数。

聚合方式与 FCF 完全一致：

```text
latest/custom: profit = NP_latest
average:       profit = mean(NP_y)
median:        profit = median(NP_y)
trim_mean:     profit = trimMean(NP_y)   // 与 FCF 相同的去极值规则
```

若 `profit <= 0` 且 `profit_basis="parent"`，尝试同一窗口重构净利润聚合；若 >0，切换 `profit_basis="reconstructed"` 并标注。仍 ≤0 → `available=false`，原因“净利润≤0”。

#### 5.7.3 比值

```text
ratio = round2(fcf_base_value / profit)
```

- `fcf_base_value <= 0` → `available=false`，原因“基期 FCF≤0”。
- `profit <= 0` → 不适用，不得用绝对值或剔除亏损年。
- `ratio > 1.5` 时追加材料性警告“FCF 为净利润的 X 倍，关注折旧摊销、减值与营运资本差异”。

`note` 固定包含：“基期 FCF（含/未含研发调整）/ 同期归母净利润（或含少数股东损益的重构净利润）；窗口 YYYY–YYYY；聚合方式 X；有效 N 年。”

### 5.8 适用性与警告

`applicable=false` 的场景：

- 未获取到年报数据。
- 金融股（`isFinancialLike(income)`）：标准 FCF 不适用。
- 基期 FCF ≤0。

不再把“最新年报净利润≤0”作为 DCF 不适用条件；净利润只影响 FCF/净利润校验。若 FCF 为正而会计亏损（如高折旧），DCF 仍可适用，但保留亏损说明。

警告清单（去重、保序、最多 6 条）：

- 市值不可用，E 按账面所有者权益（含少数股东）近似。
- 净资产为负或资本结构异常，折现率按 Re 回落。
- 有息债务为负，按 0 计。
- 债务成本不可用，按 Rf+2.0pp 估计。
- 债务成本异常（X%），请核对利息支出与有息债务。
- 折现率按合理区间下限 8.0% 约束 / 上限 15.0% 约束。
- 终值受 SGR/宏观锚/折现率−1pp 约束。
- 基期 FCF 为负，现金流贴现法不适用。
- 金融股不适用标准自由现金流估值。
- 资本支出为保全性支出的 X 倍，基期 FCF 未扣扩张性资本支出。
- FCF 为净利润的 X 倍，关注折旧摊销、减值与营运资本差异。

不得出现：“后端确定性计算”“只解释、不改数”“不得改写数字”“系统校验结果”“软上限”“包络”“离散度折减”“锚数”“回退”“退化”“三档”“带宽”“收窄”“上限 40”“下限 7”“不与基准档共用适中边界”。

### 5.9 确定性与精度

- 所有计算只用入参报表、快照、市值、行业分类、风险项；不读时间、不用随机数。
- 浮点比较与舍入统一用 `round2` / `round4` / `roundHalf` / `floorHalf` / `clampFloat`。
- 金额单位统一为元，展示再换算亿元；不得元与亿元混算。
- 同一输入两次调用，`reflect.DeepEqual` 必须为 true。
- 预推导与终态重算只有 β/RP 相关路径允许不同；其余字段必须逐位相同。

### 9.4 手工复算样例

构造一份确定性样例，用于 AC-22 和人工验收：

**折现率**

- `E=1000 亿元`，`D=200 亿元`，`V=1200 亿元`。
- `wE=0.8333`，`wD=0.1667`。
- `Rf=2.50%`，`β=1.00`，`ERP=5.50%`，`RP=0.50%` → `Re=8.50%`。
- `Rd=4.00%`，`t=25.00%` → `Rd_after=3.00%`。
- `WACC=0.8333×8.50 + 0.1667×3.00 = 7.08 + 0.50 = 7.58%`。
- 取整 `7.5%`，区间下限 `8.0%`：`round_adj=-0.08pp`，`range_adj=+0.50pp`，`r=8.00%`。
- 核对：`7.58 − 0.08 + 0.50 = 8.00`。

**复合锚 A**

- 历史锚 `9.00%`，权重 `0.45` → `4.05`。
- 前瞻锚 `12.00%`，权重 `0.45` → `5.40`。
- 宏观锚 `4.50%`，权重 `0.10` → `0.45`。
- 加权合计 `9.90%`；0.5pp 取整 `10.00%`，调整 `+0.10pp`；区间 `[−5,30]` 调整 `0.00pp`；最终 `A=10.00%`。
- 核对：`4.05 + 5.40 + 0.45 = 9.90`；`9.90 + 0.10 + 0.00 = 10.00`。

**Capex 覆盖率**

- 购建 `100 亿元`，处置收回 `10 亿元` → 净资本支出 `90 亿元`。
- 保全性支出：D&A `80 亿元` + 资产减值 `20 亿元` + 信用减值 `0` + 处置损失 `0` + 报废 `0` = `100 亿元`。
- 覆盖率 `90 ÷ 100 = 0.90`；窗口与 FCF 相同（如 2022–2024 合计）。

**FCF/净利润**

- 基期 FCF `50 亿元`（含研发调整）。
- 同窗口归母净利润合计 `40 亿元`。
- 比值 `50 ÷ 40 = 1.25`。

## 10. 关键决策、假设与风险

### 10.1 已确认决策的落地方式

| 决策 | 落地 |
|---|---|
| 0.5pp 网格 + [8,15] 区间 + 三行输出 | `discount_base_value` / `discount_rounded` / `discount_rounding_adjustment` / `discount_range_adjustment` / `discount_rate`，对账行完整展示 |
| 保全性资本支出广义唯一口径 | `preservationCapex` 原样保留，同时用于 FCF 扣减、Capex 覆盖率分母、文案；六维 `maintenanceCapex` 不动 |
| 基期 FCF 公式原样保留 | `operatingFreeCashFlow = NETCASH_OPERATE − preservationCapex` 不改；只改「Capex 覆盖率」「FCF/净利润」两个比值指标 |
| 公司特定风险溢价保留、默认 0、只加 Re、≤3pp | `company_risk_items` + `company_risk_premium`；`Re=Rf+β×ERP+RP`；禁止财务杠杆/利息保障/债务占比 |

### 10.2 需求未明确处的实现假设

以下为技术默认，不阻塞开发；若用户不同意可在开发前调整：

1. **WACC 用展示值计算**：`wE/wD` 先到 4 位小数、Re/Rd 先到 2 位小数，再算 WACC。好处是卡片乘加严格闭合；代价是与全精度 WACC 最多差 0.005pp。备选：全精度计算 WACC，再单独给对账行；不推荐，因为会对不上。
2. **三阶段 n1/n2 拆分**：`nTotal` 按公式计算；两阶段 `n1=nTotal`；三阶段 `n1=ceil(nTotal/2)`、`n2=floor(nTotal/2)`。这是同时满足“n1 公式”“n1+n2≤10”“n1,n2≥1”的唯一拆法。
3. **V 接近 0 的阈值**：`V < 1e6 元`（0.01 亿元）视为资本结构异常，`r` 回落 Re。备选：`V < 0.1 亿元`；阈值只影响极小市值/负权益公司。
4. **rationale 清洗策略**：含数字/百分号的句子直接丢弃，避免 AI 写出与卡片不一致的数字。备选：只校验数字是否等于已知参数；实现复杂，本期不做。
5. **DCF 适用性不再要求净利润>0**：只要求基期 FCF>0 且非金融股；净利润为负时仍可通过 FCF/净利润校验显示“不适用”。备选：保留净利润>0 硬条件；会误伤高折旧、正 FCF 的公司。

### 10.3 风险与规避

| 风险 | 影响 | 规避 |
|---|---|---|
| 腾讯行情市值缺失 | E 退回账面，WACC 偏离 | `equity_source=book_equity` + 明确披露；不静默 |
| 负权益/极小市值 | 权重异常 | 守卫 + `r=Re` 回落 + 警告；不输出负权重 |
| 实际 Rd 极端 | WACC 被推高/推低 | 不截断，`Rd>15`/`<1` 警告；区间约束可见 |
| AI 不返回风险项 | RP=0 | 合法，输出“未叠加公司特定风险溢价” |
| AI rationale 含数字/话术 | 输出不洁净 | 后端清洗 + 兜底句 |
| 旧缓存/旧前端 | 字段缺失 | 缓存 schema 版本；前后端同版本部署；历史记录只读忽略 |
| 删除三档引发测试大面积失败 | 开发成本 | 先删场景测试，再补 R19 新测试；保留 DCF/估值表单测试 |
| 性能 | 参数推导 <100ms | 无新增远程请求；只复用已有报表/行情/快照 |
