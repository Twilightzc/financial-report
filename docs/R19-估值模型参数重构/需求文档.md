# 估值模型参数重构（单一适中基准档）

> 需求编号：R19
> 状态：需求分析完成，待用户确认「待确认问题」后进入技术设计
> 取代关系：本文档整体取代 R15《估值模型参数分析及设定》需求文档与技术设计文档，并取代已并入 R15 的 R18 增长率估算口径。R15/R18 旧文档自本文档生效起全部废弃，仅作历史留档，不再作为实现或验收依据。

## 1. 背景与目标

### 1.1 背景

「估值模型参数分析与设定」当前由 AI 智能分析中的「估值参数」卡片输出，代码链路为后端确定性推导（`internal/service/valuation_recommend.go`、`growth.go`、`valuation_consistency.go`）+ 大模型只写 `rationale` + 前端渲染。该功能历经 R15、R18 两次叠加，现状是：

- 参数推导层级过多：三层增长锚、周期位置修正、离散度折减、软上限、包络、模型评分、三档情景、带宽与收窄、逐档 FCF 锚定同时存在。
- 同一术语存在多套口径：保全性资本支出有两套科目组合；FCF/净利润的分子分母与展示口径不一致；WACC 基线与最终折现率之间还夹着取整、截断和风险溢价。
- 展示层把推导过程直接铺给用户，并混入大量工具说明和过程话术，用户无法用卡片上的数字完成一次手工复算。

用户实际使用后列出 6 个错误：WACC 计算错误、复合锚 A 表格加总不成立、三档带宽与收窄不一致、Capex 覆盖率对不上、FCF/净利润对不上、风险溢价与叠加公司特定风险溢价对不上。这些错误不是单点 bug，而是上述多层口径叠加后的必然结果。

### 1.2 目标

本次不做增量修补，而是推翻重做，目标如下：

- **G1 单一基准档**：只输出一套「适中基准估值参数」，彻底删除保守/基准/乐观三档、带宽、收窄、逐档锚定、逐档套用。
- **G2 每个数字可复算**：用户拿卡片上的构成项和口径说明，能在 1 分钟内手工复算出最终值；加总关系必须成立，取整和区间约束必须单独可见。
- **G3 消除 6 类错误**：WACC、复合锚 A、Capex 覆盖率、FCF/净利润、风险溢价五处口径统一；三档相关错误随功能删除而消失。
- **G4 输出洁净**：估值参数区只保留参数、口径、数据年份和材料性提示，不出现工具说明、推导过程、规则元语言、内部变量名。
- **G5 确定性**：同一公司、同一期财报、同一行业分类，任何时候输出完全一致；AI 不参与任何数字计算。

可衡量的达成标准：

- 任一公司输出的折现率，与其展示的 `Re`、`Rd(税后)`、`E/V`、`D/V`、取整/约束行在 0.05pp 内闭合。
- 复合锚 A 若保留构成表，`Σ(锚值×权重)` 必须等于表中的 `A_raw`，`A_raw` 经取整/约束必须等于最终 `A`，且取整/约束单独成行。
- Capex 覆盖率、FCF/净利润均可由同一基期/同一窗口的财报科目复算，误差不超过展示精度。
- 当前产品界面、API、AI rationale 与新需求/技术文档（R15 历史留档除外）不再出现「保守/基准/乐观三档、带宽、收窄、min/max 锚定、不与基准档共用适中边界」等字样。

## 2. 现状与问题（6 个错误的根因排查）

本节是重构依据。所有结论均来自当前代码与 R15 技术设计 §20 的核对，不是推测。

### 2.1 错误一：WACC 计算错误

**证据位置**：`internal/service/valuation_recommend.go` 的 `recommendDiscountRate`、`valuationRiskPoints`、`clampDiscountRate`、`equityCostCAPM`；`internal/service/analysis.go` 的 `waccWithEquityCostDetail`、`equityValue`、`effectiveTaxRate`、`debtCapitalCost`；`internal/api/ai.go` 的 `computeAIAnalysis` 调用链。

**当前实现**

- `recommendDiscountRate` 先由 `betaFor` 取行业 β（周期 1.2 / 一般 1.0 / 公用 0.8），`equityCostCAPM` 计算 `Re = Rf 2.5% + β×ERP 5.5%`。
- `waccWithEquityCostDetail` 取 `debt = interestBearingDebt(balance)`、`equity = equityValue(balance)`，其中 `equityValue` 返回 `TOTAL_EQUITY`（账面所有者权益合计，含少数股东权益），`invested = debt + equity`，权重为 `debt/invested`、`equity/invested`。
- 债务成本 `Rd` 取“偿付利息 ÷ 平均有息债务”，税后为 `Rd×(1−实际税率)`；实际税率取 `INCOME_TAX/(TOTAL_PROFIT−INVEST_JOINT_INCOME)`，缺失回落 25%，并 clamp 到 [0,1]。
- 最终 `res.Rate = clampDiscountRate(res.WaccBaseline + res.RiskPremium)`，`clampDiscountRate` 先四舍五入到 0.5pp 网格，再截断到 [8,15]。

**错在哪里**

1. **权重用账面权益而非市值权益**。WACC 的 `E` 业界标准是股权市值，`D` 是有息债务账面值。当前链路 `RecommendValuationWithSnapshot` 的入参只有三张报表，没有行情/总市值；`computeAIAnalysis` 虽然已取到 `quote.MarketCap`，但没有传入。高 PB 公司（如消费、医药）账面权益远低于市值，导致 `E/V` 被低估、`D/V` 被高估，WACC 系统性偏离。
2. **`TOTAL_EQUITY` 含少数股东权益**。即使退化为账面口径，也应明确是“全部股东权益”还是“归母权益”；当前既未区分，也未在输出中披露。
3. **没有负权益/负投入资本的守卫**。代码只判断 `invested == 0`。当 `equity < 0` 且 `debt + equity < 0` 时，`debt/invested` 与 `equity/invested` 会同时变号，WACC 可能为负或远低于债务成本；当 `debt + equity` 接近 0 时权重会爆炸。这是会计上真实存在的困境公司场景。
4. **公司特定风险溢价加错了层级**。CAPM 的标准写法是 `Re = Rf + β×ERP + 公司特定风险溢价`，再进入 `WACC = E/V×Re + D/V×Rd×(1−t)`。当前是先用不含风险溢价的 `Re` 算出 `WACC 基线`，再把 `RiskPremium` 整个加到 WACC 上：`r = WACC + RP`。这等价于给债务部分也加了股权风险溢价，且当 `E/V < 1` 时，对股权成本的实际加成被放大为 `RP/(E/V)`。输出却写成“WACC 基线 + 公司特定风险溢价”，口径与公式不一致。
5. **风险点本身就是财务杠杆，已包含在 WACC 里**。`valuationRiskPoints` 的三项是：有息债务占比 >40%、利息保障倍数 <3、财务杠杆 >3。这三项都已经通过 `D/V` 权重和 `Rd` 进入 WACC；再作为“公司特定风险溢价”加一次，属于重复计算。真正的公司特定风险应是 β 无法覆盖的治理、诉讼、客户集中、流动性等定性事项。
6. **风险点判定缺少守卫**。第二项只看 `interestCoverage(income) != nil && *cov < 3`，没有要求“有息债务 >0”；第三项 `lev == nil || *lev > 3`，当股东权益为负时杠杆为负，不会触发风险点，反而把最危险的负权益公司判为无风险。
7. **最终值与展示值不闭合**。`WaccBaseline + RiskPremium` 先加总，再 `round(0.5pp)`，再 clamp。例：`WACC=7.8`、`RP=1.0`，展示为 8.8，最终 `r=9.0`；`WACC=14.8`、`RP=1.0`，展示为 15.8，最终被截断为 15.0。卡片上没有任何一行解释这 0.2pp/0.8pp 的差。

**重构要求**

- 采用标准 CAPM/WACC：`Re = Rf + β×ERP + RP_company`；`WACC = E/V×Re + D/V×Rd×(1−t)`；折现率 `r` 默认等于 WACC，若做取整/区间约束，必须单独展示。
- `E` 优先用总市值（行情已可得），`D` 用有息债务账面值；市值不可用时才退回账面权益，并明确披露。
- `equity ≤ 0`、`V ≤ 0`、`V` 接近 0 时不得硬算权重，应回落并给出明确警告。
- `RP_company` 默认 0；只在有可列示的非财务风险事项时逐项给出，且不得再用财务杠杆/利息保障作为加分项。
- 所有取整、区间约束必须可见，且 `r` 与构成项可闭合。

### 2.2 错误二：复合锚 A 的表格加总不成立

**证据位置**：`internal/service/growth.go` 的 `composeGrowthAnchor`；`internal/service/valuation_recommend.go` 中 `GrowthHistory`、`GrowthForward`、`GrowthCycleAdjust`、`GrowthComposite` 的赋值；`internal/service/ai.go` 的 `valuationPromptBlock`；`internal/web/app.js` 的 `growthAnchorRows`。

**当前实现**

- `composeGrowthAnchor` 计算 `raw = wHist×histAdj + wFwd×fwd.Value + wMacro×macro.Value`，随后 `RawA = roundHalf(raw)`，`A = clampFloat(RawA, −5, 30)`。
- 输出字段：`GrowthHistory = x`（历史锚，展示精度）、`GrowthCycleAdjust = round1(delta)`、`GrowthForward = round2(fwd.Value)`、`GrowthMacro = macro.Value`、`GrowthComposite = A`（已取整、已截断）。
- 后端提示词 `ai.go` 的「复合锚贡献」行，用展示值相乘后求和，写成“合计 A_raw → A”；前端 `growthAnchorRows` 也用展示值算贡献，最后一行直接显示 `A`。

**错在哪里**

1. **取整发生在不同层级**。`raw` 是全精度，`RawA` 是 0.5pp 网格，`A` 还可能被 clamp 到 [−5,30]；但表格的每个贡献项用的是已取整的 `x`、`round1(delta)`、`round2(fwd)`、`macro`。各项相加得到的是“展示值之和”，不是真实 `raw`，也不是 `RawA`。
2. **没有取整行和约束行**。表格没有“0.5pp 取整”与“区间约束 [−5,30]”两行，用户只能看到“各项之和 ≠ A”。
3. **A 被截断时差异可以很大**。若 `raw=35`，`A=30`，表格各项之和为 35，最终 A 为 30，差 5pp；当前没有任何解释。
4. **权重也是展示值**。权重 0.45/0.45/0.10 相加为 1，但若未来权重改为 0.333/0.333/0.333，按两位小数展示会得到 0.999；当前没有“权重合计”校验。
5. **同一字段存在“计算值”和“展示值”两套**。`GrowthForward` 是 `round2`，而 `composeGrowthAnchor` 用的是未取整的 `fwd.Value`；即使其他项都不取整，加总也对不上。

**重构要求**

- 二选一，不能保留现状：
  - **方案 A（推荐）**：保留一张最小构成表，但必须同时输出 `A_raw`、取整行、约束行、最终 `A`，且 `Σ(锚值×权重) = A_raw`；所有单元格统一精度（锚值 2 位、权重 2 位、贡献 2 位、合计 2 位），并做“权重合计 = 1.00”校验。
  - **方案 B**：删除构成表，只输出最终 `A` 与一句不含加总关系的依据说明（例如“综合历史、前瞻与宏观锚，取 10.5%”）。若采用 B，不得再出现任何“各项贡献相加”的表述。
- 后端计算与展示必须用同一精度口径：要么在计算前统一取整，要么在输出中显式标注“展示值经四舍五入，合计以 A_raw 为准”。不允许“计算用全精度、展示用另一套值、却不给对账行”。

### 2.3 错误三：三档带宽与收窄不一致

**证据位置**：`internal/service/valuation_recommend.go` 的 `computeScenarioBands`、`scenarioBounds`、`buildScenario`、`buildScenarios`、`scenarioCappedBy`、`scenarioFCF`；`internal/web/app.js` 的 `scenarioBandText`、`scenarioToFormParams`；R15 技术设计 §20.7。

**当前实现**

- `computeScenarioBands`：`Raw = |(histA + delta) − fwd.Value|`，`Growth = clamp(roundHalf(Raw), 1.5, 4.0)`；锚不足时 `D = 0.2×max(A,0)` 再 clamp；`A<0` 或基准模型为 zero 时 `Growth=0`；`Discount=1.0`、`Terminal=0.5` 为常量。
- `scenarioBounds`：乐观档返回 `(RawA, −5, 40, 7)`，即用未截断的 `RawA`、锚上限 40、折现率下限 7；保守/基准档返回 `(A, −5, 30, 8)`。
- `buildScenario`：`A_s = clamp(baseA + off.DA, aLo, aHi)`，`DeltaGrowth = round1(A_s − in.A)`。
- 前端 `scenarioBandText` 固定文案“带宽来源：历史与前瞻分歧 X.Xpp → 收窄到 Y.Ypp（区间 1.5–4.0pp）”。
- 基期 FCF 另有逐档锚定：保守 `min(base, Low)`、乐观 `max(base, High)`，非强周期再按 `base×[0.75,1.25]` clamp，强周期穿越。

**错在哪里**

1. **“收窄”文案与实际方向相反**。当原始分歧 `Raw < 1.5` 时，带宽被抬到下限 1.5，这是“放宽”不是“收窄”；当 `Raw > 4.0` 时是收窄。前端不区分，统一写“收窄到”。
2. **乐观档换了锚的基准**。保守/基准用已 clamp 的 `A`，乐观用未 clamp 的 `RawA`，再放宽到 40。`DeltaGrowth = A_s − A` 因此不等于 `band_g`：例如 `RawA=35`、`A=30`、`band_g=4`，乐观 `A_s=39`，`DeltaGrowth=9`，但界面写“带宽 4pp”。这是最直接的“带宽与收窄不一致”。
3. **三个维度各自独立，没有统一的“档”定义**。增长锚带宽、折现率 ±1.0pp、终值 ±0.5pp 是三个常量；终值还可能被 `macro`、`r−1`、`SGR` 吸收，`DeltaGrowth` 只记录增长锚，不记录终值实际变化。用户无法判断“这一档到底变了什么”。
4. **FCF 还有第四套档位逻辑**。基期 FCF 的 min/max + ±25% clamp + 强周期穿越，与增长/折现率/终值的带宽没有关系；同一档里 FCF、增长率、折现率可能分别朝不同方向变化。
5. **退化场景仍显示三档**。`A<0` 或 zero 模型时 `Growth=0`，三档增长参数相同，只剩折现率 ±1.0pp，但界面仍渲染完整三档表，信息量为负。
6. **“适中基准档”并不适中**。基准档是 `A`，但乐观档可以用 `RawA` 突破 30，保守档又被 clamp 到 30 以内；三档不是围绕同一基准的对称扰动，而是三套不同边界的重算。

**重构要求**

- 删除三档功能本身，而不是修正文案。所有 `scenario_*` 字段、`conservative/base/optimistic`、`band_*`、`capped_by`、逐档 FCF 锚定、逐档套用全部移除。
- 只保留一套「适中基准参数」。适中通过锚权重和单一收口规则实现，不通过“保守/乐观”两侧夹逼实现。
- 不再出现“带宽、收窄、区间 1.5–4.0pp、上限 40、下限 7、不与基准档共用适中边界”等任何字样。

### 2.4 错误四：Capex 覆盖率计算对不上

**证据位置**：`internal/service/valuation_consistency.go` 的 `capexCoverage`、`preservationCapex`；`internal/service/analysis.go` 的 `maintenanceCapex`、`constructNet`；`internal/service/ai.go` 的 capex 提示行与一致性行。

**当前实现**

- `capexCoverage(cf, income)`：分子 `cf.Fields["CONSTRUCT_LONG_ASSET"]`（购建固定资产、无形资产和其他长期资产支付的现金，总额，未扣处置收回）；分母 `preservationCapex(income, cf)`。
- `preservationCapex` = 资产减值损失 + 信用减值损失 + `FA_IR_DEPR` + `USERIGHT_ASSET_AMORTIZE` + `IA_AMORTIZE` + `LPE_AMORTIZE` + 处置长期资产损失（仅损失）+ `FA_SCRAP_LOSS`。
- 另有 `maintenanceCapex(cf)` = `FA_IR_DEPR` + `IA_AMORTIZE` + `LPE_AMORTIZE` + `USERIGHT_ASSET_AMORTIZE` + `ASSET_IMPAIRMENT` + `FA_SCRAP_LOSS`，不含信用减值损失与处置损失；`constructNet = CONSTRUCT_LONG_ASSET − DISPOSAL_LONG_ASSET`。
- 展示与提示词写作“购建长期资产现金/保全性资本支出 X 倍（>1.3 提示基期 FCF 可能偏乐观）”。

**错在哪里**

1. **分子是总额，分母是保全口径，二者不可比**。`CONSTRUCT_LONG_ASSET` 未扣 `DISPOSAL_LONG_ASSET`（处置收回），而 FCF 扣的是 `preservationCapex`；同一张表里“资本支出”有三个值：购建总额、净额、保全性支出。
2. **“保全性资本支出”有两套定义**。估值链路用 `preservationCapex`（含信用减值、处置损失），六维分析用 `maintenanceCapex`（不含）。同名不同义，用户按任一处理解都会对不上。
3. **分母混入了非资本支出项目**。资产减值损失、信用减值损失、处置损失、报废损失是损益/非现金项目，不是“维持产能必须发生的现金资本支出”；把它们放进分母，会让覆盖率的分母忽大忽小，尤其减值大年。
4. **期间不匹配**。覆盖率只看 `latest` 单年，而基期 FCF 可能是最近 3 年平均、中位数、去极值平均或自定义值。用户拿“基期 FCF”与“单年覆盖率”对照，必然对不上。
5. **分母 ≤0 时静默返回不可用**。没有说明是“无折旧摊销”还是“数据缺失”，也没有区分“资本支出为 0”和“科目缺失”。
6. **标签没有写年份、分子分母口径**。同一家公司不同年份的覆盖率可能从 0.8 变到 2.0，卡片上只有一个数字，无法判断对应哪一年。

**一个可复现的例子**

购建长期资产 100 亿元、处置长期资产收回 10 亿元、D&A 80 亿元、资产减值 20 亿元、处置损失 0。当前覆盖率 = 100 ÷（80+20）= 1.00；按“净资本支出 ÷ 保全性支出”= 90 ÷ 100 = 0.90；按“净资本支出 ÷ D&A”= 90 ÷ 80 = 1.125。三个结果都可以被称为“Capex 覆盖率”，但结论从“刚好覆盖”变成“覆盖不足”或“明显扩张”。

**重构要求**

- 全项目只保留一个“保全性资本支出”定义，FCF 扣减、Capex 覆盖率分母、说明文案三处必须完全一致。
- 分子统一为“净资本支出 = 购建长期资产支付的现金 − 处置长期资产收回的现金”，并明确“未扣处置时不能与净额混用”。
- 分母是否包含减值/处置/报废，需在待确认问题中拍板；推荐只用“折旧与摊销（D&A）”作为分母，另用一句口径说明 FCF 扣减的保全性支出包含哪些非现金项。若坚持用保全性支出，则必须把分子也改为同一口径，并改标签。
- 覆盖率必须与基期 FCF 同年/同窗口，标签写清“基期年份/窗口 + 分子 + 分母”。

### 2.5 错误五：FCF/净利润对不上

> **R23 已修订**：本节「分母优先用同期归母净利润、缺失/非正回落重构净利润」的口径已被 R23 取代。现行实现的分母**固定为重构净利润 `netProfitReconstructed`（税前利润 − 所得税，含少数股东损益）**，与 R3「净利润现金含量」同口径，`profit_basis` 恒为 `"reconstructed"`。本节其余要求（分子与基期 FCF 一致、窗口/聚合方式一致、分母 ≤0 输出「不适用（净利润≤0）」）继续有效。

**证据位置**：`internal/service/valuation_consistency.go` 的 `fcfToProfitMedian`；`internal/service/analysis.go` 的 `netProfitReconstructed`；`internal/service/valuation_recommend.go` 的 `FCFProfitRatio` 赋值；`internal/service/ai.go` 的“现金含量提示”与一致性行。

**当前实现**

- `fcfToProfitMedian`：取最近 `min(年数, 5)` 年，逐年计算 `fcf = fcfByYear[y] / netProfitReconstructed(incomeByYear[y])`；只保留 `fcf > 0 && np > 0` 的年份；有效样本 <3 返回不可用；否则返回年度比值的中位数。
- `netProfitReconstructed` = 税前利润 − 所得税，含少数股东损益，不是归母净利润。
- 分子是逐年 FCF（经营现金流 − 保全性支出），不是最终选定的基期 FCF；也不含研发调整。
- 展示与提示词写作“FCF 中位数为净利润的 X 倍（>1.5）”，前端写作“FCF/净利润”。

**错在哪里**

1. **分子不是基期 FCF**。用户看到的基期 FCF 可能是 3 年平均/中位数/去极值平均/自定义值，且可能含研发扩张加回；而 FCF/净利润用的是逐年 FCF。两个数字不在同一口径上。
2. **分母不是归母净利润**。`netProfitReconstructed` 含少数股东损益；东财 `PARENT_NETPROFIT` 才是归母。项目在 SGR 等处已经区分“归母优先、缺失回落重构”，这里没有区分。
3. **“中位数”是年度比值的中位数，不是“中位 FCF ÷ 中位净利润”**。两种算法在 FCF 与净利润年度波动不同步时结果差异很大；卡片没有说明是哪一种。
4. **亏损年份被直接丢弃**。只保留 `fcf>0 && np>0` 的年份，样本数可能从 5 年降到 3 年；分母为负的年份本应提示“FCF/净利润无意义”，现在被静默剔除，幸存者偏差会让比值偏高。
5. **有效样本数与窗口未披露**。用户不知道这个 X 倍是 3 年、4 年还是 5 年算出来的。
6. **自定义 FCF 无法参与**。`fcf_mode=custom` 时，逐年序列与自定义基期 FCF 无关，但卡片仍可能显示基于历史序列的 FCF/净利润。

**一个可复现的例子**

基期 FCF 选“最近 3 年平均”= 50 亿元；最近一年 FCF = 80 亿元、归母净利润 = 40 亿元、重构净利润 = 45 亿元。当前实现可能用最近一年 80 ÷ 45 = 1.78（或年度比值中位数），但用户按卡片上的基期 FCF 复算得到 50 ÷ 40 = 1.25（或 50 ÷ 45 = 1.11）。两个数都叫“FCF/净利润”，却相差 0.5 倍以上。

**重构要求**

- 分子必须与展示的基期 FCF 完全一致（含选取方式、窗口、研发调整）。
- 分母优先用同期归母净利润 `PARENT_NETPROFIT`；缺失/非正时回落重构净利润，并标注“含少数股东损益”。
- 聚合方式必须固定并写入口径：推荐“同窗口 FCF 合计 ÷ 同窗口归母净利润合计”；若用年度比值中位数，必须写明“年度比值中位数，有效样本 N 年，亏损年剔除”。
- 亏损年/分母 ≤0 时不得静默计算，应显示“不适用”并说明原因。
- 标签必须写清“分子口径 / 分母口径 / 窗口 / 是否含研发调整”。

### 2.6 错误六：风险溢价与叠加公司特定风险溢价对不上

**证据位置**：`internal/service/valuation_recommend.go` 的 `equityCostCAPM`、`recommendDiscountRate`、`valuationRiskPoints`、`clampDiscountRate`；`internal/service/ai.go` 的系统提示词“WACC 基线 + 公司特定风险溢价”段。

**当前实现**

- `equityCostCAPM(beta) = Rf 2.5 + β×ERP 5.5`，其中不含公司特定风险溢价。
- `valuationRiskPoints` 返回 0–3 个风险点：有息债务占比 >40%、利息保障倍数 <3、财务杠杆 >3。
- `res.RiskPremium = min(riskPoints×1.0, 3.0)`；`res.Rate = clampDiscountRate(res.WaccBaseline + res.RiskPremium)`。
- 输出字段分别有 `WaccBaseline`、`RiskPremium`、`DiscountRate`，前端按“WACC 基线 + 风险溢价”展示。

**错在哪里**

1. **风险溢价的定义与 CAPM 不一致**。CAPM 的公司特定风险溢价应加在 `Re` 上，不是加在 WACC 上；当前 `Re` 不含它，WACC 之后再加，导致：
   - 债务部分也被加了股权风险溢价；
   - `E/V < 1` 时，最终 WACC 对股权成本的实际上浮是 `RP/(E/V)`，大于名义 `RP`；
   - 展示的“WACC 基线 + RP”与 `WACC = E/V×Re + D/V×Rd(1−t)` 不是同一个公式。
2. **与财务杠杆重复计算**。三个风险点全部是财务风险，已经通过 `D/V` 和 `Rd` 反映；再加 1–3pp 等于对同一风险收两次费。
3. **“公司特定”名不副实**。真正的公司特定风险是 β 未覆盖的治理、诉讼、客户集中、流动性、会计质量等；当前没有任何一项，全部是杠杆/覆盖倍数。
4. **风险点判定有缺口**。利息保障倍数 <3 未要求有息债务 >0；负权益公司的杠杆为负，不会触发第三个风险点。
5. **取整/截断后加总不闭合**。`WACC + RP` 经 0.5pp 取整和 [8,15] 截断，最终 `r` 可能不等于两者之和，卡片没有任何解释。
6. **提示词把错误口径传给大模型**。系统提示写“折现率由 WACC 基线 + 公司特定风险溢价确定性推导”，大模型在 `rationale` 中复述这一口径，错误被二次放大。

**一个可复现的例子**

WACC 基线 7.8%、RP 1.0%、E/V = 80%。当前做法：7.8% + 1.0% = 8.8%，取整后 r = 9.0%。按 CAPM 把 RP 加在 Re 上：WACC = 7.8% + 80%×1.0% = 8.6%，取整后 r = 8.5%。两者相差 0.5pp；若再触发 8% 下限或 15% 上限，展示的“7.8+1.0”与最终 r 还会再差一截。

**重构要求**

- `RP_company` 只进入 `Re`：`Re = Rf + β×ERP + RP_company`。
- `RP_company` 默认 0；只有逐项列示的非财务风险才可加分，每项 0.5–1.0pp，合计 ≤3pp；不得再用有息债务占比、利息保障、财务杠杆作为加分项。
- 若无法给出可审计的风险事项，`RP_company` 必须为 0，并在口径说明中写“未叠加公司特定风险溢价”。
- 最终折现率的取整/区间约束单独展示，确保 `WACC → r` 的每一步可见。

## 5. 基准估值参数的计算口径

本节定义重构后**唯一一套**「适中基准估值参数」。所有数值均为后端确定性计算，AI 不参与。

### 5.1 基期自由现金流（FCF）

**定义**

```
FCF_t = 经营活动现金流量净额_t − 保全性资本支出_t
```

- 经营活动现金流量净额取现金流量表 `NETCASH_OPERATE`。
- 保全性资本支出取“维持现有经营能力必须发生的支出”的近似值，全项目只允许一个定义（见 5.2）。
- 若开启研发扩张调整：`FCF_t += max(0, 本年度研发费用 − 上年度研发费用)`；上年度缺失按 0；研发费用取利润表 `RESEARCH_EXPENSE` 近似。该调整只影响基期 FCF，不改变历史序列的展示口径，但必须在口径行注明“已加回研发扩张 X 亿元”。

**基期选取**

保留五种方式，语义固定：

| 方式 | 定义 | 年数 |
|---|---|---|
| latest | 最近一个年报的 FCF | 1 |
| average | 最近 N 年 FCF 算术平均 | N，缺省 3，超过可用年数截断 |
| median | 最近 N 年 FCF 中位数 | 同上 |
| trim_mean | 去掉最高、最低后平均；不足 3 年退化为 average | 同上 |
| custom | 用户输入值，按单位换算为元 | 1 |

- 年报口径：报告期以 `12-31` 结尾；金融股/银行不适用标准 FCF，输出“不适用”并说明原因。
- 若选取结果为负或 0：输出“现金流贴现法不适用”，不得用绝对值或强行调正。
- 输出必须包含：基期 FCF（亿元，2 位小数）、选取方式、窗口起止年份、是否含研发调整。

### 5.2 保全性资本支出（唯一口径）

> **R23 已修订**：现行实现以 R3 财务指标分析的 `maintenanceCapex(cf)`（`internal/service/analysis.go`）为**唯一权威定义**，估值链路（`operatingFreeCashFlow`、Capex 覆盖率分母、`fcf_series[].preservation_capex`、公司价值卡片）全部调用它。权威公式为：
>
> ```
> 保全性资本支出 =
>     FA_IR_DEPR + IA_AMORTIZE + LPE_AMORTIZE + USERIGHT_ASSET_AMORTIZE
>   + ASSET_IMPAIRMENT（现金流量表补充资料） + FA_SCRAP_LOSS
> ```
>
> 不再计入利润表资产减值/信用减值损失与 `DISPOSAL_LONGASSET_LOSS`（处置长期资产损失）；`preservationCapex`/`disposalLongAssetLoss` 已删除。下文「推荐定义（待确认）」保留为 R19 历史记录，不再作为实现依据。

**推荐定义（待确认）**

```
保全性资本支出 =
    固定资产折旧、油气资产折耗、生产性生物资产折旧（FA_IR_DEPR）
  + 使用权资产摊销（USERIGHT_ASSET_AMORTIZE）
  + 无形资产摊销（IA_AMORTIZE）
  + 长期待摊费用摊销（LPE_AMORTIZE）
  + 资产减值损失（ASSET_IMPAIRMENT / ASSET_IMPAIRMENT_LOSS）
  + 信用减值损失（CREDIT_IMPAIRMENT / CREDIT_IMPAIRMENT_LOSS）
  + 处置长期资产损失（仅损失，收益按 0）
  + 固定资产报废损失（FA_SCRAP_LOSS）
```

- 该定义同时用于：FCF 扣减、Capex 覆盖率分母、口径说明。三处不得再出现第二套定义。
- 该定义是项目既有的保守近似：减值/处置/报废损失并非现金资本支出，但计入分母可避免高减值、高处置年份的 FCF 被高估；必须在口径行说明“保全性支出含非现金减值/处置项”，不能把它当作纯现金资本支出。
- 若六维分析仍需“折旧摊销+资产减值+报废损失”的旧口径，必须改名为“维持性资本支出（六维分析口径）”，不得再称“保全性资本支出”。
- 减值损失按项目既有符号约定处理：非金融股用收益口径字段取反，金融股用损失口径字段；两者互斥，不得重复计。
- 若用户选择“仅 D&A”的更简口径（见待确认 Q4），则 FCF、覆盖率分母、文案同步切换，不得混用。

### 5.3 折现率（WACC / CAPM）

**定义**

```
Re = Rf + β × ERP + RP_company
WACC = (E / V) × Re + (D / V) × Rd × (1 − t)
V = E + D
r = WACC（默认）
```

- `E`、`D` 统一换算为元后计算，展示时再换算为亿元；不得用“亿元”与“元”混算。

**各项口径**

| 项 | 口径 | 取数/来源 | 边界 |
|---|---|---|---|
| Rf | 10 年期中国国债收益率；不可得时用 2.5% 常量 | 外部数据/常量 | 0–10% |
| ERP | 5.5% | 项目常量 | 固定，不随公司变 |
| β | 周期 1.2 / 一般 1.0 / 公用 0.8 | AI 行业分类；缺失按波动/FCF 周期兜底，再缺失 1.0 | 0.5–2.0 |
| RP_company | 默认 0；按非财务风险事项逐项列示，每项 0.5–1.0pp，合计 ≤3pp | 定性事项清单 | 不得用杠杆/利息保障/债务占比 |
| E | 总市值 = 行情 `MarketCap` | 腾讯行情 | >0；缺失或 ≤0 退回账面权益并披露 |
| D | 有息债务账面值 | 资产负债表 | ≥0；负值按 0 |
| Rd | 偿付利息 ÷ 平均有息债务；平均 =（期初+期末）/2 | 利润表/资产负债表 | 实际值不截断，异常高/低值给警告；不可用时 `Rf+2pp` 并 clamp [3,8]，标注“估计” |
| t | 实际税率 = 所得税 ÷（利润总额 − 联营投资收益） | 利润表 | 缺失 25%；clamp [0,1] |
| 权重 | E/V、D/V | 上述 E、D | E≤0 或 V≤0 不得硬算 |

**收口规则**

- 默认 `r = WACC`，按 0.5pp 网格四舍五入。
- 若保留合理区间 [8,15]（待确认 Q3）：先取整、再截断，输出必须同时显示“取整前 WACC”“取整后 r”“区间约束调整”三行；不得只显示最终 r。
- 若 WACC 低于下限，输出“按合理区间下限 8.0% 约束”，不得写成“WACC=8.0%”。
- 若 E 退回账面权益，必须写“市值不可用，E 按账面所有者权益（含少数股东）近似”。
- 若 `equity ≤ 0` 或 `V ≤ 0`：不得输出负权重；回落 `r = Re` 或 10.0%，并给出“净资产为负/资本结构异常”警告。

**展示对账行（示例格式，非最终文案）**

```
Re = 2.5% + 1.0×5.5% + 0.0% = 8.0%
Rd（税后）= 3.2% × (1−25.0%) = 2.4%
E/V = 82.0%，D/V = 18.0%
WACC = 82.0%×8.0% + 18.0%×2.4% = 7.0% → 取整 7.0%
```

- 所有分项保留 2 位小数；最终 r 保留 1 位（0.5pp 网格）。
- 对账容差 0.05pp；超出即视为缺陷。

### 5.4 增长率锚与复合锚 A

**历史锚 x**

- 对营业收入、重构净利润、FCF 的稳健同比增速等权平均；每项至少 2 个有效年报，且上年为正。
- 剔除异常年规则沿用项目现有 `weightedGrowth`：亏损年、基数 ≤0、极端值不计入；有效项不足时按剩余项等权。
- 全部不可用时，历史锚不可用，不得按 0% 参与加权。

**前瞻锚**

- 一致预期：`0.7×净利润 CAGR + 0.3×营收 CAGR`；机构数 ≥2、预测年度 ≥1、离散度 ≤25pp 才可用；否则不可用。
- 前瞻锚保留全精度参与计算，展示时保留 2 位小数；不得用展示值反算 A。

**宏观锚**

- 动态 GDP TTM 同比；不可用时用 4.5% 常量；clamp [0,10]。
- 必须标注“动态 GDP”或“固定值 4.5%（GDP 数据不可得）”，不得把固定值写成实时 GDP。

**权重**

| 可用锚 | 历史 | 前瞻 | 宏观 |
|---|---|---|---|
| 历史 + 前瞻（高可靠） | 0.45 | 0.45 | 0.10 |
| 历史 + 前瞻（中可靠） | 0.55 | 0.35 | 0.10 |
| 仅历史 | 0.85 | 0 | 0.15 |
| 仅前瞻 | 0 | 0.85 | 0.15 |
| 都不可用 | 0 | 0 | 0，A=0，模型退化为零增长 |

- 权重合计必须为 1.00；展示保留 2 位小数，并校验合计。

**复合锚 A**

```
A_raw = w_hist × (x + Δ_cycle) + w_fwd × 前瞻锚 + w_macro × 宏观锚
A = clamp(round0.5(A_raw), −5, 30)
```

- `Δ_cycle` 为周期位置修正，只作用于历史锚；保留时必须在输出中写一句“周期位置修正 +X.Xpp，已含于历史锚”，不再单独成表。
- `A_raw` 与 `A` 都必须可输出（若保留构成表）；取整行、约束行必须单独显示。
- A<0 时：结构性负增长 → zero 模型；周期性负增长 → perpetual 模型并给低终值；不得再把 A<0 简单截断为 0 后当正常增长。

### 5.5 g1、n1、g2、n2、g∞ 与模型

**g1**

- 推荐口径：`g1 = clamp(A, g∞, min(30%, max(前瞻锚, SGR) + 2pp))`；两者都可用时取较高者再加 2pp，只有一项可用时用该项 +2pp；都不可用时 `g1 = min(A, 30%)`。若上限低于 g∞，按 g∞ 收口并给出警告。
- 删除离散度折减、软上限、包络三重收口；只保留一个可解释的上限。
- g1 按 0.5pp 网格；若 g1 被上限压低，输出一句“g1 受前瞻/SGR +2pp 约束”，不再列四步表。
- g1 不得低于 g∞；不得为负（负增长由模型选择处理）。

**n1**

- 高增长期年数：`n1 = clamp(round((g1 − g∞) / 1.5), 3, 10)`。
- 只在两阶段/三阶段模型输出；永续/零增长模型不输出 n1。

**g2 / n2（仅三阶段）**

- g2 为中间段增长率，必须满足 `g1 ≥ g2 ≥ g∞`；n2 由剩余衰减年限决定，且 `n1 + n2 ≤ 10`。
- 无严格递减解时按 three → two → perpetual → zero 降级，并在模型名后标注“已降级”。

**g∞**

```
g∞ = max(0, floor0.5(min(宏观锚, r − 1.0, SGR)))
```

- SGR 不可用时只受宏观与 `r−1` 约束。
- 只显示真正生效的约束项（宏观/SGR/折现率−1）；不得把未生效的约束写成“受 X 约束”。
- g∞ 必须 < r；若 `r−1 < 0`，g∞ 取 0。

**模型选择**

- 内部保留 `A/gap/score` 判定：A≥6 且 gap≥4 且 score≥70 → 三阶段；A≥2 且 gap≥1.5 且 score≥45 → 两阶段；A≥0 → 永续；否则零增长。
- 对外只输出最终模型名称 + 一句“为什么选这个模型”，不输出评分、权重、阈值表。
- 若发生降级，模型名后加“（已降级）”，并给一句原因。

### 5.6 辅助指标：Capex 覆盖率与 FCF/净利润

> **R23 已修订**：本节两处口径均已调整——（1）保本支出分母统一复用 R3 `maintenanceCapex`，不含利润表减值/信用减值与处置损失；（2）FCF/净利润分母固定为**重构净利润 `netProfitReconstructed`（含少数股东损益）**，不再优先取 `PARENT_NETPROFIT`、也无回落分支。窗口、聚合方式、分子基期 FCF 一致性与「不适用」处理要求继续有效。

**Capex 覆盖率**

推荐口径（待确认 Q4、Q5）：

```
净资本支出 = 购建固定资产、无形资产和其他长期资产支付的现金（CONSTRUCT_LONG_ASSET）
           − 处置固定资产、无形资产和其他长期资产收回的现金（DISPOSAL_LONG_ASSET）
Capex 覆盖率 = 净资本支出 ÷ 保全性资本支出
```

- 分子、分母、基期必须与 FCF 同年/同窗口：FCF 为 latest 时取最新年报；为 average/median/trim_mean 时取同窗口的净资本支出合计 ÷ 保全性支出合计（或同一年数下的平均值，二者等价）；为 custom 时取最新年报并注明“自定义 FCF，覆盖率按最新年报”。不得用单年覆盖率去解释多年基期 FCF。
- 分母 ≤0：输出“不适用（保全性资本支出≤0）”；分子科目缺失：输出“不适用（购建长期资产现金缺失）”；不得静默显示 0。
- 标签必须写“净资本支出/保全性资本支出，基期 YYYY 年（或 YYYY–YYYY 窗口）”。
- 若用户最终选择“净资本支出 ÷ D&A”的行业口径（本期不推荐，见 Q4），分母改为 D&A，标签同步改为“Capex/D&A”，且 FCF、覆盖率分母、文案需整体切换，不得两套并存。

**FCF/净利润**

推荐口径（待确认 Q6）：

```
FCF/净利润 = 基期 FCF ÷ 同期归母净利润
```

- “同期”与基期 FCF 的窗口、聚合方式一致：
  - latest：最新年报 FCF ÷ 最新年报归母净利润；
  - average：窗口内 FCF 平均 ÷ 窗口内归母净利润平均；
  - median：窗口内 FCF 中位数 ÷ 窗口内归母净利润中位数；
  - trim_mean：窗口内 FCF 去极值平均 ÷ 窗口内归母净利润按同样规则去极值平均；
  - custom：自定义 FCF ÷ 最新年报归母净利润，并注明“自定义口径”。
- 归母净利润取 `PARENT_NETPROFIT`；缺失或 ≤0 时回落重构净利润，并标注“含少数股东损益”。
- 分母 ≤0：输出“不适用（净利润≤0）”，不得用绝对值或剔除亏损年后继续算。
- 标签必须写“基期 FCF/同期归母净利润，窗口 YYYY–YYYY，FCF 已/未含研发调整”。
- 若保留“年度比值中位数”作为备选，必须写明“年度比值中位数，有效样本 N 年，亏损年剔除”，且不得与基期 FCF 口径混用。

## 6. 输出格式约束（洁净输出）

### 6.1 「估值参数」区应输出什么

只保留以下六块，按顺序、紧凑展示：

1. **模型**：模型名称（零增长/永续/两阶段/三阶段）+ 一句选择理由（不超过 40 字）。
2. **基期 FCF**：金额（亿元，2 位小数）+ 选取方式 + 窗口 + 是否含研发调整。
3. **折现率**：最终 r（1 位小数）+ 一行对账（Re、Rd 税后、E/V、D/V、取整/约束）。
4. **增长参数**：A（1 位小数）、g1、n1、g2/n2（如适用）、g∞；若保留构成表，必须含 `A_raw`、取整行、约束行、最终 A。
5. **关键校验**：Capex 覆盖率、FCF/净利润；仅在可用时显示，并带口径与窗口；不可用时显示“不适用 + 原因”。
6. **一句话结论**：AI 撰写的 2–3 句 `rationale`，只解释商业与行业原因，不重复推导、不出现与参数不一致的数字。

### 6.2 禁止输出什么

**禁止的功能与字段**

- 三档：`scenarios`、`scenario_*`、`conservative`、`base`、`optimistic`、逐档模型/逐档参数/逐档 FCF/逐档套用。
- 带宽与收窄：`band_growth`、`band_discount`、`band_terminal`、`scenario_band_source`、`scenario_band_raw`、`capped_by`。
- 放宽边界：锚上限 40、折现率下限 7、`RawA` 作为乐观基准。
- 推导表：WACC 七步、模型评分表、g1 四步、终值公式行、回归年限公式行、复合锚贡献表（若不可加总）。
- 内部变量名：`A_norm`、`锚数`、`Δ_cycle`、`Sg/Sst/Sroe`、`n_total`；若保留复合锚构成表，`A_raw` 只能作为“加权合计”的括号注记，不得出现在正文或结论话术中。

**禁止的话术**

以下仅为示例，不限于此；凡属于“工具说明、过程说明、规则元语言、自我指涉”的句子一律禁止：

- “不与基准档共用适中边界”
- “后端确定性计算”“只解释、不改数”“不得改写数字”“系统校验结果”
- “带宽来源……收窄到……”“区间 1.5–4.0pp”“上限 40%”“下限 7%”
- “锚数 3”“合计 A_raw……→ A”（构成表总计行除外，且须用中文标签）、“回退”“退化”“软上限”“包络”“离散度折减”
- “以上参数由 AI 生成/由系统锁定”“本卡片仅展示，不构成投资建议”（免责声明可放在页面统一位置，不放在参数区）

**禁止的展示方式**

- 同一数字用两种精度并让用户自行对账。
- 只给最终值、不给口径与年份。
- 把“约束后值”写成“计算值”（如把被 8% 下限截断的 r 写成 WACC=8.0%）。
- 把“不适用”显示为 0、`—` 或空白而不给原因。

### 6.3 允许的输出

- 最终参数值、口径公式（一行）、数据年份/窗口、材料性警告。
- “适中基准”标签，例如“估值参数（适中基准）”。
- 一句“参数依据”，例如“综合历史 7.0%、前瞻 15.0%、宏观 4.5%，按 0.45/0.45/0.10 加权，取整后 A=10.5%”；若这句话出现加总关系，必须与 A 闭合。
- 材料性警告，例如“基期 FCF 为负，DCF 不适用”“净资产为负，折现率按 Re 回落”“g1 受 SGR+2pp 约束”“终值受宏观锚 4.5% 约束”。

### 6.4 前端与 API 约束

- 前端删除三档表格、三档套用按钮、WACC 七步、模型评分表、g1 四步、终值/回归公式行、FCF 分档说明。
- 前端只保留一个“应用参数到估值表单”按钮；应用后模型、r、g1、n1、g2、n2、g∞、基期 FCF 与卡片一致。
- API 对外只保留最终参数与对账所需的最小构成字段；`scenario_*`、`band_*`、`score_*`、`growth_damping`、`growth_cap`、`growth_envelope` 等推导字段不再对外返回。
- 历史估值记录（R16）中若存有旧的三档字段，前端必须忽略而不是报错；新记录不再写入三档字段。
- 移动端：参数表按“参数/取值/口径”三列压缩或纵向堆叠，不出现横向滚动才能看全的对账表。

## 7. 非功能需求

- **确定性**：同一公司、同一报告期、同一行业分类，多次调用输出完全一致；不得有随机数、时间依赖（除“最新年报”选择外）。
- **可复算性**：每个展示数字必须能由“财报科目 + 公式 + 年份/窗口”复算；复算误差不超过展示精度。
- **性能**：参数推导（不含 AI 调用）单次 <100ms；不得因删除三档而引入额外远程请求。
- **兼容性**：旧历史记录可读；旧 API 字段删除后前端不得白屏；移动端 375px 宽度可读。
- **精度**：构成项比率 2 位小数，最终 r 1 位小数（0.5pp 网格）；pp 1 位小数；金额亿元 2 位小数；倍数 2 位小数；年数整数。
- **可审计性**：每个参数带“数据年份/窗口”和“口径”短句；警告可定位到具体科目或约束。
- **安全**：不新增外部数据源；AI 输出继续只取 `rationale` 与 `industry_type`，其余数值一律后端回填。

## 8. 边界与约束 / 非目标

**边界**

- 只重构“估值参数分析与设定”及其在 AI 分析卡片中的展示；DCF 公式、估值表单字段、历史记录存储机制不改。
- 数据源仍为东财财报 + 腾讯行情 + DeepSeek；不新增付费数据。
- 金融股（银行/保险/券商）标准 FCF 不适用，输出“不适用”，不做强行估值。
- 市值不可得时允许退回账面权益，但必须披露，且不得静默。
- 旧 R15/R18 文档与旧三档 API 字段全部废弃；不要求向后兼容旧字段的语义，只要求不崩溃。

**非目标**

- 不做相对估值（PE/PB/PS 可比公司）。
- 不做逐科目收入/利润预测，不做三张表建模。
- 不做行业 β 回归，不引入 Wind/同花顺等外部一致预期。
- 不做目标价、买卖评级、投资建议。
- 不保留“保守/乐观”作为隐藏开关或高级选项。
- 不要求 AI 解释每一个参数；AI 只写结论性 `rationale`。
- 不追求参数“精确到小数点后多位”；优先可解释、可复算、稳定。

## 10. 待确认问题

以下问题会显著影响口径或范围，需用户拍板。每项给出推荐默认值与理由。

- **Q1 WACC 的股权权重用市值还是账面权益？**
  - 影响：折现率水平、所有公司的估值结果。
  - 推荐：**优先总市值（腾讯行情 `MarketCap`），不可用时退回账面所有者权益并披露**。理由：WACC 的业界标准是市值权重；当前链路已能取到市值，只是没有传入。
- **Q2 公司特定风险溢价是否保留？如何定义？**
  - 影响：折现率高低、是否重复计算财务风险。
  - 推荐：**保留字段但默认 0；仅在逐项列示非财务风险（治理、诉讼、客户集中、流动性、会计质量）时加分，每项 0.5–1.0pp，合计 ≤3pp；禁止用杠杆/利息保障/债务占比**。理由：CAPM 允许公司特定溢价，但当前三项全是财务风险，已含在 WACC 中。
- **Q3 折现率是否保留 0.5pp 网格与 [8,15] 区间？**
  - 影响：低风险/高风险公司的 r 是否被强行抬高或压低。
  - 推荐：**保留 0.5pp 网格便于阅读；区间约束保留但必须显示“取整前 WACC / 取整后 r / 区间调整”三行**。若用户更看重不扭曲，可改为“仅警告、不截断”，推荐前者以延续项目习惯。
- **Q4 保全性资本支出用“D&A + 资产减值 + 信用减值 + 处置/报废损失”还是“仅 D&A”？**
  - 影响：FCF 水平、Capex 覆盖率分母、跨公司可比性。
  - 推荐：**FCF 与 Capex 覆盖率统一使用项目现有“保全性支出”广义口径（D&A + 资产减值 + 信用减值 + 处置/报废损失），全项目只保留这一套**。理由：同一张卡片上的 FCF 与覆盖率必须能互相复算；若改用“仅 D&A”，则 FCF、覆盖率分母、文案必须整体切换，不能两套并存。业界常见的 Capex/D&A 口径可作为后续可选展示，但本期不做第二套分母。
- **Q5 Capex 覆盖率的分子用总额还是净额？**
  - 影响：处置资产较多的公司覆盖率差异大。
  - 推荐：**净额（购建 − 处置收回）**。理由：净额才代表当年真正的资本净投入；总额会把“卖旧买新”算成扩张。
- **Q6 FCF/净利润用“同窗口同聚合方式”还是“同窗口合计 ÷ 同窗口合计”？**
  - 影响：波动大的公司比值差异明显；也影响能否用展示的基期 FCF 直接复算。
  - 推荐：**对归母净利润施加与基期 FCF 完全相同的窗口和聚合方式**（latest/latest、average/average、median/median、trim_mean/trim_mean、custom/最新年）。理由：这样分子就是卡片上展示的基期 FCF，用户可直接复算；若改用“合计 ÷ 合计”，median/trim_mean 模式下分子与展示的基期 FCF 不是同一个值，会再次出现“对不上”。
- **Q7 分母用归母净利润还是重构净利润？**
  - 影响：含少数股东权益的集团型公司比值。
  - 推荐：**优先 `PARENT_NETPROFIT`（归母）；缺失或 ≤0 时回落重构净利润并标注“含少数股东损益”**。理由：与项目 SGR 的既有处理一致。
- **Q8 周期位置修正 Δ_cycle 是否保留？**
  - 影响：周期股历史锚和 A 的取值。
  - 推荐：**保留，但只作用于历史锚，输出一句“周期位置修正 +X.Xpp，已含于历史锚”；不再单独成表**。理由：周期股用静态历史增速会系统性高估/低估，修正是有价值的；但当前展示过于复杂。
- **Q9 g1 是否删除离散度折减/软上限/包络？**
  - 影响：高波动公司的 g1、模型选择。
  - 推荐：**删除三重收口，改为 `g1 = clamp(A, g∞, min(30%, 前瞻或 SGR + 2pp))`**。理由：保留一个可解释上限即可；三重收口让用户无法复算，也是“增长参数对不上”的来源之一。
- **Q10 模型评分是否保留？**
  - 影响：模型选择（三阶段/两阶段/永续/零增长）。
  - 推荐：**评分仅内部使用，对外只输出最终模型 + 一句理由**；若用户希望进一步简化，可改为只用 A 与 gap 判定，删除评分。推荐先保留内部评分，避免模型选择行为大幅变化。
- **Q11 五种 FCF 选取方式是否全部保留？**
  - 影响：用户自定义能力、展示复杂度。
  - 推荐：**全部保留**（latest/average/median/trim_mean/custom）。这是 R12/R13 已交付的能力，删除会伤害现有用户；本次只统一口径。
- **Q12 研发扩张加回是否保留？**
  - 影响：成长型公司基期 FCF。
  - 推荐：**保留，但只在口径行注明“已加回研发扩张 X 亿元”**；默认关闭，由用户或规则触发。
- **Q13 旧 API 字段与历史记录如何处理？**
  - 影响：前端兼容、R16 历史记录。
  - 推荐：**对外删除三档字段；历史记录中的旧字段前端忽略、不迁移、不报错；新记录不写入**。理由：用户已明确“之前全部废弃”，无需为旧字段做语义兼容。
- **Q14 需求编号与旧文档处理是否按本文档执行？**
  - 影响：文档索引与后续技术设计引用。
  - 推荐：**新需求编号 R19；R15 需求文档/技术设计文档加“已废弃，见 R19”横幅；R18 已并入 R15，随 R15 一并废弃；不删除旧文件，保留历史可追溯**。理由：满足“推翻重做”又保留审计痕迹。
