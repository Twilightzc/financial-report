# R5 技术方案：AI 智能分析（大模型财务诊断）

> 对应《产品设计文档》第 9 节。复用 R3 六维指标计算结果，接入 DeepSeek 大模型，输出五维评分 / 结论 / 行业分析 / 业务板块分析 / 估值模型推荐。

### 9.1 总体思路

- 收到「一键分析」请求后，复用 `fetchAnalysisReports` 拉取三张全量报表 + 分红、`service.ComputeAnalysis` 计算六维指标，另拉取**主营构成**（`RPT_F10_FN_MAINOP`，`FetchSegmentIncome`，取最新年报产品明细的板块名与营收占比），再把指标 + 主营构成序列化喂给大模型。报表拉取走 client 层缓存（15 分钟 TTL），避免「分析→AI 分析」重复拉取 F10（冷启动 ~12s）。
- **系统提示词（skill）** = 仅静态框架（角色 / 任务 / 输出 JSON 结构 / 五维评分标准 / 估值模型推荐（只解释不改数，R7 起替换原「估值模型推荐规则」）/ 行业分析规则 / 业务板块分析规则），不随股票变化、利于复用。
- **用户消息** = 公司信息（名称 / 代码 / 总市值）+ 主营构成（板块名 + 营收占比）+ 年度头部 + 各维度指标，每行「指标名（单位；含义）：按年度顺序的数值」（金额换算亿/万，全 nil 指标跳过、nil 显示「—」）。含义与数值同处一行，避免「字典 + 数值」重复发送指标名。
- **业务板块分析**：`businesses` 字段（`[]AIBusiness`：name/stage/contribution/prospect/risk），贡献占比据主营构成实际数值给出——同时看**营收占比、利润占比、毛利率**（`SegmentIncome` 含 RevenueRatio/ProfitRatio/GrossMargin），不只营收占比、不凭空编造。
- **大模型客户端**：OpenAI 兼容 Chat Completions，仅用标准库 `net/http`（无新增依赖），`response_format=json_object`、`temperature=0`（降低多次分析之间的参数波动）、`reasoning_effort`（前端「分析模式」随请求传入，`low` 简洁 / `medium` 标准 / `high` 详细，缺省 `low`；模型不支持时忽略该字段）、`max_tokens=8192`（给推理+回答留足空间，避免内容为空；过低会耗尽额度导致 `content` 为空）、180s 超时；解析响应 `usage` 回填 token 用量。
- **结论详略随模式变化**：`BuildAIPrompt` 按 `reasoning` 注入结论长度要求（简洁约 100 字 / 标准约 200 字 / 详细约 300 字），让不同模式在速度与详细度上真实可感（推理强度本身仅作辅助）。
- **估值推荐**：~~增长率从指标数据推导并结合行业前景/竞争格局微调~~ —— R7 起改为**后端确定性推导**（纯函数 `RecommendValuation`，见第 11 节），大模型不再产出任何数值，只写 `rationale`；本节的「估值模型推荐规则」提示词段落由第 11.7 节替换。
- 解析返回 JSON 为 `AIAnalysisResult`，做**容错解析**（浮点评分四舍五入、维度名模糊匹配到规范名并重排）后返回前端。

### 9.2 数据模型（internal/model/ai.go 新增）

```go
type AIScore struct {
    Dimension string // 盈利能力 / 偿债能力 / 现金获取能力 / 经营效率 / 成长能力
    Score     int    // 0-100
    Comment   string
}
type AIIndustry struct { Name, Prospect, Competition, Application string }
type AIValuationParam struct { Key, Label string; Value float64 } // Key 与 /valuation 参数对齐
type AIValuation struct {
    Model, ModelName string
    DiscountRate     float64
    Params           []AIValuationParam // g / g1 / n1 / g2 / n2 / g3
    Rationale        string
}
type TokenUsage struct {
    PromptTokens, CompletionTokens, TotalTokens int
}
type AIAnalysisResult struct {
    Scores     []AIScore
    Conclusion string
    Industry   AIIndustry
    Valuation  AIValuation
    Usage      *TokenUsage // 服务端回填的大模型 token 用量
}
```

### 9.3 client 层（internal/client/deepseek.go 新增）

`NewDeepSeek(apiKey, baseURL, model)` → `Chat(system, user string) (string, model.TokenUsage, error)`：

- `POST {baseURL}/chat/completions`，`Authorization: Bearer <apikey>`；baseURL 缺省 `https://api.deepseek.com/v1`，model 缺省 `deepseek-v4-pro`。
- 请求体含 `model` / `messages`（system + user）/ `response_format:{type:json_object}` / `temperature=0` / `reasoning_effort` / `max_tokens=8192`（见 9.1）。
- 解析响应 `usage`（prompt/completion/total tokens）返回给上层；`content` 为空但 `reasoning_content` 非空时给出「只返回推理未返回结果」的明确错误。
- **容错与重试**：限流(429)/5xx/网关返回 HTML（非 JSON）等临时失败自动重试 5 次（指数退避 2s/4s/8s/16s）；200 但 body 不以 `{` 开头即判为非 JSON 并给出清晰错误（凌霄泵业/奕瑞科技曾因此报 `Unexpected token '<'`，即 DeepSeek 网关/限流返回了 HTML）。非 200 或返回体含 `error` 时返回截断后的错误信息；`choices[0].message.content` 为空时返回明确错误。

**报表缓存（internal/client/eastmoney.go）**：`fetchFinancialSorted` 按 `reportName|code|pageSize|sortColumn` 做内存缓存（`reportCacheTTL=15min`，`sync.Mutex` 保护），命中时跳过 F10 请求。财报按季度更新，15 分钟缓存安全。响应 body 以 `<` 开头（HTML/网关页）时返回清晰错误而非裸 JSON 解析报错。

### 9.4 service 层（internal/service/ai.go 新增）

- `BuildAIPrompt(a FinancialAnalysis, q Quote, reasoning string, segments []SegmentIncome, rec ValuationRecommendation) (system, user string)`：system = 静态 `aiSystemFramework`；user = `buildUserMessage`（公司信息 + 主营构成 + 年度头部 + 指标数值与含义 + **确定性估值参数**）。`rec` 与 `reasoning` 是 R7 新增入参，见第 11.7 节。
- `serializeIndicators`：遍历 `done` 维度，按「维度 · 小节」分组，每指标一行 `名称（单位；含义）：按年度顺序的数值`（`formatSeriesCompact`，不重复年度标签）；全 nil 指标跳过。
- `formatAmount`：金额换算亿/万（|v| ≥ 1e8 → 亿，≥ 1e4 → 万），`%`/`倍` 保留两位小数。
- `ParseAIResult(raw) (AIAnalysisResult, error)`：去 markdown 代码块包裹 → `json.Unmarshal`（score 用 `json.Number` 容忍 88 / 88.0 / 88.5，四舍五入为 int）→ `normalizeDimension` 把维度名模糊匹配到规范名并按 `aiScoreDimensions` 顺序重排 → 校验 5 项齐全、分数 0-100。R7 起**不再**做估值参数量化（`normalizeValuation` 删除），估值字段由 `ApplyValuationRecommendation` 整体覆盖。
- 五维评分顺序固定于 `aiScoreDimensions`，前后端一致；解析失败时错误信息附带原始返回片段便于排查。

### 9.5 API 设计

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/stock/:code/ai-analysis?startYear=2021&endYear=2024` | 一键 AI 分析 |

参数：`startYear` / `endYear`（缺省最近 5 年）；`reasoning`（推理强度 `low`/`medium`/`high`，缺省 `low`，前端「分析模式」下拉选择）。apikey / model / base_url **不随请求传入**，取程序启动参数 `-apikey` / `-model` / `-baseurl`（见下），apikey 未配置时回落环境变量 `DEEPSEEK_API_KEY`（model / base_url 同理回落 `DEEPSEEK_MODEL` / `DEEPSEEK_BASE_URL`，缺省 `deepseek-v4-pro` + `https://api.deepseek.com/v1`）。

handler `GetAIAnalysis`：校验 code → 取启动参数（回落环境变量）→ `FetchQuote` + `fetchAnalysisReports`（复用，`cfPageSize`/`bsPageSize` 提升为包级常量）→ `ComputeAnalysis` → `RecommendValuation`（R7 新增，确定性估值参数）→ `BuildAIPrompt` → `NewDeepSeek().Chat` → `ParseAIResult` → `ApplyValuationRecommendation`（R7 新增，覆盖大模型估值字段）→ 返回 `{code, data, message}`。R7 起响应 `data.valuation` 新增只读字段 `base_growth` / `base_growth_note` / `volatile` / `warning`（见第 11.8 节）。

程序启动参数（`cmd/server/main.go`）：

| 参数 | 缺省 | 说明 |
| --- | --- | --- |
| `-apikey` | 空 | DeepSeek API Key；空则回落 `DEEPSEEK_API_KEY`，仍为空时 AI 接口返回提示 |
| `-model` | `deepseek-v4-pro` | DeepSeek 模型名 |
| `-baseurl` | `https://api.deepseek.com/v1` | OpenAI 兼容接口地址 |

### 9.6 前端设计（internal/web/app.js）

- 新增「AI 智能分析」卡片：「一键分析」按钮（apikey 由服务端启动参数提供，前端无输入框）+「分析模式」下拉（简洁/标准/详细）；**仅在点击时触发**（不随 `doSearch`）。
- `fetchAIAnalysis`：GET 请求（可选 `startYear`/`endYear` + `reasoning` 复用）；成功置 `aiResult` 后 `nextTick` → `renderRadar`。
- **结果缓存**：前端 `aiCache`（`Map`，key = `code|startYear|endYear|reasoning`），命中直接复用 `aiResult`、不再调用大模型消耗 token；切换股票时 `doSearch` 清空 `aiResult` 并丢弃在途旧结果（`reqCode` 校验）。
- `renderRadar`：ECharts `radar`，5 个 `indicator`（max=100），series 取五维评分。
- 结果区：雷达图 + 五维 `el-progress`（`scoreColor` 按分数档配色：≥90 红 / ≥75 橙 / ≥60 琥珀 / 其余绿，红=强）+ 结论 + 行业 + 业务板块 + 估值推荐（R7 起追加展示基准增速 X%、口径说明与套用提示，见第 11.9 节）+ 底部小字 token 用量（`aiResult.usage.total_tokens` 等）。
  - ⚠️ **已被 R9 覆盖（第 13 节）**：R9 起 `scoreColor` 四档**反转为绿=强**（≥90 绿 `#149a5e` / ≥75 黄绿 `#6aa84f` / ≥60 琥珀 `#d9a240` / <60 红 `#d64040`），与全站「绿=向好/健康」语义统一；雷达图配色同步改绿系。档位边界与 `el-progress` 行为不变。详见 13.9。
- `applyAIValuation`：把推荐的 `model` / `discount_rate` / `params` 套用到 R4 估值表单（g/g1/n1/g2/n2/g3）并触发 `fetchValuation`。字段名不变，R7 无需改动该函数。
