# R9 技术方案：指标趋势信号灯与全页颜色语义重构

> 对应需求文档 `docs/R9-指标趋势信号灯与颜色语义重构/需求文档.md`（FR-1~FR-15、AC-1~AC-23、附录 A 方向映射表 122 指标）。本轮把需求从「加一个信号灯」升级为「趋势信号灯 + 整页颜色语义重构」：以**绿=向好/健康、红=走弱/坏**作为全页统一语义色，剔除「红涨绿跌」在非行情、非原始科目场景的误用，同时**保留**红涨绿跌在行情/数值口径场景的惯例。
>
> 配色相关的既有章节被本节**覆盖**：§7.8（六维同比色）、§9.6（AI 进度条 `scoreColor`）、§10.3（趋势图柱色）、§12.9（雷达图配色）。这些章节的功能口径（布局、折行、字号、尺寸、双轴设计）不变，仅颜色取值以本节为准。
>
> **决策更新 2（2026-09，用户预览实现后二次调整）**：① **三态圆点全部渲染**——绿 `--good` / 红 `--bad` / **灰 `--neutral-bar`**（`#998c8c`），**取代**原「中性不渲染圆点」约定，灰点覆盖「方向 neutral / 趋势平稳未超 5% / 数据不足 / 维度非 done」四类，hover 给温和文案；② **tooltip 措辞按 `|R|` 幅度分级**（新增 FR-16）：`|R| < 20%`（常量 `MILD_CHANGE_THRESHOLD`）用「略有改善 / 略有走弱」，`≥ 20%` 才用「向好 / 走弱」；末词按**向好/走弱极性**取，数值动向由「升至/降至」表达（Q10.1）。
>
> 两条调整**只改展示与措辞**：FR-1 方向属性、FR-2 趋势判定（`trendThreshold = 0.05` + ε 守卫）、FR-3 判定矩阵、附录 A 方向映射表**全部不变**，六维同比色也不做深浅分层（Q10.3）。为支撑措辞分级，后端**新增只读字段 `trend_rate`（R，百分比口径）**，前后端改动清单见 **§13.13**（变更索引），本条以下各小节已按决策更新 2 就地改写。
>
> **决策更新 3（2026-09，用户再次调整）**：六维分析表的**同比颜色改回与三大报表一致的「红涨绿跌」**（正增长=红字、负增长=绿字），废弃方向感知函数 `yoyClassDir`、复用 `yoyClass`。用户澄清「增长百分比颜色区分数值正负，信号灯颜色表征整体状态，二者不是同一件事」。据此：**方向映射表只驱动信号灯与 tooltip 措辞，不再参与同比着色**；`direction` 字段仍保留（信号灯 tooltip 需要）。受影响处：§13.8 模板（六维同比改用 `yoyClass`）、§13.9（删 `yoyClassDir`）、§13.10（删 `.analysis-table .yoy.good/.bad`）。

### 13.2 总体架构与数据流

新增能力拆成「**后端单一真值 + 前端纯展示**」两层，方向映射与信号判定**只存在于后端**（FR-14：不得只存在于前端）：

```
后端（internal/service，纯函数、无 IO）
  ComputeAnalysis(balance, cashflow, income, dividends, startYear, endYear)
    ├─ 六大维度构造（现状不变，指标 Values 与年份升序对齐）
    └─ applyTrendSignals(&analysis)                        ★R9 新增（回填 pass）
         ├─ it.Direction  = IndicatorDirection(it.Key)     ← indicatorDirections 映射表（67 条 + 缺省 neutral）
         ├─ t, rate, ok   = trendOf(it.Values)             ← ★决策更新 2：单次算出趋势 + R（FR-2）
         ├─ it.TrendSignal = signalOf(t, it.Direction)     ← 仅 dim.Status=="done"（FR-3 矩阵）
         └─ it.TrendRate   = rate × 100（ok 时；否则 nil）  ← ★决策更新 2：R 外传（百分比口径）
  → model.FinancialAnalysis（JSON 新增 direction / trend_signal / trend_rate）

前端（internal/web/app.js，纯展示）
  analysis.dimensions[*].sections[*].indicators[*]
    ├─ 圆点：:class="trendDotClass(it)"      → .trend-dot.improving / .worsening / .neutral（三态全渲染，无 v-if）
    ├─ tooltip：trendTip(it, years, s.title, dim.status)
    │     绿/红 → 「近 N 年…由 s1 升至/降至 sm（R%），{方向短语}{略有改善|略有走弱|向好|走弱}」← |R| 与 20% 分级
    │     灰   → 四类温和文案（方向 neutral / 趋势平稳 / 数据不足 / 维度非 done）
    ├─ 六维同比：yoyClassDir(values, i, it.direction) → .good / .bad（中性/上年≤0 → 无色）
    ├─ 趋势图：barColorOf(it.trend_signal, v) → 向好绿 / 走弱红 / 中性灰 / 负值恒红
    ├─ 雷达图：PALETTE.good 绿色系
    └─ AI 进度条：scoreColor 四档反转（绿→红）
  三大报表：yoyClass(values, i) → .up / .down（红涨绿跌，**原样保留**）
```

为什么把方向映射与信号判定放后端：需求 FR-14 明确要求「单一数据源、不得只存在于前端」；放后端后 ① 映射与信号可被 Go 单测覆盖（AC-14）；② 前端只需渲染，无需维护第二份判断逻辑；③ 未来的 AI 分析、导出等消费者可直接复用（本轮不喂给 AI，见 13.12 #10）。

### 13.3 数据模型（`internal/model/analysis.go`）

在 `AnalysisIndicator` 末尾追加两个字段（**不改动**其余字段与顺序）：

```go
type AnalysisIndicator struct {
	Key            string     `json:"key"`
	Name           string     `json:"name"`
	Values         []*float64 `json:"values"`
	Unit           string     `json:"unit"`
	Kind           string     `json:"kind,omitempty"`
	Interpretation string     `json:"interpretation,omitempty"`
	Note           string     `json:"note,omitempty"`

	// R9 新增：趋势信号灯（见 13.5/13.6）
	// Direction 不设 omitempty：AC-1 要求「每个指标都带方向属性」，缺字段会让「neutral」与「旧响应」不可区分。
	Direction   string `json:"direction"`                // higher_better / lower_better / neutral
	TrendSignal string `json:"trend_signal,omitempty"`   // improving / worsening；无色（平稳/无信号/中性/维度非 done）时省略

	// ★决策更新 2 新增：首末相对变化率 R（FR-2 同一口径、同一次计算），**百分比口径 0–100**
	//（如 11.5 表示 +11.5%，与 model 内其余 unit=="%" 的字段同为 0–100，见 analysis.go 的 ratioPct ×100）。
	// R 不可计算（趋势 = trendNone）时为 nil；**必须是指针**：R=0（首末持平）是合法值，须输出 0，
	// 否则前端无法区分「持平」与「数据不足」。前端只把它用于措辞分级与文案，不参与信号判定（FR-16）。
	TrendRate *float64 `json:"trend_rate,omitempty"`
}
```

字段口径：

| 字段 | 取值 | 输出策略 | 说明 |
| --- | --- | --- | --- |
| `direction` | `higher_better` / `lower_better` / `neutral` | **始终输出** | 只由 `key` 决定，**与年份范围无关**（FR-1 口径提示）；未在映射表中的 key → `neutral`（FR-1 兜底） |
| `trend_signal` | `improving` / `worsening` / 省略 | 省略 = 无色（前端渲染**灰点**） | 只由「方向 × 所选范围内趋势」决定（FR-3）；`neutral` 方向恒省略（FR-3 表）。**不新增 `neutral` 枚举值**——灰点由前端按「非 improving 且非 worsening」推导，保持 JSON 契约向后兼容 |
| `trend_rate` | `R × 100`（如 `11.5` / `-23.5` / `0`）/ 省略 | 省略 = R 不可计算 | **不变式：`trend_rate` 非 nil ⟺ 趋势 ≠ `trendNone`**（即「R 可计算」）。故**方向 neutral 但 R 可算的指标也要输出** `trend_rate`——FR-5 的两条灰点文案（「该指标无明确好坏方向」「变化不大，趋势平稳」）都要显示 R。决策更新 2 的措辞分级**只读该字段**，不在前端重算 R（避免第二份口径） |

- `trend_signal` 用 `omitempty` 而非「始终输出空串」：与 R8 的 `adjust_rd` 不同，**这里不存在「0 值 vs 缺字段」的歧义** —— 前端判据是「真值 / 直接比较 `'improving'`/`'worsening'`」，`""` 与缺失行为完全一致；省略可让 55 个中性指标（占 45%）的响应更小。`direction` 则相反（有 `neutral` 这个**有意义**的第三态，且是 AC-1 的验收对象），故不加 `omitempty`（沿用 §12.3 的 R8 教训）。
- **`trend_rate` 必须保持 `*float64` 指针类型**（决策更新 2）：指针 + `omitempty` 的语义是「仅 nil 时省略」，非 nil 的 `0.0` **会**被输出为 `0`，这正是「首末持平（R=0）≠ 数据不足（nil）」的判据所在。⚠️ 若有人把它「简化」成值类型 `float64` + `omitempty`，R=0 的指标会被静默省略、前端误判为「数据不足」——故 13.11 增加了一条 JSON 序列化断言（`"trend_rate":0` 必须出现）作为护栏。
- 枚举用英文小写+下划线，与项目既有枚举风格一致（`kind` 的 `sub`/`subtotal`/`net`、`status` 的 `done`/`pending`/`no_data`）。

### 13.4 数据源与字段映射

**无新增数据拉取、无新增字段映射。** 趋势/方向完全由 `ComputeAnalysis` 产出的既有 `AnalysisIndicator.Values`（`[]*float64`，与 `FinancialAnalysis.Years` 升序对齐，元素为 `nil` 表示无数据/无法计算）推导；`applyTrendSignals` 不接触 `model.ReportRow`，也不改变任何既有指标口径。

已核实的既有保证（设计依赖、实现时不得破坏）：

| 依赖 | 位置 | 说明 |
| --- | --- | --- |
| `Values` 与 `Years` 等长、升序对齐 | `internal/service/analysis.go:1745` `yearValues`、`:1565` `absValues`、`:1804` `derivedValues`、`:1574` `ratioOf`、`:1813` `ratioValues` | 全部 `make([]*float64, len(years))` 后按下标写入，故趋势计算可**直接按切片顺序**取首末非空值，无需年份参与 |
| `nil` 表示无数据/无意义 | 同上 + `indN`/`nilNote`（`analysis.go:1849`/`:1850`） | 与 FR-2「剔除 `null` 后取有效序列」一一对应 |
| 年份范围已按 `startYear`/`endYear` 截断 | `analysis.go:105` `years := yearRange(cfYears, startYear, endYear)` | 信号天然作用于「所选年份范围」（FR-2 触发条件），**无需改 handler** |
| 维度状态 | `analysis.go:109`/`:171`/`:237` 等 | `pending`/`no_data` 维度 `Sections` 为空或整维度无指标 → FR-12① 天然满足，回填时再显式跳过非 `done` |

### 13.6 趋势判定与信号计算（FR-2 / FR-3）

同一文件内新增（纯函数、无 IO）：

```go
// trendThreshold 趋势显著性相对阈值（FR-2，可配置常量）：|R| < 5% 视为平稳。
const trendThreshold = 0.05

// residualEpsilon 端点「残差零」绝对阈值（已落地，实测得出）：|v| < ε 视为浮点残差而非真实取值。
// 免费接口下「应为 0」的科目会留下残差（实测 2.09e-07 / 7.86e-15），两个残差端点比大小会得到 R≈−100% 的误导信号。
const residualEpsilon = 1e-6

type trend int

const (
	trendNone trend = iota // 无信号（有效数据 < 2 点 / 首值为 0 / 全为空）
	trendFlat              // 平稳（|R| < 阈值）
	trendRising            // 上升（R ≥ 阈值）
	trendFalling           // 下降（R ≤ −阈值）
)

// trendOf 按「首个非空值 vs 末个非空值 + 相对变化率」判断趋势（FR-2），并一并返回相对变化率 R。
// 序列含 null 空洞时只取首末非空值，中间空洞不参与。
// ★决策更新 2：趋势与 R 由**同一次**计算产出（单一真值），避免前端重算或双份口径。
// ok=false 表示 R 不可计算（趋势 = trendNone，此时 rate 无意义、返回 0）。
func trendOf(values []*float64) (t trend, rate float64, ok bool) {
	first, last, n := firstAndLast(values)
	// 无信号：有效点不足 / 首值残差零（含精确 0，分母无意义）。
	if n < 2 || math.Abs(first) < residualEpsilon {
		return trendNone, 0, false
	}
	// 无信号：末值残差零；但精确 0 是合法末值（如「营业外支出降到 0」是真实向好信号，R=−100%），故显式排除。
	if last != 0 && math.Abs(last) < residualEpsilon {
		return trendNone, 0, false
	}
	r := (last - first) / math.Abs(first) // 分母取绝对值，使负值区间/跨零点也有正确符号
	switch {
	case r >= trendThreshold:
		return trendRising, r, true
	case r <= -trendThreshold:
		return trendFalling, r, true
	default:
		return trendFlat, r, true
	}
}

// trendDirection 保持原签名（既有 8 个单测直接调用），改为 trendOf 的薄封装（决策更新 2）。
func trendDirection(values []*float64) trend {
	t, _, _ := trendOf(values)
	return t
}

// firstAndLast 返回首个/末个非空值及其有效数据点个数；全为空时 n==0（first/last 为 0 值，调用方先判 n）。
func firstAndLast(values []*float64) (first, last float64, n int) {
	for _, v := range values {
		if v == nil {
			continue
		}
		if n == 0 {
			first = *v
		}
		last = *v
		n++
	}
	return
}

// signalOf 方向 × 趋势 → 信号（FR-3 矩阵）的纯函数核（决策更新 2 抽出，供回填与单测共用）：
// higher_better 上升 / lower_better 下降 → improving；反向 → worsening；中性、平稳、无信号 → 无色。
func signalOf(t trend, direction string) string {
	switch direction {
	case dirHigherBetter:
		return signalByTrend(t, true)
	case dirLowerBetter:
		return signalByTrend(t, false)
	default:
		return signalNone
	}
}

// trendSignal 保持原签名（TestTrendSignalMatrix 直接调用），改为 trendOf+signalOf 的组合（决策更新 2）。
func trendSignal(values []*float64, direction string) string {
	t, _, _ := trendOf(values)
	return signalOf(t, direction)
}

func signalByTrend(t trend, higherBetter bool) string {
	switch t {
	case trendRising:
		if higherBetter {
			return signalImproving
		}
		return signalWorsening
	case trendFalling:
		if higherBetter {
			return signalWorsening
		}
		return signalImproving
	default:
		return signalNone
	}
}

// applyTrendSignals 回填全部指标的 direction / trend_signal / trend_rate（FR-1/FR-3，决策更新 2 加 trend_rate）。
// 方向属性与维度状态无关（对每个指标都回填）；趋势、信号与 R 仅对已实现（done）维度计算（FR-12①）。
func applyTrendSignals(a *model.FinancialAnalysis) {
	for di := range a.Dimensions {
		dim := &a.Dimensions[di]
		for si := range dim.Sections {
			items := dim.Sections[si].Indicators
			for ii := range items {
				it := &items[ii]
				it.Direction = IndicatorDirection(it.Key)
				if dim.Status != "done" {
					continue
				}
				t, rate, ok := trendOf(it.Values) // 趋势与 R 同一次算出（单一真值）
				it.TrendSignal = signalOf(t, it.Direction)
				if ok {
					pct := rate * 100 // API 百分比口径（0–100），与 model 内其余 % 字段一致
					it.TrendRate = &pct // pct 为循环体内新声明的变量，取址安全（每轮一块新内存）
				}
			}
		}
	}
}
```

`internal/service/analysis.go` 的 `ComputeAnalysis`（`:100`）末尾改为：

**② 四个新增纯函数**（`yoyClassDir` / `trendDotClass` / `trendTip` / `barColorOf`）：

```js
// FR-7：方向感知同比色（六维分析表专用）。返回 'good' / 'bad' / ''（无色）。
// 与 yoyText 的显示规则一致：首年、任一年缺失、上年为 0 或负 → 无色；
// 与信号灯不同，此处比较相邻两年（逐年信息），且仅看符号（持平即无色），不套用 5% 阈值。
function yoyClassDir(values, i, direction) {
  if (i === 0) return '';
  const prev = values[i - 1], cur = values[i];
  if (cur == null || prev == null || prev === 0 || prev < 0) return '';
  if (direction !== 'higher_better' && direction !== 'lower_better') return ''; // 中性方向一律不着色
  if (cur === prev) return '';                                                  // 持平 → 无色
  const up = cur > prev;
  return (direction === 'higher_better') === up ? 'good' : 'bad';
}

// ★决策更新 2（FR-4）：信号灯圆点类名——向好 improving / 走弱 worsening / 其余一律 neutral（灰）。
// 三态全覆盖：任何指标都必须落到这三个类之一，故**不存在空类**（AC-24 每行恰一个圆点）。
// trend_rate 守卫：后端不变式为「有信号 ⟺ trend_rate 非 nil」，故该守卫只对**旧响应/脏数据**生效，
// 此时保守降级为灰，保证「圆点颜色」与「tooltip 文案（数据不足）」不会自相矛盾。
function trendDotClass(it) {
  if (typeof it.trend_rate !== 'number') return 'neutral';
  return (it.trend_signal === 'improving' || it.trend_signal === 'worsening') ? it.trend_signal : 'neutral';
}

// FR-5 / FR-16：信号说明文案。phrase = 该指标所属小节标题（方向解读短语，可为空）；
// dimStatus = 所属维度状态（决策更新 2 新增，非 'done' 时给维度级灰点文案）。
// **三态都必须返回非空文案**（FR-5 / AC-10）：绿/红 → 幅度分级措辞；灰 → 四类温和文案。
// 措辞分级只读后端 trend_rate（单一真值，不在前端重算 R）：|R| < MILD_CHANGE_THRESHOLD 用温和词。
function trendTip(it, years, phrase, dimStatus) {
  const name = it.name || '该指标';
  // ① 维度非 'done'（FR-12①）：整维度不参与趋势判定。当前模板不渲染非 done 维度的指标行，属防御分支。
  if (dimStatus && dimStatus !== 'done') return `${name}：该维度暂无数据，暂无法判断趋势`;
  const vs = it.values || [];
  let i1 = -1, im = -1;
  for (let i = 0; i < vs.length; i++) {
    if (vs[i] != null) { if (i1 < 0) i1 = i; im = i; }
  }
  // ② 数据不足（FR-12②③⑥⑦）：R 不可计算（缺字段/非数字）或有效点 < 2。
  //    注意用 typeof 判缺失而非真值判断——trend_rate === 0（首末持平）是合法值。
  const rate = it.trend_rate;
  if (typeof rate !== 'number' || !isFinite(rate) || i1 < 0 || i1 === im) {
    return `${name}在所选范围内数据不足，暂无法判断趋势`;
  }
  const s1 = vs[i1], sm = vs[im];
  const ys = years || [];
  const span = (ys[im] != null && ys[i1] != null) ? (ys[im] - ys[i1] + 1) : (im - i1 + 1);
  const pct = `${rate >= 0 ? '+' : ''}${rate.toFixed(1)}%`;
  const vals = (sm === s1)
    ? `保持在 ${fmtAnalysisVal(s1, it.unit)}`                                          // R=0：避免「由 X 降至 X」
    : `由 ${fmtAnalysisVal(s1, it.unit)} ${sm > s1 ? '升至' : '降至'} ${fmtAnalysisVal(sm, it.unit)}`;
  const s = it.trend_signal;
  // ③ 灰点（无信号）：温和陈述，禁用「向好/走弱/改善」评价词（FR-5）。
  if (s !== 'improving' && s !== 'worsening') {
    // 方向 neutral（可算出 R）→ 用「无明确好坏方向」；方向有向且无信号 → 必为趋势平稳（|R| < 5%）。
    if (it.direction === 'neutral') return `近 ${span} 年${name}${vals}（${pct}），该指标无明确好坏方向`;
    return `近 ${span} 年${name}变化不大（${pct}），趋势平稳`;
  }
  // ④ 绿点/红点：末词按**向好/走弱极性**取（FR-16 Q10.1），数值动向已由「升至/降至」表达。
  const lead = (phrase && phrase !== it.name) ? phrase : ''; // 与指标名重复时省略短语
  const mild = Math.abs(rate) < MILD_CHANGE_THRESHOLD;
  const concl = (s === 'improving') ? (mild ? '略有改善' : '向好') : (mild ? '略有走弱' : '走弱');
  return `近 ${span} 年${name}${vals}（${pct}），${lead}${concl}`;
}

// FR-10：指标趋势图柱色 —— 向好绿 / 走弱红 / 无信号或中性灰；负值无论信号一律红。
function barColorOf(signal, value) {
  if (value != null && value < 0) return PALETTE.bad;
  if (signal === 'improving') return PALETTE.good;
  if (signal === 'worsening') return PALETTE.bad;
  return PALETTE.neutral;
}
```

**灰点四类原因与判据（FR-5 / FR-12，决策更新 2 新增）**——四个分支互斥且穷尽，**优先级自上而下**：

| 序 | 原因 | 前端判据（`trendTip`） | 文案模板 | 对应 FR/AC |
| --- | --- | --- | --- | --- |
| ① | 维度非 `done`（`pending`/`no_data`） | `dimStatus && dimStatus !== 'done'` | `{指标名}：该维度暂无数据，暂无法判断趋势` | FR-12① / AC-8 |
| ② | 数据不足（有效点 < 2 / 全为空 / 首值为 0 / 端点残差零 / 恒为空指标） | `typeof trend_rate !== 'number' \|\| !isFinite \|\| i1 < 0 \|\| i1 === im` | `{指标名}在所选范围内数据不足，暂无法判断趋势` | FR-12②③⑥⑦ / AC-7、AC-9 |
| ③ | 方向 `neutral`（R 可算） | `direction === 'neutral'` | `近 {N} 年{指标名}由 {s1}{unit} 升至/降至 {sm}{unit}（{R}%），该指标无明确好坏方向` | FR-12④ / AC-6 |
| ④ | 方向有向但趋势平稳（`\|R\| < 5%`） | 其余（有 R、非 neutral、无信号 ⟹ 必为 `trendFlat`，由 FR-3 矩阵的逆否保证） | `近 {N} 年{指标名}变化不大（{R}%），趋势平稳` | FR-12⑤ / AC-5 |

> 优先级说明：① 最先（整维度不参与）；② 先于 ③④（R 不可算时谈方向/平稳无意义）。③ 与 ④ 的先后按 FR-5 的字面口径——「方向 neutral（可算出 R）」与「**方向有向**但趋势平稳」是两类，故判据看 `direction` 而非 `|R|`：`neutral` 方向即使首末持平也走 ③（保留首末数值信息），有向指标才走 ④。
>
> `{R}` 一律取后端 `trend_rate`（百分比口径，`toFixed(1)` 带符号），不再 `((sm−s1)/|s1|)×100` 重算；`{N}` 仍取 `ym − y1 + 1`（`years` 缺失时退化为下标差）。

**绿/红点措辞矩阵（FR-16 极性 × 幅度，8 组合，决策更新 2 新增）**——`{结论词}` 只由**向好/走弱极性**决定，数值动向由 `升至/降至` 决定，二者独立：

| 方向 | 数值动向 | `trend_signal` | `\|R\|` | 圆点 | 句式（`…` 为共用部分） | tooltip 尾部 |
| --- | --- | --- | --- | --- | --- | --- |
| `higher_better` | 上升 | `improving` | < 20% | 绿 | `近 {N} 年{指标名}由 {s1} 升至 {sm}（{R}%）` | `{方向短语}略有改善` |
| `higher_better` | 上升 | `improving` | ≥ 20% | 绿 | 同上 | `{方向短语}向好` |
| `higher_better` | 下降 | `worsening` | < 20% | 红 | `…降至…` | `{方向短语}略有走弱` |
| `higher_better` | 下降 | `worsening` | ≥ 20% | 红 | 同上 | `{方向短语}走弱` |
| `lower_better` | 上升 | `worsening` | < 20% | 红 | `…升至…` | `{方向短语}略有走弱`（**不得**出现「略有改善」） |
| `lower_better` | 上升 | `worsening` | ≥ 20% | 红 | 同上 | `{方向短语}走弱` |
| `lower_better` | 下降 | `improving` | < 20% | 绿 | `…降至…` | `{方向短语}略有改善` |
| `lower_better` | 下降 | `improving` | ≥ 20% | 绿 | 同上 | `{方向短语}向好` |

- **阈值边界**：`|R|` 恰好 `20.0` → 按 `≥ 20%` 用评价词（与 FR-16 口径一致）；`19.9` → 温和词。常量改动**只影响本表末列**，不影响圆点颜色（AC-27）。

22. **灰点两类的优先级按 `direction` 判定，而非按 `|R|`**：`trend_rate == null` → 「数据不足」；否则 `direction === 'neutral'` → 「该指标无明确好坏方向」（**即使首末持平**）；否则 → 「变化不大…趋势平稳」【推荐】：按 FR-5 的字面口径，「方向 neutral（可算出 R）」与「**方向有向**但趋势平稳」是互斥两类；`direction` 优先还能保留中性指标的「首末数值 + 变化率」信息（AC-6 明确要求灰点 tooltip 含首末数值与变化率）。有向指标落到 ④ 分支时必为 `trendFlat`（由 FR-3 矩阵逆否保证），故第三分支**不可能**漏掉「有向 + `|R| ≥ 5%` + 无信号」的情况。
23. **`sm === s1`（R=0）时的措辞用「保持在 X（+0.0%）」**，不用「由 X 降至 X」【推荐】：中性方向指标的 R 恰好为 0 是合法（且会被 `trend_rate` 正常输出）的，`sm > s1 ? 升至 : 降至` 的裸三元会在此时错写「降至」。有向指标不可能命中（有信号要求 `|R| ≥ 5%`，此时 `sm ≠ s1`）。
24. **圆点的键盘聚焦环显式声明为「各自语义色」（灰= `--neutral-bar`、绿= `--good`、红= `--bad`），不动全局 `:focus-visible`** 【推荐，附带发现】：实现时发现既有 `.analysis-table .trend-dot { outline: none }` 的特异性 (0,2,0) **高于**全局 `:focus-visible` (0,1,0)，会把它整个吃掉——即**现状下圆点聚焦时没有任何可见焦点提示**（原 13.10② 的注释「配合全局 `:focus-visible` 显示品牌色外框」与实际不符，属既有缺口）。本次要满足 FR-4「灰点不得用品牌红/语义红」，需写特异性更高的规则；既然要写，就三态各写一条（灰/绿/红各自语义色），顺带把「聚焦无提示」的 a11y 缺口一起修掉（也符合 FR-15「颜色不得是唯一信息载体、键盘可聚焦」）。**备选 A**：只写 `.neutral:focus-visible`（最小改动，但绿/红点聚焦仍无任何提示，三态不一致）。**备选 B**：把基础规则的 `outline: none` 去掉（会让圆点聚焦时套上全局**品牌红**环，违反 FR-4，**不推荐**）。若担心「改动绿/红点的聚焦外观」超出需求范围，请指示改回备选 A。
25. **前端断言仍走临时 Node harness（打桩 Vue/ElementPlus/echarts 后加载 `app.js`），不新增常驻测试基建**——沿用 R9 既有做法（见 `docs/测试报告/2026-09-25-*.md` 的「无前端常驻测试基建」遗留项）。**建议**：若本次要顺带补齐，可把 harness 落成 `internal/web/app_test.mjs` 并加进常用命令（属独立改动，需用户点头）。
26. **不新增 `neutral` 信号枚举值**：灰点由前端按「非 `improving` 且非 `worsening`」推导（FR-4 的三态是**展示**概念，不是新的业务状态）【推荐】：保持 `trend_signal` 的 JSON 契约与 R9 完全一致（向后兼容、无回归面），且「灰」的判据与 CSS 类名 `neutral` 各司其职。**备选**：后端输出 `trend_signal=neutral`——会让既有断言（`TrendSignal ∈ {"", improving, worsening}`）失效，收益仅是省一次前端推导。
