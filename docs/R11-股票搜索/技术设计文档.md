# R11 技术方案：股票搜索（代码 / 名称 / 模糊子串）

> 需求来源：`docs/R11-股票搜索/需求文档.md`（已定稿，含 D1~D7 已决策记录与 T1/T2 遗留项）。
> 对应现状代码：前端 `internal/web/app.js:749-754`（`querySearch` 仅过滤本地历史）、`internal/web/app.js:483-489`（`doSearch` 直接拼 `/api/stock/${code}/...`）、`internal/web/app.js:816-831`（`el-autocomplete` 模板）；后端 `internal/api/handler.go:38-43`（`len(code)!=6` 校验）、`internal/api/router.go:15-19`（`:code` 路由）、`internal/client/eastmoney.go:79-85`（`quotePrefix` 仅分 sh/sz）。

### 15.1 设计目标与影响面

**目标**：把「纯代码 + 本地历史联想」升级为「代码 / 名称 / 任意子串的实时检索」，覆盖 FR-1~FR-9：

| FR | 落点 |
| --- | --- |
| FR-1/FR-2 代码+名称任意子串、精确>前缀>子串、同层代码升序、≤10 条 | 服务端 `service.RankCandidates`（15.7） |
| FR-3 拼音 / 首字母 | **用户拍板改为「本期启用」**（东财数据源原生提供 `PinYin` 首字母，见 15.2 发现 ②）。服务端 `MatchRank` 的命中范围扩展为 `code + name + PinYin`（15.7 `MatchRank`）。**全拼上游不支持**（`maotai` 实测 0 命中），仍按无命中处理 |
| FR-4 候选展示「代码+名称+市场」、过期响应丢弃、失败静默降级 | 前端 `querySearch` + 模板（15.8） |
| FR-5 唯一命中直进 / 多命中取第 1 条 / 无命中可读提示 | 前端 `doSearch`（15.8） |
| FR-6 历史保留并整合去重 | 前端 `loadHistory`/`addHistory` + `querySearch` 合并（15.8） |
| FR-7 独立检索接口、最终必用 6 位代码 | 新增 `GET /api/stock/search`（15.6）+ `doSearch` 解析后回填 `code`（15.8） |
| FR-8 市场标识 sh/sz/bj、ST 原样保留、北交所取数前缀 | 服务端 `SecurityType` 白名单映射（15.5）+ `quotePrefix` 修正（15.7.5） |
| FR-9 移动端 | `style.css` 新规则（15.8.7） |

**是否破坏既有接口**：**否**。

- 新增 1 条 GET 路由，不改动 `/api/stock/:code/...` 的路径语义与「`:code` 必须是 6 位」校验（15.6.1 已核实两者在 gin 路由树中共存）。
- `quotePrefix` 仅**扩展**分支：既有 sh/sz 代码返回值不变（新旧对照表见 15.7.5）。
- 前端 `doSearch` 由同步改为 `async`：4 个调用点（`@click`、`@keyup.enter`、`pickCode`、`handleSelect`）签名不变，仍是零参调用。
- `addHistory` 由 `(cd, name)` 改为 `(cd, name, market?)`：旧调用点 `app.js:325` 传 2 参仍兼容（market 缺失时按 `guessMarket` 兜底）。

**非目标**（沿用需求第 5 节）：不改任何指标口径/估值公式/AI 逻辑；不做多条件筛选与批量对比；不支持港/美/B 股与海外市场；不做财报科目全文检索。

### 15.2 选型结论与实测依据（FR-7 / D7 / T2）

**结论：采用东财搜索联想接口 `GET https://searchapi.eastmoney.com/api/suggest/get`（`type=14`），服务端做「过滤 + 本地二次校验 + 重排 + 截断」后转发。不维护本地静态股票清单。**

实测命令（本机沙箱过滤代理下**可直连，HTTP 200**）：

```bash
curl -s --data-urlencode "input=茅台" -G \
  "https://searchapi.eastmoney.com/api/suggest/get?type=14&count=50"
```

实测原始返回（`input=茅台`，已删去无关字段）：

```json
{"QuotationCodeTable":{"Data":[{"Code":"600519","Name":"贵州茅台","PinYin":"GZMT","ID":"6005191",
 "JYS":"2","Classify":"AStock","MarketType":"1","SecurityTypeName":"沪A","SecurityType":"1",
 "MktNum":"1","TypeUS":"2","QuoteID":"1.600519","UnifiedCode":"600519","InnerCode":"46077278941243"}],
 "Status":0,"Message":"成功","TotalCount":1,"BizCode":"","BizMsg":""}}
```

**实测数据**

| 项 | 实测值 |
| --- | --- |
| 可达性 | HTTP 200（沙箱过滤代理下直连成功，无需 `dangerouslyDisableSandbox`） |
| 耗时 | `count=50` 时 0.21s（3 次采样 0.215 / 0.213 / 0.210s） |
| 响应体 | `count=50` 时 13749 B |
| `count` 上限 | 20 / 50 / 100 均按请求条数返回（`平安` 的 `TotalCount=794`，可截断取用） |
| `token` 参数 | 实测**可省略**（不带 token 仍返回结果）；本设计仍带公开常量 token（与东财 web 端行为一致，且为将来限流收紧留后路） |
| 空输入 | `input=` → `{"Data":null,"Status":1,"Message":"未查询到数据","TotalCount":0}` |
| 空格 | 上游**已自带去空格**：`input=6 0 0 5 1 9` → `600519 贵州茅台` |
| 未命中 | `input=maotai` → `TotalCount=0`、`Data:null` |

**★ 关键实测发现（直接决定实现方案，逐条都有实测支撑）**

| # | 发现 | 实测证据 | 设计含义 |
| --- | --- | --- | --- |
| ① | 上游返回**全市场混排**，非仅 A 股 | `input=0519` 前 10 条含 `920519 XD万德股`(京A)、`430519 博控科技`(三板)、`870519 弘盛特阀`(三板)、`00519 诺科达科技`(港股)；`input=6005` 前 2 条是**日股** `6005 三浦工业`、**台股** `6005 群益证`；`input=宁德` 大量港股窝轮；`input=平安` 含美股 `PASW 平安生物医药` | **必须服务端过滤**；且过滤要放在排序之前，否则「10 条候选里只剩 1 条 A 股」 |
| ② | 上游**支持拼音首字母匹配**，但**不支持全拼** | 首字母：`input=gzmt` → `600519 贵州茅台`（`TotalCount=1`）、`input=btr` → `920185 贝特瑞`、`input=gzm` → 18 条（命中 `GZMT 贵州茅台` / `GZMB 高争民爆` / `YGZM 阳光照明`，即上游对首字母也做子串匹配）；全拼：`input=maotai` / `guizhoumaotai` / `ningde` / `zhongguopingan` → **`TotalCount=0`**，`input=pingan` 仅回一条港股代码 | 用户拍板**启用拼音**：`PinYin` 进候选、纳入 `MatchRank` 命中判定（15.7.2）。但上游 `PinYin` 字段**仅存首字母**（实测 `GZMT`/`TCLKJ`/`BTR`/`ZGSH`），无全拼字段 → **全拼只能按无命中处理**，如实标注（15.10 R1） |
| ③ | **科创板不是 `SecurityType=1`**，是 `25` | `688981 中芯国际`/`688111 金山办公`/`688036 传音控股` → `SecurityType=25`、`SecurityTypeName=科创板`、`Classify=23` | 若白名单只写 `{1,2,27}` 会**漏掉整个科创板**。白名单必须为 `{1,2,25,27}`（15.5.3） |
| ④ | 北交所上市股票已被上游**统一归一为 `920xxx` + `SecurityType=27`（京A）**；未上市的 43/83/87 新三板为 `SecurityType=10`（三板） | `input=832000` → `920000 安徽凤凰`（京A/27）；`input=835185` → `920185 贝特瑞`（京A/27）；`input=430047` → `920047 诺思兰德`（京A/27）；而 `input=430` 返回的 `430519`/`870519` 是 `SecurityType=10`（三板） | 过滤 `SecurityType=10` **不会漏掉北交所上市标的**；同时保证 6 位代码能直接喂给现有 `/api/stock/:code/...`（北交所也是 6 位） |
| ⑤ | B 股有独立枚举 | `900901 云赛B股` → `SecurityType=3`（沪B）；`200011 深物业B` → `SecurityType=4`（深B） | 白名单天然排除 B 股，无需额外规则（对齐需求非目标「不支持 B 股」） |
| ⑥ | 未查询到 = `Status:1` + `Data:null`，**不是 HTTP 错误** | `input=` / `input=maotai` 实测 | 解析时把 `Status!=0` 或 `Data==nil` 一律当作**空结果**，不作为错误（不触发降级提示） |
| ⑦ | 上游**不做我们需要的排序口径** | `input=平安` 返回序为 `000001 平安银行`、`001359 平安电工`、`601318 中国平安`、三板…；`input=0519` 与需求「同层按代码升序」并不总一致 | 排序必须自建（15.7.3） |

**备选方案对比**

| 方案 | 优点 | 缺点 | 判断 |
| --- | --- | --- | --- |
| **A. 东财联想接口 + 服务端过滤/重排**（推荐） | 零数据维护、始终最新（含 ST/XD 改名即时生效）、单次 0.21s/13KB、天然支持任意子串、**原生提供首字母拼音（免自建拼音库/免 `go get`）** | 依赖外部接口；返回混排需过滤；**无全拼字段（全拼无法支持）** | **采用** |
| B. 本地静态 A 股代码-名称清单（随二进制内嵌） | 无外部依赖、响应 <5ms、完全确定性 | 需自行获取与更新清单（沙箱无法 `go get`、无数据文件）、退市/改名/ST 变动会失真、二进制体积增加、且「任意子串」需全表扫描 5000+ 条 | 备选（作为**降级兜底**可在后续迭代加，本期不做） |
| C. 东财其他接口（如 `push2` 行情列表全量拉取后本地过滤） | 数据全 | 单次拉全市场行情重、有频率风控、仍需二次维护缓存 | 否 |

**降级策略（对应 NFR「外部依赖约束」与 FR-4 边界）**：上游不可用/超时/返回非 JSON → 服务端返回 `code:1`；前端**不弹错、不阻塞**，联想下拉静默退化为「仅历史命中」，`doSearch` 给出中性提示并引导用户「直接输入 6 位代码」。6 位代码直通链路（`/api/stock/:code/indicators` 等）**完全不经过本接口**，故基础能力零影响。

### 15.3 总体架构与数据流

```
┌─ 前端 internal/web/app.js ──────────────────────────────────────────────┐
│ querySearch(q, cb)  ← el-autocomplete(:debounce=250, trigger-on-focus)  │
│   ├ q 为空  → cb(历史)                       [FR-6]                     │
│   └ q 非空  → fetchSearch(q) ──┐             + seq 过期响应丢弃 [FR-4]   │
│ doSearch()  ← 查询按钮 / 回车  │                                        │
│   ├ 6 位纯数字 → 直通（行为不变）[FR-5]                                 │
│   └ 其它 → fetchSearch(q) ─────┤ [FR-5 取第1条 / FR-7 必须回填6位代码]   │
└────────────────────────────────┼────────────────────────────────────────┘
                                 │ GET /api/stock/search?q=茅台
┌─ 后端 ─────────────────────────▼────────────────────────────────────────┐
│ api（Gin）  handler.GetSearch                                            │
│   ① q = service.NormalizeQuery(q)；空 / 超长 → code:0 + [] (不发上游)    │
│   ② c.SearchStocks(q)                                                   │
│ service（纯函数，无 IO）                                                 │
│   ③ items = service.RankCandidates(q, raw, SearchMaxResults)             │
│        = 本地校验(code+name+拼音) → 去重 → 排序 → 截断10 [FR-2/FR-3]     │
│ client（数据获取）                                                       │
│   SearchStocks：suggest 接口 GET(type=14,count=50) → parseSuggestItems    │
│        = 按 SecurityType 白名单过滤非 A 股 + 市场映射 sh/sz/bj  [FR-8]    │
│        + 60s TTL 内存缓存                                                │
└──────────────────────────────────────────────────────────────────────────┘
                          ▼
        https://searchapi.eastmoney.com/api/suggest/get
```

**分层归属理由**（不破坏 `api → service/client → model` 单向依赖）：

- **`client`**：IO 与「东财字段 → 项目结构体」的**数据源适配**（`SecurityType` 枚举映射、过滤非 A 股）属数据获取层职责，与既有 `quotePrefix`、`toReportRows` 同构。
- **`service`**：查询归一化、命中判定、排序、去重、截断是**纯业务规则**（无 IO），放 service 才能像既有 `indicator.go`/`trend_signal.go` 一样单测，且满足「service 保持纯函数无 IO」的硬约束。
- **`model`**：`StockCandidate` 是跨层通用的标准结构体，与三张表/行情同级。
- 前端只走 `/api/*`，不直连东财。

### 15.4 数据模型（`internal/model/search.go` 新增）

```go
package model

// StockCandidate 股票检索候选（A 股：沪/深/京）。
type StockCandidate struct {
	Code        string `json:"code"`        // 6 位证券代码，如 "600519"、"920185"
	Name        string `json:"name"`        // 证券简称，原样保留 ST/*ST/XD 前缀
	Market      string `json:"market"`      // 交易所前缀：sh / sz / bj
	MarketLabel string `json:"marketLabel"` // 市场徽标文案：沪 / 深 / 京
	PinYin      string `json:"-"`           // 名称首字母（大写），仅服务端命中判定用，不进 API 返回
}
```

| 字段 | 类型 | 口径与约定 |
| --- | --- | --- |
| `Code` | string | 6 位数字字符串。**北交所已被上游归一为 `920xxx`**（15.2 发现 ④），可直接作为 `/api/stock/:code/...` 的 `:code`，也满足 `len(code)==6`。不做零填充以外的补零处理（上游已是 6 位） |
| `Name` | string | 上游 `Name` 原样透传。`ST`/`*ST`/`XD`/`XD*` 前缀**不裁剪**（FR-8 要求原样保留展示），前端的宽窄屏截断只作用于展示层 |
| `Market` | string | 仅三值 `sh`/`sz`/`bj`，由 `SecurityType` 白名单映射得出（15.5.3），**不是**由代码首位推断 |
| `MarketLabel` | string | `沪`/`深`/`京`。放服务端计算（单一事实源），前端只渲染，避免两端各写一份映射 |
| `PinYin` | string | **名称首字母**（东财 `PinYin` 原样透传 + `ToUpper`，实测形如 `GZMT`/`ZGSH`/`TCLKJ`/`BTR`）。`json:"-"`：**仅用于服务端命中判定，不进 API 返回**（用户拍板：候选展示仍是代码+名称+市场）。上游**无全拼字段**（15.2 发现 ②） |

**不含 `price` 字段**：D4 明确「当前价为可选、不因取价拖慢联想」。候选若带现价需对每条候选再打一次腾讯行情（10 次外部请求），与 NFR「单次联想 1s 内」直接冲突，故本期**不返回**；前端模板用 `v-if="item.price"` 预留兼容位（字段缺失即不渲染），后续若要接只需在 `parseSuggestItems` 后追加一次批量取价，接口契约不变。

```go
// internal/client/search.go
type suggestResp struct {
	QuotationCodeTable struct {
		Data       []suggestItem `json:"Data"`
		Status     int           `json:"Status"`
		Message    string        `json:"Message"`
		TotalCount int           `json:"TotalCount"`
	} `json:"QuotationCodeTable"`
}

type suggestItem struct {
	Code         string `json:"Code"`
	Name         string `json:"Name"`
	Classify     string `json:"Classify"`     // AStock / NEEQ / HK / UsStock / OTCFUND / BK / 23 ...
	SecurityType string `json:"SecurityType"` // 字符串枚举，见 15.5.3
	JYS          string `json:"JYS"`          // 交易市场码：2=沪 6=深 80=创业板 81=北交所/三板 HK/NASDAQ/...
	MktNum       string `json:"MktNum"`       // 1=沪 0=深(含京A/三板) 116=港 105=美 150=场外基金 90=板块
	PinYin       string `json:"PinYin"`       // 名称首字母，如 "GZMT"（纳入命中判定，见 15.7.2）
}
```

| 东财字段 | 类型 | 映射到 | 依据/备注 |
| --- | --- | --- | --- |
| `Data[].Code` | string | `StockCandidate.Code` | 6 位；北交所已归一为 `920xxx` |
| `Data[].Name` | string | `StockCandidate.Name` | 含 ST/XD 前缀，原样透传 |

#### 15.7.2 `NormalizeQuery` / `MatchRank`（命中判定口径，FR-1/FR-2/FR-3）

```go
// NormalizeQuery：去所有空白 + 大写。中文 ToUpper 为恒等，故对中文名称无副作用。
// strings.Fields 按 unicode.IsSpace 切分（含 \t \n 与全角空格 U+3000），与前端 /\s+/ 口径一致。
func NormalizeQuery(q string) string {
	return strings.ToUpper(strings.Join(strings.Fields(q), ""))
}

// MatchRank 返回命中层级。q 必须是 NormalizeQuery 的结果；名称与拼音均按大写比较。
//
//	0 代码精确      1 代码/名称前缀   2 代码/名称子串
//	3 拼音精确      4 拼音前缀       5 拼音子串
//	-1 未命中
//
// 拼音（首字母）层级整体排在「代码/名称命中」之后，对齐 FR-3 后续迭代约定的
// 「拼音命中排在中文子串命中之后」。
func MatchRank(q string, c model.StockCandidate) int {
	if q == "" {
		return -1 // 空串下 HasPrefix/Contains 恒真，必须前置拦截
	}
	// ① 代码 / 名称
	name := strings.ToUpper(c.Name)
	switch {
	case c.Code == q || name == q:
		return 0
	case strings.HasPrefix(c.Code, q) || strings.HasPrefix(name, q):
		return 1
	case strings.Contains(c.Code, q) || strings.Contains(name, q):
		return 2
	}
	// ② 拼音首字母（东财 PinYin；实测仅有首字母，无全拼）
	py := strings.ToUpper(c.PinYin)
	switch {
	case py == "":
		return -1
	case py == q:
		return 3
	case strings.HasPrefix(py, q):
		return 4
	case strings.Contains(py, q):
		return 5
	default:
		return -1
	}
}
```

**命中判定权威仍在本地**：上游除「代码/名称子串」外还会做**它自己的**模糊匹配——实测 `gzm` 会回 `600195 中牧股份`（`PinYin=ZMGF`，既非代码/名称子串，也不含 `GZM`）这类无法用我们规则解释的项，`gz` 会回一堆台股（`2338 光罩`/`3178 公准`）。故 `MatchRank` 仍是对上游召回的**二次校验**，只是校验范围由「code + name」扩展为「code + name + PinYin」：凡不能被解释的返回项一律丢弃，保证「命中口径」与「排序口径」自洽、可复现（NFR 确定性）。

**拼音能力实测对照表**（用户拍板「启用拼音」后的完整行为，全部为本次实测结论）

| 输入 | 上游返回 | 本地判定 | 最终结果 |
| --- | --- | --- | --- |
| `gzmt`（首字母精确） | `600519 贵州茅台`（`PinYin=GZMT`） | `py == "GZMT"` → rank **3** | ✅ 命中 `600519 贵州茅台·沪`（原「无命中」**已反转为命中**） |
| `gzm`（首字母前缀） | 18 条，含 `GZMT`/`GZMB`/`YGZM`/`ZMGF` | `GZMT`/`GZMB` 前缀 rank 4；`YGZM` 子串 rank 5；`ZMGF` 丢弃 | ✅ 4 条：`002827 高争民爆`、`600519 贵州茅台`、`600261 阳光照明`、`601888 中国中免`（见 15.9 D #12） |
| `btr` | `920185 贝特瑞`（`PinYin=BTR`） | rank 3 | ✅ `920185 贝特瑞·京` |
| `zgsd` | `TotalCount=0`（中国中免首字母为 `ZGZM`） | — | ❌ 无命中（正确：不误报） |
| `maotai` / `guizhoumaotai` / `ningde` / `zhongguopingan`（**全拼**） | `TotalCount=0` | 无可匹配输入 | ❌ **无命中**——上游 `PinYin` 字段**只有首字母、没有全拼**，构不出匹配依据（15.10 R1 如实标注） |
| `pingan`（全拼，恰为某港股代码） | 仅回港股 `05131 PING AN B2907` | `SecurityType` 过滤后为空 | ❌ 无命中 |
| `tcl`（名称本身含字母） | `000100 TCL科技` 等 | 名称前缀 rank 1（**走名称路径，不经拼音**） | ✅ 4 条（FR-1 大小写不敏感） |

**拼音为何也分「精确/前缀/子串」三层**：若把全部拼音命中压成单一层级（统一 rank 3），`gzm` 的同层并列会按代码升序排成 `002827 高争民爆 → 600519 贵州茅台 → …`，把最相关的前缀命中（贵州茅台）挤到第二位。故本设计**镜像**「精确/前缀/子串」三层（3/4/5），与代码/名称完全同构：既满足「拼音排在中文子串命中之后」（全部 ≥ 3 > 2），又让拼音域内的相关性排序保持一致语义。备选：单一 rank 3（少 2 个分支，代价是丢失前缀相关性，`gzm` 场景体验变差）。

#### 15.7.3 `RankCandidates`（排序 / 去重 / 截断，FR-2）

```go
func RankCandidates(q string, in []model.StockCandidate, limit int) []model.StockCandidate {
	type ranked struct {
		rank int
		cand model.StockCandidate
	}
	best := make(map[string]ranked, len(in))
	for _, c := range in {
		r := MatchRank(q, c)
		if r < 0 {
			continue // 丢弃无法被 code/name/拼音解释的上游召回（含上游自身的其它模糊匹配）
		}
		if prev, ok := best[c.Code]; !ok || r < prev.rank {
			best[c.Code] = ranked{r, c} // 同一 code 只留最优（去重，不改变对外位次）
		}
	}
	out := make([]ranked, 0, len(best))
	for _, v := range best {
		out = append(out, v)
	}
	sort.Slice(out, func(i, j int) bool {
		if out[i].rank != out[j].rank {
			// 0..2 = 代码/名称域的 精确>前缀>子串；3..5 = 拼音域的 精确>前缀>子串
			return out[i].rank < out[j].rank
		}
		return out[i].cand.Code < out[j].cand.Code // 同层按代码升序（字符串字典序 == 数字序，因等长 6 位）
	})
	if limit > 0 && len(out) > limit {
		out = out[:limit]
	}
	res := make([]model.StockCandidate, 0, len(out))
	for _, v := range out {
		res = append(res, v.cand)
	}
	return res
}
```

口径与边界：

- **确定性**（NFR「确定性」）：`sort.Slice` 用 `(rank, code)` 全序，且 `code` 唯一（已去重），故**无并列、无随机**；相同输入 → 相同顺序。**不使用** `sort.SliceStable` 依赖输入序（输入序来自上游，会变）。
- **同层代码升序的一致性**：A 股代码恒为 6 位数字串，字典序与数值序等价；`920519` 排在 `600519` 之后（`9`>`6`），符合「按代码升序」的字面规则。
- **拼音命中恒在代码/名称命中之后**：`rank` 单调递增（`0..2` 为代码/名称域、`3..5` 为拼音域），故只要存在任一代码/名称命中，拼音命中必定排其后（对齐 FR-3 后续迭代约定）。另：纯数字查询串在拼音域恒不可达（`PinYin` 只含字母），代码查询行为不受拼音引入影响。
- **同一候选既命中名称又命中拼音时取更优层级**：`MatchRank` **先判代码/名称、命中即返回**，故不会因拼音层级编号更大而劣化（例：`tcl` 命中 `TCL科技` 的名称前缀 → rank 1，不走拼音域）。
- **`limit <= 0`** 表示不截断（仅测试用）；handler 恒传 `SearchMaxResults`。
- **空 `q` 前置返回**（handler 层已拦截，这里 `MatchRank` 也返回 `-1`，双重兜底，避免空串 `HasPrefix` 全命中）。
- **`in` 为 nil/空** → 返回空切片（**非 nil**），保证 JSON 序列化为 `[]` 而非 `null`（前端 `r.items.length` 判定不受影响）。

| `qt.gtimg.cn/q=sz920185` | ❌ `v_pv_none_match="1";` |
| `qt.gtimg.cn/q=sh920185` | ❌ `v_pv_none_match="1";` |

即：**腾讯已支持 `bj` 前缀，现状代码对北交所必然取数失败**（返回 `v_pv_none_match` → `FetchQuote` 报「未获取到行情数据」）。同时实测确认东财财报侧**无需前缀**：datacenter 用 `filter=(SECURITY_CODE="920185")` 可直接返回 `SECUCODE="920185.BJ"` 的资产负债表，故**只有行情前缀需要修**。

修正实现：

```go
// quotePrefix 根据 6 位代码推断交易所前缀。
// sh：沪市主板/科创板（6 开头）、沪B（9 开头，含 900xxx）
// sz：深市主板/创业板（0/3 开头）、深B（200xxx）
// bj：北交所（920xxx 新码段，以及 43/83/87/88 开头的存量码段）
// 注意：920xxx 与沪B 的 900xxx 同以 9 开头，故必须**先判 920**。
func quotePrefix(code string) string {
	switch {
	case strings.HasPrefix(code, "920"),
		strings.HasPrefix(code, "43"),
		strings.HasPrefix(code, "83"),
		strings.HasPrefix(code, "87"),
		strings.HasPrefix(code, "88"):
		return "bj"
	case strings.HasPrefix(code, "6"), strings.HasPrefix(code, "9"):
		return "sh"
	default:
		return "sz"
	}
}
```

新旧对照（回归安全性）：

| 代码 | 旧行为 | 新行为 | 影响 |
| --- | --- | --- | --- |
| `600519` / `601318` / `688981` / `900901` | `sh` | `sh` | 无变化 |
| `000001` / `300750` / `200011` | `sz` | `sz` | 无变化 |
| `920185` / `920047`（北交所新码段） | `sh` ❌ | `bj` ✅ | **修复**（原本取不到行情） |
| `430047` / `830799` / `870925` / `880xxx` | `sz` ❌ | `bj` ✅ | **修复**（存量码段兜底；上游已归一为 920xxx，此分支为防御性） |

> 与检索层的一致性：检索候选的 `market` 来自东财 `SecurityType`（权威），`quotePrefix` 是按代码推断（本地）。两者在 `920xxx` 与 `43/83/87/88` 上口径一致；若将来出现不一致（上游给出 `bj` 而代码前缀推不出），以**检索结果的 `market` 为准**展示、以 `quotePrefix` 为准取数——记载于此作为已知的潜在不一致点（当前实测无此情形）。

**6 位校验是否需要放开**：**不需要**（15.6.1）。

- 上游召回已过滤为非 A 股排除，候选 `Code` 恒为 6 位；
- `doSearch` 在非 6 位输入时**先解析出 6 位代码再发起查询**（15.8.4），故 `/api/stock/:code/...` 收到的永远是 6 位；
- 保留 `handler.go` 的 `len(code)!=6` 校验作为**最后一道防线**（防御手工构造 URL / 书签旧链接），并把错误文案保留原样（不再由正常交互路径触达，满足验收「不出现原始报错」）。

#### 15.8.4 `querySearch` / `doSearch` / `handleSelect` / 历史

```js
// 改写 app.js:749-754。q 空 → 仅历史；q 非空 → 历史命中 ∪ 服务端候选（历史优先），去重，截断 10。
function querySearch(query, cb) {
  const raw = (query || '').trim();
  const q = normalizeQueryInput(raw);
  const hist = history.value
    .filter(h => !q || h.code.includes(q) || normalizeQueryInput(h.name).includes(q))
    .map(h => ({ value: h.code, code: h.code, name: h.name,
                 market: h.market, marketLabel: marketLabelOf(h.market), kind: 'hist' }));
  if (!q) { cb(hist); return; }

  const seq = ++searchSeq;
  fetchSearch(raw).then(r => {
    if (seq !== searchSeq) return;                       // ★ 丢弃过期响应（FR-4）
    if (!r.ok) { cb(hist); return; }                     // ★ 静默降级：只给历史命中（FR-4 边界）
    const seen = new Set(), items = [];
    const push = (it) => { if (it.code && !seen.has(it.code)) { seen.add(it.code); items.push(it); } };
    hist.forEach(push);                                  // FR-6：历史命中优先（同级加权）
    r.items.forEach(c => push({ value: c.code, code: c.code, name: c.name,
                                market: c.market, marketLabel: c.marketLabel, kind: 'result' }));
    const list = items.slice(0, MAX_HISTORY);            // 合并后仍 ≤10（复用 MAX_HISTORY=10）
    if (!list.length) list.push({ value: raw, kind: 'empty', text: SEARCH_EMPTY_TEXT });
    cb(list);
  });
}
```

```js
function loadHistory() {
  try {
    const raw = JSON.parse(localStorage.getItem(HISTORY_KEY) || '[]');
    // 旧数据只有 {code,name}：补 market，保证展示有徽标（FR-6/FR-8）
    history.value = (Array.isArray(raw) ? raw : []).map(h => ({
      code: h.code, name: h.name || '', market: h.market || guessMarket(h.code),
    }));
  } catch (e) { history.value = []; }
}
function addHistory(cd, name, market) {
  if (!cd) return;
  const list = history.value.filter(h => h.code !== cd);
  list.unshift({ code: cd, name: name || '', market: market || guessMarket(cd) });
  if (list.length > MAX_HISTORY) list.length = MAX_HISTORY;
  history.value = list;
  saveHistory();
}
```

**关键取舍：空态行用「哨兵候选项」而非空数组**。EP 的 `el-autocomplete` 在 `cb([])` 时**不展开下拉**，无法满足 D6「下拉内空态提示（不关闭下拉）」。故传 1 条哨兵 `{ value: raw, kind: 'empty', text: ... }`：

- `value` 取**用户当前的输入原文**（**不是空串**）。EP 在 select 时先 `emit('update:modelValue', item.value)` 再 emit `select`（`handleSelect` 才轮到我们）。若 `value` 为空串，点一下空态行就会**把用户已输入的内容清空**（违反 NFR「用户已输入的内容不得被联想流程覆盖」）；取 `raw` 则 modelValue 不变，配合 `handleSelect` 的提前 return，**点击空态行是完全无副作用**的。

#### 15.8.6 `doSearch` 的双触发风险（既有问题，登记备查）

`@keyup.enter="doSearch"` 与 `el-autocomplete` 自身的「回车选中当前高亮项」在同一次回车里可能**都触发**（EP 在 keydown 选中 → 我们 `handleSelect → doSearch`；随后 keyup 又触发 `doSearch`），导致同一只股票重复拉 4 个接口。**该行为在改动前已存在**（现有代码同样是 `@select` + `@keyup.enter` 双绑），故不属本次回归；但改动后 `doSearch` 变为 async，重复调用会**并发两轮请求**（既有的 `fetchData`/`fetchAnalysis` 均无 in-flight 去重）。可选硬化（**推荐做，成本 3 行**）：

```js
let searchBusy = false;
async function doSearch() {
  if (searchBusy) return;
  searchBusy = true;
  try { /* 上述主体 */ } finally { searchBusy = false; }
}
```

> 注意 `searchBusy` 需覆盖 `await fetchSearch` 期间；单纯用 `loading.value`（`fetchData` 的）无法覆盖解析阶段。是否落地由 coder/tester 视实测表现决定，不作为验收阻塞项。

| # | 决策点 | 推荐（本设计采用） | 理由 | 备选 |

| 1 | 检索数据源（T2/D7） | **东财 suggest 联想接口** + 服务端过滤/重排 | 零数据维护、始终最新（ST/XD 改名即时生效）、实测 0.21s/13.7KB、原生支持任意子串；本地静态清单需自备数据文件且会因退市/改名失真，沙箱又无法 `go get` 拉数据 | 本地静态 A 股清单（作将来降级兜底）；`push2` 全市场行情拉取（过重） |
