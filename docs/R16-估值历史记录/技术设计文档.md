### 20.1 设计目标与影响面

#### 20.1.1 目标

1. 用户主动发起的成功估值（手动「计算估值」、AI「套用到估值」）形成一条**服务端持久化**快照；搜索带来的自动估值**不记录**。
2. 服务端以单个 JSON 文件保存记录，单进程内互斥锁串行读写，临时文件 + `Sync` + `rename` 原子写；文件不存在/损坏时降级为空列表并留档损坏文件。
3. 暴露 4 个 `/api/valuation-history` 接口（GET / POST / DELETE `:code` / DELETE 全部），统一 `{code,data,message}`，写操作返回服务端完整最新列表。
4. 前端删除 localStorage 读写，改为 `fetch` 调用；加载/失败/重试态完整；多个记录类请求用单调序号防止旧响应覆盖新列表。
5. 首次加载把旧 localStorage 记录中服务端缺失的 `code` 按旧时间从早到晚补发 POST；成功后写迁移标记，失败下次重试，保留旧数据作备份。
6. 顶栏入口、抽屉、分页、点击回填、切换股票重置（FR-12）等既有交互不变。

#### 20.1.3 不变量与既有行为变更

- 服务端保证文件与接口返回始终满足：`version=1`、按 `createdAt` 倒序、`code` 唯一、最多 50 条。
- 记录是**快照**：不监听行情/年报变化，不存在被动刷新路径。
- 既有估值/指标/报表/分析/AI 接口契约不变；记录接口失败不得影响其余功能。
- `fetchValuation()` 的 `source` 参数、请求序号 + code 绑定的竞态守卫（FR-12.3）保持现状；仅把「成功后的落记录」从同步写 localStorage 改为异步 POST。
- `createdAt` 的权威来源改为**服务端**；前端 `buildValuationRecord` 不再生成时间。

#### 20.1.4 风险与边界

- 文件 ≤50 KB，本地读写应在 100ms 内完成；不维护长期内存副本，每次请求重新读文件（人工编辑下次请求即生效）。
- 写失败（磁盘满/目录只读）不提交任何变更，接口返回 `code=1`；前端提示且不把该条加入列表。
- **不支持多实例并发写**：互斥锁只在本进程内生效；两个进程指向同一文件时原子 rename 能避免文件损坏，但会出现后写覆盖先写。推荐同一数据文件只由一个服务进程使用。
- `-data` 为相对路径时相对**进程工作目录**；从不同目录启动会指向不同文件，需显式指定。
- 记录接口无鉴权（Q7 已拍板）；同局域网可访问者即可读写/清空记录，记录仅含公开数据快照。

### 20.2 总体架构与数据流

新增一个**叶子存储层** `internal/store`，依赖 `internal/model` 与标准库；`api` 依赖 `store`，`main` 负责构造并注入。分层仍保持单向：

```
api（Gin handler/router）──→ store（文件读写，仅标准库 + model）
        │
        ├──→ service（指标计算，纯函数，无 IO）
        └──→ client（外部数据获取）
                    ↓
                  model（标准结构体）
```

`store` 不感知 HTTP、不做业务计算；`service` 不感知存储。

```
【读】打开抽屉 / 应用初始化
  Vue ──GET /api/valuation-history──→ Handler.GetValuationHistory
        → store.List()：加锁 → 读文件 → 解析/归一化 → 去重/排序/截断
        → {code:0,data:{items:[...]}} → 前端整体替换 valuationHistory

【写】手动计算 / AI 套用成功（auto 不写）
  Vue recordValuation() ──POST 单条──→ Handler.UpsertValuationHistory
        → store.Upsert()：加锁 → 读文件 → 服务端 createdAt → 删除同 code
          → 置顶 → 截断 50 → 排序 → 临时文件+Sync+rename
        → 返回完整 items → 前端整体替换 + 徽标更新

【删】单条 / 清空
  DELETE /api/valuation-history/:code ──→ store.Delete(code)（幂等）──→ 完整 items
  DELETE /api/valuation-history       ──→ store.Clear()             ──→ 空 items

【迁移】应用初始化首次 GET 成功后（每次页面加载只尝试一次）
  localStorage(valuationHistory) → 逐条校验/排序 → 取服务端缺失 code
  → 按旧 createdAt 从早到晚逐条 POST → 全部成功写 valuationHistoryMigrated=1
  → 保留 localStorage 原数据（一次性备份）
```

**为什么新增 `internal/store` 而不是塞进 `api`**：文件读写、原子写、归一化是可独立单测的纯存储逻辑；放在 `api` 会让 handler 文件同时承担 IO 与 HTTP，且无法在无 HTTP 的情况下测并发/损坏恢复。`store` 作为叶子包不破坏既有依赖方向。

### 20.3 数据模型

#### 20.3.1 文件信封

固定位置 `<data>/valuation_history.json`（`-data` 缺省 `./data`），内容：

```json
{
  "version": 1,
  "items": [ { /* ValuationRecord */ } ]
}
```

- `version` 固定 `1`；读取时 `version != 1` 或 `items` 非数组 → 视为空列表，下一次写入落盘修正。
- `items` 始终为数组（空列表写 `[]`，不写 `null`）。
- 金额字段一律为**元**；不适用字段写 `null`（不是省略），保证文件可人工阅读、结构稳定。

#### 20.3.2 `ValuationRecord`（`internal/model/valuation_history.go`）

可选数值/字符串使用指针，确保 `null` 能原样落盘与回读；`omitempty` 一律不用。

```go
package model

// ValuationRecord 一条估值历史记录（计算时点快照）。
// 金额单位一律为元；不适用的可选字段为 nil（JSON null）。
type ValuationRecord struct {
	Code        string `json:"code"`        // 6 位代码，唯一键
	Name        string `json:"name"`        // 公司名，缺失为空串
	Market      string `json:"market"`      // sh / sz / bj
	CreatedAt   string `json:"createdAt"`   // 服务端写入时刻，ISO 8601 UTC（RFC3339）
	Source      string `json:"source"`      // manual / ai
	Year        *int   `json:"year"`        // 基期年报年份

	Model     string `json:"model"`     // zero/perpetual/two_stage/three_stage
	ModelName string `json:"modelName"` // 模型中文名

	DiscountRate   *float64 `json:"discountRate"`   // 折现率 %
	GrowthRate     *float64 `json:"growthRate"`     // 永续增长率 %（perpetual）
	Stage1Growth   *float64 `json:"stage1Growth"`   // 第一阶段增长率 %
	Stage1Years    *int     `json:"stage1Years"`    // 第一阶段年数
	Stage2Growth   *float64 `json:"stage2Growth"`   // 第二阶段增长率 %
	Stage2Years    *int     `json:"stage2Years"`    // 第二阶段年数
	TerminalGrowth *float64 `json:"terminalGrowth"` // 三阶段终值增长率 %

	FCFMode     string `json:"fcfMode"`     // latest/average/median/trim_mean/custom
	FCFModeName string `json:"fcfModeName"` // 中文名
	FCFYears    *int   `json:"fcfYears"`    // 选取年数（平均值/中位数/去极值）
	AdjustRD    bool   `json:"adjustRD"`    // 研发调整开关

	RDAdjustment   *float64 `json:"rdAdjustment"`   // 研发扩张加回金额（元）
	FCFCustomValue *float64 `json:"fcfCustomValue"` // 自定义基期 FCF 的元值
	FCFCustomUnit  *string  `json:"fcfCustomUnit"`  // yuan/qian/wan/yi

	BaseFCF             *float64 `json:"baseFCF"`             // 基期经营资产自由现金流（元）
	FinancialAssetValue *float64 `json:"financialAssetValue"` // 金融资产价值（元）
	LongEquityValue     *float64 `json:"longEquityValue"`     // 长期股权投资价值（元）
	OperatingAssetValue *float64 `json:"operatingAssetValue"` // 经营资产价值 DCF（元）
	CompanyValue        *float64 `json:"companyValue"`        // 公司价值（元）
	DebtValue           *float64 `json:"debtValue"`           // 债务价值/有息债务（元）
	EquityValue         *float64 `json:"equityValue"`         // 股权价值（元）
	EquityValuePerShare *float64 `json:"equityValuePerShare"` // 每股股权价值（元）
}
```

字段与前端 `buildValuationRecord`（`app.js:667`）逐一对应，命名沿用 FR-2 的 camelCase。`notes`、AI 结论、行情价格等**不入库**。

#### 20.3.3 `null` 语义与单位

- 数值/字符串指针为 `nil` 时 JSON 输出 `null`；前端 `normalizeValuationRecord` 已把 `null` 归一为 `null`/空串。
- `adjustRD` 无指针：缺失/`null`/非法均视为 `false`。
- `fcfCustomValue` **始终是换算后的元值**（与 `ValuationResult.fcf_custom_value` 一致）；`fcfCustomUnit` 仅用于展示/回填时反算，见 20.4.2。
- 时间统一 RFC3339 UTC，服务端用 `time.Now().UTC().Format(time.RFC3339)`（秒级）。同一秒内的多条按写入顺序排序：新写入者在前。

#### 20.3.4 校验与归一化（服务端）

`store.normalizeRecord(rec) (model.ValuationRecord, bool)`：

1. `Code = strings.TrimSpace(rec.Code)`；不匹配 `^\d{6}$` → 返回 `false`（丢弃整条）。
2. `CreatedAt` 必须能被 `time.Parse(time.RFC3339, ...)` 解析（Go 解析时自动接受小数秒，前端旧数据的 `.123Z` 可解析）→ 否则丢弃。
3. `Market` 不在 `sh/sz/bj` → 按代码回填（`guessMarket`）。
4. `Source` 仅保留 `ai`，其余归一为 `manual`。
5. `FCFModeName` 为空且 `FCFMode` 非空 → 按映射回填：`latest=最近一年`、`average=近几年平均值`、`median=近几年中位数`、`trim_mean=去极值平均值`、`custom=自定义`。
6. `ModelName` 为空且 `Model` 非空 → 回填：`zero=零增长模型`、`perpetual=永续增长模型`、`two_stage=两阶段模型`、`three_stage=三阶段模型`。
7. 其余字段不做数值合法性推算（记录是快照，只保证类型与键）；指针字段由 JSON 解码保证类型。

排序/去重/截断 `dedupeSortTruncate(items)`：

1. `sort.SliceStable` 按 `createdAt` 倒序（相同时间保持原顺序，即后写入者在前）。
2. 顺序遍历按 `code` 去重，保留第一条（即最新）。
3. 截断到 `MaxValuationRecords = 50`。

#### 20.4.2 自定义基期 FCF 单位口径（易错，必须保持）

`fcf_custom_value` 是**换算成元后的值**（`internal/model/valuation.go:50`、`internal/service/valuation.go`），`fcf_custom_unit` 只是用户当时选择的展示单位：

- 记录中存**元值**，同时保留 `fcfCustomUnit`。
- 列表展示：`显示值 = fcfCustomValue / VAL_FCF_UNIT_FACTOR[unit]`，再拼 `fcfUnitLabel(unit)`（亿/万/千/元）。
- 点击回填：`valFCFCustomValue = record.fcfCustomValue / VAL_FCF_UNIT_FACTOR[unit]`。
- 换算系数复用 `app.js:291` 的 `VAL_FCF_UNIT_FACTOR`，不新增常量。

#### 20.4.3 服务端补充/覆盖字段

- `createdAt`：**无条件覆盖**为服务端当前 UTC 时间；请求体传入值忽略（FR-13.2）。
- `market`：缺失/非法时按代码回填。
- `fcfModeName`、`modelName`：缺失时按 key 回填。
- `source`：非 `ai` 一律 `manual`。
- 不做名称解析、不访问东财/腾讯，不引入新数据源。

### 20.5 接口 / API 设计

#### 20.5.1 统一约定

- 路径前缀固定 `/api/valuation-history`。
- 响应沿用项目约定：`{"code":0,"message":"ok","data":...}`；`code=0` 成功。
- 成功时 `data` 统一为 `{"items":[ValuationRecord...]}`，**写操作返回写入/删除后的完整最新列表**（≤50 条）。
- 金额单位元；时间 RFC3339 UTC。

#### 20.5.2 `GET /api/valuation-history` — 读取列表

- 请求：无参数。
- 成功：`200 {"code":0,"message":"ok","data":{"items":[...]}}`。
- 文件不存在/读取失败/JSON 损坏：仍返回 `code=0` + 空 `items`（损坏文件另存 `.corrupt-<时间戳>`，见 20.6.3），不返回 500。
- 列表保证 `createdAt` 倒序、`code` 唯一、≤50。

#### 20.5.3 `POST /api/valuation-history` — 新增或覆盖一条

- 请求体：单个 `ValuationRecord`。`createdAt` 可省略，传入也忽略。
- 校验：
  - 请求体必须是合法 JSON 对象，非法 → `400 {"code":1,"message":"请求体不是合法的估值记录 JSON","data":null}`；
  - 请求体上限 64 KiB（`http.MaxBytesReader`），超限 → 400；
  - `code` 去空白后必须为 6 位数字，否则 `400 {"code":1,"message":"股票代码需为6位数字","data":null}`。
- 处理（单次加锁内完成）：服务端时间 → 删除同 `code` 旧记录 → 新记录置顶 → 超过 50 截断最早 → 排序 → 原子落盘。
- 成功：`200 {"code":0,"message":"ok","data":{"items":[...]}}`。
- 写失败（磁盘/权限）：`200 {"code":1,"message":"保存失败：<原因>","data":null}`，磁盘既有内容不变。

请求示例：

```json
{
  "code": "300750", "name": "宁德时代", "market": "sz", "source": "ai",
  "year": 2025, "model": "two_stage", "modelName": "两阶段模型",
  "discountRate": 9, "stage1Growth": 15, "stage1Years": 5, "stage2Growth": 3,
  "fcfMode": "average", "fcfModeName": "近几年平均值", "fcfYears": 3,
  "adjustRD": true, "rdAdjustment": 123000000,
  "baseFCF": 45600000000, "financialAssetValue": 80000000000,
  "longEquityValue": 0, "operatingAssetValue": 1400000000000,
  "companyValue": 1480000000000, "debtValue": 20000000000,
  "equityValue": 1460000000000, "equityValuePerShare": 331.08
}
```

调用时机严格遵循 FR-1：仅手动「计算估值」与 AI「套用」成功后调用；`auto` 自动计算不调用。

#### 20.5.4 `DELETE /api/valuation-history/:code` — 删除单条

- `:code` 必须 6 位数字，否则 `400 + code=1`。
- 记录存在则删除；不存在按**幂等成功**（无操作）。
- 成功返回删除后的完整 `items`；写失败 `200 + code=1`，内容不变。

#### 20.5.5 `DELETE /api/valuation-history` — 清空全部

- 成功返回 `{"code":0,"message":"ok","data":{"items":[]}}`。
- 写失败 `200 + code=1`，磁盘内容保持不变。

#### 20.6.2 `loadLocked`：读取、容错、归一化

```go
func (s *ValuationHistoryStore) loadLocked() []model.ValuationRecord {
	raw, err := os.ReadFile(s.path)
	if err != nil {
		if !errors.Is(err, os.ErrNotExist) {
			log.Printf("读取估值记录失败 %s: %v", s.path, err) // 读取失败按空列表处理（FR-13.1）
		}
		return []model.ValuationRecord{}
	}

	var env struct {
		Version int               `json:"version"`
		Items   []json.RawMessage `json:"items"`
	}
	if err := json.Unmarshal(raw, &env); err != nil {
		log.Printf("估值记录文件损坏 %s: %v；已备份", s.path, err)
		s.backupCorruptLocked()
		return []model.ValuationRecord{}
	}
	if env.Version != ValuationHistoryVersion || env.Items == nil {
		return []model.ValuationRecord{} // 版本不符/items 非数组：空列表，下次写入修正
	}

	out := make([]model.ValuationRecord, 0, len(env.Items))
	for _, item := range env.Items {
		var rec model.ValuationRecord
		if err := json.Unmarshal(item, &rec); err != nil {
			log.Printf("丢弃非法估值记录条目: %v", err)
			continue
		}
		if norm, ok := normalizeRecord(rec); ok {
			out = append(out, norm)
		}
	}
	return dedupeSortTruncate(out)
}
```

- 逐条 `json.RawMessage` 解码：单条字段类型非法只丢弃该条，不影响整份文件。
- `version != 1` 或 `items` 缺失/`null` → 空列表；`items` 为对象等类型错误会在信封解码阶段失败 → 走损坏备份路径。
- **损坏备份**：仅当文件存在但 JSON 解析失败时，将原文件重命名为 `valuation_history.json.corrupt-<UTC时间戳>`（如 `valuation_history.json.corrupt-20261017T120000Z`）；重命名失败只记日志。避免下一次写入静默覆盖可恢复数据。

#### 20.6.3 `saveLocked`：原子写

```go
func (s *ValuationHistoryStore) saveLocked(items []model.ValuationRecord) error {
	if items == nil {
		items = []model.ValuationRecord{}
	}
	env := struct {
		Version int                     `json:"version"`
		Items   []model.ValuationRecord `json:"items"`
	}{ValuationHistoryVersion, items}

	buf, err := json.MarshalIndent(env, "", "  ")
	if err != nil {
		return fmt.Errorf("序列化估值记录失败：%w", err)
	}

	dir := filepath.Dir(s.path)
	if err := os.MkdirAll(dir, 0o755); err != nil {
		return err
	}
	tmp, err := os.CreateTemp(dir, ValuationHistoryFileName+".tmp-*")
	if err != nil {
		return err
	}
	tmpName := tmp.Name()
	cleanup := func() {
		_ = tmp.Close()
		_ = os.Remove(tmpName)
	}
	if _, err := tmp.Write(buf); err != nil {
		cleanup()
		return err
	}
	if err := tmp.Sync(); err != nil { // 落盘后再 rename，进程中途退出时旧文件完整
		cleanup()
		return err
	}
	if err := tmp.Chmod(0o644); err != nil { // CreateTemp 默认 0600，放宽为可读
		cleanup()
		return err
	}
	if err := tmp.Close(); err != nil {
		_ = os.Remove(tmpName)
		return err
	}
	if err := os.Rename(tmpName, s.path); err != nil { // macOS/Linux 覆盖已存在文件为原子操作
		_ = os.Remove(tmpName)
		return err
	}
	return nil
}
```

- 写失败时临时文件被清理，目标文件保持原样；内存中也没有已提交的副本（本就不维护内存副本）。
- 目标平台以 macOS/Linux 为准；Windows 不在本期验收目标。
- 可选增强（非必需）：rename 后对目录 `Sync`，提升掉电持久性；本期不要求。

#### 20.6.4 `List` / `Upsert` / `Delete` / `Clear`

```go
func (s *ValuationHistoryStore) List() []model.ValuationRecord {
	s.mu.Lock()
	defer s.mu.Unlock()
	return s.loadLocked()
}

func (s *ValuationHistoryStore) Upsert(rec model.ValuationRecord) ([]model.ValuationRecord, error) {
	s.mu.Lock()
	defer s.mu.Unlock()

	rec.CreatedAt = time.Now().UTC().Format(time.RFC3339) // 服务端权威时间，忽略传入值
	norm, ok := normalizeRecord(rec)
	if !ok {
		return nil, fmt.Errorf("股票代码需为6位数字") // handler 已校验，这里是防御
	}

	items := s.loadLocked()
	out := make([]model.ValuationRecord, 0, len(items)+1)
	out = append(out, norm) // 新记录置顶
	for _, r := range items {
		if r.Code != norm.Code { // 同 code 整体覆盖，不触发 50 条淘汰
			out = append(out, r)
		}
	}
	if len(out) > MaxValuationRecords {
		out = out[:MaxValuationRecords] // 淘汰 createdAt 最早的一条
	}
	out = dedupeSortTruncate(out) // 归一化排序 + 去重 + 截断（幂等）

	if err := s.saveLocked(out); err != nil {
		return nil, err // 不提交任何变更
	}
	return out, nil
}

func (s *ValuationHistoryStore) Delete(code string) ([]model.ValuationRecord, error) {
	s.mu.Lock()
	defer s.mu.Unlock()

	items := s.loadLocked()
	out := make([]model.ValuationRecord, 0, len(items))
	changed := false
	for _, r := range items {
		if r.Code == code {
			changed = true
			continue
		}
		out = append(out, r)
	}
	if !changed {
		return items, nil // 幂等：不存在即无操作，不写盘
	}
	if err := s.saveLocked(out); err != nil {
		return nil, err
	}
	return out, nil
}

func (s *ValuationHistoryStore) Clear() ([]model.ValuationRecord, error) {
	s.mu.Lock()
	defer s.mu.Unlock()

	empty := []model.ValuationRecord{}
	if err := s.saveLocked(empty); err != nil {
		return nil, err
	}
	return empty, nil
}
```

要点：

- 所有公开方法都在**同一次持锁**内完成「读 → 改 → 写」，不存在丢失更新。
- `Upsert` 先置顶、再截断、最后统一排序：覆盖已有公司不会淘汰任何其他记录；新增第 51 家时淘汰最早一条。
- `Delete` 不存在该 code 时直接返回当前列表且不写盘，满足幂等语义。
- `Clear` 即使文件不存在也写一份空信封，确保后续读取稳定。

#### 20.6.5 并发与多进程边界

- 单进程：`sync.Mutex` 串行化全部公开方法；GET 也持锁读，保证不会读到写的一半（rename 本身也保证）。
- 多进程：无文件级锁。两个进程同时写会出现「后写覆盖先写」的丢失更新，但不会产生半截 JSON。文档已声明该限制。
- 读多写少，50 条文件读取成本可忽略，不做缓存。

```js
function applyValuationHistory(items) {
  valuationHistory.value = Array.isArray(items) ? items : [];
  const maxPage = Math.max(1, valHistoryTotalPages.value);
  if (valHistoryPage.value > maxPage) valHistoryPage.value = maxPage;

async function fetchValuationHistory() {
  const seq = ++valHistorySeq;
  valHistoryLoading.value = true;
  try {
    const res = await fetch(VAL_HISTORY_API);
    const json = await readJSON(res);
    if (seq !== valHistorySeq) return { ok: false, stale: true, message: '' };
    if (json.code !== 0) {
      valHistoryError.value = json.message || '加载估值记录失败';
      return { ok: false, message: valHistoryError.value };
    }
    applyValuationHistory(historyItemsOf(json));
    valHistoryError.value = '';
    valHistoryLoaded.value = true;
    return { ok: true, message: '' };
  } catch (e) {
    if (seq !== valHistorySeq) return { ok: false, stale: true, message: '' };
    valHistoryError.value = '暂时无法加载估值记录（' + e.message + '）';
    return { ok: false, message: valHistoryError.value };
  } finally {
    if (seq === valHistorySeq) valHistoryLoading.value = false;
  }
}

async function postValuationRecord(rec) {
  const seq = ++valHistorySeq;
  valHistoryLoading.value = false; // 写请求接管列表状态，避免被它取代的 GET 留下 loading
  try {
    const res = await fetch(VAL_HISTORY_API, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(rec),
    });
    const json = await readJSON(res);
    if (seq !== valHistorySeq) {
      // 已被更新的请求取代：服务端是否成功仍以 code 判断，但不回写本地列表
      return { ok: json.code === 0, stale: true, message: json.message || '' };
    }
    if (json.code !== 0) return { ok: false, message: json.message || '保存失败' };
    applyValuationHistory(historyItemsOf(json));
    valHistoryError.value = '';
    valHistoryLoaded.value = true;
    return { ok: true, message: '' };
  } catch (e) {
    if (seq !== valHistorySeq) return { ok: false, stale: true, message: '' };
    return { ok: false, message: '网络请求失败：' + e.message };
  }
}

async function deleteValuationRecord(cd) {
  const rec = valuationHistory.value.find(x => x.code === cd);
  if (!rec || valHistoryDeleting.value) return;
  valHistoryDeleting.value = cd;
  const seq = ++valHistorySeq;
  valHistoryLoading.value = false;
  try {
    const res = await fetch(`${VAL_HISTORY_API}/${encodeURIComponent(cd)}`, { method: 'DELETE' });
    const json = await readJSON(res);
    if (seq === valHistorySeq) {
      if (json.code === 0) {
        applyValuationHistory(historyItemsOf(json));
        ElementPlus.ElMessage.success('已删除 ' + (rec.name || rec.code) + ' 的估值记录');
      } else {
        ElementPlus.ElMessage.warning('删除失败，请重试');
      }
    }
  } catch (e) {
    if (seq === valHistorySeq) ElementPlus.ElMessage.warning('删除失败，请重试');
  } finally {
    if (valHistoryDeleting.value === cd) valHistoryDeleting.value = '';
  }
}
```

**乱序规则**：每个记录类请求在发起时 `++valHistorySeq`；响应返回时只有 `seq === valHistorySeq` 才允许更新列表/错误态。旧响应一律丢弃（POST 的旧响应仍可按服务端 `code` 判定是否成功，供迁移计数，但不回写列表）。

**loading 归属**：GET 设置 `valHistoryLoading=true`，只有仍是最新序号时在 `finally` 清除；任何写请求发起时立即把 `valHistoryLoading` 置 `false` 并接管列表状态，避免过期 GET 把 loading 卡死。

1. `valHistoryError && valuationHistory.length` → 顶部弱化警告条「刷新失败，显示的是上次加载的记录」+「重试」按钮；列表照常展示。

#### 20.8.6 旧 localStorage 迁移（FR-15）

**读取旧数据**（沿用原 `loadValuationHistory` 逻辑，仅用于迁移）：

```js
function readLegacyValuationHistory() {
  try {
    const text = localStorage.getItem(VAL_HISTORY_KEY);
    if (!text) return [];
    const raw = JSON.parse(text);
    if (!raw || typeof raw !== 'object' || raw.version !== VAL_HISTORY_VERSION
        || !Array.isArray(raw.items)) return [];
    const items = raw.items
      .map(normalizeValuationRecord)
      .filter(Boolean)
      .sort((a, b) => Date.parse(b.createdAt) - Date.parse(a.createdAt));
    const seen = new Set();
    const out = [];
    for (const it of items) {
      if (seen.has(it.code)) continue; // 重复 code 保留最新
      seen.add(it.code);
      out.push(it);
      if (out.length >= 50) break;     // 只迁最新 50 条（服务端上限）
    }
    return out;
  } catch (e) {
    return []; // localStorage 不可用/损坏：无可迁移数据
  }
}
```

**迁移算法**（幂等、可中断重试）：

```js
async function maybeMigrateLegacyValuationHistory() {
  if (valHistoryMigrationRunning) return;
  try {
    if (localStorage.getItem(VAL_HISTORY_MIGRATED_KEY) === '1') return;
  } catch (e) {
    return; // localStorage 不可用，无法迁移
  }

  const legacy = readLegacyValuationHistory(); // createdAt 倒序（新→旧）
  if (!legacy.length) {
    markLegacyMigrationDone(); // 没有旧数据：直接标记，避免每次启动重复检查
    return;
  }

  const existing = new Set(valuationHistory.value.map(r => r.code)); // 当前服务端列表
  const pending = legacy.filter(r => !existing.has(r.code)).reverse(); // 只补缺失，旧→新
  if (!pending.length) {
    markLegacyMigrationDone(); // 服务端已覆盖全部 code：以服务端为准
    return;
  }

  valHistoryMigrationRunning = true;
  let failed = 0;
  for (const record of pending) {
    const { createdAt, ...body } = record; // createdAt 由服务端重新生成
    const r = await postValuationRecord(body);
    if (!r.ok) failed++;                    // stale 但 code=0 视为成功（服务端已保存）
  }
  valHistoryMigrationRunning = false;

  if (failed === 0) {
    markLegacyMigrationDone();
    ElementPlus.ElMessage.success(`已迁移 ${pending.length} 条本机估值记录到服务端`);
  } else {
    // 不写标记；下次页面加载初始化 GET 后只补仍缺失的 code
    ElementPlus.ElMessage.warning(`有 ${failed} 条估值记录迁移失败，将在下次打开时重试`);
  }
}

function markLegacyMigrationDone() {
  try { localStorage.setItem(VAL_HISTORY_MIGRATED_KEY, '1'); } catch (e) {}
}
```

要点：

- **触发**：仅初始化 `GET` 成功后尝试一次（每次页面加载最多一次）；初始化失败则不迁移，下次加载再来。
- **服务端优先**：`existing` 中的 code 直接跳过，不覆盖其他设备较新的记录。
- **顺序**：旧列表是 `createdAt` 倒序，`reverse()` 后从早到晚发送；服务端按写入顺序生成新时间戳，最终顺序与旧列表一致。
- **部分失败**：不写标记，提示剩余数量；下次加载重新 GET 后只补仍缺失的 code，已成功的不会重复按旧值覆盖（因为已存在于服务端列表）。
- **旧数据保留**：**不删除** localStorage 的 `valuationHistory` 键，作为一次性升级备份。
- 迁移期间的 POST 也走 `valHistorySeq`；即使被用户操作取代，服务端保存仍生效，迁移计数按 `code` 判定。
- 迁移完成/无旧数据后写 `valuationHistoryMigrated=1`，之后不再检查。
- `stockSearchHistory` 不迁移、不受影响。

### 20.11 关键决策点 / 待确认项

以下均已按需求文档与既有代码惯例给出推荐，**无阻塞项**；若用户不认可可在开发前调整。

- **D1 存储组件放在哪一层**
  - 推荐：新增叶子包 `internal/store`，`api → store → model`，与 `client` 同级；handler 通过 `NewHandler` 注入。
  - 理由：文件读写/原子写/归一化可独立单测；不污染 handler；不破坏 `service` 纯函数约束。
  - 备选：`internal/api/valuation_history_store.go`（少一个包，但 handler 文件承担 IO，测试并发/损坏恢复需绕 HTTP）。

- **D2 `createdAt` 精度**
  - 推荐：`time.RFC3339`（秒级，`2026-10-17T05:59:12Z`）。同一秒内多条按写入顺序（新在前）稳定排序。
  - 理由：文件可读、与需求示例一致；迁移/快速连续写入的顺序由「置顶 + 稳定排序」保证。
  - 备选：`RFC3339Nano`（毫秒/纳秒），可减少同秒并列，但文件略长、示例不一致。

- **D3 读取失败/损坏的对外表现**
  - 推荐：严格按 FR-13.1，GET 恒返回 `code=0` + 空列表；只记 warning 日志并备份损坏文件。
  - 备选：读取失败返回 `code=1`（会违反当前需求，不采用）。

- **D4 迁移尝试频率**
  - 推荐：每次页面加载、初始化 GET 成功后尝试一次；部分失败后同一次会话不重复，刷新/下次打开再补。
  - 理由：避免抽屉反复打开时重复发请求；与需求「下次打开时重试」一致。
  - 备选：每次成功 GET 都尝试（更激进，但会产生无意义请求）。

- **D5 POST 必填字段**
  - 推荐：仅强制 `code` 为 6 位数字；其余字段缺省/`null` 均接受（前端始终发完整字段）。
  - 理由：需求未列出必填业务字段，记录是快照；宽松口径兼容旧客户端/人工调用。
  - 备选：强制 `model/discountRate/year` 等，需在需求中补充清单。

- **D6 迁移是否发送旧 `createdAt`**
  - 推荐：不发送；服务端按写入顺序生成新时间戳，批次顺序由「旧→新」遍历保证。
  - 理由：FR-4.1/FR-13.2 明确服务端时间为权威；避免旧时间与服务器时钟差异造成排序异常。

**假设（按合理默认执行，不阻塞）**：

- 迁移标记键名沿用需求建议 `valuationHistoryMigrated`；旧数据键 `valuationHistory` 永久保留（本版不清理）。
- 服务端对 `modelName` 也做缺失回填（需求只点名 `market`/`fcfModeName`，属无害增强）。
- 记录接口无鉴权（Q7 已确认）；`-data` 目录创建失败只记日志，读写接口在请求时返回 `code=1`。
- 请求体上限 64 KiB（单条约 0.6–1 KB，远低于上限）。
- 前端对服务端返回条目只做「缺 code / 时间非法则跳过」的防御，不排序/去重/截断。
- `data/` 不提交仓库（`.gitignore` 增加 `/data/`）。
