### 20.1 设计目标与影响面

**目标**

1. 用户主动发起的成功估值（手动「计算估值」、AI「套用到估值」）自动落一条本机持久化快照；搜索带来的自动估值**不记录**。
2. 顶栏常驻「估值记录」入口 + 右侧抽屉，支持卡片式查看、单条删除、二次确认清空。
3. 点击记录按「关抽屉 → 切股 → 重置 → 回填参数 → 自动重算」的固定时序恢复，不修改快照、不新增记录。
4. 切换股票时在**请求发起当下**把「公司估值」卡片全量重置为页面默认值，并用「请求序号 + code 绑定」守卫丢弃旧公司晚到的响应（FR-12）。

**涉及文件与改动点**

**既有行为变更（必须知悉）**

- `fetchValuation()` 新增可选入参 `source`（缺省 `'auto'`）。模板中「计算估值」按钮必须改为 `@click="fetchValuation('manual')"`——**不能**继续写 `@click="fetchValuation"`，否则 Vue 会把原生事件对象当作 `source` 传入（函数内部做了兜底归一化，但仍应显式传参）。

- 其余卡片、接口契约、估值算法均不变。

**风险与边界**

- 纯本地操作，无网络/后端/算法风险；50 条 × 约 0.6–1 KB，远低于 localStorage 配额。
- localStorage 不可用/超限时静默降级为内存态，不阻断任何估值流程。
- 记录是快照，**不监听** `valuation`、行情、年报，不存在被动刷新路径。

### 20.2 总体架构与数据流

全部逻辑位于 `createApp({ setup() { ... } })` 闭包内，沿用现有 Vue 3 组合式 API 风格；不新增模块文件。数据流分两条：

```
【写入】用户主动动作
  计算估值按钮  ──→ fetchValuation('manual') ─┐
  AI 套用到估值 ──→ applyAIValuation() ───────┼─→ fetchValuation('ai') ─┐
  doSearch 自动 ──→ fetchValuation()  ────────┘  ('auto'，不记录)      │
                                                                        ▼
                              ┌──────── 竞态守卫（seq + reqCode）通过后才继续 ────────┐
                              │  valuation.value = json.data                          │
                              │  source !== 'auto' → buildValuationRecord()           │
                              │        → valuationHistory.unshift/覆盖 → save 到 localStorage
                              └───────────────────────────────────────────────────────┘

【读取/回填】
  顶栏入口 → valHistoryOpen = true → 抽屉渲染 valuationHistory
  点击条目 → 关抽屉 → pendingValuationRestore = record → code = record.code → doSearch()
       doSearch: 解析最终 code
                 → loadedCode 存在且 ≠ 新 code ? resetValuationState() : 不重置
                 → pendingValuationRestore.code === 新 code ? applyValuationParams(record)
                 → fetchData/financials/analysis/companyValue + fetchValuation()（auto，不记录）
  删除/清空 → 只改 valuationHistory 与 localStorage，不碰 valuation / 搜索历史
```

**分层理由**：`fetchValuation` 是唯一估值请求入口（`app.js:539`），把「来源标记 + 竞态守卫 + 记录落盘」集中在此，避免在按钮、AI、搜索三处各写一份；`doSearch` 是唯一换股入口（`app.js:591`，所有入口最终都经它），把「重置 + 回填」集中在此，保证时序。

#### 20.3.4 校验与降级规则（FR-4）

`normalizeValuationRecord(raw)` 逐条校验：

1. `raw` 非对象 → 丢弃。
2. `code` 先 `String(...).trim()`，不匹配 `/^\d{6}$/` → 丢弃。
3. `createdAt` 无法 `Date.parse` → 丢弃（时间非法会破坏排序与展示）。
4. 其余字段按「类型不符即置空」修复，不丢弃整条：
   - 数值：`typeof x === 'number' && Number.isFinite(x)`，否则 `null`；`year/stage*Years/fcfYears` 取整（`Math.round`）。
   - 布尔：严格 `x === true`。
   - 字符串：`typeof x === 'string' ? x : ''`；`market` 不在 `sh/sz/bj` 时用 `guessMarket(code)`；`source` 仅 `ai`，其余归一为 `manual`；`fcfModeName` 为空时按 `fcfMode` 从 `valFCFModes` 回填。
5. 加载后：先按 `Date.parse(createdAt)` 倒序排序，再按 `code` 去重（保留排序后的第一条），最后 `slice(0, 50)`。

**localStorage 不可用/写入失败**：`loadValuationHistory()` 与 `saveValuationHistory()` 全部 `try/catch`；写入失败置模块级 `valHistoryPersist = false`，之后不再尝试写入（本次会话仅内存），**不弹任何错误**。读取异常同样置 `false` 并返回空列表。

#### 20.4.2 自定义基期 FCF 的单位口径（易错，必须按此实现）

`valuation.fcf_custom_value` 是**换算成元后的值**（`internal/model/valuation.go:50`、`internal/service/valuation.go:201-202`），而 `fcf_custom_unit` 只是用户当时选择的展示单位。因此：

- **记录中存元值**（按 FR-2 字段来源），同时保留 `fcfCustomUnit`。
- **列表展示**：`显示值 = fcfCustomValue / VAL_FCF_UNIT_FACTOR[fcfCustomUnit]`，再拼 `fcfUnitLabel(unit)`（亿/万/千/元）。直接拿元值拼「亿」会放大 1 亿倍。
- **点击回填**：`valFCFCustomValue = record.fcfCustomValue / VAL_FCF_UNIT_FACTOR[record.fcfCustomUnit]`，因为表单输入框接收的是「所选单位下的数值」。
- 换算系数复用 `app.js:291` 的 `VAL_FCF_UNIT_FACTOR`，不新增常量。

### 20.6 核心实现细节 / 算法

#### 20.6.1 记录触发与来源区分（FR-1）

只有三个调用点：

| 调用点 | 现状 | 改为 | 是否记录 |
| --- | --- | --- | --- |
| 「计算估值」按钮（`app.js:1376`） | `@click="fetchValuation"` | `@click="fetchValuation('manual')"` | 是，`source='manual'` |
| `applyAIValuation`（`app.js:773`） | `fetchValuation()` | `fetchValuation('ai')` | 是，`source='ai'` |
| `doSearch`（`app.js:620`） | `fetchValuation()` | 保持 `fetchValuation()` | 否（缺省 `'auto'`） |

函数内部先做来源归一化，防止事件对象/脏值误入：

```js
const src = (source === 'manual' || source === 'ai') ? source : 'auto';
```

记录写入时机严格为「HTTP 成功 + `code === 0` + 竞态守卫通过 + `valuation.value` 已赋值」之后；本地校验失败、HTTP 异常、JSON 解析失败、业务 `code != 0`、旧请求被丢弃，均不写记录。

```js
function recordValuation(code, name, source, v) {
  if (!v || typeof v !== 'object') return;
  const rec = buildValuationRecord(code, name, source, v);
  if (!rec) return;
  const wasEmpty = valuationHistory.value.length === 0;
  const list = valuationHistory.value.filter(r => r.code !== code); // 同 code 覆盖
  list.unshift(rec);                                                // 置顶
  if (list.length > MAX_VALUATION_RECORDS) list.length = MAX_VALUATION_RECORDS; // 淘汰最早
  valuationHistory.value = list;
  saveValuationHistory();
  maybeShowFirstRecordHint(wasEmpty);
}
```

`buildValuationRecord` 中的数值统一经 `toNum(x) = (typeof x === 'number' && isFinite(x)) ? x : null`；年份/年数 `Math.round`；`createdAt = new Date().toISOString()`；`market = guessMarket(code)`。

**名称快照**（请求发起时，不能用响应时数据）：

```js
function resolveRecordName(code) {
  const s = data.value && data.value.stock;
  if (s && String(s.code) === code && s.name) return s.name;
  const h = history.value.find(x => x.code === code);
  return h && h.name ? h.name : '';
}
```

`doSearch` 自动估值在 `fetchData` 未返回时 `data.value` 可能为空，但自动估值不记录，不影响正确性；手动/AI 发起时当前股票数据已加载。

#### 20.6.2 localStorage 读写、去重、上限（FR-3 / FR-4）

```js
function loadValuationHistory() {
  try {
    const text = localStorage.getItem(VAL_HISTORY_KEY);
    if (!text) return [];
    const raw = JSON.parse(text);
    if (!raw || typeof raw !== 'object' || raw.version !== VAL_HISTORY_VERSION
        || !Array.isArray(raw.items)) return [];
    const items = raw.items
      .map(normalizeValuationRecord)
      .filter(Boolean)
      .sort((a, b) => Date.parse(b.createdAt) - Date.parse(a.createdAt));
    const seen = new Set(), out = [];
    for (const it of items) {
      if (seen.has(it.code)) continue;   // 损坏数据里重复 code：保留最新
      seen.add(it.code);
      out.push(it);
      if (out.length >= MAX_VALUATION_RECORDS) break;
    }
    return out;
  } catch (e) {
    valHistoryPersist = false;           // 隐私模式 / 被禁用 / 被策略拦截
    return [];
  }
}

function saveValuationHistory() {
  if (!valHistoryPersist) return false;
  try {
    localStorage.setItem(VAL_HISTORY_KEY, JSON.stringify({
      version: VAL_HISTORY_VERSION,
      items: valuationHistory.value,
    }));
    return true;
  } catch (e) {
    valHistoryPersist = false;           // 静默降级：仅内存，不弹错误
    return false;
  }
}
```

- 初始化：在 `loadHistory()`（`app.js:973`）之后执行 `valuationHistory.value = loadValuationHistory();` 并读取首次提示标记。
- 每次 `add/remove/clear` 后立即调用 `saveValuationHistory()`；**加载时不回写**。
- 上限淘汰天然成立：列表始终按「新记录 unshift + 加载时倒序」维持 createdAt 倒序，`list.length = 50` 截掉的即最早一条；覆盖已有 code 时先 filter 再 unshift，**不触发淘汰**。

#### 20.6.5 竞态守卫（FR-12.3，核心）

**规则**：每次 `fetchValuation` 调用先 `++valRequestSeq` 并快照 `reqCode`；响应（成功、业务失败、异常）只有在 `seq === valRequestSeq && code.value.trim() === reqCode` 时才允许落地。`valLoading` 只允许「最新序号」的请求关闭（避免用户只改输入框、未触发新请求时 loading 卡死）。

```js
function isCurrentValRequest(seq, reqCode) {
  return seq === valRequestSeq && code.value.trim() === reqCode;
}

async function fetchValuation(source = 'auto') {
  const reqCode = (code.value || '').trim();
  if (!reqCode) return;
  const src = (source === 'manual' || source === 'ai') ? source : 'auto';
  const seq = ++valRequestSeq;                  // ① 任何新请求都使旧请求过期
  const reqName = resolveRecordName(reqCode);   // ② 发起时快照名称

  // 自定义 FCF 本地校验：失败只提示，不发请求，也顺手结束 loading
  if (valFCFMode.value === 'custom') {
    const msg = validateCustomFCF(valFCFCustomValue.value, valFCFCustomUnit.value);
    if (msg) {
      valError.value = msg;
      valuation.value = null;
      valuationCode = '';
      valLoading.value = false;
      return;
    }
  }

  valLoading.value = true;
  valError.value = '';
  try {
    const res = await fetch(url);               // url 构造沿用现有逻辑
    const json = await readJSON(res);
    if (!isCurrentValRequest(seq, reqCode)) return;   // ③ 旧请求：成功/业务失败一律丢弃

    if (json.code !== 0) {
      valError.value = json.message || '估值失败';
      valuation.value = null;
      valuationCode = '';
      return;
    }
    valuation.value = json.data || null;
    valuationCode = json.data ? reqCode : '';         // ④ 记录当前结果归属
    if (src !== 'auto' && json.data) {                // ⑤ 卡片写入后落记录
      recordValuation(reqCode, reqName, src, json.data);
    }
  } catch (e) {
    if (!isCurrentValRequest(seq, reqCode)) return;   // ⑥ 旧请求的异常静默丢弃
    valError.value = '请求失败：' + e.message;
    valuation.value = null;
    valuationCode = '';
  } finally {
    if (seq === valRequestSeq) valLoading.value = false; // ⑦ 仅最新请求可关 loading
  }
}
```

要点：

- `finally` 用 `seq === valRequestSeq`（**不看 code**）：用户只输入未搜索时也能正常结束 loading；若已是旧序号则绝不触碰新请求的 loading。
- 旧请求**不得**写 `valuation`、`valError`、`valLoading`、`recordValuation`，也不弹任何提示。
- 重置先 `valRequestSeq++`，因此从「点击新股票」到「新请求发出」之间若旧响应返回，同样被丢弃。
- 手动「计算估值」与 AI「套用」走同一守卫：被丢弃的旧请求不产生记录。

#### 20.6.6 `doSearch` 集成：重置 → 回填 → 自动计算（FR-7 / FR-12）

```js
async function doSearch() {
  const raw = (code.value || '').trim();
  if (!raw) return;
  if (searchBusy) return;                       // pendingValuationRestore 保留，交由后续调用消费

  const restore = pendingValuationRestore;      // 一次性快照
  pendingValuationRestore = null;

  try {
    searchHint.value = '';
    // ...（现有：非 6 位先检索解析，失败则 return；成功回写 code.value）
    // 现有：aiResult / aiError / aiLoading 清空

    const nextCode = code.value.trim();
    const loadedCode = data.value && data.value.stock ? String(data.value.stock.code) : '';
    // 已加载股票变了，或当前估值结果属于另一只股票（覆盖“旧估值已返回、新股票数据尚未落地”的窗口）
    const changed = (!!loadedCode && loadedCode !== nextCode)
                 || (!!valuationCode && valuationCode !== nextCode);

    if (changed) resetValuationState();         // ★ 请求发起当下重置（FR-12.1）
    if (restore && restore.code === nextCode) {
      applyValuationParams(restore);            // ★ 必须在 fetchValuation 之前
    }

    fetchData(); fetchFinancials(); fetchAnalysis();
    fetchValuation();                           // 缺省 auto，不记录
    fetchCompanyValue();
  } finally {
    searchBusy = false;
  }
}
```

- **首次查询**（`loadedCode === ''` 且 `valuationCode === ''`）不重置：页面初始即默认值。
- **同代码重复查询**：`changed === false`，保留当前参数与结果。
- `valuationCode` 是「当前卡片结果归属」的权威标记（只有成功响应写入、重置/失败清空）。加上它可避免一种残留：A 的估值已返回、但 A 的 `fetchData` 尚未落地（`data.value` 暂为 `null`）时立刻搜索 B，仅凭 `loadedCode` 会漏掉重置，B 数据到达瞬间会短暂显示 A 的估值卡片。
- 检索失败/无命中的早退路径不会走到重置与回填；`restore` 已被消费丢弃（无换股，无需恢复）。
- `applyValuationParams` 必须在 `fetchValuation()` 调用前完成。`fetchValuation` 在第一个 `await` 之前同步读取全部 ref，因此紧随其后的请求一定使用回填后的参数（与 `app.js:759` 既有注释同理）。

边界：若点击记录时恰有搜索在途（`searchBusy === true`），本次 `doSearch` 会在入口早退，`pendingValuationRestore` 保留到下一次 `doSearch`；消费时有 `restore.code === nextCode` 校验，不会误作用到其他股票。该窗口极短（正常搜索不会同时点抽屉），不做额外重试。

```js
function applyValuationParams(r) {
  if (r.model) valModel.value = r.model;
  if (isNum(r.discountRate)) valDiscount.value = r.discountRate;
  if (isNum(r.growthRate)) valG.value = r.growthRate;
  if (isNum(r.stage1Growth)) valG1.value = r.stage1Growth;
  if (isNum(r.stage1Years)) valN1.value = Math.round(r.stage1Years);
  if (isNum(r.stage2Growth)) valG2.value = r.stage2Growth;
  if (isNum(r.stage2Years)) valN2.value = Math.round(r.stage2Years);
  if (isNum(r.terminalGrowth)) valG3.value = r.terminalGrowth;

  if (r.fcfMode) valFCFMode.value = r.fcfMode;
  if (isNum(r.fcfYears)) valFCFYears.value = Math.round(r.fcfYears);
  if (r.fcfMode === 'custom') {
    const unit = r.fcfCustomUnit || 'yi';
    valFCFCustomUnit.value = unit;
    valFCFCustomValue.value = isNum(r.fcfCustomValue)
      ? Math.round((r.fcfCustomValue / (VAL_FCF_UNIT_FACTOR[unit] || 1)) * 100) / 100
      : null;
  }
  valAdjustRD.value = r.adjustRD === true;
}
```

- 记录中 `null`/缺省的字段不写入，保留重置后的默认值（模型无关参数本就不参与计算）。
- 同代码点击时没有重置，`null` 字段保留用户当前值；这与「以记录参数为准」的可见字段（模型、折现率、FCF 模式、年数、研发开关）不冲突。
- 重算失败沿用 `valError` 提示，记录不受影响。

#### 20.6.8 展示格式化（FR-6）

```js
function fmtRecordTime(iso) {
  const d = new Date(iso);
  if (isNaN(d.getTime())) return '—';
  const p = n => String(n).padStart(2, '0');
  return `${d.getFullYear()}-${p(d.getMonth() + 1)}-${p(d.getDate())} `
       + `${p(d.getHours())}:${p(d.getMinutes())}`;       // 本地时间，不用相对时间
}

function fmtRecordPerShare(v) {
  return (typeof v === 'number' && isFinite(v) && v > 0) ? v.toFixed(2) + ' 元' : '—';
}

function recordModelName(r) {
  if (r.modelName) return r.modelName;
  const m = valModels.find(x => x.key === r.model);
  return m ? m.label : '';
}

function recordParamSummary(r) {
  const parts = [];
  if (recordModelName(r)) parts.push(recordModelName(r));
  if (isNum(r.discountRate)) parts.push('折现率 ' + fmtNum(r.discountRate) + '%');

  let fcf;
  if (r.fcfMode === 'custom') {
    const unit = r.fcfCustomUnit || 'yuan';
    const shown = isNum(r.fcfCustomValue)
      ? Math.round((r.fcfCustomValue / (VAL_FCF_UNIT_FACTOR[unit] || 1)) * 100) / 100 : null;
    fcf = '基期FCF 自定义 ' + (shown == null ? '—' : fmtNum(shown)) + fcfUnitLabel(unit);
  } else {
    fcf = '基期FCF ' + (r.fcfModeName || '—')
        + (r.fcfYears ? '（' + r.fcfYears + '年）' : '');
  }
  parts.push(fcf);

  if (isNum(r.year)) parts.push('基期 ' + r.year + ' 年报');
  if (r.adjustRD) parts.push('研发调整');
  return parts.join(' · ');
}
```

- 金额（股权价值/公司价值等）一律 `fmtYi`（`app.js:57`）；折现率/增长率用 `fmtNum`（`app.js:712`）。
- 每股值 `> 0` 才展示；为 0/null 时主结果位突出「股权价值」。
- 参数摘要固定顺序：模型名 → 折现率 → 基期 FCF（含年数/自定义单位）→ 基期年 → 研发调整。

### 20.10 关键决策点 / 待确认项

以下均已按需求文档与既有代码惯例给出推荐，**无阻塞项**；若用户不认可可在开发前调整。

- **D1「首次记录提示」的“只提示一次”边界（唯一需要拍板的小口径）**
  - 推荐：用一个独立 localStorage 标记 `valuationHistoryHintShown`，**清空全部后不重置**，即每浏览器/每 origin 一生只提示一次。
  - 理由：需求原文「用一个本地标记确保只提示一次；之后依靠顶栏徽标数量变化提供反馈」。若清空后再次提示，会与“只提示一次”冲突；且徽标已能提供反馈。
  - 备选：清空时一并删除该标记（每次“空列表后的第一条”都提示）。代价是多一次打扰。

- **D2 竞态守卫中的“当前代码”取 `code.value` 还是 `data.stock.code`**
  - 推荐：`code.value.trim()`（需求 FR-12.3 原文「当前代码已变化」；输入框是用户意图的最新表达）。
  - 理由：序号已能覆盖“发起新请求”的场景，code 比较用于覆盖“只改输入未搜索”的情况；实现简单、无歧义。
  - 备选：`data.value.stock.code`（只认已加载股票）。会在“输入已改但未搜索”时让旧响应继续落地，不如推荐方案严格。

- **D3 记录中自定义 FCF 存元值还是存输入值**
  - 推荐：按需求 FR-2 存接口返回的**元值**，展示/回填时用 `fcfCustomUnit` 反算（20.4.2）。理由：与接口字段一一对应，未来切后端存储时无需改结构；代价是两处展示必须做单位换算，已在设计中固定。
  - 备选：直接存输入值 + 单位（展示更直观，但与接口字段语义不一致，迁移时需换算）。

- **D4 抽屉尺寸实现方式**
  - 推荐：`valHistoryDrawerSize` 响应式 ref（`<=768px ? '100%' : '420px'`），在初始化、打开、resize 时同步；不依赖 `el-drawer` 的 class 落点。
  - 备选：纯 CSS 媒体查询覆盖 `.el-drawer` 宽度，需 `!important` 且依赖 class 落点，稳定性较差。

- **D5 错误提示的保留**
  - 推荐：单条删除给 `ElMessage.success` 轻提示；清空成功不额外提示（空态即反馈）；localStorage 失败始终静默。与 FR-8/FR-9/FR-4 一致。

**假设（按合理默认执行，不阻塞）**：记录加载时对重复 code 保留 `createdAt` 最新的一条；`createdAt` 非法的条目直接丢弃；记录条数徽标显示实际条数（≤50）；抽屉关闭后焦点回到顶栏入口。
