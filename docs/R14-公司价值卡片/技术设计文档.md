# R14 技术方案：公司价值卡片（独立卡片）

> 需求文档：`docs/R14-公司价值卡片/需求文档.md`（已定稿，2026-10-11）。
> 一句话：新增一张**独立卡片**「公司价值」（与「财务指标分析」卡片并列，非第 7 个 Tab），逐年展示三个量——**经营资产自由现金流 / 金融资产价值 / 长期股权投资价值**，自带年份范围选择，`higher_better`/`neutral` 趋势信号灯 + 同比，**零新增外部数据源**。

### 18.1 设计目标与影响面

**目标**：把「公司估值」中只输出**单点**的三个组成量的**账面/流量原始值**，组织成**逐年列表**，供观察逐年变化；口径与估值模块同源，不新增任何外部拉取，不改动现有六维分析与估值模块。

**影响面（文件清单）**

| 文件 | 改动性质 | 说明 |
| --- | --- | --- |
| `internal/model/analysis.go` | 新增 | 新增 `CompanyValue` 结构体（复用 `AnalysisIndicator`） |
| `internal/service/company_value.go` | **新增文件** | `ComputeCompanyValue` 纯函数 |
| `internal/service/trend_signal.go` | 改动 | 抽出 `applyTrendSignalsToIndicators` 供复用；`indicatorDirections` 增 `operating_fcf: higher_better`（67→68） |
| `internal/api/handler.go` | 改动 | 新增 `GetCompanyValue`（复用 `fetchAnalysisReports`） |

| `internal/web/app.js` | 改动 | 新增「公司价值」卡片、refs、`fetchCompanyValue`/`changeCvRange`、`doSearch` 触发、setup 导出 |

### 18.2 总体架构与接口形态

**分层**（沿用单向依赖）：

```
前端「公司价值」卡片
  └─ GET /api/stock/:code/company-value?startYear=&endYear=
        └─ api.Handler.GetCompanyValue
              ├─ api.fetchAnalysisReports(code, cfPageSize, bsPageSize)   ← 复用既有并发拉取（3 张 F10 全量报表）
              └─ service.ComputeCompanyValue(balance, cashflow, income, startYear, endYear)  ← 纯函数，无 IO
                    ├─ operatingFreeCashFlow(cf)           ← 复用估值口径（valuation.go）
                    ├─ financialAssets(balance)             ← 复用资产资本维度重分类（analysis.go:1592）
                    ├─ longEquityInvest(balance)            ← 复用（analysis.go:536）
                    └─ applyTrendSignalsToIndicators(...)   ← 复用 R9 趋势信号（trend_signal.go）
```

**接口形态决策：新增独立接口，不复用 `/analysis`**（推荐，采用）。

- **理由 1（独立性）**：需求要求卡片**自带年份范围**、与六维筛选**相互独立**。独立接口可携带独立 `startYear/endYear`、独立 loading/error 状态，前端不需在 `/analysis` 上再挂一套 `cv_startYear/cv_endYear` 参数，避免把两张卡片的筛选耦合到同一响应、也避免改公司价值范围时连带重算六维。
- **理由 2（兼容性）**：`/analysis` 响应结构零改动，兼容性最强；新接口失败不影响六维卡片。
- **理由 3（无新数据源）**：handler **直接复用 `fetchAnalysisReports`**（`handler.go:196`），打的是与六维分析**完全相同**的 3 个 F10 端点（`RPT_F10_FINANCE_GCASHFLOW/GBALANCE/GINCOME`），**不新增任何数据源**、不新增取数函数。
- **代价（风险 R1）**：`doSearch` 时 `/analysis` 与 `/company-value` 会各拉一遍同样的 3 张报表（本项目既有模式即「每张卡片各自拉数」——`fetchFinancials`/`fetchAnalysis`/`fetchValuation` 现有已各拉一组，共 9 次）。新卡片使其增至 12 次。**此为既有架构的固有冗余，非本需求引入的新模式**；若需消除，见 18.10「待确认 R1」的进程内缓存选项（本期不默认做）。

### 18.3 数据模型（`internal/model/analysis.go` 新增）

复用既有 `AnalysisIndicator`（含 `Key/Name/Values []*float64/Unit/Kind/Interpretation/Note/Direction/TrendSignal/TrendRate`），新增卡片级容器：

```go
// CompanyValue 公司价值卡片（独立于六维分析）：三个逐年指标 + 卡片级口径提示。
// Years 与 Indicators[].Values 对齐（升序，nil=无数据，前端显示「—」）。
// Status：done=已实现且有年报数据；no_data=无年报数据。
type CompanyValue struct {
    Years      []int               `json:"years"`
    Status     string              `json:"status"`               // done / no_data
    Indicators []AnalysisIndicator `json:"indicators"`           // 恰 3 项，顺序固定
    Notes      []string            `json:"notes,omitempty"`      // 卡片级口径提示（流量/存量不可加）
}
```

**字段口径与约定**

- `unit` 三者均为 `"元"`（前端 `fmtAnalysisVal` 走 `fmtYi` 亿/万格式化，保留 2 位小数）。
- `kind` 三者均留空（无子项/合计层级；**无合计行**，见 FR-3）。
- `Direction` 不设 `omitempty`（与 `AnalysisIndicator` 既有约定一致，后端恒回填）。
- 三指标 key（**新增，避免与资产资本维度同名 key 混淆**）：
  1. `operating_fcf`（经营资产自由现金流）
  2. `financial_assets_value`（金融资产价值）
  3. `long_equity_value`（长期股权投资价值）

**omitempty 约定**：`Status`、`Indicators` 恒定输出（无 omitempty）；`Notes` 用 `omitempty`（无提示时省略）。

### 18.4 数据源与字段映射（无新增字段）

全部复用既有实测字段，**本卡片不引入任何新东财字段**：

| 指标 | 复用函数 | 关键字段（均已实测核对） |
| --- | --- | --- |
| 经营资产自由现金流 | `operatingFreeCashFlow(cf)` → `maintenanceCapex(cf)`（R23） | 现金流表 `NETCASH_OPERATE`、`FA_IR_DEPR`、`USERIGHT_ASSET_AMORTIZE`、`IA_AMORTIZE`、`LPE_AMORTIZE`、`ASSET_IMPAIRMENT`（资产减值准备，nil 按 0）、`FA_SCRAP_LOSS`；**不依赖利润表**（`DISPOSAL_LONGASSET_LOSS` 与利润表减值 R23 起不参与） |
| 金融资产价值 | `financialAssets`（`analysis.go:1592`） | 资产负债表 19 科目（`financialAssetFields`，`analysis.go:27`，含 `TRADE_FINASSET_NOTFVTPL`、`LEND_FUND` 等），`sum0Fields` 求和、nil 计 0 |
| 长期股权投资价值 | `longEquityInvest`（`analysis.go:536`） | 资产负债表 `LONG_EQUITY_INVEST`（账面价值） |

单位口径：三者均为「元」（原始值，负值原样保留）。

### 18.5 接口 / API 设计

**路由**（`router.go` 新增，紧随 `/analysis` 之后）：

```go

```

**请求**：`GET /api/stock/:code/company-value?startYear=2020&endYear=2024`

### 18.6 服务层实现与复用（新增 `internal/service/company_value.go`）

```go
// ComputeCompanyValue 计算「公司价值」卡片三指标逐年值（纯函数，无 IO）。
// 年份由现金流量表年报年份派生（与 ComputeAnalysis 一致），再按 [startYear,endYear] 截取。
func ComputeCompanyValue(balance, cashflow, income []model.ReportRow, startYear, endYear int) model.CompanyValue
```

**逐年计算口径**

```
balanceByYear, _ := annualRows(balance)
cfByYear, cfYears := annualRows(cashflow)
incomeByYear, _ := annualRows(income)
years := yearRange(cfYears, startYear, endYear)      // 复用 analysis.go:131

for each y in years:
    # 1) 经营资产自由现金流：恒可算（年份来自现金流表）
    fcf = operatingFreeCashFlow(incomeByYear[y], cfByYear[y])   // 复用 valuation.go:396
    #   利润表缺失 → incomeByYear[y] 为零值行 → 减值项计 0，FCF 仍计算（FR-6）

    # 2) 金融资产价值 / 3) 长期股权投资价值：整年资产负债表缺失 → nil（不得为 0，FR-6）
    b, ok := balanceByYear[y]
    if ok { finVal[i] = fp(financialAssets(b)); longVal[i] = fp(longEquityInvest(b)) }
    else  { finVal[i] = nil;                longVal[i] = nil }
```

**要点与边界**

- **复用而非重写**：`operatingFreeCashFlow`（`valuation.go:396`）、`financialAssets`（`analysis.go:1592`）、`longEquityInvest`（`analysis.go:536`）均为**包内未导出函数**，同包 `service` 直接调用，无需导出或搬迁；`annualRows`/`yearRange`/`fp`/`v0`/`joinYears` 同样直接复用。**不抽公共层、不去重**。
- **「整年缺失 vs 科目缺失」区分（FR-6 关键）**：用 `_, ok := balanceByYear[y]` 判定「整张表缺」，缺 → `nil`（前端「—」）；表在但科目缺 → `financialAssets`/`longEquityInvest` 内部 `sum0Fields`/`v0` 已把 nil 视为 0（= 0，合法值）。
- **指标恒构造**：无论 `years` 是否为空，都构造 3 个指标（`Values` 长度为 0 时空切片），保证「未纳入年份范围/无数据」时 key 仍稳定产出（供 18.9 的 key 覆盖断言）。
- **status**：`len(years)==0` → `"no_data"`，否则 `"done"`。
- **自由现金流缺失年份提示**：R23 起 FCF 只依赖现金流量表，利润表缺失不影响计算，原 `missingIncomeNote` 及 `operating_fcf.Note` 已删除。
- **研发调整**：**不叠加**（需求已决 Q5）——直接用报表口径 `operatingFreeCashFlow`，不调用 `rdExpansion`。
- **无合计行**（需求已决 Q3）：卡片级 `Notes` 追加一条「流量与存量不可直接相加，故不设合计行」提示。

**指标构造**（`ind` 复用，`analysis.go:1851`）：

| key | name | unit | kind | interpretation（tooltip 文案，要点） |
| --- | --- | --- | --- | --- |
| `operating_fcf` | 经营资产自由现金流 | 元 | "" | 经营活动现金流量净额 − 保全性资本支出（与财务指标分析同口径）；年度流量，可为负，不与存量相加 |
| `financial_assets_value` | 金融资产价值 | 元 | "" | 资产负债表重分类金融资产账面合计，与资产资本维度「金融资产」同源同值 |
| `long_equity_value` | 长期股权投资价值 | 元 | "" | 资产负债表「长期股权投资」账面价值（账面口径，非估值模块的收益资本化值） |

### 18.7 趋势信号接入（`trend_signal.go`）

**方向映射**：仅新增 1 条 `"operating_fcf": dirHigherBetter`（`indicatorDirections`，`trend_signal.go:29`，67→68 条）。`financial_assets_value`/`long_equity_value` **不写入映射表**——按项目兜底约定（`IndicatorDirection` 未命中 → `dirNeutral`，`trend_signal.go:103`）即为 `neutral`，无需显式条目。

**回填逻辑复用（小重构，行为不变）**：把 `applyTrendSignals`（`trend_signal.go:212`）的内层循环抽为：

```go
// applyTrendSignalsToIndicators 回填一列指标的 direction / trend_signal / trend_rate。
// status 非 "done" 时只回填方向、不算趋势（与既有语义一致）。
func applyTrendSignalsToIndicators(items []model.AnalysisIndicator, status string) {
    for i := range items {
        it := &items[i]
        it.Direction = IndicatorDirection(it.Key)
        if status != "done" { continue }
        t, rate, ok := trendOf(it.Values)
        it.TrendSignal = signalOf(t, it.Direction)
        if ok { pct := rate * 100; it.TrendRate = &pct }
    }
}
```

`applyTrendSignals` 改为对每个维度调用该函数（**输出逐字节不变**，既有单测直接回归）；`ComputeCompanyValue` 对 `CompanyValue.Indicators` 调用同一函数（`status="done"`）。

**信号语义**：自由现金流 `higher_better` → 上行绿点/下行红点；金融资产价值、长期股权投资价值 `neutral` → 恒灰点（不出向好/走弱信号），与需求 FR-7 一致。

### 18.9 测试与验证

**Go 单测（新增 `internal/service/company_value_test.go`）** — 直接测纯函数 `ComputeCompanyValue`（表驱动，构造 `rowWith` 合成三张表）：

| 用例 | 输入要点 | 断言 |
| --- | --- | --- |
| 三指标基本值 | 2020–2024 五年，现金流/资产负债/利润表齐全 | `len(Indicators)==3`、key 顺序 `operating_fcf/financial_assets_value/long_equity_value`、`unit=="元"`、`status=="done"`、`years` 升序对齐 |
| FCF 口径 | 已知 `NETCASH_OPERATE` 与折旧/摊销/减值 | `operating_fcf` 值 == `NETCASH_OPERATE − capex`（逐项核） |
| 金融资产与资产资本一致 | 同一 row 调 `ComputeAnalysis` 资产资本维度 | `financial_assets_value[y]` == 维度三 `financial_assets` 该年值 |
| 长投一致 | 同上 | `long_equity_value[y]` == 维度三 `long_equity_invest` 该年值 |
| 整年资产负债表缺失 | 某年 balance 无该年行，但其在现金流年份内 | 该年 `financial_assets_value`/`long_equity_value` 为 **nil**（非 0） |

### 18.10 关键决策点 / 待确认项

1. **R1 双份 F10 拉取（独立接口的代价）**。推荐**独立接口 + 复用 `fetchAnalysisReports`**（本期采用）：理由见 18.2。代价是 `doSearch` 时公司价值卡片与六维分析各自拉一遍同样的 3 张报表。**可选优化（待用户拍板，本期不做）**：在 `Handler` 内加一个按 `code` 键、短 TTL（如 60s）的进程内报表缓存，供 `/analysis` 与 `/company-value` 共享，消除重复拉取并降低冷启动耗时；代价是引入可变状态与缓存失效复杂度（且需处理并发 singleflight，标准库需手写 map+mutex）。**默认不加**，保持无状态。
2. **R2 指标 key 命名**。推荐**新 key**（`operating_fcf`/`financial_assets_value`/`long_equity_value`），与资产资本维度既有 `financial_assets`/`long_equity_invest` 区分，避免「同 key 跨卡片复用」在 golden 测试与语义上的歧义。若用户偏好复用 `financial_assets`/`long_equity_invest`，也可（两者皆 `neutral`，方向不冲突），但会弱化「卡片归属」的表达，**不推荐**。
3. **R3 长期股权投资价值取账面 vs 收益资本化（需求已决 Q2，取账面）**。副作用：本卡片「长期股权投资价值」与估值卡片同名但**不同值**（后者 = 账面 × 长投收益率 ÷ 折现率）。已通过 `interpretation` tooltip 明示「账面口径，非估值模块的收益资本化值」，并列入需求「数值重叠属预期」。**维持**。
4. **R4 年份来源口径**。年份由**现金流量表**年报年份派生（与 `ComputeAnalysis` 一致，需求 FR-6 认可）。副作用：若某年资产负债表有、现金流量表无，则该年整体不出现（其金融资产/长投也不展示）。**维持**（与六维分析一致，避免两卡片年份列错位）。
5. **R5 默认年份范围「最近 5 个年报」**。复用 handler 既有缺省口径（`endYear=最近年报年`、`startYear=endYear-4`，与 `/analysis` 相同）。**维持**。
6. **R6 本卡片不提供趋势图弹窗**。需求 FR-2 只要求「并列展示 3 行 × 年份列 + 解读 tooltip + 同比」，未要求趋势图；故不渲染 `chart-btn`/`showIndicatorChart`，保持最小改动。若后续需要，可直接复用既有弹窗组件。
7. **R7 `Notes` 文案定稿**。卡片级「流量与存量不可直接相加，故不设合计行」+ 指标级「某年利润表缺失，未扣减值损失，自由现金流可能偏高」。文案以需求 FR-3/FR-6 为准，实现时如需微调以不改变语义为前提。
