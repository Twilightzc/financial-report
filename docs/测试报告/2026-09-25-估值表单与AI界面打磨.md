### 3.2 逐条重点验证

**① 主题 B：`rdAdjustSuggestion` 阈值与边界（12.4/12.5）—— 通过**

- 严格大于：`50/1000`（恰 5%）→ `false`；`49/1000`（4.9%）→ `false`；`51/1000`（5.1%）→ `true`。经验证 `rdAdjustThreshold*100 == 5.0` 且 `50/1000*100 == 5.0`，边界在浮点上精确、可断言。
- 取「利润表末位年报」而非三表 `latestYear`：**独立构造反例验证**——资产负债表/现金流表年报年份为 2025、利润表为 2024（研发费用率 8%），结果 `AdjustRD=true`、`RDRatio=8`。若误用 `latestYear=2025`，`incomeByYear[2025]` 是零值行 → `RESEARCH_EXPENSE` 缺失 → 会误判 `false`。实现取利润表年份切片末位，正确。
- 季报过滤：`2024-12-31`（3%）+ `2025-03-31`（50%）→ `false`、ratio 3（季报被 `annualRows` 过滤）。
- 行序无关：输入行倒序（真实接口按 `REPORT_DATE` 倒序返回）与升序结果一致（`annualRows` 内部排序）。
- 缺失语义三分：键不存在 / 值显式 `nil` / `Fields==nil` → `(false, nil)`；研发费用**显式 0** → `(false, 0)`（非 nil，参与判定但不触发）。
- 营收边界：`0` / `-100` → `(false, nil)`；`0.001`（极小正数）→ 正常判定（100% → true），未把极小数误当无效。
- 空年份切片 + 非空 map → 长度守卫先行拦下，不 panic。
- 确定性：同一报表 6 次调用 `AdjustRD`/`RDRatio` 逐字段一致（`-race` 下亦通过）。

**② JSON 契约 —— 通过**

- `^adjust_rd` 恒输出：`map[string]json.RawMessage` 键存在性断言，`true` / `false` / 0 值三种情形下键均出现且类型为 `bool`；`"adjust_rd":false` 字面量亦直接断言。

- 覆盖语义：大模型即便返回 `valuation{adjust_rd:false, rd_ratio:1.5}` 也被确定性值覆盖；`rationale` 保留大模型原文。
- 提示词未改：`BuildAIPrompt`/`valuationPromptBlock` 无 diff；`ai_test.go` 的 user 消息断言全绿（未新增研发调整相关文本，符合设计 12.5 ④）。

## 4. 遗留问题与风险

### 4.1 发现的问题（1 项，低危，未修复 —— 本会话 `coder` 不可达）

**问题 1（低危，主题 A / FR-1）：`--val-input-w: 120px` 未触发设计自定的兜底升级，文本可视区仅 36px（设计估算 46px），最宽合法取值余量为 1.0–1.3px**

- 定位：`internal/web/style.css` `.val-form { --val-input-w: 120px }`（R4 估值段）。
- 实测依据（权威来源，非推测）：`element-plus@2.7.0/dist/index.css` 中 `.el-input-number .el-input__wrapper{padding-left:42px;padding-right:42px}` —— 控件左右各占 42px，故文本区 = 宽度 − 84px：**90px → 6px**（旧年数框，与「只看到个 1」现象吻合）、**110px → 26px**（旧百分比框，与「偏紧」吻合）、**120px → 36px**（现状）、130px → 46px。
- 期望 vs 实际：设计 12.7 明确要求「实现后量一次 `.el-input-number .el-input__wrapper` 的 padding；**若文本区实测 < 40px，按 12.11 #12 的兜底顺序处理（120 → 130px）**」。实测 36px < 40px → 兜底条件已满足，但实现仍是 120px。根因是设计 12.7 的假设「两侧控件 + 内边距合计约占 74px」偏低 10px（真实 84px）。
- 影响量化（fontTools 按 14px 精算最宽合法取值 `100.0`，折现率/增长率 max=100 且 `precision=1` 时实际可显示 5 字符）：

  | 字体 | `100.0` | `-50.0` | `50` | 是否容纳于 36px |
  | --- | --- | --- | --- | --- |
  | SF Pro Text（macOS `-apple-system`） | 34.69px | 34.18px | 16.68px | 勉强（余 1.3px） |
  | Helvetica / Arial（近似 Segoe UI） | 35.03px | 31.91px | 15.57px | 勉强（余 1.0px） |
  | Hiragino Sans GB（本项目字体栈内） | 37.07px | 33.21px | 16.99px | **裁切 ~1.1px** |
  | Verdana（偏宽 sans 参照） | 40.69px | 38.15px | 17.80px | **裁切 ~4.7px** |

  即：**在 macOS/Windows 主流字体栈下 FR-1 成立（余量 1.0–1.3px），但零容忍**；换字体（项目字体栈已含 Hiragino Sans GB）即裁切小数点后一位，与 FR-1「小数点不得被裁切」相抵触。
- 建议：按设计 12.11 #12 将 `--val-input-w` 调至 **130px**（文本区 46px，余量约 11px）。安全性设计已预先核算：320px 视口单列字段内容 = 92+8+130+8+12 = **250px ≤ 262px**，不横向溢出，`max-width` 兜底逻辑与模板均无需改动 —— 仅 1 个 CSS token。
- 状态：本会话 `SendMessage` 返回 `No agent named 'coder' is reachable`，已整理为可复现清单交回主对话；**未修复**。若维持 120px，则记为「设计兜底条件已触发但实现选择不升级」的待确认取舍，不阻塞其余结论（主题 B/C 与 FR-2/FR-3/FR-4 全部通过）。

### 4.2 非缺陷的观察项

1. **`rd_ratio` 展示取整与判定口径的窄带不一致（设计 12.11 #13 已明确取舍）**：判定用未取整比率、展示取整 2 位。研发费用率落在 (5.000%, 5.005%) 时 `adjust_rd=true` 但文案显示「研发费用率 5%」，读者可能疑惑「5% 也触发？」。真实样本（宁德 5.23%、中芯 8.20%）不受影响；属可接受取舍，若要消除可把该字段精度提到 3 位或对文案改用「>5%」表述。
2. **设计文档 12.9 期望输出表最后一行为笔误**：`经营活动现金流量净额` 标注为 4|6 折行，与同节规则「无后缀时中点折行」自相矛盾（该名 10 字，中点应为 5|5）。代码按规范实现为 5|5；建议同步修正文档该行示例，避免后来者按字面反推规则。仅文档问题，无代码影响。
3. **`RDRatio` 用 `float64 + omitempty`（coder 上报分歧 1）**：与设计 12.3 表格「0 值省略（无法判定 / 研发费用恰为 0）」完全一致，且 `adjust_rd` 恒输出不受影响 —— 已用三种情形断言确认，**不是缺陷**。
