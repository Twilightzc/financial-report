### 3.4 发现的问题（2 项，均低危，未修复）

**问题 1（低危）：`base_growth` 带 `omitempty`，X=0 时前端不显示「基准增速 0%」，与设计 11.9 矛盾**

- 定位：`internal/model/ai.go`（`BaseGrowth float64 \`json:"base_growth,omitempty"\``）+ `internal/web/app.js`（`v-if="aiResult.valuation.base_growth != null"`）。
- 实测序列化（X=0）：`{"model":"zero",...,"base_growth_note":"可用同比增速样本不足（需至少 2 个年报且上年为正），基准增速按 0 计，模型退化为零增长"}` —— `base_growth` 字段缺失。
- 触发范围比预期宽：不止「数据不足」，任何三指标同比增速中位数恰为 0 的公司都会命中（构造实测：营业收入三年恒定 → X=0、model=perpetual，前端显示「永续增长模型 / 折现率 9.0% / 永续增长率 4%」+ 一句提到「…同比增速中位数」的说明，却看不到基准增速这个数）。
- 期望：设计 11.9 明确「`base_growth = 0` 时显示『基准增速 0%』并同时显示口径说明」，需求 FR-7 要求「接口返回基准增速 X% … 前端展示该基准增速」。实际 0 值在接口与界面都不可见，客户端也无法区分「0%」与「旧版本无该字段」。
- 建议：去掉 `BaseGrowth` 的 `omitempty`（`volatile`/`warning` 保留 omitempty 语义正确）。仅改前端无法区分 0 与缺失，不推荐。

**问题 2（低危，真实数据复现）：`base_growth_note` 在「各指标可计算年份不连续」时措辞误导**

- 定位：`internal/service/valuation_recommend.go`（note 构造，约 72–77 行）：N 取三指标参与年份的**去重并集数量**，并表述为「近 N 个完整年度（…）」。
- 真实复现（600029 南方航空）：净利润因 2021–2025 上期为负全部跳过，其最近 3 个可计算年份为 2018/2019/2020；营业收入贡献 2023/2024/2025 → 并集 6 年，实际输出：
  `近 6 个完整年度（2018、2019、2020、2023、2024、2025）营业收入 / 净利润 / 经营活动现金流量净额同比增速中位数`
  （参数本身正确，仅文字易被读成「最近 6 个连续年度」。）
- 期望：口径说明应体现「每个指标各取最近 3 个可计算年度」。建议：仅当并集年份恰为数据中最近的连续 N 个年报年份时沿用现文案，否则改为「营业收入 / 净利润 / 经营活动现金流量净额各取最近 3 个可计算年度（…）同比增速中位数」。
- 影响：仅说明文字（`base_growth_note`）；改文案需同步调整 `valuation_recommend_test.go` 的前缀断言（常规场景文案不变则无需调整）。

## 4. 遗留问题与风险

### 4.1 未验证项（环境限制，非代码问题）

- **HTTP 端到端未验证**：本会话沙箱**禁止 bind 监听端口**（Go 报 `listen tcp 127.0.0.1:18099: bind: operation not permitted`，Node 报 `listen EPERM`），无法起服务后用 curl 连点 3 次 `/api/stock/600519/ai-analysis` 对比 `valuation`；`dangerouslyDisableSandbox` 在本会话被禁用。因此 **handler + HTTP + DeepSeek 真实调用链路未端到端验证**（handler 串接逻辑仅通过代码核对 + 单元级覆盖函数验证）。
- **真实数据获取方式**：Go 的 macOS 平台证书校验被沙箱阻断（`x509: OSStatus -26276`，设置 `SSL_CERT_FILE`/`GODEBUG` 亦无效），故真实数据用 curl 抓取原始响应后复用 `client.toReportRows` 解析，**未覆盖 `client` 自身的 HTTP 路径**。
- **R6 视觉验收未做**：无头浏览器/真机未运行，验收标准中「320/375/414px 下无文字重叠、无裁切、无横向滚动、横竖屏切换后无残留」属人工核对项；本报告只能证明 option 结构与 CSS 规则符合设计（几何量：窄屏左右边距合计 20px、绘图区占比约 92%）。
- **`Date.now()`/随机性**：`RecommendValuation` 无时间/随机依赖，仅通过代码核对（未做多次跨时间调用）。

### 4.2 已知风险与建议

1. **分档边界对浮点敏感**：X 恰为 20/8 时按设计对**未取整**的 X 判定，浮点误差可能使「精确 20%」落到 19.999…→`two_stage`。属设计取舍（11.5 第 4 步），非缺陷；若希望边界稳健，可考虑改为对「取整后的 X」分档。
2. **亏损/波动公司的解释链条较长**：X% 为三指标（各取最近 3 个可计算年度）合并中位数，亏损公司会出现「净利润样本来自较早年份」（如南航 2018–2020），叠加问题 2 的措辞，用户理解成本偏高；建议前端在 note 旁增加「各指标取最近 3 个可计算年度」的固定副标题。
3. **`warning` 覆盖面**：仅在最新年报基期 FCF ≤ 0 时提示。实测南航套用成功但每股股权价值为 **-131.88 元**（公司价值 < 债务价值），此时无任何提示 —— 不属 R7 设计范围（R4 未报校验错误），但建议后续评估是否对「估算股权价值 ≤ 0」也给出提示。
4. **R2 前端 `fmtYi` 与图表 `fmtAxisValue` 的万/亿阈值不同**（`fmtYi` 用 `|亿|<0.01` → 万；`fmtAxisValue` 用 `|亿|<1` → 万），这是既有差异（`fmtAxisValue` 为 R6 新增、按需求 FR-1 规定），tooltip 用 `fmtYi`、轴刻度用 `fmtAxisValue`，同一数值在不同位置显示口径不同（如 5e6：tooltip `0.05亿`、刻度 `500万`）。与需求/设计一致，记为观察项。

### 4.3 建议后续补测点

- 真机 / DevTools 设备模拟（320/375/414/1440px）视觉核对与横竖屏轮换。
- 有网 + `-apikey` 环境下：同一股票连续 3 次 + 清缓存重来 + 三种分析模式各一次，diff `valuation` 全字段；点「套用到估值」核对 R4 无校验报错。
- 抽查更多特征股票（金融股外的亏损/负增长/高负债样本）核对 `base_growth` 与 `warning` 合理性。
