# R23 估值口径对齐财务指标分析

> 一句话：全项目只保留一套「保全性资本支出」定义；估值链路（DCF、AI 估值关键校验、公司价值卡片）一律复用「财务指标分析（六维分析）」的口径，财务指标分析是唯一权威数据源。

## 1. 背景与目标

### 1.1 背景

系统里存在两个同名但不同义的「保全性资本支出」，导致同一只股票在「财务指标分析」与「AI 估值 / 公司估值」里算出的资本支出、自由现金流（FCF）、FCF/净利润对不上：

| 链路 | 代码位置 | 当前公式 |
| --- | --- | --- |
| 财务指标分析（权威） | `internal/service/analysis.go:1843` `maintenanceCapex(cf)` | `FA_IR_DEPR + IA_AMORTIZE + LPE_AMORTIZE + USERIGHT_ASSET_AMORTIZE + ASSET_IMPAIRMENT + FA_SCRAP_LOSS`（全部取**现金流量表补充资料**，nil 视为 0） |
| 估值链路 | `internal/service/valuation_consistency.go:37` `preservationCapex(income, cf)` | `assetImpairmentLoss(利润表) + creditImpairmentLoss(利润表) + FA_IR_DEPR + USERIGHT_ASSET_AMORTIZE + IA_AMORTIZE + LPE_AMORTIZE + disposalLongAssetLoss(处置长期资产损失，仅计损失) + FA_SCRAP_LOSS` |

同时，「FCF ÷ 净利润」的分母在两条链路也不同：

| 链路 | 当前净利润口径 |
| --- | --- |
| 财务指标分析「净利润现金含量」 | `netProfitReconstructed`（税前利润 − 所得税，**含少数股东损益**），`internal/service/analysis.go:987` |
| 估值「关键校验 FCF/净利润」 | 优先 `PARENT_NETPROFIT`（**归母**）；归母缺失或聚合后 ≤0 时才回落重构净利润，`internal/service/valuation_consistency.go:111-167` |

**实测证据（海康威视 002415，2025 年报，东财原始字段）**：

- 现金流量表补充资料：`FA_IR_DEPR` 16.46 亿、`IA_AMORTIZE` 1.07 亿、`LPE_AMORTIZE` 0.97 亿、`USERIGHT_ASSET_AMORTIZE` 2.05 亿、`ASSET_IMPAIRMENT` 4.37 亿、`FA_SCRAP_LOSS` 0.001 亿 → **财务指标分析口径约 24.91 亿**。
- 旧估值口径再把利润表资产减值损失 4.37 亿、信用减值损失 8.01 亿计入（处置损失为负按 0）→ **约 32.92 亿**。
- 经营活动现金流量净额 253.39 亿 → 旧 FCF 约 220.48 亿，新 FCF 约 228.48 亿，差 8.01 亿（信用减值损失）。
- 同期归母净利润约 141.95 亿；重构净利润（利润总额 − 所得税近似）约 154.3 亿。FCF/净利润由约 **1.55 降为约 1.48**，刚好跨越 1.5 告警阈值。

> 上述金额为东财原始字段直接推算，实际接口取数/重构口径可能有小数级差异，以代码实算为准；数值仅用于说明两套口径的差异量级。

### 1.2 目标

1. **单一数据源**：全项目只保留一套「保全性资本支出」实现，以财务指标分析 `maintenanceCapex` 为唯一权威定义；估值链路不得再写第二套公式。
2. **估值全链路一致**：DCF 公司估值、AI 估值「资本支出覆盖率」分母、「逐年自由现金流」保全列、公司价值卡片，四处的保全性资本支出对同一年度必须完全相等，并与财务指标分析「保全性资本支出」指标相等。
3. **净利润分母一致**：AI 估值「FCF ÷ 净利润」的分母改为重构净利润，与财务指标分析「净利润现金含量」同口径。
4. **不回归既有估值口径**：R19/R20/R21/R22 已定的 WACC、复合锚 A、g1 上限、终值增长率、5×3 敏感性矩阵、模型分类阈值不改变；`FCF = 经营活动现金流量净额 − 保全性资本支出` 的结构不改变。

## 2. 用户故事 / 使用场景

- 作为使用估值功能的投资者，我希望「财务指标分析」里看到的保全性资本支出、FCF，和「AI 估值」「公司估值」里看到的是同一个数，这样我能按同一套口径复算，而不是怀疑哪一处算错了。
- 作为关注利润含金量的投资者，我希望「FCF ÷ 净利润」的分母与「净利润现金含量」一致（都含少数股东损益），这样两个指标能互相印证。
- 作为维护者，我希望同名字段只有一个实现，后续调整口径时只改一处，不会出现两条链路各自演化。

## 3. 功能需求

### FR-1（P0）保全性资本支出只保留一个实现

- 全项目「保全性资本支出」必须只有一处实现：沿用以财务指标分析为准的 `maintenanceCapex(cf model.ReportRow) float64`（`internal/service/analysis.go:1843`）。
- 权威公式固定为：

  ```
  保全性资本支出 =
      固定资产折旧、油气资产折耗、生产性生物资产折旧（FA_IR_DEPR）
    + 无形资产摊销（IA_AMORTIZE）
    + 长期待摊费用摊销（LPE_AMORTIZE）
    + 使用权资产摊销（USERIGHT_ASSET_AMORTIZE）
    + 资产减值准备（ASSET_IMPAIRMENT，现金流量表补充资料）
    + 固定资产报废损失（FA_SCRAP_LOSS）
  ```

- 必须删除估值侧的第二套实现 `preservationCapex(income, cf)` 及其专用辅助 `disposalLongAssetLoss(cf)`；不得以「别名函数 / 包装函数」形式保留第二套公式。
- `assetImpairmentLoss`、`creditImpairmentLoss` 仍保留给财务指标分析的其他指标使用，但**不得**再参与保全性资本支出/FCF 计算。
- 任一科目缺失（nil）按 0 计，与 `maintenanceCapex` 现有行为一致；不得因缺科目改用利润表口径回填。

### FR-2（P0）估值链路全部复用 FR-1 的实现

以下四处必须调用同一个 `maintenanceCapex(cf)`，不得各自取数或各自求和：

1. **经营资产自由现金流**：`operatingFreeCashFlow = NETCASH_OPERATE − maintenanceCapex(cf)`（`valuation.go:517`）。结构不变，只替换减项来源。
2. **AI 估值「资本支出覆盖率」分母**：`capexCoverageDetail` 的分母按窗口逐年 `maintenanceCapex(cf)` 求和（`valuation_consistency.go:72`）。分子仍为 R19 定义的「净资本支出 = `CONSTRUCT_LONG_ASSET` − `DISPOSAL_LONG_ASSET`」。
3. **AI 估值「逐年自由现金流」保全列**：`fcfSeries[].preservation_capex = maintenanceCapex(cf)`（`valuation_recommend.go:394`），并保持 `FCF = operating_cash − preservation_capex`。
4. **公司价值卡片**：`operatingFreeCashFlow` 已复用上述第 1 项，随之一致（`company_value.go:24`）。

间接受影响但无需改公式：DCF 四种模型的经营资产价值（`company_value.go:24`、`valuation.go:162` 等）自动使用新 FCF；FCF 历史增速、周期判定、研发调整建议等也随 FCF 输入变化，属预期结果。

### FR-3（P0）「FCF ÷ 净利润」分母统一为重构净利润

- `fcfProfitDetail` 的分母必须改为 `netProfitReconstructed(income)`（税前利润 − 所得税，含少数股东损益），不再优先取 `PARENT_NETPROFIT`。
- 窗口与聚合方式保持现状：与基期 FCF 使用同一窗口、同一聚合方式（latest / average / median / trim_mean / custom）。自定义 FCF 仍按最新年报校验。
- 删除「归母缺失/聚合后 ≤0 → 回落重构净利润」的分支；聚合后净利润 ≤ 0 时直接判为不可用，原因「净利润≤0」。
- `profit_basis` 字段保留（避免 API 破坏），值固定为 `"reconstructed"`；口径说明文案统一为「重构净利润（含少数股东损益）」。
- 该分母必须与财务指标分析「净利润现金含量」的净利润口径一致；对同一最新年报，`fcf_profit_check.profit` 必须等于财务指标分析该年 `net_profit` 的重构值。

### FR-4（P1）展示与提示文案同步

- `capexCheck.note` 必须说明分母口径与财务指标分析一致，示例：

  ```
  净资本支出（购建−处置收回）/ 保全性资本支出（折旧摊销、资产减值准备、固定资产报废损失，与财务指标分析同口径）；窗口 YYYY–YYYY。
  ```

- `fcfProfitCheck.note` 必须写明分母为「重构净利润（含少数股东损益）」。
- AI 提示词中的「关键校验」行（`internal/service/ai.go:162-168`）同步改为「FCF/净利润（重构口径，含少数股东损益）」；不得再输出「归母净利润」。
- 公司价值卡片中经营资产自由现金流的指标说明由「（估值口径）」改为「（与财务指标分析同口径）」；删除已失效的「利润表缺失 → 未扣减减值损失」提示（`missingIncomeNote`），因为新公式不再依赖利润表。
- 前端无需新增/删除控件或字段；`preservation_capex`、`capex_check.note`、`fcf_profit_check.note` 结构不变，仅文案与数值变化。

### FR-5（P1）数据缺失与边界处理

- `ASSET_IMPAIRMENT` 缺失（nil）按 0；不得回退到利润表 `ASSET_IMPAIRMENT_INCOME` / `CREDIT_IMPAIRMENT_INCOME`，否则口径再次分叉。
- 仅使用年报（报告期以 `12-31` 结尾）；季度/半年报缺少补充资料字段，不参与计算（沿用现有 `annualRows` 过滤）。
- 现金流量表年报缺失的年度不产生 FCF（沿用现有年度交集逻辑）；利润表缺失不再影响 FCF 计算。
- 保全性资本支出合计 ≤ 0 时，资本支出覆盖率仍输出「不适用：保全性资本支出≤0」；FCF 为负/零时 DCF 仍输出「现金流贴现法不适用」。
- 分母净利润 ≤ 0 时，FCF/净利润仍输出「不适用：净利润≤0」。

## 4. 非功能需求

- **一致性**：同一股票、同一年报年度，财务指标分析、AI 估值、DCF、公司价值卡片四处的保全性资本支出必须完全相等（浮点严格相等，均由同一函数产生）。
- **纯函数与确定性**：`maintenanceCapex`、`operatingFreeCashFlow`、`fcfProfitDetail` 保持纯函数，无 IO、无随机、无时间依赖；同一输入重复计算结果一致。
- **性能**：不新增任何外部数据请求；不增加额外报表拉取；计算复杂度不变。
- **兼容性**：不新增/删除 API 端点与查询参数；不改变响应 JSON 字段名与结构；`profit_basis` 字段保留。
- **移动端**：前端展示结构不变，沿用现有响应式布局与 `checkText` 渲染。
- **可追溯**：口径说明文案必须让用户能按「保全性资本支出 = 折旧摊销 + 资产减值准备 + 报废损失」复算，不得再出现「含信用减值/处置损失」的旧描述。

## 5. 边界与约束

- **不做**：不改财务指标分析（R3）的公式、指标标签、展示；不改 FCF 公式结构；不改 WACC/CAPM、复合锚 A、g1 上限、终值增长率、5×3 敏感性矩阵、模型分类与降级规则；不新增数据源。
- **口径差异（有意为之）**：新公式**不含**利润表信用减值损失、处置长期资产损失；这是为与财务指标分析对齐而做的取舍。R4 书籍原文的「减值损失 + 信用减值损失 + 处置损失」仅作为背景说明，不再作为实现依据。
- **数值会变**：所有依赖 FCF 的估值结果（基期 FCF、DCF 经营资产价值、公司/股权价值、AI 关键校验、告警触发与否）都会变化；这是本次需求的预期结果，不属于 bug。
- **间接影响**：FCF 历史增速、周期股判定、研发扩张建议等由 FCF 输入派生的结论可能变化；其算法本身不改，R19/R22 的参数约束继续生效。
- **字段可用性**：`ASSET_IMPAIRMENT` 为现金流量表补充资料科目。实测海康威视 2023–2025 年报有值（4.37 亿等），贵州茅台 2024–2025 年报为空（无资产减值，按 0 合理）。因此不能假设该字段恒可用，nil 必须按 0 处理。
- **历史数据**：R16 历史估值快照、旧 AI 缓存不做迁移或重算。
- **金融股**：DCF 对金融股仍不适用，沿用现有 `isFinancialLike` 判定；本次不处理金融股 FCF 口径。

## 6. 验收标准
