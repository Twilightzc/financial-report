# R7 技术方案：AI 估值模型参数确定性约束

> **「本文『确定性推导』原则仍有效；其估值参数具体规则（风险点得数表→折现率、volatile 单阈值、g1=floor(x/2)、单阈值模型分档）已被 R15 取代，最新口径见 `docs/R15-估值模型参数分析及设定/技术设计文档.md` §19。」**

> 对应需求文档 `docs/R7-AI估值模型参数确定性约束/需求文档.md`。采用已拍板的**方案 A**：估值参数由后端纯函数按财报数据确定性推导，大模型只写 `rationale`。

### 11.1 设计目标与影响面

| 项 | 内容 |
| --- | --- |
| 目标 | 同一股票同一条件下任意次分析的 `valuation.model` / `model_name` / `discount_rate` / `params` **完全一致（差值为 0）**，参数全部落在固定网格；参数可追溯到基准增速 X% |
| 新增文件 | `internal/service/valuation_recommend.go`（确定性推导，纯函数）、`internal/service/valuation_recommend_test.go`（单测） |
| 修改文件 | `internal/model/ai.go`（新增 `ValuationRecommendation` + `AIValuation` 只读字段）、`internal/service/ai.go`（提示词改写、`BuildAIPrompt`/`buildUserMessage` 签名、删除 `normalizeValuation`、新增 `ApplyValuationRecommendation`）、`internal/api/ai.go`（串接推导与覆盖、日志）、`internal/web/app.js`（展示基准增速与提示） |
| 不改动 | R4 估值公式与口径（`internal/service/valuation.go` 全部不动）、五维评分/结论/行业/板块的生成方式、`/api/stock/:code/ai-analysis` 既有响应字段语义、不新增任何数据拉取 |
| 破坏性 | `service.BuildAIPrompt` 函数签名变更（包内 API，调用点仅 handler 与单测）；HTTP 接口只**新增**只读字段，向后兼容 |

非目标（明确不做）：不追求结论/点评/理由文案的逐字一致；不做 LLM 失败时的半成品降级（FR-9，维持现状报错可重试）；金融股仍不支持（沿用 R3/R4 限制）。

### 11.2 总体架构与数据流

新增能力全在 `service` 层（纯函数，无 IO），`api` 层只做串接：

```
GetAIAnalysis（internal/api/ai.go）
  ├─ FetchQuote
  ├─ fetchAnalysisReports → cashflow, balance, income, dividends      （已有）
  ├─ service.ComputeAnalysis(...)                                     （已有）
  ├─ service.RecommendValuation(balance, cashflow, income)            ★新增：确定性估值参数
  ├─ service.BuildAIPrompt(analysis, quote, reasoning, segments, rec)  ★签名扩展：把参数喂给大模型
  ├─ client.NewDeepSeek(...).Chat(system, user)                       （已有）
  ├─ service.ParseAIResult(raw)                                       （已有；删除参数量化）
  └─ service.ApplyValuationRecommendation(&result, rec)               ★新增：覆盖大模型估值字段
```

关键点：`RecommendValuation` 只依赖 `internal/model` 的报表行与 `service` 包内既有口径函数（`revenue`、`netProfitReconstructed`、`interestBearingDebt`、`totalCapital`、`leverage`、`interestCoverage`、`operatingFreeCashFlow` 等），**不需要**六维 `FinancialAnalysis` 结构，也不新增任何字段映射。大模型的输入里带上确定性参数，是为了让 `rationale` 与参数一致（FR-7 边界）。

**确定性来源**：`RecommendValuation` 不接收 `startYear`/`endYear`/`reasoning`。参数只由**财报数据本身**决定（取数据中最近若干完整年度），因此不同年份范围、不同分析模式之间的参数也一致（比 FR-6 的要求更强，同时与 R4「基于最新年报」一致）。

### 11.3 数据模型（`internal/model/ai.go`）

新增确定性推荐结果结构体（不含 `rationale`，`rationale` 仍由大模型产出）：

```go
// ValuationRecommendation 由财报数据确定性推导的估值参数推荐（纯计算结果，无 IO、无随机）。
type ValuationRecommendation struct {
    Model          string             // zero / perpetual / two_stage / three_stage
    ModelName      string             // 中文名（复用 service.valuationModelNames）
    DiscountRate   float64            // 折现率 %（8.0–12.0，0.5 一档）
    Params         []AIValuationParam // 模型对应的增长率/年数参数（zero 为空切片）
    BaseGrowth     float64            // 基准增速 X%（%）
    BaseGrowthNote string             // 基准增速口径说明（FR-7）
    Volatile       bool               // 近三年同比增速极差是否 > 40 个百分点
    RiskPoints     int                // 折现率风险点计数 0–3（可观测用）
    Warning        string             // 套用后估值可能不适用的提示（FR-8）
}
```

`AIValuation` 追加 4 个只读附加字段（`omitempty` 保证旧客户端不因缺字段报错）：

```go
type AIValuation struct {
    Model        string             `json:"model"`
    ModelName    string             `json:"model_name"`
    DiscountRate float64            `json:"discount_rate"`
    Params       []AIValuationParam `json:"params"`
    Rationale    string             `json:"rationale"`

    // R7 新增（服务端确定性回填，只读）
    BaseGrowth     float64 `json:"base_growth,omitempty"`      // 基准增速 X%
    BaseGrowthNote string  `json:"base_growth_note,omitempty"` // 基准增速口径说明
    Volatile       bool    `json:"volatile,omitempty"`         // 是否剧烈波动（g1 按基准增速 50% 取）
    Warning        string  `json:"warning,omitempty"`          // 套用提示（如基期 FCF ≤ 0）
}
```

`Params` 的 `key` 与 `label` 沿用现状（`/valuation` 参数对齐，前端 `applyAIValuation` 按 key 取值）：

> R8 在 `AIValuation` / `ValuationRecommendation` 上各追加 `AdjustRD`（json `adjust_rd`，不加 `omitempty`）与 `RDRatio`（json `rd_ratio`）两个只读字段，详见 12.3；本节其余口径不变。

> **结构体后续已大幅扩展**：R13 追加 `FCF*` 基期推荐字段、R15 追加 `IndustryType`/`Beta`/`WaccBaseline`/`Growth*`/`SGR`/`FCFCyclical`/`BaseYear`/`CapexCoverage` 等只读字段。当前完整字段以 R15 技术设计 §19.3 为准，本节列出的 R7 初始字段仅为历史起点。

| 模型 | params（key / label） |
| --- | --- |
| `zero` | 无（空切片） |
| `perpetual` | `g` / 永续增长率 |
| `two_stage` | `g1` / 高增长期增长率、`n1` / 高增长期年数、`g2` / 永续增长率 |
| `three_stage` | `g1` / 第一阶段增长率、`n1` / 第一阶段年数、`g2` / 第二阶段增长率、`n2` / 第二阶段年数、`g3` / 永续增长率 |

### 11.4 数据源与字段映射（均为既有字段，无新增）

| 用途 | 报表 | 字段 / 口径函数 | 说明 |
| --- | --- | --- | --- |
| 营业收入同比增速 | 利润表 `RPT_F10_FINANCE_GINCOME` | `revenue(income)` = `TOTAL_OPERATE_INCOME` | 与六维分析同一口径 |
| 净利润同比增速 | 利润表 | `netProfitReconstructed(income)` | 六维「净利润」的重构口径（≈报表净利润，含少数股东） |
| 经营现金流同比增速 | 现金流量表 `RPT_F10_FINANCE_GCASHFLOW` | `v0(cf, "NETCASH_OPERATE")` | nil 视为 0 |
| 有息债务占比 | 资产负债表 `RPT_F10_FINANCE_GBALANCE` | `interestBearingDebt(b)` ÷ `totalCapital(b)` × 100 | 与资产资本维度「有息债务占比」同口径 |
| 财务杠杆倍数 | 资产负债表 | `leverage(b)` = `totalCapital(b)` ÷ `equityValue(b)`（`TOTAL_EQUITY`） | 资产资本维度口径（含息债务），**非**综合维度的杜邦口径 `dupontLeverage` |
| 利息保障倍数 | 利润表 | `interestCoverage(income)` = `ebitTotal(income)` ÷ `realFinanceExpense(income)` | `*float64`，真实财务费用 ≤ 0 时为 nil |
| 基期 FCF 提示 | 利润表 + 现金流量表 | `operatingFreeCashFlow(incomeByYear[y], cfByYear[y])` | 与 R4 保全性资本支出口径一致 |

所有函数均为 `internal/service` 包内既有实现，无需实测新字段。

### 11.5 核心实现（`internal/service/valuation_recommend.go`）

对外主函数（纯函数，无 IO/随机/时间依赖）：

```go
func RecommendValuation(balance, cashflow, income []model.ReportRow) model.ValuationRecommendation
```

内部分解为若干可直接单测的小函数（便于逐分支断言）。R15 起内部函数集已演进（`classifyModel`/`growthSamples`/`discountRateFor` 等旧符号已删除，新增 `classifyModelScore`/`sustainableGrowth`/`RecommendBaseFCF`/`detectFCFCycle` 等），最新函数清单见 R15 §19.5~19.8，此处不再罗列旧签名。

**第 1 步：年报索引**

```go
incomeByYear, incomeYears := annualRows(income)
cfByYear, cfYears := annualRows(cashflow)
balanceByYear, balanceYears := annualRows(balance)
```

**第 2–6 步：基准增速 / volatile / 模型分档 / 折现率 / 增长率年数（旧规则，已被 R15 取代，见顶部提示）**

原「三指标合并取中位数求 X%、极差>40pp 判 volatile、单阈值 20/8/0 分档、风险点得数表→折现率、g1=floor(X/2) 砍半、gk/stageYears 反相关映射」等具体推导步骤已被 R15 §19.6~19.8 取代，此处不再保留旧正文。最新口径：

- 基准增速 X%：营收/重构净利润/FCF 三项稳健增速**显式等权**（窗口 5 年，缺项归一化）；
- volatile：样本仅取营收+净利润同比增速、≥3 样本且极差 >40pp（FCF 周期由 R15 P3 单独识别）；
- 模型分档：增速/稳定性/ROE 三信号评分（门槛 70/45/25，硬闸门 12/6/3）；
- 折现率：WACC 基线 + 公司风险溢价，收口到 [8,15] 的 0.5 网格；
- g1：`X × (1 − clamp(离散度×0.004, 0, 0.40))`，并受 `floor(SGR)` 上限约束。

**第 7 步：套用提示（FR-8 异常）**

```
fcf := operatingFreeCashFlow(incomeByYear[yLatest], cfByYear[yLatest])
fcf <= 0 → Warning = 「以最新年报计的基期经营资产自由现金流为负或零，套用后 R4 估值可能提示「现金流贴现法不适用」」
```

对应 R4 默认 `fcf_mode=latest` 的情形；若用户在 R4 表单改过基期选取方式，提示可能不适用（`warning` 文案已限定「可能」）。

**确定性纪律（实现约束）**：不遍历 map 取极值或决定顺序（一律用 `annualRows` 返回的升序年份切片）；所有舍入显式使用 `math.Round`/`math.Floor`；不引用时间、随机数、环境变量。

### 11.6 用确定性结果覆盖大模型返回

新增：

```go
// ApplyValuationRecommendation 用确定性推导结果覆盖大模型返回的估值参数字段，只保留其 rationale。
func ApplyValuationRecommendation(r *model.AIAnalysisResult, rec model.ValuationRecommendation) {
    r.Valuation.Model = rec.Model
    r.Valuation.ModelName = rec.ModelName
    r.Valuation.DiscountRate = rec.DiscountRate
    r.Valuation.Params = rec.Params
    r.Valuation.BaseGrowth = rec.BaseGrowth
    r.Valuation.BaseGrowthNote = rec.BaseGrowthNote
    r.Valuation.Volatile = rec.Volatile
    r.Valuation.Warning = rec.Warning
    // Rationale 保持大模型返回值，不覆盖
}
```

- **覆盖位置选择 handler 层而非 `ParseAIResult` 内部**，理由：`ParseAIResult` 的输入只有大模型文本，而确定性参数来自报表数据，若塞进 `ParseAIResult` 就必须改其签名、把报表透传进解析层，破坏「解析只管文本」的职责；独立函数也让「覆盖」这一步可单测（构造不一致的模型输出，断言最终以后端为准，对应 FR-5 验收项）。
- **删除 `normalizeValuation`**（`internal/service/ai.go`）及其在 `ParseAIResult` 中的调用：模型/折现率/参数已整体被覆盖，保留量化逻辑会误导后来者以为大模型数值仍有效。FR-1 要求的「网格外值必须被吸附」改由**构造保证**（所有取值来自固定集合 + `g1` 的 clamp），并以单测断言（见 11.10）。`ParseAIResult` 其余逻辑（评分容错、维度重排、校验）不变，`math` 包仍用于评分取整。

### 11.7 提示词改写（`internal/service/ai.go`）

**选定方案：大模型不再产出任何估值数值，只产出 `rationale`；同时把后端确定性参数作为「事实」喂进用户消息。**

理由：需求 FR-5/FR-7 要求「rationale 不得与后端参数矛盾」。若仍让模型产出数值（哪怕会被覆盖），模型写理由时依据的是它自己心里的数字，很可能与最终回填的参数冲突；反过来把确定性参数明确告知模型，它才能写出与参数自洽的解释。副作用是提示词更短、token 更省、且彻底移除了「模型选择歧义」在提示词里的残留。

1. `aiSystemFramework` 输出结构里的 `valuation` 示例改为只含理由：

```json
"valuation": {"rationale": "选择理由（2-3 句，只能解释、不能改数）"}
```

2. 用下面这段**替换**原「## 估值模型推荐规则」整节（原 43–53 行那段含 g1 ±3% 微调、`zero 或 two_stage` 二选一等歧义规则，全部删除）：

```markdown
## 估值模型推荐（只解释、不改数）
- 估值参数已由系统按该公司实际财报数据**确定性推导**，并会在用户消息中给出（模型、折现率、各阶段增长率与年数、基准增速 X% 及其口径）。同一家公司每次分析结果完全相同。
- 你的任务**仅为这些参数写 rationale（2-3 句）**：说明为什么该模型合适、该折现率与增长率反映了哪些财务与行业因素（可结合行业前景/竞争格局做定性解释）。
- 硬性要求：rationale 中出现的任何数字必须与给定参数完全一致；**不得**建议或写出其它模型/折现率/增长率取值。
- 输出 JSON 中 valuation 只返回 {"rationale": "..."}；其余字段由系统回填，即使填写也会被忽略。
```

3. `buildUserMessage` 追加一段确定性参数（数据来自 `rec`，措辞随模型变化）：

```markdown
估值参数（系统按实际财报数据确定性推导，请据实解释、不得改动）：
- 基准增速 X：13.20%（近 3 个完整年度「营业收入 / 净利润 / 经营活动现金流量净额」同比增速中位数）
- 模型：两阶段模型（two_stage）；折现率：9.0%
- 参数：高增长期增长率 g1=12%；高增长期年数 n1=6；永续增长率 g2=3%
- 提示：<rec.Warning，无则省略>
```

4. 签名变更：`BuildAIPrompt(a model.FinancialAnalysis, q model.Quote, reasoning string, segments []model.SegmentIncome, rec model.ValuationRecommendation) (system, user string)`；`buildUserMessage` 同步新增 `rec` 入参。system 仍是纯静态框架（不随公司变化），确定性参数只进用户消息，保持既有设计。

### 11.11 R7 关键决策点

1. **「近 3 个完整年度」的锚点 = 数据中最近 3 个可算同比的年报**，与请求的 `startYear`/`endYear` 无关（推荐）。理由：参数只由财报数据决定 → 不同年份范围/不同分析模式之间参数也完全一致（强于 FR-6 要求），且与 R4「基于最新年报」口径一致。备选：锚定请求年份范围的末年（参数会随用户选择变化，但仍可复现）。
2. **X% 的聚合 = 9 个（至多）样本合并后取一次中位数**（推荐，贴合需求原文「取中位数」且抗单年异常）。备选：三个指标各取中位数后再取三项中位数（对单一指标极端波动更稳健，但多一层聚合、解释成本略高）。
3. **极差 > 40pp 的判据作用于同一组合并样本**（推荐，保证唯一解释）。备选：三个指标各自极差取最大值。
4. **折现率映射用 9.0/10.0/11.0/12.0 四档（等距 1%）**，风险点 0–3 一一对应，数据缺失回落 10.0（推荐）。备选：更细的 0.5% 打分表（用满网格，但需要给三个指标分配权重，规则变复杂、更难解释）。
5. **永续增长率 gk 与折现率反相关**（r ≤ 9.0 → 4%；r ≤ 11.0 → 3%；r = 12.0 → 2%）：公司风险越低、质地越稳，长期永续增长假设越高（推荐）。备选：恒取 3%（最简、最保守，但与「低风险公司可给更高永续增速」的常识脱节）。
6. **阶段年数按 X 分档**（X<12 → n1=5/n2=3；X<20 → 6/3；X<30 → 8/4；X≥30 → 10/5）。网格只给了取值范围（n1 ∈ 5–10、n2 ∈ 3–5），需要一条确定性映射；分档规则单调、只用网格值（推荐）。备选：一律取下限 n1=5、n2=3（更保守、规则最简）。
7. **三阶段第二阶段增长率 g2 = min(4, gk+1)**，形成 g1 → g2 → g3 递减路径（推荐，符合三阶段模型「高增长→过渡→永续」的语义）。备选：`g2 = gk`（此时三阶段退化为「两阶段但高增长期更长」，语义打折）。
8. **提示词契约改为「大模型只返回 rationale」**，并把确定性参数作为事实喂进用户消息（推荐，理由见 11.7）。备选：契约不变（模型仍返回数值但被覆盖）——省去提示词改动，但模型写理由时依据自己臆造的数字，容易与最终参数矛盾，且多耗 token。
9. **`normalizeValuation` 删除**（推荐，参数已整体覆盖，保留会误导）。备选：保留为「防御性清洗」——但对最终响应无任何作用，属死代码。
10. **`warning` 的判据用最新年报单年 FCF**（对应 R4 默认 `fcf_mode=latest`）（推荐）。注意其在用户改过 R4 基期选取方式时可能不适用，文案已用「可能」软化。
