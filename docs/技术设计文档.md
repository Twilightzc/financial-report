## 2. 总体架构

前后端分离，Go 提供 REST JSON API，Vue SPA 通过 Axios 调用。

```
┌─────────────────────────────────────────────────────┐
│  Vue 3 SPA（浏览器）                                  │
│  输入代码 → 指标表                                    │
└───────────────────────┬─────────────────────────────┘
                        │ Axios / REST JSON
                        ▼
┌─────────────────────────────────────────────────────┐
│  Go 后端（Gin）                                       │
│  handler（API 层）→ service（指标计算）→ client（数据获取）│
└───────────────────────┬─────────────────────────────┘
                        │ HTTP GET（免费接口）
                        ▼
┌─────────────────────────────────────────────────────┐
│  东方财富免费数据接口                                  │
│  三大报表（datacenter）+ 行情（push2）                 │
└─────────────────────────────────────────────────────┘
```

## 3. 后端设计

### 3.1 目录结构

```
backend/
├── cmd/server/main.go        # 入口，启动 Gin 服务
├── internal/
│   ├── api/                  # HTTP 层：路由 + handler
│   │   ├── router.go
│   │   └── handler.go
│   ├── service/              # 指标计算引擎（纯函数）
│   │   └── indicator.go
│   ├── client/               # 东财数据获取（HTTP 客户端）
│   │   ├── eastmoney.go
│   │   └── models.go         # 东财返回结构体
│   └── model/                # 领域模型：标准化报表结构体
│       └── financial.go
├── go.mod
└── go.sum
```

### 3.2 分层职责

- **model**：标准化的三张表结构体 + 指标结果结构体，全项目通用。
- **client**：封装东财接口调用，负责原始 JSON → 标准化结构体的映射。只依赖 `model`。
- **service**：指标计算纯函数，输入 `model` 报表 + 行情，输出指标值。无网络、无 IO。
- **api**：Gin 路由与 handler，解析参数、调用 service、返回 JSON。

依赖方向单向：`api → service → model`，`api → client → model`。

### 3.3 数据源（东方财富免费接口）

- **三大报表**：`datacenter-web.eastmoney.com` 接口，用 `reportName` 参数区分资产负债表 / 利润表 / 现金流量表，返回结构化 JSON。
- **行情**：`push2.eastmoney.com` 接口，获取最新股价、总股本（用于计算市值、PE/PB 分母）。
- **字段映射**：东财接口字段较多且部分科目有行业差异，实现时需对真实返回逐字段核对，再映射进 `model` 结构体。

> 注意：东财接口非官方文档化，字段名与可用性需在实现阶段实测确认；若遇不稳定，备选 Tushare Pro HTTP API（需 token + 积分）。

### 3.4 标准化报表结构体（示意）

```go

    TotalLiabilities float64   // 负债合计

    // ... 按需补充科目
}

type IncomeStatement struct {
    ReportDate       time.Time
    Revenue          float64 // 营业收入

    NetProfitParent  float64 // 归母净利润
    // ...
}

type CashFlowStatement struct {
    ReportDate        time.Time

    // ...
}
```

### 3.5 指标计算引擎（service）

- 指标设计为「纯函数 + 明确入参」，便于后续替换为用户指定的分析方法。
- 返回统一的 `IndicatorResult`，key 为指标名，value 为数值 + 单位/口径。

```go
func CalcPE(price, eps float64) float64        // 市盈率
func CalcPB(price, bps float64) float64        // 市净率
func CalcPS(marketCap, revenue float64) float64 // 市销率
func CalcDividendYield(dividend, price float64) float64 // 股息率
```

## 6. R2 技术方案：三大报表浏览与同比分析

> 对应《产品设计文档》第 6 节。在 R1 基础上新增：三张报表全科目展示、年份范围筛选（仅年报）、同比上年增长率，与 R1 共用页面。

### 6.1 总体思路

- **全科目**采用「白名单字典」方案：维护三张表的「字段 key → 中文名」映射表，仅展示映射表中的科目，天然排除接口返回的元数据（代码/名称/报告期等）与派生字段（`*_RATIO`、`*_YOY` 等）。
- **年份范围**由前端传入 `startYear`/`endYear`，后端只返回范围内年报（报告期以 `12-31` 结尾）。
- **同比**在前端计算（纯展示逻辑，含红涨绿跌着色），后端只返回各年原始数值，保持后端轻量。

### 6.2 数据模型（internal/model/financial.go 新增）

```go
// FieldDef 科目字典条目：字段 key → 中文名
type FieldDef struct {
    Key  string
    Name string
}

// ReportRow 单期报表原始行（数值字段，nil=无数据）
type ReportRow struct {
    ReportDate string
    Fields     map[string]*float64
}

// StatementItem 单个科目的跨年度数值（与 Statement.Years 对齐，nil=无数据）
type StatementItem struct {
    Field  string     `json:"field"`
    Name   string     `json:"name"`
    Values []*float64 `json:"values"`
}

// Statement 单张报表：年份正序 + 全科目
type Statement struct {
    Years []int           `json:"years"`
    Items []StatementItem `json:"items"`
}

// Financials 三张表聚合返回
type Financials struct {
    Balance  Statement `json:"balance"`
    Income   Statement `json:"income"`
    Cashflow Statement `json:"cashflow"`
}
```

### 6.3 科目字典（internal/model/fields.go 新增）

三张表各一张有序白名单（顺序即展示顺序），仅列出真实财务科目：

```go
var BalanceFields = []FieldDef{
    {"TOTAL_ASSETS", "资产总计"},
    {"TOTAL_LIABILITIES", "负债合计"},
    {"TOTAL_EQUITY", "所有者权益合计"},
    // ... 待按 columns=ALL 实测补全
}

var IncomeFields = []FieldDef{
    {"TOTAL_OPERATE_INCOME", "营业总收入"},
    {"OPERATE_COST", "营业成本"},
    {"PARENT_NETPROFIT", "归母净利润"},
    // ...
}

var CashflowFields = []FieldDef{
    {"NETCASH_OPERATE", "经营活动现金流量净额"},
    // ...
}
```

补全方式见 6.9（一次性实测 `columns=ALL` 返回，敲定全部中文映射）。

### 6.4 client 层（internal/client/eastmoney.go 新增）

- 新增 `FetchRawFinancial(reportName, code string, pageSize int) ([]model.ReportRow, error)`：
  - 复用现有 `fetchFinancial`（`columns=ALL`）取原始行；
  - 将每行剔除非数值字段，仅保留数值字段并 `toFloat` 归一为 `Fields map[string]float64`。
- 现有三个 `FetchXxx`（R1 用）保持不变，R2 走 `FetchRawFinancial`。

### 6.5 service 层（internal/service/statement.go 新增）

纯函数、无 IO：

```go
func BuildStatement(rows []model.ReportRow, fields []model.FieldDef, startYear, endYear int) model.Statement
```

逻辑：
1. 过滤：仅保留年报（`ReportDate` 以 `12-31` 结尾）且年份在 `[startYear, endYear]`。
2. 年份去重、升序，生成 `Years`。
3. 按 `fields` 顺序，为每个科目生成与 `Years` 对齐的 `Values`（缺失年份/无数据科目值为 `nil`，前端显示「—」）。
4. 返回 `Statement`。

### 6.6 API 设计（internal/api）

新增路由：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/stock/:code/financials?startYear=2020&endYear=2024` | 返回三张表全科目（范围内年报） |

- 参数：`startYear`、`endYear` 为可选 4 位年份；缺省时后端取「最近 5 个年报」。
- handler `GetFinancials`：
  1. 校验 `code`（6 位）。
  2. 解析/兜底年份范围（缺省 = 数据中最近 5 个年报）。
  3. 分别 `FetchRawFinancial`（`pageSize=40`，约覆盖 10 个年报）取三张表。
  4. 调用 `service.BuildStatement` 组装 `model.Financials`。
  5. 返回统一结构 `{code, data, message}`。
- 边界：范围内无年报 → 返回 `code:0` 且 `years`/`items` 为空，前端提示「所选年份范围无数据」。

响应示例：

```json
{
  "code": 0, "message": "ok",
  "data": {
    "balance": {
      "years": [2020, 2021, 2022, 2023, 2024],
      "items": [
        {"field": "TOTAL_ASSETS", "name": "资产总计", "values": [213395000000, 234500000000, 0, 0, 0]}
      ]
    },
    "income": { "years": [], "items": [] },
    "cashflow": { "years": [], "items": [] }
  }
}
```

### 6.7 前端设计（internal/web/app.js）

- 与 R1 共用页面：顶部搜索框 → R1 指标区 → R2 三大报表区。
- 查询时并行请求 `/indicators` 与 `/financials`。
- **Tab 切换**：`el-tabs` 三个页签（资产负债表 / 利润表 / 现金流量表）。
- **年份筛选**：两个 `el-select`（起始年/结束年）；选项由返回 `years` 生成，默认最近 5 年；变更后重新请求 `/financials`。
- **表格**：行 = 科目，列 = 年份；每格展示「数值（亿元）+ 下方同比（红涨绿跌）」。
- 数值统一 `÷1e8` 显示为亿元。

### 6.8 同比计算与展示规则

- 公式：`(当年 − 上年) / 上年 × 100%`。
- 展示：每年数值下方标注同比；红涨（`#f56c6c`）绿跌（`#67c23a`），复用现有 `style.css`。
- 边界：
  - 当年或上年无数据（`null`，如非金融股的银行专属科目）→ 数值显示「—」、同比显示「—」。
  - 上年 = 0 → 显示「—」。
  - 上年 < 0 → 增长率符号失真，仅显示数值、不显示百分比。
  - 范围内最早年份 → 无上年，显示「—」。

### 6.9 字段中文名映射（一次性实测步骤）

R2 主要工作量在敲定三张表的全科目中文映射。步骤：

1. 对样例股票（如 600519）调用 datacenter 三张表接口（`columns=ALL`）。
2. 导出返回字段清单。
3. 逐字段区分：财务科目（保留，补中文名）／元数据（排除）／派生比例与同比（排除）。
4. 写入 `model/fields.go` 三张白名单。

### 6.10 边界与验收对照

| 产品验收 | 技术实现 |
| --- | --- |
| 三张表全科目展示 | 白名单字典 + `BuildStatement` |
| 年份范围筛选 | `startYear`/`endYear` + 年报过滤 |
| 同比正确 | 前端相邻年计算，规则见 6.8 |
| 边界不报错 | 上期 0/负、缺年份 → 「—」/仅数值/空提示 |

## 7. R3 技术方案：六维财务指标分析

> 对应《产品设计文档》第 7 节。新增「财务指标分析」能力：按六大维度输出派生指标 + 解读。六大维度均已实现：「投资活动现金流分析」「筹资活动现金流分析」「资产资本分析」「股权价值增加值分析」「股东权益回报分析」「经营活动现金流分析」。

### 7.1 总体思路

- **六维框架**：定义固定的六个维度（顺序即展示顺序），每个维度下分若干「小节」，小节内为「指标」列表。
- **指标统一结构**：`指标名 + 跨年度数值 + 单位 + 解读`，其中数值用 `[]*float64`（与 `Years` 对齐，nil = 无法计算/无数据，前端显示「—」）。
- **分期落地**：六大维度均已实现——「投资活动现金流分析」「筹资活动现金流分析」「资产资本分析」「股权价值增加值分析」「股东权益回报分析」「经营活动现金流分析」。
- **数据源切换**：分析需要现金流量表、资产负债表、利润表的**全量接口**（摘要接口缺少明细科目），新增全量报表拉取路径。

### 7.2 数据模型（internal/model/analysis.go 新增）

```go
// AnalysisIndicator 单个分析指标（跨年度数值，与 FinancialAnalysis.Years 对齐）
type AnalysisIndicator struct {
    Key            string     `json:"key"`
    Name           string     `json:"name"`
    Values         []*float64 `json:"values"`   // nil = 无数据/无法计算
    Unit           string     `json:"unit"`     // 元/%/倍
    Kind           string     `json:"kind,omitempty"` // ""/subtotal/net
    Interpretation string     `json:"interpretation,omitempty"`
    Note           string     `json:"note,omitempty"` // 异常标注：无意义/未显示年份的原因说明
}

type AnalysisSection struct {
    Title      string              `json:"title"`
    Indicators []AnalysisIndicator `json:"indicators"`
}

type AnalysisDimension struct {
    Key      string            `json:"key"`
    Name     string            `json:"name"`
    Status   string            `json:"status"` // done / pending / no_data
    Sections []AnalysisSection `json:"sections"`
}
```

**无意义值标注**：指标某年值为 nil（分母 ≤ 0、上期缺失、原值不可得等导致无法计算/无意义）时，前端显示「—」，并在指标名旁用琥珀色 `!` 徽标标注原因。后端 `nilNote(values, years, reason)` 生成「{年份} 年{原因}，未显示」，`indN(...)` 构造指标时自动写入 `Note` 字段（`internal/service/analysis.go`）；覆盖周转率/周转天数、收益率/回报率、现金含量、现金自给率、财务杠杆、利息保障倍数、债务/股权资本成本、WACC、扩张性资本支出比例等全部可返回 nil 的指标。实际所得税税率因存在多种失真情况，单独用 `effectiveTaxRateDisplay`/`effectiveTaxRateNote` 处理。

```go
type FinancialAnalysis struct {
    Years      []int               `json:"years"` // 年份升序
    Dimensions []AnalysisDimension `json:"dimensions"`
}
```

### 7.3 数据源：全量报表接口

投资活动现金流分析需要现金流量表明细科目（收回投资/处置固定资产/取得子公司/收到其他等），摘要接口 `RPT_DMSK_FN_CASHFLOW` 只有 4 个投资科目，不足。改用全量接口：

| 报表 | 全量接口 reportName | 字段数 |
| --- | --- | --- |
| 现金流量表 | `RPT_F10_FINANCE_GCASHFLOW` | 254 |
| 资产负债表 | `RPT_F10_FINANCE_GBALANCE` | 319 |
| 利润表 | `RPT_F10_FINANCE_GINCOME` | 203 |
| 分红送配 | `RPT_SHAREBONUS_DET` | 30 |

- 全量接口冷启动慢（现金流 ~12s），`client` 新增 `hcSlow`（60s 超时）与 `FetchRawFinancialFull`（复用 `toReportRows` 归一逻辑）。
- **金融股限制**：银行/保险/券商使用不同 reportName（如 `RPT_F10_FINANCE_BCASHFLOW`），通用接口返回「返回数据为空」，当前暂不支持，handler 返回友好提示。

### 7.4 投资活动现金流字段映射（全量接口实测，易错）

投资活动现金流入：

| 字段 key | 中文名 |
| --- | --- |
| `WITHDRAW_INVEST` | 收回投资收到的现金 |
| `RECEIVE_INVEST_INCOME` | 取得投资收益收到的现金 |
| `DISPOSAL_LONG_ASSET` | 处置固定资产、无形资产和其他长期资产收回的现金净额 |
| `DISPOSAL_SUBSIDIARY_OTHER` | 处置子公司及其他营业单位收到的现金净额 |
| `RECEIVE_OTHER_INVEST` | 收到其他与投资活动有关的现金 |
| `TOTAL_INVEST_INFLOW` | 投资活动现金流入小计 |

投资活动现金流出：

**营运负债（12 核心科目）**：`NOTE_PAYABLE / ACCOUNTS_PAYABLE / ADVANCE_RECEIVABLES / CONTRACT_LIAB / FEE_COMMISSION_PAYABLE / STAFF_SALARY_PAYABLE / LONG_STAFFSALARY_PAYABLE / TAX_PAYABLE / DEFER_INCOME / DEFER_INCOME_1YEAR / OTHER_CURRENT_LIAB / DEFER_TAX_LIAB`（应付票据、应付账款、预收款项、合同负债、应付手续费及佣金、应付职工薪酬、长期应付职工薪酬、应交税费、递延收益非流动、递延收益流动、其他流动负债、递延所得税负债）。

**长期股权投资**：`LONG_EQUITY_INVEST`。**资产合计**为「金融资产 + 周转性经营投入 + 长期经营资产 + 长期股权投资」（重分类合计，非 `TOTAL_ASSETS`）。

### 7.5 service 层（internal/service/analysis.go 新增）

纯函数、无 IO：

```go
func ComputeAnalysis(balance, cashflow, income []model.ReportRow, dividends []model.DividendEvent, startYear, endYear int) model.FinancialAnalysis
```

- 过滤年报并截取 `[startYear, endYear]`，生成升序 `Years`。
- 遍历六大维度：`investing` 调 `buildInvestingAnalysis`，`financing` 调 `buildFinancingAnalysis`，`asset_capital` 调 `buildAssetCapitalAnalysis`，`equity_value_added` 调 `buildEquityValueAddedAnalysis`，`comprehensive` 调 `buildComprehensiveAnalysis`，`operating` 调 `buildOperatingAnalysis`。
- 每个已实现维度对范围内**每一年**计算派生指标，指标值与 `Years` 对齐。

**口径规则**：派生指标涉及现金流量表**主表必有科目**时，接口返回 `null` 表示「无该交易」而非「无数据」，故用 `v0()`（nil 视为 0）计算，避免「无并购活动」被误判为「无数据」。金融资产、有息债务等重分类求和用 `sum0Fields()`（nil 视为 0：不持有即 0）。

### 7.6 投资活动现金流分析指标口径

| 指标 | 公式 | 口径说明 |
| --- | --- | --- |
| 长期经营资产净投资额 | 购建长期经营资产支付的现金 − 处置长期经营资产收回的现金 | 主表科目，nil 按 0 |
| 保全性资本支出 | 折旧 + 摊销（含使用权资产摊销）+ 资产减值准备 + 固定资产报废损失 | 暂以现金流量表补充资料科目近似 |
| 长期经营资产扩张性资本支出 | 净投资额 − 保全性资本支出 | — |
| 长期经营资产扩张性资本支出比例 | 扩张性资本支出 ÷ 长期经营资产期初净额 × 100% | 期初净额=上期末长期经营资产（13 科目）之和 |
| 并购活动净合并额 | 取得子公司支付的现金 − 处置子公司收回的现金 | 主表科目，nil 按 0 |
| 战略投资活动总体规模扩张 | 扩张性资本支出 + 并购活动净合并额 | — |

> 保全性资本支出为「近似口径」；长期经营资产期初净额按《公司财务指标分析》文档「长期经营资产」定义（13 科目）取值。

**筹资活动现金流分析指标口径**：

| 指标 | 公式 | 口径说明 |
| --- | --- | --- |
| 战略投资活动综合现金需求 | 长期经营资产净投资额 + 并购活动净合并额 | 复用投资维度 `constructNet` + `mergerNet` |
| 现金自给率 | 经营活动现金流量净额 ÷ 战略投资综合现金需求 × 100% | 需求为 0 时 nil；>100% 视为自给 |
| 筹资需求 | 期初金融资产 + 经营现金流净额 − 战略投资综合现金需求 | 期初金融资产 = 上期末金融资产（15 科目） |
| 股东筹资净额 | 吸收投资收到的现金 − 分配股利、利润支付的现金 | 分配股利利润 = 分配股利利润或偿付利息 − 偿付利息 |
| 债务筹资净额 | 借款+发债收到的现金 − 偿还债务+偿付利息支付的现金 | 主表科目，nil 按 0 |
| 偿付利息支付现金 | 分配股利利润或偿付利息现金 − 母公司股东股利 − 少数股东股利 | 文档方法一；母公司股利取自分红送配接口 |
| 债务资本成本 | 偿付利息支付现金 ÷ 平均有息债务余额 × 100% | 现金利息含资本化利息，近似总利息支出；为 0 时 nil |
| 加权平均资本成本 | (有息债务/投入资本)×税后债务成本 + (股东权益/投入资本)×8% | 股权成本默认 8%；税后债务成本 = 债务成本×(1−实际税率) |

实际所得税税率 = 所得税费用 ÷ (利润总额 − 长期股权投资收益)，分母 ≤ 0 或缺失时回落 25%，clamp 到 [0,1]（内部计算口径）。综合分析「实际所得税税率」展示口径：基数 ≤ 0、所得税为负或比率 > 100% 的年份视为失真值，`effectiveTaxRateDisplay` 返回 nil（界面显示「—」），`effectiveTaxRateNote` 在指标旁标注原因（如威孚高科利润主要由长投收益构成、基数过小）。

**资产资本分析指标口径**：

| 指标 | 公式 | 口径说明 |
| --- | --- | --- |
| 周转性经营投入 | 营运资产 − 营运负债 | 营运资产/负债 = 核心科目 + 占比不过大的自由裁量科目 |
| 经营资产 | 周转性经营投入 + 长期经营资产 | 资产资本表「经营资产」层级，`operatingAssetsTotal` |
| 资产合计 / 资本合计 | 金融资产+周转性经营投入+长期经营资产+长期股权投资 / 有息债务+股东权益 | 占比分母；二者恒相等（未分类差额并入营运） |
| 各类资产/资本占比 | 各类资产（资本）÷ 资产合计（资本合计）× 100% | 短期资产占比 = 金融资产占比 + 周转性经营投入占比；长期资产占比 = 长期经营资产占比 + 长期股权投资占比 |
| 财务杠杆倍数 | 资本合计 ÷ 股东权益 | 倍；股东权益为 0 时 nil |
| 长期融资净额 | 长期债务 + 股东权益 − 长期经营资产 − 长期股权投资 | 为负=短融长投（激进）、≈0=匹配、为正=稳健 |
| 短期融资净额 | 短期债务 − 金融资产 − 周转性经营投入 | — |
| 周转性经营长期化率 |（股东权益 + 长期债务 − 长期经营资产 − 长期股权投资）÷ 周转性经营投入 × 100% | 周转性经营投入 ≤ 0（营运负债 ≥ 营运资产）时 nil |

自由裁量科目占比 = 科目值 ÷ `TOTAL_ASSETS`，>10% 或未分类差额较大时写入 `AnalysisDimension.Notes` 提示核实（科目仍计入营运，不排除）。

**股权价值增加值分析指标口径**（把利润表重构为股权价值增加表）：

| 指标 | 公式 | 口径说明 |
| --- | --- | --- |
| 息税前经营利润 | 营业收入 − 营业成本 − 税金及附加 − 销售费用 − 管理费用 − 研发费用 − 资产减值损失 − 信用减值损失 + 资产处置收益 + 其他收益 + 营业外收入 − 营业外支出 | 减值全部归经营（简化）；`nil` 按 0 |
| 息税前金融资产收益 | 短期投资收益（投资收益 − 长期股权投资收益）+ 利息收入 + 净敞口套期收益 + 公允价值变动净收益 + 汇兑净收益 + 税前其他综合收益 | 按文档 (26)+(27)+(28)+(29)+(30)+(31)；其他综合收益（税后）用 `preTaxOtherComprehensiveIncome` 按统一税率还原税前 |
| 息税前利润总额 | 息税前经营利润 + 息税前金融资产收益 + 长期股权投资收益 | — |
| 真实财务费用 | 财务费用 + 利息收入（`FE_INTEREST_INCOME`） | 把财务费用中被抵减的利息收入还原 |
| 财务费用抵税效应 | 真实财务费用 × 实际所得税税率 | 债务利息的抵税金额 |
| 税后真实财务费用 | 真实财务费用 − 财务费用抵税效应 = 真实财务费用 × (1−税率) | 税后实际债务成本 |
| 税前利润 | 息税前利润总额 − 真实财务费用 | ≈ 利润表利润总额 |
| 净利润 | 税前利润 − 所得税费用 | 重构口径，≈ 利润表净利润（含少数股东损益）；亦 = 息前税后利润总额 − 税后真实财务费用 |
| 经营利润所得税 / 金融资产收益所得税 | 息税前经营利润 × 税率 / 息税前金融资产收益 × 税率 | 经营/金融资产收益各自承担的所得税 |
| 息前税后利润总额 | 息前税后经营利润 + 息前税后金融资产收益 + 长期股权投资收益 | 经营/金融各乘 (1−税率)；长投已缴税不再乘 |
| 各类费用率 | 营业成本率 / 税金及附加率 / 销售费用率 / 管理费用率 / 研发费用率 = 各科目 ÷ 营业收入；资产减值损失率 = (资产减值损失 + 信用减值损失) ÷ 营业收入 | 分母营业收入为 0 时 nil |
| 毛利率 / 息前税后营业收入利润率 | (营业收入−营业成本) ÷ 营业收入 / 息前税后经营利润 ÷ 营业收入 | 分母营业收入为 0 时 nil |
| 营业外收支及其他占比 / 总费用率 | 营业外收支及其他占比 = (资产处置收益+其他收益+营业外收入−营业外支出) ÷ 营业收入；总费用率 = (税金及附加+销售+管理+研发+资产减值损失+信用减值损失−营业外收支及其他) ÷ 营业收入 | 分母营业收入为 0 时 nil |
| 财务成本负担率 | 真实财务费用 ÷ 息税前利润总额 × 100% | 分母为 0 时 nil |
| 债务资本成本率 | 真实财务费用 ÷ 平均有息债务余额 × 100% | 平均有息债务 = (期初+期末)÷2；无有息债务/上期缺失/真实财务费用 ≤ 0 时 nil（区别于筹资维度「偿付利息支付现金」的现金口径） |
| 股权资本成本 | 股东权益（`TOTAL_EQUITY`）× 8% | 期末口径，含少数股东，与净利润口径一致 |
| 股权价值增加值 | 净利润 − 股权资本成本 | 为正创造超预期回报、为负损毁价值 |

实际所得税税率复用筹资维度的 `effectiveTaxRate`（所得税费用 ÷ (利润总额 − 长期股权投资收益)，缺失回落 25%、clamp 到 [0,1]）。净利润与股东权益均取**含少数股东**口径，保持一致。

**股东权益回报分析指标口径**（把资产资本表与股权价值增加表结合，需利润表 + 资产负债表，无需额外拉取）：

| 指标 | 公式 | 口径说明 |
| --- | --- | --- |
| 股东权益回报率（ROE） | 净利润 ÷ 股东权益 × 100% | 杜邦四因素：息税前资产回报率×财务成本效应比率×财务杠杆倍数×企业所得税效应比率 |
| 息税前资产回报率 | 息税前利润 ÷ 资产总额 × 100% | 全公司口径，杜邦四因素分解的首项 |
| 息税前经营资产回报率 | 息税前经营利润 ÷ 经营资产 × 100% | = 息税前经营利润率 × 经营资产周转率 |
| 息税前经营利润率 | 息税前经营利润 ÷ 营业收入 × 100% | 纯经营口径，区别于含金融/长投收益的息税前利润率 |
| 长期股权投资收益率 | 长期股权投资收益 ÷ 长期股权投资 × 100% | — |
| 金融资产收益率 | 息税前金融资产收益 ÷ 金融资产 × 100% | — |
| 资产周转率 | 营业收入 ÷ 资产总额 | 资产总额取 `TOTAL_ASSETS`（含全部负债），次 |
| 经营资产周转率 | 营业收入 ÷ 经营资产 | 经营资产 = 周转性经营投入 + 长期经营资产 |
| 长期经营资产/周转性经营投入周转率 | 营业收入 ÷ 长期经营资产 / 周转性经营投入 | 经营资产周转率的子项 |
| 固定资产周转率 | 营业收入 ÷ 平均固定资产净值 | 长期经营资产周转率的子项；平均净值 = (期初+期末)`FIXED_ASSET`÷2 |
| 固定资产成新率 | 平均固定资产净值 ÷ 平均固定资产原值 | 长期经营资产周转率的子项；原值需附注，免费接口不可得，恒为空（用户确认保留指标） |
| 应收账款周转率 | 营业收入 ÷ 平均应收账款净额 | 净额 = 应收账款+应收票据−预收账款 |
| 存货周转率 | 营业成本 ÷ 平均存货余额 | 销货成本用营业成本替代 |
| 应付账款周转率 | 营业成本 ÷ 平均应付账款净额 | 净额 = 应付账款+应付票据−预付账款；采购成本用营业成本替代 |
| 周转天数 / 营业周期 / 现金周期 | 365÷周转率 / 存货天数+应收天数 / 营业周期−应付付账期 | 计算期天数取 365 |
| 财务成本效应比率 | 税前利润 ÷ 息税前利润 × 100% | = 1 − 财务成本负担率 |
| 财务杠杆倍数（杜邦） | 资产总额 ÷ 股东权益 | 区别于资产资本维度「资本合计÷股东权益」的有息债务口径 |
| 财务杠杆效应 | 财务成本效应比率 × 财务杠杆倍数 | — |
| 债务对股东权益比率 |（短期借款 + 长期借款）÷ 股东权益 | — |
| 利息保障倍数 | 息税前利润 ÷ 真实财务费用 | 「利息费用」取真实财务费用（用户确认） |
| 企业所得税效应比率 | 净利润 ÷ 税前利润 × 100% | = 1 − 实际所得税税率 |

分母 ≤ 0（经营资产/股东权益/真实财务费用/长期股权投资/金融资产等）或上期数据缺失时指标为 nil（前端显示「—」）。

**经营活动现金流分析指标口径**（把经营活动现金流量表与利润表结合，需现金流量表 + 利润表，无需资产负债表）：

| 指标 | 公式 | 口径说明 |
| --- | --- | --- |
| 营业收入现金含量 | 销售商品、提供劳务收到的现金 ÷ 营业收入 × 100% | 未剔除增值税销项税额的简化口径；平稳期约 100% |
| 成本费用付现率 |（采购商品付现 + 支付职工现金）÷（营业成本+税金及附加+销售费用+管理费用+研发费用）× 100% | 未剔除增值税进项税额的简化口径；平稳期应低于 100% |
| 息前税后经营利润现金含量 | 经营活动现金流量净额 ÷ 息前税后经营利润 | 息前税后经营利润复用股权价值维度口径；利润 ≤ 0 时 nil |
| 净利润现金含量 | 经营活动现金流量净额 ÷ 净利润 | 净利润取重构口径（税前利润 − 所得税）；利润 ≤ 0 时 nil |
| 经营活动现金流量净额 | 直接取 `NETCASH_OPERATE` | 按文档五档解读 |

## 8. R4 技术方案：公司股票估值

> 对应《产品设计文档》第 8 节。新增「公司股票估值」能力：现金流贴现法（DCF），四种估值模型，基于最新年报。

### 8.1 总体思路

- 公司价值 = 金融资产价值 + 长期股权投资价值 + 经营资产价值；股权价值 = 公司价值 − 债务价值（有息债务）。
- 金融资产价值取账面；长期股权投资价值收益资本化（账面 × 收益率 ÷ 折现率）；经营资产价值对「经营资产自由现金流」按模型贴现。
- 估值模型与增长率/折现率/年数由查询参数传入，后端纯函数计算，前端模型单选 + 动态参数。
- 基期自由现金流支持四种选取方式（最近一年 / 近几年平均值 / 近几年中位数 / 去极值平均值）；支持研发费用调整（成长科技股，把研发投入扩张部分加回自由现金流）。

### 8.2 数据模型（internal/model/valuation.go 新增）

```go
type ValuationParams struct {

    Stage1Years    int

type ValuationResult struct {
    Model, ModelName string
    Year         int
    DiscountRate float64
    // ... 输入参数回显

    RDAdjustment         float64 // 研发投入扩张部分加回金额
    BaseFCF          float64  // 基期经营资产自由现金流
    LongEquityBook   float64  // 长期股权投资账面
```

### 8.3 数据源

复用三张全量报表接口 + 行情：

- 金融资产 / 长期股权投资 / 有息债务 → 资产负债表 `RPT_F10_FINANCE_GBALANCE`（仅需最新年报，`pageSize=8` 覆盖约 2 个年报）。
- 资产减值损失 / 信用减值损失 / 长期股权投资收益 / 研发费用 → 利润表 `RPT_F10_FINANCE_GINCOME`（多期，`pageSize=40` 覆盖约 10 个年报）。
- 经营现金流净额 / 折旧摊销 / 处置损失 / 报废损失 → 现金流量表 `RPT_F10_FINANCE_GCASHFLOW`（多期，`pageSize=40`）。
- 总股本（每股股权价值）→ 行情 `FetchQuote`。

> 基期自由现金流取「平均值/中位数」需多期现金流；研发费用调整需上年度研发费用，故现金流与利润表拉取约 10 个年报。

### 8.5 service 层（internal/service/valuation.go 新增）

```go
func ComputeValuation(balance, cashflow, income []model.ReportRow, params model.ValuationParams, totalShares float64) (model.ValuationResult, error)
```

- 取三张表年报，逐年计算经营资产自由现金流（`operatingFreeCashFlow`），按 `FCFMode` 用 `selectBaseFCF` 选取基期（latest 取最近一年 / average、median、trim_mean 取最近 `FCFYears` 年，年数超可用年份时截断；trim_mean 为去掉最高最低后的平均值，少于 3 年时退化为普通平均值）；再计算金融资产价值、长期股权投资价值（收益资本化 `max(0, 账面×(收益率÷折现率))`）、经营资产价值（DCF）、公司价值、债务价值、股权价值、每股股权价值。
- 研发费用调整：`AdjustRD` 为真时，`rdExpansion = max(0, 本年度研发费用 − 上年度研发费用)` 加回基期自由现金流（上年度缺失时返回 0）；研发费用取利润表 `RESEARCH_EXPENSE` 近似研发投入。
- 贴现函数：`dcfZero`（FCF÷r）、`dcfPerpetual`（FCF×(1+g)÷(r−g)）、`dcfTwoStage`、`dcfThreeStage`（增长率以小数参与运算）。
- 保全性资本支出 = 资产减值损失 + 信用减值损失 + `FA_IR_DEPR` + `USERIGHT_ASSET_AMORTIZE` + `IA_AMORTIZE` + `LPE_AMORTIZE` + `DISPOSAL_LONGASSET_LOSS`（仅计损失，收益按 0）+ `FA_SCRAP_LOSS`。
- 参数校验：折现率 > 0；各模型永续/终值增长率 < 折现率；阶段年数 > 0；经营资产自由现金流 > 0（否则现金流贴现法不适用）。
- 长期股权投资占总资产 >10% 时写入 `Notes` 提示单独估值；基期取平均值/中位数时写入所用年份。

## 9. R5 技术方案：AI 智能分析（大模型财务诊断）

> 对应《产品设计文档》第 9 节。复用 R3 六维指标计算结果，接入 DeepSeek 大模型，输出五维评分 / 结论 / 行业分析 / 业务板块分析 / 估值模型推荐。

### 9.1 总体思路

- 收到「一键分析」请求后，复用 `fetchAnalysisReports` 拉取三张全量报表 + 分红、`service.ComputeAnalysis` 计算六维指标，另拉取**主营构成**（`RPT_F10_FN_MAINOP`，`FetchSegmentIncome`，取最新年报产品明细的板块名与营收占比），再把指标 + 主营构成序列化喂给大模型。报表拉取走 client 层缓存（15 分钟 TTL），避免「分析→AI 分析」重复拉取 F10（冷启动 ~12s）。
- **系统提示词（skill）** = 仅静态框架（角色 / 任务 / 输出 JSON 结构 / 五维评分标准 / 估值模型推荐（只解释不改数，R7 起替换原「估值模型推荐规则」）/ 行业分析规则 / 业务板块分析规则），不随股票变化、利于复用。
- **用户消息** = 公司信息（名称 / 代码 / 总市值）+ 主营构成（板块名 + 营收占比）+ 年度头部 + 各维度指标，每行「指标名（单位；含义）：按年度顺序的数值」（金额换算亿/万，全 nil 指标跳过、nil 显示「—」）。含义与数值同处一行，避免「字典 + 数值」重复发送指标名。
- **业务板块分析**：`businesses` 字段（`[]AIBusiness`：name/stage/contribution/prospect/risk），贡献占比据主营构成实际数值给出——同时看**营收占比、利润占比、毛利率**（`SegmentIncome` 含 RevenueRatio/ProfitRatio/GrossMargin），不只营收占比、不凭空编造。
- **大模型客户端**：OpenAI 兼容 Chat Completions，仅用标准库 `net/http`（无新增依赖），`response_format=json_object`、`temperature=0`（降低多次分析之间的参数波动）、`reasoning_effort`（前端「分析模式」随请求传入，`low` 简洁 / `medium` 标准 / `high` 详细，缺省 `low`；模型不支持时忽略该字段）、`max_tokens=8192`（给推理+回答留足空间，避免内容为空；过低会耗尽额度导致 `content` 为空）、180s 超时；解析响应 `usage` 回填 token 用量。
- **结论详略随模式变化**：`BuildAIPrompt` 按 `reasoning` 注入结论长度要求（简洁约 100 字 / 标准约 200 字 / 详细约 300 字），让不同模式在速度与详细度上真实可感（推理强度本身仅作辅助）。
- **估值推荐**：~~增长率从指标数据推导并结合行业前景/竞争格局微调~~ —— R7 起改为**后端确定性推导**（纯函数 `RecommendValuation`，见第 11 节），大模型不再产出任何数值，只写 `rationale`；本节的「估值模型推荐规则」提示词段落由第 11.7 节替换。
- 解析返回 JSON 为 `AIAnalysisResult`，做**容错解析**（浮点评分四舍五入、维度名模糊匹配到规范名并重排）后返回前端。

### 10.2 关键判断：「窄屏」的口径取图表可用宽度，「移动端」的口径取视口

需求里两个阈值口径不同，必须分别实现，不能混用一个：

- **FR-2/FR-3 的「窄屏」= 图表可用宽度 < 480px**：决定图例位置、图例缩略、字号与 `grid` 左右边距。在渲染时用 `chartRef.clientWidth` 实测（`narrow = el.clientWidth < CHART_NARROW_WIDTH`，常量 `CHART_NARROW_WIDTH = 480`）。
- **FR-4 的「移动端」= 视口 ≤ 768px**：决定图表容器高度（380px → 320px）与弹窗内边距，沿用既有 CSS 媒体查询断点，不去 JS 里算。

两者会在中间区间（视口约 548–768px）出现组合：容器高度已是移动端 320px、而图表宽度 > 480px 仍用顶部图例。这是两个需求条款直接推导的结果，属预期行为，不算回归。用 JS 实测宽度而非按视口推断，好处是弹窗宽度本身是 `min(680px, 92vw)`（非固定），实测值才是真实可用宽度。

### 10.3 option 改造（`internal/web/app.js`）

把现在内联在 `renderIndicatorChart` 里的 option 构造拆成**纯函数 + 常量**，便于按宽度重算：

```js
const CHART_NARROW_WIDTH = 480; // 图表可用宽度窄于此值时：图例移底、字号 11px、边距收紧

// 左 y 轴刻度：单位语义由刻度标签承载（FR-1）。
function fmtAxisValue(v, unit) {
  if (unit === '元') {
    if (v === 0) return '0';
    const yi = v / 1e8;
    if (Math.abs(yi) >= 1) return yi.toFixed(1) + '亿';
    return (v / 1e4).toFixed(0) + '万';
  }
  if (unit === '%') return fmtAxisPct(v);
  if (unit === '倍') return v.toFixed(2) + '倍';
  return Number(v).toFixed(2);
}

// 百分比刻度：至多 1 位小数（12.5% / 10% / 0% / -5%）；左轴与右轴（同比增速）共用。
function fmtAxisPct(v) {
  if (v === 0) return '0%';
  const r = Math.round(v * 10) / 10;
  return (Number.isInteger(r) ? r.toFixed(0) : r.toFixed(1)) + '%';
}

// 窄屏图例缩略：超过 6 个汉字截断为 6 字 + 「…」（全名仍在弹窗标题与 tooltip）
function legendLabel(name, narrow) {
  return narrow && name.length > 6 ? name.slice(0, 6) + '…' : name;
}

// 同比增速折线（首年/上期缺失/上期为 0 或负 → null），口径不变
function growthSeries(values) {
  return values.map((v, i) => {
    if (i === 0) return null;
    const prev = values[i - 1];
    if (v == null || prev == null || prev === 0 || prev < 0) return null;
    return ((v - prev) / prev) * 100;
  });
}
```

`buildIndicatorChartOption(it, years, values, growth, narrow)` 返回完整 option，关键改动：

| 项 | 现状 | 改后（宽屏 / 窄屏） |
| --- | --- | --- |
| 左 y 轴轴名 | `name: unit`（`%` / `元` / `倍` 单符号） | **移除轴名**（Q1 推荐方案，单位已由刻度承载） |
| 左 y 轴刻度 | `fmtAxis`：`%`/`倍` 返回裸数字 | `axisLabel.formatter: (v) => fmtAxisValue(v, unit)`（`%`→`12.5%`、`倍`→`1.20倍`、`元`→`1.2亿`/`500万`/`0`） |
| 右 y 轴（增速） | `name:'增速 %'` + `'{value}%'` | 保留轴名，加 `nameGap: 8`；formatter 改 `fmtAxisPct`（避免 `{value}%` 输出长小数） |
| 图例 | `top:0`，`data:[it.name,'同比增速']` | 宽屏：`top:0`，fontSize 12；窄屏：`bottom:0, left:'center', itemGap:12`，fontSize 11；窄屏长名缩略（同时用于 `legend.data` 与 series `name`） |
| grid | `{left:64,right:64,top:40,bottom:32}` | 宽屏 `{left:12,right:16,top:48,bottom:24,containLabel:true}`；窄屏 `{left:8,right:12,top:28,bottom:46,containLabel:true}`（左右合计 20px ≤ 24px，满足 FR-3） |
| 字号 | 未显式设置（默认 12） | 窄屏 legend/axisLabel/nameTextStyle 统一 11，宽屏 12 |
| x 轴刻度 | 默认 | 加 `axisLabel.hideOverlap: true`（ECharts 5.5 支持），年份多时不互相压字 |

要点与理由：

1. **图例文本必须同时改在 `legend.data` 与 series `name` 上**：ECharts 图例按 `name` 与 series 关联，只改 `legend.data` 会导致图例项点不动/不显示。缩略后 series `name` 也变了，但 tooltip 用的是自定义 `formatter`（内部写死 `it.name` 与 `'同比增速'`），弹窗标题也用 `chartIndicator.name`，所以**全名信息不丢**（满足 FR-2）。
2. **`containLabel: true` 与边距的关系**：开启后 `grid.left/right/bottom` 是「轴刻度标签之外」的留白，因此左右可压到 8/12px 而不会裁切 `1.2亿` 这类长刻度（FR-3 边界）。窄屏 `bottom: 46px` 是给底部图例留位（x 轴标签由 containLabel 负责）。
3. **`top` 的取值**：顶部无图例（窄屏）时 `top:28px` 刚好容纳右轴轴名（文本 + `nameGap:8`）；顶部有图例（宽屏）时 `top:48px` 让图例与轴名分层，消除需求里「图例换行压住轴名」的根因。
4. **仅 1 年数据时不渲染增速系列**（FR-2 边界）：`growth` 全为 null 时不 push 折线 series、不加右 y 轴、`legend.data` 只含指标名一项。这同时避免了一个隐患——若折线系列被移除而 `yAxisIndex:1` 仍存在，或反之，图例会与系列错配。
5. **`grid.top`/`bottom` 的具体像素值需实机微调**：右 y 轴轴名（`nameLocation:'end'` 默认置顶）在 `containLabel` 下的占位由 ECharts 内部布局决定，文档给不出可以离线验证的精确值；实现时按 10.7 的手工核对（320px 下 `%` 与长名指标各一张）确认无压字/裁切，若轴名与绘图区顶部过挤，优先微调 `grid.top`（窄屏 28 → 32）而非移除轴名。

`renderIndicatorChart()` 改为：计算 `growth` → `dispose` 旧实例 → `echarts.init(el)` → 实测 `chartNarrow.value = el.clientWidth < CHART_NARROW_WIDTH` → `chart.setOption(buildIndicatorChartOption(...))`。

### 10.6 弹窗生命周期：resize 重排与销毁（FR-5）

```js
const chartNarrow = ref(false); // 当前图表是否处于窄屏布局

let chartResizeTimer = null;
function handleChartResize() {
  if (!chartVisible.value || !chartRef.value) return;
  clearTimeout(chartResizeTimer);
  chartResizeTimer = setTimeout(() => {
    if (!chartVisible.value || !chartRef.value) return;
    const el = chartRef.value;
    const chart = echarts.getInstanceByDom(el);
    if (!chart) return;
    const next = el.clientWidth < CHART_NARROW_WIDTH;
    if (next !== chartNarrow.value) {
      // 跨越 480px 阈值：图例位置/grid/字号需整体重算
      chartNarrow.value = next;
      chart.setOption(buildIndicatorChartOption(chartIndicator.value, analysis.value.years || [], chartIndicator.value.values || [], growthSeries(chartIndicator.value.values || []), next));
    }
    chart.resize(); // 容器尺寸变化后重新测量
  }, 120); // 防抖，横竖屏切换时 resize 会连续触发
}

// 弹窗关闭时销毁实例，避免 echarts 实例挂在已移除的 DOM 上
function disposeIndicatorChart() {
  if (!chartRef.value) return;
  const c = echarts.getInstanceByDom(chartRef.value);
  if (c) c.dispose();
```

### 11.5 核心实现（`internal/service/valuation_recommend.go`）

对外主函数（纯函数，无 IO/随机/时间依赖）：

```go
func RecommendValuation(balance, cashflow, income []model.ReportRow) model.ValuationRecommendation
```

内部分解为若干可直接单测的小函数（便于逐分支断言）：

```go
func classifyModel(x float64) string                                   // 基准增速 → 模型
func medianOf(values []float64) float64                                // 中位数（偶数取中间两值平均）
func growthSamples(byYear map[int]model.ReportRow, years []int, value func(model.ReportRow) float64) []float64
func recommendParams(model string, x float64, volatile bool, gk float64) []model.AIValuationParam
func perpetualGrowth(discount float64) float64                        // 折现率 → 永续增长率 gk
func stageYears(x float64) (n1, n2 int)                                // 基准增速 → 阶段年数
func discountRateFor(riskPoints int, hasBalance bool) float64          // 风险点 → 折现率
func valuationRiskPoints(balance, income model.ReportRow) (int, bool)  // 财务风险点计数
```

**第 1 步：年报索引**

```go
incomeByYear, incomeYears := annualRows(income)
cfByYear, cfYears := annualRows(cashflow)
balanceByYear, balanceYears := annualRows(balance)
```

**第 2 步：三个指标的同比增速样本**

对每个指标，从所在表的**年报年份升序切片**（禁止遍历 map，保证确定性）中，取**最近 3 个「本年与上年均有年报」的年份**计算同比增速：

```
growth(y) = (v(y) − v(y−1)) / v(y−1) × 100%
跳过条件（该样本不计入，也不记为 0）：v(y−1) 缺失、v(y−1) ≤ 0、v(y) 缺失
```

即 `v(y−1) ≤ 0`（上期为 0 或负）与上期缺失一律跳过（满足 FR-3 边界「跳过该样本，不得记为 0 参与中位数」）。

```
samples = 营业收入样本(≤3) ++ 净利润样本(≤3) ++ 经营现金流样本(≤3)   // 最多 9 个
```

**第 3 步：基准增速 X% 与剧烈波动**

```
len(samples) == 0 → X = 0，BaseGrowthNote = 「可用同比增速样本不足，基准增速按 0 计，模型退化为零增长」
否则             → X = medianOf(samples)
Volatile = len(samples) >= 2 && (max(samples) − min(samples) > 40)   // 极差 > 40 个百分点
```

- 中位数对 9 个样本天然抗单年异常；偶数个样本取中间两值平均。
- **极差判据作用于参与中位数的同一组样本**（三个指标合并后），保证「剧烈波动」只有一种解释、无歧义分支。
- 可用年度不足 3 年时，按实际可用样本取中位数（FR-3 推荐降级）；不足 2 年（`len(samples) == 0`）→ X=0 且模型为 `zero`——这是需求允许的两条路径中**唯一固定**的一条，且在 `BaseGrowthNote` 中明确标注。

**第 4 步：模型分档（对未取整的 X 判定，唯一确定）**

| X（%） | model | 是否用 g1 |
| --- | --- | --- |
| X ≥ 20 | `three_stage` | 是 |
| 8 ≤ X < 20 | `two_stage` | 是 |
| 0 ≤ X < 8 | `perpetual` | 否 |
| X < 0 | `zero` | 否 |

`ModelName` 复用 `service.valuationModelNames`（`internal/service/valuation.go`），与 R4 前端 `valModels` 中文名一致。

**第 5 步：折现率（FR-4，取三张表中年报最新年份）**

```
yLatest = max(incomeYears ∪ cfYears ∪ balanceYears)
b = balanceByYear[yLatest]，inc = incomeByYear[yLatest]

b 缺失（无法评估）→ discount = 10.0（默认档，FR-4 推荐降级）
否则：
  cap := totalCapital(b)
  debtRatio := cap > 0 ? interestBearingDebt(b)/cap*100 : 0
  lev := leverage(b)          // 资本合计÷股东权益；股东权益为 0 → nil
  cov := interestCoverage(inc) // 真实财务费用 ≤ 0 → nil（无利息负担）

  riskPoints := 0
  if debtRatio > 40                       → riskPoints++   // 有息债务占比偏高
  if cov != nil && *cov < 3               → riskPoints++   // 利息保障不足；nil 视为无息负债，不计风险
  if lev == nil || *lev > 3               → riskPoints++   // 杠杆过高 / 股东权益为 0

  discount = [9.0, 10.0, 11.0, 12.0][riskPoints]   // riskPoints 0/1/2/3
```

- 折现率恒为网格值且在 [8.0, 12.0] 内，`DiscountRate` 不再需要四舍五入。
- `利息保障倍数` 因真实财务费用 ≤ 0 而缺失时走「视为无利息负担、不扣分」的确定性分支，不由大模型补猜（FR-4 边界）。
- 该映射使用网格的 9.0 / 10.0 / 11.0 / 12.0 四档（等距 1%）；8.0 / 8.5 / 9.5 / 11.5 是网格允许值但本规则不产出（网格是**允许集**而非必须用满）。

**第 6 步：增长率与年数（全部落在 FR-1 网格内）**

```
g1raw = Volatile && (model 为 two_stage/three_stage) ? floor(X/2) : X
g1    = clamp(round(g1raw), -5, 30)     // 剧烈波动时按 FR-2 补充：g1 取基准增速的 50% 向下取整
gk    = perpetualGrowth(discount)：discount ≤ 9.0 → 4；discount ≤ 11.0 → 3；否则 → 2
(n1, n2) = stageYears(X)：X < 12 → (5,3)；X < 20 → (6,3)；X < 30 → (8,4)；否则 → (10,5)
```

- `Volatile` 只在 X ≥ 8（模型含 g1）时体现；X < 8 时 g1 不参与模型，规则自然不生效（与 FR-2 补充「模型仍按上表档位判定」一致）。
- `gk ∈ {2,3,4}` 且恒小于折现率（折现率最小 9.0 > 4），FR-1 的 `g2/g3 < discount_rate` 由构造保证，无需事后吸附。
- 三阶段中第二阶段增长率 `g2` 取「比永续增长率高一档」以形成递减路径：`two_stage` 的 `g2 = gk`；`three_stage` 的 `g2 = min(4, gk+1)`、`g3 = gk`（`gk = 4` 时退化为 `g2 = g3 = 4`，受网格上限约束，属可接受）。

**第 7 步：套用提示（FR-8 异常）**

```
fcf := operatingFreeCashFlow(incomeByYear[yLatest], cfByYear[yLatest])
fcf <= 0 → Warning = 「以最新年报计的基期经营资产自由现金流为负或零，套用后 R4 估值可能提示「现金流贴现法不适用」」
```

对应 R4 默认 `fcf_mode=latest` 的情形；若用户在 R4 表单改过基期选取方式，提示可能不适用（`warning` 文案已限定「可能」）。

**确定性纪律（实现约束）**：不遍历 map 取极值或决定顺序（一律用 `annualRows` 返回的升序年份切片）；所有舍入显式使用 `math.Round`/`math.Floor`；不引用时间、随机数、环境变量。

### 11.6 用确定性结果覆盖大模型返回

新增：

```go
// ApplyValuationRecommendation 用确定性推导结果覆盖大模型返回的估值参数字段，只保留其 rationale。
func ApplyValuationRecommendation(r *model.AIAnalysisResult, rec model.ValuationRecommendation) {
    r.Valuation.Model = rec.Model
    r.Valuation.ModelName = rec.ModelName
    r.Valuation.DiscountRate = rec.DiscountRate
    r.Valuation.Params = rec.Params
    r.Valuation.BaseGrowth = rec.BaseGrowth
    r.Valuation.BaseGrowthNote = rec.BaseGrowthNote
    r.Valuation.Volatile = rec.Volatile
    r.Valuation.Warning = rec.Warning
    // Rationale 保持大模型返回值，不覆盖
}
```

- **覆盖位置选择 handler 层而非 `ParseAIResult` 内部**，理由：`ParseAIResult` 的输入只有大模型文本，而确定性参数来自报表数据，若塞进 `ParseAIResult` 就必须改其签名、把报表透传进解析层，破坏「解析只管文本」的职责；独立函数也让「覆盖」这一步可单测（构造不一致的模型输出，断言最终以后端为准，对应 FR-5 验收项）。
- **删除 `normalizeValuation`**（`internal/service/ai.go`）及其在 `ParseAIResult` 中的调用：模型/折现率/参数已整体被覆盖，保留量化逻辑会误导后来者以为大模型数值仍有效。FR-1 要求的「网格外值必须被吸附」改由**构造保证**（所有取值来自固定集合 + `g1` 的 clamp），并以单测断言（见 11.10）。`ParseAIResult` 其余逻辑（评分容错、维度重排、校验）不变，`math` 包仍用于评分取整。

### 11.7 提示词改写（`internal/service/ai.go`）

**选定方案：大模型不再产出任何估值数值，只产出 `rationale`；同时把后端确定性参数作为「事实」喂进用户消息。**

理由：需求 FR-5/FR-7 要求「rationale 不得与后端参数矛盾」。若仍让模型产出数值（哪怕会被覆盖），模型写理由时依据的是它自己心里的数字，很可能与最终回填的参数冲突；反过来把确定性参数明确告知模型，它才能写出与参数自洽的解释。副作用是提示词更短、token 更省、且彻底移除了「模型选择歧义」在提示词里的残留。

### 11.11 R7 关键决策点

1. **「近 3 个完整年度」的锚点 = 数据中最近 3 个可算同比的年报**，与请求的 `startYear`/`endYear` 无关（推荐）。理由：参数只由财报数据决定 → 不同年份范围/不同分析模式之间参数也完全一致（强于 FR-6 要求），且与 R4「基于最新年报」口径一致。备选：锚定请求年份范围的末年（参数会随用户选择变化，但仍可复现）。
2. **X% 的聚合 = 9 个（至多）样本合并后取一次中位数**（推荐，贴合需求原文「取中位数」且抗单年异常）。备选：三个指标各取中位数后再取三项中位数（对单一指标极端波动更稳健，但多一层聚合、解释成本略高）。
3. **极差 > 40pp 的判据作用于同一组合并样本**（推荐，保证唯一解释）。备选：三个指标各自极差取最大值。
4. **折现率映射用 9.0/10.0/11.0/12.0 四档（等距 1%）**，风险点 0–3 一一对应，数据缺失回落 10.0（推荐）。备选：更细的 0.5% 打分表（用满网格，但需要给三个指标分配权重，规则变复杂、更难解释）。
5. **永续增长率 gk 与折现率反相关**（r ≤ 9.0 → 4%；r ≤ 11.0 → 3%；r = 12.0 → 2%）：公司风险越低、质地越稳，长期永续增长假设越高（推荐）。备选：恒取 3%（最简、最保守，但与「低风险公司可给更高永续增速」的常识脱节）。
6. **阶段年数按 X 分档**（X<12 → n1=5/n2=3；X<20 → 6/3；X<30 → 8/4；X≥30 → 10/5）。网格只给了取值范围（n1 ∈ 5–10、n2 ∈ 3–5），需要一条确定性映射；分档规则单调、只用网格值（推荐）。备选：一律取下限 n1=5、n2=3（更保守、规则最简）。
7. **三阶段第二阶段增长率 g2 = min(4, gk+1)**，形成 g1 → g2 → g3 递减路径（推荐，符合三阶段模型「高增长→过渡→永续」的语义）。备选：`g2 = gk`（此时三阶段退化为「两阶段但高增长期更长」，语义打折）。
8. **提示词契约改为「大模型只返回 rationale」**，并把确定性参数作为事实喂进用户消息（推荐，理由见 11.7）。备选：契约不变（模型仍返回数值但被覆盖）——省去提示词改动，但模型写理由时依据自己臆造的数字，容易与最终参数矛盾，且多耗 token。
9. **`normalizeValuation` 删除**（推荐，参数已整体覆盖，保留会误导）。备选：保留为「防御性清洗」——但对最终响应无任何作用，属死代码。
10. **`warning` 的判据用最新年报单年 FCF**（对应 R4 默认 `fcf_mode=latest`）（推荐）。注意其在用户改过 R4 基期选取方式时可能不适用，文案已用「可能」软化。
