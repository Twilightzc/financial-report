## 1. 背景与目标

### 1.1 背景

AI 智能分析（R5）目前是「就这家公司论这家公司」：输出评分、结论、行业定性、业务板块与估值推荐，但**不告诉用户还有哪些公司值得顺手一看**。

- 用户看到「业务板块分析」里的「白酒」「锂电池」等板块名后，想知道这个行业/板块的龙头是谁、能不能直接点过去看它的财报，目前只能自己回忆公司名、再回到搜索框手动查。
- 用户看一家公司时，除了「这个行业里最大的是谁」，还想知道「和它体量相当、直接抢生意的是谁」；只给行业龙头榜会漏掉规模相近的直接竞争者。
- 用户判断一家公司在产业链中的位置时，需要知道它的上游供应商、下游客户与合作伙伴；这些信息散落在研报和公告里，工具内没有任何入口。
- 最初设想三类信息都由 AI 输出，但大模型给股票代码容易幻觉（记错、编造、张冠李戴），直接把 AI 代码用于跳转会把用户带到错误的公司页面。
- 实测发现：**行业分类与同行市值榜都有确定性数据源**——财报行自带 `INDUSTRY_CODE` / `INDUSTRY_NAME`，东财 `IndustryAnalysis` 接口直接给出同行业按总市值排序的公司列表与自身排名。因此龙头公司与主要竞争对手都不需要 AI 生成，可做到确定性、可验证、带可靠代码；AI 只负责更难结构化、但允许「参考」的细分业务、产业链与合作关系。

### 1.2 目标

- AI 分析结果中新增四类来源不同的「相关公司」信息，并与现有分析结论同屏展示：
  1. **行业龙头（确定性）**：后端按公司所属行业读取同行市值榜，取 0–3 家，带可靠代码、可直接跳转；
  2. **主要竞争对手（确定性）**：基于同一份同行市值榜，以当前公司市值排名为锚，取前后相邻的规模相近公司，0–4 家，带可靠代码、可直接跳转；
  3. **细分业务相关公司（AI 推断）**：在每个主营构成板块下列出 0–3 家相关公司，以名称为主，点击时复用现有搜索解析为 A 股代码；
  4. **产业链上下游 + 合作 / 关联公司（AI 推断）**：围绕公司主要主业各列 0–3 家，以名称为主，点击时复用现有搜索解析为 A 股代码。
- 四类信息按来源与可靠性分别标注：龙头标「行业龙头 · <行业名>（按总市值排序）」，竞争对手标「主要竞争对手 · <行业名>（按市值排名相邻）」，细分业务相关与产业链标「AI 推断 · 供参考」，合作公司标「AI 推断 · 需核实」。
- AI 不再输出龙头与竞争对手；不新增第二次大模型调用。龙头与竞争对手共用一次上游接口请求，失败时静默降级为空，不影响 AI 分析主体。
- AI 未返回、返回空或字段异常时，对应小节不显示；评分、结论、估值推荐与现有页面行为保持 0 回归。

### 1.3 可衡量目标

- **龙头确定性**：同一只股票、同一份上游数据，返回的龙头名单、顺序与代码完全一致（无 AI 参与、无随机）。
- **龙头可跳转性**：点击任意一家非本公司龙头，直接使用其代码切换股票，**不发起名称搜索请求**，最终打开的公司与点击项一致。
- **竞争对手邻接性**：`competitors` 中每家公司都与当前公司同属一个行业榜单、与自身排名距离 ≤ 2、且不是当前公司本身；同一上游数据下名单与顺序完全一致。
- **竞争对手可跳转性**：点击任意一家竞争对手，直接使用其代码切换股票，**不发起名称搜索请求**，最终打开的公司与点击项一致。
- **AI 公司可解析性**：点击任意一家 A 股细分业务/产业链/合作公司，最终打开的公司名称与用户点击的名称完全一致；解析失败时明确提示，不发生错误跳转。
- **细分业务覆盖**：每个业务板块最多展示 3 家相关公司；某板块 AI 未返回或返回空时，该板块不显示相关公司行，其余内容不受影响。
- **降级可靠性**：行业接口超时、返回异常、公司排名缺失或行业字段缺失时，龙头与竞争对手区域为空且不报错，AI 分析的评分/结论/估值展示不受影响。
- **成本可控**：不新增第二次 LLM 调用；新增 AI 输出控制在约 900 tokens 以内；分析阶段只新增一次行业接口请求（龙头与竞争对手共用）。
- 在 320px / 375px / 768px 视口下，相关公司区域不出现横向滚动。

## 2. 用户故事 / 使用场景

- 作为正在研究某只 A 股的个人投资者，我在「行业分析」里看到公司所属行业（如「白酒Ⅱ」）后，想直接看到该行业按总市值排序的龙头公司，并一键点进去查看其财报，以便横向比较。
- 作为关注直接竞争格局的投资者，我想看到与当前公司体量相近、市值排名前后相邻的同业公司，而不是只看到行业里最大的几家巨头，以便做更贴近的横向对比。
- 作为研究多业务公司的投资者，我想在「动力电池 / 储能电池 / 电池材料」每个细分业务下分别看到相关公司，而不是只看到一个公司级行业龙头名单，以便按业务线找对标。
- 作为想理解公司产业位置的投资者，我想看到围绕其主营业务的上下游公司与合作方，以便判断它对上游的依赖、对下游客户的议价能力与外部合作绑定程度。
- 作为不记得股票代码的用户，我只想点一下公司名就跳到它的分析页：龙头名单由系统直接给出代码，点了就能进；AI 给的公司名也由系统自动解析，不需要我复制粘贴，更不能把我带到错误的公司。

## 3. 功能需求

### 3.1 数据来源与输出结构

#### 3.1.1 数据来源与生成方式

| 信息类型 | 来源 | 生成方式 | 代码可信度 | 数量 |
| --- | --- | --- | --- | --- |
| 行业龙头 `leaders` | 财报行 `INDUSTRY_CODE` / `INDUSTRY_NAME` + 东财 `IndustryAnalysis` 同行市值榜 | **后端确定性获取**，不经过大模型 | 高（接口原始代码，6 位数字校验后直接使用） | 0–3 家 |
| 主要竞争对手 `competitors` | 同一份 `IndustryAnalysis` 同行市值榜（含 `gsgm[0].TOTAL_CAP_RANK`） | **后端确定性获取**，不经过大模型 | 高（接口原始代码，6 位数字校验后直接使用） | 0–4 家（单侧 ≤2 家） |
| 细分业务相关公司 `businesses[].related` | 大模型（输入含主营构成与六维指标） | AI 推断 | 低（仅名称可信；代码可选、仅作消歧） | 每板块 0–3 家 |
| 产业链上下游 `chain.upstream` / `chain.downstream` | 大模型（输入含主营构成与六维指标） | AI 推断 | 低（仅名称可信；代码可选、仅作消歧） | 各 0–3 家 |
| 合作 / 关联公司 `partners` | 大模型 | AI 推断 | 低（同上，且合作关系时效性最弱） | 0–3 家 |

- 行业分类优先取本次分析所用报表行中的 `INDUSTRY_CODE` / `INDUSTRY_NAME`；若最新年报行缺失，可回退到报表范围内最近一期带行业字段的行。行业字段仅用于展示与说明，**不改变三大报表与六维分析的任何展示**。
- 同行榜请求使用公司自身的市场前缀（沪 `SH` / 深 `SZ` / 京 `BJ`）+ 6 位代码；市场前缀判定沿用项目现有能力，北交所按既有已知限制处理。该请求同时服务 `leaders` 与 `competitors`。
- 同行榜需过滤「行业平均」「行业中值」等哨兵行以及代码非 6 位数字的行；剩余行按 `TOTAL_CAP` 降序（同市值按代码升序，保证确定性）取前 3，用于 `leaders`。
- 龙头榜应将 `gsgm`（自身）与 `gsgm_zsz[]`（同行）合并、按代码去重后统一排序；当前公司自身保留并标记 `is_self=true`，自身条目不参与点击跳转（见 FR-5）。
- 主要竞争对手与龙头共用同一次 `IndustryAnalysis` 响应：在完成过滤、去重、排序后的同一张同行榜上，按当前公司排名 `R` 另取前后相邻公司（规则见 FR-12）；**不得为竞争对手新增接口请求**。
- 细分业务相关公司按业务板块独立输出、独立清洗、独立截断，不做跨板块合并；同一公司可在不同板块、或与 `leaders` / `competitors` / `chain` / `partners` 重复出现（角色不同），去重只在单个列表内进行。

#### 3.1.3 行业龙头 / 主要竞争对手项 `LeaderCompany`（后端回填）

| 字段 | 类型 | 必填 | 说明与约束 |
| --- | --- | --- | --- |
| `name` | string | 是 | 接口返回的证券简称，去除首尾空白；为空则丢弃 |
| `code` | string | 是 | 6 位数字；非 6 位数字一律丢弃 |
| `market` | string | 是 | `sh` / `sz` / `bj` |
| `market_label` | string | 是 | `沪` / `深` / `京` |
| `total_cap` | number | 否 | 总市值（元）；用于排序与调试，界面不强制展示 |
| `total_cap_rank` | number | 否 | 同行总市值排名（从 1 开始）；缺失时按本次排序下标 +1 |
| `is_self` | bool | 否 | 是否为当前分析的公司；缺失按 `false` 处理。竞争对手列表不包含自身，该字段恒为 `false` |
| `rank_distance` | number | 否 | 竞争对手专用：与当前公司市值排名的距离（1 = 相邻）；龙头项不带该字段 |

`leaders` 容器字段：`industry_code`（可选）、`industry_name`（可选）、`companies`（0–3 家，按总市值降序）。

`competitors` 容器字段：`industry_code`（可选）、`industry_name`（可选）、`self_rank`（可选，当前公司市值排名，从 1 开始）、`companies`（0–4 家，按 `total_cap_rank` 升序即总市值降序）。

#### 3.1.4 AI 公司项 `CompanyRef`（细分业务相关 / 产业链 / 合作公司共用）

| 字段 | 类型 | 必填 | 说明与约束 |
| --- | --- | --- | --- |
| `name` | string | 是 | **证券简称**（如「贵州茅台」「宁德时代」），不得使用「XX股份有限公司」等法定全称；去除首尾空白，长度 ≤ 30 字 |
| `code` | string | 否 | 6 位数字；**仅作解析时的候选消歧提示**，不直接展示、不单独用于跳转；非 6 位数字一律丢弃 |
| `market` | string | 否 | `A股` / `非A股`，缺省按 `A股` 处理；`非A股` 仅展示、不可跳转 |
| `relation` | string | 否 | 关系标签，如「上游原材料」「下游客户」「战略合作」「渠道合作」；长度 ≤ 20 字 |
| `note` | string | 否 | 一句话说明，长度 ≤ 30 字；不得包含买卖建议或评级 |

#### 3.1.5 位置约定

- `leaders`：顶层新增对象，由后端在 AI 解析完成后确定性回填；表示公司整体所属行业的龙头榜，与 `businesses` **不做一一绑定**。
- `competitors`：顶层新增对象，与 `leaders` 同源、同一次接口获取；表示与当前公司市值排名相邻的规模相近竞争者，与 `businesses` 不做绑定（见 FR-12）。
- `businesses[].related`：挂在每个业务板块条目下，表示该细分业务的相关公司（AI 推断），与板块一一对应；与顶层 `leaders` / `competitors` 的定位不同（见 FR-1 / FR-11 / FR-12）。
- `chain.upstream` / `chain.downstream`：顶层新增 `chain` 对象，围绕公司**营收占比最大的主营板块**给出。
- `partners`：顶层新增数组，表示合作 / 关联公司。

> 说明：以上为接口契约层面的要求，具体 Go 结构体命名与 `omitempty` 策略由技术设计确定；但「缺省不报错、空列表可省略、旧响应可兼容」的行为要求不变。

### 3.2 关键设计结论与理由

| 设计点 | 结论 | 理由 |
| --- | --- | --- |
| 龙头来源 | **后端确定性获取**（财报行业字段 + 东财同行市值榜），AI 不输出龙头 | 实测数据源准确、代码可靠，彻底消除龙头名单的幻觉风险；还能省掉这部分 AI 输出 token |
| 竞争对手来源 | 与龙头**同一份**同行市值榜确定性提取，AI 不输出竞争对手 | 同一请求内即可得到；按市值排名相邻定义「规模相近」客观、可复现，且无需额外 token 与请求 |
| 竞争对手 vs 行业龙头 | `leaders` = 行业市值前 3 的巨头；`competitors` = 自身排名前后相邻、规模相近的直接竞争者（单侧 ≤2、合计 ≤4） | 龙头回答「行业最大的是谁」，竞争对手回答「和我抢生意的是谁」；对非龙头公司尤其有意义，比遥远的行业巨头更具可比性 |
| 功能拆分 | 四层：`leaders`（确定性行业龙头）+ `competitors`（确定性规模相近竞争者）+ `businesses[].related`（AI 细分业务）+ `chain` / `partners`（AI 产业链/合作） | 各类数据可靠性、跳转方式、免责强度不同，必须分开建模与标注 |
| 细分业务 vs 行业龙头 | `leaders` = 公司整体所属行业的确定性龙头；`businesses[].related` = 各细分业务的 AI 相关公司 | 多业务公司的行业分类只有一个，无法覆盖各业务线；二者互补，不能互相替代，也不能把龙头名单整段复制到每个板块 |
| 代码幻觉 | 龙头与竞争对手代码直接可信、按代码跳转；AI 公司的 `code` 仅作搜索候选消歧、永不直接展示或单独跳转 | 把「可信代码」与「AI 给的代码」在数据结构和交互上彻底分开，避免一条链路污染另一条 |
| 可靠性分级 | 龙头与竞争对手（数据来源）、细分业务（AI 中等）、产业链（AI 中等）、合作（AI 最低） | 龙头与竞争对手可按市值排名验证；细分业务与产业链随公司而异；合作关系的时效性与真实性最难保证 |
| 交互 | 龙头 / 竞争对手点击直接按代码切换；AI 公司点击按名称走搜索解析；均同页切换 | 与现有 `doSearch()` 一致，不新开页面；两类路径各自用最可靠的主键 |
| 展示位置 | 龙头与竞争对手放在「行业分析」小节内（龙头在上、竞争对手紧随其下）；细分业务相关公司放在各业务板块卡片内；产业链上下游 + 合作公司放在「业务板块分析」之后、「估值模型推荐」之前 | 龙头与竞争对手都是公司级行业数据，放在行业名称旁边最自然；细分业务相关公司与板块一一对应；产业链与合作方属于公司整体视角 |
| 边界 | 龙头 3 家、竞争对手 4 家（单侧 ≤2）、其余每块 3 家；空则整块不显示；不新增 LLM 调用；行业接口失败静默降级 | 控制冗长、幻觉面与 token；接口失败不能拖垮 AI 分析主体 |
| 「一键分析」快捷 | 本期**不做**每家公司的 AI 分析快捷入口；点击只加载该公司的财务数据 | AI 分析按 R5 设计必须由用户显式触发，自动触发会带来数分钟等待与不可控 token 消耗 |

### 3.3 功能条目

#### FR-1 行业龙头（确定性获取，P0）

- **触发**：AI 分析成功返回；后端在处理过程中按公司所属行业获取同行市值榜。
- **要求**：
  - 龙头名单**必须**由后端确定性获取，**不得**由大模型生成或改写；AI 若返回 `leaders` 字段一律忽略。
  - 按 `TOTAL_CAP` 降序展示 **0–3 家**；同市值按代码升序，保证同一份数据下顺序稳定。
  - 过滤「行业平均」「行业中值」等哨兵行，以及代码非 6 位数字、名称为空的行。
  - 当前公司自身若出现在榜中，**保留**并标记为「本公司」，用于展示其在行业中的市值位次；该条不可点击。
  - 展示标题为「行业龙头 · <行业名>（按总市值排序）」（如「行业龙头 · 白酒Ⅱ」）；行业名缺失时只显示「行业龙头（按总市值排序）」。
  - 龙头名单不参与 AI 评分、结论与估值，也不影响 `businesses` 的内容。
  - **与细分业务相关公司的区别**：`leaders` 是公司整体所属行业的龙头榜（确定性、单一行业）；`businesses[].related` 是各细分业务的相关公司（AI 推断，见 FR-11）。二者互补，不得互相覆盖或合并去重。
  - **与主要竞争对手的区别**：`leaders` 取行业市值前 3；`competitors` 取当前公司排名前后相邻的公司（见 FR-12）。二者同源但口径不同，允许名单重叠。
- **边界**：
  - 行业接口超时、返回异常、无有效同行、公司无行业分类 → `leaders.companies` 为空，**静默降级**，不弹错、不阻塞分析。
  - 同行不足 3 家时按实际数量展示。
  - **本期不提供「每个业务板块各自的龙头」**：确定性数据源只给出公司所属的一个行业分类，无法可靠地把每个主营板块映射到不同行业。若后续技术设计能建立稳定的「板块名 → 行业」映射，可作为增强项另行评估，本期不作为验收项。
  - 行业分类可能较宽（如「电池」「军工电子Ⅱ」），龙头名单反映的是该分类下的市值排序，不代表产品对「优质」的评价。

#### FR-2 产业链上游 / 下游公司（AI 推断，P1）

- **触发**：AI 分析成功返回，且 `chain.upstream` 或 `chain.downstream` 非空。
- **要求**：
  - 围绕公司**主要主业**（多主业时以营收占比最大的板块为准）列出上游与下游公司，各最多 **3 家**。
  - 上游指原材料、零部件、设备、能源等供应商侧公司；下游指客户、渠道、终端应用等需求侧公司。
  - 每家公司的 `relation` 应说明其在链条中的角色（如「锂矿/正极材料」「整车厂」「经销渠道」）。
  - **竞争对手不得放入上游 / 下游**；竞争同行由「行业龙头」与「主要竞争对手」承载。
- **边界**：
  - 上游或下游为空 → 只隐藏对应的子块；两者都为空 → 整个「产业链上下游」子块不显示。
  - 主营构成数据缺失时，AI 可基于公司名称与行业常识推断，但必须在 `note` 中降低断言强度（如「据公开信息」）；仍无把握时输出空数组。
  - 非 A 股公司（海外 / 未上市）按 FR-5 的非 A 股规则处理。

#### FR-3 合作 / 关联公司（AI 推断，P1）

- **触发**：AI 分析成功返回，且 `partners` 非空。
- **要求**：
  - 列出与当前公司有**公开可查**合作关系的公司，最多 **3 家**；合作关系包括战略合作、合资、长期供货/采购、渠道合作等。
  - 每家公司必须给出 `relation`（合作类型）与可选 `note`（合作内容的一句话说明）。
  - AI 只能列出其有较高把握、公开可查的合作关系；**不确定时输出空数组**，不得编造。
  - 该子块必须展示强免责文案（见 FR-7）。
- **边界**：
  - `partners` 为空或全部条目无效 → 整个子块不显示。
  - 合作关系可能已终止或未公开披露，产品不承诺准确性；用户以公司公告为准。

#### FR-4 公司项的清洗、去重与上限（P0）

- **行业龙头（确定性数据）**：
  - `name` 去除首尾空白；`code` 必须为 6 位数字，否则丢弃该条。
  - 过滤哨兵行（名称含「行业平均」「行业中值」）与重复代码（同一代码只保留首次出现项）。
  - 按 `total_cap` 降序排序后截取前 3；`total_cap` 缺失时沿用接口返回顺序，不得随机重排。
  - 当前公司自身保留并标记 `is_self`，其余条目 `is_self=false`。
- **主要竞争对手（确定性数据）**：
  - 与龙头的清洗规则一致（`name` 非空、`code` 为 6 位数字、过滤哨兵行与重复代码）。
  - 排除当前公司自身；不产生 `is_self=true` 条目。
  - 按 FR-12 的相邻规则取数，单侧最多 2 家、合计最多 4 家；不足时按实际数量展示，不用更远排名补位。
  - `rank_distance` 缺失时按 `|total_cap_rank − self_rank|` 计算；仍无法得出时保留该条但不展示距离。
- **AI 公司项（细分业务相关 / 产业链 / 合作）**：
  - `name` 去除首尾空白；为空则丢弃该条目。
  - `code` 仅在为 6 位数字时保留，否则视为无代码；不得因代码格式非法而丢弃整家公司。
  - `market` 仅接受 `A股` / `非A股`，其余值按 `A股` 处理。
  - `relation` / `note` 去除首尾空白，超长时截断并加省略号（`relation` ≤ 20 字，`note` ≤ 30 字）。
  - 同一列表内按归一化名称（去空白、大小写不敏感，与 R11 `NormalizeQuery` 同口径）去重，保留首次出现项。
  - 规范化后名称与当前公司名称相同 → 丢弃，避免「自己推荐自己」。
  - `businesses[].related` 的清洗与产业链/合作公司一致：按板块独立执行「排除自身 → 去重 → 截断」；某板块条目全部无效时该板块的 `related` 为空。
- **共同上限与展示约束**：
  - `leaders.companies` 3 家，`competitors.companies` 4 家（单侧最多 2 家），`businesses[].related` 每板块 3 家，`chain.upstream` 3 家，`chain.downstream` 3 家，`partners` 3 家。
  - **去重只在单个列表内进行**：同一公司可在不同业务板块、或与 `leaders` / `competitors` / `chain` / `partners` 重复出现（角色不同），不得跨列表合并或删除。`leaders` 与 `competitors` 的重叠是预期行为（龙头排名靠前时，竞争对手会包含龙头榜中的公司）。
  - 所有列表按既定顺序展示，**不做「优质度/收益率」排序**，不展示任何股价、评级或买卖建议；龙头可保留总市值/排名字段用于排序，但界面不强制展示。

#### FR-5 跳转可靠性：龙头 / 竞争对手按代码、AI 公司按名称（P0）

- **行业龙头 / 主要竞争对手点击（可信代码路径）**：
  - 点击非本公司龙头或任意竞争对手时，先校验其 `code` 为 6 位数字，然后**直接以该代码**走现有换股流程；**不得**发起名称搜索请求。
  - 点击标记为「本公司」的龙头不产生跳转（可滚动回结果区顶部），避免无意义重载；竞争对手列表不含自身，全部可点击。
  - 龙头 / 竞争对手代码来自确定性接口，但仍需做 6 位数字与空值校验；非法条目不渲染为可点击。
- **AI 细分业务相关 / 产业链 / 合作公司点击（名称解析路径）**：
  - `businesses[].related` 的点击行为与产业链 / 合作公司完全一致，不得因它挂在业务板块下就改用代码跳转。
  - 界面上以**公司名称**为唯一展示主键；AI 返回的 `code` **不得直接展示为可点击代码**，也不得作为跳转路径参数。
  - 点击时调用现有 `GET /api/stock/search?q=<公司名>` 解析（复用 `fetchSearch()` 与 60s 缓存），按以下顺序确定目标公司：
    1. 归一化名称与某候选 `name` **完全相等** → 选中该候选；
    2. 无完全相等、但检索结果**有且仅有 1 条**候选 → 选中该候选；
    3. 以上均不满足（存在多条非精确候选）→ **不切换股票**，给出可读提示（推荐文案：「未找到唯一匹配的 A 股公司，请手动搜索「<公司名>」」）。
  - **AI 代码的作用边界**：`code` 不在界面展示，也不作为跳转参数；仅在「完全同名候选多于一条」时用于消歧，且必须**同时满足**：① 为 6 位数字；② 出现在该名称的检索结果中；③ 对应候选的名称与查询完全相等。任一不满足即忽略 AI 代码，按检索结果或失败处理。**不得**用 AI 代码在非精确候选之间做选择（例如名称只写了「平安」时，不能靠代码把用户带去「平安银行」）。
  - 如后续产品需要在标签上展示代码，只能展示「经当前名称检索命中且名称完全一致」的解析结果代码，**绝不展示 AI 原始代码**。
- **通用交互约束**：
  - 非 A 股（AI 项 `market=非A股`）公司展示「非A股」标记，**不可点击**；点击时提示「非 A 股公司，暂不支持财报分析」。
  - 同一时刻只允许一个解析/跳转请求处于进行中；被点击的标签在解析期间显示 loading / 禁用态，防止连点发起多次切换。
  - 搜索服务不可用 / 超时 → 静默降级为行内提示，不弹全局错误、不切换股票。
  - 所有跳转最终必须使用 6 位数字代码；禁止把 AI 返回的任意字符串拼进 `/api/stock/:code/...` 路径。

#### FR-6 点击跳转与页面行为（P0）

- **触发**：FR-5 任一解析路径成功。
- **要求**：
  - 行为与用户在搜索框选中该股票后点击「查询」**完全一致**：回填搜索框代码、记录搜索历史、加载指标 / 三大报表 / 六维分析 / 估值，并停留在**同一页面**。
  - **不得**自动触发该公司的 AI 分析；AI 分析仍由用户点击「一键分析」显式发起。
  - 切换股票后沿用现有行为：清空当前 `aiResult`（避免残留上一家公司的分析），页面滚动到结果区顶部，让用户看到新公司抬头。
  - 原公司的 AI 结果已在前端 `aiCache` 中保留：切回原股票后再次点击「一键分析」应直接复用缓存，不重复消耗 token（现有能力，不得回退）。
- **边界**：解析失败或用户取消时不改变当前股票、不清空当前 AI 结果。

#### FR-7 可靠性分级与免责文案（P0）

- **要求**：不同来源按不同口径标注，文案必须在界面上可见（不依赖 hover）：

| 信息类型 | 标签 / 标题后缀 | 免责说明（推荐措辞） |
| --- | --- | --- |
| 行业龙头 | 「行业龙头 · <行业名>（按总市值排序）」 | 「名单来自东财行业分类与同行市值数据，按总市值排序，随行情与行业分类更新；排序不代表投资价值，不构成投资建议。」 |
| 主要竞争对手 | 「主要竞争对手 · <行业名>（按市值排名相邻）」 | 「名单来自东财行业分类与同行市值数据，按与本公司市值排名相邻选取；排名不代表投资价值，不构成投资建议。」 |
| 细分业务相关公司 | 「AI 推断 · 供参考」 | 「基于该业务板块的 AI 推断，可能与公司级行业龙头或其他板块重叠，仅用于拓展研究。」 |
| 产业链上下游 | 「AI 推断 · 供参考」 | 「基于公司主营业务的产业链推断，不代表真实交易关系。」 |
| 合作 / 关联公司 | 「AI 推断 · 需核实」 | 「合作关系可能已变化或未被公开披露，请以公司公告为准；不构成投资建议。」 |

- 相关公司区域（或整张 AI 卡片）应有一句统一的弱化说明：细分业务相关、产业链与合作公司信息由 AI 生成，龙头与竞争对手信息来自第三方数据，均仅用于拓展研究，不构成投资建议。
- AI 输出中不得出现「推荐买入 / 增持 / 目标价 / 强烈推荐」等投资建议措辞；`note` 只描述行业地位或合作关系。
- 当 AI 输出的名称与检索解析结果冲突时，**以检索结果为准**，界面展示解析到的证券简称。

#### FR-8 展示位置与移动端适配（P1）

- **展示位置**（沿用现有卡片式结果区）：
  1. **行业龙头与主要竞争对手**：都放在「行业分析」小节内，现有「前景 / 竞争格局 / 应用方向」之后；先展示「行业龙头 · <行业名>（按总市值排序）」子块，其下再展示「主要竞争对手 · <行业名>（按市值排名相邻）」子块，均为公司标签列表；不重复挂到每个业务板块卡片下。
  2. **细分业务相关公司**：放在「业务板块分析」每个板块卡片内，现有「风险」行之后，展示一行「相关公司」标签；该板块无相关公司时不显示该行，也不留空标题。此处只展示该细分业务的 `related`，不重复展示公司级 `leaders` / `competitors`。
  3. **相关公司（产业链 / 合作）**：新增小节，位于「业务板块分析」之后、「估值模型推荐」之前：
     - 子块一「产业链上下游」：桌面端「上游」「下游」左右两栏，窄屏上下堆叠；
     - 子块二「合作 / 关联公司」：单列标签列表。
  4. 每个公司标签建议包含：公司名称 +（可选）关系标签 +（非 A 股时）「非A股」标记 +（龙头为本公司时）「本公司」标记 +（竞争对手可选）排名标记（如「第 2」）。
- **移动端**：
  - 公司标签允许换行排布，不得出现横向滚动。
  - 触控目标高度 ≥ 28px；相邻标签间距足够，避免误触。
  - 长公司名允许换行或省略号截断，但必须保留可读的名称主体；不得把名称截成单字。
  - 关系标签与名称在窄屏下可分行，不重叠。
- **空态**：
  - 龙头为空 → 「行业龙头」子块整体不显示；
  - 竞争对手为空 → 「主要竞争对手」子块整体不显示；二者都为空时「行业分析」仅保留原有内容；
  - 某板块 `businesses[].related` 为空或全部条目无效 → 该板块不显示「相关公司」行，板块的前景/风险等原有内容照常显示；
  - 单个 AI 列表为空 → 隐藏对应子块 / 行；
  - 「产业链上下游」与「合作公司」都为空 → 整个「相关公司」小节不显示，不出现空标题。

#### FR-9 降级、容错与兼容（P0）

- **龙头 / 竞争对手数据降级**：
  - 行业接口超时、网络失败、返回非 JSON、返回空列表或字段异常 → `leaders.companies` 与 `competitors.companies` 均为空，**静默降级**；不得使 AI 分析请求失败，不弹全局错误。
  - 行业字段（`INDUSTRY_CODE` / `INDUSTRY_NAME`）缺失不阻塞同行榜请求；仅影响标题中的行业名展示。
  - 竞争对手依赖同一份榜单与自身排名：排名缺失且无法从榜单推断、有效同行不足 2 家、榜单仅含自身 → `competitors.companies` 为空，不报错、不触发额外请求。
  - 龙头 / 竞争对手数据获取与 AI 调用相互独立：任一失败不影响另一方；接口失败时评分、结论、业务板块、估值推荐照常返回。
- **AI 返回缺字段 / 空数组 / 类型异常**：
  - `businesses[].related`、`chain`、`partners` 缺失、为 `null`、空数组或类型不符合契约时，**按空处理并跳过展示**，不得导致 `ParseAIResult` 整体失败。
  - 单条公司项字段异常（如 `code` 为数字、`note` 非字符串等）只丢弃该条或该字段，不影响同列表其他公司，也不影响评分 / 结论 / 估值展示。
  - 某板块的 `related` 异常只影响该板块的相关公司行，不影响该板块的前景/风险，也不影响其他板块。
- **不新增 LLM 调用**：`businesses[].related` / `chain` / `partners` 必须复用现有的一次 LLM 调用与分析阶段已取到的数据；**不得**为此新增第二次大模型调用。
- **网络请求边界**：
  - 分析阶段最多新增 **1 次** `IndustryAnalysis` 上游请求，龙头与竞争对手共用该次响应；不得为每个业务板块、细分业务或竞争对手重复请求。`businesses[].related` 随同一次 LLM 调用返回，不产生额外请求。
  - 渲染相关公司列表时**不得**为解析代码而批量调用搜索接口；AI 公司的解析只在用户点击时发生。
  - 行业榜单数据（龙头与竞争对手）建议使用短 TTL 缓存或与 AI 结果一并缓存（具体由技术设计定），但不得改变现有 AI 缓存 key。
- **缓存兼容**：后端 AI 缓存（10 分钟 TTL）与前端 `aiCache` 的 key 均不变；升级后命中旧缓存时，结果中没有新增字段，页面按空处理、其余内容正常展示。若本次行业接口抓取失败，缓存中的龙头与竞争对手为空，TTL 内不自动重试（属可接受降级）。
- **历史记录不受影响**：R16 估值历史记录、R4 估值计算、R5 五维评分与估值推荐均不因本需求改变；相关公司数据不写入估值记录、不参与估值。

#### FR-10 提示词与 AI 输出质量约束（P0）

系统提示词必须新增以下约束（措辞可由技术设计打磨，约束本身不可省）：

- **AI 不输出行业龙头与主要竞争对手**：明确告知大模型「行业龙头与主要竞争对手由系统确定性获取，不要在结果中输出」；即使返回 `leaders` / `competitors` 字段也由后端忽略/覆盖。
- **必须输出细分业务相关公司**：每个 `businesses[]` 条目必须包含 `related` 数组，围绕该板块的产品、技术或应用列出 0–3 家相关公司；无把握时输出空数组。
- 输出 JSON 必须包含 `businesses[].related`、`chain.upstream`、`chain.downstream`、`partners` 四组字段；无内容时输出空数组。
- 公司统一使用**证券简称**，不使用法定全称；优先 A 股上市公司。
- 每个业务板块的 `related` 最多 3 家；上游、下游、合作公司各最多 3 家；不得包含当前公司自身；同一列表内不得重复。
- `businesses[].related` 必须与该板块的业务直接相关（如同类产品/竞品、该业务的上下游、客户或应用方），**不得把公司级行业龙头名单整段复制到每个板块**，也不得跨板块套用同一组公司；`relation` 应说明其与该细分业务的关系（如「同类高端白酒」「储能电芯客户」）。
- `code` 为可选项，**只在确信时填写**，不确定就留空；不得猜测或编造代码。
- 合作关系只列公开可查、较高把握的内容；不确定时输出空数组，**不得编造合作方**。
- `relation` / `note` 保持简短（各自 ≤ 20 / 30 字），只描述产业链角色或合作内容，不写买卖建议、评级、目标价。
- 产业链上下游必须围绕公司**营收占比最大的主营板块**展开；公司主业不清晰时优先少列或不列。
- 不得改动既有 `scores / conclusion / industry / businesses` 原有字段（`name/stage/contribution/prospect/risk`）与 `valuation` 的任何内容；`businesses` 内只允许新增 `related`，AI 输出顶层只允许新增 `chain` / `partners`（`leaders` / `competitors` 由后端回填，不属于 AI 输出）。

#### FR-11 细分业务相关公司（AI 推断，P1）

- **触发**：AI 分析成功返回，且某个 `businesses[].related` 非空。
- **要求**：
  - 每个业务板块（主营构成板块）下展示该细分业务的相关公司，0–3 家；使用 `CompanyRef` 结构，以名称为主。
  - `related` 应与该板块的产品 / 技术 / 应用直接相关，例如同类产品/竞品、该业务的上游供应商、下游客户或应用方；`relation` 说明其与该细分业务的关系。
  - 不得把公司级 `leaders` 名单整段复制到每个板块，也不得让所有板块共用同一组公司。
  - 当前公司自身不得出现在 `related` 中；同一板块内按名称去重，超出 3 家截断。
  - 点击行为与 FR-5 的 AI 公司路径一致：按名称走搜索解析；非 A 股不可点击。
- **与 `leaders` 的关系**：
  - `leaders` = 公司整体所属行业的确定性龙头榜（单一行业、按总市值排序、可靠代码）；
  - `businesses[].related` = 各细分业务的 AI 相关公司；
  - 多业务公司（如宁德时代：动力电池 / 储能电池 / 电池材料）二者互补，同时展示，不互相替代、不跨列表去重。
- **边界**：
  - 某板块 `related` 缺失、为空或全部条目无效 → 该板块不显示相关公司行；板块的前景 / 风险等原有内容照常显示。
  - AI 对细分业务不熟悉时允许输出空数组；不得为了凑数编造公司。
  - 细分业务名称是公司自定义口径，可能与行业标准分类不同；不要求与 `leaders.industry_name` 对齐。
  - 不新增 LLM 调用与上游请求；复用同一次 AI 输出。

#### FR-12 主要竞争对手（确定性获取，P0）

- **触发**：AI 分析成功返回；后端在获取行业龙头榜的同一次 `IndustryAnalysis` 响应中一并计算，不新增请求。
- **定义**：主要竞争对手 = 与当前公司同属一个行业分类、按总市值排名与当前公司**相邻**的规模相近公司；`leaders` 是行业市值最大的前 3 家，`competitors` 是与自身体量相当的直接竞争者，二者口径不同。
- **取值规则（必须确定性）**：
  1. 使用与 FR-1 完全相同的清洗后同行榜：过滤哨兵行与非法行、按代码去重、按 `TOTAL_CAP` 降序、同市值按代码升序排列，得到长度为 `N` 的榜单。每行的**有效排名**优先取接口 `TOTAL_CAP_RANK`（须为正整数），缺失或非法时取该行在榜单中的位置（从 1 开始）；有效排名重复时按榜单顺序保留首次出现项。
  2. 确定当前公司基准排名 `R`：优先取接口 `gsgm[0].TOTAL_CAP_RANK`（须为正整数且落在 `1..N`）；缺失或非法时，按当前公司代码在榜单中的位置（从 1 开始）确定；仍无法确定 → `competitors.companies` 为空。
  3. 候选顺序固定为有效排名 `R-1`、`R+1`、`R-2`、`R+2`（由近及远，同距离先上后下）；跳过越界、非法、与当前公司同代码的条目。
  4. **单侧最多 2 家、合计最多 4 家**；某一侧不足时按实际数量展示，不向同侧突破 2 家上限，也不用更远排名补位。
  5. 有效候选少于 2 家（榜单仅含自身，或除自身外的有效同行不足 2 家）→ `competitors.companies` 为空。
  6. 结果按有效排名升序（即总市值降序）展示；`rank_distance` = `|R − 该公司有效排名|`。
- **展示**：与 `leaders` 同在「行业分析」小节，位于龙头子块之下，标题「主要竞争对手 · <行业名>（按市值排名相邻）」；每项展示公司名称，可带排名标签（如「第 2」），不展示股价、评级或买卖建议。
- **跳转**：与龙头同待遇——带可靠代码，点击直接按代码走现有换股流程，不发起名称搜索；本列表不含自身。
- **边界**：
  - 同行榜不足、公司排名缺失且无法从榜单推断、榜单仅含自身 → 为空，**静默降级**，不弹错。
  - 行业接口失败、超时或返回异常 → 与龙头一起为空，不影响 AI 分析主体。
  - 行业分类可能较宽（如「电池」「军工电子Ⅱ」），竞争对手是「同一行业分类下规模相近的公司」，不保证产品/业务完全一一对应。
  - 与 `leaders` 允许重叠（如排名第 1 的公司的竞争对手会包含龙头榜第 2、3 名），**不做跨列表去重**；与 `businesses[].related` / `chain` / `partners` 同样不跨列表去重。
- **成本**：不新增 LLM 调用、不新增上游请求，复用同一次 `IndustryAnalysis` 响应。

## 4. 非功能需求

- **性能 / 耗时**：
  - 分析阶段新增 1 次 `IndustryAnalysis` 上游请求（龙头与竞争对手共用）；该请求必须有明确超时（建议 ≤ 2s），失败或超时只导致龙头与竞争对手为空，**不得阻塞或拖垮** AI 分析主体。
  - 单次 AI 分析的总耗时增量主要来自新增 AI 输出与一次行业接口请求，目标控制在相同分析模式下的 **10% 以内**。
  - 点击龙头 / 竞争对手到发起换股请求应在 **300ms 内**完成（无搜索环节）；点击 AI 公司名到发起换股请求，解析环节应在 **1.5s 内**完成（搜索接口有 60s 缓存）。
  - 渲染 20 个左右的公司标签不得造成明显卡顿；不引入图片、外部请求或复杂图表。
- **Token 预算**：
  - AI 不再输出龙头与竞争对手，但新增 `businesses[].related`；系统提示词新增约 300–400 tokens，单次输出新增约 500–900 tokens；合计增量应控制在现有单次分析用量的 **约 20% 以内**。竞争对手由接口确定性计算，不占 AI token。
  - 不得为此调整 `max_tokens=8192` 上限或新增第二次调用；token 用量展示保持现状。
- **确定性与缓存**：
  - 龙头与竞争对手名单在同一份上游数据下必须确定：固定按 `TOTAL_CAP` 降序、同市值按代码升序，竞争对手按固定候选顺序取数，无随机、无时间依赖。
  - 同一缓存 key 在 TTL 内返回完全相同的结果；跨缓存周期允许行业榜单与 AI 名单变化，界面已用免责文案覆盖该不确定性。
- **兼容性**：
  - 继续使用内嵌 Vue 3 + Element Plus + ECharts（CDN）与现有 CSS，不引入构建步骤或新前端依赖。
  - 不改动 `GET /api/stock/:code/ai-analysis` 的请求参数与统一响应结构 `{code, data, message}`；新增字段只做向后兼容的增量。
- **安全 / 正确性**：
  - 公司名、关系、说明等均为纯文本展示，必须按文本转义，不得作为 HTML 渲染。
  - 所有跳转必须使用 6 位数字代码；龙头与竞争对手代码来自确定性接口也要做格式校验，AI 返回的任意字符串不得拼进 `/api/stock/:code/...` 路径。
- **易用性**：
  - 标记必须让用户一眼区分「可直接跳转的龙头 / 竞争对手」「需解析的 AI 公司」「仅展示的非 A 股」；解析中、解析失败都有明确的行内反馈。

## 5. 边界与约束

- **非目标**：
  - 不做选股器、排行榜、评分榜或「优质公司」客观评价；不展示相关公司的股价、PE、评级或买卖建议。
  - 不做竞争对手市场份额、竞争强度评分、竞争关系图谱或「谁更强」的判断；仅按市值排名相邻关系列出名单。
  - 不做批量对比、批量导入、自选股/收藏、相关公司独立详情页。
  - 不保证 AI 细分业务/产业链/合作名单的完整性、时效性与准确性，也不保证每个细分业务都有相关公司；产品定位是「拓展研究线索」而非「投资建议」。
  - **不做每个业务板块各自的龙头映射**：确定性数据源只提供公司所属的一个行业分类；各细分业务的相关公司由 AI 推断（`businesses[].related`），不是行业龙头榜。
  - 不改变 R4 估值计算、R5 评分维度与结论、R16 估值历史记录的既有逻辑。
- **依赖**：
  - 报表响应行中的 `INDUSTRY_CODE` / `INDUSTRY_NAME`（需补齐 model 映射）；
  - 东财 `PC_HSF10/IndustryAnalysis/PageAjax` 同行市值榜接口（`gsgm` / `gsgm_zsz[]`，龙头与竞争对手共用）；
  - 现有一次 DeepSeek 调用与 `aiSystemFramework` / `ParseAIResult` 链路（新增 `businesses[].related` 输出与容错解析）；
  - R11 的 `GET /api/stock/search` 名称解析能力与前端 `fetchSearch()`；
  - 现有 `doSearch()` 换股链路与 `aiCache`。
- **已知限制**：
  - 行业分类可能较宽或滞后（如「电池」「军工电子Ⅱ」），龙头与竞争对手名单与用户理解的「细分板块」不一定完全对应；「规模相近」仅由总市值排名相邻近似，不代表业务完全同类。
  - 行业接口可能限流/不可用，届时龙头与竞争对手区域均为空；10 分钟缓存内不自动重试。
  - 当前公司排名可能缺失或与榜单不一致（`TOTAL_CAP_RANK` 异常）；回退为榜单位置后仍无法确定时，竞争对手为空。
  - 行业同行数量很少时，竞争对手可能因有效候选不足 2 家而为空。
  - 行业字段可能在某些报表行缺失；缺失时仅影响行业名展示，不影响榜单抓取（榜单只依赖股票代码）。
  - 细分业务是公司自定义口径（如「茅台酒 / 系列酒」），AI 对细分业务的覆盖程度取决于其行业知识；冷门或新兴业务可能返回空数组，属正常降级。
  - 同一公司可能同时出现在 `leaders`、`competitors`、`businesses[].related`、`chain`、`partners` 中（角色不同），去重只在单个列表内进行，跨列表重复不是缺陷；龙头与竞争对手的重叠尤其常见。
  - AI 训练数据可能滞后：细分业务/产业链/合作公司可能已更名、被 ST、退市或关系已终止；解析失败时以行内提示兜底。
  - 搜索只覆盖 A 股（沪/深/京），海外与未上市公司无法跳转，只能作为产业链背景信息展示。
  - 北交所行情前缀存在既有已知限制（R11 T-1），龙头/跳转沿用现有处理。

## 7. 已决策记录（2026-10-17）

- **D1 每块公司数量上限** → **每条列表默认 3 家**（龙头 0–3 家，每个细分业务 `related` 0–3 家，上游/下游/合作各 0–3 家）；**主要竞争对手例外：0–4 家、单侧最多 2 家**。理由：兼顾横向参考价值与结果区简洁度，控制 token 与错误面；竞争对手需要同时覆盖排名上下两侧，故上限放宽到 4 家。
- **D2 是否允许出现非 A 股公司** → **允许展示但不可点击，并标注「非A股」**。理由：产业链上下游常有海外巨头，完全排除会损失关键背景；但本工具无法分析非 A 股，只能作参考。该规则仅适用于 AI 输出的产业链/合作公司；行业龙头与主要竞争对手来自 A 股同行榜。
- **D3 点击公司名是否直接切换股票** → **直接切换、不弹二次确认**，与现有搜索选中即查询的体验一致。当前 AI 结果会按既有逻辑清空，但保留在前端缓存中，切回后可恢复。
- **D4 是否为龙头 / 竞争对手提供「一键分析」快捷入口** → **本期不做**。点击只负责加载该公司的财务数据；AI 分析仍由用户在 AI 卡片中显式点击「一键分析」，避免误触触发数分钟等待与不可控消耗。
- **D5 行业龙头改为后端确定性获取** → **AI 不再输出龙头**。来源：财报行 `INDUSTRY_CODE` / `INDUSTRY_NAME` + 东财 `IndustryAnalysis` 同行市值榜（`gsgm` / `gsgm_zsz[]`）；过滤哨兵行后按 `TOTAL_CAP` 降序取前 3；龙头带可靠代码，点击直接按代码跳转，无搜索解析、无幻觉风险。
- **D6 AI 仅输出细分业务相关公司、产业链上下游与合作公司** → `businesses[].related` / `chain.upstream` / `chain.downstream` / `partners`，以名称为主，`code` 可选且仅作精确同名消歧，点击走 R11 搜索解析。
- **D7 行业龙头展示位置** → 放在「行业分析」小节内，标题带所属行业名；不重复挂到每个业务板块卡片下，避免同一名单在多板块重复，也规避「板块名 → 行业」映射的不确定性。
- **D8 细分业务相关公司走 AI、与公司级龙头互补** → 每个 `businesses[]` 新增 `related`（每板块 0–3 家，AI 推断）。主营构成板块是公司自定义口径，不对应东财标准行业板块，公司级 `IndustryAnalysis` 只有单一行业分类，无法覆盖多业务公司的各细分业务；因此 `leaders`（公司整体所属行业龙头，确定性）与 `businesses[].related`（各细分业务相关公司，AI）同时展示、互为补充，不互相替代，也不跨列表去重。
- **D9 主要竞争对手走接口、与龙头按排名区分** → 新增 `competitors`，与 `leaders` 共用同一次 `IndustryAnalysis` 响应确定性提取，不经过 AI、不新增请求。`leaders` = 行业市值前 3 的巨头；`competitors` = 以当前公司排名 `R` 为锚，按 `R-1 → R+1 → R-2 → R+2` 取前后相邻公司（单侧 ≤2、合计 ≤4、排除自身），带可靠代码、点击按代码直跳。二者同在「行业分析」小节展示（龙头在上、竞争对手在下），允许名单重叠、不跨列表去重。
