## 1. 背景与目标

### 1.1 背景

AI 智能分析（R5）目前是「就这家公司论这家公司」：输出评分、结论、行业定性、业务板块与估值推荐，但**不告诉用户还有哪些公司值得顺手一看**。

- 用户看到「业务板块分析」里的「白酒」「锂电池」等板块名后，想知道这个行业/板块的龙头是谁、能不能直接点过去看它的财报，目前只能自己回忆公司名、再回到搜索框手动查。
- 多业务公司（如宁德时代）横跨动力电池、储能电池等不同业务线，用户想知道**每条业务线各自的龙头**是谁，而不是只看到公司整体所属的一个行业龙头榜。
- 用户判断一家公司在产业链中的位置时，需要知道它的上游供应商、下游客户与合作伙伴；这些信息散落在研报和公告里，工具内没有任何入口。
- 最初设想相关公司信息都由 AI 输出，但大模型给股票代码容易幻觉（记错、编造、张冠李戴），直接把 AI 代码用于跳转会把用户带到错误的公司页面。
- 实测发现：**公司级行业分类与同行市值榜都有确定性数据源**——财报行自带 `INDUSTRY_CODE` / `INDUSTRY_NAME`，东财 `IndustryAnalysis` 接口直接给出同行业按总市值排序的公司列表与自身排名。因此全局行业龙头不需要 AI 生成，可做到确定性、可验证、带可靠代码；但主营构成的细分业务是公司自定义口径，没有干净的「细分业务 → 标准行业 → 龙头」接口，只能由 AI 推断。

### 1.2 目标

- AI 分析结果中新增四类来源不同的「相关公司」信息，并与现有分析结论同屏展示：
  1. **全局行业龙头（确定性）**：后端按公司所属行业读取同行市值榜，展示 0–3 家且**不含本公司自身**；若本公司排名在前 3，跳过自身、顺延取第 4 家补足，并注明「本公司也是该行业龙头（排名第 N）」；带可靠代码、可直接跳转；
  2. **细分业务龙头（AI 推断）**：在每个主营构成板块下列出该业务所属行业的头部公司 0–3 家，以名称为主，点击时复用现有搜索解析为 A 股代码；
  3. **细分业务相关公司（AI 推断）**：在每个主营构成板块下列出客户 / 供应商 / 渠道 / 合作方等相关公司 0–3 家，以名称为主，同一解析路径；
  4. **产业链上下游 + 合作 / 关联公司（AI 推断）**：围绕公司主要主业各列 0–3 家，以名称为主，同一解析路径。
- 四类信息按来源与可靠性分别标注：全局龙头标「行业龙头 · <行业名>（按总市值排序）」；细分业务龙头标「AI 推荐 · 供参考」；细分业务相关与产业链标「AI 推断 · 供参考」；合作公司标「AI 推断 · 需核实」。
- AI 不再输出全局行业龙头；不新增第二次大模型调用。全局龙头只新增一次上游接口请求，失败时静默降级为空；细分业务龙头与细分业务相关公司随同一次 AI 输出返回，不产生额外请求。
- AI 未返回、返回空或字段异常时，对应小节不显示；评分、结论、估值推荐与现有页面行为保持 0 回归。

### 1.3 可衡量目标

- **龙头确定性**：同一只股票、同一份上游数据，返回的龙头名单、顺序与代码完全一致（无 AI 参与、无随机）。
- **龙头可跳转性**：点击任意一家非本公司龙头，直接使用其代码切换股票，**不发起名称搜索请求**，最终打开的公司与点击项一致。
- **龙头去自身**：全局龙头展示的 0–3 家公司中**不得包含本公司自身**；若本公司市值排名在前 3，则展示排名顺延后的 3 家，并出现「本公司也是该行业龙头（排名第 N）」说明；若本公司不在前 3，则不出现该说明。
- **细分业务龙头覆盖**：每个业务板块最多展示 3 家细分业务龙头；某板块 AI 未返回或返回空时，该板块不显示龙头行，其余内容不受影响。
- **细分业务龙头可解析性**：点击任意一家 A 股细分业务龙头，最终打开的公司名称与点击名称完全一致；解析失败时明确提示，不发生错误跳转。
- **AI 公司可解析性**：点击任意一家 A 股细分业务相关 / 产业链 / 合作公司，最终打开的公司名称与用户点击的名称完全一致；解析失败时明确提示，不发生错误跳转。
- **降级可靠性**：行业接口超时、返回异常或行业字段缺失时，全局龙头区域为空且不报错；AI 细分业务龙头 / 相关公司缺失或异常时，仅隐藏对应行，AI 分析的评分/结论/估值展示不受影响。
- **成本可控**：不新增第二次 LLM 调用；新增 AI 输出（细分业务龙头 + 相关公司）控制在约 1400 tokens 以内；分析阶段只新增一次行业接口请求（仅服务全局龙头）。
- 在 320px / 375px / 768px 视口下，相关公司区域不出现横向滚动。

## 2. 用户故事 / 使用场景

- 作为正在研究某只 A 股的个人投资者，我在「行业分析」里看到公司所属行业（如「白酒Ⅱ」）后，想直接看到该行业按总市值排序的龙头公司，并一键点进去查看其财报，以便横向比较。
- 作为研究多业务公司的投资者，我想在「动力电池 / 储能电池 / 电池材料」每个细分业务下分别看到该业务所属行业的龙头公司，而不是只看到公司整体行业的一张龙头榜，以便按业务线找头部对标。
- 作为想摸清业务生态的投资者，我想在每个细分业务下看到客户、供应商、渠道或合作方等相关公司，与「行业龙头」区分开，以便判断该业务的外部依赖。
- 作为想理解公司产业位置的投资者，我想看到围绕其主营业务的上下游公司与合作方，以便判断它对上游的依赖、对下游客户的议价能力与外部合作绑定程度。
- 作为不记得股票代码的用户，我只想点一下公司名就跳到它的分析页：龙头名单由系统直接给出代码，点了就能进；AI 给的公司名也由系统自动解析，不需要我复制粘贴，更不能把我带到错误的公司。

## 3. 功能需求

### 3.1 数据来源与输出结构

#### 3.1.1 数据来源与生成方式

| 信息类型 | 来源 | 生成方式 | 代码可信度 | 数量 |
| --- | --- | --- | --- | --- |
| 全局行业龙头 `leaders` | 财报行 `INDUSTRY_CODE` / `INDUSTRY_NAME` + 东财 `IndustryAnalysis` 同行市值榜 | **后端确定性获取**，不经过大模型 | 高（接口原始代码，6 位数字校验后直接使用） | 0–3 家（不含本公司） |
| 细分业务龙头 `businesses[].leaders` | 大模型（输入含主营构成与六维指标） | AI 推断 | 低（仅名称可信；代码可选、仅作消歧） | 每板块 0–3 家 |
| 细分业务相关公司 `businesses[].related` | 大模型（输入含主营构成与六维指标） | AI 推断 | 低（仅名称可信；代码可选、仅作消歧） | 每板块 0–3 家 |
| 产业链上下游 `chain.upstream` / `chain.downstream` | 大模型（输入含主营构成与六维指标） | AI 推断 | 低（仅名称可信；代码可选、仅作消歧） | 各 0–3 家 |
| 合作 / 关联公司 `partners` | 大模型 | AI 推断 | 低（同上，且合作关系时效性最弱） | 0–3 家 |

- 行业分类优先取本次分析所用报表行中的 `INDUSTRY_CODE` / `INDUSTRY_NAME`；若最新年报行缺失，可回退到报表范围内最近一期带行业字段的行。行业字段仅用于展示与说明，**不改变三大报表与六维分析的任何展示**。
- 同行榜请求使用公司自身的市场前缀（沪 `SH` / 深 `SZ` / 京 `BJ`）+ 6 位代码；市场前缀判定沿用项目现有能力，北交所按既有已知限制处理。
- 同行榜需过滤「行业平均」「行业中值」等哨兵行以及代码非 6 位数字的行；剩余行按 `TOTAL_CAP` 降序（同市值按代码升序，保证确定性）。
- 全局龙头应将 `gsgm`（自身）与 `gsgm_zsz[]`（同行）合并、按代码去重后统一排序；**展示时排除当前公司自身**：按排名升序跳过自身、取满 3 家（若自身在前 3，实际会顺延取到第 4 名）；若自身排名在前 3，另记录 `self_rank` 供前端展示说明。
- 细分业务龙头与细分业务相关公司均按业务板块独立输出、独立清洗、独立截断，不做跨板块合并；同一公司可在不同板块之间、或在全局 `leaders` / `businesses[].leaders` / `businesses[].related` / `chain` / `partners` 之间重复出现（角色不同），去重只在单个列表内进行。
- 细分业务龙头由 AI 根据主营构成板块名称与该板块的产品 / 技术描述推断其所属行业，再列出该行业的头部公司；不要求映射到东财标准行业分类，也不与全局 `leaders.industry_name` 对齐。

#### 3.1.3 全局行业龙头项 `LeaderCompany`（后端回填）

| 字段 | 类型 | 必填 | 说明与约束 |
| --- | --- | --- | --- |
| `name` | string | 是 | 接口返回的证券简称，去除首尾空白；为空则丢弃 |
| `code` | string | 是 | 6 位数字；非 6 位数字一律丢弃 |
| `market` | string | 是 | `sh` / `sz` / `bj` |
| `market_label` | string | 是 | `沪` / `深` / `京` |
| `total_cap` | number | 否 | 总市值（元）；用于排序与调试，界面不强制展示 |
| `total_cap_rank` | number | 否 | 同行总市值排名（从 1 开始）；缺失时按本次排序下标 +1 |
`leaders` 容器字段：`industry_code`（可选）、`industry_name`（可选）、`self_rank`（可选，仅当本公司市值排名在前 3 时返回，从 1 开始，用于渲染「本公司也是该行业龙头（排名第 N）」）、`companies`（0–3 家，**不含本公司**，按总市值降序）。

#### 3.1.4 AI 公司项 `CompanyRef`（细分业务龙头 / 细分业务相关 / 产业链 / 合作公司共用）

| 字段 | 类型 | 必填 | 说明与约束 |
| --- | --- | --- | --- |
| `name` | string | 是 | **证券简称**（如「贵州茅台」「宁德时代」），不得使用「XX股份有限公司」等法定全称；去除首尾空白，长度 ≤ 30 字 |
| `code` | string | 否 | 6 位数字；**仅作解析时的候选消歧提示**，不直接展示、不单独用于跳转；非 6 位数字一律丢弃 |
| `market` | string | 否 | `A股` / `非A股`，缺省按 `A股` 处理；`非A股` 仅展示、不可跳转 |
| `relation` | string | 否 | 关系标签，如「该业务行业龙头」「上游原材料」「下游客户」「战略合作」「渠道合作」；长度 ≤ 20 字 |
| `note` | string | 否 | 一句话说明，长度 ≤ 30 字；不得包含买卖建议或评级 |

#### 3.1.5 位置约定

- `leaders`：顶层新增对象，由后端在 AI 解析完成后确定性回填；表示公司整体所属行业的龙头榜（不含本公司），与 `businesses` **不做一一绑定**。
- `businesses[].leaders`：挂在每个业务板块条目下，表示该细分业务所属行业的头部公司（AI 推断），与板块一一对应；与同板块的 `related` 并列但含义不同（龙头 vs 相关方）。
- `businesses[].related`：挂在每个业务板块条目下，表示该细分业务的客户 / 供应商 / 渠道 / 合作方等相关公司（AI 推断）；与 `businesses[].leaders`（行业头部）和顶层 `leaders`（公司整体行业）都不同。
- `chain.upstream` / `chain.downstream`：顶层新增 `chain` 对象，围绕公司**营收占比最大的主营板块**给出。
- `partners`：顶层新增数组，表示合作 / 关联公司。

> 说明：以上为接口契约层面的要求，具体 Go 结构体命名与 `omitempty` 策略由技术设计确定；但「缺省不报错、空列表可省略、旧响应可兼容」的行为要求不变。

### 3.2 关键设计结论与理由

| 设计点 | 结论 | 理由 |
| --- | --- | --- |
| 全局龙头来源 | **后端确定性获取**（财报行业字段 + 东财同行市值榜），AI 不输出全局龙头 | 实测数据源准确、代码可靠，彻底消除龙头名单的幻觉风险；还能省掉这部分 AI 输出 token |
| 全局龙头去自身 | 展示的 0–3 家不含本公司；若本公司排名在前 3，跳过自身、顺延取第 4 家补足，并注明「本公司也是该行业龙头（排名第 N）」 | 用户已经在这家公司的分析页，列表里再放「本公司」没有信息增量；顺延补足既保证 3 家，又保留「本公司是龙头」这一事实 |
| 细分业务龙头来源 | AI 推断（`businesses[].leaders`，每板块 0–3 家） | 主营构成是公司自定义口径，没有干净的「细分业务 → 标准行业 → 龙头」接口；只能由 AI 按板块语义推断 |
| 细分业务龙头 vs 细分业务相关 | `businesses[].leaders` = 该业务所属行业的头部公司；`businesses[].related` = 客户 / 供应商 / 渠道 / 合作方等相关公司 | 二者回答不同问题（谁是行业头部 vs 它与谁做生意），必须分字段、分标签，不能混在一个列表 |
| 功能拆分 | 四类：全局龙头（确定性）+ 细分业务龙头（AI）+ 细分业务相关公司（AI）+ 产业链 / 合作（AI） | 各类数据可靠性、跳转方式、免责强度不同，必须分开建模与标注 |
| 代码幻觉 | 全局龙头代码直接可信、按代码跳转；AI 公司（细分业务龙头 / 相关 / 产业链 / 合作）的 `code` 仅作搜索候选消歧、永不直接展示或单独跳转 | 把「可信代码」与「AI 给的代码」在数据结构和交互上彻底分开，避免一条链路污染另一条 |
| 可靠性分级 | 全局龙头（数据来源）、细分业务龙头（AI 中等）、细分业务相关（AI 中等）、产业链（AI 中等）、合作（AI 最低） | 全局龙头可按市值排名验证；细分业务与产业链随公司而异；合作关系的时效性与真实性最难保证 |
| 交互 | 全局龙头点击直接按代码切换；AI 公司（含细分业务龙头）点击按名称走搜索解析；均同页切换 | 与现有 `doSearch()` 一致，不新开页面；两类路径各自用最可靠的主键 |
| 展示位置 | 全局龙头放在「行业分析」小节内；细分业务龙头与相关公司放在各业务板块卡片内（细分业务龙头在前、相关公司在后）；产业链上下游 + 合作公司放在「业务板块分析」之后、「估值模型推荐」之前 | 全局龙头是公司级行业数据；细分业务龙头与相关公司与板块一一对应；产业链与合作方属于公司整体视角 |
| 边界 | 全局龙头 3 家（不含自身）；细分业务龙头 / 相关各 3 家；其余每块 3 家；空则整块不显示；不新增 LLM 调用；行业接口失败静默降级 | 控制冗长、幻觉面与 token；接口失败不能拖垮 AI 分析主体 |
| 「一键分析」快捷 | 本期**不做**每家公司的 AI 分析快捷入口；点击只加载该公司的财务数据 | AI 分析按 R5 设计必须由用户显式触发，自动触发会带来数分钟等待与不可控 token 消耗 |

### 3.3 功能条目

#### FR-1 全局行业龙头（确定性获取，P0）

- **触发**：AI 分析成功返回；后端在处理过程中按公司所属行业获取同行市值榜。
- **要求**：
  - 龙头名单**必须**由后端确定性获取，**不得**由大模型生成或改写；AI 若返回顶层 `leaders` 字段一律忽略。
  - 按 `TOTAL_CAP` 降序排列，同市值按代码升序，保证同一份数据下顺序稳定。
  - **展示的龙头不含本公司自身**：按排名升序遍历，跳过当前公司，取满 **3 家**；若本公司排名在前 3，实际会顺延取到第 4 名（例如本公司第 1，则展示第 2、3、4 名）。
  - 若本公司排名在前 3，必须在龙头子块内注明「本公司也是该行业龙头（排名第 N）」，N 取本公司的实际排名；该说明为纯文本，不可点击。
  - 若本公司排名不在前 3，则正常展示前 3，且不出现上述说明。
  - 过滤「行业平均」「行业中值」等哨兵行，以及代码非 6 位数字、名称为空的行。
  - 展示标题为「行业龙头 · <行业名>（按总市值排序）」（如「行业龙头 · 白酒Ⅱ」）；行业名缺失时只显示「行业龙头（按总市值排序）」。
  - 龙头名单不参与 AI 评分、结论与估值，也不影响 `businesses` 的内容。
  - **与细分业务龙头的区别**：`leaders` 是公司整体所属行业的确定性龙头（单一行业）；`businesses[].leaders` 是各细分业务所属行业的 AI 龙头（见 FR-12）。二者互补，不得互相覆盖或合并去重。
  - **与细分业务相关公司的区别**：`businesses[].related` 是该细分业务的客户 / 供应商 / 渠道 / 合作方等相关公司（AI 推断，见 FR-11），不是行业龙头。
- **边界**：
  - 行业接口超时、返回异常、无有效同行、公司无行业分类 → `leaders.companies` 为空，**静默降级**，不弹错、不阻塞分析。
  - 排除自身后可展示家数不足 3 家时，按实际数量展示；本公司排名前 3 但榜单不足 4 家时，仍展示「本公司也是该行业龙头」说明，只是列表少于 3 家。
  - **本接口不提供「每个业务板块各自的龙头」**：确定性数据源只给出公司所属的一个行业分类，无法可靠地把每个主营板块映射到不同行业；各细分业务龙头由 AI 推断（见 FR-12）。
  - 行业分类可能较宽（如「电池」「军工电子Ⅱ」），龙头名单反映的是该分类下的市值排序，不代表产品对「优质」的评价。

#### FR-2 产业链上游 / 下游公司（AI 推断，P1）

- **触发**：AI 分析成功返回，且 `chain.upstream` 或 `chain.downstream` 非空。
- **要求**：
  - 围绕公司**主要主业**（多主业时以营收占比最大的板块为准）列出上游与下游公司，各最多 **3 家**。
  - 上游指原材料、零部件、设备、能源等供应商侧公司；下游指客户、渠道、终端应用等需求侧公司。
  - 每家公司的 `relation` 应说明其在链条中的角色（如「锂矿/正极材料」「整车厂」「经销渠道」）。
  - **同行业的头部公司不得放入上游 / 下游**；行业头部由全局龙头与细分业务龙头承载。
- **边界**：
  - 上游或下游为空 → 只隐藏对应的子块；两者都为空 → 整个「产业链上下游」子块不显示。
  - 主营构成数据缺失时，AI 可基于公司名称与行业常识推断，但必须在 `note` 中降低断言强度（如「据公开信息」）；仍无把握时输出空数组。
  - 非 A 股公司（海外 / 未上市）按 FR-5 的非 A 股规则处理。

#### FR-3 合作 / 关联公司（AI 推断，P1）

- **触发**：AI 分析成功返回，且 `partners` 非空。
- **要求**：
  - 列出与当前公司有**公开可查**合作关系的公司，最多 **3 家**；合作关系包括战略合作、合资、长期供货/采购、渠道合作等。
  - 每家公司必须给出 `relation`（合作类型）与可选 `note`（合作内容的一句话说明）。
  - AI 只能列出其有较高把握、公开可查的合作关系；**不确定时输出空数组**，不得编造。
  - 该子块必须展示强免责文案（见 FR-7）。
- **边界**：
  - `partners` 为空或全部条目无效 → 整个子块不显示。
  - 合作关系可能已终止或未公开披露，产品不承诺准确性；用户以公司公告为准。

#### FR-4 公司项的清洗、去重与上限（P0）

- **全局行业龙头（确定性数据）**：
  - `name` 去除首尾空白；`code` 必须为 6 位数字，否则丢弃该条。
  - 过滤哨兵行（名称含「行业平均」「行业中值」）与重复代码（同一代码只保留首次出现项）。
  - 按 `total_cap` 降序排序；`total_cap` 缺失时沿用接口返回顺序，不得随机重排。
  - **按排名升序跳过当前公司自身**，取满 3 家；若本公司排名在前 3，则记录 `self_rank` 供前端渲染说明；`companies` 中永远不出现本公司。
- **AI 公司项（细分业务龙头 / 细分业务相关 / 产业链 / 合作）**：
  - `name` 去除首尾空白；为空则丢弃该条目。
  - `code` 仅在为 6 位数字时保留，否则视为无代码；不得因代码格式非法而丢弃整家公司。
  - `market` 仅接受 `A股` / `非A股`，其余值按 `A股` 处理。
  - `relation` / `note` 去除首尾空白，超长时截断并加省略号（`relation` ≤ 20 字，`note` ≤ 30 字）。
  - 同一列表内按归一化名称（去空白、大小写不敏感，与 R11 `NormalizeQuery` 同口径）去重，保留首次出现项。
  - 规范化后名称与当前公司名称相同 → 丢弃，避免「自己推荐自己」。
  - `businesses[].leaders` 与 `businesses[].related` 使用同一套清洗规则，均按板块独立执行「排除自身 → 去重 → 截断 3」；某板块条目全部无效时对应数组为空。
- **共同上限与展示约束**：
  - `leaders.companies` 3 家（不含本公司），`businesses[].leaders` 每板块 3 家，`businesses[].related` 每板块 3 家，`chain.upstream` 3 家，`chain.downstream` 3 家，`partners` 3 家。
  - **去重只在单个列表内进行**：同一公司可在不同业务板块、或与全局 `leaders` / `chain` / `partners` 重复出现（角色不同），不得跨列表合并或删除。同一公司同时出现在全局 `leaders` 与某板块的 `businesses[].leaders` 中属预期行为（公司整体是龙头，该板块也是行业头部）。
  - 所有列表按既定顺序展示，**不做「优质度/收益率」排序**，不展示任何股价、评级或买卖建议；全局龙头可保留总市值/排名字段用于排序，但界面不强制展示。

#### FR-5 跳转可靠性：全局龙头按代码、AI 公司按名称（P0）

- **全局行业龙头点击（可信代码路径）**：
  - `leaders.companies` 中的公司全部可点击；点击时先校验其 `code` 为 6 位数字，然后**直接以该代码**走现有换股流程；**不得**发起名称搜索请求。
  - 「本公司也是该行业龙头（排名第 N）」是纯文本说明，不可点击、不触发换股。
  - 龙头代码来自确定性接口，但仍需做 6 位数字与空值校验；非法条目不渲染为可点击。
- **AI 细分业务龙头 / 相关 / 产业链 / 合作公司点击（名称解析路径）**：
  - `businesses[].leaders` 与 `businesses[].related` 的点击行为完全一致，且与产业链 / 合作公司一致；不得因它们挂在业务板块下就改用代码跳转。
  - 界面上以**公司名称**为唯一展示主键；AI 返回的 `code` **不得直接展示为可点击代码**，也不得作为跳转路径参数。
  - 点击时调用现有 `GET /api/stock/search?q=<公司名>` 解析（复用 `fetchSearch()` 与 60s 缓存），按以下顺序确定目标公司：
    1. 归一化名称与某候选 `name` **完全相等** → 选中该候选；
    2. 无完全相等、但检索结果**有且仅有 1 条**候选 → 选中该候选；
    3. 以上均不满足（存在多条非精确候选）→ **不切换股票**，给出可读提示（推荐文案：「未找到唯一匹配的 A 股公司，请手动搜索「<公司名>」」）。
  - **AI 代码的作用边界**：`code` 不在界面展示，也不作为跳转参数；仅在「完全同名候选多于一条」时用于消歧，且必须**同时满足**：① 为 6 位数字；② 出现在该名称的检索结果中；③ 对应候选的名称与查询完全相等。任一不满足即忽略 AI 代码，按检索结果或失败处理。**不得**用 AI 代码在非精确候选之间做选择（例如名称只写了「平安」时，不能靠代码把用户带去「平安银行」）。
  - 如后续产品需要在标签上展示代码，只能展示「经当前名称检索命中且名称完全一致」的解析结果代码，**绝不展示 AI 原始代码**。
- **通用交互约束**：
  - 非 A 股（AI 项 `market=非A股`）公司展示「非A股」标记，**不可点击**；点击时提示「非 A 股公司，暂不支持财报分析」。
  - 同一时刻只允许一个解析/跳转请求处于进行中；被点击的标签在解析期间显示 loading / 禁用态，防止连点发起多次切换。
  - 搜索服务不可用 / 超时 → 静默降级为行内提示，不弹全局错误、不切换股票。
  - 所有跳转最终必须使用 6 位数字代码；禁止把 AI 返回的任意字符串拼进 `/api/stock/:code/...` 路径。

#### FR-6 点击跳转与页面行为（P0）

- **触发**：FR-5 任一解析路径成功。
- **要求**：
  - 行为与用户在搜索框选中该股票后点击「查询」**完全一致**：回填搜索框代码、记录搜索历史、加载指标 / 三大报表 / 六维分析 / 估值，并停留在**同一页面**。
  - **不得**自动触发该公司的 AI 分析；AI 分析仍由用户点击「一键分析」显式发起。
  - 切换股票后沿用现有行为：清空当前 `aiResult`（避免残留上一家公司的分析），页面滚动到结果区顶部，让用户看到新公司抬头。
  - 原公司的 AI 结果已在前端 `aiCache` 中保留：切回原股票后再次点击「一键分析」应直接复用缓存，不重复消耗 token（现有能力，不得回退）。
- **边界**：解析失败或用户取消时不改变当前股票、不清空当前 AI 结果。

#### FR-7 可靠性分级与免责文案（P0）

- **要求**：不同来源按不同口径标注，文案必须在界面上可见（不依赖 hover）：

| 信息类型 | 标签 / 标题后缀 | 免责说明（推荐措辞） |
| --- | --- | --- |
| 全局行业龙头 | 「行业龙头 · <行业名>（按总市值排序）」 | 「名单来自东财行业分类与同行市值数据，按总市值排序，随行情与行业分类更新；排序不代表投资价值，不构成投资建议。」 |
| 细分业务龙头 | 「AI 推荐 · 供参考」 | 「基于该业务板块所属行业的 AI 推断，可能与公司级行业龙头或其他板块重叠，仅用于拓展研究。」 |
| 细分业务相关公司 | 「AI 推断 · 供参考」 | 「基于该业务板块的 AI 推断，可能与公司级行业龙头、同板块龙头或其他板块重叠，仅用于拓展研究。」 |
| 产业链上下游 | 「AI 推断 · 供参考」 | 「基于公司主营业务的产业链推断，不代表真实交易关系。」 |
| 合作 / 关联公司 | 「AI 推断 · 需核实」 | 「合作关系可能已变化或未被公开披露，请以公司公告为准；不构成投资建议。」 |

- 相关公司区域（或整张 AI 卡片）应有一句统一的弱化说明：细分业务龙头、细分业务相关、产业链与合作公司信息由 AI 生成，全局行业龙头信息来自第三方数据，均仅用于拓展研究，不构成投资建议。
- AI 输出中不得出现「推荐买入 / 增持 / 目标价 / 强烈推荐」等投资建议措辞；`note` 只描述行业地位或合作关系。
- 当 AI 输出的名称与检索解析结果冲突时，**以检索结果为准**，界面展示解析到的证券简称。

#### FR-8 展示位置与移动端适配（P1）

- **展示位置**（沿用现有卡片式结果区）：
  1. **全局行业龙头**：放在「行业分析」小节内，现有「前景 / 竞争格局 / 应用方向」之后，作为「行业龙头 · <行业名>（按总市值排序）」子块展示公司标签列表；若 `self_rank` 存在，在标签列表上方或下方展示一行说明「本公司也是该行业龙头（排名第 N）」；标签列表本身不含本公司。不重复挂到每个业务板块卡片下。
  2. **细分业务龙头与相关公司**：放在「业务板块分析」每个板块卡片内，现有「风险」行之后，依次展示两行：
     - 「细分业务龙头（AI 推荐）」：该板块的 `leaders` 标签；
     - 「相关公司」：该板块的 `related` 标签。
     两行各自独立：某个数组为空或全部条目无效时只隐藏该行，不留空标题；此处只展示该细分业务的字段，不重复展示公司级 `leaders`。
  3. **相关公司（产业链 / 合作）**：新增小节，位于「业务板块分析」之后、「估值模型推荐」之前：
     - 子块一「产业链上下游」：桌面端「上游」「下游」左右两栏，窄屏上下堆叠；
     - 子块二「合作 / 关联公司」：单列标签列表。
  4. 每个公司标签建议包含：公司名称 +（可选）关系标签 +（非 A 股时）「非A股」标记。
- **移动端**：
  - 公司标签允许换行排布，不得出现横向滚动。
  - 触控目标高度 ≥ 28px；相邻标签间距足够，避免误触。
  - 长公司名允许换行或省略号截断，但必须保留可读的名称主体；不得把名称截成单字。
  - 关系标签与名称在窄屏下可分行，不重叠。
- **空态**：
  - 全局龙头为空 → 「行业龙头」子块整体不显示；`self_rank` 存在但没有可展示的同行时，仍保留「本公司也是该行业龙头（排名第 N）」说明；
  - 某板块 `businesses[].leaders` 为空或全部条目无效 → 该板块不显示「细分业务龙头」行；
  - 某板块 `businesses[].related` 为空或全部条目无效 → 该板块不显示「相关公司」行；
  - 上述两行都不显示时，板块的前景 / 风险等原有内容照常显示；
  - 「产业链上下游」与「合作公司」都为空 → 整个「相关公司」小节不显示，不出现空标题。

#### FR-9 降级、容错与兼容（P0）

- **全局龙头数据降级**：
  - 行业接口超时、网络失败、返回非 JSON、返回空列表或字段异常 → `leaders.companies` 为空，**静默降级**；不得使 AI 分析请求失败，不弹全局错误。
  - 行业字段（`INDUSTRY_CODE` / `INDUSTRY_NAME`）缺失不阻塞同行榜请求；仅影响标题中的行业名展示。
  - 本公司在榜单中排名缺失且无法确定时，不影响其他同行展示，只是不渲染「本公司也是该行业龙头」说明。
  - 全局龙头数据获取与 AI 调用相互独立：任一失败不影响另一方；接口失败时评分、结论、业务板块、估值推荐照常返回。
- **AI 返回缺字段 / 空数组 / 类型异常**：
  - `businesses[].leaders`、`businesses[].related`、`chain`、`partners` 缺失、为 `null`、空数组或类型不符合契约时，**按空处理并跳过展示**，不得导致 `ParseAIResult` 整体失败。
  - 单条公司项字段异常（如 `code` 为数字、`note` 非字符串等）只丢弃该条或该字段，不影响同列表其他公司，也不影响评分 / 结论 / 估值展示。
  - 某板块的 `leaders` 或 `related` 异常只影响该板块对应的行，不影响该板块的前景/风险，也不影响其他板块。
- **不新增 LLM 调用**：`businesses[].leaders` / `businesses[].related` / `chain` / `partners` 必须复用现有的一次 LLM 调用与分析阶段已取到的数据；**不得**为此新增第二次大模型调用。
- **网络请求边界**：
  - 分析阶段最多新增 **1 次** `IndustryAnalysis` 上游请求，仅用于全局龙头；不得为每个业务板块或细分业务重复请求。`businesses[].leaders` / `businesses[].related` 随同一次 LLM 调用返回，不产生额外请求。
  - 渲染相关公司列表时**不得**为解析代码而批量调用搜索接口；AI 公司的解析只在用户点击时发生。
  - 全局龙头数据建议使用短 TTL 缓存或与 AI 结果一并缓存（具体由技术设计定），但不得改变现有 AI 缓存 key。
- **缓存兼容**：后端 AI 缓存（10 分钟 TTL）与前端 `aiCache` 的 key 均不变；升级后命中旧缓存时，结果中没有新增字段（含 `businesses[].leaders`、`self_rank`），页面按空处理、其余内容正常展示。若本次行业接口抓取失败，缓存中的全局龙头为空，TTL 内不自动重试（属可接受降级）。
- **历史记录不受影响**：R16 估值历史记录、R4 估值计算、R5 五维评分与估值推荐均不因本需求改变；相关公司数据不写入估值记录、不参与估值。

#### FR-10 提示词与 AI 输出质量约束（P0）

系统提示词必须新增以下约束（措辞可由技术设计打磨，约束本身不可省）：

- **AI 不输出全局行业龙头**：明确告知大模型「公司整体所属行业的龙头由系统确定性获取，不要输出顶层 `leaders`」；即使返回也由后端忽略/覆盖。
- **必须输出细分业务龙头**：每个 `businesses[]` 条目必须包含 `leaders` 数组，列出该板块所属行业的头部公司 0–3 家；无把握时输出空数组。
- **必须输出细分业务相关公司**：每个 `businesses[]` 条目必须包含 `related` 数组，列出该板块的客户 / 供应商 / 渠道 / 合作方等相关公司 0–3 家；无把握时输出空数组。
- 输出 JSON 必须包含 `businesses[].leaders`、`businesses[].related`、`chain.upstream`、`chain.downstream`、`partners` 五组字段；无内容时输出空数组。
- 公司统一使用**证券简称**，不使用法定全称；优先 A 股上市公司。
- 每个业务板块的 `leaders`、`related` 各最多 3 家；上游、下游、合作公司各最多 3 家；不得包含当前公司自身；同一列表内不得重复。
- `businesses[].leaders` 必须与该板块所属行业直接相关（该行业的头部 / 龙头公司），`relation` 说明其行业地位（如「高端白酒龙头」「储能电池头部」）；**不得把全局行业龙头名单整段复制到每个板块**，也不得让所有板块共用同一组公司。
- `businesses[].related` 必须与该板块的业务直接相关（如客户、供应商、渠道、合作方），**不得与同板块的 `leaders` 混用**，也不得把全局或该板块的龙头名单当作相关公司填充。
- `code` 为可选项，**只在确信时填写**，不确定就留空；不得猜测或编造代码。
- 合作关系只列公开可查、较高把握的内容；不确定时输出空数组，**不得编造合作方**。
- `relation` / `note` 保持简短（各自 ≤ 20 / 30 字），只描述行业地位、产业链角色或合作内容，不写买卖建议、评级、目标价。
- 产业链上下游必须围绕公司**营收占比最大的主营板块**展开；公司主业不清晰时优先少列或不列。
- 不得改动既有 `scores / conclusion / industry / businesses` 原有字段（`name/stage/contribution/prospect/risk`）与 `valuation` 的任何内容；`businesses` 内只允许新增 `leaders` / `related`，AI 输出顶层只允许新增 `chain` / `partners`（顶层 `leaders` 由后端回填，不属于 AI 输出）。

#### FR-11 细分业务相关公司（AI 推断，P1）

- **触发**：AI 分析成功返回，且某个 `businesses[].related` 非空。
- **要求**：
  - 每个业务板块（主营构成板块）下展示该细分业务的相关公司，0–3 家；使用 `CompanyRef` 结构，以名称为主。
  - `related` 应是该板块的**客户、供应商、渠道、合作方等业务相关方**，与该板块的产品 / 技术 / 应用直接相关；**不是该行业的龙头 / 头部公司**（后者归入 `businesses[].leaders`）。`relation` 说明其与该细分业务的关系（如「储能电芯客户」「正极材料供应商」「区域经销渠道」）。
  - 不得把全局 `leaders` 或该板块的 `businesses[].leaders` 名单整段复制到 `related`，也不得让所有板块共用同一组公司。
  - 当前公司自身不得出现在 `related` 中；同一板块内按名称去重，超出 3 家截断。
  - 点击行为与 FR-5 的 AI 公司路径一致：按名称走搜索解析；非 A 股不可点击。
- **与 `leaders` 的关系**：
  - 全局 `leaders` = 公司整体所属行业的确定性龙头榜（单一行业、按总市值排序、可靠代码、不含本公司）；
  - `businesses[].leaders` = 该细分业务所属行业的 AI 龙头（每板块 0–3 家）；
  - `businesses[].related` = 该细分业务的客户 / 供应商 / 渠道 / 合作方等 AI 相关方；
  - 多业务公司（如宁德时代：动力电池 / 储能电池 / 电池材料）三类信息互补，同时展示，不互相替代、不跨列表去重。
- **边界**：
  - 某板块 `related` 缺失、为空或全部条目无效 → 该板块不显示相关公司行；板块的前景 / 风险等原有内容照常显示。
  - AI 对细分业务不熟悉时允许输出空数组；不得为了凑数编造公司。
  - 细分业务名称是公司自定义口径，可能与行业标准分类不同；不要求与 `leaders.industry_name` 对齐。
  - 不新增 LLM 调用与上游请求；复用同一次 AI 输出。

#### FR-12 细分业务龙头（AI 推断，P1）

- **触发**：AI 分析成功返回，且某个 `businesses[].leaders` 非空。
- **定义**：`businesses[].leaders` = 该细分业务所属行业的头部 / 龙头公司；与同板块的 `related`（客户 / 供应商 / 渠道 / 合作方）不同，也与全局 `leaders`（公司整体行业、确定性）不同。
- **要求**：
  - 每个业务板块下展示该细分业务所属行业的龙头公司，0–3 家；使用 `CompanyRef` 结构，以名称为主。
  - AI 根据板块名称与该板块的产品 / 技术描述推断所属行业，再列出该行业头部公司；`relation` 说明其行业地位（如「高端白酒龙头」「储能电池头部」）。
  - 不得把全局 `leaders` 名单整段复制到每个板块，也不得让所有板块共用同一组公司；不同板块的龙头企业应随业务线变化（如宁德时代：动力电池板块→动力电池头部，储能电池板块→储能电池头部）。
  - 当前公司自身不得出现在 `leaders` 中；同一板块内按名称去重，超出 3 家截断。
  - 展示标签为「AI 推荐 · 供参考」，与 `related` 的「AI 推断 · 供参考」区分。
  - 点击行为与 FR-5 的 AI 公司路径一致：按名称走搜索解析；非 A 股不可点击。
- **与全局 `leaders` 的关系**：
  - 全局 `leaders` = 公司整体所属行业的确定性龙头（单一行业、接口获取、可靠代码、不含本公司）；
  - `businesses[].leaders` = 各细分业务所属行业的 AI 龙头；
  - 多业务公司的行业分类只有一个，全局龙头覆盖不了各业务线，因此二者互补；同一公司可同时出现在两处（角色一致或相近），不做跨列表去重。
- **边界**：
  - 某板块 `leaders` 缺失、为空或全部条目无效 → 该板块不显示「细分业务龙头」行；板块的前景 / 风险等原有内容照常显示。
  - AI 对细分业务所属行业不熟悉时允许输出空数组；不得为了凑数编造公司。
  - 细分业务名称是公司自定义口径，AI 推断的行业可能与标准分类不同；不要求与全局 `leaders.industry_name` 对齐。
  - 不新增 LLM 调用与上游请求；复用同一次 AI 输出。

## 4. 非功能需求

- **性能 / 耗时**：
  - 分析阶段新增 1 次 `IndustryAnalysis` 上游请求（仅用于全局龙头）；该请求必须有明确超时（建议 ≤ 2s），失败或超时只导致全局龙头为空，**不得阻塞或拖垮** AI 分析主体。
  - 单次 AI 分析的总耗时增量主要来自新增 AI 输出与一次行业接口请求，目标控制在相同分析模式下的 **10% 以内**。
  - 点击全局龙头到发起换股请求应在 **300ms 内**完成（无搜索环节）；点击 AI 公司名（含细分业务龙头 / 相关 / 产业链 / 合作）到发起换股请求，解析环节应在 **1.5s 内**完成（搜索接口有 60s 缓存）。
  - 渲染 30 个左右的公司标签不得造成明显卡顿；不引入图片、外部请求或复杂图表。
- **Token 预算**：
  - AI 不再输出全局龙头，但新增 `businesses[].leaders` 与 `businesses[].related` 两组细分业务公司；系统提示词新增约 400–500 tokens，单次输出新增约 800–1400 tokens；合计增量应控制在现有单次分析用量的 **约 25% 以内**。全局龙头由接口确定性计算，不占 AI token。
  - 不得为此调整 `max_tokens=8192` 上限或新增第二次调用；token 用量展示保持现状。
- **确定性与缓存**：
  - 全局龙头名单在同一份上游数据下必须确定：固定按 `TOTAL_CAP` 降序、同市值按代码升序，排除自身后按排名顺序取满 3 家，无随机、无时间依赖。
  - 同一缓存 key 在 TTL 内返回完全相同的结果；跨缓存周期允许全局龙头与 AI 名单变化（AI 输出本身不具有跨调用确定性），界面已用免责文案覆盖该不确定性。
- **兼容性**：
  - 继续使用内嵌 Vue 3 + Element Plus + ECharts（CDN）与现有 CSS，不引入构建步骤或新前端依赖。
  - 不改动 `GET /api/stock/:code/ai-analysis` 的请求参数与统一响应结构 `{code, data, message}`；新增字段只做向后兼容的增量。
- **安全 / 正确性**：
  - 公司名、关系、说明等均为纯文本展示，必须按文本转义，不得作为 HTML 渲染。
  - 所有跳转必须使用 6 位数字代码；全局龙头代码来自确定性接口也要做格式校验，AI 返回的任意字符串不得拼进 `/api/stock/:code/...` 路径。
- **易用性**：
  - 标记必须让用户一眼区分「可直接跳转的全局龙头」「需解析的 AI 公司（含细分业务龙头）」「仅展示的非 A 股」；解析中、解析失败都有明确的行内反馈。

## 5. 边界与约束

- **非目标**：
  - 不做选股器、排行榜、评分榜或「优质公司」客观评价；不展示相关公司的股价、PE、评级或买卖建议。
  - **本期不做公司级「主要竞争对手」榜单**：该需求经用户澄清为误解，已整体回退（见 D9）。
  - 不做批量对比、批量导入、自选股/收藏、相关公司独立详情页。
  - 不保证 AI 细分业务龙头 / 相关公司 / 产业链 / 合作名单的完整性、时效性与准确性，也不保证每个细分业务都有龙头或相关公司；产品定位是「拓展研究线索」而非「投资建议」。
  - **不做「细分业务 → 标准行业 → 龙头」的确定性映射**：细分业务是公司自定义口径，各细分业务龙头由 AI 推断（`businesses[].leaders`），不是接口龙头榜。
  - 不改变 R4 估值计算、R5 评分维度与结论、R16 估值历史记录的既有逻辑。
- **依赖**：
  - 报表响应行中的 `INDUSTRY_CODE` / `INDUSTRY_NAME`（需补齐 model 映射）；
  - 东财 `PC_HSF10/IndustryAnalysis/PageAjax` 同行市值榜接口（`gsgm` / `gsgm_zsz[]`，仅用于全局龙头）；
  - 现有一次 DeepSeek 调用与 `aiSystemFramework` / `ParseAIResult` 链路（新增 `businesses[].leaders` / `businesses[].related` 输出与容错解析）；
  - R11 的 `GET /api/stock/search` 名称解析能力与前端 `fetchSearch()`；
  - 现有 `doSearch()` 换股链路与 `aiCache`。
- **已知限制**：
  - 行业分类可能较宽或滞后（如「电池」「军工电子Ⅱ」），全局龙头名单与用户理解的「细分板块」不一定完全对应。
  - 行业接口可能限流/不可用，届时全局龙头区域为空；10 分钟缓存内不自动重试。
  - 当前公司排名在前 3 但同行不足 4 家时，全局龙头可能少于 3 家；「本公司也是该行业龙头」说明仍会展示。
  - 行业字段可能在某些报表行缺失；缺失时仅影响行业名展示，不影响榜单抓取（榜单只依赖股票代码）。
  - 细分业务是公司自定义口径（如「茅台酒 / 系列酒」），AI 对细分业务所属行业的判断可能偏差；冷门或新兴业务可能返回空数组，属正常降级。
  - AI 给出的细分业务龙头可能与全局 `leaders` 重叠，也可能与用户理解的标准行业龙头不一致；其可靠性低于接口龙头，已用「AI 推荐 · 供参考」标注。
  - 同一公司可能同时出现在全局 `leaders`、`businesses[].leaders`、`businesses[].related`、`chain`、`partners` 中（角色不同），去重只在单个列表内进行，跨列表重复不是缺陷。
  - AI 训练数据可能滞后：细分业务龙头 / 相关公司 / 产业链 / 合作公司可能已更名、被 ST、退市或关系已终止；解析失败时以行内提示兜底。
  - 搜索只覆盖 A 股（沪/深/京），海外与未上市公司无法跳转，只能作为背景信息展示。
  - 北交所行情前缀存在既有已知限制（R11 T-1），全局龙头 / 跳转沿用现有处理。

## 7. 已决策记录（2026-10-17）

- **D1 每块公司数量上限** → **每条列表 3 家**（全局龙头 0–3 家且不含自身，每个细分业务 `leaders` / `related` 各 0–3 家，上游 / 下游 / 合作各 0–3 家）。理由：兼顾横向参考价值与结果区简洁度，控制 token 与错误面。
- **D2 是否允许出现非 A 股公司** → **允许展示但不可点击，并标注「非A股」**。理由：产业链上下游常有海外巨头，完全排除会损失关键背景；但本工具无法分析非 A 股，只能作参考。该规则仅适用于 AI 输出的细分业务 / 产业链 / 合作公司；全局龙头来自 A 股同行榜。
- **D3 点击公司名是否直接切换股票** → **直接切换、不弹二次确认**，与现有搜索选中即查询的体验一致。当前 AI 结果会按既有逻辑清空，但保留在前端缓存中，切回后可恢复。
- **D4 是否为全局龙头提供「一键分析」快捷入口** → **本期不做**。点击只负责加载该公司的财务数据；AI 分析仍由用户在 AI 卡片中显式点击「一键分析」，避免误触触发数分钟等待与不可控消耗。AI 公司同此处理。
- **D5 全局行业龙头改为后端确定性获取** → **AI 不再输出全局龙头**。来源：财报行 `INDUSTRY_CODE` / `INDUSTRY_NAME` + 东财 `IndustryAnalysis` 同行市值榜（`gsgm` / `gsgm_zsz[]`）；过滤哨兵行后按 `TOTAL_CAP` 降序；龙头带可靠代码，点击直接按代码跳转，无搜索解析、无幻觉风险。
- **D6 AI 仅输出细分业务龙头、细分业务相关公司、产业链上下游与合作公司** → `businesses[].leaders` / `businesses[].related` / `chain.upstream` / `chain.downstream` / `partners`，以名称为主，`code` 可选且仅作精确同名消歧，点击走 R11 搜索解析。
- **D7 全局行业龙头展示位置** → 放在「行业分析」小节内，标题带所属行业名；不重复挂到每个业务板块卡片下，避免同一名单在多板块重复。
- **D8 细分业务相关公司走 AI、与全局龙头互补** → 每个 `businesses[]` 新增 `related`（每板块 0–3 家，AI 推断），表示该业务的客户 / 供应商 / 渠道 / 合作方。主营构成板块是公司自定义口径，不对应东财标准行业板块，公司级 `IndustryAnalysis` 只有单一行业分类，无法覆盖多业务公司的各细分业务；因此全局 `leaders`（确定性）与 `businesses[].related`（AI）同时展示、互为补充，不互相替代，也不跨列表去重。
- **D9 主要竞争对手（已回退）** → 2026-10-17 曾按误解新增公司级 `competitors`（同行业市值排名相邻），后经用户澄清撤回：**本期不做全局竞争对手**，相关字段、接口口径、展示与验收项均已从本需求移除。保留此记录以说明回退原因，避免技术设计误实现。
- **D10 细分业务龙头走 AI** → 每个 `businesses[]` 新增 `leaders`（每板块 0–3 家，AI 推断），列出该细分业务所属行业的头部 / 龙头公司。理由：主营构成是公司自定义口径，没有干净的「细分业务 → 标准行业 → 龙头」接口；它与同板块 `related`（相关方）区分，也与全局 `leaders`（公司整体行业、确定性）区分，对多业务公司尤为重要。
- **D11 全局龙头去自身** → `leaders.companies` 不再展示本公司自身。若本公司市值排名在前 3，则跳过自身、顺延取第 4 家补足 3 家，并通过 `self_rank` 在龙头处注明「本公司也是该行业龙头（排名第 N）」；若本公司不在前 3，则正常展示前 3、无该说明。理由：用户已在当前公司页面，重复展示自身无信息增量；但「本公司是行业龙头」这一事实仍有价值，用一句说明保留。
