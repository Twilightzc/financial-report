# R17 技术方案：AI 相关公司推荐（行业龙头确定性获取 + 产业链/合作公司 AI 推断）

> 需求文档：`docs/R17-AI相关公司推荐/需求文档.md`（2026-10-17 定稿；D1–D10 已拍板。D8 为业务板块相关公司扩展见 §21.11；**D9「主要竞争对手」已按用户澄清回退，§21.12 仅保留为历史记录**；D10 为最终修订：回退 competitors、新增 `businesses[].leaders`、全局龙头去自身，见 §21.13）。
> 关联既有章节：R5（AI 智能分析链路）、R7（AI 估值参数确定性约束：AI 不产出数值）、R11（搜索名称解析 `GET /api/stock/search`）、R16（前端 `aiCache` 与 `doSearch` 换股链路）。
> 行号基于 2026-10-17 当前工作区代码（`internal/client/eastmoney.go` 422 行、`internal/service/ai.go` 516 行、`internal/api/ai.go` 144 行、`internal/web/app.js` 约 2060 行），实现时以函数名/类名为准，行号仅作定位参考。
>
> **实测修正（务必先读）**：需求文档 3.1.1 假设「本次 AI 分析所用报表行」自带 `INDUSTRY_CODE` / `INDUSTRY_NAME`。实测结论：
> - `RPT_F10_FINANCE_GBALANCE` / `GINCOME` / `GCASHFLOW`（AI 分析实际使用的全量报表）**没有**这两个字段；
> - `RPT_DMSK_FN_BALANCE` / `INCOME` / `CASHFLOW`（`columns=ALL`）**都有**，实测 `600519 → INDUSTRY_CODE=1277`、`INDUSTRY_NAME=白酒Ⅱ`；
> - `emweb IndustryAnalysis` 响应本身**不含**行业名（`gsgm` 无 `INDUSTRY_*`，`hyzx` 为 null）。
>
> 因此本设计保留「优先读本次分析报表行」的代码路径（为未来/其它报表源兜底），并新增一次**极轻量、2s 超时、与 LLM 并发**的 DMSK 资产负债表读取作为行业名回退（详见 21.4.2 与 21.10 D1）。正常页面流程中该请求通常命中既有报表缓存（`/api/stock/:code/indicators` 已用同 key 拉过 `RPT_DMSK_FN_BALANCE|code|8`），实际不产生上游请求。

### 21.1 设计目标与影响面

**目标**

1. AI 分析结果顶层新增 `leaders`（确定性与后端回填）、`chain.upstream` / `chain.downstream` / `partners`（AI 推断）。
2. 行业龙头由后端调东财 `IndustryAnalysis` 同行市值榜获取：过滤哨兵、按 `TOTAL_CAP` 降序、同市值按代码升序；**排序后跳过自身，取前 3 家补足**（自身在前 3 时顺延取第 4 名），并在 `LeaderBoard.SelfRank` 记录自身有效排名；**AI 不输出全局龙头，AI 返回的顶层 `leaders` 一律忽略**。
3. AI 仅新增 `chain` / `partners` / `businesses[].leaders` / `businesses[].related` 输出约束与容错解析，不新增第二次 LLM 调用，不改变 `max_tokens`。
4. 龙头失败静默降级为空，不影响评分/结论/业务板块/估值；`/api/stock/:code/ai-analysis` 请求参数与统一响应结构不变。
5. 前端：全局龙头按代码直接换股（不发起搜索），AI 公司（含板块龙头/板块相关公司）按名称走现有搜索解析，非 A 股不可点击；空块整段隐藏，移动端不横向滚动；`self_rank>0` 时显示「本公司也是该行业龙头（排名第 N）」。
6. D8：每个业务板块可带 0–3 家「板块相关公司」（`businesses[].related`，AI 推断、按名称解析），与 `leaders` / `chain` / `partners` 互补且不跨列表去重。
7. D10（替代 D9）：**回退全局 `competitors`**；每个业务板块新增 0–3 家「细分业务龙头」（`businesses[].leaders`，AI 推断、按名称解析），与 `related` 各自独立清洗；全局龙头列表不含自身，`self_rank` 单独展示。

### 21.2 总体架构与数据流

```
前端「一键分析」
  └─ GET /api/stock/:code/ai-analysis?reasoning=..&startYear=..&endYear=..
       └─ api/ai.go GetAIAnalysis
            └─ aiResultCache.getOrCompute(aiCacheKey{code,reasoning,start,end}, 10min)  // key 不变
                 └─ computeAIAnalysis
                      ├─ FetchQuote(code)                                    // 腾讯，既有
                      ├─ goroutine A: FetchIndustryPeers(code)               // ★R17，2s，失败静默
                      │     └─ emweb IndustryAnalysis → 一次排名榜 → Leaders（去自身 + self_rank）
                      ├─ fetchAnalysisReports(code)                          // F10 三表，既有
                      ├─ service.IndustryFromReportRows(balance, income, cf) // 优先读报表行（F10 通常为空）
                      │     └─ 为空 → goroutine B: FetchIndustry(code)        // ★R17，2s，读 DMSK 资产负债表
                      ├─ ComputeAnalysis / RecommendValuation                // 既有
                      ├─ FetchSegmentIncome / BuildAIPrompt                  // 既有（prompt 增规则）
                      ├─ DeepSeek Chat（仅 1 次）                             // 既有
                      ├─ ParseAIResult(raw, quote.Name)                      // service：容错解析 + 自身排除（含 businesses[].leaders / related）
                      ├─ ApplyValuationRecommendation                        // 既有
                      └─ join A/B → 回填 result.Leaders（确定性，含 self_rank）→ 写入缓存
```

**时序结论（推荐）**：龙头请求在 `FetchQuote` 成功后立即并发启动，与 F10 报表冷启动、LLM 调用重叠；行业名回退请求在报表拉取完成后启动，也与 LLM 调用重叠；两者均在 `ParseAIResult` 之后用带缓冲 channel 汇合。LLM 正常耗时数十秒，龙头与行业名最坏各 2s，**对总耗时增量近似为 0**；LLM 失败提前返回时，goroutine 写入容量 1 的缓冲 channel 后自行退出，不泄漏、不阻塞。

**缓存交互结论（推荐）**：龙头与行业名随 AI 结果一起写入现有 10 分钟缓存，**不单独缓存、不改 key**。理由：
- 需求 FR-9 明确允许「与 AI 结果一并缓存」，并规定「本次龙头抓取失败，缓存中的龙头为空，TTL 内不自动重试」；
- 同一 cache key 在 TTL 内返回完全一致的结果（确定性验收项），独立刷新龙头会破坏这一点；
- 命中缓存时不再发起龙头请求，进一步降低上游压力。
- D10 上线后旧缓存可能仍带 `competitors` / `is_self` / 自包含的龙头列表；新前端忽略这些字段，且龙头列表在 TTL（10 分钟）内可能短暂包含自身。进程重启或 TTL 过期后自然恢复，**不为此改缓存 key**（约束优先）。

### 21.3 数据模型（`internal/model`）

#### 21.3.1 `internal/model/ai.go` 新增结构

```go
// LeaderCompany 行业龙头（后端确定性回填，非 AI 输出）。
// D10：移除 IsSelf / RankDistance；龙头列表本身不含自身，自身排名由 LeaderBoard.SelfRank 承载。
type LeaderCompany struct {
    Name         string  `json:"name"`                     // 证券简称（已 trim；为空的行在 client 层丢弃）
    Code         string  `json:"code"`                     // 6 位数字（非 6 位在 client 层丢弃）
    Market       string  `json:"market"`                   // sh / sz / bj（复用 client.quotePrefix）
    MarketLabel  string  `json:"market_label"`             // 沪 / 深 / 京（复用 client.marketLabel）
    TotalCap     float64 `json:"total_cap,omitempty"`      // 总市值（元）；缺失为 0 不输出
    TotalCapRank int     `json:"total_cap_rank,omitempty"` // 同行总市值排名（从 1 开始）；缺失时按市值降序榜位置回填
}

// LeaderBoard 行业龙头榜（leaders 容器）。
type LeaderBoard struct {
    IndustryCode string          `json:"industry_code,omitempty"` // DMSK 原始值，实测为 "1277"（不是 "BK1277"）
    IndustryName string          `json:"industry_name,omitempty"` // 实测 "白酒Ⅱ"
    // D10：本公司位于去重排序榜前 3 时记录其有效排名（>0）；否则为 0 且 omitempty 不输出。
    SelfRank  int             `json:"self_rank,omitempty"`
    Companies []LeaderCompany `json:"companies"` // 0–3 家，按总市值降序，**不含自身**；非 nil（空数组）
}

// CompanyRef AI 推断的产业链/合作公司（名称是唯一展示主键，Code 仅作精确同名消歧）。
type CompanyRef struct {
    Name     string `json:"name"`                // 证券简称，≤30 字
    Code     string `json:"code,omitempty"`      // 可选；仅保留 6 位数字，前端不展示、不直接跳转
    Market   string `json:"market,omitempty"`    // A股 / 非A股；清洗后恒为二者之一
    Relation string `json:"relation,omitempty"`  // 关系标签，≤20 字
    Note     string `json:"note,omitempty"`      // 一句话说明，≤30 字
}

// AIChain 产业链上下游（AI 推断）。
type AIChain struct {
    Upstream   []CompanyRef `json:"upstream,omitempty"`   // 上游供应商侧，0–3 家
    Downstream []CompanyRef `json:"downstream,omitempty"` // 下游客户/渠道侧，0–3 家
}
```

**omitempty 策略说明**
- `Leaders` / `Chain` 用指针 + `omitempty`：无内容时整个对象不输出，前端 `v-if` 直接判断。
- `Partners` 用切片 + `omitempty`：空切片不输出。
- `LeaderBoard.SelfRank` **设 `omitempty`**：仅当自身位于去重排序榜前 3 时输出有效排名（>0）；否则 0 省略。前端用 `self_rank > 0` 判断。
- `LeaderBoard.Companies` **不设** `omitempty`：容器出现时 `companies` 恒为非 nil 数组；通常 0–3 家，特殊情况下可为空（行业榜只有本公司，但 `self_rank>0`，用于展示自身龙头提示）。
- **D9 已回退**：不存在 `CompetitorBoard`、`LeaderCompany.IsSelf`、`LeaderCompany.RankDistance`；旧响应/旧缓存中的这些字段被 `encoding/json` 忽略。

#### 21.3.4 `AIBusiness` 增量字段（D8/D10，`internal/model/ai.go:18-28`）

```go
type AIBusiness struct {
    Name         string `json:"name"`
    Stage        string `json:"stage"`
    Contribution string `json:"contribution"`
    Prospect     string `json:"prospect"`
    Risk         string `json:"risk"`

    // R17-D10：该细分业务的行业龙头（AI 推断），0–3 家；与公司级 leaders 相互独立。
    Leaders []CompanyRef `json:"leaders,omitempty"`
    // R17-D8：该业务板块的相关公司（AI 推断），0–3 家；与 Leaders、公司级 leaders/chain/partners 相互独立。
    Related []CompanyRef `json:"related,omitempty"`
}
```

- **只增字段**：既有 5 个字段的名称、类型、JSON tag 均不变；旧缓存/旧响应缺 `leaders` / `related` 时反序列化为 nil，前端按空处理。
- **复用 `CompanyRef`**：两个字段的字段与清洗规则（名称 ≤30、relation ≤20、note ≤30、`market` 仅 `A股`/`非A股`、`code` 仅 6 位）与 `chain` / `partners` 完全一致，不引入新结构。
- **`omitempty`**：该板块没有内容时对应字段不输出，避免 `leaders: []` / `related: []` 空壳；前端仍以 `b.leaders && b.leaders.length`、`b.related && b.related.length` 防御。
- **不提升到顶层、不跨列表合并**：`businesses[].leaders`、`businesses[].related`、`AIAnalysisResult.Leaders/Chain/Partners` 是并列数据，**禁止合并、去重或互相覆盖**；`leaders` 与 `related` 之间也不去重（同一公司可同时作为某板块的行业龙头与相关方出现）。
- **语义区分**：`leaders` 是「该细分业务所属行业的头部/龙头公司」（同行竞争者），`related` 是「该板块的客户/供应商/渠道/合作方」；提示词必须明确区分，避免 AI 把两者混为一谈。

#### 21.3.5 D9 字段已移除（历史说明）

D9 曾新增 `LeaderCompany.IsSelf`、`LeaderCompany.RankDistance`、`CompetitorBoard`、`AIAnalysisResult.Competitors`；按 D10 全部移除，**不要在新代码/新测试/新前端中引用**。完整回退清单见 §21.13.2。

D10 的 `LeaderBoard.SelfRank` 设置 `omitempty`：只有自身位于去重排序榜前 3 时才输出有效排名；`Companies` 不含自身，专用提示见 §21.13.3。

### 21.4 数据源与字段映射

#### 21.4.1 行业龙头榜（新增，唯一业务新增上游；D10 单榜）

- **URL**：`https://emweb.securities.eastmoney.com/PC_HSF10/IndustryAnalysis/PageAjax?code={SH|SZ|BJ}{6位代码}`
- **D10**：只派生全局 `leaders`（去自身、前 3、`self_rank`），不新增其它榜单、不新增上游请求；取值算法见 §21.13.3。
  - 市场前缀复用 `client.quotePrefix(code)`（`internal/client/eastmoney.go:94-107`，返回小写 `sh/sz/bj`），拼 URL 时 `strings.ToUpper`。
  - 实测：`SH600519`、`SZ300750` 均返回 `200 application/json`；**无需额外 Header**（未带 UA/Referer 也能取到）。
- **响应关键字段（实测）**：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `gsgm[]` | 数组 | 自身；取 `[0]`。字段与同行相同 |
| `gsgm_zsz[]` | 数组 | 同行按总市值降序；**含哨兵行** |
| `CORRE_SECURITY_CODE` | string | 6 位代码；哨兵行为「行业平均」等非数字 |
| `CORRE_SECURITY_NAME` | string | 证券简称；哨兵行为「行业平均」「行业中值」 |
| `TOTAL_CAP` | number | 总市值，**单位元**（实测茅台 `1661358447729`） |
| `FREECAP` | number | 流通市值，**单位亿元**（实测 `16613.58`）；**本需求不使用**，避免单位混淆 |
| `TOTAL_CAP_RANK` | number | 同行总市值排名，从 1 开始；哨兵行可能为 null |

- **不使用的字段**：`gsgm_hypj`（行业平均）、`gsgm_hyzz`（行业中值）、`gsgm_ltsz` / `gsgm_yysr` / `gsgm_jlr`（其它维度榜单）。统一从 `gsgm + gsgm_zsz` 合并取数，避免同一公司在多个榜单重复。
- **行业代码口径**：DMSK 返回 `INDUSTRY_CODE=1277`（纯数字），需求示例中的 `BKxxxx` 仅为示意。**不得**自行加 `BK` 前缀；前端不展示该字段，仅透传。
- **行业名口径**：`INDUSTRY_NAME=白酒Ⅱ`（带罗马数字后缀），来自 DMSK 报表行，不是 AI 的 `industry.name`。两者可能措辞不同（「白酒」vs「白酒Ⅱ」），不互相覆盖。

#### 21.4.2 行业分类（回退读取 DMSK）

- **首选**：`service.IndustryFromReportRows(balance, income, cashflow)` 扫描本次 AI 分析已拉取的 `[]model.ReportRow`（F10，行按 `REPORT_DATE` 倒序），返回第一个 `IndustryName` 或 `IndustryCode` 非空的行。F10 当前没有该字段，实际返回空，走回退。

  - 超时：走新增的 `hcFast`（2s）；冷缓存时最坏 2s，且与 LLM 调用并发。
  - 失败/空数据：行业名与行业代码均为空，仅影响龙头标题（降级为「行业龙头（按总市值排序）」），不影响榜单抓取（榜单只需代码）。

**选择算法（纯函数，便于单测）**

> D10 把逻辑拆为 `rankIndustryPeers(peers)`（过滤/去重/排序/回填排名）+ `topLeaderBoard(ranked, selfCode)`（去自身取前 3、计算 `SelfRank`）；`buildLeaderBoard(selfCode, peers)` 保留为薄包装。完整算法与边界见 §21.13.3，以下为旧口径示意，**以 §21.13.3 为准**。

```go
func isSixDigitCode(s string) bool {
    if len(s) != 6 {
        return false
    }
    for _, ch := range s {
        if ch < '0' || ch > '9' {
            return false
        }
    }
    return true
}

// buildLeaderBoard 合并自身与同行，过滤哨兵/非法行，去重，按总市值降序；
// 跳过自身取前 3，并在自身位于前 3 时回填 SelfRank。
func buildLeaderBoard(selfCode string, peers []industryPeer) model.LeaderBoard {
    return topLeaderBoard(rankIndustryPeers(peers), selfCode)
}

// rankIndustryPeers 过滤/去重/排序/回填有效排名；不再标记 IsSelf。
func rankIndustryPeers(peers []industryPeer) []model.LeaderCompany {
    seen := make(map[string]bool, len(peers))
    list := make([]model.LeaderCompany, 0, len(peers))
    for _, p := range peers {
        name := strings.TrimSpace(p.Name)
        code := strings.TrimSpace(p.Code)
        if name == "" || !isSixDigitCode(code) {
            continue
        }
        if strings.Contains(name, "行业平均") || strings.Contains(name, "行业中值") {
            continue // 哨兵行（代码已非 6 位，双保险）
        }
        if seen[code] {
            continue // 同一代码只保留首次出现（gsgm 在前，自身优先保留）
        }
        seen[code] = true
        m := quotePrefix(code)
        list = append(list, model.LeaderCompany{
            Name:         name,
            Code:         code,
            Market:       m,
            MarketLabel:  marketLabel(m), // 复用 search.go 的 marketLabel
            TotalCap:     toFloat(p.TotalCap),
            TotalCapRank: int(toFloat(p.TotalCapRank)), // 可能为 0，排序后回填
        })
    }

    sort.SliceStable(list, func(i, j int) bool {
        ci, cj := list[i].TotalCap, list[j].TotalCap
        if ci == 0 && cj == 0 {
            return false // 均缺失：保持接口返回顺序（SliceStable）
        }
        if ci == 0 {
            return false // 缺失市值后置
        }
        if cj == 0 {
            return true
        }
        if ci != cj {
            return ci > cj
        }
        return list[i].Code < list[j].Code // 同市值按代码升序，保证确定性
    })

    for i := range list {
        if list[i].TotalCapRank <= 0 {
            list[i].TotalCapRank = i + 1 // 回退：市值降序榜位置
        }
    }
    return list
}

// topLeaderBoard：跳过自身取前 3；自身位于排序榜前 3 时记录有效排名。
func topLeaderBoard(ranked []model.LeaderCompany, selfCode string) model.LeaderBoard {
    selfIdx := -1
    for i := range ranked {
        if ranked[i].Code == selfCode {
            selfIdx = i
            break
        }
    }
    selfRank := 0
    if selfIdx >= 0 && selfIdx < industryPeersTopN {
        selfRank = ranked[selfIdx].TotalCapRank
        if selfRank <= 0 {
            selfRank = selfIdx + 1
        }
    }
    list := make([]model.LeaderCompany, 0, industryPeersTopN)
    for i := range ranked {
        if ranked[i].Code == selfCode {
            continue // D10：龙头列表不含自身
        }
        list = append(list, ranked[i])
        if len(list) == industryPeersTopN {
            break
        }
    }
    return model.LeaderBoard{SelfRank: selfRank, Companies: list}
}
```

**边界说明**
- 自身是否出现：`gsgm` 自身与 `gsgm_zsz` 合并去重排序后，**始终跳过自身**；若自身位于前 3，则第 4 名顺延补足 3 家；若自身不在前 3，正常取前 3，`SelfRank=0`（字段省略）。
- `SelfRank` 取自身行的**有效排名**：优先上游 `TOTAL_CAP_RANK`，缺失时回退排序位置（`index+1`）；仅当自身排序位置在前 3 时才写入，否则为 0。
- 榜单只有本公司：`Companies` 为空非 nil 数组，`SelfRank=1`；api 层仍保留 `Leaders`（用于前端展示「本公司也是该行业龙头」）。
- `TOTAL_CAP` 缺失按 0 处理，排在有效市值之后；不随机重排。
- 北交所沿用 `quotePrefix` 的既有判定（`920/43/83/87/88 → bj`）；接口不支持时静默为空。

// parseChain 解析 chain 对象；整体缺失/类型错误/上下游均空 → nil。
// selfName 透传给 sanitizeCompanyRefs，确保自身在截断前被排除。
func parseChain(raw json.RawMessage, selfName string) *model.AIChain {
    if len(raw) == 0 || string(raw) == "null" {
        return nil
    }
    var c struct {
        Upstream   json.RawMessage `json:"upstream"`
        Downstream json.RawMessage `json:"downstream"`
    }
    if err := json.Unmarshal(raw, &c); err != nil {
        return nil
    }
    up := sanitizeCompanyRefs(parseCompanyRefs(c.Upstream), selfName)
    down := sanitizeCompanyRefs(parseCompanyRefs(c.Downstream), selfName)
    if len(up) == 0 && len(down) == 0 {
        return nil
    }
    return &model.AIChain{Upstream: up, Downstream: down}
}

// parseCompanyRefs 逐条宽松解析：顶层不是数组 → nil；单条类型异常只丢该条/该字段。
func parseCompanyRefs(raw json.RawMessage) []model.CompanyRef {
    if len(raw) == 0 || string(raw) == "null" {
        return nil
    }
    var items []json.RawMessage
    if err := json.Unmarshal(raw, &items); err != nil {
        return nil
    }
    out := make([]model.CompanyRef, 0, len(items))
    for _, item := range items {
        var m map[string]any
        if err := json.Unmarshal(item, &m); err != nil {
            continue
        }
        out = append(out, model.CompanyRef{
            Name:     stringField(m, "name"),
            Code:     codeField(m, "code"),
            Market:   stringField(m, "market"),
            Relation: stringField(m, "relation"),
            Note:     stringField(m, "note"),
        })
    }
    return out
}

func stringField(m map[string]any, key string) string {
    if v, ok := m[key].(string); ok {
        return v
    }
    return "" // 非字符串一律按空处理
}

// codeField 兼容 AI 把代码写成数字；数字 000858 会退化为 858，随后因非 6 位被丢弃（可接受）。
func codeField(m map[string]any, key string) string {
    switch v := m[key].(type) {
    case string:
        return strings.TrimSpace(v)
    case float64:
        return strconv.FormatFloat(v, 'f', -1, 64)
    default:
        return ""
    }
}

// sanitizeCompanyRefs 清洗、去重、排除自身、截断、上限。
// selfName 非空时，同名条目在「记入 seen / 计入上限」之前直接丢弃——
// 避免自身占用 3 个名额导致最终只剩 2 家（必须先排除再截断）。
func sanitizeCompanyRefs(in []model.CompanyRef, selfName string) []model.CompanyRef {
    seen := make(map[string]bool, len(in))
    selfKey := NormalizeQuery(selfName)
    out := make([]model.CompanyRef, 0, aiCompanyMax)
    for _, c := range in {
        name := strings.TrimSpace(c.Name)
        if name == "" {
            continue
        }
        key := NormalizeQuery(name) // 与 R11 同口径：去全部空白 + 大写
        if key == "" || key == selfKey || seen[key] {
            continue
        }
        code := strings.TrimSpace(c.Code)
        if !isSixDigitCode(code) {
            code = "" // 代码非法只丢字段，不丢整条
        }
        market := strings.TrimSpace(c.Market)
        if market != "非A股" {
            market = "A股" // 缺省/非法一律按 A股
        }
        seen[key] = true
        out = append(out, model.CompanyRef{
            Name:     truncateRunes(name, aiCompanyNameMax),
            Code:     code,
            Market:   market,
            Relation: truncateRunes(strings.TrimSpace(c.Relation), aiRelationMaxRunes),
            Note:     truncateRunes(strings.TrimSpace(c.Note), aiNoteMaxRunes),
        })
        if len(out) == aiCompanyMax {
            break
        }
    }
    return out
}

// truncateRunes 按字符截断并加省略号，保证总长度 ≤ max。
func truncateRunes(s string, max int) string {
    if utf8.RuneCountInString(s) <= max {
        return s
    }
    r := []rune(s)
    return string(r[:max-1]) + "…"
}

async function openAICompany(c) {
  if (!c || companyResolveBusy || searchBusy) return;
  const key = companyKey(c);
  if (c.market === '非A股') {
    companyHint.value = '非 A 股公司，暂不支持财报分析';
    return;
  }
  companyResolveBusy = true;
  companyResolving.value = key;
  companyHint.value = '';
  try {
    const r = await fetchSearch(c.name); // 复用 R11：60s 缓存、失败静默
    if (!r.ok) {
      companyHint.value = `搜索服务暂不可用，请手动搜索「${c.name}」`;
      return;
    }
    const norm = normalizeQueryInput(c.name);
    const exact = r.items.filter(it => normalizeQueryInput(it.name) === norm);
    let hit = null;
    if (exact.length === 1) {
      hit = exact[0];                       // ① 名称完全相等
    } else if (exact.length > 1) {
      // ② 完全同名多于一条：仅当 AI code 为 6 位且命中同名候选时才用它消歧
      if (isSixDigitCode(c.code)) {
        hit = exact.find(it => it.code === String(c.code)) || null;
      }
    } else if (r.items.length === 1) {
      hit = r.items[0];                     // ③ 无完全同名且仅 1 条候选
    }
    if (!hit) {
      companyHint.value = `未找到唯一匹配的 A 股公司，请手动搜索「${c.name}」`;
      return;
    }
    companyHint.value = `已解析为 ${hit.name}（${hit.code}），正在切换…`;
    code.value = hit.code;                  // 最终必须用 6 位代码
    await doSearch();                       // 清空 aiResult、加载新公司数据；不自动触发 AI 分析
  } finally {
    companyResolveBusy = false;
    companyResolving.value = '';
  }
}

- 以**名称**为唯一展示主键；AI 的 `code` 不展示、不拼进 `/api/stock/:code/...`。
- `code` 只在「完全同名候选 > 1」时参与消歧，且必须命中同名候选；绝不用于非精确候选之间选择。
- 失败/歧义只写 `companyHint`，不调用 `doSearch`，当前股票与 `aiResult` 均不变。
- 同一时刻只有一个解析请求（`companyResolveBusy`），被点击标签显示「解析中…」并降低透明度。

### 21.10 关键决策点 / 待确认项

| 编号 | 决策点 | 推荐方案 | 理由 / 备选 |
| --- | --- | --- | --- |
| D1 | 行业名回退是否需要新增一次 DMSK 请求（需求假设报表行自带，实测 F10 没有） | **新增 `FetchIndustry`（2s、与 LLM 并发、与 `/indicators` 共享缓存 key）** | 正常页面流程命中缓存、实际 0 请求；冷启动最多 1 次 2s 短请求且不影响时长；行业名缺失只影响标题。备选：严格只允许 1 次新增请求时，去掉回退、仅用 `IndustryFromReportRows`，标题降级为「行业龙头（按总市值排序）」。建议按推荐方案实现，若验收卡「新增请求数」再切换备选。 |
| D2 | 龙头是否随 AI 结果缓存 | **随结果缓存（10min，key 不变）** | 需求 FR-9 明确允许；保证同 key 结果一致；命中缓存不再请求上游；失败空结果 TTL 内不重试属可接受降级。备选：独立短 TTL 龙头缓存，但会破坏「同 key 完全一致」。 |
| D3 | 全局龙头是否保留自身 | **D10 改为：始终排除自身，前 3 顺延；自身排名写入 `self_rank`** | 用户澄清「龙头列表本身不含自身」，避免「龙头榜里混入本公司」；自身信息用独立提示表达。与 D9 前口径不同，以 §21.13.3 为准。 |

| D5 | AI 公司名超过 30 字如何处理 | **按字符截断并加省略号** | 需求只约束 relation/note 的截断方式；证券简称实际远小于 30 字，超长通常是 AI 输出法定全称，截断后搜索会失败并走行内提示，不会错误跳转。备选：直接丢弃超长名称。 |

### 21.11 D8 扩展：业务板块相关公司（`businesses[].related`）

#### 21.11.1 目标与边界

- 每个业务板块可带 **0–3 家**「板块相关公司」，输出在 `businesses[].related`，用于回答「这块业务具体和哪些公司相关」。
- 与既有四组数据的关系（**互补、不合并、不跨列表去重**）：

| 数据 | 来源 | 粒度 | 解析方式 | 前端跳转 |
| --- | --- | --- | --- | --- |
| `leaders` | 东财 emweb（确定性） | 公司整体行业龙头（不含自身） | 后端 `buildLeaderBoard` | **代码直跳**（不搜索） |
| `chain.upstream/downstream` | AI 推断 | 公司整体产业链 | 后端 `parseChain` | 名称搜索 |
| `partners` | AI 推断 | 公司整体合作方 | 后端 `sanitizeCompanyRefs` | 名称搜索 |
| **`businesses[].leaders`** | **AI 推断** | **单个业务板块所属细分行业龙头** | **每板块独立 `sanitizeCompanyRefs`** | **名称搜索** |
| **`businesses[].related`** | **AI 推断** | **单个业务板块相关方** | **每板块独立 `sanitizeCompanyRefs`** | **名称搜索** |

- 同一家公司允许同时出现在 `leaders`、`chain`、`partners`、多个业务板块的 `related` 中；后端**不得**做跨列表去重、合并或互相覆盖（需求明确要求）。

**`parseBusinesses` 实现**：

```go
// parseBusinesses 逐条宽松解析业务板块；顶层不是数组 → nil；单条异常只丢该条。
// 每条 related 复用 parseCompanyRefs + sanitizeCompanyRefs：
// 先排除自身、再去重、再截断到 3 家；不同板块的 seen 互相独立（不跨板块去重）。
func parseBusinesses(raw json.RawMessage, selfName string) []model.AIBusiness {
    if len(raw) == 0 || string(raw) == "null" {
        return nil
    }
    var items []json.RawMessage
    if err := json.Unmarshal(raw, &items); err != nil {
        return nil // businesses 为对象/字符串等脏类型：整体按空，不影响其余字段
    }
    out := make([]model.AIBusiness, 0, len(items))
    for _, item := range items {
        var b struct {
            Name         string          `json:"name"`
            Stage        string          `json:"stage"`
            Contribution string          `json:"contribution"`
            Prospect     string          `json:"prospect"`
            Risk         string          `json:"risk"`
            Leaders      json.RawMessage `json:"leaders"` // D10：类型异常只影响本板块 leaders
            Related      json.RawMessage `json:"related"` // D8：类型异常只影响本板块 related
        }
        if err := json.Unmarshal(item, &b); err != nil {
            continue // 单条板块字段类型异常：丢该板块，保留其余板块
        }
        if strings.TrimSpace(b.Name) == "" {
            continue // null / 空对象 / 缺板块名：无法展示，直接丢弃
        }
        // leaders 与 related 各自独立解析/清洗/截断，互不去重、互不覆盖。
        leaders := sanitizeCompanyRefs(parseCompanyRefs(b.Leaders), selfName)
        related := sanitizeCompanyRefs(parseCompanyRefs(b.Related), selfName)
        if len(leaders) == 0 {
            leaders = nil // omitempty：无板块龙头不输出空数组
        }
        if len(related) == 0 {
            related = nil // omitempty：无相关公司不输出空数组
        }
        out = append(out, model.AIBusiness{
            Name:         b.Name,
            Stage:        b.Stage,
            Contribution: b.Contribution,
            Prospect:     b.Prospect,
            Risk:         b.Risk,
            Leaders:      leaders,
            Related:      related,
        })
    }
    if len(out) == 0 {
        return nil
    }
    return out
}
```

**解析边界（务必按此实现）**：

- `businesses` 缺失 / `null` / 非数组 → 整个 `businesses` 为 nil，**不报错**。
- 单条板块元素不是对象 / 为 `null` / 缺 `name` / 基础字段类型错误 → 只丢该板块，其余板块正常（空名称板块无法渲染，直接跳过）。
- `related` 缺失 / `null` / 非数组 / 清洗后为空 → 该板块 `Related=nil`：**只隐藏该板块的「相关公司」子块，业务板块卡片本身与其他字段保留**。
- `related` 单条非对象 / 字段类型错误 → 只丢该条/该字段（`parseCompanyRefs` 现有行为）。
- `related` 清洗与 `chain` / `partners` 完全同口径：空名丢弃、名称去全部空白+大写后去重、自身排除、非法 code 只丢 code、`market` 非法归 `A股`、relation/note 截断、每板块上限 3。
- **自身排除在每个板块内独立执行**；自身出现在多个板块时，每个板块各丢一次，不影响其他板块。
- **不做任何跨列表操作**：不把 `leaders` 塞进 `related`，不把 `related` 与 `chain` / `partners` 合并或去重，不因某公司已出现在 `chain` 而将其从某板块 `related` 中删除（反向亦然）。
- **D10 更新**：`businesses[].leaders` 现已纳入解析（见 §21.13.4），与 `related` 各自独立清洗；AI 伪造的**顶层** `leaders` / `competitors` 仍一律忽略。上文的跨列表规则同样适用于 `leaders` 与 `related` 之间：同一公司可同时出现在两者中，不做去重。

### 21.12 D9 扩展：主要竞争对手（`competitors`）——已回退

> **状态：已被 D10 取代，禁止按本节实现。** 用户澄清取消全局「主要竞争对手」，D9 已落地的 `CompetitorBoard` / `LeaderCompany.RankDistance` / `AIAnalysisResult.Competitors` / `buildCompetitors` / 前端展示块与相关测试全部回退；完整清理清单与最终口径见 §21.13。本节仅保留为历史设计记录，便于理解为何删除。

#### 21.12.1 目标与口径

- 在行业分析内、行业龙头之下新增「主要竞争对手」：与本公司**行业总市值排名相邻**的 2–4 家公司。
- **同源同请求**：与 `leaders` 来自同一次 emweb `IndustryAnalysis` 拉取、同一份合并排名榜（`gsgm` + `gsgm_zsz`）；不新增 HTTP 请求、不新增 LLM 调用、不新增缓存。
- **确定性**：完全由后端按榜单排名计算，AI 不参与；AI 返回的 `competitors` 一律忽略。
- **取值规则（FR-12）**：
  1. 以本公司有效排名 `R` 为锚（优先 `gsgm[0].TOTAL_CAP_RANK`，缺失回退市值降序榜位置）；
  2. 按 `R-1 → R+1 → R-2 → R+2` 顺序取同行（即单侧至多 2 家、合计至多 4 家）；
  3. 排除自身；有效候选 **<2 家 → 整块为空**（`Competitors=nil`）；
  4. 最终按排名升序输出，每家带 `rank_distance = |peerRank - R|`（1 或 2）。
- **不跨列表去重**：`competitors` 与 `leaders` 允许重叠（本公司排名第 3 时，排名第 1/2 的公司既是龙头也是竞争对手）；与 `chain` / `partners` / `businesses[].related` 同样互不合并、互不删除。
- 失败语义：emweb 请求失败/超时/非 JSON → `leaders` 与 `competitors` **同时为空**；仅 `competitors` 候选不足时，`leaders` 正常返回。

#### 21.12.2 model

见 §21.3.5。要点：

    IndustryCode string          `json:"industry_code,omitempty"`
    IndustryName string          `json:"industry_name,omitempty"`

**排名榜构建（唯一排序口径）**：

```go
// rankIndustryPeers 合并自身与同行，过滤哨兵/非法行，去重，按总市值降序，
// 并回填有效排名：优先响应里的 TOTAL_CAP_RANK，缺失时按排序后的榜单位置（index+1）。
func rankIndustryPeers(selfCode string, peers []industryPeer) []model.LeaderCompany {
    seen := make(map[string]bool, len(peers))
    list := make([]model.LeaderCompany, 0, len(peers))
    for _, p := range peers {
        name := strings.TrimSpace(p.Name)
        code := strings.TrimSpace(p.Code)
        if name == "" || !isSixDigitCode(code) {
            continue
        }
        if strings.Contains(name, "行业平均") || strings.Contains(name, "行业中值") {
            continue
        }
        if seen[code] {
            continue // 同代码只保留首次（gsgm 在前，自身优先）
        }
        seen[code] = true
        m := quotePrefix(code)
        list = append(list, model.LeaderCompany{
            Name:         name,
            Code:         code,
            Market:       m,
            MarketLabel:  marketLabel(m),
            TotalCap:     toFloat(p.TotalCap),
            TotalCapRank: int(toFloat(p.TotalCapRank)), // 可能为 0，排序后回填
            IsSelf:       code == selfCode,
        })
    }

    sort.SliceStable(list, func(i, j int) bool {
        ci, cj := list[i].TotalCap, list[j].TotalCap
        if ci == 0 && cj == 0 {
            return false // 均缺失：保持接口返回顺序
        }
        if ci == 0 {
            return false // 缺失市值后置
        }
        if cj == 0 {
            return true
        }
        if ci != cj {
            return ci > cj
        }
        return list[i].Code < list[j].Code
    })

    for i := range list {
        if list[i].TotalCapRank <= 0 {
            list[i].TotalCapRank = i + 1 // 回退：市值降序榜位置
        }
    }
    return list
}

// buildLeaderBoard 保持原签名/原语义，供既有单测与调用方使用。
func buildLeaderBoard(selfCode string, peers []industryPeer) model.LeaderBoard {
    return topLeaderBoard(rankIndustryPeers(selfCode, peers))
}

func buildIndustryBoards(selfCode string, peers []industryPeer) (model.LeaderBoard, *model.CompetitorBoard) {
    ranked := rankIndustryPeers(selfCode, peers)
    return topLeaderBoard(ranked), buildCompetitors(ranked)
}

func topLeaderBoard(ranked []model.LeaderCompany) model.LeaderBoard {
    n := len(ranked)
    if n > industryPeersTopN {
        n = industryPeersTopN
    }
    list := make([]model.LeaderCompany, n) // n=0 时仍是非 nil 空数组，保持既有契约
    copy(list, ranked[:n])
    return model.LeaderBoard{Companies: list}
}
```

**竞争对手选择**：

```go
// buildCompetitors 以本公司有效排名 R 为锚，按 R-1 → R+1 → R-2 → R+2 取同行。
// 单侧至多 2 家、合计至多 4 家；有效候选 <2 家返回 nil。
func buildCompetitors(ranked []model.LeaderCompany) *model.CompetitorBoard {
    selfIdx := -1
    for i := range ranked {
        if ranked[i].IsSelf {
            selfIdx = i
            break
        }
    }
    if selfIdx < 0 {
        return nil // 榜单里没有本公司，无法确定锚点
    }
    selfRank := ranked[selfIdx].TotalCapRank
    if selfRank <= 0 {
        return nil // rankIndustryPeers 已回填，理论不会发生
    }

    // 排名 → 同行；同排名只保留市值榜中靠前者（确定性）。
    byRank := make(map[int]model.LeaderCompany, len(ranked))
    for _, c := range ranked {
        if c.IsSelf {
            continue
        }
        if _, ok := byRank[c.TotalCapRank]; !ok {
            byRank[c.TotalCapRank] = c
        }
    }

    targets := []struct{ rank, distance int }{
        {selfRank - 1, 1},
        {selfRank + 1, 1},
        {selfRank - 2, 2},
        {selfRank + 2, 2},
    }

    out := make([]model.LeaderCompany, 0, industryCompetitorMax)
    for _, t := range targets {
        if t.rank <= 0 {
            continue
        }
        c, ok := byRank[t.rank]
        if !ok {
            continue
        }
        c.RankDistance = t.distance
        out = append(out, c)
        delete(byRank, t.rank) // 四个目标互不重复，双保险
        if len(out) == industryCompetitorMax {
            break
        }
    }
    if len(out) < industryCompetitorMin {
        return nil // 有效候选 <2 家：整块为空
    }

    sort.SliceStable(out, func(i, j int) bool {
        if out[i].TotalCapRank != out[j].TotalCapRank {
            return out[i].TotalCapRank < out[j].TotalCapRank
        }
        return out[i].Code < out[j].Code
    })
    return &model.CompetitorBoard{SelfRank: selfRank, Companies: out}
}
```

**`R` 的确定与回退（严格按此优先级）**：

1. `gsgm[0].TOTAL_CAP_RANK`（有效正数）；
2. 若 `gsgm` 缺失，则取合并榜中 `code == selfCode` 行的 `TOTAL_CAP_RANK`；
3. 仍缺失 → 该行在**市值降序榜**中的位置 +1（`rankIndustryPeers` 统一回填）；
4. 榜单中完全找不到本公司 → `Competitors=nil`（无法确定锚点），`Leaders` 仍按前 3 返回。

> 由于 `gsgm` 在合并时排在最前、去重保留首次，自身行的 `TOTAL_CAP_RANK` 天然等于 `gsgm[0].TOTAL_CAP_RANK`，与需求优先级一致。
>
> 同行行的有效排名同样「优先 `TOTAL_CAP_RANK`、缺失回退榜单位置」；目标排名在榜中不存在（如接口只返回部分同行）时直接跳过，因此可能得到 2–3 家或最终为空。

**为什么按「排名映射」而不是直接取 `ranked[selfIdx±1]`**：
- 上游 `gsgm_zsz` 的 `TOTAL_CAP_RANK` 可能不连续（实测 `000998` 的同行排名为 1/2/4/5/6，本公司为 3），直接取数组相邻项会把排名 4 误当成本公司「下一名」。
- 排名映射严格按 `R±1/±2` 命中；目标不存在就跳过，符合「有效候选」口径。

#### 21.12.7 D9 设计决策

| 编号 | 决策点 | 推荐方案 | 理由 / 备选 |
| --- | --- | --- | --- |
| Q1 | `rank_distance` 的语义 | **绝对距离 1/2（不带方向）** | 需求只要求「带 rank_distance」；前端展示「相邻 N 名」无歧义，也避免「前一/后一」被误解为涨跌方向。备选：带符号 `-2..+2`，需前端额外映射，收益低。 |
| Q2 | 取邻居用「排名映射」还是「数组相邻」 | **排名映射** | 上游排名可能不连续（实测 `000998` 为 1/2/4/5/6，自身 3），数组相邻会错取；映射严格符合 `R±1/±2`。 |
| Q3 | 排名缺失如何回退 | **市值降序榜排序后的位置 +1** | 与需求「缺失回退榜单位置」一致；在排序后回填，避免用合并前的原始下标（`gsgm` 恒在首位会失真）。 |
| Q4 | 有效候选 <2 家 | **`Competitors=nil`，整块不输出** | 需求明确；避免只有 1 家时给出误导性的「竞争对手」结论。 |
| Q5 | 与 leaders 重叠是否去重 | **不去重** | 需求明确「与 leaders 重叠不去重、不跨列表去重」；排名第 3 的本公司，其前两名天然同时是龙头与竞争对手。 |
| Q6 | `buildLeaderBoard` 是否改签名 | **保留原签名作为薄包装** | 既有单测与调用方零改动；新逻辑集中在 `rankIndustryPeers` / `buildIndustryBoards` / `buildCompetitors`，降低回归风险。 |

**取数与选择算法**

```go
// FetchIndustryPeers 恢复单返回值；失败由 api 层静默降级。
func (c *Client) FetchIndustryPeers(code string) (model.LeaderBoard, error) {
    if !isSixDigitCode(code) {
        return model.LeaderBoard{}, fmt.Errorf("股票代码需为6位数字")
    }
    return c.fetchIndustryPeersURL(code, industryURL(code))
}

func (c *Client) fetchIndustryPeersURL(selfCode, rawURL string) (model.LeaderBoard, error) {
    body, err := c.get(c.hcFast, rawURL)
    if err != nil {
        return model.LeaderBoard{}, err
    }
    if trimmed := strings.TrimSpace(string(body)); strings.HasPrefix(trimmed, "<") {
        return model.LeaderBoard{}, fmt.Errorf("行业同行接口返回了非 JSON 内容（疑似限流或代理拦截）：%s", truncate(trimmed, 200))
    }
    var r industryAnalysisResp
    if err := json.Unmarshal(body, &r); err != nil {
        return model.LeaderBoard{}, err
    }
    peers := make([]industryPeer, 0, len(r.Gsgm)+len(r.GsgmZsz))
    peers = append(peers, r.Gsgm...)
    peers = append(peers, r.GsgmZsz...)
    return buildLeaderBoard(selfCode, peers), nil
}

// rankIndustryPeers：过滤哨兵/非法行、按代码去重、按总市值降序、
// 回填有效排名（优先 TOTAL_CAP_RANK，缺失用排序位置 index+1）。不再标记自身。
func rankIndustryPeers(peers []industryPeer) []model.LeaderCompany {
    // ...过滤/去重/构造 list（不设置 IsSelf）...
    sort.SliceStable(list, /* 总市值降序，同市值按代码升序，缺失市值后置，均缺失保持接口顺序 */)
    for i := range list {
        if list[i].TotalCapRank <= 0 {
            list[i].TotalCapRank = i + 1
        }
    }
    return list
}

// topLeaderBoard：跳过自身取前 3；自身位于排序榜前 3 时记录有效排名。
func topLeaderBoard(ranked []model.LeaderCompany, selfCode string) model.LeaderBoard {
    selfIdx := -1
    for i := range ranked {
        if ranked[i].Code == selfCode {
            selfIdx = i
            break
        }
    }
    selfRank := 0
    if selfIdx >= 0 && selfIdx < industryPeersTopN {
        selfRank = ranked[selfIdx].TotalCapRank
        if selfRank <= 0 { // 理论上 rankIndustryPeers 已回填，双保险
            selfRank = selfIdx + 1
        }
    }
    list := make([]model.LeaderCompany, 0, industryPeersTopN)
    for i := range ranked {
        if ranked[i].Code == selfCode {
            continue
        }
        list = append(list, ranked[i])
        if len(list) == industryPeersTopN {
            break
        }
    }
    return model.LeaderBoard{SelfRank: selfRank, Companies: list}
}

func buildLeaderBoard(selfCode string, peers []industryPeer) model.LeaderBoard {
    return topLeaderBoard(rankIndustryPeers(peers), selfCode)
}
```

**边界与示例（必须逐项覆盖）**

| 场景 | `Companies`（代码顺序） | `SelfRank` | 说明 |
| --- | --- | --- | --- |
| 自身排名 1，榜 1–5 | 2, 3, 4 | 1 | 跳过自身，顺延第 4 补足 3 |
| 自身排名 2，榜 1–5 | 1, 3, 4 | 2 | 同上 |
| 自身排名 3，榜 1–5 | 1, 2, 4 | 3 | 同上 |
| 自身排名 4，榜 1–5 | 1, 2, 3 | 0（省略） | 自身不在前 3，正常取前 3 |
| 自身不在榜单 | 1, 2, 3 | 0（省略） | 上游未返回自身；不影响龙头 |
| 只有本公司 | `[]`（非 nil） | 1 | api 仍保留 `Leaders`，前端只显示自身龙头提示 |
| 有效同行仅 1 家，自身第 1 | 该同行 | 1 | 不足 3 家按实际数量 |
| `TOTAL_CAP_RANK` 缺失 | 按市值排序后位置 | 回退位置 | 优先上游排名，缺失用排序位置 |
| 重复自身行（gsgm + gsgm_zsz） | 去重后只跳过一次 | 正确 | 同代码只保留首次 |

#### 21.13.8 D10 设计决策 / 待确认

| 编号 | 决策点 | 推荐方案 | 理由 / 备选 |
| --- | --- | --- | --- |
| R1 | `LeaderCompany.IsSelf` 是否保留但恒 false | **删除字段** | 前端同二进制发布，无外部消费者；保留死字段会让前端继续写 `is_self` 分支，违背「列表不含自身」的语义。 |
| R2 | `SelfRank` 是否 `omitempty` | **是，0 省略** | 只有前 3 才有展示价值；旧响应缺字段自然为 0，前端 `v-if` 简洁。 |
| R3 | 自身前 3 但 `Companies` 为空时是否保留 `Leaders` | **保留（`len>0 || SelfRank>0`）** | 行业榜只有本公司时仍应提示「本公司也是该行业龙头」；否则 `self_rank` 永远无法展示。若产品要求「无同行不显示龙头块」，可改为仅在 `len>0` 时保留。 |
| R4 | `self_rank` 取上游 `TOTAL_CAP_RANK` 还是排序位置 | **优先上游，缺失回退 `index+1`** | 与既有「有效排名」口径一致；排序位置用于判断是否前 3。上游排名异常时以排序位置为准更稳，但会偏离接口原始排名，需按实际数据验证。 |
| R5 | 板块龙头与相关公司展示顺序 | **`leaders` 在上、`related` 在下** | 先看行业格局、再看上下游/合作方，符合阅读顺序；需求允许两者上下任选。 |
| R6 | 板块龙头点击是否允许 code 直跳 | **不允许，统一 `openAICompany`** | 与 D8 一致；AI 代码可能幻觉，名称搜索更安全。 |
| R7 | 是否因旧缓存含自身而改缓存 key | **不改** | 约束「缓存 key 不变」；旧缓存 TTL 10 分钟，重启即清；前端忽略 `is_self`，最坏短暂多一个自身 chip。 |
| R8 | token 超 900 预算怎么办 | **优先压缩 leaders 的 note/数量，不新增调用** | 典型 500–900 tokens；最坏约 1.1k。若验收严格，可令 `leaders` 只输出 `name` + `relation`，或每板块最多 2 家；不得改 `max_tokens` 或加第二次调用。 |

> 唯一需要主对话拍板的是 R3（仅本公司时是否显示龙头提示）与 R8（严格 900 token 预算时是否压缩 leaders）。其余按推荐方案落地。
