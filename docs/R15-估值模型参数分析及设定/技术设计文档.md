### 19.1 设计目标与影响面

**目标**：在不破坏 R7「确定性推导、大模型不产出数值」纪律的前提下，把估值参数（重点是**折现率 r**）从「信用风险分档」升级为「有经济学含义的资本成本推导」，并在出口处对**不适用于现金流贴现法**的公司（金融股 / 负 FCF / 亏损）明确给出「不适用」结论而非硬套模型。

**R7 语义的精确化（本次修订，非推翻）**：R7 的原文表述是「大模型不产出**任何数值**，参数全部由后端确定性推导」。本设计的 §19.12 把这条纪律**精确化**为：

> 大模型**不产出数值**，但**可以产出受约束的定性分类（枚举三选一）**；该分类经由**后端常量表**确定性映射为数值（β），再由确定性推导链（Re → WACC 基线 → 收口 r → gk → 参数）导出全部下游数值。

区分点在于「**产出的是分类，不是数值**」，且分类空间被硬约束为 3 个枚举 —— AI 无法把任意数字注入参数（这是 R7 要防的），但仍可贡献它在 R7 框架下**唯一不可由财报推导**的那部分信息（行业属性）。**代价（须知悉）**：R7 的「同股多次分析结果逐字段相同」由「无条件成立」弱化为「**给定相同 `industry_type` 时逐字段相同**」——分类本身是定性判断，与 `rationale` 属同类（DeepSeek 客户端 `Temperature=0.0`，`deepseek.go:92`，实践中稳定，但非数学保证）；其参数方差被枚举**限定为至多 2 个离散档位**（r 至多相差 ~1.1pp），不存在无界漂移。若 AI 未给出合法分类，回落路径（§19.12.2）完全确定性，与初稿的两档方案一致。

### 19.2 总体架构与数据流

```
GetAIAnalysis (api/ai.go:17)
  └─ fetchAnalysisReports(code, cfPageSize=40, bsPageSize=44)   // ★资产负债表≈11 个年报（多期可得）
  └─ RecommendValuation(balance, cashflow, income)   // ★第一次（预推导）：industry_type 未知，β 走 volatile 兜底
       ├─ (既有) 基准增速 X / Volatile / 模型 / 研发调整 / 基期 FCF 推荐
       ├─ (P1 新增) riskPoints,hasBalance := valuationRiskPoints(最新年资产负债表, 最新年利润表)   // 沿用既有
       ├─ (P1 新增) dr := recommendDiscountRate(..., industryType="") // ★WACC 基线 + 风险溢价 → clamp → 0.5 网格
       │        └─ betaFor("", volatile) → 兜底 β；waccWithEquityCost(...) ← 复用 debtCapitalCost / effectiveTaxRate / interestBearingDebt / equityValue
       ├─ (P1 新增) gk := min(longTermGDP, perpetualGrowthRaw(r))   // 上限常量显式化（G6）
       └─ (P1 新增) 出口收口：一致性守卫(C1~C3) + 不适用判定(Q6) → Warning 多条拼接
  └─ BuildAIPrompt(..., rec) → valuationPromptBlock 喂「r 构成 + 请判定 industry_type」给大模型（只写 rationale / 只给分类）
  └─ llm.Chat → ParseAIResult(raw)                // result.Valuation.IndustryType = AI 的原始分类
  └─ (★本次修订新增) RecommendValuationWithIndustry(balance, cashflow, income, result.Valuation.IndustryType)
       ↑ 第二次（终态）：betaFor(industryType, volatile) → 常量表 β → 重算 Re/WACC 基线/r/gk/Params（其余字段与第一次相同）
  └─ ApplyValuationRecommendation(&result, rec)   // 覆盖全部只读字段（含 IndustryType/IndustryTypeName/Beta/BetaTier），保留 rationale
  └─ 前端：展示「行业类型 + β 档位 + r 构成」/ 不适用提示；applicable===false 时禁用「套用到估值」
```

- 新增逻辑全部在 **service（纯函数、无 IO、无随机、无时间依赖）**；`client` 不新增拉取，`api` 只在既有 `GetAIAnalysis` 内**多调一次纯函数**（第二次调用不产生 IO，只做算术）。符合分层单向依赖。
- **不新增数据源**（Q9）：`Rf` / `ERP` / `β` 全部取代码内常量表；`industry_type` 不是新数据源，而是**大模型对已有输入（主营构成 `SegmentIncome` + 指标 + 行业常识）的定性归纳**，前端不因它新增任何拉取。
- **两次推导的一致性**：第二次调用复用**同一个** `recommendValuation(...)` 实现（§19.12.4），唯一入参差异是 `industryType`；模型 / 基准增速 / 波动 / 研发调整 / 基期 FCF 推荐均与第一次逐位相同（它们不依赖 β）。

**P2~P4 数据流增量**（在同一 `recommendValuation` 内，纯算术、无新增 IO）：

```
annualRows(income/cashflow/balance) → baseYear（利润表∩现金流量表最新年，P4 C7）
  ├─ incomeWindow(≤5) / fcfYears(∩, ≤5；P3 起 ≤7) / fcfByYear
  ├─ [P2] growthComponents(营收/净利润/FCF) → X、volatile、GrowthDispersion
  ├─ [P2] roeWindow(≤5) + retentionRate(baseYear) → SGR
  ├─ [P2] classifyModelScore(X, 稳定性, ROE) → 模型档位 + ModelScore
  ├─ [P3] detectFCFCycle(fcfYears ≤7) → Cyclical/CV/SignChanges → 动态 fcf_years
  ├─ [P3] recommendDiscountRate(..., fallbackCyclical=volatile||Cyclical) → r/gk
  ├─ [P2/P3] recommendParams(模型, X, dispersion, gk, SGR) → 可能降级的模型 + 参数
  ├─ [P2/P3] RecommendBaseFCF(fcfByYear, fcfYears[, cycle]) → 基期 FCF 方式/年数
  ├─ [P3] rdAdjustSuggestion(incomeByYear, baseYear) → 研发双条件
  └─ [P4] C4/C5/C6/C7 追加到 warns → Warning 字符串
```

> 注：`balance` 在 AI 链路由 `bsPageSize=44`（≈11 年报）拉取，P2 的 SGR/ROE 窗口与 P4 的 ΔNWC 均可直接使用，**无需改 handler 取数**（§19.4）。
>
> **实现顺序约束**：`fcfByYear` / `detectFCFCycle` 必须**前移到 `recommendDiscountRate` 之前**（β 兜底依赖 `Cyclical`）；`classifyModelScore` 必须在 `recommendParams` 之前；`baseYear` 必须在所有取年函数之前。`go vet` 无法发现顺序错误，coder 须按此顺序组织 `recommendValuation`。

#### 19.5.2 推导链（伪代码级）

```
─ 输入：balanceByYear, incomeByYear, latest（三表最新年报年）, volatile（R7 已算）, riskPoints, hasBalance
─ 输入（本次修订新增）：industryType（大模型输出的行业分类原始串；预推导阶段为 ""）

Step 1  β 档位（AI 定性分类 → 常量表映射为主；volatile 仅在 AI 未分类时兜底；全确定性，见 19.12.2）
        key := normalizeIndustryType(industryType)     // 归一化到白名单，落空为 ""
        beta, tierKey, tierName, basis := betaFor(industryType, volatile)
          normalizeIndustryType 命中  → β = valIndustryBetas[key]（周期 1.2 / 一般 1.0 / 公用 0.8），basis = 「AI 行业分类」
          industryType 未命中（""）   → β = volatile ? 1.2(周期性) : 1.0(一般)，basis = 兜底（「波动兜底」/「缺省回落」）
        // 预推导阶段 industryType=""，故 Step 1 必走 volatile 兜底（= 初稿的两档方案），与旧结果一致

Step 2  股权成本 Re（CAPM）
        Re := equityCostCAPM(beta) = Rf(2.5) + beta × ERP(5.5)
          beta=1.0 → Re=8.0%（与原硬编码 8% 吻合，验证常量合理性）
          beta=1.2 → Re=9.1%

Step 3  WACC 基线
        if !hasBalance:
            baseline = NaN（不可算），Rate := valDiscountFallback(10.0)，premium := 0，加 Warning「缺少资产负债表…」
        else:
            base := waccWithEquityCost(balanceByYear, incomeByYear, latest, Re)   // 见 19.5.3
            baseline = (base == nil ? Re : *base)   // 投入资本=0（无债务且无权益）时退化为纯股权成本 Re
            premium := min(float64(riskPoints) × 1.0, valRiskPremiumCap)          // 0~3%

Step 4  收口：加风险溢价 → clamp[8,15] → 0.5 网格（四舍五入到 0.5）
        raw := baseline + premium
        r := round(raw / 0.5) × 0.5
        if r < 8  → r = 8
        if r > 15 → r = 15

Step 5  永续增长率 gk（G6：上限常量显式化）
        gkRaw := perpetualGrowthRaw(r)   // 沿用旧映射：r≤9→4；r≤11→3；else→2
        gk    := min(valLongTermGDP(4), gkRaw)

Step 6  自校验（出口一致性 C1~C3）：r > gk 恒成立（min r=8 > max gk=4），否则加 Warning（防御）
```

**Rf + β×ERP 与旧 8% 的衔接验证**：`β=1.0` 时 `Re = 2.5 + 1.0×5.5 = 8.0`，恰等于 `analysis.go:1751` 硬编码的股权成本，说明 P1 未凭空造数；r 的变化**只来自三处**：(a) WACC 里债务加权含真实 Rd（原先完全不含）、(b) 加公司特定风险溢价、(c) 网格放宽到 [8,15]。

> **为什么用「整函数重跑」而不是「局部改 β」**：β → Re → WACC 基线 → r → `gk` → `Params`（三阶段 `g2 = min(4, gk+1)`）是一条完整的确定性推导链，任何「只改 β 展示值、不改 r」或「只改 r、不改 Params」的局部更新都会留下**自相矛盾**的响应（β 与 r 不符、r 与 gk 不符）。整函数重跑保证「一个入口、一条链、两次调用只有 `industryType` 一个入参差异」，且重跑是纯算术（对 10 年期三表数据量级为微秒~毫秒级），相对一次 180s 超时的 LLM 调用可忽略（`deepseek.go:38`）。

### 19.6 P2（详细，可直接编码）：基准增速 FCF 口径 + 多信号模型分档 + 三阶段递减（G3+G4+G5+G7）

> 需求来源：方法论 §5（增长率）、§6（模型分档）、§8（C2/C4）、§10.2（G3~G5/G7）；用户授权「一切以最新方法论为准，可推翻旧规则」。
> **行为级变更**：X 口径、模型分档、g1 折减、SGR 上限、三阶段参数会**同时改变所有公司的推荐结果**；须在 P1 回归通过后整体切换（方法论 §11 P2 风险项）。

**目标**：

1. `X` 与贴现对象同口径：三项 = 营业收入、重构净利润、**经营资产自由现金流（FCF）**；显式等权。

5. **R13 解耦**：`RecommendBaseFCF` 不再吃 R7 的 `x/volatile`，改用 FCF 自身序列（消除「X 改口径 → R13 静默漂移」）。

#### 19.6.3 G3：三项稳健增速与等权 X

**单指标稳健增速 `indicatorGrowth(years []int, values []float64) (value float64, basis string, ok bool)`**：

```
if len(years) < 2 || len(values) != len(years) → (0, "", false)

// ① 同比增速样本（上年 > 0 才计入；上年 ≤ 0 时同比无意义，跳过而非记 0）
gs := []
for i = 1..n-1:
    if values[i-1] > 0 → gs.append((values[i]-values[i-1]) / values[i-1] × 100)

// ② 优先「同比去极值后中位数」
if len(gs) > 0:
    if len(gs) >= 4 → 排序后去掉最高、最低（各 1 个），再取剩余中位数
    else            → 直接取中位数（n=2 时中位数即平均）
    return (median, "同比去极值中位数", true)

// ③ 无有效同比点时，退化为窗口 CAGR（仅首末均为正且年份间隔 > 0）
if values[0] > 0 && values[n-1] > 0 && years[n-1] > years[0]:
    v := (pow(values[n-1]/values[0], 1/(years[n-1]-years[0])) - 1) × 100
    return (v, "CAGR", true)

return (0, "", false)
```

- **为什么优先同比中位数而不是 CAGR**：旧 P5 的问题是「3 年窗口只有 2 个同比点，对首末年异常敏感」；把窗口扩到 5 年（最多 4 个同比点）并去掉最高最低后，同比中位数比「只用首末两点」的 CAGR 更抗单年异常。CAGR 仅作为「所有上年均非正、但首末为正」时的兜底。
- 三项取值函数：营收 `revenue`（窗口 `incomeWindow`）、净利润 `netProfitReconstructed`（同）、FCF 为 `fcfByYear[y]`（窗口 `fcfGrowthYears`，即 FCF 序列的最近 5 年，与营收/净利润同窗但允许 FCF 序列整体更长）。
- **显式等权**：
  ```
  k := 可用项数（revOK + npOK + fcfOK，取值 1~3）
  X := (xRev + xNP + xFCF) / k          // 仅对可用项求和
  insufficient := k == 0
  ```
  缺项**不补 0**（补 0 会把「缺数据」误读成「零增长」）；`BaseGrowthNote` 写明「按 k 项等权（××样本不足）」。
- `BaseGrowthNote` 新文案（`years` 是同比终点年，不含窗口首年，措辞用「同比年度」）：
  ```
  近 4 个同比年度（2021、2022、2023、2024）基准增速按 3 项等权：营收 20.00%、净利润 20.00%、FCF 25.31%
  （营收/净利润为同比去极值中位数；FCF 为 CAGR）。
  ```
  样本年份不连续时沿用 `growthNote` 的「可计算的 N 个同比年度」措辞。
- **`volatile` 重定义（G5 稳定性信号）**：
  ```
  // ★不含经营现金流增速、不含 FCF 增速；且按指标分别计算，避免把「营收与净利润的水平差」误当波动
  revSpread := len(revYoY) >= valVolatileMinSamples(2) ? spread(revYoY) : (不可用)
  npSpread  := len(npYoY)  >= valVolatileMinSamples(2) ? spread(npYoY)  : (不可用)
  GrowthDispersion := max(可用的 revSpread / npSpread)；都不可用 → 0
  volatile := 任一可用 spread > valVolatileSpread(40)
  StabilityAvailable := 至少一个 spread 可用
  ```
  - **根因修复**：旧 `volatile` 把「经营活动现金流量净额同比增速」并入样本，经营现金流天然剧烈波动（茅台实测 `[81,38,-33]`），导致 15/16 非金融股 `volatile=true`。新样本只保留**营收与净利润**（盈利波动），FCF 的周期波动由 P3 的 `detectFCFCycle` 单独识别。
  - **为什么按指标分别算**：若把营收与净利润的同比点混在一起取极差，「营收稳定 10%、净利润稳定 30%」会被误判为 20pp 的波动（实际是水平差，不是波动）。取两指标**各自极差的最大值**，才是「最不稳定的那个指标」的真实波动。
  - `volatile` 仍保留在响应中（字段名/JSON 不变），但语义变为「营收或净利润增速波动」；前端文案相应改写（§19.6.9）。

```
       + (StabilityAvailable ? valModelWeightStability : 0)
       + (ROEAvailable      ? valModelWeightROE : 0)
score := (valModelWeightGrowth×Sg
        + (StabilityAvailable ? valModelWeightStability×Sst : 0)
        + (ROEAvailable      ? valModelWeightROE×Sroe : 0)) / total
ModelScore := round(score × 100) / 100      // 展示保留 2 位
```

**落档（按序命中，唯一出口）**：

```
if insufficient || X < 0 || X < valModelZeroMaxX(3) → zero
else if score ≥ 70 && X ≥ valModelThreeMinX(12)     → three_stage
else if score ≥ 45 && X ≥ valModelTwoMinX(6)        → two_stage
else if score ≥ 25                                  → perpetual
else                                                 → zero
```

- **边界平滑**：得分是连续函数，`X=19.9` 与 `20.1` 的得分差约 `0.6×2.5×0.2=0.3` 分，不再有「跨 20% 就换模型」的断崖；真正的硬闸门只剩 `X≥12 / X≥6 / X<3`（方法论 Q4 明确要求 `X<3` 归零增长）。
- **增速硬闸门的理由**：稳定性/ROE 只能「锦上添花」，不能把 5% 增速的成熟公司推到两阶段（否则与生命周期映射矛盾）；因此两阶段/三阶段分别要求 `X≥6 / X≥12`。
- **参考算例**（用于单测）：

#### 19.6.5 G4：SGR 上限与 g1 连续折减

**留存率与 SGR**：

```go
// retentionRate 留存率近似 = (期末股东权益 − 期初股东权益) ÷ 当期净利润，clamp[0,1]。
// 期初/期末权益必须 > 0、净利润必须 > 0；任一缺失/非正 → 不可用。
func retentionRate(balanceByYear, incomeByYear map[int]model.ReportRow, year int) (float64, bool)

// sustainableGrowth SGR = ROE(year) × retention × 100（%）。ROE 或留存率不可用 → ok=false。
func sustainableGrowth(balanceByYear, incomeByYear map[int]model.ReportRow, year int) (sgr, retention float64, ok bool)
```

- 口径说明：留存率用「股东权益增长率 ÷ 净利润」近似，**无法剔除增发/回购**（分红链路已删，`payout` 不可得，方法论 §5.1 允许该替代口径）。
- **行业增速上限**：方法论 G4 写「`min(X, SGR, 行业增速上限)`」。本项目**不新增行业增速常量表**（Q9：不新增数据源，且 A 股行业增速缺乏稳定免费口径），统一用既有 `valGrowthMax=30` 作为「生命周期/行业增速上限」代理；`valGrowthMin=-5` 为负增速下限。二者均已在 P1 常量表中，不新增。
- `SGR` 单位 %；`RetentionRate` 单位 0–1。
- **不可用降级**：`sgr <= 0` 或 `ok=false` → **不施加 SGR 上限**，`warns` 追加「可持续增长率不可用（留存率/ROE 数据不足），高增长期增长率未施加上限」。不得编造留存率。
- **上限按向下取整**：`g1cap := floor(sgr)`。因为 `g1` 是整数百分比，用 `floor` 才能保证 C4（`g1 ≤ SGR`）严格成立。
- 若 `g1` 被上限压低：`warns` 追加「高增长期增长率受可持续增长率 %.2f%% 约束（折减后为 %.2f%%）」；`Warning` 属于正常口径说明，**不是**「不适用」。

**g1 连续折减**（取代旧「volatile → floor(X/2)」）：

```
damping := StabilityAvailable ? clamp(GrowthDispersion × valGrowthDampingPerPP, 0, valGrowthDampingMax) : 0
g1raw := X × (1 − damping)
g1 := clamp(round(g1raw), valGrowthMin(-5), valGrowthMax(30))
if sgrOK && sgr > 0 {
    g1cap := floor(sgr)
    if g1 > g1cap { g1 = clamp(g1cap, valGrowthMin, valGrowthMax); warnSGR = true }
}
```

- 语义：增速离散度 0 → 不折减；40pp → 折减 16%；≥100pp → 折减 40%。旧规则「只要 volatile 就砍半」在修复 `volatile` 后仍过于粗暴，且对 `D=41pp` 与 `D=200pp` 一视同仁；连续折减单调、可单测。
- **年数仍按 X**：`n1, n2 = stageYears(X)` 不变。理由：折减的是「速度」（保守化），不是「跑道长度」；若按折减后的 g1 再缩短跑道，会双重保守。

**规则**（`g1` 按 19.6.5 计算；`gk` 为 P1 的 `min(valLongTermGDP, perpetualGrowthRaw(r))`）：


### 19.7 P3（详细，可直接编码）：周期识别 + 动态年数 + 研发双条件（G8+G9+G11）

```
        prevSign = s
    }
c.SignChanges = signChanges
c.Evaluated = len(vals) >= valCycleMinYears && mean > 0
if c.Evaluated {
    c.CV = stddev(vals) / mean      // 总体标准差（÷n），与均值同单位
}
c.Cyclical = c.Evaluated && (c.CV > valCycleCVThreshold || c.SignChanges >= valCycleSignChanges)
```

- **均值 ≤ 0 时不计算 CV**（负均值会让 CV 符号翻转、失去意义），且 `Evaluated=false → Cyclical=false`：现金流中枢为负的公司不适用「周期去极值平均」，交给 R2（全非正）/R4（最新年 ≤0）处理。
- 用**总体标准差（÷n）**而非样本标准差（÷(n−1)）：窗口就是全部可用历史，不涉及抽样推断；n=3 时两者差异显著，必须固定口径以免测试漂移。
- `SignChanges` 的实测参考：宝钢/中远海控等强周期股典型为 2~4 次；茅台/海天等消费股为 0~1 次。阈值 2 次为「至少一个完整低谷+高峰」。
- **为什么不用 `volatile`**：`volatile` 衡量的是营收/净利润增速，属于**成长稳定性**；FCF 周期是**现金流形态**。二者可同时为真或一真一假（如高增长但现金流为负的扩张期公司），混用会重复保守。

#### 19.7.3 G9：动态 `fcf_years`

```go
// fcfWindowYears 按 FCF 周期状态给出推荐窗口年数（不含可用年数截断）。
func fcfWindowYears(c fcfCycle) int {
    switch {
    case !c.Evaluated:                  return valFCFRecMaxYears // 数据不足：不额外缩短，交给 R1 兜底
    case c.Cyclical:                    return valFCFYearsCyclical
    case c.CV > valFCVMildThreshold:    return valFCFYearsMild
    default:                            return valFCFYearsStable
    }
}
```

| 状态 | 判据 | `fcf_years` | 理由 |
| --- | --- | --- | --- |
| 平稳 | `CV ≤ 0.30` | 3 | 近期水平代表性强，长窗口会把成长稀释掉 |
| 中等波动 | `0.30 < CV ≤ 0.50` | 5 | 平滑单年异常，同时保留近况 |
| 强周期 | `CV > 0.50` 或符号翻转 ≥2 | 7（取满可用） | 覆盖一轮周期，避免高点/低点单年 |
| 不可判定 | 年数 <3 / 均值 ≤0 | 7（取满可用） | 由 R1（<3 年）与 R2/R4 决定退化，不在此处猜 |

- **重要**：动态年数只在 `RecommendBaseFCF` 内部**决定窗口大小**，输出的 `FCFYears` 仍为实际使用年数（`latest/custom` 为 0）。这样前端 `fcf_years` 下拉与后端推荐始终一致。
- 前端控件 `valFCFYears` 的 `max=10`（`app.js:1361`）已覆盖 7，**无需改控件**。
- `R5` 的「单调增」判断在缩短后的窗口（平稳=3）上执行，会更容易判 latest；这是有意为之（平稳公司取近况）。若需更保守可把平稳档设为 5，属可调常量，不列为待确认。

**规则**：

```
highGrowth := (mdl == two_stage || mdl == three_stage) && g1 > gk
if !highGrowth → ""                                  // 永续/零增长不涉及扩张 Capex 假设

capRatio, ok := capexCoverage(cf, income)
if ok && capRatio > valCapexCoverageHigh:
    → "基期自由现金流为保全口径（仅扣折旧摊销与减值），近一年购建长期资产现金为保全性支出的 %.2f 倍，
       未扣除扩张性资本支出；在高增长假设下偏乐观，建议下调增长率或改用更低增速场景。"

// ΔNWC 增强（可选，仅当多期资产负债表可用）
delta, ok := deltaNWC(balanceByYear, baseYear)
if ok && baseFCF > valNWCMinFCF && delta > 0 && delta/baseFCF > valNWCDragRatio:
    → 追加（同一 C5 提示内用「；」连接）"营运资本同比增加 %.2f 亿元（占基期 FCF 的 %.0f%%），
       扩张期现金消耗未体现在基期 FCF 中。"
```

- **`baseFCF` 的来源**：用推荐结果复算 `selectBaseFCF(fcfByYear, fcfYears, rec.FCFMode, rec.FCFYears, rec.FCFCustomYuan)`（纯函数，与 R4 套用口径完全一致）；返回 error 或值 ≤0 → 跳过 ΔNWC 分量（不告警）。
- **`capexCoverage` 的分子**：`CONSTRUCT_LONG_ASSET`（购建固定资产、无形资产和其他长期资产支付的现金，`fields.go:80`），**不减** `DISPOSAL_LONG_ASSET`（处置是现金流入，与「扩张强度」无关；`constructNet` 才是投资净额口径）。
- **分母**：`maintenanceCapex(income)`（= 资产减值 + 信用减值 + `FA_IR_DEPR` + `USERIGHT_ASSET_AMORTIZE` + `IA_AMORTIZE` + `LPE_AMORTIZE` + 处置损失 + `FA_SCRAP_LOSS`，与 R4 FCF 同口径）。**不要**用 `CONSTRUCT_LONG_ASSET` 与营收/总资产比，否则失去「扩张 vs 保全」的语义。
- **`coreWorkingCapital` 为什么不用 `workingCapital`**：后者包含 `residualAssets/residualLiabilities`（未分类差额），会把「报表科目变动」误读成「营运资本变动」；C5 的 ΔNWC 必须可解释，故只用核心科目集。**这是对 §19.10 #1 的收口**：不依赖残差，故无需再实测残差稳定性。
- **ΔNWC 的方向**：只对「增加」告警（占用现金）；减少视作现金释放，不告警（避免把改善当风险）。
- **多期资产负债表可得性**：AI handler 已拉 `bsPageSize=44`（约 11 个年报），baseYear−1 基本可得；缺失则静默跳过 ΔNWC 分量，**不**写「数据不足」告警（避免噪声）。
- C5 只告警，不修改 `Params`。方法论 §3.4 允许「(a) 扣扩张 Capex 或 (b) 降增速」二选一；本项目选择「保持 FCF 口径 + 告警提示」，因为自动扣扩张 Capex 会与 R4 的基期 FCF 口径冲突（用户可在前端自行调低 g）。

#### 19.8.5 C6：FCF 与净利润关系（告警）

**新增函数**：

```go
// fcfToProfitMedian 最近 ≤5 年 FCF ÷ 重构净利润 的中位数。
// 仅纳入 FCF>0 且净利润>0 的年度；有效年度 <3 → ok=false。
func fcfToProfitMedian(fcfByYear map[int]float64, incomeByYear map[int]model.ReportRow,
    years []int) (median float64, samples int, ok bool)
```

**规则**：

```
ratio, n, ok := fcfToProfitMedian(fcfByYear, incomeByYear, fcfYears)
if ok && ratio > valFCFProfitHigh:
    → "近 %d 年经营自由现金流中位数为净利润的 %.2f 倍，长期显著高于净利润，
       请关注折旧摊销、减值与营运资本变动带来的会计现金含量差异。"
```

- **只判断「显著高于」**：FCF < 净利润是正常现象（扩张期），由 C5 / 适用性判定覆盖，不在 C6 告警。
- **净利润取 `netProfitReconstructed`**（与 R4 应用口径一致），不用报表 `PARENT_NETPROFIT`。
- **`years` 用 `fcfYears`**（P2 交集），保证分子分母同年。
- 若 `n < 3` 或全部净利润 ≤0 → 跳过，无告警。亏损公司已由 `Applicable=false` 处理。

#### 19.8.6 出口整合顺序（`recommendValuation` 末尾）

```
1. baseYear 对齐（C7）→ 计算 X / 模型 / g1 / SGR / params / 基期 FCF
```

### 19.11 R15 关键决策点 / 待确认项

1. **r 的 WACC 基线化会改变既有推荐结果（P1 固有影响，已按 Q1 采纳）**。茅台等低杠杆公司 r 由 9.0 降至 8.0（股权成本 8.0 + 风险溢价 0），高杠杆周期股 r 可能升到 12~15。**已按 Q1「推荐」采纳**，无需再确认；此处仅登记「预期行为变化」并已在 19.9 列入端到端核对。
2. **β 三档改由 AI 行业分类驱动**（2026-10-16 用户决策）：AI 输出受约束枚举 `industry_type` → 后端常量表映射 β（周期 1.2 / 一般 1.0 / 公用 0.8），`volatile` 仅作兜底（不抬升有效分类档）。详见 §19.12。
3. **无资产负债表时的 r 兜底**。保留现状 `valDiscountFallback=10.0`（保守）+ Warning，**不**改为「纯股权成本 8.0」。**推荐保留 10.0**：缺表即无法评估资本结构与财务风险，取更保守值更稳妥，且与现状一致（最小惊讶）。
4. **不适用时「仍输出模型」vs「不输出模型」**。**已定稿：仍输出** `model`/`params`（保 R7 恒产出与 prompt 完整），仅在 `applicable=false` 时由前端禁用「套用到估值」。P1 已按此实现，P2~P4 不改。若未来产品要求「不适用即不显示模型」，需另行约定 `model=""` 的空值契约（会波及 prompt 与前端渲染）。
5. **金融股判定的启发式（`OPERATE_COST` 缺失）是否足够**。属**待实测**（19.10 #3）；若不可靠，采用降级方案（复用 handler 取数失败路径前移判定）。**此为唯一可能影响 P1 边界的实测项**，但即使不可靠也可回落（degrade）不阻塞 P1。
6. **`beta` 字段不设 `omitempty`**（避免 `1.0` 被省略导致前端显示抖动），`applicable` 同样不设；其余新字段设 `omitempty`。**推荐此组合**（与既有 `base_growth`/`adjust_rd`/`fcf_mode` 风格一致）。
7. **出口收口提前到 P1（相对方法论 §11 的两处调整之一）**：把一致性校验挂点与不适用判定并入 P1，P4 只追加 C4~C7。**推荐**（避免 `RecommendValuation` 出口二次重构）；如需严格按方法论分期，可把 19.5.4 的不适用判定单列到 P4，但会留下 `Warning` 拼接的临时实现。
8. **β 的 `volatile` 优先级（2026-10-16 二次拍板：采用「AI 优先、`volatile` 仅兜底」，见 §19.12.2 / §19.12.9）**。本次修订原取「AI 分类为准 + `volatile` 作 β 下限（β = max(表值, 1.2)）」，备选是「AI 分类为准，`volatile` 仅在 AI 未给出合法分类时兜底」（更严格贴合「β 只来自 industry_type」的字面）。**已拍板采用备选（后者）**：AI 分类有效时 β 直接取常量表值，`volatile` **不**抬升；仅在 AI 未分类 / 分类非法时才用 `volatile` 两档兜底。**实测依据（tester）**：`volatile` 信号纳入噪声极大的「经营活动现金流量净额同比增速」后近于普及——抽样 16 只非金融股中 **15 只 `volatile=true`**；叠加「β = max(查表值, volatile?1.2:0)」的下限后，β 恒被钉在 1.2，AI 判定的「周期 / 一般 / 公用」三档完全失效（`utility` 的 0.8 永不生效）。故改为「AI 为主、`volatile` 仅兜底」，让分类权完整回到 AI。切换成本极低（只改 `betaFor` 一处、< 10 行，`BetaBasis` 取值收敛为「AI 行业分类」/「波动兜底」/「缺省回落」三种）。
9. **prompt 中折现率与最终值可能不一致（本次修订引入的已知代价，见 §19.12.5）**。因 β 依赖 AI 返回、而 prompt 先于 AI 返回组装，预推导折现率可能在终态被重算。**推荐**：prompt 显式声明「折现率/永续增长率将按你判定的行业类型重算」，并要求 rationale **不写这两项的具体数值**（其余参数如基准增速 X / 模型 / g1 / n1 不受 β 影响，可正常引用）。备选（更严格但更贵）是**两次 LLM 调用**（先分类、后分析），本设计不采用。若用户认为「rationale 必须能引用折现率数值」，需回到备选方案，**届时请回主对话确认**。

#### 19.11.1 P2~P4 决策记录（旧规则 → 新规则）

> 用户 2026-10-17 明确授权：「全部都推进实现；一切以最新的需求（方法论文档）为准；以前的旧规则觉得不合理的可以推翻」。以下决策**不再作为待确认项**，仅登记「旧规则 → 新规则 → 理由」。

| # | 旧规则 | 新规则 | 理由 |
| --- | --- | --- | --- |
| D1 | `volatile` 样本 = 营收 + 净利润 + **经营现金流**同比增速，极差 >40 → true | 样本仅 = 营收 + 净利润同比增速；≥3 样本且极差 >40 → true | 经营现金流天然剧烈波动（茅台实测 `[81,38,-33]`），导致 15/16 非金融股误报；`volatile` 应衡量**盈利**波动，FCF 周期由 P3 单独识别 |
| D2 | `volatile=true` → `g1 = floor(X/2)`（一刀砍半） | `g1raw = X × (1 − clamp(D/100, 0, 0.40))`，再受 `floor(SGR)` 限制 | 二值规则对 `D=41` 与 `D=200` 同等惩罚、且对稳定高增长公司过度保守；连续折减单调、可单测，最大折减 40% |
| D3 | `X` = 三类样本合并后取一次中位数（含经营现金流） | 三项（营收/重构净利润/FCF）各自稳健增速后**显式等权**，缺项按可用项数归一化、**不补 0** | X 必须与贴现对象 FCF 同口径；合并取中位数会让样本多的指标主导，且经营现金流污染严重 |
| D4 | `classifyModel` 单阈值：`X≥20` 三阶段 / `X≥8` 两阶段 / `X≥0` 永续 / `<0` 零增长 | 三信号评分（增速 0.6 + 稳定性 0.2 + ROE 0.2，缺项归一化），门槛 70/45/25，硬闸门 `X≥12`/`X≥6`/`X<3→zero` | 消除 `19.9% vs 20.1%` 断崖；单靠增速会把「高增长但 ROE 低/波动大」的公司推到三阶段；Q4 明确要求 `X<3` 归零增长 |
| D5 | 三阶段 `g2 = min(4, gk+1)`、`g3 = gk` | `g2 = gk+1`、`g3 = gk`，强制 `g1>g2>g3`；无解按 `three→two→perpetual→zero` 降级 | 旧规则在 `gk=4` 时 `g2=g3=4`，递减路径失效（P8 类矛盾）；`g2` 是第二阶段增速非终值，不受 `valLongTermGDP=4` 约束 |
| D6 | 无 SGR 上限（`g1 = min(X, 30)`） | `g1 ≤ floor(SGR)`；`SGR = ROE × 留存率`，留存率 = `(权益期末−权益期初)÷净利润` clamp[0,1]；不可用 → 不设上限 + Warning | 方法论 C4 / G4：企业无法支撑的增速不可用；`g1` 为整数，用 `floor` 才能严格满足 C4 |
| D7 | `RecommendBaseFCF(fcfByYear, years, x, volatile)` 读 R7 全局信号 | `RecommendBaseFCF(fcfByYear, years, cycle)`，R4/R6/R9 只用 **FCF 自身**增速/极差/中枢 | 解耦「X 口径变化 → R13 静默漂移」；基期 FCF 选择应只取决于 FCF 序列与周期状态 |
| D8 | R5 custom 的 `gS = clamp(FCF 增速中位数, 0, X)`（用全局 X） | `gS = clamp(FCF 增速中位数, 0, 15%)` | 全局 X 含营收/净利润，可能把 FCF 外推到与其自身趋势无关的水平；15% 是保守上限 |
| D9 | `fcf_years` 固定 3（`valFCFRecMaxYears=5`，R1 至少 3） | 动态：平稳 3 / 中等 5 / 强周期 7；上限 7 | 方法论 §3.3：A 股 3 年小周期偏短，周期股需覆盖一轮周期；平稳公司长窗口会稀释近况 |
| D10 | 无周期识别，`volatile` 兼任 FCF 波动判据 | `detectFCFCycle`：CV>0.5 或符号翻转≥2 → 强周期；强周期强制 `trim_mean` + 7 年 | 现金流形态与盈利增速是两件事；混用会重复保守或漏判 |
| D11 | 研发建议 = 费用率 >5% 单条件 | 费用率 >5% **且** 研发投入同比扩张 >0；上年缺失 → false | 方法论 G11：避免成熟公司因会计口径波动被误加回；缺上年不猜 |
| D12 | C4~C7 无校验（P8 矛盾可漏出） | C4 强制 cap + 防御复核；C5/C6/C7 只告警、不二次降级 | 方法论 G10 要求「违反则降级并 Warning」；但 C5/C6 自动扣减会与 R4 口径冲突、双重保守，故只提示（方法论 §3.4 允许 (a)/(b) 二选一，本项目选 (b) 由用户在前端调 g） |
| D13 | 基期 FCF 用 `cfYears`、`r` 用三表最新年（可能不同年） | 统一 `baseYear = 利润表 ∩ 现金流量表` 最新共同年；FCF/g/r/R&D 全部按该年 | 方法论 C7：三者口径同源；混年会让债务成本、税率、FCF 错配 |
| D14 | β 兜底只看 `volatile` | 兜底看 `volatile || FCF 强周期`；AI 分类仍优先 | 周期股的现金流风险不应只由盈利增速捕捉；只影响 AI 未分类的兜底路径 |
| D15 | 不适用时仍输出模型（保留） | **保留**（P1 决策不变） | 保 R7 恒产出与 prompt 完整；前端 `applicable=false` 禁用套用 |
| D16 | AI 定性修正层（Q7）不开放 | **不开放**（P4 确认） | 维持「大模型不产出任何数值」；如需开放须单独立项 |

**P2~P4 不再向用户提问的事项**（均可由方法论 + 授权推导）：

- `volatile` 是否保留经营现金流 → 不保留（D1，有实测根因）。
- `g1` 折减方式 → 连续折减（D2）。
- 三阶段 `g2` 上限 → 允许 5（D5，R4 仅校验 `g3<r`）。
- C5/C6 是否自动降参 → 不自动（D12）。
- SGR 不可得是否编造留存率 → 不编造（D6）。
- 评分权重/门槛 → 先用 D4 常量，实测后调常量，不改结构（§19.10 #8）。

### 19.12 β 三档：AI 行业分类（定性）→ 确定性映射（数值）【2026-10-16 用户决策修订】

> 本节是本次修订的**规范来源**：19.0 / 19.1 / 19.2 / 19.3 / 19.4 / 19.5.1~19.5.3 / 19.5.5 / 19.9 / 19.10 的相关段落若与本节冲突，**以本节为准**。

#### 19.12.1 决策与对 R7 的定位

| 项 | 初稿（已废弃） | 本次修订（生效） |
| --- | --- | --- |
| β 档位来源 | `volatile` 单一信号「周期 1.2 / 一般 1.0」 | **AI 输出的行业类型枚举（定性）→ 后端常量表（数值）**，三档全部可达 |
| 公用事业 0.8 | 表内保留但不可达（延后） | **可达**（AI 判 `utility` 触发） |
| `volatile` 作用 | 唯一的 β 判定信号 | **仅在「AI 未给出合法分类」时兜底**（见 19.12.2 / §19.11 #8），不抬升有效分类档 |
| AI 的角色 | 只写 `rationale`（纯文字） | 写 `rationale`（纯文字）+ **输出一个受约束的定性枚举** `industry_type` |

**对 R7 的精确化（非推翻）**：R7 纪律「大模型不产出任何数值」，本次修订精确化为「**大模型不产出数值，只产出受约束的定性分类；该分类经后端常量表确定性映射为数值**」。两条边界必须写死在实现里，否则精确化退化为推翻：

1. **AI 的产出物只能是枚举三选一**，不是数字 —— prompt 里明确列出 3 个 ASCII key，并声明「不得输出其它取值」；后端 `normalizeIndustryType` 对任何非法输入**不报错、不采信**，直接走兜底（19.12.2）。**AI 永远无法把任意 β 注入参数**（这正是 R7 要防的）。
2. **枚举 → β → r → gk → Params 全程是纯函数 + 常量表**，无 IO、无随机、无时间依赖（service 层不变）。

因此 R7 的幂等性由「无条件成立」变为「**给定相同 `industry_type` 时成立**」。该弱化是**有界且离散**的：分类只有 3 种取值，参数差异至多落在 2 个档位（β 差 0.2/0.4，Re 差 1.1/2.2pp，经 WACC 权重与 [8,15] 收口后折现率差异通常 ≤ 1.1pp），不存在初稿担心的「AI 自由填数导致无界漂移」。`industry_type` 与 `rationale` 同属「大模型产出的定性内容」，前者只是被**结构化了**。

#### 19.12.2 受约束枚举、常量表与解析规则

**枚举与常量表**（`service/valuation_recommend.go`，§19.5.1 已给代码）：

| key | 中文名（`*Name`） | β（`valIndustryBetas`） | 典型行业（写进 prompt 供大模型对照） |
| --- | --- | --- | --- |
| `cyclical` | 周期性行业 | **1.2**（`valBetaCyclical`） | 钢铁、煤炭、化工、有色、航运、建材、养殖、券商 |
| `general` | 一般行业 | **1.0**（`valBetaNormal`，**回落档**） | 消费、制造、医药、科技，及无法明确归入另两类的多数行业 |
| `utility` | 公用事业 | **0.8**（`valBetaUtility`） | 电力、燃气、水务、高速公路、港口 |

**归一化 `normalizeIndustryType(raw string) string`**（纯字符串匹配，无 IO）：

```
n := strings.ToLower(strings.TrimSpace(raw))     // 容忍大小写/空白
switch {
  case n == ""                                     → return ""            // 缺失 → 交给 betaFor 兜底
  case n ∈ valIndustryKeys                         → return n             // 精确命中（AI 照 prompt 输出时的正常路径）
  case contains(n, "cycl") || contains(n, "周期")  → return "cyclical"    // 中英文变体 / 带「型」「行业」后缀
  case contains(n, "utilit") || contains(n, "公用") → return "utility"
  case contains(n, "general") || contains(n, "normal") || contains(n, "一般") → return "general"
  default                                          → return ""            // 无法识别：不猜、不报错，走兜底
}
```

- 匹配顺序**必须**按上表（`cyclical` → `utility` → `general`）：`general` 的关键词最泛（`一般`），放最后避免吞掉其它档位。`normal` 仅作兼容别名（初稿曾用 `normal` 作 key）。
- **不做语义推断**（不用 `SegmentIncome.Name` 关键词组合去反推行业）—— 那正是初稿顾虑的「脆弱映射」，本次把它交给大模型，后端只做**字符串归一**。

**β 解析 `betaFor(industryType string, volatile bool) (beta float64, tierKey, tierName, basis string)`**（**β 的唯一入口**，其余代码不得自行映射）：

```
key := normalizeIndustryType(industryType)

// ① AI 分类有效 → 常量表取值（主信号，volatile 不抬升）
if key != "" {
    return valIndustryBetas[key], key, valIndustryTypeNames[key], "AI 行业分类"   // 1.2 / 1.0 / 0.8
}

// ② AI 分类缺失/非法 → volatile 两档兜底（与初稿方案逐位一致）
if volatile { return valBetaCyclical, valIndustryCyclical, valIndustryTypeNames[valIndustryCyclical], "波动兜底" }
return valBetaNormal, valIndustryGeneral, valIndustryTypeNames[valIndustryGeneral], "缺省回落"
```

**优先级关系（2026-10-16 拍板，见 19.11 #8）**：**AI 分类是唯一主信号，`volatile` 只在 AI 未给出合法分类时兜底，绝不抬升已生效的分类档。**

> **P3 扩展（2026-10-17，见 §19.7.7）**：`betaFor` 第 2 参由 `volatile bool` 更名为 `fallbackCyclical bool`，调用方传 `volatile || fcfCycle.Cyclical`；下表第 4~6 行的 `volatile` 列语义同步替换为 `fallbackCyclical`（`basis` 文案改为「波动/周期兜底」）。**主信号优先级与三档取值完全不变**，本节仍是 β 映射的规范来源。

| 情形 | AI 分类 | volatile | β（生效） | `industry_type_name`（展示） | `beta_tier`（展示） | basis |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | cyclical | 任意 | 1.2 | 周期性行业 | 周期性行业 | AI 行业分类 |
| 2 | general | 任意 | 1.0 | 一般行业 | 一般行业 | AI 行业分类 |
| 3 | utility | 任意 | 0.8 | 公用事业 | 公用事业 | AI 行业分类 |
| 4 | 非法/缺失 | false | 1.0 | 一般行业 | 一般行业 | 缺省回落 |
| 5 | 非法/缺失 | true | 1.2 | 周期性行业 | 周期性行业 | 波动兜底 |
| 6 | 任意 | （预推导期 `industryType==""`） | 1.2 / 1.0 | 周期性/一般行业 | 同左 | 波动兜底/缺省回落 |

- **AI 分类有效时两个展示标签恒同档**（`industry_type_name` = `beta_tier` = 分类档中文名）；仅 AI 未分类的兜底路径才会出现「周期性行业」（`volatile=true`）。
- **为什么取「兜底」而不取「下限（max）」**：实测（tester，16 只非金融股 **15 只** `volatile=true`）表明 `volatile` 因纳入噪声大的「经营活动现金流增速」而近于普及；取「下限」会把 β 恒钉在 1.2、令 AI 的「周期 / 一般 / 公用」三档完全失效（详见 19.11 #8）。改为「AI 为主、`volatile` 仅兜底」后分类权完整回到 AI。
- `betaFor` 的 `beta` 输出**必须** ∈ {0.8, 1.0, 1.2}（19.9 单测断言），它是唯一进入 `equityCostCAPM` 的 β。

#### 19.12.4 链路：预推导 → prompt → AI 返回 → 终态重算 → 覆盖

`api/ai.go` 的 `GetAIAnalysis` 改为（**唯一需要改的调用点**，其余 handler 不动）：

```go
// ① 预推导（industryType=""）：β 走 volatile 兜底；用于组装 prompt
rec := service.RecommendValuation(balance, cashflow, income)

segments, _ := h.c.FetchSegmentIncome(code)
system, user := service.BuildAIPrompt(analysis, *quote, reasoningEffort, segments, rec)

raw, usage, err := llm.Chat(system, user)
// ... err 处理 ...
result, err := service.ParseAIResult(raw)      // result.Valuation.IndustryType = AI 的原始分类
// ... err 处理 ...

// ② ★终态重算：用 AI 的 industry_type 重解析 β 并重算 r / gk / Params
industryRaw := result.Valuation.IndustryType                  // ★必须在 Apply 之前取出（Apply 会覆盖该字段）
rec = service.RecommendValuationWithIndustry(balance, cashflow, income, industryRaw)

// ③ 覆盖（含把 IndustryType 归一化回填）
service.ApplyValuationRecommendation(&result, rec)

log.Printf("AI 估值参数确定性推荐: code=%s 行业类型=%s β=%.1f(%s) 基准增速=%.2f%% 波动=%v 模型=%s 折现率=%.1f%% 风险点=%d 研发调整=%v 研发费用率=%.2f%%",
    code, rec.IndustryType, rec.Beta, rec.BetaBasis, rec.BaseGrowth, rec.Volatile, rec.Model, rec.DiscountRate, rec.RiskPoints, rec.AdjustRD, rec.RDRatio)
```

受 β 影响、被第二次调用**重算**的字段（其余字段两次调用逐位相同）：

| 字段 | 依赖链 |
| --- | --- |
| `Beta` / `BetaTier` / `IndustryType` / `IndustryTypeName` / `BetaBasis` | `industryType` → `betaFor` |
| `RiskFreeRate` / `EquityRiskPremium` | 常量（不变，重算后同值，仅为口径完整） |
| `WaccBaseline` | β → Re → `waccWithEquityCost` |
| `DiscountRate` | `WaccBaseline` + `RiskPremium` → clamp/grid |
| `Params` | `gk = min(longTermGDP, perpetualGrowthRaw(r))` → `recommendParams(mdl, x, volatile, gk)`（三阶段 `g2 = min(4, gk+1)` 同受影响） |
| `RiskPremium` / `Model` / `BaseGrowth` / `Volatile` / `RiskPoints` / `Warning` / `AdjustRD` / `RDRatio` / `FCF*` | 与 β 无关，两次逐位相同（**幂等回归断言点**） |

**顺序约束（易错的实现细节）**：`result.Valuation.IndustryType` 必须在 `ApplyValuationRecommendation` **之前**读取 —— 后者会把该字段覆盖为归一化值，之后再读就拿不回 AI 原始串了。建议在 `api` 里显式赋给一个局部变量（如上 `industryRaw`）后再调 `Apply`，从代码结构上消除这个顺序依赖。

**失败路径不新增分支**：AI 未返回 `industry_type`（缺字段 / `null` / 空串）→ `result.Valuation.IndustryType == ""` → `normalizeIndustryType("") == ""` → `betaFor` 走 volatile 兜底（情形 4/5）。**全程不返错、不重试**，与 R7「估值字段缺失不影响主流程」一致。

#### 19.12.5 可复现性论证与 prompt 一致性策略

**(1) 可复现性**：给定同一份财报 + 同一 `industry_type`，全部输出字段逐位可复现（纯函数 + 常量表）。`industry_type` 本身由大模型产出，其稳定性依赖：`Temperature=0.0`（`deepseek.go:92`）、枚举空间只有 3 个、prompt 明确列出 3 个 key 并要求「不确定取 general」。**残余风险**：LLM 并非数学确定性系统，同一输入可能给出不同分类（概率低）。**影响被两条设计限制住**：①枚举有界 ⇒ 参数差异有界（≤ 2 个离散档位）；②任何缺失/非法 ⇒ 走 deterministic 兜底。**因此「同股多次分析差值=0」的回归测试口径需相应放宽为「同股多次分析，参数差异仅可能来自 `industry_type` 分类差异，且 `industry_type` 相同则逐位相同」**（§19.9 给出对应断言写法）。

**(2) prompt 与终态的一致性（已知代价）**：β 依赖 AI 返回，而 prompt 先于 AI 返回组装 ⇒ prompt 只能给出**预推导**折现率（β 走 `volatile` 兜底，即 1.0 或 1.2）。若 AI 判定的分类使 β 变化（情形 1/3：AI 判 `cyclical` → 1.2、`utility` → 0.8，而预推导兜底档可能为 1.0），终态折现率会与 prompt 中给出的不同，导致 `rationale` 若引用了预推导折现率就会「说不一致」。

**处理（推荐）**：

- prompt 的折现率/折现率构成行**显式声明其为预推导值**，并说明「系统将按你判定的 `industry_type` 重算折现率与永续增长率」；
- 在 rationale 约束中**明确豁免**折现率与永续增长率这两项：要求「不要写出折现率/永续增长率的具体数值，改为解释其口径与依据（WACC 基线 + 公司风险溢价 + 行业 β 档位）」；
- 其余参数（基准增速 X、模型名、`g1`、`n1`、`n2`、基期 FCF 选取）**不依赖 β**，可照旧要求「出现的数字必须与给定参数完全一致」。

**备选（不采用，19.11 #9 已登记）**：两次 LLM 调用（第一次仅返回 `industry_type` 的极小 prompt，第二次带终态参数做完整分析）—— 可让 prompt 与终态严格一致，代价是**多一次网络往返**（当前单次超时 180s，`deepseek.go:38`）、多一倍失败面与 token 成本。个人投资场景下不划算。

#### 19.12.9 本节关键决策点 / 待确认项

1. **`volatile` 与 AI 分类的优先级**：**已按「AI 主，`volatile` 仅兜底」定稿**（2026-10-16 二次拍板，19.11 #8）。原取「AI 主 + `volatile` 下限（max）」；实测（tester，16 只非金融股 15 只 `volatile=true`）表明下限会把 β 恒钉在 1.2、令三档失效，故改用兜底语义——AI 分类有效即取表值、`volatile` 仅在其缺失/非法时兜底，切换只改 `betaFor` 一处。
2. **prompt 折现率与终态可能不一致**：取「prompt 声明预推导 + rationale 豁免折现率/永续增长率数值」（19.11 #9）。备选「两次 LLM 调用」。**已按前者定稿**；若用户要求 rationale 必须引用折现率数值，请回主对话确认切换。
3. **AI 分类准确度未实测**（19.10 #5）：需抽样核对（茅台/宝洁对标的美的一般型、宝钢/中远海控周期型、长江电力/宁沪高速公用事业型）。**不阻塞 P1**（有确定性回落），但影响「三档是否真能生效」的成色；若实测发现分类偏差大，优先收紧 prompt（给更多行业内举例），而不是回到关键词硬映射。
4. **`IndustryType` 双向语义**（19.12.3）：同一 JSON 字段先承载 AI 原始值、后被确定性覆盖。**已定稿**并在 `api` 侧用局部变量固化「先读后写」的顺序；若评审认为「入参不应复用出参字段」，可改为在 `ParseAIResult` 里把原始值搬到 `ValuationRecommendation` 之外的临时变量（**改动量约 5 行**，语义等价）。

#### 19.13.5 需回主对话找用户拍板的问题

**结论：无阻塞性待拍板项。** 以下 4 项已按方法论与授权自行决定，仅作为「可选确认」列出；若用户不反对，按推荐执行：

1. **模型评分权重与门槛（0.6/0.2/0.2、70/45/25）**
   - **推荐**：先按本设计常量上线，用 §19.9 的 6 个算例与 10~20 只样本回测后只调常量。
   - **备选**：更保守（门槛 75/50/30）或更看 ROE（0.5/0.2/0.3）。影响：仅档位边界，不改结构。
2. **推荐输出的终值网格放宽为 `0–4` 整数**
   - **推荐**：接受。降级到永续时可能输出 `g=0/1`（方法论 §7 允许终值 0），前端 `el-input-number` 无网格限制。
   - **备选**：仍限制 `{2,3,4}`，则降级永续时必须把 `g` 抬到 2，会造成「低增长公司被给 2% 永续」的高估；**不推荐**。
3. **C5/C6 只告警、不自动降参**
   - **推荐**：只告警。自动扣扩张 Capex 会与 R4 的基期 FCF 口径冲突，且与 C4 的自动降 `g1` 叠加会双重保守。
   - **备选**：C5 触发时自动把三阶段降为两阶段。影响：更保守但会掩盖「高 Capex 高成长」公司的真实价值；**不推荐**。
4. **三阶段 `g2` 允许 5（方法论 G7 的字面 `clamp(gk+1, g1, 4)` 在 `gk=4` 时仍退化为 `g2=g3=4`）**
   - **推荐**：`g2 = gk+1 = 5`。G7 的字面公式上界 4 会让 P8 的边界 bug 原样保留；C3 只约束**终值** `g3≤4`，第二阶段增速不是终值。R4 的 `dcfValue` 仅校验 `g3<r`，`5<r(≥8)` 合法；前端 `valG2` 允许到 50。
   - **备选**：严格按字面上界 4，则 `gk=4` 时三阶段必须全部降级为两阶段（`g1>4` 时仍可两阶段）。影响：所有 `gk=4` 的公司失去三阶段路径，**不推荐**。

### 19.14 P5：成长型公司 FCF 噪声误判修复（成长性否决 + FCF 分项可靠性 + 下行稳定性）

> **生效日期**：2026-10-17。本节是 **P3/P4 之后的增量规范**；与 §19.6.3（X 等权）、§19.6.4（稳定性信号）、§19.7.2（周期识别）、§19.7.3（动态 `fcf_years`）冲突处，**以本节为准**。
>
> **触发样本**：睿创微纳 `688002`（红外成像芯片，营收连续高增）。现状推荐为「永续增长 + 强周期 7 年 FCF 窗口」，明显不合理。根因是 **FCF 噪声（成长/扩张期 lumpy）同时污染了三处**：基准增速 X 的 FCF 分项、模型分档的稳定性信号、FCF 周期判定。
>
> **纪律不变**：全新增规则均为 **纯函数、常量驱动、无 IO/随机/时间依赖**；AI 仍只输出 `industry_type` 定性枚举与 `rationale` 文字，**不产出任何数值**（R7）。不新增数据源、不新增第三方依赖、不改变任何 API 路由。

#### 19.14.1 问题、数据与目标

**实测根因链（睿创微纳 688002，2025 年报口径）**：

| 环节 | 现状值 | 问题 |
| --- | --- | --- |
| 营收稳健增速 | `+40.29%` | 正常，反映真实成长 |
| 重构净利润稳健增速 | 需求记录 `+17.51%`；本设计复核 2025 年报为 `+25.89%` | 正常（口径/数据版本差异，不影响结论） |
| FCF 稳健增速 | `-45.76%`（本设计复核 `-45.90%`） | FCF 序列 lumpy：2024 `-1.77` 亿 → 2025 `+10.94` 亿；CV `1.61`、符号翻转 `2` 次 |
| 基准增速 X | 三项等权 `≈4.01%~6.76%` | 被 FCF 负向中位数严重拖低；剔除 FCF 后应为 `≈28.90%~33.09%` |
| 稳定性分 | `0.00` | 净利润 YoY 极差 `≈161.7pp`（-37.47% 与 +124.21%），旧规则把「翻倍式增长」也当波动惩罚 |

**三条修复目标（用户已批准方向）**：

1. **周期判定加成长性否决**：营收持续高增长的公司，即使 FCF CV 高，也不判「强周期」；但必须与真周期股（如中远海控 `601919`）区分。
2. **FCF 增速分项可靠性**：FCF 序列不稳定（高 CV / 符号翻转 / 有效同比点不足 / 增速极差过大）时，不把 FCF 增速计入 X，避免负向噪声污染；X 改由其余可用项等权。
3. **稳定性信号下行口径**：稳定性分只惩罚「下行波动」（同比为负的部分），正向大波动（翻倍式增长）不扣分。

#### 19.14.2 总体链路与执行顺序（关键：周期判定前移）

现状（`valuation_recommend.go:214-238`）先算 X、再算周期；但**修复点 2 的 FCF 可靠性依赖原始周期判据 `RawCyclical`**，因此必须把周期判定前移到 X 之前。新顺序：

```text
incomeWindow/fcfYears/fcfGrowthYears/fcfByYear
        │
        ├─► assessGrowthPattern(incomeByYear, incomeWindow) ──► gp (Veto)
        │
        ├─► detectFCFCycle(fcfByYear, fcfYears, gp) ──► RawCyclical / GrowthVeto / Cyclical(生效)
        │
        ├─► assessFCFGrowth(fcfByYear, fcfGrowthYears, otherAvailable, cycle)
        │        └─► xFCF / Included / ExcludeReason
        │
        ├─► X = weightedGrowth(xRev, okRev, xNP, okNP, xFCF, fcfTerm.Included)
        │
        ├─► revYoY/npYoY → raw spread(volatile/damping) + downside spread(st)
        │
        ├─► fallbackCyclical = (volatile && !gp.Veto) || cycle.Cyclical
        │        └─► recommendDiscountRate / β
        │
        ├─► classifyModelScore(X, downsideDispersion, ...)
        │
        └─► RecommendBaseFCF(fcfByYear, fcfYears, cycle)   // 生效 Cyclical 才走 trim_mean
```

- `gp` 只依赖利润表（营收、营业成本），不依赖 X，**无循环依赖**。
- `cycle.RawCyclical` 是原始判据（CV/符号翻转），`cycle.Cyclical = RawCyclical && !GrowthVeto` 是生效判据；下游（`trim_mean`、`fcf_years`、`β` 兜底）一律看生效判据，展示层同时保留原始判据。
- `volatile` 仍按**全幅极差**计算（语义不变，供展示与 g1 折减）；稳定性分改用**下行离散度**。

#### 19.14.4 修复点 1：成长性否决（成长型 vs 周期型）

**判定函数**：

```go
// assessGrowthPattern 用最近 valGrowthWindowYears(5) 年利润表判定是否为「持续成长型」。
// 纯函数：只读营收(TOTAL_OPERATE_INCOME)与营业成本(OPERATE_COST)，无 IO/随机/时间。
func assessGrowthPattern(incomeByYear map[int]model.ReportRow, years []int) growthPattern
```

**伪代码**：

```text
gp := growthPattern{}
obs := [revenue(incomeByYear[y]) for y in years]          // years 已升序
if len(obs) < valGrowthVetoMinYears(3) → return gp
first, last := obs[0], obs[len-1]
span := years[len-1] - years[0]
if first <= 0 || last <= 0 || span <= 0 → return gp

yoy := []
for i = 1..len(obs)-1:
    if obs[i-1] > 0 → yoy.append((obs[i]-obs[i-1])/obs[i-1] × 100)
if len(yoy) < 2 → return gp

gp.Evaluated   = true
gp.RevenueCAGR = (pow(last/first, 1/span) - 1) × 100
gp.MinYoY      = min(yoy)
gp.StrongYears = count(yoy[i] >= valGrowthVetoStrongYoY(10))
gp.YoYCount    = len(yoy)

// 毛利率极差：仅统计 revenue>0 且 operateCost>0 的年度
gms := []
for y in years:
    rev, cost := revenue(incomeByYear[y]), operateCost(incomeByYear[y])
    if rev > 0 && cost > 0 → gms.append((rev-cost)/rev × 100)
if len(gms) >= 2:
    gp.GrossMarginOK    = true
    gp.GrossMarginRange = max(gms) - min(gms)

gp.Veto = gp.RevenueCAGR >= valGrowthVetoMinCAGR(15)
       && gp.MinYoY      >= valGrowthVetoMaxDecline(-10)
       && gp.StrongYears >= valGrowthVetoStrongYears(2)
       && (!gp.GrossMarginOK || gp.GrossMarginRange <= valGrowthVetoMaxGMRange(20))

gp.Basis = fmt.Sprintf("营收 CAGR %.2f%%、最小同比 %.2f%%、强增长年 %d/%d、毛利率极差 %s",
    gp.RevenueCAGR, gp.MinYoY, gp.StrongYears, gp.YoYCount, gmRangeText)
return gp
```

**区分成长型与周期型的判据（本次采用三层）**：

| 层 | 判据 | 成长型（睿创 688002） | 周期型（中远海控 601919） |
| --- | --- | --- | --- |
| ① 营收趋势 | 窗口 CAGR ≥ 15% | `37.2%` ✅ | `-9.9%` ❌ |
| ② 下行容忍 | 最小年同比 ≥ -10% | `+21.3%` ✅ | `-55.1%` ❌ |
| ③ 毛利率稳定性 | 极差 ≤ 20pp | `11.8pp` ✅ | `27.9pp` ❌ |
| ④ 强增长年数 | ≥ 2 年同比 ≥ 10% | `4/4` ✅ | `1/4` ❌ |
| **结论** | ①~④ 全满足 → `Veto=true` | **否决**（非强周期） | **不否决**（仍强周期） |

- **为什么用「营收趋势 + 毛利率」而不是「FCF 与营收背离」**：真周期股在景气高点也会出现营收高增 + FCF 大幅波动，单看背离无法区分；营收是否出现**显著下行年**（-10% 以下）与**毛利率是否随商品价格大幅摆动**，才是成长扩张与行业周期的稳定分界。
- **毛利率缺失的处理**：`GrossMarginOK=false` 时该条件不阻塞（只靠营收三层判据）；金融股本身已由 `isFinancialLike` 判不适用，不受影响。
- **阈值取值依据（实测）**：睿创营收 `17.80→63.04` 亿（2021→2025），YoY `+48.65/+34.51/+21.27/+46.06`，CAGR `37.2%`，毛利率 `46.6%~58.3%`（极差 `11.8pp`）；中远海控营收 `3336.94→2195.04` 亿，YoY `+17.19/-55.13/+33.29/-6.14`，CAGR `-9.9%`，毛利率 `16.4%~44.3%`（极差 `27.9pp`）。两组样本在 5 年窗口内均能稳定区分。

**否决后的联动（精确规则）**：

```text
// detectFCFCycle 末尾
c.RawCyclical = c.Evaluated && (c.CV > valCycleCVThreshold || c.SignChanges >= valCycleSignChanges)
c.GrowthVeto  = c.RawCyclical && gp.Veto
c.Cyclical    = c.RawCyclical && !c.GrowthVeto
```

| 下游 | 否决命中时 | 未命中时 |
| --- | --- | --- |
| `fcf_years` | `valFCFYearsGrowth=5`（不再取 7） | 按 CV 取 3/5/7 |
| `RecommendBaseFCF` R3 | **不进入** `trim_mean`（生效 `Cyclical=false`） | 强周期仍走 `trim_mean` |
| `fallbackCyclical` | `(volatile && !gp.Veto) || cycle.Cyclical` → 成长股的「净利润翻倍」不再抬高 β；AI 分类仍优先 | 原 `volatile || cycle.Cyclical` |
| `FCFCyclical`（JSON） | `false`（生效） | 原值 |

**`fcfWindowYears` 的分支顺序（必须照此实现）**：

```go
}
```

- 旧实现的 `case c.Cyclical || c.CV > valCycleCVThreshold` 必须拆掉 `|| c.CV > ...`：成长性否决后 `Cyclical=false` 但 `CV` 仍可能 >0.5，若保留旧分支会再次返回 7，修复失效。

- **β 兜底的精确含义**：`gp.Veto` 只抑制 `volatile` 这个**盈利增速兜底信号**，不改变 AI `industry_type` 的优先级。预推导阶段（`industryType=""`）睿创的 β 由 1.2 回落 1.0；终态 AI 判 `general` 时仍为 1.0。若 AI 判 `cyclical`，即使 `gp.Veto=true`，β 仍取 1.2（AI 分类优先，§19.12）。
- **为什么不直接把 `volatile` 改成下行口径**：`volatile` 仍用于展示与 g1 全幅折减；把「是否抬高 β」交给 `gp.Veto` 更精确，且不影响其他公司。

#### 19.14.5 修复点 2：FCF 增速分项的可靠性

**「不稳定」的判定（按序命中，唯一原因）**：

```go
// assessFCFGrowth 计算 FCF 增速并判定是否计入 X。
// otherAvailable = okRev || okNP（至少有一个非 FCF 分项可用）。
func assessFCFGrowth(fcfByYear map[int]float64, years []int, otherAvailable bool, cycle fcfCycle) fcfGrowthTerm
```

```text
v, basis, ok := fcfSeriesGrowth(fcfByYear, years)       // 复用既有 indicatorGrowth
t := fcfGrowthTerm{Value: v, Basis: basis, Available: ok, Included: ok}
if !ok → return t

yoys := fcfGrowthPoints(fcfByYear, years)               // 复用既有：仅计上一年 FCF > 0

switch {
case !otherAvailable:
    // 唯一可用分项：即使不稳定也保留，避免 k=0 被误判为「样本不足」
    return t
case cycle.RawCyclical:
    t.Included = false
    t.Reason = fmt.Sprintf("序列不稳定：变异系数 %.2f、正负交替 %d 次", cycle.CV, cycle.SignChanges)
case len(yoys) < valFCFGrowthMinPoints(2):
    t.Included = false
    t.Reason = fmt.Sprintf("有效同比点仅 %d 个（窗口内存在非正 FCF）", len(yoys))
case spread(yoys) > valFCFGrowthSpread(40):
    t.Included = false
    t.Reason = fmt.Sprintf("同比增速极差 %.2f pp（> %.0f pp）", spread(yoys), valFCFGrowthSpread)
}
return t
```

- **为什么用 `RawCyclical` 而不是生效 `Cyclical`**：成长性否决只说明「不是周期」，并不说明 FCF 序列稳定；被否决的成长股 FCF 仍然是 lumpy 的，必须同样从 X 中剔除。真周期股（`RawCyclical=true`）的 FCF 增速中位数同样没有生命周期的可比意义，也一并剔除；它们的基期 FCF 仍由 `trim_mean` + 7 年窗口处理。
- **为什么剔除而不是降权**：需求基线是 `X=(40.29%+17.51%)/2=28.90%`，即两项等权；降权系数（如 0.5）会得到 `≈14%`，仍被 FCF 拖累。剔除后 note 会如实写明「FCF 未计入」，可解释、可单测。
- **对称剔除而非只剔除负值**：只剔除负值等于「保留有利噪声、丢弃不利噪声」，会产生选择偏差；对称剔除在统计上更干净，且真周期股的周期风险仍由生效 `Cyclical`、`fcf_years=7`、`trim_mean` 与 β 兜底承担。
- **边界**：`FCF` 不可用 → `Available=false`、`Included=false`，计入 `missing`；FCF 可用但未计入 → 只计入 `excluded`，**不再**写成「FCF 样本不足」，避免编造。

**X 聚合**：

```go
fcfTerm := assessFCFGrowth(...)
x, k := weightedGrowth(xRev, okRev, xNP, okNP, fcfTerm.Value, fcfTerm.Included)
insufficient := k == 0
```

- `weightedGrowth` 签名不变；调用处第 6 参由 `okFCF` 改为 `fcfTerm.Included`。
- `GrowthFCFOK` 仍表示**数据是否可算**（睿创为 `true`）；`GrowthFCFIncluded=false` 表示**未计入 X**。两者不能混用。

**口径说明文案（`buildBaseGrowthNote`）**：

```text
近 4 个同比年度（2022、2023、2024、2025）基准增速按 2 项等权：营收 40.29%、净利润 25.89%；
FCF -45.90% 未计入（序列不稳定：变异系数 1.61、正负交替 2 次）。（营收：同比去极值中位数；净利润：同比去极值中位数）。
```

- 实现上建议给 `buildBaseGrowthNote` 追加**可变参数** `excluded ...string`，既有调用/测试不必改签名：
  ```go
  func buildBaseGrowthNote(years []int, k int, parts, bases, missing []string, excluded ...string) string
  ```
- `parts` 只包含**计入**的分项；未计入的 FCF 通过 `excluded` 单独拼接，`missing` 只放真正不可用的分项。禁止把「未计入」写进 `missing`。
- `k` 必须等于 `parts` 的项数（两项等权时 `k=2`），note 中不得出现「三项等权」。

#### 19.14.6 修复点 3：稳定性信号改为下行口径

**下行离散度**：

```text
// 单指标下行离散度 = max(0, -min(同比样本))；样本数 < 2 或不可用 → ok=false
func downsideIf(values []float64, min int) (float64, bool) {
    if len(values) < min → (0, false)
    lo := min(values)
    if lo >= 0 → (0, true)
    return -lo, true
}
```

**计算**：

```text
revYoY := rowYoY(incomeByYear, incomeWindow, revenue)
npYoY  := rowYoY(incomeByYear, incomeWindow, netProfitReconstructed)

revSpread, revOK := spreadIf(revYoY, valVolatileMinSamples)
npSpread,  npOK  := spreadIf(npYoY,  valVolatileMinSamples)
dispersion := max(可用 revSpread / npSpread)        // 全幅极差：volatile + g1 折减仍用它

revDown, revDownOK := downsideIf(revYoY, valVolatileMinSamples)
npDown,  npDownOK  := downsideIf(npYoY,  valVolatileMinSamples)
downsideDispersion := max(可用 revDown / npDown)    // 下行极差：稳定性分用它
stabilityAvailable := revOK || npOK                 // 可用性口径不变
volatile := (revOK && revSpread > valVolatileSpread) || (npOK && npSpread > valVolatileSpread)
```

**新的稳定性分**：

```text
Sst = stabilityAvailable ? clamp(100 - valStabilityPenalty(2.0) × downsideDispersion, 0, 100) : 0
```

- **只罚下行，不罚正向大波动**：`downsideIf` 以 0 为锚，只有同比为负才产生惩罚；净利润从 +50% 到 +120% 的「翻倍式增长」不扣分。
- **`stabilityAvailable` 不变**：仍要求单指标至少 2 个同比点；不可用时权重按剩余权重归一化（§19.6.4）。
- **g1 折减仍用全幅 `dispersion`**（`recommendParams` 第 3 参不改）：本次只修复「模型落档」的稳定性信号；g1 折减属于速度保守化，改成下行口径会额外抬高高增长公司的 g1，超出本次授权范围。若后续需要，可把第 3 参替换为 `downsideDispersion`，属独立评审项。
- **`GrowthDispersion` 字段语义不变**（全幅极差，供展示/volatile/g1）；新增 `GrowthDownsideDispersion` 承载稳定性分输入，两者必须都输出，避免解释时混淆。

**算例（睿创 688002，2025 年报）**：

| 指标 | 旧规则 | 新规则 |
| --- | --- | --- |
| 营收 YoY | `+48.65/+34.51/+21.27/+46.06` | 同 |
| 净利润 YoY | `-37.47/+47.04/+4.74/+124.21` | 同 |
| 稳定性输入 | 全幅极差 `161.68pp` | 下行极差 `37.47pp` |
| `Sst` | `clamp(100-2×161.68,0,100)=0` | `clamp(100-2×37.47,0,100)=25.06` |

| 对称剔除 FCF 会抬高真周期股的 X | 周期股在景气高点的生命周期档位可能上移 | 生效 `Cyclical` 仍为 true，`fcf_years=7` + `trim_mean` 保守化基期；稳定性下行分惩罚低谷；β 兜底仍可为 1.2。若后续需要更强约束，可单独立项「生效周期 → 模型上限 two_stage」，本次不引入 |
| 成长性阈值误判 | 个别真周期股被豁免，或个别成长股未被豁免 | 四层判据（CAGR/最小同比/强增长年/毛利率极差）相互制衡；阈值全部为常量，可回测后只调常量 |
| 毛利率缺失/口径异常 | 毛利率条件不阻塞，可能放松否决 | `GrossMarginOK=false` 时只靠营收三层判据；金融股已判不适用；Basis 明示「毛利率极差 不可用」 |
| 年报不足 3 年 | 新公司无法触发否决 | 保守保持现状（不猜）；数据满足后再生效 |
| 稳定性分口径变化 | 所有公司 `Sst` 变化，部分档位边界移动 | 存在上行样本时 `downside ≤ raw spread`，`Sst` 不降；若窗口内全部为负增长，下行口径可能更严格（有意为之：持续萎缩应被惩罚）；硬闸门 X≥12/6/3 不变 |
| 正向波动不再扣分 | 极端「一次性暴增」公司稳定性分偏高 | X 已用去极值中位数；`valGrowthMax=30` 与 SGR 上限约束 g1；ROE/增速信号仍在 |

**回滚**：

- 本次不新增 feature flag（三条规则是口径修正，无中间态）。如需灰度，可增加 `valGrowthNoiseFix = true` 总开关，但会在三处引入分支，**不推荐**；直接回滚本次提交即可恢复旧行为。
- 旧的 `FCFCyclical` 语义已被收敛为「生效判据」；若回滚，前端需同步回滚 `fcf_cyclical_raw`/`fcf_growth_veto` 展示。

**关键决策点（已按推荐定稿；若用户不同意，回主对话确认）**：

| # | 决策 | 推荐 | 备选与影响 |
| --- | --- | --- | --- |
| Q1 | FCF 不稳定时「剔除」还是「降权/改 CAGR」 | **剔除，其余可用项等权**（两项时 `X=(rev+np)/2`） | 降权 0.5 仍被拖累（睿创约 14%）；改 CAGR 对首末年敏感且无法消除符号翻转，**不推荐** |
| Q2 | FCF「不稳定」是否包含正负号方向 | **对称剔除**（不看 `xFCF` 正负） | 仅剔除负值会产生选择偏差；对称剔除对真周期股的影响由周期规则兜底 |
| Q3 | 成长性否决阈值 | `CAGR≥15%`、`MinYoY≥-10%`、`强增长年≥2`、`毛利率极差≤20pp` | 更严（CAGR≥20、极差≤15）会漏掉部分成长股；更松（CAGR≥10、极差≤30）会放入部分周期股 |
| Q4 | 成长性否决后的 `fcf_years` | **5 年** | 3 年更贴近近况但平滑不足；7 年正是本次要修正的误判，**不推荐** |
| Q5 | 稳定性分只罚下行还是罚趋势偏离 | **只罚下行（以 0 为锚）** | 罚「低于自身稳健增速」会再次惩罚高增长后的正常回落，且引入趋势基准，解释成本高 |
| Q6 | g1 折减是否也改用下行离散度 | **不改**（仍用全幅） | 改后会额外抬高成长股 g1，超出本次授权；可作为后续独立评审 |
| Q7 | 成长性否决是否抑制 β 兜底的 `volatile` | **抑制**：`(volatile && !gp.Veto) 或 cycle.Cyclical` | 不抑制则预推导阶段睿创仍 β=1.2；AI 分类优先的纪律不变，终态影响有限 |

**结论**：三条修复均为纯函数、常量驱动、可单测，改动收敛在 `valuation_recommend.go` + `model/ai.go` + `ai.go` 的展示/回填 + `app.js` 的只读展示。Q1~Q7 已有推荐且可回退，**无阻塞性待拍板项**；若用户对 Q3 阈值或 Q5 口径有不同偏好，仅需调常量/替换 `downsideIf` 输入，不改结构。
