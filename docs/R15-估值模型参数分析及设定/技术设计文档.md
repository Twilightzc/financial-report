### 19.1 设计目标与影响面

**目标**：在不破坏 R7「确定性推导、大模型不产出数值」纪律的前提下，把估值参数（重点是**折现率 r**）从「信用风险分档」升级为「有经济学含义的资本成本推导」，并在出口处对**不适用于现金流贴现法**的公司（金融股 / 负 FCF / 亏损）明确给出「不适用」结论而非硬套模型。

**`AIValuation` 新增 JSON 只读字段**（响应体）：


字段约定：

- **`applicable` 不设 `omitempty`**：算法恒产出（true/false 均须出现），与 `adjust_rd` / `fcf_mode` 同风格；旧客户端忽略未知字段。前端判定用 `=== false`（旧缓存响应无该字段时为 `undefined !== false`），保证**旧响应不误禁用按钮**（向后兼容，见 19.5.5）。
- 其余 7 个设 `omitempty`：`omitempty` 仅省略 Go 零值（数值 `0`、字符串 `""`）。`beta` 恒为 `1.0/1.2/0.8`（非零）→ 必输出；`string` 型 `beta_tier` 恒非空 → 必输出；`wacc_baseline`/`risk_premium` 为 0 时省略属正常语义（如 riskPoints=0 → 无 `risk_premium` 字段，前端 `v-if` 自然不显示）。**故 `beta` 无需特殊处理**。
- **`beta_tier`**：P1 取常量表中文名，未命中行业判定时恒为「一般行业」。
- 不新建 model 常量：档位 key 复用 `service` 包 `valBeta*` 常量。

### 19.5 P1（详细，可直接编码）：折现率 r 的 WACC 基线化 + 出口收口

#### 19.5.1 新增常量表（`internal/service/valuation_recommend.go`）

```go
// R15/P1《自由现金流估值参数设定方法论》常量表（生效日期 2026-10-16）。
// Rf / ERP / β 均为固定常量（Q8/Q9：不新增数据源，随版本手动更新并注明生效日期）。
const (
    valRiskFreeRate    = 2.5  // Rf 无风险利率 %（10 年期国债收益率常量）
    valEquityRiskPrem  = 5.5  // ERP 股权风险溢价 %（A 股常用常量）
    valBetaCyclical    = 1.2  // β 周期性行业
    valBetaNormal      = 1.0  // β 一般行业
    valBetaUtility     = 0.8  // β 公用事业（P1 不可达，待行业判定启用，见 19.11 #2）
    valRiskPremiumCap  = 3.0  // 公司特定风险溢价上限 %（= 风险点满格 3 × 1.0）
    valDiscountRateMin = 8.0  // r 收口下限 %
    valDiscountRateMax = 15.0 // r 收口上限 %（放宽自原 [9,12]）
    valDiscountRateStep = 0.5 // r 收口网格步长 %
    valLongTermGDP     = 4.0  // 长期名义 GDP 增速上限 %（永续增长率 gk 上界，G6 常量显式化）
)

// valBetaTierNames β 档位中文名（供展示与 prompt）。
var valBetaTierNames = map[string]string{
    "cyclical": "周期性行业", "normal": "一般行业", "utility": "公用事业",
}
```

**保留** `valDiscountFallback = 10.0`（无资产负债表时的保守兜底，语义与现状一致）；**删除** `valDiscountTable`。

#### 19.5.2 推导链（伪代码级）

```
─ 输入：balanceByYear, incomeByYear, latest（三表最新年报年）, volatile（R7 已算）, riskPoints, hasBalance

Step 1  β 档位（确定性，仅用 volatile）
        beta, tierKey, tierName := betaFor(volatile)
          volatile          → (1.2, "cyclical", "周期性行业")
          !volatile         → (1.0, "normal",   "一般行业")
          // 公用事业 0.8 表内保留，P1 不可达（需行业判定，见 19.11 #2）

Step 2  股权成本 Re（CAPM）
        Re := equityCostCAPM(beta) = Rf(2.5) + beta × ERP(5.5)
          beta=1.0 → Re=8.0%（与原硬编码 8% 吻合，验证常量合理性）
          beta=1.2 → Re=9.1%

Step 3  WACC 基线
        if !hasBalance:
            baseline = NaN（不可算），Rate := valDiscountFallback(10.0)，premium := 0，加 Warning「缺少资产负债表…」
        else:
            base := waccWithEquityCost(balanceByYear, incomeByYear, latest, Re)   // 见 19.5.3
            baseline = (base == nil ? Re : *base)   // 投入资本=0（无债务且无权益）时退化为纯股权成本 Re
            premium := min(float64(riskPoints) × 1.0, valRiskPremiumCap)          // 0~3%

Step 4  收口：加风险溢价 → clamp[8,15] → 0.5 网格（四舍五入到 0.5）
        raw := baseline + premium
        r := round(raw / 0.5) × 0.5
        if r < 8  → r = 8
        if r > 15 → r = 15

Step 5  永续增长率 gk（G6：上限常量显式化）
        gkRaw := perpetualGrowthRaw(r)   // 沿用旧映射：r≤9→4；r≤11→3；else→2
        gk    := min(valLongTermGDP(4), gkRaw)

Step 6  自校验（出口一致性 C1~C3）：r > gk 恒成立（min r=8 > max gk=4），否则加 Warning（防御）
```

**Rf + β×ERP 与旧 8% 的衔接验证**：`β=1.0` 时 `Re = 2.5 + 1.0×5.5 = 8.0`，恰等于 `analysis.go:1751` 硬编码的股权成本，说明 P1 未凭空造数；r 的变化**只来自三处**：(a) WACC 里债务加权含真实 Rd（原先完全不含）、(b) 加公司特定风险溢价、(c) 网格放宽到 [8,15]。

#### 19.5.4 出口收口与不适用判定（Q6 / C1~C3 挂点）

在 `RecommendValuation` 组装修饰前，引入一个**警告累加器**与**适用性判定**（P4 向同一累加器追加 C4~C7）：

```go
warns := []string{}
if dr.Warning != "" { warns = append(warns, dr.Warning) }

// —— C1~C3 一致性守卫（构造上恒成立，作为防御与 P4 挂点）——
// C1 r > g_term：r≥8 > gk≤4，恒成立。
// C2 g_term ≤ g(预测期末段) ≤ g1：由 recommendParams 的三阶段递减构造保证（P1 未改，P2 修复边界）。
// C3 g_term ≤ longTermGDP：由 gk = min(valLongTermGDP, …) 构造保证。

// —— 不适用判定（Q6，按序命中，唯一出口）——
applicable, reason := true, ""
switch {
case operatingFreeCashFlow(inc, cf) <= 0:
    applicable, reason = false, "以最新年报计的基期经营资产自由现金流为负或零，现金流贴现法不适用。"
case isFinancialLike(inc):
    applicable, reason = false, "金融股（无「营业成本」科目，报表口径与现金流贴现法不匹配），暂不支持估值。"
case netProfitReconstructed(inc) <= 0:
    applicable, reason = false, "最新年报净利润为负（亏损），无法构成可持续现金流，现金流贴现法不适用。"
}
if !applicable { warns = append(warns, reason) }

warning := strings.Join(warns, "；")   // 既有 Warning 字段（类型/JSON 名不变）
```

### 19.6 P2（概要）：基准增速口径与模型分档（G3+G4+G5+G7）

**目标**：让 `X%` 与贴现对象（FCF）同口径、三项显式等权；模型分档由单阈值改多信号，消除 `19.9% vs 20.1%` 边界抖动。

- **改动点**：`RecommendValuation` 的样本构造段（`:76-99`）与 `classificationModel`（`classifyModel` :425）。
- **依赖**：仅用既有字段（营收 / `netProfitReconstructed` / FCF），无新增拉取。`fcfGrowthPoints`（:252）已存在可复用。
- **G3 规则（概要）**：三项＝营收、净利润、**FCF**；每项取窗口内 **CAGR**（或同比去极值后中位数）；`X = (x_rev + x_np + x_fcf) / 3`（**显式等权**，不再「样本合并取一次中位数」）；`volatile` 判定沿用极差 > 40pp。
- **G4 规则（概要）**：`g1 = min(X, SGR, valGrowthMax(30))`；`SGR = ROE × 留存率`，留存率取「股东权益增长率」近似 `(权益期末 − 权益期初) ÷ 净利润`（clamp[0,1]）；`ROE`/留存率不可得 → 不设上限、加 Warning。**依赖多期资产负债表**（AI 分析已具备）。
- **G5 规则（概要）**：三信号打分落档——增速水平（X 分档）+ 增速稳定性（`volatile`）+ ROE 水平（净利含金量/ROE 分档）；`X<3%` 归 `zero`（现归 `perpetual`）；`18%~22%` 网格平滑归同档。分档表与每信号权重建常量。
- **G7 规则（概要）**：三阶段 `g2 = clamp(gk+1, g1, valLongTermGDP)`，保证 `g1 ≥ g2 ≥ g3`；无可行解 → 降级为 `two_stage`。
- **触发条件**：`X%` 变化会平移所有档位，属**行为级变更**，须在 P1 稳定并回归后再做（方法论 P2 风险项）。

### 19.7 P3（概要）：基期 FCF 可持续性与动态年数（G8+G9+G11）

- **改动点**：`RecommendBaseFCF`（:168，新增「强周期」判据与新规则）、`valFCFRecMaxYears`（:34 5→7）、`rdAdjustSuggestion`（:323 双条件）。
- **G8（周期性识别）**：新增确定性判据 `FCF 变异系数 = 标准差 ÷ 均值 > 0.5`（常量）或**正负交替** → 判「强周期」，推荐 `trim_mean` 且 `fcf_years` 取满可用年份。依赖 FCF 多期序列（已具备）。
- **G9（动态年数）**：`fcf_years` 按波动性给（平稳 3、强周期 5~7），上限 5→7；前端 `valFCFYears` `:max=10`（`app.js:1361`）已支持，无需改控件。
- **G11（研发双条件）**：`rdAdjustSuggestion` 由「费用率 > 5%」改为「费用率 > 5% **且** 研发同比扩张 > 0」双条件，避免成熟公司因会计口径波动误加回。
- **触发条件**：改变基期 FCF 与 `adjust_rd` 建议，P1/P2 稳定后独立迭代。

### 19.8 P4（概要）：一致性校验层（G10，C4~C7）

- **改动点**：`RecommendValuation` 出口的 `warns` 累加器（P1 已建挂点，见 19.5.4）追加 C4~C6；C7 口径同源已由 R7/R13 构造保证。
- **C4（SGR 上限）**：`g1 > SGR` → 降 `g1` 到 SGR 或加 Warning（与 P2 的 G4 同源，P2 已引入 SGR 后此处只做「超过即告警」）。
- **C5（Capex 与 g 匹配）**：`Capex 覆盖率 = CONSTRUCT_LONG_ASSET ÷ maintenanceCapex` > 1.3（常量）且模型为高增长（`two_stage`/`three_stage`）→ Warning「基期 FCF 为保全口径，未含扩张性资本支出，高增长假设偏乐观」。**字段无新增**：`CONSTRUCT_LONG_ASSET`（`fields.go:80`，已用于 `constructNet`）、`maintenanceCapex`（`analysis.go:1793`）。
- **C6（FCF 与净利润关系）**：`FCF ÷ netProfitReconstructed` 长期显著 > 1（如 > 1.5 倍，复用 `cashToProfit` 思路）→ Warning「自由现金流长期远超净利润，注意会计现金含量」。`netProfitReconstructed ≤ 0` 时跳过。
- **ΔNWC（可选，C5 增强）**：`ΔNWC = workingCapital(balanceByYear[y]) − workingCapital(balanceByYear[y−1])`（`analysis.go:596`）；仅当多期资产负债表可得时启用，否则**省略该分量并跳过相应判据**（见 19.10 #1）。
- **AI 定性修正层（Q7）**：**不开放**。维持 R7「大模型不产出任何数值」纪律；本层若有需求须单独立项评审。

### 19.11 R15 关键决策点 / 待确认项

1. **r 的 WACC 基线化会改变既有推荐结果（P1 固有影响，已按 Q1 采纳）**。茅台等低杠杆公司 r 由 9.0 降至 8.0（股权成本 8.0 + 风险溢价 0），高杠杆周期股 r 可能升到 12~15。**已按 Q1「推荐」采纳**，无需再确认；此处仅登记「预期行为变化」并已在 19.9 列入端到端核对。
2. **β 三档中「公用事业 0.8」P1 不可达（需用户知悉）**。P1 只用 `volatile` 判「周期 1.2 / 一般 1.0」；公用事业档需行业判定（待实测，见 19.10 #5）。**推荐**：P1 先不做行业 β，避免引入脆弱映射；若用户坚持 P1 即需三档生效，则须提供**确定性行业来源**（如主营构成关键词白名单），否则会破坏可复现性——**倾向不做**。
3. **无资产负债表时的 r 兜底**。保留现状 `valDiscountFallback=10.0`（保守）+ Warning，**不**改为「纯股权成本 8.0」。**推荐保留 10.0**：缺表即无法评估资本结构与财务风险，取更保守值更稳妥，且与现状一致（最小惊讶）。
4. **不适用时「仍输出模型」vs「不输出模型」**。本设计**仍输出** `model`/`params`（保 R7 恒产出与 prompt 完整），仅在 `applicable=false` 时由前端禁用「套用到估值」。**推荐**；若产品要求「不适用即不显示模型」，需约定 `model=""` 的空值契约（会波及 prompt 与前端渲染），**需用户拍板**（当前倾向不采用）。
5. **金融股判定的启发式（`OPERATE_COST` 缺失）是否足够**。属**待实测**（19.10 #3）；若不可靠，采用降级方案（复用 handler 取数失败路径前移判定）。**此为唯一可能影响 P1 边界的实测项**，但即使不可靠也可回落（degrade）不阻塞 P1。
6. **`beta` 字段不设 `omitempty`**（避免 `1.0` 被省略导致前端显示抖动），`applicable` 同样不设；其余新字段设 `omitempty`。**推荐此组合**（与既有 `base_growth`/`adjust_rd`/`fcf_mode` 风格一致）。
7. **出口收口提前到 P1（本设计相对方法论 §11 的唯一调整）**：把一致性校验挂点与不适用判定并入 P1，P4 只追加 C4~C7。**推荐**（避免 `RecommendValuation` 出口二次重构）；如需严格按方法论分期，可把 19.5.4 的不适用判定单列到 P4，但会留下 `Warning` 拼接的临时实现。
