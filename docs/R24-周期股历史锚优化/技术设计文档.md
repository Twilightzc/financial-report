# R24 周期股历史锚优化 技术设计文档

> 需求依据：`docs/R24-周期股历史锚优化/需求文档.md`（FR-1 ~ FR-8、AC-1 ~ AC-17）。
> 设计范围：只改「历史锚增速口径」及由此带来的窗口、输出字段与测试变化；不改周期判定算法、周期位置修正、三锚权重、模型分档、折现率、终值、基期 FCF 选取、DCF 四模型。
>
> **决策基线（用户已拍板，本文不再讨论替代方案）**
>
> | 编号 | 决策 |
> | --- | --- |
> | Q1 | 周期股历史锚 CAGR 窗口 = **最近 7 个年报**；不足 7 年时用全部可用年报。非周期股保持现有 5 年窗口。 |
> | Q2 | 把完整 `isCyclical` 判定（`cycleWindow` + `profitCycle` + `detectCyclical`）整体前移到历史锚之前；不得用 `cycle.Cyclical` 代理。预推导阶段（`IndustryType` 为空）走 FCF/盈利周期；AI 阶段优先 AI 行业分类。 |
> | Q3 | `delta` / `cycleAdjustment` 公式、阈值、±6pp 上限、只作用于历史锚，全部不变。 |
> | Q4 | FCF 剔除规则保留（`RawCyclical → Included=false`）；若 AI 判定周期但 FCF 稳定未剔除，该 FCF 分项也使用 CAGR，不允许同一历史锚内混合口径。 |
> | Q5 | CAGR 无定义（首值 ≤0 / 末值 ≤0 / 跨度 ≤0 / 样本 <2）时回退现行「同比去极值中位数」；回退也不可用时该分项不可用。 |
> | Q6 | 新增 `growth_history_basis` 枚举字段（`cyclical_cagr` / `cyclical_mixed` / `robust_median`）；前端最多一句弱化说明；不新增表。 |
> | Q7 | 本轮不做跨周期正常化收益。 |
>
> **与需求文档的两处差异（已在第 10 节列为待确认）**
>
> 1. 需求文档 FR-1 / Q2 写的是「周期股沿用最近 5 个年报」，已被用户锁定的 Q1（7 年）取代；本文按 7 年设计。AC-1 的 5 年样本数字只有在「可用年报不足 7 年」或测试 fixture 仅给 5 年时才能精确复现；真实公司若已有 7 年以上数据，结果会与 AC-1 的 5 年数字不同。
> 2. 需求文档 FR-1 写「FCF 参与时使用现有 ≤5 年窗口」；本文按 Q1 的一致性默认 FCF 也切到周期股 7 年窗口（见 6.2、10.2），如需保持 FCF 5 年需主对话确认。

## 1. 设计目标与影响面

### 1.1 目标

1. 周期股（`isCyclical=true`）历史锚中的营收、重构净利润、参与合成的 FCF，改为「窗口首末年度复合增速（CAGR）」。
2. V 型复苏年不再被「去极值」剔除，历史锚能反映全窗口趋势。
3. 周期判定提前到历史锚之前，保证历史锚、`pos`、`delta`、负增长归因使用**同一个** `isCyclical`。
4. 非周期股所有既有数值、字段、文案逐位不变。
5. 输出可审计的口径字段，前端只增加一句说明。

### 1.2 非目标

- 不改 `indicatorGrowth` 的默认优先级（非周期股仍为同比去极值中位数优先）。
- 不改 `computeCyclePosition`、`cycleAdjustment`、`detectCyclical`、`detectProfitCycleDetail`、`detectFCFCycle`。
- 不改 `buildGrowthAnchorTable`、三锚权重、0.5pp 取整、[−5, 30] 区间、g1 上限结构、模型阈值/降级链。
- 不改 WACC/CAPM、β 档位、终值/稳定度、基期 FCF 选取、Capex 校验、FCF/净利润校验、敏感性矩阵。
- 不新增数据源、不新增 IO/网络/AI 调用、不新增第三方依赖。
- 不改 R16 估值历史快照的结构与数据。

- 无路由、请求参数、既有 JSON 字段名/语义变化。

## 2. 总体架构

### 2.1 分层与调用链（不变）

```
api/ai.go  GetAIAnalysis
  ├─ 预推导：service.RecommendValuation(input{IndustryType:""})
  ├─ 调 AI（定性行业分类/风险）
  ├─ AI 阶段：service.RecommendValuation(input{IndustryType: AI 分类})
  └─ service.ApplyValuationRecommendation(&result, rec)
        └─ model.AIValuation（JSON 返回 / 缓存）

service 层保持纯函数：无 IO、无随机、无时间依赖。
```

R24 的所有计算仍集中在 `RecommendValuation` 及其私有纯函数内，不跨层、不引入 client 依赖。

### 2.2 `RecommendValuation` 内部顺序

现状（`internal/service/valuation_recommend.go:233`）：

```
annualRows / 基期年
→ incomeWindow=5, fcfYears≤10, fcfGrowthYears=5, fcfByYear
→ gp = assessGrowthPattern(incomeWindow)
→ cycle = detectFCFCycle
→ 历史锚（5 年，同比去极值中位数）
→ 波动/离散度/下行
→ 折现率
→ cycleWindow=7, profitCycle, isCyclical, pos, delta      ← 当前在 299–309
→ 宏观锚/前瞻锚/复合锚 A
→ SGR/终值/负增长归因/基期 FCF/校验/输出
```

R24 目标顺序：

```
annualRows / 基期年
→ incomeWindow=5, fcfYears≤10, fcfGrowthYears=5, fcfByYear
→ gp = assessGrowthPattern(incomeWindow)                  ← 判定输入窗口不变
→ cycle = detectFCFCycle（≤10 年）                        ← 判定输入窗口不变
→ cycleWindow=7, profitCycle, isCyclical, pos, delta      ← 整体前移
→ historyWindow / fcfHistoryWindow（周期股各 7 年，否则沿用 5 年）
→ 历史锚（周期股 CAGR 优先，无定义回退中位数）
→ 波动/离散度/下行（仍用 5 年 incomeWindow）
→ 折现率（fallbackCyclical 仍用 cycle.Cyclical + 波动）
→ 宏观锚/前瞻锚/复合锚 A
→ SGR/终值/负增长归因/基期 FCF/校验/输出
```

关键点：

- `gp`、`cycle` 的输入窗口保持不变，因此 `isCyclical`、`pos`、`delta` 的取值与移动前一致（AC-7）。
- `fallbackCyclical` 在折现率处使用，仍基于 `cycle.Cyclical` 与波动，不受前移影响。
- 后续对 `profitCycle`、`pos`、`delta`、`posWarn` 的引用都在新位置之后，不存在前向引用。
- 波动、离散度、ROE、研发调整继续使用 `incomeWindow`（5 年），不随历史锚窗口扩大，避免 AC-13 之外的副作用。

### 3.2 `model.AIValuation`（API/缓存结构）

```go
GrowthHistoryBase     float64 `json:"growth_history_base"`     // 历史锚周期修正前，%
```

`ApplyValuationRecommendation`（`internal/service/ai.go:790–794`）在既有映射后补两行，字符串原样透传，不做取整：

```go

GrowthHistoryAdjusted: round2(rec.GrowthHistoryAdjusted),
GrowthHistoryBasis:    rec.GrowthHistoryBasis,
GrowthHistoryNote:     rec.GrowthHistoryNote,
```

### 3.3 枚举取值与判定

| 值 | 含义 | 触发条件 |
| --- | --- | --- |
| `cyclical_cagr` | 周期股，所有**实际计入**历史锚的分项都用 CAGR | `isCyclical && histOK` 且计入项 basis 全为 `CAGR` |
| `cyclical_mixed` | 周期股，至少一个计入分项回退同比中位数 | `isCyclical && histOK` 且任一计入项 basis 非 `CAGR` |
| `robust_median` | 非周期股现行口径 | `!isCyclical && histOK` |
| `""`（字段省略） | 历史锚不可用 | `!histOK` |

判定只统计 `okRev`、`okNP`、`fcfTerm.Included` 三项；被剔除的 FCF、不可用的分项不参与。若周期股只有 FCF 一个计入项且它回退中位数，返回 `cyclical_mixed`（不新增 `cyclical_median`，保持 Q6 三值约定）。

### 3.4 JSON 示例（周期股，全部 CAGR）

```json
{
  "growth_history_base": -3.32,
  "growth_history_adjusted": -1.53,
  "growth_history_basis": "cyclical_cagr",
  "growth_history_note": "周期股历史锚按 2019–2025 年复合增速计算。",
  "growth_cycle_adjust": 1.8,
  "growth_cycle_note": "周期位置 中位（-0.18）修正 +1.8pp，已含于历史锚。"
}
```

非周期股：

```json
{
  "growth_history_base": 11.0,
  "growth_history_adjusted": 11.0,
  "growth_history_basis": "robust_median"
}
```

（`growth_history_note` 省略。）

### 3.5 为什么放顶层而不放 `GrowthAnchorTable`

- `GrowthAnchorTable`（`internal/model/ai.go:51–61`）的职责是「三锚加权合成的可复算构成」，恒满足 `Σ(Value×Weight)=Raw`、`Raw+调整=Final`；历史锚口径是**输入侧**计算细节，放进表内会让「构成表」混入元信息。
- 与 `growth_history_base` / `growth_history_adjusted` / `growth_cycle_note` 同级，前端只需在历史锚附近读一个字段，`ApplyValuationRecommendation` 也只需两行赋值。
- 需求 Q6 的字段名就是顶层语义 `growth_history_basis`，避免嵌套路径 `growth_anchor.history_basis` 与既有 API 风格不一致。
- 备选 `GrowthAnchorTable.HistoryBasis` 可行但无额外收益，本文不采用。

## 4. 数据源与字段映射

### 4.1 输入完全不变

R24 不新增任何东财/腾讯字段，仍使用 `RecommendValuation` 已接收的三张表：

| 指标 | 来源 | 字段/函数 | 单位 |
| --- | --- | --- | --- |
| 营业收入 | 利润表 | `TOTAL_OPERATE_INCOME`，`revenue()` | 元 |
| 重构净利润 | 利润表 | `netProfitReconstructed()` = 税前利润 − 所得税 | 元 |
| 自由现金流 | 现金流量表 | `operatingFreeCashFlow()` = `NETCASH_OPERATE` − 保全性资本支出 | 元 |
| 毛利率/净利率（周期位置） | 利润表 | 现有 `computeCyclePosition` | % |
| 年报年度 | 三表 | `annualRows()`，只取 `12-31` | 年 |

### 4.2 窗口选择

| 窗口 | 非周期股 | 周期股 | 用途 |
| --- | --- | --- | --- |
| `incomeWindow` | 最近 ≤5 个年报 | 最近 ≤5 个年报 | 成长性判定、波动/离散度、ROE、研发调整（**不变**） |
| `cycleWindow` | 最近 ≤7 个年报 | 最近 ≤7 个年报 | 周期位置、盈利周期、结构指标（**不变**） |
| `historyWindow` | = `incomeWindow`（≤5） | `yearWindow(incomeYears, latest, 7)` | 营收/净利润历史锚增速 |
| `fcfYears` | 最近 ≤10 个年报 | 最近 ≤10 个年报 | 基期 FCF 选取、FCF 周期判定（**不变**） |
| `fcfHistoryYears` | = `fcfGrowthYears`（≤5） | `yearWindow(fcfYears, latest, 7)` | FCF 历史锚增速及计入判定 |

说明：

- 「7 年窗口」= 最近 7 个年报观测值，CAGR 指数跨度为末年年份 − 首年年份（7 个观测通常跨 6 年），与 `r18CycleMaxWindowYears` 的用法一致。
- 周期股若只有 5 年数据，则实际窗口为 5 年，AC-1 的 5 年样本即属于此情况。
- `fcfHistoryYears` 只从「利润表 ∩ 现金流量表」的年度中取，FCF 缺失年不会用 0 补齐（沿用 `yearWindow` 语义）。

### 4.3 单位与换算

- CAGR 与原 `indicatorGrowth` 一致，输出百分数（`×100`）。
- 历史锚 `x`、`GrowthRevenue` / `GrowthProfit` / `GrowthFCF` 仍为百分数原值；展示层 `round2` 不变。
- 不使用金额绝对值做跨年比较，窗口内只依赖首末比值，天然消除单位/规模影响。

### 4.4 字段易错提醒

- 利润表**没有** `OPERATE_INCOME` / `NETPROFIT`；营业总收入用 `TOTAL_OPERATE_INCOME`。
- 重构净利润必须走 `netProfitReconstructed`，不要直接取 `PARENT_NETPROFIT`（口径与 R19 保持一致）。
- FCF 的保全性资本支出走 `operatingFreeCashFlow`，不要重复计 `OILGAS_BIOLOGY_DEPR`（已含于 `FA_IR_DEPR`）。

## 5. 接口 / API 设计

### 5.1 路由与请求

不变：

```
GET /api/stock/:code/ai-analysis
```

R24 不新增 query 参数。两阶段调用的输入仍由 `internal/api/ai.go:143–174` 组装：

1. 预推导：`IndustryType=""`，`isCyclical` 由 FCF 强周期或盈利周期判定。
2. AI 返回后：`input.IndustryType = result.Valuation.IndustryType`，`input.CompanyRisks = result.Valuation.CompanyRisks`，再次 `RecommendValuation`。
3. `ApplyValuationRecommendation` 覆盖 AI 输出中的估值参数。

因此同一公司可能出现「预推导用中位数、AI 阶段用 CAGR」的差异；这是设计预期（AC-8），前端只展示最终 AI 阶段结果。

### 5.2 响应

统一 `{code, data, message}`，`code==0` 成功。新增字段位于 `data.valuation`：

```json
{
  "code": 0,
  "message": "",
  "data": {
    "valuation": {
      "growth_history_base": 3.09,
```

### 6.2 `windowCAGR`（FR-1 / FR-2）

```go
// windowCAGR 窗口首末年度复合增速（%）。
// 要求 years 升序、与 values 等长；首值/末值必须为正，跨度必须为正。
func windowCAGR(years []int, values []float64) (float64, bool) {
    if len(years) < valGrowthMinSamples || len(values) != len(years) {
        return 0, false
    }
    first, last := values[0], values[len(values)-1]
    span := years[len(years)-1] - years[0]
    if first <= 0 || last <= 0 || span <= 0 {
        return 0, false
    }
    v := (math.Pow(last/first, 1/float64(span)) - 1) * 100
    if math.IsNaN(v) || math.IsInf(v, 0) {
        return 0, false
    }
    return v, true
}
```

边界：

| 场景 | 结果 |
| --- | --- |
| `len(years) < 2` 或长度不一致 | `false` |
| 首值 ≤0 | `false` |
| 末值 ≤0 | `false` |
| 年份跨度 ≤0（重复年/倒序） | `false` |
| `math.Pow` 溢出/NaN | `false`（`indicatorGrowth` 原实现无此守卫，新函数必须有） |
| 稀疏年度（如 2021、2023、2025） | 按实际跨度 4 年计算，允许 |

`indicatorGrowth` 保持原逻辑，仅把 `"同比去极值中位数"` / `"CAGR"` 替换为 `growthBasisMedian` / `growthBasisCAGR` 常量，返回值与优先级逐位不变。**不在 `indicatorGrowth` 内调用 `windowCAGR`**，避免给非周期股引入任何行为差异。

### 6.3 `historyGrowth`（FR-1 / FR-5）

```go
// historyGrowth 历史锚单指标增速。
// 非周期股：完全沿用 indicatorGrowth（同比去极值中位数优先）。
// 周期股：优先窗口首末 CAGR；CAGR 无定义时回退 indicatorGrowth（有效同比点 → 中位数）。
func historyGrowth(years []int, values []float64, cyclical bool) (value float64, basis string, ok bool) {
    if !cyclical {
        return indicatorGrowth(years, values)
    }
    if v, okC := windowCAGR(years, values); okC {
        return v, growthBasisCAGR, true
    }
    return indicatorGrowth(years, values)
}
```

为什么回退直接复用 `indicatorGrowth`：

- Q5 要求回退「现行同比去极值中位数」，复用可保证去极值、样本数阈值（≥4 才去极值）、中位数定义完全一致。
- CAGR 无定义时，`indicatorGrowth` 的 CAGR 分支实际上也不会成功（无有效同比点意味着窗口内数值全 ≤0 或首值 ≤0），因此不会出现「回退后又返回 CAGR」的歧义；即使出现，`resolveHistoryBasis` 也会按 `CAGR` 计入，不会误标 `mixed`。

### 6.4 序列封装与 FCF 分项

```go
func rowSeriesGrowth(byYear map[int]model.ReportRow, years []int,

        vals[i] = fcfByYear[y]
    }

}
```

`assessFCFGrowth` 只改两处：增速调用传入 `cyclical`，剔除规则与原因文案不变。

```go
func assessFCFGrowth(fcfByYear map[int]float64, years []int,
    otherAvailable bool, cycle fcfCycle, cyclical bool) fcfGrowthTerm {
    v, basis, ok := fcfSeriesGrowth(fcfByYear, years, cyclical)
    t := fcfGrowthTerm{Value: v, Basis: basis, Available: ok, Included: ok}
    if !ok || !otherAvailable {
        return t
    }
    yoys := fcfGrowthPoints(fcfByYear, years)
    switch {
    case cycle.RawCyclical:
        t.Included = false
        t.Reason = "FCF 序列波动较大"
    case len(yoys) < valFCFGrowthMinPoints:
        t.Included = false
        t.Reason = "FCF 有效同比点不足"
    case spread(yoys) > valFCFGrowthSpread:
        t.Included = false
        t.Reason = "FCF 增速极差过大"
    }
    return t
}
```

FCF 口径规则（对应 Q4 / FR-5 / AC-9 / AC-10）：

| 场景 | 增速口径 | `Included` | `GrowthFCFOK` |
| --- | --- | --- | --- |
| 非周期股，FCF 稳定 | 同比去极值中位数 | true | true |
| 非周期股，FCF 原始强周期 | 中位数 | false（营收/净利至少一项可用时） | true（只要增速可算） |
| AI 判周期，FCF 稳定 | **CAGR** | true | true |
| AI 判周期，FCF 原始强周期 | **CAGR** | false | true |
| 周期股，营收/净利都不可用，FCF 是唯一项 | **CAGR** | true | true |
| CAGR 无定义 | 回退中位数（若可用） | 按上述规则 | 回退成功则 true |

- `GrowthFCFOK` 的语义始终是「FCF 增速是否可算」，不是「是否计入历史锚」；不得把 `Included=false` 写成 `GrowthFCFOK=false`。
- 周期股 FCF 的计入判定使用 `fcfHistoryYears`（7 年）；`fcfYears`（≤10 年）仍只用于基期 FCF 选取和 `detectFCFCycle`。
- 若 FCF 因 `RawCyclical` 被剔除，其自身 `GrowthFCF` 仍按周期口径计算（CAGR 优先），只是不进入 `weightedGrowth`；这保证同一页面展示的分项口径一致。

### 6.5 口径枚举与说明文案

```go
// resolveHistoryBasis 历史锚口径枚举（只统计实际计入的分项）。
func resolveHistoryBasis(isCyclical, histOK bool, included []string) string {
    if !histOK {
        return ""
    }
    if !isCyclical {
        return valHistoryBasisRobustMedian
    }
    for _, b := range included {
        if b != growthBasisCAGR {
            return valHistoryBasisCyclicalMixed
        }
    }
    return valHistoryBasisCyclicalCAGR
}
```

非周期股为什么可以直接返回 `robust_median`：只要 `histOK=true`，至少一个分项来自 `indicatorGrowth`；在正常数据下，非周期分项有有效同比点时返回中位数，无有效同比点时 CAGR 也不可用，因此不会出现非周期 `CAGR` 且可用的情形。该结论只依赖 `indicatorGrowth` 现有逻辑，R24 不改它。即使未来逻辑变化，也只需把此处改为按 `included` 判定，不影响 API。

```go
// historyBasisNote 生成一句弱化说明；非周期/不可用返回空串。
func historyBasisNote(basis string, historyWindow, fcfWindow []int) string {
    years := historyWindow
    if len(years) < 2 {
        years = fcfWindow
    }
    span := ""
    if len(years) >= 2 {
        span = fmt.Sprintf("%d–%d 年", years[0], years[len(years)-1])
    }
    switch basis {
    case valHistoryBasisCyclicalCAGR:
        if span == "" {
            return "周期股历史锚按窗口复合增速计算。"
        }
        return fmt.Sprintf("周期股历史锚按 %s复合增速计算。", span)
    case valHistoryBasisCyclicalMixed:
        if span == "" {
            return "周期股历史锚部分分项因首末值非正改用同比中位数。"
        }
        return fmt.Sprintf("周期股历史锚按 %s窗口计算，首末值非正的分项改用同比中位数。", span)
    default:
        return ""
    }
}
```

文案约束（AC-16）：

- 只出现「周期股历史锚按 YYYY–YYYY 年复合增速计算。」或含「首末值非正的分项改用同比中位数」的一句。
- 不出现公式、权重、阈值、内部键名、CAGR 计算过程。
- 非周期股不输出说明，避免无意义 UI。

### 6.7 边界与 nil 处理汇总

| 场景 | 行为 |
| --- | --- |
| 无利润表 / 少于 2 年 | `historyWindow` 为空或 1 年；营收/净利不可用；FCF 若可用仍可计入；`histOK` 由 FCF 决定。 |
| 首值 ≤0 | 该分项 CAGR 不可用，回退中位数；有有效同比点则可用。 |
| 末值 ≤0 | 同上；注意亏损年末值也会触发回退，避免负值 CAGR 无意义。 |
| 跨度 0 / 年份重复 | `windowCAGR=false`；正常 `annualRows` 不会产生重复年，测试直接调用时需守卫。 |
| 中间年份缺失 | 按实际首末年份跨度计算，不按观测数计算；这是「全窗口趋势」的正确口径。 |
| 某项回退、某项 CAGR | 历史锚仍可合成，basis=`cyclical_mixed`。 |
| 全部不可用 | `histOK=false`，`basis=""`，`note=""`；A 走既有「仅前瞻+宏观」或「全不可用」路径。 |
| `math.Pow` 溢出 | 返回 `false`，不产生 `+Inf` / `NaN`。 |
| FCF 只有 1 个有效同比点但 CAGR 可用 | `GrowthFCFOK=true`（增速可算），`Included=false`（剔除规则不变）。 |

### 6.8 数值验证样例

**样例 A：AC-1 天山铝业 5 年样本（fixture 仅 2021–2025）**

营收：`100 → 114.83 → 100.7978 → 97.7134 → 102.6283`
净利润：`100 → 69.24 → 57.2269 → 115.8443 → 123.9882`

| 口径 | 营收 | 净利润 | 历史锚基数 |
| --- | --- | --- | --- |
| 周期股 CAGR | **+0.65%** | **+5.52%** | **+3.09%** |
| 非周期股中位数 | +0.985% | −5.16% | −2.09% |

**样例 C：p5 中远海控型 fixture（10 年年报，周期股取 2019–2025）**

- 重构净利润：`70 → 60.48`，CAGR ≈ **−2.41%**

- 该样本位置计算：GMpos≈−0.36、NMpos≈0、position≈−0.18、`delta≈+1.8pp`，调整后约 −1.53%。这说明 CAGR 口径可能让原本为正的历史锚转负，属于「透明趋势口径」的已知代价（需求文档第 11 节）。

### 6.9 两阶段 AI 行为

| 阶段 | `IndustryType` | `isCyclical` 来源 | 历史锚口径 |

## 11. 风险、限制与回滚

### 11.1 已知限制

- **端点敏感**：CAGR 只看首末，若窗口恰好从峰值到谷底，结果会明显为负（如 p5 中远海控样本 −4.24%），可能使 A 转负并切换模型。这是「透明趋势口径」的代价，需求已接受。
- **7 年仍未必覆盖完整周期**：铝、航运等可能是 7–10 年；本轮按锁定决策取 7 年，跨周期正常化留待 Q7 后续需求。
- **CAGR 与 delta 部分重叠**：周期高位时末年利润偏高会推高 CAGR，delta 又给负修正；本轮保留 delta，重叠未量化。
- **历史锚可能由正转负**：周期股估值模型/参数会随输入变化（AC-12 允许），可能出现 zero/perpetual 的跳变；前端需能正常展示。
- **FCF 窗口一致性假设**：若确认 FCF 保持 5 年，混合窗口会让 `cyclical_cagr` 的「全窗口」语义略弱，但枚举仍成立。

### 11.2 实现风险与规避
