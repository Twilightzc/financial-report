# R22 估值参数平滑与终值连续化 技术设计文档

> 需求依据：`docs/R22-估值参数平滑与终值连续化/需求文档.md`（唯一有效口径）。
> 修订关系：本设计只修订 R19/R20/R21 中的两条口径——**SGR 的多年平滑**与**终值增长率上限的连续化**。R19/R20/R21 的其余全部口径（FCF、WACC/CAPM、复合锚 A、模型分类与降级链、n1 规则、Capex 覆盖率、FCF/净利润、敏感性矩阵结构、0.5pp 网格、输出洁净、三档已废除）继续有效；冲突时以 R22 需求文档与本设计为准。
> 默认决策：需求文档 §7 的 Q1–Q8 已全部按推荐值采纳，本设计不再逐条重复，只在 §9 列出实现层面的补充假设。

## 1. 设计目标与影响面

### 1.1 设计目标

| 目标 | 实现方式 |
|---|---|
| G1 SGR 更稳定 | 新增多年平滑聚合：`ROE_avg × ret_avg`，窗口 5 年、至少 3 个有效年度，不足回落单年；单年分子分母完全复用现有函数 |
| G2 终值连续化 | 新增稳定度 `stability = 1 − min(0.8, c_raw)`，终值上限 `cap = 2% + (宏观锚 − 2%) × stability`，取消周期/非周期二分 |
| G3 约束不放松 | 仍按 `g∞ = max(0, floorHalf(min(cap, r − 1pp, SGR)))`，SGR 与 `r−1pp` 优先于稳定度上限 |
| G4 可复算、输出洁净 | 新增 `terminal_stability`、`sgr_window_years` 两个可复算数字；依据句只出现业务语言与数字，不出现 `cap`/`stability`/`macro`/`sgr` 等内部键名 |
| G5 不回归 | 只改 SGR 聚合与终值上限输入；FCF、WACC、锚 A、模型分类、n1、敏感性矩阵结构不动 |

## 2. 总体架构与数据流

### 2.1 分层职责

- 全部计算仍在 `internal/service`，纯函数、无 IO、无随机、不读时钟。
- `internal/client` 不变：不新增行情/财报/宏观/分红取数。
- `internal/api` 不变：handler 仍调用 `RecommendValuation`，再由 `ApplyValuationRecommendation` 覆盖 AI 返回的估值块。
- `internal/web` 不变：只消费既有 `/api/*` 字段。

新增逻辑放置：

```
internal/service/growth.go
  ├─ sgrSingleYear                 ← 从 sustainableGrowthR18 抽出的单年口径
  ├─ sustainableGrowthSmoothed      ← SGR 多年聚合（新）
  ├─ detectProfitCycleDetail        ← 盈利周期明细（新，供稳定度取毛利率极差）
  ├─ stabilityIndustryComponent     ← 稳定度行业分量（新）
  ├─ stabilityFCFComponent          ← 稳定度 FCF 分量（新）
  ├─ stabilityProfitComponent       ← 稳定度盈利周期分量（新）
  ├─ cyclicIntensity                ← 加权周期强度（新）
```

### 2.2 计算顺序

`RecommendValuation` 现有顺序已经满足依赖，不需要重排或新增 IO：

```
annualRows(income/cashflow/balance)
  → latest、incomeWindow、fcfYears
  → gp = assessGrowthPattern(...)                         [已有，254]
  → cycle = detectFCFCycle(...)                           [已有，255]
  → 历史锚/前瞻锚/宏观锚 → A                              [已有]
  → discount = valuationDiscount(...)                     [已有，293]
  → pc = detectProfitCycleDetail(...)                     [改，298]
  → isCyclical = detectCyclical(...)                      [不变，299；仍用于 β/周期位置/负增长归因]
  → sgr, retention, sgrYears, retentionBasis, sgrOK =
        sustainableGrowthSmoothed(...)                    [新增，替换 318]
  → stability = terminalStability(industry, cycle, pc, gp) [新增]
  → g∞, terminalConstraint, terminalNote =
        terminalGrowth(macro, r, sgr, sgrOK, stability, sgrYears) [改，320]
  → gap、模型分类、g1 = growthG1(..., sgrYears)            [改，340-343]
  → paramsFromPath → AI 参数
```

关键点：

1. `stability` 与 `isCyclical` 共用 `industry_type`、`cycle`、`pc`、`gp` 同一组输入，但**互不替代**：`isCyclical` 继续服务 β 档位、周期位置修正与负增长归因；`stability` 只服务终值上限。
2. SGR 只计算一次，同时传给 `terminalGrowth` 与 `growthG1`，杜绝一处单年、一处多年。
3. 没有新增数据请求，`terminalStability` 只做常数次比较与线性插值。

## 3. 数据模型

### 3.1 `model.AIValuation` 新增/变更字段

文件：`internal/model/ai.go:110-203`。

```go
// 四、增长参数（在原字段附近插入）
GrowthTerminal     float64 `json:"growth_terminal"`              // g∞，%，1 位小数
TerminalStability  float64 `json:"terminal_stability,omitempty"` // 稳定度 0–1，2 位小数；新计算恒输出
TerminalConstraint string  `json:"terminal_constraint"`          // stability/sgr/discount/zero；cyclical/macro 仅历史兼容
TerminalNote       string  `json:"terminal_note,omitempty"`
SGR                float64 `json:"sgr,omitempty"`                // 仅在终值受 SGR 约束时输出；语义变为近 N 年平均
RetentionRate      float64 `json:"retention_rate,omitempty"`     // 平均留存率 0–1；与 sgr 同步输出
RetentionBasis     string  `json:"retention_basis,omitempty"`    // payout/equity_growth/mixed/unavailable
SGRWindowYears     int     `json:"sgr_window_years,omitempty"`   // 实际有效年度数；回落单年=1，不可用省略
```

口径：

- `terminal_stability`：`[0.2, 1.0]`（受行业分量下限 0.05 与权重 0.50 约束，实际最高约 0.975），`round2`；无论稳定度上限是否真正生效都输出。`omitempty` 只在旧数据缺失时为 0 时省略。
- `sgr_window_years`：`sgrOK=true` 时输出；平滑成功为 3–5，回落单年为 1，SGR 不可用为 0（省略）。
- `retention_basis`：新计算恒输出；全部有效年度用分红口径为 `payout`，全部用权益增长口径为 `equity_growth`，混用为 `mixed`，SGR 不可用为 `unavailable`。该字段为 API 诊断字段，前端不展示。
- `sgr`/`retention_rate` 的可见规则**不变**：仍只在 `terminal_constraint == "sgr"` 时输出。新增的 `sgr_window_years`/`retention_basis` 是描述 SGR 聚合过程的结构化字段，不扩大旧字段的可见范围。

## 6. 核心实现细节

### 6.1 SGR 多年平滑

#### 6.1.1 单年口径（保持不变）

从现有 `sustainableGrowthR18`（`growth.go:971-1008`）抽出 `sgrSingleYear`，逻辑逐行保持：

```text
equity_t = balance_t.TOTAL_EQUITY
np_t     = income_t.PARENT_NETPROFIT
if np_t <= 0:
    np_t = netProfitReconstructed(income_t)   // ParentFallback = true
if equity_t <= 0 || np_t <= 0:
    unavailable

ROE_t = np_t / equity_t × 100

if r18PayoutRetentionEnabled && div.Available:
    cash_t, records_t = dividendForYear(div.Records, t)
    if records_t > 0:
        payout_t   = cash_t / np_t
        ret_t      = clamp(1 − payout_t, 0, 1)
        basis_t    = "payout"
        if payout_t > 1: PayoutExceeded = true   // 单年 warning：现金分红超过归母净利润，留存率按 0 计。
        SGR_t = ROE_t × ret_t
        return OK=true
if retentionRate(balance, income, t) 可用:
    ret_t      = clamp((equity_t − equity_{t−1}) / npReconstructed_t, 0, 1)
    basis_t    = "equity_growth"
    SGR_t = ROE_t × ret_t
    return OK=true
return unavailable
```

说明：

- `r18PayoutRetentionEnabled` 为 `true`（`growth.go:43`），保留该开关语义；关闭时直接走权益增长口径。
- 分红口径优先，且只要该年度有分红记录就返回，不再尝试权益增长口径，与现有实现一致。
- `retentionRate`（`valuation_recommend.go:684-699`）内部使用重构净利润，是既有口径，本次不改。
- `ParentFallback`/`PayoutExceeded` 是新增的内部布尔量，仅用于多年聚合时去重提示，不对外输出。
- 单年 warning 与现有文本逐字一致：归母回落为「归母净利润缺失或非正，留存率与 ROE 按重构净利润近似。」；分红超净利润为「现金分红超过归母净利润，留存率按 0 计。」；不可用为「留存率/ROE 数据不足，自筹资金可持续增速不可用，终值不施加该约束。」。

`detectProfitCycleDetail` 不影响本节。

#### 6.1.2 窗口与有效年度

1. 候选年度 = 资产负债表与利润表都有年报的年度，且 `≤ 基期年`：

   ```go
   sgrCandidates := commonYears(balanceYears, incomeYears) // 升序交集，由聚合函数内部再取最近 5 年
   ```

   - `annualRows` 已按 `12-31` 过滤年报（`analysis.go:1940-1953`），无需再次判断。
   - `yearWindow`（`valuation_recommend.go:655-667`）取最近 5 个年度标签；数据有缺口时按实际存在的年度取，不向前补第 6 年。
   - 5 年与现有 `valGrowthWindowYears = 5` 一致（`valuation_recommend.go:51`）；只在 `sustainableGrowthSmoothed` 内部 window 一次，避免调用处与函数内重复过滤。
   - `balanceYears`/`incomeYears` 来自 `annualRows` 的年度列表，已升序；`commonYears` 保持升序。

2. 一个年度为有效年度，当且仅当 `sgrSingleYear` 返回 `OK=true`，即：
   - `equity_t > 0`；
   - 选定净利润 `np_t > 0`（归母优先，缺失/非正回落重构）；
   - 留存率可计算（分红口径有该年度分红记录，或权益增长口径满足 `equity_t>0 && equity_{t−1}>0 && npReconstructed_t>0`）。

3. ROE 与留存率使用**同一个有效年度集合**：由 `sgrSingleYear` 一次性返回，不存在「ROE 可算、留存率不可算」的年度被单独纳入。

#### 6.1.3 聚合公式

有效年度数 `n ≥ 3` 时：

```text
ROE_avg = (Σ ROE_t) / n
ret_avg = (Σ ret_t) / n
SGR     = ROE_avg × ret_avg
```

- 算术平均，等权；不做 winsorize。
- 单位：`ROE_avg` 为百分数（%），`ret_avg` 为 0–1，`SGR` 为百分数（%）。
- 不采用「逐年 SGR 再平均」，避免单年「低净利润 × 高留存率」的乘积噪声。
- 已知近似：忽略 ROE 与留存率的协方差，作为单一适中基准可接受（需求 §7 Q2）。

#### 6.1.4 回落与不可用

```text
if n >= 3:
    使用聚合值，windowYears = n
else:
    d = sgrSingleYear(latest)
    if d.OK:
        sgr/retention/basis = d 的单年值，windowYears = 1
        warning = joinWarns([]string{d.Warning,
            "可用年度不足 3 年，自筹资金可持续增速按最近一年计算。"})
    else:
        sgrOK = false，windowYears = 0，basis = "unavailable"
        warning = "可用年度不足 3 年，且最近一年数据不可用，自筹资金可持续增速不可用，终值不施加该约束。"
```

- 基期年亏损但历史仍有 ≥3 个有效年度时，基期年只是被剔除，**继续平滑**，不直接不可用。
- 有效年度为 3 或 4 个时使用实际年度，不向前补第 6 年凑满 5 个。
- 平滑 SGR 只纳入净利润 > 0 的年度，因此 `SGR ≥ 0`；`ret_avg = 0` 时 `SGR = 0`，沿用现有「SGR 为 0 → g∞=0、g1 上限 1pp」处理。
- 不因单年 ROE 极端值做额外截断。

#### 6.1.5 `retention_basis` 聚合

| 有效年度使用的口径 | 输出 |
|---|---|
| 全部 `payout` | `payout` |
| 全部 `equity_growth` | `equity_growth` |
| 两者都有 | `mixed` |
| 无有效年度且回落单年 | 单年口径 |
| 不可用 | `unavailable`（仍对外输出，供诊断） |

#### 6.1.6 提示文案（去重）

多年聚合时，同一提示最多输出一次：

- 任一有效年度发生归母回落：`归母净利润缺失或非正，留存率与 ROE 按重构净利润近似。`
- 任一有效年度分红超过净利润：`现金分红超过归母净利润，留存率按 0 计。`
- 回落单年：见 §6.1.4。
- 单年不可用：沿用「留存率/ROE 数据不足，自筹资金可持续增速不可用，终值不施加该约束。」。

提示仍进入 `warnings` 数组，受既有「最多 6 条」截断约束（`valuation_recommend.go:435`）。

#### 6.2.2 三个信号分量

**行业分量** `c_industry`（权重 0.50）

| 归一化行业 | 取值 |
|---|---:|
| `cyclical` | 0.85 |
| `general` | 0.15 |
| `utility` | 0.05 |
| 缺失/非法 | 0.30 |

行业类型取 `normalizeIndustryType(input.IndustryType)`，**不取** `discount.IndustryType`：后者在 AI 缺失时可能因经营波动回落为 `cyclical`，会与 FCF 分量重复计权；需求明确「缺失=0.30」。

**FCF 分量** `c_fcf`（权重 0.30）

- 可用性：`cycle.Evaluated == true`（`detectFCFCycle` 已保证 ≥3 年且 FCF 均值 >0）；否则该分量不可用。
- 基础值：

  ```text
  CV ≤ 0.15        → 0
  CV ≥ 0.60        → 1
  0.15 < CV < 0.60 → (CV − 0.15) / (0.60 − 0.15)
  ```

- 符号翻转加成：`cycle.SignChanges >= 2` 时 `c_fcf = max(c_fcf, 0.80)`。
- 结果自然落在 `[0,1]`。

**盈利周期分量** `c_profit`（权重 0.20）

- 可用性：盈利周期窗口（`cycleWindow = yearWindow(incomeYears, latest, r18CycleMaxWindowYears)`，最多 7 年）至少 3 年，且有效毛利率样本 ≥2；否则该分量不可用。
- 毛利率极差 `GMRange` 由 `detectProfitCycleDetail` 返回（与 `detectProfitCycle` 使用同一窗口、同一 `revenue/operateCost`、同一 `spread`）。
- 不复用 `gp.GrossMarginRange`：它服务于 5 年成长性判定（`assessGrowthPattern`），与 `detectProfitCycle` 的 7 年周期窗口不同；复用会让同一「毛利率极差」出现两种口径。
- 基础值：

  ```text
  极差 ≤ 3pp        → 0
  极差 ≥ 15pp       → 1
  3pp < 极差 < 15pp → (极差 − 3) / (15 − 3)
  ```

- 命中加成：`pc.Hit == true` 时 `c_profit = max(c_profit, 0.80)`。
- 结果 clamp 到 `[0,1]`。
- 「缺失」指数据不可用，不是数值为 0：毛利率样本充足但极差为 0 时，分量可用且取 0，会拉低 `c`（体现稳定），不按缺失归一化。只有窗口不足或样本不足才视为缺失。

#### 6.2.3 权重归一化

```text
num = 0.50 × c_industry
den = 0.50
if FCF 分量可用:    num += 0.30 × c_fcf;    den += 0.30
if 盈利分量可用:    num += 0.20 × c_profit; den += 0.20
c_raw = num / den
```

- 行业分量始终存在（缺失按 0.30），`den ≥ 0.50`。
- 缺失分量不按 0 计入，而是把权重按剩余分量归一化。
- 只有行业分量可用时：`c_raw = c_industry`。

#### 6.2.4 成长性否决与封顶

```text
if gp.Veto && normalizedIndustry != "cyclical":
    c_raw = min(c_raw, 0.15)
c         = min(0.80, c_raw)
stability = 1 − c
```

- 成长性否决表示公司不是周期型，不应再因 FCF 波动压低终值；行业为 `cyclical` 时按现有 AI 优先原则，否决不覆盖稳定度。
- `c` 封顶 0.80 对应稳定度下限 0.20，衔接 R21 的 2.5% 周期股基准；这是映射结果，不是额外的终值硬下限。
- `stability` 全精度参与 `cap` 计算；只在输出与依据句中 `round2`。

### 6.3 终值连续化

#### 6.3.1 公式

```text
cap = 2.0% + (宏观锚 − 2.0%) × stability
g_raw = min(cap, r − 1.0pp, SGR if sgrOK)
g∞    = max(0, floorHalf(g_raw))
```

- 宏观锚为 `macro.Value`（已是 0.5pp 网格；动态 GDP TTM 同比，不可用 4.5%）。
- `cap` 在 `[min(2%,宏观锚), max(2%,宏观锚)]` 之间连续取值；宏观锚 <2% 时公式仍成立，不另行抬高。
- 连续化体现在 `cap` 与中间档增多（2.5/3.0/3.5/4.0/4.5），最终仍按 0.5pp 网格向下取整。
- 终值作用于最终永续段：永续模型 `g`、两阶段 `g2`、三阶段 `g3`；三阶段中间段构造规则不变。

#### 6.3.2 约束优先级与枚举

- 真正生效的约束取 `min(cap, r−1pp, SGR)` 的来源。
- 并列时主约束优先级：`sgr > discount > stability`（沿用 R19/R20 的 `sources` 顺序与 `1e-9` 判定）。
- `terminal_constraint` 取值：
  - `g_raw <= 0` → `zero`；
  - SGR 最低 → `sgr`；
  - `r−1pp` 最低 → `discount`；
  - `cap` 最低 → `stability`。
- 新计算不再返回 `cyclical`/`macro`；二者仅作为历史值兼容（§3.4）。
- 稳定度上限未生效时，依据句不得写「受稳定度约束」。

### 8.3 端到端复算样例

以宏观锚 4.5%、折现率 8.5%、SGR 可用为例：

| 样本 | 行业 | FCF CV | 毛利率极差 / 命中 | stability | cap | g∞ | 预期约束 |
|---|---|---|---:|---:|---:|---:|---|

复算步骤（用户可手工验证）：

1. 取「近 N 年平均」SGR；
2. 取 `terminal_stability`；
3. 计算 `cap = 2% + (4.5% − 2%) × stability`；
4. 取 `min(cap, r−1pp, SGR)`，向下取整到 0.5pp，若小于 0 则取 0。

按 AC-21，测试报告需对深度周期、稳定消费、中间态三个样本分别记录：平滑 SGR 与窗口、`terminal_stability`、`cap`（取整前）、`g∞`、`g1`、`terminal_note` 与 `g1_note`。其中深度周期同时断言「SGR 更低」和「r−1pp 更低」两个分支仍优先于稳定度上限。

## 9. 关键决策点 / 待确认

需求 §7 的 Q1–Q8 已全部按推荐默认采纳，无阻塞项。以下是实现层面的补充假设，均与需求一致，实现前无需再向用户确认：

1. **行业分量取原始 AI 分类，不取 β 兜底**：`terminalStability` 使用 `normalizeIndustryType(input.IndustryType)`；缺失/非法按 0.30。`discount.IndustryType` 在 AI 缺失时可能因波动回落为 `cyclical`，若复用它会让「缺失=0.30」失效，并与 FCF 分量重复计权。
2. **盈利周期分量使用 7 年周期窗口的毛利率极差**：由 `detectProfitCycleDetail` 返回，与 `detectProfitCycle` 同窗口、同字段，不另起一套。窗口不足 3 年时该分量不可用（与现有盈利周期判定门限一致），而不是用 2 年样本强行计算。
3. **`sgr_window_years` 在 `sgrOK` 时输出，`retention_basis` 恒输出**：`retention_basis` 在 SGR 不可用时取 `unavailable`（需求 FR-1 线 120 明确列出该值），作为 API 诊断字段；不改变 `sgr`/`retention_rate` 仅在终值受 SGR 约束时输出的既有规则。
4. **稳定度全精度参与 cap，仅输出/文案 round2**：避免先取整再插值造成档位偏移；`terminal_stability` 字段与依据句使用 2 位小数。
5. **稳定度上限生效时依据句使用最终 g∞**：句式「终值增长率按稳定度 0.20 对应的长期上限 2.5% 封顶。」中的 2.5% 是 floorHalf 后的最终值；当 cap 为 3.86%、最终 3.5% 时写 3.5%，满足「同时包含稳定度数值与最终终值数值」。
6. **`retention_basis` 重新对外输出**：R19 曾将其列为内部字段，R22 FR-5/AC-5 明确要求区分 `payout`/`equity_growth`/`mixed`，因此作为附加字段恢复输出；不影响旧客户端。
7. **删除 `r20CyclicalTerminalPP` 的生产用途**：2.5% 不再是硬编码常量，而是 `2% + (宏观锚−2%)×0.2` 的结果；测试中的 2.5% 断言改为局部期望值或由新常量计算。
8. **`detectCyclical` 不变**：稳定度不替代、不修改二元周期判定；`isCyclical` 继续服务 β 档位、周期位置修正与负增长归因，二者允许不一致。
