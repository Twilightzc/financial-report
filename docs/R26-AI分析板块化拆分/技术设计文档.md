# R26 AI 分析板块化拆分 技术设计文档

> 需求依据：`docs/R26-AI分析板块化拆分/需求文档.md`（FR-1 ~ FR-15、AC-1 ~ AC-20）。
> 设计范围：把现有「一次取数 + 一次 LLM 调用 + 整包返回」的 AI 智能分析，拆为「公司财务分析 / 行业分析 / 估值参数分析 / 商业模式分析（R27 预留）」四个模块；每个模块独立提示词、独立解析、独立缓存、独立触发；顶部「一键全分析」在后端一次取数后并发调用各模块；删除「分析模式（`reasoning`）」，统一详细档。**不改变任何分析内容口径**（五维评分、雷达图、行业/业务板块/相关公司规则、R7/R19～R25 估值参数确定性口径、DCF、取数）。
>
> **用户已拍板、本文不再讨论的决策**
>
> | 编号 | 决策 |
> | --- | --- |
> | Q1 | 接口形态 = 方案 B：单端点 `GET /api/stock/:code/ai-analysis` + `module` 参数，缺省 `all`。 |
> | Q2 | 每模块独立 LLM 调用；`all` = 各已上线模块**并发**调用（R26 为 3 次）。 |
> | Q3~Q10 | 总体结论保持现有五段式；单请求整体返回（不引入 SSE）；前端分模块卡片纵向堆叠；R26 不渲染商业模式卡片；缓存上限 64→128；不做 API 兼容层；行业/估值模块可按需裁剪输入（以输出结构等价为验证前提）；接受各模块独立、不做跨模块一致性复核。 |
> | — | 删除 `reasoning` 参数及其全部语义；旧调用方传入则忽略。 |
> | — | 开发顺序：先 R26 再 R27；`aiCacheSchema` 本需求 `r25 → r26`，R27 再 `r26 → r27`。 |
>
> **本文新增的实现层默认约定（需求未展开，按此落地）**
>
> 1. **`AIAnalysisResult` 保留为测试/聚合类型**：不再出现在 API 响应与缓存中；`ParseAIResult` 保留为「组合解析」测试辅助，handler 不再调用。这样 R17 等大量既有解析测试可平滑迁移，不构成对外兼容层。
> 2. **模块结果载荷用 `any` 承载**：`AIFinancialResult` / `AIIndustryResult` / `AIValuationResult` 三选一；缓存中保存同一接口值，命中后直接序列化。载荷在写入缓存后视为只读。
> 3. **行业模块单请求不拉三张全量报表**：F10 全量报表当前没有 `INDUSTRY_*` 字段（见 `internal/service/ai.go:734` 注释），`IndustryFromReportRows` 实际恒为空；因此单行业分析直接走 DMSK `FetchIndustry`。`all` 中若已因财务/估值模块拉了报表，则仍按「报表行优先、缺失回退 DMSK」执行，与现状一致。若未来 F10 增加行业字段，把行业模块的 `Needs.Reports` 置 true 即可。
> 4. **行业名以后端确定性分类为准**：行业模块 `Finalize` 中用 DMSK/报表行得到的行业名覆盖 AI 的 `industry.name`（有值时才覆盖），使行业卡片标题与龙头榜一致；AI 的 prospect/competition/application 不改。此为需求 §5.2 的推荐缓解措施。
> 5. **估值模块 LLM 失败即模块失败**：即使后端预推导的 `rec` 已可用，也不在 LLM 失败时返回「半成品成功」；失败不写缓存、可单独重试，符合 FR-7/FR-9。

## 1. 设计目标与影响面

### 1.1 目标

1. 四个模块边界清晰、字段归属唯一（需求 §2.3）；任一模块响应只含本模块字段。
2. 单模块可独立触发、独立缓存、独立失败重试；`all` 一次取数、多模块并发 LLM 调用。
3. 删除分析模式，统一详细档（总体结论约 300 字），`reasoning` 参数忽略。
4. 模块注册表驱动：R27 只新增一个模块定义（Go + 前端各一项），不改既有模块提示词、解析与渲染。
5. 内容与确定性口径零回归：给定相同 AI 文本输出，各模块确定性字段与拆分前逐值一致。

### 1.2 非目标

- 不改五维评分维度、评分标准、雷达图、总体结论五段式内容要求。
- 不改行业/业务板块/相关公司的条数、清洗、去重、排除自身、免责声明规则。
- 不改 `RecommendValuation`、`ApplyValuationRecommendation` 的确定性口径与两段式顺序。
- 不改东财/腾讯数据源、`cfPageSize`/`bsPageSize`、年报过滤、年份兜底、代码校验。
- 不新增 SSE/流式、不持久化分析结果、不做跨模块一致性复核、不实现 R27 商业模式内容。

### 1.4 兼容性结论

- **HTTP 接口有结构性变化**：`module` 新增；`reasoning` 忽略；响应由整包 `AIAnalysisResult` 变为模块级响应/聚合响应。前端同版本发布，不做兼容层。
- **缓存主动失效**：`aiCacheSchema` 升 `r26`，旧 r25 整包缓存不再命中；无迁移。
- **前端本地缓存**：内存 Map，刷新即失；key 改为 `代码|起始年|结束年|模块`。
- **模型层**：`AIAnalysisResult`、`AIValuation`、`AIScore` 等既有类型字段不变；新增模块结果类型，避免大规模改动既有测试。

## 2. 总体架构

### 2.1 分层与调用链

```
前端 app.js
  ├─ 模块注册表（4 项，R26 可见 3 项）
  ├─ 每卡片「一键分析」 → GET /api/stock/:code/ai-analysis?module=<id>&...
  ├─ 顶部「一键全分析」 → GET ...?module=all&...
  └─ 模块状态机 idle/loading/ok/error（not_implemented 不渲染）

api.GetAIAnalysis
  ├─ 校验 code / module / apikey / 年份
  ├─ resolve modules（service.aiModuleSpecs）
  ├─ 逐模块 cache.peek：命中直接返回，命中模块不参与取数
  ├─ 对未命中模块求 needs 并集，一次构建 AIModuleInput：
  │     ├─ FetchQuote
  │     ├─ fetchAnalysisReports（三表并发，财务/估值需要）
  │     ├─ FetchSegmentIncome（失败降级为空）
  │     ├─ FetchIndustryPeers（失败降级为空）
  │     ├─ FetchIndustry 或报表行行业分类
  │     ├─ fetchGrowthSnapshot（估值需要）
  │     ├─ service.ComputeAnalysis（财务需要）
  │     └─ service.RecommendValuation 预推导（估值需要）
  ├─ 每个未命中模块：cache.getOrCompute(moduleKey, runAIModule)
  │     └─ BuildPrompt → DeepSeek.Chat → Parse → Finalize
  └─ 聚合 {module/status/result/usage/elapsed_ms/cached} 或 {modules, usage, elapsed_ms}

service 层：纯函数（提示词、解析、finalize、推荐计算）
client 层：唯一 IO（东财/腾讯/DeepSeek）
model 层：标准结构与模块响应类型
```

### 2.2 Go 侧模块注册表

新增 `internal/service/ai_modules.go`：

```go
type AIModuleNeeds struct {
    Quote         bool // 行情（模块公共）
    Reports       bool // 三张 F10 全量报表
    Segments      bool // 主营构成
    Growth        bool // 外部增长快照（一致预期/GDP/分红）
    Peers         bool // 行业同行市值榜
    Industry      bool // 行业分类（DMSK 或报表行）
    Analysis      bool // service.ComputeAnalysis（六维指标）
    ValuationBase bool // service.RecommendValuation 预推导
}

// AIModuleInput 一次请求内共享的只读事实，由 api 层构建、service 层消费。
type AIModuleInput struct {
    Quote        model.Quote
    Analysis     model.FinancialAnalysis
    Segments     []model.SegmentIncome
    Rec          model.ValuationRecommendation
    Leaders      model.LeaderBoard
    IndustryCode string
    IndustryName string

    // 仅供估值模块 finalize 两段式重算；其余模块不读。
    ValuationInput service.ValuationRecommendInput
}

type AIModuleSpec struct {
    ID          string
    Title       string // 中文标题（仅展示/日志）
    Description string // 一句话职责（前端展示）
    Implemented bool
    Needs       AIModuleNeeds
    // BuildPrompt 只读取 AIModuleInput，不产生 IO。
    BuildPrompt func(in AIModuleInput) (system, user string)
    // Parse 只解析本模块 JSON；返回 *model.AIFinancialResult / *model.AIIndustryResult / *model.AIValuationResult。
    Parse func(raw, selfName string) (any, error)
    // Finalize 可选：确定性回填（行业龙头/行业名）或两段式重算（估值）。
    Finalize func(payload any, in AIModuleInput) (any, error)
}

var aiModuleSpecs = []AIModuleSpec{

```

`ResolveAIModules(module string) ([]AIModuleSpec, bool, error)`：

- `""` 或 `"all"` → 返回全部 4 个 spec，`all=true`。
- 合法模块 ID → 返回单个 spec，`all=false`。
- 其他 → 返回 error（handler 映射 400）。

`UnionNeeds(specs []AIModuleSpec) AIModuleNeeds`：逐项 OR；`all` 取并集；仅未命中模块参与。

### 3.3 模块响应与聚合响应

```go
// 单模块响应（同时是 all 响应 modules 的条目）。
type AIModuleResponse struct {
    Module    string      `json:"module"`
    Status    string      `json:"status"` // ok / error / not_implemented
    Message   string      `json:"message,omitempty"`
    Result    any         `json:"result,omitempty"` // 三选一模块载荷
    Usage     *TokenUsage `json:"usage,omitempty"`
    ElapsedMS int64       `json:"elapsed_ms"`
    Cached    bool        `json:"cached"`
}

// 全分析聚合响应。
type AIAllModulesResponse struct {
    Modules    map[string]AIModuleResponse `json:"modules"`
    Usage      TokenUsage                  `json:"usage"` // 各成功模块之和（含缓存模块的原始用量）
    ElapsedMS  int64                       `json:"elapsed_ms"`
}
```

- `Result` 使用 `any`：缓存与响应共用同一接口值，避免 `json.RawMessage` 二次转义；载荷写入后只读。
- 单模块响应直接作为 `data` 返回，不再外包一层。
- `AIAnalysisResult` 保留原字段（`Scores/Conclusion/Industry/Businesses/Valuation/Leaders/Chain/Partners/Usage`），仅供 `ParseAIResult` 组合解析与既有测试使用；handler、缓存、前端均不再使用。

## 4. 数据源、取数与并发

### 4.1 模块 → 数据依赖

| 模块 | Quote | Reports | Segments | Growth | Peers | Industry | ComputeAnalysis | RecommendValuation |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| `financial` | 必须 | 必须 | 必须 | — | — | — | 必须 | — |
| `industry` | 必须 | 可选¹ | 必须 | — | 必须 | 必须 | — | — |
| `valuation` | 必须 | 必须 | 必须 | 必须 | — | — | — | 预推导必须 |
| `business_model`（R27） | 待定 | 待定 | 待定 | 待定 | 待定 | 待定 | 待定 | 待定 |

¹ 单行业模块不主动拉三张 F10 全量报表，直接 `FetchIndustry`（DMSK）；`all` 中若报表已由财务/估值模块拉取，则按「报表行优先」使用 `IndustryFromReportRows`，为空再回退 DMSK。原因见文档头部实现层约定 3。

### 4.2 取数一次原则

`all`（或任意多模块组合）的取数流程：

1. 先对每个请求模块做 `cache.peek`；**已缓存模块不参与 needs 并集**。
2. 对未命中模块求 `needs` 并集。
3. 按下表并发启动各取数（相互无依赖）：

| 数据 | 调用 | 失败策略 |
| --- | --- | --- |
| 行情 | `h.c.FetchQuote(code)` | 硬失败：所有依赖模块失败 |
| 三表 | `h.fetchAnalysisReports(code, cfPageSize, bsPageSize)` | 硬失败：财务/估值失败 |
| 主营构成 | `h.c.FetchSegmentIncome(code)` | 忽略错误，按无主营构成降级 |
| 增长快照 | `h.fetchGrowthSnapshot(code)` | 内部已降级，不返回错误 |
| 同行榜 | `h.c.FetchIndustryPeers(code)` | 记日志，龙头降级为空 |
| 行业分类 | 报表行优先；无则 `h.c.FetchIndustry(code)` | 记日志，行业名降级为空 |
| 六维指标 | `service.ComputeAnalysis(balance, cashflow, income, startYear, endYear)` | 纯函数，无失败 |
| 估值预推导 | `service.RecommendValuation(ValuationRecommendInput{...})` | 纯函数，无失败 |

4. 年份范围：沿用 `parseYearRange`；未指定时用 `latestAnnualYear(cashflow)` 兜底 `latest-4`（仅当 `needs.Analysis` 需要）；显式非法年份返回 `errInvalidYearRange` → 400。
5. 组装 `AIModuleInput`（只读），再并发执行各模块 LLM。

> 取数顺序可优化为「先启动相互独立的 goroutine，再按模块需要汇合」；关键是**每类上游请求在单次请求内最多一次**。

### 4.3 并发执行

```go
var wg sync.WaitGroup
var mu sync.Mutex
responses := make(map[string]model.AIModuleResponse, len(specs))

for _, p := range pending {
    if !p.spec.Implemented {
        responses[p.spec.ID] = notImplementedResponse(p.spec.ID)
        continue
    }
    if p.hit { // peek 命中
        responses[p.spec.ID] = okResponse(p.spec.ID, p.outcome, true, 0)
        continue
    }
    if fetchErr != nil {
        responses[p.spec.ID] = errorResponse(p.spec.ID, "分析失败，请重试")
        continue
    }
    wg.Add(1)
    go func(p pendingModule) {
        defer wg.Done()
        started := time.Now()
        out, outcome, err := h.aiCache.getOrCompute(p.key, func() (*aiModuleOutcome, error) {
            return h.runAIModule(p.spec, data, apiKey, modelName, baseURL)
        })
        mu.Lock()
        defer mu.Unlock()
        if err != nil {
            log.Printf("AI 模块分析失败: code=%s module=%s err=%v", code, p.spec.ID, err)
            responses[p.spec.ID] = errorResponse(p.spec.ID, "分析失败，请重试")
            return
        }
        cached := outcome == aiCacheHit
        elapsed := int64(0)
        if !cached {
            elapsed = time.Since(started).Milliseconds()
        }
        responses[p.spec.ID] = okResponse(p.spec.ID, out, cached, elapsed)
    }(p)
}
wg.Wait()
```

- 并发上限 = 请求模块数（R26 ≤3，R27 ≤4），无需额外信号量。
- 各模块的 DeepSeek 重试互不影响；一个模块 429 退避不阻塞其他模块。
- 缓存未命中但已有同 key 在途请求时，`getOrCompute` 等待并复用 leader（`aiCacheCoalesced`），不重复调用 LLM；此路径可能多做一次并集取数，但不重复 LLM，属可接受权衡。

## 8. 缓存设计

### 8.1 key 与常量

```go
const (
    aiCacheTTL    = 10 * time.Minute
    aiCacheMax    = 128 // 64 → 128：一次 all 最多写 3~4 条
    aiCacheSchema = "r26"
)

type aiCacheKey struct {
    Schema         string
    Code           string
    Module         string // financial / industry / valuation / business_model
    StartYear      int
    EndYear        int
    RangeSpecified bool
}

func aiCacheKeyFor(code, module string, startYear, endYear int, rangeSpecified bool) aiCacheKey
```

- 删除 `Reasoning` 维度；`RangeSpecified` 语义不变。
- key 不含 API key、模型名；模型切换不会自动失效（沿用现状）。

### 8.2 读写接口

```go
type aiResultCache struct {
    mu       sync.Mutex
    entries  map[aiCacheKey]aiCacheEntry
    inflight map[aiCacheKey]*aiFlight
    now      func() time.Time
}

// peek 只读检查（过期即删，不触发计算、不等待在途）：用于「全命中不取数」。
func (c *aiResultCache) peek(key aiCacheKey) (*aiModuleOutcome, bool)

// getOrCompute 唯一读写入口：命中返回；未命中本请求计算；同 key 在途等待复用；失败不缓存。
func (c *aiResultCache) getOrCompute(
    key aiCacheKey,
    compute func() (*aiModuleOutcome, error),
) (*aiModuleOutcome, aiCacheOutcome, error)
```

- `peek` 在 handler 取数前调用；命中模块直接返回 `cached=true`，不参与 needs 并集。
- `getOrCompute` 内部再次检查缓存，处理 `peek` 与计算之间被其他请求填充的情况。
- `finish` 逻辑不变：成功才写 entries；无论成败删除 inflight 并唤醒等待者；panic 路径不写缓存。
- `storeLocked`：满 128 先清过期，仍满整体清空（沿用现状）。
- `cached` 语义：`aiCacheHit` → true；`aiCacheMiss` / `aiCacheCoalesced` → false；`elapsed_ms` 仅 miss 时记录实际耗时。

### 8.3 单模块与全分析共享

- 单模块请求与 `all` 请求使用同一 `aiResultCache`、同一 `aiCacheKeyFor` 规则。
- `all` 对每个模块独立 `peek` → 未命中独立 `getOrCompute`；命中模块不重复 LLM。
- 失败模块不写缓存；其他模块成功写入互不影响。

### 9.2 请求函数

```js
function aiLocalKey(moduleId) {
  return `${(code.value || '').trim()}|${analysisStartYear.value || ''}|${analysisEndYear.value || ''}|${moduleId}`;
}

function resetAIModule(id) {
  const s = aiModules[id];
  s.status = 'idle'; s.result = null; s.usage = null;
  s.elapsedMs = null; s.cached = false; s.error = '';
}

function applyAIModuleSuccess(id, result, usage, elapsedMs, cached) {
  const s = aiModules[id];
  s.status = 'ok'; s.result = result; s.usage = usage || null;
  s.elapsedMs = elapsedMs; s.cached = !!cached; s.error = '';
  if (id === 'valuation') autoApplyAIValuation(result && result.valuation);
  if (id === 'financial') renderRadarAfterRender();
}

async function runAIModule(id) {
  if (!canRunAI.value || aiAllLoading.value || aiModules[id].status === 'loading') return;
  const reqCode = code.value.trim();
  const local = aiCache.get(aiLocalKey(id));
  if (local) {
    applyAIModuleSuccess(id, local.result, local.usage, null, true);
    return;
  }
  const s = aiModules[id];
  s.status = 'loading'; s.error = ''; s.result = null; s.usage = null; s.elapsedMs = null;
  const started = nowMs();
  try {
    const params = [`module=${id}`];
    if (analysisStartYear.value && analysisEndYear.value) {
      params.push(`startYear=${analysisStartYear.value}`, `endYear=${analysisEndYear.value}`);
    }
    const res = await fetch(`/api/stock/${reqCode}/ai-analysis?${params.join('&')}`);
    const json = await readJSON(res);
    if (code.value.trim() !== reqCode) return; // 期间换股，丢弃
    if (json.code !== 0 || !json.data || json.data.status !== 'ok') {
      s.status = 'error';
      s.error = (json && json.message) || '分析失败，请重试';
      return;
    }
    const elapsed = Number(((nowMs() - started) / 1000).toFixed(1));
    aiCache.set(aiLocalKey(id), { result: json.data.result, usage: json.data.usage });
    applyAIModuleSuccess(id, json.data.result, json.data.usage, elapsed, false);
  } catch (e) {
    if (code.value.trim() !== reqCode) return;
    s.status = 'error';
    s.error = '请求失败：' + e.message;
  }
}

async function runAllAIModules() {
  if (!canRunAI.value || aiAnyLoading.value) return;
  const reqCode = code.value.trim();
  aiAllLoading.value = true;
  aiAllError.value = '';
  aiAllElapsedMs.value = null;
  aiAllUsage.value = null;
  visibleAIModules.forEach(m => {
    const s = aiModules[m.id];
    s.status = 'loading'; s.error = ''; s.result = null; s.usage = null; s.elapsedMs = null;
  });
  const started = nowMs();
  try {
    const params = ['module=all'];
    if (analysisStartYear.value && analysisEndYear.value) {
      params.push(`startYear=${analysisStartYear.value}`, `endYear=${analysisEndYear.value}`);
    }
    const res = await fetch(`/api/stock/${reqCode}/ai-analysis?${params.join('&')}`);
    const json = await readJSON(res);
    if (code.value.trim() !== reqCode) return;

    const modules = json && json.data && json.data.modules;
    if (!modules) {
      visibleAIModules.forEach(m => {
        aiModules[m.id].status = 'error';
        aiModules[m.id].error = (json && json.message) || '分析失败，请重试';
      });
      aiAllError.value = (json && json.message) || '分析失败，请重试';
      return;
    }

    visibleAIModules.forEach(m => {
      const r = modules[m.id];
      if (!r) {
        aiModules[m.id].status = 'error';
        aiModules[m.id].error = '未返回结果，请重试';
        return;
      }
      if (r.status === 'ok') {
        aiCache.set(aiLocalKey(m.id), { result: r.result, usage: r.usage });
        // 统一在循环后触发一次估值自动套用，避免重复
        aiModules[m.id].status = 'ok';
        aiModules[m.id].result = r.result;
        aiModules[m.id].usage = r.usage || null;
        aiModules[m.id].elapsedMs = r.cached ? null : (r.elapsed_ms != null ? r.elapsed_ms / 1000 : null);
        aiModules[m.id].cached = !!r.cached;
        aiModules[m.id].error = '';
      } else {
        aiModules[m.id].status = 'error';
        aiModules[m.id].error = r.message || '分析失败，请重试';
      }
    });
    if (aiModules.valuation.status === 'ok') {
      autoApplyAIValuation(aiModules.valuation.result && aiModules.valuation.result.valuation);
    }
    renderRadarAfterRender();
    aiAllElapsedMs.value = Number(((nowMs() - started) / 1000).toFixed(1));
    aiAllUsage.value = json.data.usage || null;
    if (json.code !== 0) aiAllError.value = json.message || '分析失败，请重试';
  } catch (e) {
    if (code.value.trim() !== reqCode) return;
    visibleAIModules.forEach(m => {
      aiModules[m.id].status = 'error';
      aiModules[m.id].error = '请求失败：' + e.message;
    });
    aiAllError.value = '请求失败：' + e.message;
  } finally {
    if (code.value.trim() === reqCode) aiAllLoading.value = false;
  }
}
```

## 11. 不变项与回归边界

以下内容不得改变（只允许移动渲染位置）：

1. **五维评分**：维度名与顺序、0-100 整数、恰好 5 项、缺失报错、行业适配说明。
2. **雷达图**：数据来源、维度、颜色分档、窄屏布局。
3. **总体结论**：五段式内容要求与详细档篇幅（约 300 字）；仅从「整包结论」变为财务模块结论。
4. **行业/业务板块/相关公司**：R17 龙头确定性回填、业务板块 2-4 个、细分龙头/相关公司各 0-3 家、产业链上下游/合作各 0-3 家、名称清洗/去重/排除自身/字数上限、免责声明。
5. **估值参数**：R7/R19～R25 模型选择、基期 FCF（含 R25 复苏感知窗口）、WACC/CAPM、增长锚/终值、关键校验、警告、`rationale` 清洗与确定性覆盖；AI 仍只提供 `industry_type`/`company_risks`/`rationale`；两段式重算顺序不变。
6. **DCF 与估值卡片**：四模型、参数校验、敏感性矩阵、公司价值卡片、估值历史（R16）与自动套用来源语义。
7. **数据源与取数**：东财三表/主营构成/行业分类/同行榜、腾讯行情、增长快照；期数、年报过滤、年份兜底、代码校验、字段映射。
8. **缓存语义**：TTL 10 分钟、失败不缓存、在途合并；仅新增模块维度并升 schema。
9. **接口返回包络**：`{code, data, message}` 与 `code==0` 成功语义。
10. **其他页面**：三大报表、六维分析、公司价值、估值卡片、估值历史、搜索无回归。

## 13. 关键实现点、风险与待确认

### 13.1 coder 必须注意的实现点

1. **先 peek 再取数**：`all` 若全部模块命中缓存，必须直接返回，不得触发任何上游请求（沿用 H1 测试语义）。只有未命中模块参与 needs 并集。
2. **模块结果只读**：`aiModuleOutcome.Payload` 写入缓存后不得再修改；`Finalize` 返回新对象或已冻结对象。
3. **`all` 的并发写入**：多个 goroutine 写 `responses` map 必须加锁，或改用索引数组后统一组装。
4. **估值两段式**：`FinalizeValuationResult` 必须值拷贝 `in.ValuationInput`，再写入 AI 的 `industry_type`/`company_risks`；不能污染共享 `AIModuleInput`。
5. **`CompanyRisks` 输入通道**：Apply 后清空，不得出现在最终 `valuation` JSON 中。
6. **行业龙头**：始终由后端注入；AI 返回的 `leaders` 在解析阶段忽略；龙头获取失败只降级为空。
7. **行业名覆盖**：仅在 `in.IndustryName != ""` 时覆盖 AI 的 `industry.name`；不要覆盖 prospect/competition/application。
8. **单模块失败**：返回 `code=1`、`data=null`；`all` 中模块失败不拖垮其他模块，顶层只要有一个成功即 `code=0`。
9. **错误文案**：模块级统一「分析失败，请重试」；真实 error 只写日志，不得包含提示词、字段名、schema。
10. **删除 reasoning**：handler、提示词、缓存 key、前端状态、前端请求、本地缓存 key、日志、测试断言全部清理；旧参数传入忽略。
11. **财务模块不发送估值事实块**；行业/估值模块不发送六维指标全量序列；财务模块保留完整指标序列。
12. **前端估值自动套用**：只能由 `id==='valuation'` 成功触发；all 中循环结束后统一触发一次，避免重复 `fetchValuation('ai')`。
13. **雷达图**：只有财务卡片存在；`renderRadarAfterRender`/`resizeRadarOnShow` 改读 `aiModules.financial.result`；财务卡片隐藏/显示时按现有 resize 机制处理。
14. **换股竞态**：每个请求捕获 `reqCode`，返回时与当前 `code` 对比；换股时重置所有模块状态。
15. **`business_model`**：R26 单模块明确报错；`all` 返回 `not_implemented`；前端注册表过滤，不渲染死按钮。

### 13.2 风险与取舍

| 风险 | 说明 | 缓解 |
| --- | --- | --- |
| 输入 token 重复 | 每个模块各发一次公司头/主营构成（财务还发完整指标） | 行业/估值裁剪六维指标；接受总 token 增加，属模块化代价 |
| 全分析瞬时 3 并发 | 上游 DeepSeek 限流/网关抖动 | 客户端已有 429/5xx 指数退避；模块间互不阻塞；并发上限仅 3~4 |
| 模块间措辞不一致 | 独立生成，不再共享上下文 | 同一事实源、`temperature=0`、确定性字段后端统一；明确接受（Q10） |
| 行业单模块不拉报表 | 与需求「报表行优先」存在理论差异 | F10 当前无行业字段，实际等价；未来 F10 增加字段时把 `Needs.Reports=true` |
| 行业名覆盖 | AI 行业名与后端分类可能不同 | 以后端确定性分类为准，与龙头榜一致（需求 §5.2 推荐） |
| 估值模块 LLM 失败 | 预推导结果已可用，但模块仍失败 | 失败可单独重试；不缓存半成品；符合 FR-7 |
| 前端本地缓存跨版本 | 页面刷新丢失，不持久化 | 仅内存 Map；服务端缓存兜底 |
| `any` 载荷 | 类型安全弱于具体类型 | 只在模块边界使用；Parse/Finalize 内部均为具体类型 |
| 全部失败时的 `data` | 顶层 `code=1` 仍返回 modules | 前端先读 `data.modules` 再判断 `code`，逐卡展示错误 |

### 13.3 待确认项（默认按本文执行）

| 编号 | 问题 | 推荐 | 理由 |
| --- | --- | --- | --- |
| D1 | 行业单模块是否强制拉三张 F10 报表以执行「报表行优先」？ | **不拉**，直接 DMSK；`all` 中报表已存在时仍报表行优先 | F10 当前无行业字段，报表行优先恒为空；可显著降低单模块耗时与上游压力。若要求严格逐字实现，改为 `Needs.Reports=true`。 |
| D2 | 行业模块是否用后端确定性行业名覆盖 AI 的 `industry.name`？ | **覆盖（有值时）** | 需求 §5.2 明确建议「行业名称优先采用后端确定性行业分类（与龙头榜一致）」；prospect/competition/application 不受影响。 |
| D3 | `AIAnalysisResult` / `ParseAIResult` 是否保留？ | **保留为测试辅助**，不参与 API/缓存 | 避免 R17 等大量解析测试重写；不构成对外兼容层。若 coder 选择删除，需同步迁移全部相关测试。 |
| D4 | `NewDeepSeek` 的 `reasoning_effort` 如何处理？ | 保持 4 参签名，handler 固定传 `"high"`；`deepseek-flash` 仍不发送 | 需求 FR-4 建议固定 `high`；不改客户端签名可减少测试改动。 |
| D5 | 全分析本地缓存全命中时是否跳过请求？ | **可选优化**：全部命中则直接渲染；否则仍请求 `module=all` | 服务端缓存已能兜底；跳过请求是纯前端优化，不影响正确性。 |

## 附录 A：Handler 主流程伪代码

```go
func (h *Handler) GetAIAnalysis(c *gin.Context) {
    code := c.Param("code")
    if len(code) != 6 || !isSixDigitCode(code) {
        c.JSON(400, gin.H{"code": 1, "message": "股票代码需为6位数字", "data": nil})
        return
    }

    moduleParam := strings.TrimSpace(c.DefaultQuery("module", "all"))
    specs, isAll, err := service.ResolveAIModules(moduleParam)
    if err != nil {
        c.JSON(400, gin.H{"code": 1, "message": err.Error(), "data": nil})
        return
    }
    if !isAll && len(specs) == 1 && !specs[0].Implemented {
        c.JSON(200, gin.H{"code": 1, "message": "该分析模块尚未上线", "data": nil})
        return
    }

    apiKey := h.aiAPIKey
    if apiKey == "" { apiKey = os.Getenv("DEEPSEEK_API_KEY") }
    if apiKey == "" { c.JSON(200, gin.H{"code": 1, "message": "未配置 AI 分析的 apikey，请以 -apikey 参数启动服务或设置环境变量 DEEPSEEK_API_KEY", "data": nil}); return }
    modelName := firstNonEmpty(h.aiModel, os.Getenv("DEEPSEEK_MODEL"))
    baseURL := firstNonEmpty(h.aiBaseURL, os.Getenv("DEEPSEEK_BASE_URL"))

    startYear, endYear, rangeOK := parseYearRange(c)
    requestStart := time.Now()

    // 1) 逐模块查缓存
    type pendingModule struct {
        spec service.AIModuleSpec
        key  aiCacheKey
        hit  *aiModuleOutcome
        ok   bool
    }
    pending := make([]pendingModule, 0, len(specs))
    misses := make([]service.AIModuleSpec, 0, len(specs))
    for _, spec := range specs {
        key := aiCacheKeyFor(code, spec.ID, startYear, endYear, rangeOK)
        p := pendingModule{spec: spec, key: key}
        if spec.Implemented {
            if out, ok := h.aiCache.peek(key); ok {
                p.hit, p.ok = out, true
            } else {
                misses = append(misses, spec)
            }
        }
        pending = append(pending, p)
    }

    // 2) 未命中模块并集取数（全命中则不取数）
    var data service.AIModuleInput
    var fetchErr error
    if len(misses) > 0 {
        needs := service.UnionNeeds(misses)
        data, _, _, fetchErr = h.buildAIModuleData(code, needs, startYear, endYear, rangeOK)
    }

    // 3) 并发执行
    responses := make(map[string]model.AIModuleResponse, len(pending))
    var mu sync.Mutex
    var wg sync.WaitGroup
    for _, p := range pending {
        if !p.spec.Implemented {
            responses[p.spec.ID] = notImplementedResponse(p.spec.ID)
            continue
        }
        if p.ok {
            responses[p.spec.ID] = okResponse(p.spec.ID, p.hit, true, 0)
            continue
        }
        if fetchErr != nil {
            log.Printf("AI 模块取数失败: code=%s module=%s err=%v", code, p.spec.ID, fetchErr)
            responses[p.spec.ID] = errorResponse(p.spec.ID, "分析失败，请重试")
            continue
        }
        wg.Add(1)
        go func(p pendingModule) {
            defer wg.Done()
            started := time.Now()
            out, outcome, err := h.aiCache.getOrCompute(p.key, func() (*aiModuleOutcome, error) {
                return h.runAIModule(p.spec, data, apiKey, modelName, baseURL)
            })
            mu.Lock()
            defer mu.Unlock()
            if err != nil {
                log.Printf("AI 模块分析失败: code=%s module=%s err=%v", code, p.spec.ID, err)
                responses[p.spec.ID] = errorResponse(p.spec.ID, "分析失败，请重试")
                return
            }
            cached := outcome == aiCacheHit
            elapsed := int64(0)
            if !cached { elapsed = time.Since(started).Milliseconds() }
            responses[p.spec.ID] = okResponse(p.spec.ID, out, cached, elapsed)
        }(p)
    }
    wg.Wait()

    // 4) 组装
    if !isAll {
        resp := responses[specs[0].ID]
        if resp.Status != model.AIModuleStatusOK {
            c.JSON(200, gin.H{"code": 1, "message": resp.Message, "data": nil})
            return
        }
        c.JSON(200, gin.H{"code": 0, "message": "ok", "data": resp})
        return
    }

    all := model.AIAllModulesResponse{Modules: responses, ElapsedMS: time.Since(requestStart).Milliseconds()}
    okCount := 0
    for _, r := range responses {
        if r.Status == model.AIModuleStatusOK {
            okCount++
            if r.Usage != nil {
                all.Usage.PromptTokens += r.Usage.PromptTokens
                all.Usage.CompletionTokens += r.Usage.CompletionTokens
                all.Usage.TotalTokens += r.Usage.TotalTokens
            }
        }
    }
    if okCount == 0 {
        c.JSON(200, gin.H{"code": 1, "message": "AI 分析失败，请稍后重试", "data": all})
        return
    }
    c.JSON(200, gin.H{"code": 0, "message": "ok", "data": all})
}
```
